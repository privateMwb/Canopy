Why Infrastructure as Code

Infrastructure you build by clicking is infrastructure nobody can review, repeat, or fully explain. Code fixes all three at once.

§1The Problem With Clicking

A console is fine for exploring. It is a poor way to run anything you care about: there is no record of who changed what, no way to rebuild the same thing next week, and the real setup lives in someone's memory. Two environments built "the same way" by hand slowly diverge, and that divergence is called drift.

Infrastructure as code (IaC) means writing down what you want in text files, keeping them in version control, and letting a tool make reality match. You get code review for infrastructure changes, a history you can read, and the ability to create an identical environment on demand.

§2Declarative vs. Imperative

An imperative script says *how*: create a network, then create a subnet, then attach it. Run it twice and you may get two networks. A declarative configuration says *what* should exist and leaves the steps to the tool. Terraform is declarative: you describe the end state, and it compares that to what exists and works out the difference.

# Imperative: a sequence of steps you must keep correct
create_bucket "logs"
create_bucket "logs"        # runs again -> error or duplicate

# Declarative: the desired end state
resource "aws_s3_bucket" "logs" {
  bucket = "acme-logs"
}
# applying twice changes nothing the second time

That second property, idempotence, is what makes declarative tools safe to run repeatedly.

§3Where Terraform Fits

Terraform reads configuration written in HashiCorp Configuration Language (HCL), talks to cloud and SaaS APIs through plugins called providers, and records what it created in a state file. It is not a configuration manager: it creates and changes infrastructure (networks, servers, databases, DNS), while tools like Ansible configure what runs *inside* a server.

The mental model Terraform is a loop: read desired state from code, read actual state from the world, compute the difference, apply it. Every later topic in this track is a detail of that loop.

§4Common Mistakes

MistakeWhat HappensFix
Treating the console as the source of truthTerraform and reality disagree, and the next apply may revert a manual fixMake changes in code and apply them, even for urgent fixes
Writing scripts that assume a clean slateA rerun fails or duplicates resourcesPrefer declarative configuration that is safe to apply repeatedly
Expecting Terraform to configure software inside serversServers exist but nothing is installedUse images, cloud-init, or a configuration tool for the inside of a machine
Practice
  1. List three things in an environment you know that exist only because someone clicked them. What would it take to rebuild each from scratch?
  2. Rewrite "create three subnets" as a declarative statement. What does the tool need to know to decide whether to create anything?
Key takeaways
  • IaC makes infrastructure reviewable, repeatable, and versioned.
  • Declarative configuration describes the end state, so applying it twice is safe.
  • Terraform provisions infrastructure; it is not a tool for configuring the inside of machines.
