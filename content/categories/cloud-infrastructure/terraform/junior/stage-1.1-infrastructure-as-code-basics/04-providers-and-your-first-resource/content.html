Providers & Your First Resource

A provider teaches Terraform how to talk to an API. Configure one, declare a resource, and you have created something real.

§1What a Provider Is

Terraform core knows nothing about clouds. Providers are plugins that implement the resources and data sources for a platform: aws, azurerm, google, github, cloudflare, and thousands more. You declare which ones you need, and terraform init downloads them.

terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

source is the provider's address in the registry, and version is a constraint (covered fully in stage 1.3). The provider block holds configuration such as region. Credentials normally come from the environment or a profile, never from the file.

§2Your First Resource

Start somewhere with no account required, using the local provider to write a file.

resource "local_file" "greeting" {
  filename = "${path.module}/hello.txt"
  content  = "Hello from Terraform\n"
}

After init and apply, hello.txt exists. Edit content and run plan: Terraform shows an in-place change or a replacement depending on what the provider says about that argument. The same flow with aws_s3_bucket creates a real bucket in your account.

§3Where Credentials Come From

The AWS provider reads environment variables (AWS_ACCESS_KEY_ID, AWS_PROFILE), shared config files, or an assumed role. Keeping secrets out of .tf files means they stay out of git and out of code review.

Check which account you are in Before the first apply to a real cloud, confirm the identity Terraform will use (for AWS, aws sts get-caller-identity). Applying to the wrong account is a very ordinary and very expensive mistake.

§4Common Mistakes

MistakeWhat HappensFix
Hard-coding access keys in a provider blockSecrets end up in git and stateUse environment variables, profiles, or role assumption
Omitting required_providersTerraform guesses the source and version, and results drift between machinesDeclare source and a version constraint explicitly
Forgetting the regionPrompts or errors, or resources land somewhere unexpectedSet region in the provider block or a variable
Practice
  1. Create a local_file, apply it, change its content, and read the plan before applying again.
  2. Add the random provider and use random_pet output as part of a file name.
Key takeaways
  • Providers are plugins that give Terraform resources for a platform; init installs them.
  • Declare each provider's source and version under required_providers.
  • Credentials come from the environment or a profile, not from your configuration files.
