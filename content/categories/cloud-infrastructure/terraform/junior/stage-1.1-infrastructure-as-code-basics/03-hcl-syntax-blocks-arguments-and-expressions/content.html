HCL Syntax: Blocks, Arguments & Expressions

HCL is small: blocks, arguments, and expressions. Once you can read those three, you can read any Terraform file.

§1Blocks and Arguments

A block has a type, optional labels, and a body in braces. Inside are arguments (name = value) and sometimes nested blocks.

resource "aws_instance" "web" {      # type "resource", labels: resource type and local name
  ami           = "ami-0abc1234"     # argument
  instance_type = "t3.micro"

  tags = {                           # an argument whose value is a map
    Name = "web"
  }

  root_block_device {                # a nested block
    volume_size = 20
  }
}

A resource is addressed as TYPE.NAME, here aws_instance.web. The type decides which arguments are valid; the name is yours and only needs to be unique per type.

§2Values and Expressions

HCL has strings, numbers, booleans, lists, maps, and null. Expressions let you compute values instead of hard-coding them.

locals {
  env  = "prod"
  name = "app-${local.env}"                 # interpolation inside a string
  size = local.env == "prod" ? 100 : 20     # conditional
  azs  = ["a", "b", "c"]
}

output "first_az" { value = local.azs[0] }

You reference other things by address: aws_instance.web.id is an attribute of a resource, var.region is an input variable, local.name is a local value. Those references are what connect your configuration into a graph.

§3Files, Comments, and Layout

Terraform loads every .tf file in a directory and treats them as one configuration, so file names are for humans. Common splits are main.tf, variables.tf, and outputs.tf. Comments start with # or //, or sit between /* and */.

Argument or block? If the documentation shows name = { ... } it is an argument holding an object. If it shows name { ... } with no equals sign, it is a nested block. Mixing them up is the most common first syntax error.

§4Common Mistakes

MistakeWhat HappensFix
Quoting references like "aws_instance.web.id"You get the literal text, not the IDWrite the bare reference, or use "${...}" only inside a longer string
Using = for a nested block"Unsupported argument" or a type errorMatch the docs: blocks take no equals sign
Duplicating a resource name for the same type"Duplicate resource" errorGive each resource of a type a unique local name
Practice
  1. Write a locals block that builds a name from a prefix and an environment, then print it with an output.
  2. Open any resource page in the registry and mark which items are arguments and which are nested blocks.
Key takeaways
  • HCL is blocks containing arguments, whose values can be expressions.
  • Everything is referenced by address, such as TYPE.NAME.attribute, var.x, and local.x.
  • Terraform treats all .tf files in a directory as one configuration.
