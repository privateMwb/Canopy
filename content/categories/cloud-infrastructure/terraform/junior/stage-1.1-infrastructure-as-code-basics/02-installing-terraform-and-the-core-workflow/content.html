Installing Terraform & the Core Workflow

Four commands make up almost everything you do with Terraform. Learn what each one reads, writes, and refuses to do.

§1Installing

Install the terraform binary from HashiCorp's downloads page or a package manager, then confirm it runs. If you will work across projects that need different versions, a version manager such as tfenv or tenv saves pain later.

brew tap hashicorp/tap
brew install hashicorp/tap/terraform     # macOS; Linux and Windows have equivalents
terraform version

§2The Core Loop

Create a directory with one .tf file. This example uses the random provider so you need no cloud account.

terraform {
  required_providers {
    random = { source = "hashicorp/random" }
  }
}

resource "random_pet" "name" {
  length = 2
}

output "pet" {
  value = random_pet.name.id
}
terraform init       # download providers, set up the working directory
terraform plan       # show what would change; changes nothing
terraform apply      # show the plan, ask to confirm, then do it
terraform destroy    # plan and delete everything this configuration manages

init is run once per directory (and again when providers, modules, or the backend change). plan is a read-only preview. apply makes the changes and records them in state. destroy is just an apply whose goal is "nothing".

§3Reading the Output

The plan marks each resource: + create, - destroy, ~ update in place, -/+ replace. The summary line, such as Plan: 1 to add, 0 to change, 0 to destroy, is the fastest check that the change matches your intent. Run apply a second time and Terraform reports no changes, which is idempotence in action.

Always read the plan terraform apply shows the same plan and waits for "yes". Typing yes without reading it is how people delete databases. For anything beyond a lab, save the plan with terraform plan -out=tfplan and apply exactly that file.

§4Common Mistakes

MistakeWhat HappensFix
Skipping init after adding a provider or module"Inconsistent dependency lock file" or "Module not installed"Run terraform init whenever providers, modules, or the backend change
Running apply -auto-approve by habitChanges land without reviewReserve it for pipelines that have already shown and approved a plan
Editing files in the wrong directoryTerraform sees an empty configuration and plans nothingRun commands in the directory that contains your .tf files
Practice
  1. Run the configuration above, then run terraform apply again. What does the second run say and why?
  2. Change length to 3 and read the plan before applying. Is it an update or a replacement?
  3. Run terraform destroy and confirm what it lists.
Key takeaways
  • init prepares, plan previews, apply changes, and destroy removes.
  • The plan is the contract: read it before you confirm.
  • Re-running apply on unchanged code does nothing, and that is by design.
