Networking Resources

A network is the foundation of most stacks. Describing it in code makes it repeatable and reviewable, down to every route.

§1The Pieces

A basic AWS network is a handful of resources that reference each other. The VPC is the private address space. Subnets carve it into zones. An internet gateway connects it to the outside, and route tables decide where traffic goes.

resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  tags                 = { Name = "${var.name}-vpc" }
}

resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id
}

resource "aws_subnet" "public" {
  for_each                = { a = 0, b = 1 }
  vpc_id                  = aws_vpc.main.id
  cidr_block              = cidrsubnet(aws_vpc.main.cidr_block, 8, each.value)
  availability_zone       = data.aws_availability_zones.available.names[each.value]
  map_public_ip_on_launch = true
  tags                    = { Name = "${var.name}-public-${each.key}" }
}

§2Routes

A subnet is "public" only because its route table sends internet-bound traffic to the gateway.

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.main.id
  }
}

resource "aws_route_table_association" "public" {
  for_each       = aws_subnet.public
  subnet_id      = each.value.id
  route_table_id = aws_route_table.public.id
}

Private subnets get a route table without the internet gateway route, and usually a NAT gateway for outbound access. Be aware that NAT gateways bill hourly plus per gigabyte, so add one deliberately.

Let the graph do the ordering Notice that nothing here says "create the VPC first". Each vpc_id = aws_vpc.main.id is the dependency. Using for_each over aws_subnet.public also keeps associations tied to their subnets by key.

§3Common Mistakes

MistakeWhat HappensFix
Overlapping or hard-coded CIDR blocksPeering or routing conflicts laterPlan address space up front and derive subnets with cidrsubnet
Forgetting the route table associationA "public" subnet cannot reach the internetAssociate every subnet with the route table you intend
Adding NAT gateways casuallyA steady hourly charge for each oneCreate them intentionally, and destroy test stacks
Practice
  1. Build a VPC with two public subnets across two availability zones and apply it.
  2. Add a private route table with no internet route and associate a third subnet with it.
Key takeaways
  • A network is VPC, subnets, gateway, and routes, all linked by references.
  • A subnet's "public" or "private" character comes from its route table.
  • Derive CIDR blocks with functions instead of typing them.
