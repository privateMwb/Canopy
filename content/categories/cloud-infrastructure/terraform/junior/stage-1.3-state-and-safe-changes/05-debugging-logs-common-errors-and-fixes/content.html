Debugging: Logs, Common Errors & Fixes

Most Terraform errors repeat. Knowing the common ones, and how to turn on detailed logging, turns a wall of text into a quick fix.

§1Reading an Error

Terraform errors name the file and line, the resource, and often the API's own message. Read the bottom first: the underlying cause is usually there.

Error: creating S3 Bucket (acme-logs): BucketAlreadyExists
  with aws_s3_bucket.logs,
  on main.tf line 12, in resource "aws_s3_bucket" "logs":

Here the cause is not Terraform at all: bucket names are global, and someone owns that one. The fix is a different name.

§2Turning On Logs

When the message is not enough, enable logging. It prints every API request and the provider's internal decisions.

export TF_LOG=DEBUG                    # TRACE is the most verbose
export TF_LOG_PATH=./terraform.log     # write to a file instead of the screen
terraform plan
unset TF_LOG TF_LOG_PATH

Logs can contain credentials and request bodies. Read them locally, redact before sharing, and do not leave them on in CI.

§3The Errors You Will Meet Most

ErrorUsual causeFix
"No valid credential sources found"Missing or expired credentialsCheck the environment or profile and the active identity
"Error acquiring the state lock"Another run is active, or a crashed run left a lockWait, or terraform force-unlock once you are sure no run is active
"Provider produced inconsistent result"A provider bug or a race with the APIRe-run, update the provider, and search the issue tracker
"Unsupported argument"Typo, or an argument not in your provider versionCheck the docs for your pinned version
"Cycle"Resources depend on each otherBreak the loop with a separate resource or a different reference
Read the cloud's own message Many apparent Terraform errors are the cloud API refusing a request: a quota, a missing permission, or an invalid combination. The fix is rarely in Terraform itself.

§4Common Mistakes

MistakeWhat HappensFix
Leaving TF_LOG=TRACE onHuge, noisy output, and secrets in logsSet it for one command, then unset it
Force-unlocking without checkingTwo runs write state at once and corrupt itConfirm no run is active first
Fixing the error and the symptom, not the causeThe same error reappears on the next applyRead the bottom of the message and the API's wording
Practice
  1. Provoke an "Unsupported argument" error and read exactly what Terraform tells you.
  2. Run a plan with TF_LOG=DEBUG and TF_LOG_PATH set, then find the HTTP request for one resource.
Key takeaways
  • Read errors from the bottom up; the cloud's message is usually the real cause.
  • TF_LOG and TF_LOG_PATH expose requests, but may contain secrets.
  • Most errors are credentials, locks, version mismatches, or API quotas.
