Cost, Tagging & Compliance Automation

When cost and ownership are visible by default, waste and orphaned resources stop hiding. Tagging and automation make that routine.

§1Tags as Infrastructure

Tags tie resources to an owner, a cost center, an environment, and the code that created them. Apply them once at the provider level.

provider "aws" {
  region = var.region
  default_tags {
    tags = {
      Owner       = var.owner
      CostCenter  = var.cost_center
      Environment = var.environment
      ManagedBy   = "terraform"
      Repo        = "github.com/acme/infrastructure"
    }
  }
}

Billing reports and cost tools can then group spend by those tags. Some resources do not support tags, so also use account structure, naming, and cloud billing allocation features.

§2Estimating Cost in Review

Show cost before it is incurred, as part of the pull request.

infracost breakdown --path .
infracost diff --path . --compare-to baseline.json

Posting a cost estimate with the plan lets reviewers ask "do we really need three NAT gateways?" at the cheapest possible moment.

§3Compliance Automation

Combine layers so nothing depends on memory:

  • Policy at plan time requires tags, allowed regions, encryption, and approved instance sizes (lesson 2.3.3).
  • Cloud-side rules such as tag policies, service control policies, and configuration-monitoring services catch resources made outside Terraform.
  • Budgets and alerts as code: define a budget per account or tag, with notifications.
resource "aws_budgets_budget" "monthly" {
  name         = "${var.environment}-monthly"
  budget_type  = "COST"
  limit_amount = "500"
  limit_unit   = "USD"
  time_unit    = "MONTHLY"
}
Visibility changes behavior Teams that see their own cost and ownership each week tend to clean up on their own. Make the report unavoidable and attribute spend to a team, and much waste disappears without any mandate.

§4Common Mistakes

MistakeWhat HappensFix
Tagging by convention onlyUntagged resources slip throughEnforce required tags with policy
Relying on tags for resources that cannot carry themSpend stays unattributedUse accounts, naming, and billing allocation too
Looking at cost only after the bill arrivesExpensive decisions are already madeEstimate cost in the pull request
Practice
  1. Add default_tags to a provider and write a policy that fails any resource missing Owner.
  2. Run a cost estimation tool against a stack and list the three most expensive resources.
Key takeaways
  • Apply ownership and cost tags once through default_tags, and enforce them with policy.
  • Show cost estimates in pull requests, before spending happens.
  • Combine plan-time policy with cloud-side rules and budgets.
