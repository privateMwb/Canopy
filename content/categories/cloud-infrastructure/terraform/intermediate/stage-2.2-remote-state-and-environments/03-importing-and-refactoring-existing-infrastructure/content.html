Importing & Refactoring Existing Infrastructure

Real infrastructure often exists before Terraform does, and good code gets renamed. Import and moved handle both without recreating anything.

§1Importing Existing Resources

An import block tells Terraform to adopt a real resource into state on the next apply. Write the matching resource block, then import it.

import {
  to = aws_s3_bucket.legacy
  id = "acme-legacy-bucket"
}

resource "aws_s3_bucket" "legacy" {
  bucket = "acme-legacy-bucket"
}

Run terraform plan. The plan shows an import, and any differences between your code and the real resource. Adjust the code until the plan shows no unwanted changes. The id format is documented in each resource's Import section.

Terraform can even draft the code for you:

terraform plan -generate-config-out=generated.tf

Treat generated code as a first draft to tidy, not a finished result. The older CLI command terraform import ADDRESS ID still works, but the block form is reviewable and can run in a pipeline.

§2Renaming and Moving

Renaming a resource in code looks like "destroy the old name, create a new one" unless you say otherwise. A moved block records the change.

moved {
  from = aws_instance.web
  to   = aws_instance.app
}

It also handles moving a resource into a module, or changing from count to for_each. Keep the block until every environment has applied it.

§3Letting Go

To stop managing a resource without deleting it, use a removed block.

removed {
  from = aws_s3_bucket.legacy
  lifecycle { destroy = false }
}
Import adopts, it does not write your code Import only attaches an existing object to an address in state. A mismatch between your code and the real settings shows up as changes in the next plan, so read it carefully. A careless import followed by an apply can modify a live resource.

§4Common Mistakes

MistakeWhat HappensFix
Applying right after import without reading the planLive settings are modified to match incomplete codeIterate until the plan shows only the intended changes
Renaming a resource without a moved blockPlan destroys and recreates itAdd moved before applying the rename
Deleting a block to "stop managing"Terraform destroys the real resourceUse a removed block with destroy = false
Practice
  1. Create a bucket by hand, then import it with an import block and drive the plan to "no changes".
  2. Rename a resource in code and use a moved block so the plan shows zero destroys.
Key takeaways
  • import adopts existing resources; moved renames; removed releases.
  • After importing, the plan must be clean before you apply.
  • These blocks are reviewable code, unlike one-off state commands.
