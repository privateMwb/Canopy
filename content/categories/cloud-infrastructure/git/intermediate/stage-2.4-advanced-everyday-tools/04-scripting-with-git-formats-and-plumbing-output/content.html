Scripting With Git: Formats & Plumbing Output

Git's everyday commands are designed for people, so scripts should use stable, machine-readable output instead of parsing what a human would read.

§1Porcelain and Plumbing

Git distinguishes porcelain (friendly commands such as status, log, commit) from plumbing (low-level commands such as rev-parse, for-each-ref, rev-list, cat-file). Human output can change between versions or with your config, but plumbing and explicit machine formats are stable contracts.

§2Stable Output Options

git status --porcelain=v2 --branch     # fixed format for scripts, ignores user config
git status --porcelain -z                  # NUL-separated, safe for odd filenames
git rev-parse --show-toplevel              # path to the repository root
git rev-parse --abbrev-ref HEAD            # current branch name
git symbolic-ref --short HEAD              # branch name; errors when detached
git diff --name-only origin/main...HEAD    # changed files
git diff --numstat                         # added/removed lines per file, tab separated

§3Format Strings

--format (alias --pretty=format:) lets you pick exactly the fields you need.

git log --format='%h|%an|%ad|%s' --date=short -5
git for-each-ref --sort=-committerdate refs/heads/ \
  --format='%(refname:short) %(committerdate:relative) %(authorname)'
git shortlog -sn --no-merges                 # commit count per author
PlaceholderMeaning
%H / %hFull / short commit hash
%an, %aeAuthor name, email
%ad, %crAuthor date, relative commit date
%s, %bSubject, body

§4A Small Tool

#!/bin/sh
# stale-branches.sh: local branches with no commits in 90 days
set -eu
cutoff=$(date -d '90 days ago' +%s 2>/dev/null || date -v-90d +%s)
git for-each-ref refs/heads --format='%(refname:short) %(committerdate:unix)' |
while read -r name ts; do
  [ "$ts" -lt "$cutoff" ] && echo "$name"
done

Always check exit codes (set -e), quote variables, and handle filenames with spaces by using -z where available. Test the script on a repository with awkward names.

Never parse human output git status text, colors, and wording change with versions and settings. If a script depends on them, it will break. Use --porcelain, --format, or plumbing commands, which are documented stable interfaces.

§5Common Mistakes

MistakeWhat HappensFix
Parsing the output of git log or git statusScripts break on upgrade or with a different configUse --porcelain or --format
Assuming filenames have no spaces or quotesTruncated or misread pathsUse -z and NUL-aware tools
Using git branch output in a scriptIncludes a * marker and spacingUse git for-each-ref or git branch --format
Practice
  1. Write a one-liner using git for-each-ref that lists branches sorted by most recent commit, with author names.
  2. Write a script that prints the number of commits per author with git shortlog, then format it as CSV.
Key takeaways
  • Scripts should use porcelain flags, format strings, and plumbing commands, not human-readable output.
  • --format, for-each-ref, and rev-parse cover most scripting needs.
  • Use -z and quoting to survive odd filenames.
