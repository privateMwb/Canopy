Hooks, Linting & Branch Protection

Hooks run your checks automatically on your own machine, and branch protection enforces the rules on the server, because only the server cannot be skipped.

§1Local Hooks

A hook is a script Git runs at a chosen moment. Hooks live in .git/hooks/ and are not committed or shared, so each clone needs them installed. Useful ones:

HookRunsTypical use
pre-commitBefore a commit is createdLinting, formatting, secret scanning
commit-msgAfter you write a messageEnforce a message convention
pre-pushBefore pushingRun the fast tests
#!/bin/sh
# .git/hooks/pre-commit (make it executable: chmod +x)
npx eslint --max-warnings=0 $(git diff --cached --name-only --diff-filter=ACM | grep '\.js$') || {
  echo "Lint failed: fix the errors, or commit with --no-verify"; exit 1; }

A non-zero exit status blocks the commit. Developers can bypass hooks with --no-verify, so hooks are a convenience, not a guarantee.

§2Sharing Hooks With the Team

Since .git/hooks is not versioned, teams commit their hooks and point Git at them, or use a hook manager such as pre-commit, Husky, or Lefthook.

git config core.hooksPath .githooks     # use hooks committed in the repo
# or with a manager:
pre-commit install                         # reads .pre-commit-config.yaml

§3Branch Protection on the Server

Rules set on the hosting site apply to everyone and cannot be skipped with a flag. Typical settings for main:

  • Require a pull request before merging, and a minimum number of approving reviews
  • Require status checks (tests, lint, build) to pass, and the branch to be up to date
  • Block force pushes and branch deletion
  • Require signed commits or linear history, if the team wants them
  • Apply the rules to administrators too
Local hooks give fast feedback; the server gives certainty Run the quick checks in hooks so mistakes are caught in seconds. Repeat the important ones in CI and branch protection, since anyone can skip a local hook.

§4Common Mistakes

MistakeWhat HappensFix
Relying on hooks aloneA --no-verify commit slips throughEnforce the same checks in CI and protection rules
Slow pre-commit hooksPeople bypass them out of frustrationKeep them fast; move heavy tests to pre-push or CI
Hooks that exist only in one .git/hooksNobody else has themCommit hooks and set core.hooksPath, or use a hook manager
Practice
  1. Write a pre-commit hook that rejects any commit containing the text TODO-REMOVE, and prove it blocks a commit.
  2. List the branch protection rules you would apply to main for a team of five, and say which of them a hook cannot replace.
Key takeaways
  • Hooks automate local checks but can be skipped and are not shared by default.
  • Share hooks through core.hooksPath or a hook manager.
  • Branch protection on the server is the enforcement that cannot be bypassed.
