Interactive Rebase & Squashing

Interactive rebase lets you edit a branch's commits before review, reordering, rewording, dropping, and combining them into a clear story.

§1Starting an Interactive Rebase

git rebase -i opens a todo list of commits, oldest first. Name how far back to go, or give the branch you are rebasing onto.

git rebase -i HEAD~4          # the last four commits
git rebase -i origin/main      # everything since I branched from main
pick  a1b2c3d Add search endpoint
pick  b2c3d4e Fix typo
pick  c3d4e5f Add search tests
pick  d4e5f6a Oops, fix test again

§2The Commands

CommandEffect
pickKeep the commit as is
rewordKeep the changes, edit the message
editPause so you can change or split the commit
squashMerge into the previous commit and combine messages
fixupMerge into the previous commit and discard this message
dropDelete the commit entirely

Reordering lines reorders commits. Change a word, save, and close the editor; Git then replays the list.

pick   a1b2c3d Add search endpoint
fixup  b2c3d4e Fix typo
pick   c3d4e5f Add search tests
fixup  d4e5f6a Oops, fix test again
# result: two clean commits

§3Autosquash: Fixing As You Go

When you notice a mistake in an earlier commit, record it as a fixup and let Git fold it in later:

git commit --fixup a1b2c3d              # creates "fixup! Add search endpoint"
git rebase -i --autosquash origin/main   # lines the fixup right beneath its target
git config --global rebase.autoSquash true

Squashing before review turns "wip", "typo", and "oops" commits into a few meaningful ones. Do this only on commits that are not yet shared.

Rewrite before you share, not after Interactive rebase is for polishing your own private branch. If the commits are already in someone else's hands, leave them alone and add a new commit instead.

§4Common Mistakes

MistakeWhat HappensFix
Deleting a line in the todo listThat commit is dropped silentlyUse drop deliberately; abort with git rebase --abort if unsure
Squashing unrelated changes togetherCommits that mix several purposesCombine only commits belonging to one idea
Interactive-rebasing shared historyTeammates must reconcile rewritten commitsLimit it to unpublished or personal branches
Practice
  1. Make five messy commits with names like "wip" and "fix", then use rebase -i to squash them into two well-named commits.
  2. Use git commit --fixup and --autosquash to correct a typo in a commit three steps back.
Key takeaways
  • rebase -i lets you pick, reword, edit, squash, fixup, drop, and reorder commits.
  • --fixup with --autosquash folds later corrections into the right commit.
  • Polish only private commits; never rewrite shared history.
