Rebase vs. Merge

Rebase replays your commits on top of another branch to give a straight history, and it is safe only for commits nobody else has.

§1What Rebase Does

Merge joins two histories with a new commit. Rebase takes your commits, sets them aside, moves your branch to the new base, and replays your commits one by one on top.

before:  A ← B ← C   main          after rebase:  A ← B ← C ← D' ← E'   feature
              ↖ D ← E   feature

D' and E' are new commits with new hashes, because their parent changed.

git switch feature
git fetch origin
git rebase origin/main           # replay feature's commits onto the latest main
git rebase --continue            # after fixing a conflict
git rebase --abort               # back out completely

§2Merge or Rebase?

  • Rebase your own unpublished branch onto main to keep a linear, readable history before opening a PR.
  • Merge when you want to preserve exactly what happened, or when the branch is shared.
  • Resolving conflicts happens per replayed commit with rebase, and once with merge.

§3The Golden Rule

Never rebase commits that others have based work on. Rewriting shared history gives collaborators duplicate and conflicting commits.

git push --force-with-lease      # after rebasing your own pushed branch

--force-with-lease refuses to overwrite commits you have not seen, which is much safer than a plain --force.

The key insight Rebase changes commit identities. Use it freely on private work and never on history other people depend on.

§4Common Mistakes

MistakeWhat HappensFix
Rebasing main or a shared branchTeammates' histories diverge and conflictRebase only your private feature branches
Using git push --force after a rebaseYou may erase a teammate's new commitsUse --force-with-lease
Rebasing with a dirty working treeGit refuses or the state gets confusingCommit or stash first
Practice
  1. Rebase a two-commit feature branch onto an updated main and compare the log with a merge version.
  2. Cause a conflict in the second replayed commit and finish the rebase.
Key takeaways
  • Rebase replays commits onto a new base and creates new commits.
  • Prefer rebase for private branches and merge for shared ones.
  • Never rebase shared history, and use --force-with-lease when you must push.
