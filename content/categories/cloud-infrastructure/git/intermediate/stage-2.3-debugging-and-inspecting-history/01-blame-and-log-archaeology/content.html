Blame & Log Archaeology

git blame shows who last changed each line, and a few log options answer the harder question of when and why something appeared, changed, or vanished.

§1Blame: Who Last Touched This Line?

git blame annotates every line of a file with the commit, author, and date that last modified it. Despite the name, it is for finding context: follow the commit to its message and pull request to learn why.

git blame app.py                  # whole file
git blame -L 40,60 app.py         # only lines 40 to 60
git blame -w app.py               # ignore whitespace-only changes
git blame -C -C app.py            # detect lines moved or copied between files
git show a1b2c3d                  # then read the commit it points to

Big mechanical commits, such as a reformat, hide the real author. List them in a file and tell blame to skip them:

echo a1b2c3d4 >> .git-blame-ignore-revs     # the formatting commit
git config blame.ignoreRevsFile .git-blame-ignore-revs

§2The Pickaxe: When Did This Appear or Vanish?

-S finds commits that changed the number of occurrences of a string. -G finds commits whose diff matches a regular expression.

git log -S"calculate_tax" --oneline         # commits that added or removed this string
git log -G"timeout\s*=\s*\d+" --oneline    # commits whose diff matches the pattern
git log -S"calculate_tax" -p -- billing/    # include the diffs, limited to a folder

§3Following a Function or a Line Range

git log -L :calculate_tax:billing.py        # every change to one function
git log -L 40,60:app.py                      # every change to a line range
git log --follow -- docs/old-name.md         # history across renames
git log --diff-filter=D --name-only          # which files were deleted, and when
git log --since="2 weeks ago" --author="Ada" --stat
Blame finds the last change, not the origin The latest commit on a line may only be a rename or reformat. Use -w, -C, --follow, or the pickaxe to walk back to the commit that introduced the idea.

§4Common Mistakes

MistakeWhat HappensFix
Treating blame as a way to assign faultA culture of blaming people rather than understanding codeUse it to find context and ask questions
Stopping at a formatting commitThe real reason for the line stays hiddenUse -w, -C, or .git-blame-ignore-revs
Using -S and expecting line-level matchesIt only counts occurrence changes in a commitUse -G for regex matches in any changed line
Practice
  1. Pick a function in any repository and use git log -L :name:file to read its full history.
  2. Use git log -S to find the commit that first introduced a specific string, then read its message.
Key takeaways
  • git blame finds the last commit per line; the real insight is in that commit's message.
  • log -S and -G search history for when text appeared or changed.
  • log -L and --follow trace functions, ranges, and renames.
