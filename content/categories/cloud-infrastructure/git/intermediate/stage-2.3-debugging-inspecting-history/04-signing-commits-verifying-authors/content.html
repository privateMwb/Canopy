Signing Commits & Verifying Authors

Signing commits proves that they came from you, because a name and an email in a commit can be set to anything.

§1Why Sign

Anyone can run git config user.name "Someone Else", and commits will carry that name. A signature is cryptographic proof, checked against a public key, that the holder of a private key made the commit.

§2Signing With an SSH Key

Modern Git can sign with the same SSH key you already use.

git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true      # sign every commit
git commit -S -m "Fix rounding"              # or sign one commit
git tag -s v1.2.0 -m "Release 1.2.0"         # signed tag

Upload the public key to your host as a "signing key" so it shows a Verified badge. GPG keys also work and remain common.

§3Verifying

git log --show-signature -3
git verify-commit a1b2c3d
git verify-tag v1.2.0

For SSH signatures, set gpg.ssh.allowedSignersFile so Git knows which keys belong to whom.

§4What Signing Does and Does Not Prove

  • It proves the key holder made the commit.
  • It does not prove the code is safe, or that the key was not stolen.
  • Protect the private key with a passphrase or a hardware key.

§5Enforcing

Hosts can require signed commits on protected branches. Use that when provenance matters, for example for releases, regulated code, or widely used libraries.

The key insight Signing ties a commit to a key, and the key to a person. It guards against impersonation, not against bad code.

§6Common Mistakes

MistakeWhat HappensFix
Assuming the author name proves identityAnyone can set itSign commits and verify them
Signing but never uploading the public keyThe host shows commits as unverifiedRegister the signing key
Leaving the private key unprotectedA stolen key forges signaturesUse a passphrase or a hardware token
Practice
  1. Sign a commit and a tag, and verify both on the command line and on your host.
  2. Explain in three sentences what a signature proves and what it does not.
Key takeaways
  • Commit author fields are unauthenticated, while signatures are verifiable.
  • Git can sign with SSH or GPG keys, and hosts can display and enforce verification.
  • Protect the private key, since signing is only as strong as the key.
