Submodules, Subtrees & Large Files

Submodules and subtrees embed other repositories, and Git LFS keeps large binaries from bloating history.

§1Submodules

A submodule records a specific commit of another repository inside yours.

git submodule add https://github.com/example/lib.git vendor/lib
git commit -m "Add lib as submodule"
git clone --recurse-submodules https://github.com/you/app.git
git submodule update --init --recursive      # after a plain clone or pull
cd vendor/lib && git switch main && git pull # update it, then commit the new pointer in the parent

The parent repository stores only a pointer to a commit, so teammates must update submodules, which people forget.

§2Subtrees

git subtree copies another project's history into a subdirectory of yours, so clones need nothing special.

git subtree add --prefix=vendor/lib https://github.com/example/lib.git main --squash
git subtree pull --prefix=vendor/lib https://github.com/example/lib.git main --squash

Subtrees are simpler for consumers but make pushing changes back harder. Package managers (npm, pip, Go modules) are often a better answer than either.

§3Large Files

Git stores every version of every file forever, so large binaries make clones huge.

git lfs install
git lfs track "*.psd" "*.mp4"
git add .gitattributes
git lfs ls-files

LFS stores pointers in the repository and the real files on a separate server. Track large file types before committing them, because it will not shrink history that already holds them.

§4Choosing

Use a package manager when one exists, submodules for pinned third-party code you may edit, subtrees for simple vendoring, and LFS for large assets.

The key insight A submodule is a pointer to a commit, not a folder of code. Everyone must update it deliberately.

§5Common Mistakes

MistakeWhat HappensFix
Cloning without --recurse-submodulesThe submodule folder is emptyUse the flag or run git submodule update --init
Committing large binaries and adding LFS laterHistory stays bloatedTrack the patterns before the first commit, or rewrite history
Using submodules for ordinary dependenciesPainful for contributorsPrefer a package manager
Practice
  1. Add a submodule, clone the project elsewhere, and make sure the submodule contents appear.
  2. Track a large file type with LFS and compare repository size before and after.
Key takeaways
  • Submodules store a pointer to another repository's commit.
  • Subtrees copy another repository into a folder with its history.
  • Use LFS for large files, and set it up before committing them.
