Configuration, Aliases & Dotfiles

Git reads settings from three layers, and a few well-chosen options and aliases will save thousands of keystrokes and prevent common frustrations.

§1Three Levels of Config

Git settings come from three files, each overriding the one before it:

LevelFlagFileApplies to
System--system/etc/gitconfigEvery user on the machine
Global--global~/.gitconfigAll your repositories
Local--local (default).git/configOne repository only
git config user.email "me@work.example"        # local: only this repo
git config --global user.email "me@home.example"
git config --list --show-origin                  # every setting and the file it came from
git config --get user.email                       # the effective value here

A common use of the local level is a work email in work repositories and a personal email everywhere else.

§2Aliases

An alias is a custom short command stored in your config.

git config --global alias.st "status -sb"
git config --global alias.lg "log --oneline --graph --decorate --all"
git config --global alias.last "log -1 HEAD --stat"
git config --global alias.unstage "restore --staged"
git lg      # now runs the long log command

§3Useful Settings Worth Knowing

git config --global init.defaultBranch main
git config --global pull.ff only                 # refuse surprise merge commits on pull
git config --global push.autoSetupRemote true    # first push sets upstream automatically
git config --global fetch.prune true             # drop deleted remote branches on fetch
git config --global rerere.enabled true          # remember conflict resolutions
git config --global diff.colorMoved default

§4Dotfiles

Your ~/.gitconfig is a dotfile. Many developers keep their dotfiles in a Git repository of their own so a new machine can be set up in minutes. Never put tokens or private keys in it.

Check where a value comes from When Git behaves strangely, git config --list --show-origin shows every setting and its file. A forgotten local setting overriding your global one is a classic cause.

§5Common Mistakes

MistakeWhat HappensFix
Setting the wrong email in a repositoryCommits are attributed to an unintended identityUse the local level and verify with git config --get user.email
Aliases that hide dangerous commandsA short alias runs something destructive without thoughtKeep aliases for viewing; avoid aliasing reset --hard or push --force
Putting secrets in ~/.gitconfigLeaked if the dotfiles repo is sharedKeep credentials in a keychain or credential helper
Practice
  1. Create aliases for status, a graph log, and unstaging, and use each once.
  2. Set a different email for one repository only, and prove which value applies with git config --get user.email in two folders.
Key takeaways
  • Config layers are system, global, and local, with local winning.
  • Aliases shorten frequent commands; --show-origin explains where each setting came from.
  • A few settings (pull.ff, fetch.prune, rerere) prevent common annoyances.
