Branches Are Just Pointers

A branch is only a movable label on a commit, which is why creating one is instant and cheap.

§1What a Branch Is

A branch is a file containing the hash of one commit. When you commit, the current branch label moves forward to the new commit. HEAD points to the branch you are on.

A ← B ← C   main
          ↖
            D ← E   feature

Creating feature copies nothing. It just adds a new label at the current commit.

§2Working With Branches

git branch                      # list branches, * marks the current one
git switch -c feature/login     # create and move to a new branch
git switch main                 # move back
git branch -m old-name new-name # rename
git branch -d feature/login     # delete (refuses if unmerged)

git switch replaced the older git checkout for changing branches. Switching rewrites your working tree to match that branch's commit, so commit or stash edits first.

§3Why Branch

Branches isolate work in progress. You can fix a bug on main while a feature stays half-built on its own branch, then combine them when ready.

git log --oneline --graph --all
The key insight Branching is cheap, so use it freely: one branch per task keeps unfinished work away from working code.

§4Common Mistakes

MistakeWhat HappensFix
Working directly on main for everythingHalf-done work mixes with stable codeCreate a branch for each task
Switching branches with uncommitted editsGit may refuse, or edits come along unexpectedlyCommit or stash before switching
Thinking a branch is a copy of filesYou expect it to be heavyRemember it is a pointer to one commit
Practice
  1. Create two branches, make a commit on each, and draw the history from git log --graph --all.
  2. Find where HEAD points by reading .git/HEAD.
Key takeaways
  • A branch is a label pointing to one commit.
  • git switch -c creates and moves to a branch in one step.
  • Use branches to isolate each task.
