Resolving Merge Conflicts

A conflict means Git cannot decide between two edits to the same lines, and resolving it is a deliberate, learnable routine.

§1Why Conflicts Happen

If two branches change the same lines differently, or one deletes a file the other edits, Git stops and asks you to decide.

<<<<<<< HEAD
timeout = 30
=======
timeout = 60
>>>>>>> feature/login

Above ======= is your current branch, and below is the branch being merged. Edit the file to the final text you want and delete all three marker lines.

§2The Routine

git merge feature/login        # reports CONFLICT in config.py
git status                     # lists "both modified" files
# edit config.py, remove markers, keep the right result
git add config.py              # mark as resolved
git commit                     # finish the merge
git merge --abort              # give up and return to before the merge
git checkout --ours config.py  # keep your version of the file
git checkout --theirs config.py   # keep the other branch's version

§3After Resolving

Run your tests: a clean-looking merge can still be wrong. A merge tool or editor with a three-way view helps (git mergetool).

§4Reducing Conflicts

Merge main into your branch often, keep branches short, and avoid reformatting whole files in a feature branch.

The key insight Resolving a conflict means choosing the correct final content, not choosing a side. Often the answer combines both.

§5Common Mistakes

MistakeWhat HappensFix
Leaving conflict markers in the fileBroken code gets committedSearch for <<<<<<< before git add
Choosing a whole side blindlyOne person's work is silently droppedRead both changes and combine them
Panicking mid-mergeMistakes while confusedUse git merge --abort and start again calmly
Practice
  1. Create a conflict on purpose, resolve it by combining both edits, and run git log --graph to see the merge.
  2. Start a conflicting merge, abort it, and confirm the repository is back as it was.
Key takeaways
  • Conflict markers show your side above and theirs below.
  • Resolve by editing, then git add, then git commit.
  • git merge --abort is always available.
