Branch Naming, Cleanup & Tags

Consistent branch names keep a repository navigable, deleting merged branches keeps it tidy, and tags give important commits permanent names like v1.0.

§1Naming Conventions

Good names say what the branch is for. Many teams use a short prefix, a slash, and a lowercase hyphenated description, often including a ticket number.

feature/user-login
fix/cart-total-rounding
chore/update-dependencies
fix/PROJ-482-empty-search-crash

Avoid spaces, uppercase confusion, and vague names like test or new-stuff. The convention matters less than everyone following the same one.

§2Cleaning Up

After a branch is merged, its pointer is no longer needed. The commits stay in history; only the label goes away.

git branch --merged              # branches already merged into the current one
git branch -d feature/user-login   # delete safely: refuses if not merged
git branch -D experiment           # force delete: you lose the only label to those commits
git branch -m old-name new-name    # rename

§3Tags: Permanent Labels

A branch label moves as you commit. A tag is a label that stays on one commit forever, used to mark releases. An annotated tag stores a message, author, and date, and is the right choice for releases.

git tag v1.0.0                       # lightweight tag at the current commit
git tag -a v1.0.0 -m "First stable release"   # annotated tag
git tag                              # list tags
git show v1.0.0                      # see the tag and its commit
git tag -a v0.9.0 a1b2c3d            # tag an older commit

Tags are not pushed by default. Share them explicitly, as the remotes stage shows: git push origin v1.0.0.

Deleting a branch rarely deletes work git branch -d only removes the label. If the commits were merged, they remain in history. The risky one is -D on an unmerged branch, since those commits become hard to find again.

§4Common Mistakes

MistakeWhat HappensFix
Vague names like test2Nobody knows what a branch is for or whether it can be deletedUse a prefix and a descriptive slug
Using -D out of habitUnmerged commits lose their only nameUse -d, which refuses when work would be lost
Using lightweight tags for releasesNo message, author, or date recordedUse git tag -a with a message
Practice
  1. Rename a poorly named branch to follow a prefix convention, merge it, and delete it with -d.
  2. Tag the current commit as v1.0.0 with an annotated tag, then use git show to inspect it.
Key takeaways
  • Use consistent, descriptive branch names with a short prefix.
  • Delete merged branches with -d; the commits stay in history.
  • Annotated tags give releases a permanent, documented name.
