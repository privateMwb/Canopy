Ignoring Files & Undoing Simple Mistakes

A .gitignore keeps junk out of history, and a few safe commands undo small mistakes before they spread.

§1Ignoring Files

Create a .gitignore file in the repository root listing patterns Git should not track.

node_modules/
*.log
.env
build/
.DS_Store
!important.log

Ignore dependencies, build output, editor files, logs, and secrets such as .env. A leading ! re-includes a file. Ignoring only affects untracked files: a file already committed stays tracked.

git rm --cached secret.env     # stop tracking, keep the file on disk
git check-ignore -v build/app.js   # why is this ignored?

§2Undoing Small Mistakes

git restore file.txt                 # discard unstaged changes to a file
git restore --staged file.txt        # unstage, keep the edits
git commit --amend -m "Better message"   # rewrite the LAST commit
git commit --amend --no-edit         # add staged changes to the last commit

git restore on unstaged edits is permanent: those changes were never saved in Git. Amending replaces the last commit, so only do it before you have shared it.

§3A Useful Safety Habit

Before any destructive command, run git status and ask whether the work exists anywhere else. Committed work is very hard to lose, while uncommitted work is easy to lose.

The key insight Commit early and often. Anything committed can almost always be recovered, and anything uncommitted may not be.

§4Common Mistakes

MistakeWhat HappensFix
Adding .env to .gitignore after committing itThe secret is still in historyRemove it from history and rotate the secret (Stage 1.3)
Using git restore on work you wantedUnstaged edits are gone for goodCommit or stash first if unsure
Amending a commit that is already pushedOthers' copies now conflict with yoursOnly amend unshared commits
Practice
  1. Add a .gitignore, create an ignored file and a tracked file, and confirm with git status.
  2. Make a typo in a commit message, fix it with --amend, and view the result with git log.
Key takeaways
  • .gitignore keeps generated files and secrets out, but only for untracked files.
  • restore discards edits, restore --staged unstages, and --amend fixes the last commit.
  • Committed work is safe; uncommitted work needs care.
