Installing, Configuring & Your First Commit

Install Git, tell it who you are, then create a repository and make your first commit with init, add, and commit.

§1Installing and Setting Your Identity

Check whether Git is already installed, and install it if not. On macOS, git --version offers to install the developer tools; on Windows, use Git for Windows; on Linux, use your package manager.

git --version               # confirm it is installed
sudo apt install git         # Debian/Ubuntu
brew install git             # macOS with Homebrew

Every commit records an author, so set your name and email once. The --global flag stores them for your user account across all repositories.

git config --global user.name "Ada Lovelace"
git config --global user.email "ada@example.com"
git config --global init.defaultBranch main   # name new branches main
git config --list                              # review your settings

§2Creating a Repository

git init turns a folder into a repository by creating a hidden .git directory that holds the entire history. Delete .git and the folder goes back to being plain files, so never delete it by accident.

mkdir recipes && cd recipes
git init                     # creates the .git directory
git status                   # shows: On branch main, no commits yet

§3Add, Then Commit

Create a file, stage it, and commit. The -m flag supplies the message inline.

echo "# My Recipes" > README.md
git status                   # README.md is untracked
git add README.md            # stage it
git commit -m "Add README with project title"
git log --oneline            # one line per commit

A file is untracked until you first add it, then tracked from then on. To stage everything changed in the current folder, use git add ., but check git status first so you do not stage something you did not intend.

Your identity is not your login user.name and user.email only label your commits. They are not credentials, and anyone can type any value. Hosting sites match the email to an account to show your avatar, so use the address registered there.

§4Common Mistakes

MistakeWhat HappensFix
Skipping the identity setupGit warns it guessed a name, and commits carry a wrong or ugly authorSet user.name and user.email once with --global
Running git init in the wrong folderA repository appears inside your home directory or inside another repoRun pwd first, and check for an existing .git folder
Using git add . without lookingStray or secret files get stagedRun git status before and after adding
Practice
  1. Install Git, set your name, email, and default branch, then print your configuration to confirm.
  2. Create a new folder, initialize a repository, add two files, and make two separate commits, one per file.
Key takeaways
  • Set your name and email once with git config --global.
  • git init creates a repository; the history lives in the .git folder.
  • The basic cycle is edit, git add, git commit.
