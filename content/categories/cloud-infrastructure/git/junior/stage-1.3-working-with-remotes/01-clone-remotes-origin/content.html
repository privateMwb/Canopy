Clone, Remotes & Origin

A remote is a named link to another copy of the repository, and cloning is how you get your first copy.

§1Cloning

git clone https://github.com/example/project.git
git clone git@github.com:example/project.git my-folder
cd project
git log --oneline | head

Cloning downloads the full history and sets up a remote named origin pointing back to where it came from.

§2Remotes

git remote -v                         # list remotes and their URLs
git remote add upstream https://github.com/original/project.git
git remote rename origin github
git remote remove upstream

A remote is just a name and a URL. You can have several: for example origin for your fork and upstream for the original project.

§3Remote-Tracking Branches

After a clone, origin/main is a read-only bookmark of where main was on the remote the last time you talked to it.

git branch -a                         # local and remote-tracking branches
git log main..origin/main             # commits on the remote you do not have

Your local main and origin/main are different pointers that can drift apart until you fetch, push, or pull.

§4The Mental Model

There is no central copy that is more real than the others. Hosted services such as GitHub are simply agreed meeting points that everyone pushes to and pulls from.

The key insight origin/main is your last known snapshot of the remote, not live data. It only updates when you fetch.

§5Common Mistakes

MistakeWhat HappensFix
Thinking origin/main updates automaticallyYou compare against stale informationRun git fetch first
Cloning with one URL type and failing authenticationPermission denied errorsUse the URL style (HTTPS or SSH) that you have set up credentials for
Adding a remote with a typoPushes fail or go to the wrong placeCheck with git remote -v
Practice
  1. Clone a repository, list its remotes, and find the commit where origin/main points.
  2. Add a second remote and explain why a team might need two.
Key takeaways
  • Cloning copies the full history and creates the origin remote.
  • A remote is a named URL, and remote-tracking branches are local bookmarks of it.
  • No copy is special: the hosted one is an agreement, not a rule.
