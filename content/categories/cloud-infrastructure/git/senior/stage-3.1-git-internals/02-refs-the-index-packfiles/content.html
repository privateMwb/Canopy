Refs, the Index & Packfiles

Branches are small files, the index is a data structure, and packfiles compress many objects into deltas.

§1Refs

A ref is a name pointing to a hash.

cat .git/HEAD                        # ref: refs/heads/main
cat .git/refs/heads/main             # a commit hash
cat .git/packed-refs                 # many refs packed into one file
git for-each-ref --format='%(refname) %(objectname:short)'
git symbolic-ref HEAD                # refs/heads/main

Branches live in refs/heads, remote-tracking branches in refs/remotes, and tags in refs/tags. HEAD is usually a symbolic ref to a branch. A detached HEAD holds a commit hash directly.

§2The Index

The staging area is a binary file, .git/index, listing every tracked path with its mode, blob hash, and file-system metadata (timestamps, size). Git compares that metadata to detect changes quickly, without re-reading every file.

git ls-files --stage                 # contents of the index
git ls-files -u                      # during a conflict: the three stages (base, ours, theirs)

During a merge conflict the index holds up to three versions of a file, which is how --ours and --theirs work.

§3Packfiles

New objects begin as individual loose files. Periodically, Git packs them into a .pack file with an .idx index, storing similar objects as deltas against each other, so a repository can be far smaller than the sum of its versions.

git count-objects -vH                # loose vs. packed sizes
git gc                               # repack and prune
git verify-pack -v .git/objects/pack/pack-*.idx | head

Pushing and fetching send thin packs: only the objects the other side lacks.

The key insight Branch, tag, and HEAD are all just names for hashes. Moving a branch is writing 41 bytes to a file.

§4Common Mistakes

MistakeWhat HappensFix
Editing files in .git by handYou can corrupt refs or the indexUse git update-ref and other plumbing commands
Expecting loose objects to stay small foreverRepositories grow until packedLet git gc run, or run it after large imports
Confusing detached HEAD with an errorPanic when switching to a tag or commitCreate a branch if you want to keep new commits
Practice
  1. Inspect .git/HEAD, a branch ref, and the index of a small repository, and describe each.
  2. Compare git count-objects -vH before and after git gc on a repository with many commits.
Key takeaways
  • Refs map names to hashes, and HEAD usually points to a branch.
  • The index is a binary table that also stores conflict stages during merges.
  • Packfiles store objects as deltas for compact storage and efficient transfer.
