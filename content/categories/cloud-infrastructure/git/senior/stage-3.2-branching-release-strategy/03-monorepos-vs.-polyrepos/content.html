Monorepos vs. Polyrepos

A monorepo and many small repositories each solve real problems and create others, and Git has features that make big repositories workable.

§1Monorepo

All projects live in one repository.

  • Pros: atomic cross-project changes, shared tooling, easy refactoring, one place for versions and standards.
  • Cons: needs build tooling that builds only what changed, access control is coarser, and Git itself slows down at scale.

§2Polyrepo

One repository per service or library.

  • Pros: clear ownership, independent release cycles, simpler access control, fast clones.
  • Cons: cross-repo changes need coordinated pull requests, dependency versions drift, and shared tooling is duplicated.

§3Making Big Repositories Workable

git clone --filter=blob:none --sparse https://example.com/big.git   # partial clone, sparse checkout
cd big && git sparse-checkout set services/payments libs/common
git sparse-checkout list
git clone --depth 1 https://example.com/big.git        # shallow clone for CI
git config core.fsmonitor true
git config feature.manyFiles true

Partial clones fetch file contents on demand, sparse checkout materializes only chosen directories, and shallow clones truncate history.

§4Tooling Needs

Monorepos need affected-target builds and caching (Bazel, Nx, Turborepo, Pants), code owners per directory, and CI that runs only relevant tests.

§5Choosing

The decision is mostly about organization: how teams own code and how often changes cross boundaries. Do not adopt a monorepo without the tooling to support it.

The key insight Monorepo versus polyrepo is a choice about coordination cost. Pick the one that matches how your teams actually change code together.

§6Common Mistakes

MistakeWhat HappensFix
Moving to a monorepo with no build toolingEvery change rebuilds and retests everythingAdopt affected-target builds first
Splitting into many repos but sharing code by copyingVersions driftPublish shared libraries as versioned packages
Full clones in CI of a huge repositorySlow pipelinesUse shallow or partial clones
Practice
  1. Practice a partial clone with sparse checkout and compare size and time against a full clone.
  2. List three changes in your organization that cross project boundaries and estimate the cost in each model.
Key takeaways
  • Monorepos reduce coordination across projects and demand tooling and scale features.
  • Polyrepos give isolation and ownership and cost cross-repo coordination.
  • Partial clone, sparse checkout, and shallow clones keep big repositories usable.
