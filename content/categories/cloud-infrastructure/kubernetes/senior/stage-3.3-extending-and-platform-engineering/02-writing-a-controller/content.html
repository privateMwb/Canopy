Writing a Controller

Writing a controller means writing one idempotent reconcile function and letting a framework handle watching, caching, and queueing.

§1The Shape of a Controller

A controller watches objects, and for each change calls a reconcile function with the object's name. The function reads the desired state, observes the actual state, and makes one step toward convergence. It must be:

  • Idempotent: running it twice with no change does nothing the second time.
  • Level-based: it computes from current state rather than depending on which event triggered it.
  • Safe to retry: failures return an error, and the framework requeues with backoff.

§2Frameworks

  • client-go: the low-level Go client with informers, listers, and work queues. Flexible and verbose.
  • controller-runtime: higher-level library with managers, caches, and a clean reconciler interface. Used by most operators.
  • Kubebuilder and Operator SDK: scaffolding and code generation (CRD manifests from Go types, RBAC markers) on top of controller-runtime.
  • Operators can also be written in other languages (Python with Kopf, Java with the Java Operator SDK), and simple cases can use Helm or Ansible-based operators.
kubebuilder init --domain example.com --repo github.com/myorg/backup-operator
kubebuilder create api --group data --version v1 --kind Backup
make manifests generate       # regenerate CRDs and deepcopy code
make install run              # install CRDs and run locally against your cluster

§3A Reconciler

func (r *BackupReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
    var backup datav1.Backup
    if err := r.Get(ctx, req.NamespacedName, &backup); err != nil {
        return ctrl.Result{}, client.IgnoreNotFound(err)   // deleted: nothing to do
    }

    // Desired: a CronJob that runs the backup
    desired := buildCronJob(&backup)
    if err := ctrl.SetControllerReference(&backup, desired, r.Scheme); err != nil {
        return ctrl.Result{}, err
    }

    var existing batchv1.CronJob
    err := r.Get(ctx, client.ObjectKeyFromObject(desired), &existing)
    switch {
    case apierrors.IsNotFound(err):
        err = r.Create(ctx, desired)
    case err == nil && !equality.Semantic.DeepEqual(existing.Spec, desired.Spec):
        existing.Spec = desired.Spec
        err = r.Update(ctx, &existing)
    }
    if err != nil {
        return ctrl.Result{}, err                          // requeue with backoff
    }

    backup.Status.Phase = "Scheduled"
    return ctrl.Result{}, r.Status().Update(ctx, &backup)
}

In SetupWithManager, .For(&Backup{}).Owns(&batchv1.CronJob{}) tells the framework to also reconcile when the owned CronJob changes.

§4Essential Techniques

  • Owner references make Kubernetes garbage-collect created objects when the parent is deleted.
  • Finalizers let your controller run cleanup (deleting an external resource) before the object is removed: the object stays in Terminating until you remove the finalizer.
  • Status conditions (type, status, reason, message) report progress in a standard form that tools and humans can read.
  • Leader election lets you run several replicas with only one active.
  • Events (r.Recorder.Event) surface what the controller did in kubectl describe.
  • Avoid hot loops: return RequeueAfter for periodic work rather than immediate retries.

§5Testing

Use envtest, which runs a real API server and etcd locally, to test reconciliation against the real API without a full cluster, and add end-to-end tests with kind.

Never assume the cache is fresh Reads come from a local cache that may lag behind writes. Conflicts (resourceVersion mismatches) are normal; return the error and let the retry handle it.

§6Common Mistakes

MistakeWhat HappensFix
Reconcile that is not idempotentRetries create duplicates or loopsCompute desired state and compare it to actual state
Forgetting owner referencesChild objects leak after the parent is deletedSet a controller reference on everything you create
Finalizer that can fail foreverObjects stick in TerminatingMake cleanup retry-safe and handle already-missing external resources
Practice
  1. Scaffold a project with kubebuilder, implement a reconciler that creates a ConfigMap for each custom object, and verify deletion cleans it up.
  2. Add a finalizer that logs a message before the object is removed.
Key takeaways
  • A controller is an idempotent, level-based reconcile function driven by watches.
  • controller-runtime and kubebuilder provide caching, queues, and scaffolding.
  • Owner references, finalizers, status conditions, and envtest are the core techniques.
