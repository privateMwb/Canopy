Custom Resources & Operators

Custom Resource Definitions add new object types to the Kubernetes API, and operators pair them with controllers that encode the operational knowledge of running a piece of software.

§1Extending the API

A CustomResourceDefinition (CRD) teaches the API server a new kind. Once registered, the new kind behaves like built-in ones: you can kubectl get it, protect it with RBAC, store it in Git, and watch it.

apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: backups.data.example.com
spec:
  group: data.example.com
  scope: Namespaced
  names:
    kind: Backup
    plural: backups
    singular: backup
    shortNames: ["bk"]
  versions:
    - name: v1
      served: true
      storage: true
      subresources:
        status: {}
      schema:
        openAPIV3Schema:
          type: object
          properties:
            spec:
              type: object
              required: ["database", "schedule"]
              properties:
                database: { type: string }
                schedule: { type: string }
                retentionDays: { type: integer, minimum: 1, default: 7 }
            status:
              type: object
              x-kubernetes-preserve-unknown-fields: true

Then a user creates an instance:

apiVersion: data.example.com/v1
kind: Backup
metadata:
  name: orders-nightly
spec:
  database: orders
  schedule: "0 2 * * *"

A CRD alone only stores data. Nothing happens until a controller acts on it.

§2Schema and Validation

The OpenAPI schema validates objects at admission, with types, required fields, enums, and defaults. CEL validation rules (x-kubernetes-validations) express cross-field rules directly in the CRD, with no webhook. Define a status subresource so controllers can update status without modifying spec, and keep spec (what the user wants) cleanly separate from status (what the controller observed).

§3What an Operator Is

An operator is a CRD plus a controller that manages a complex application the way a human expert would: install, configure, scale, back up, fail over, and upgrade. Examples:

OperatorWhat it manages
cert-managerCertificates, issued and renewed from Let's Encrypt or private CAs
Prometheus OperatorPrometheus servers, alert rules, and monitors
CloudNativePG / Zalando Postgres operatorPostgreSQL clusters, replicas, failover, backups
StrimziKafka clusters and topics
CrossplaneCloud resources (databases, buckets) as Kubernetes objects

The user declares kind: PostgresCluster with three instances, and the operator creates StatefulSets, Services, Secrets, and handles failover, which is the "desired state" model applied to application-level concerns.

§4Operating CRDs

  • Versioning: CRDs support multiple versions with conversion between them; deleting a CRD deletes every instance, so protect them.
  • Installing: Helm charts install CRDs in a special crds/ directory and do not upgrade them automatically, so manage CRD upgrades deliberately.
  • Many CRDs add load on the API server and etcd; avoid creating hundreds of thousands of custom objects casually.
Operators are code you operate An operator runs with broad permissions and holds your data's lifecycle. Evaluate maturity, update cadence, and how it behaves when it is down or misconfigured, as you would a database vendor.

§5Common Mistakes

MistakeWhat HappensFix
Deleting a CRD casuallyEvery instance and its data declarations vanishRestrict RBAC and back up CRs
CRD with no schema validationGarbage input is accepted and breaks the controllerDefine a structural schema and CEL rules
Writing status into specUsers and controllers overwrite each otherUse the status subresource for observed state
Practice
  1. Apply the CRD above and create a Backup object; confirm kubectl get backups works and nothing else happens.
  2. List what a controller for Backup would need to watch, create, and update.
Key takeaways
  • CRDs add new kinds to the API with schema validation and RBAC for free.
  • An operator is a CRD plus a controller encoding operational knowledge.
  • Manage CRD versions and lifecycle with care; deleting a CRD deletes its objects.
