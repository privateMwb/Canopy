Storage Classes, Dynamic Provisioning & Snapshots

StorageClasses create volumes on demand, and snapshots give you point-in-time copies for backup and cloning.

§1Dynamic Provisioning

Instead of an admin pre-creating volumes, a StorageClass describes how to create one when a claim appears. The class names a provisioner (usually a CSI driver for a cloud disk or storage system) and its parameters.

apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-ssd
provisioner: ebs.csi.aws.com
parameters:
  type: gp3
reclaimPolicy: Delete
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer

A PVC then asks for the class by name:

spec:
  storageClassName: fast-ssd
  accessModes: ["ReadWriteOnce"]
  resources:
    requests:
      storage: 50Gi

A claim that omits the class uses the cluster's default StorageClass (marked with an annotation).

§2Settings That Matter

FieldWhy it matters
volumeBindingMode: WaitForFirstConsumerDelays creation until a pod is scheduled, so the disk is created in the same zone as the pod
reclaimPolicyDelete removes the disk with the claim; Retain keeps it
allowVolumeExpansionLets you grow a volume by editing the PVC's size
parametersProvider-specific options such as disk type or IOPS

Zone matters because a cloud disk exists in one zone and can only attach to nodes there. With Immediate binding, a volume can be created in a zone where the pod cannot run, leaving it Pending.

Volumes can be expanded but not shrunk. Resize by editing spec.resources.requests.storage on the PVC.

§3Snapshots

With the CSI snapshot add-on installed, you create a point-in-time copy through API objects:

apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshot
metadata:
  name: db-before-upgrade
spec:
  volumeSnapshotClassName: csi-snapclass
  source:
    persistentVolumeClaimName: data-db-0

A new PVC can then be created from that snapshot using dataSource, which gives you a clone or a restore. Snapshots are storage-level and usually crash-consistent; for databases, combine them with application-level backups and test restores regularly.

A snapshot is not a backup by itself Many snapshots live in the same storage system as the volume. If that system fails or the account is lost, so are the snapshots. Copy backups elsewhere.

§4Common Mistakes

MistakeWhat HappensFix
Immediate binding in a multi-zone clusterDisk is created in a zone with no suitable nodeUse WaitForFirstConsumer
Using Delete reclaim for precious dataDeleting a PVC destroys the diskUse Retain or maintain backups
Trusting snapshots without restore testsYou discover problems during an outagePractice restoring on a schedule
Practice
  1. Create a StorageClass with WaitForFirstConsumer and watch the PVC stay Pending until a pod uses it.
  2. Expand a PVC and confirm the new size inside the pod.
Key takeaways
  • StorageClasses plus CSI drivers create volumes on demand.
  • Binding mode, reclaim policy, and expansion settings control placement and safety.
  • Snapshots help, but real backups need independence and tested restores.
