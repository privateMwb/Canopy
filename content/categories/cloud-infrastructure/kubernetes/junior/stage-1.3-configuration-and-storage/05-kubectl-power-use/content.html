kubectl Power Use

A few kubectl output and editing features turn it from a viewer into a fast, scriptable tool for inspecting and changing a cluster.

§1Output Formats

kubectl get pods -o wide                  # adds node and pod IP
kubectl get pod web -o yaml               # the full live object
kubectl get pods -o name                  # just kind/name, handy for scripts
kubectl get pods --sort-by=.metadata.creationTimestamp
kubectl get pods --field-selector=status.phase=Running

§2JSONPath and Custom Columns

When you need one field, extract it instead of scanning YAML:

kubectl get pod web -o jsonpath='{.status.podIP}'
kubectl get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.nodeName}{"\n"}{end}'
kubectl get pods -o custom-columns=NAME:.metadata.name,NODE:.spec.nodeName,IMAGE:.spec.containers[0].image

jsonpath shines in scripts; custom-columns gives readable tables. Pair with jq when you need heavier filtering: kubectl get pods -o json | jq '.items[].metadata.name'.

§3Changing Objects Precisely

kubectl patch deployment web -p '{"spec":{"replicas":4}}'
kubectl patch deployment web --type=json \
  -p='[{"op":"replace","path":"/spec/replicas","value":4}]'
kubectl set image deployment/web nginx=nginx:1.28
kubectl label pod web-1 tier=frontend
kubectl annotate pod web-1 owner=team-a
kubectl rollout restart deployment/web

patch changes only the fields you name. The default merge patch is easiest; --type=json is exact and good for list edits.

§4Diff, Dry-Run, and Server-Side Apply

kubectl diff -f web.yaml                      # preview against the live object
kubectl apply -f web.yaml --dry-run=server    # validated by the real API server
kubectl apply -f web.yaml --server-side       # field ownership tracked by the server

--dry-run=server is stronger than client because admission rules and the true schema are checked. Server-side apply records which manager owns which field, which reduces conflicts when several tools touch one object.

§5Plugins and Convenience

  • Plugins are executables named kubectl-<name> on your PATH. The krew plugin manager installs many, such as ctx, ns, and neat.
  • kubectl explain, kubectl api-resources, and shell completion (source <(kubectl completion zsh)) save constant lookups.
  • Aliases such as k=kubectl are worth setting up.
Safety habit For any change you did not just write, run kubectl diff first, and for anything destructive, double-check kubectl config current-context.

§6Common Mistakes

MistakeWhat HappensFix
Parsing kubectl get table text in scriptsColumn formats change and break the scriptUse -o json or -o jsonpath
Patching with the wrong strategyLists are replaced instead of mergedUse a JSON patch for precise list edits
Skipping diff before applyUnexpected fields change in productionMake diff plus dry-run=server part of the routine
Practice
  1. Print every pod name with its node using a single jsonpath command.
  2. Change a Deployment's replica count with patch, then confirm with kubectl get deploy -o jsonpath.
Key takeaways
  • -o yaml, jsonpath, and custom-columns extract exactly what you need.
  • patch, diff, and --dry-run=server change and verify objects safely.
  • Plugins and completion make daily use faster.
