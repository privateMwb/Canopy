Dashboards & Quality-of-Life Tools

A few terminal and desktop tools make daily Kubernetes work faster and safer once you understand the commands underneath.

§1Why Bother

After the basics, most time goes to looking around: switching clusters, finding a pod, reading logs, checking events. The right tools remove friction from that loop. They are conveniences, not replacements; learn the raw kubectl first so you understand what the tools do for you.

§2Tools Worth Knowing

ToolWhat it gives you
k9sA terminal UI: browse pods, tail logs, exec, delete, and switch namespaces with keystrokes
Lens / OpenLensA desktop app with a graphical view of clusters, workloads, and metrics
kubectx and kubensFast switching of context and namespace
sternTails logs from many pods at once, with colors
kubectl krewA plugin manager that installs community kubectl plugins
kubecolorColors kubectl output for readability
kubectx staging           # switch cluster
kubens shop               # switch default namespace
stern -n shop web         # follow logs from every pod matching "web"
k9s                       # launch the terminal UI

§3A Comfortable Daily Workflow

  • Aliases and completion: alias k=kubectl, plus shell completion for resource names.
  • A prompt that shows context and namespace, so you always see which cluster a command will hit. Tools like starship or kube-ps1 do this.
  • Separate kubeconfig files per environment, combined through the KUBECONFIG variable or kubectx, so production is never one typo away.
  • Read-only access for routine work: use an account that can only view production, and elevate only for changes.
alias k=kubectl
source <(kubectl completion zsh)
complete -o default -F __start_kubectl k    # bash: completion for the alias
export KUBECONFIG=~/.kube/dev:~/.kube/prod
Tools hide, commands teach A GUI that deletes a pod with one click does the same thing as kubectl delete pod. If you cannot do the task with plain kubectl, you will be stuck the day the tool is not installed on the jump host.

§4Common Mistakes

MistakeWhat HappensFix
Relying only on a GUIYou cannot work over SSH or in a minimal environmentLearn the kubectl equivalents of what you click
No visible context in the promptYou run a command against production by accidentShow context and namespace in the prompt
One kubeconfig with full admin everywhereEvery command can change productionSeparate configs and prefer read-only credentials
Practice
  1. Install k9s, open a pod's logs, and then do the same with kubectl logs.
  2. Set up a prompt or alias so your current context is always visible.
Key takeaways
  • k9s, Lens, kubectx, stern, and krew make daily work faster.
  • Visible context, aliases, and separated kubeconfigs prevent costly mistakes.
  • Keep the underlying kubectl commands in your head; tools are a convenience.
