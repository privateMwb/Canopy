kubectl & a Local Cluster

A local cluster on your laptop plus a handful of kubectl commands is enough to practice almost everything in the Junior level.

§1Getting a Local Cluster

You do not need cloud infrastructure to learn. Several tools run a real, small cluster on your machine:

ToolHow it worksGood for
minikubeA VM or container holding a single-node clusterBeginners; many built-in add-ons
kind"Kubernetes in Docker": nodes are containersFast, throwaway clusters; CI; multi-node tests
k3d / k3sA lightweight distribution, optionally in DockerLow memory use
Docker DesktopA built-in single-node cluster toggleZero extra install on Mac and Windows

Any of them is fine. The examples here use kind:

kind create cluster --name learn
kubectl cluster-info --context kind-learn
kubectl get nodes

§2kubectl: The Everyday Commands

kubectl is the command line client for the API server. It reads connection details and credentials from a kubeconfig file, normally ~/.kube/config, which can hold several clusters and a current context (which cluster and user to use right now).

kubectl config get-contexts          # which clusters do I know about?
kubectl config current-context       # which one am I pointed at?
kubectl get pods                     # list pods in the current namespace
kubectl get pods -A                  # all namespaces
kubectl describe pod <name>          # details plus recent events
kubectl logs <pod>                   # container output
kubectl exec -it <pod> -- sh         # a shell inside the container
kubectl delete pod <name>

The pattern is always kubectl <verb> <resource> [name] [flags]. Two verbs earn their keep: get for a quick list and describe for the story behind one object, including the Events section at the bottom where scheduling and startup problems show up.

§3Try a Quick Pod

kubectl run hello --image=nginx
kubectl get pods -w                  # -w watches changes; Ctrl+C to stop
kubectl delete pod hello

kubectl run is handy for experiments, but later lessons replace it with manifest files, which is how real work is done.

Check your context The most expensive kubectl mistake is running a command against the wrong cluster. Run kubectl config current-context before anything destructive, and consider a prompt that shows it.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting the namespaceget pods returns nothing and you assume nothing runsUse -n <namespace> or -A to look across all of them
Running commands against the wrong contextYou delete or change something in a shared clusterCheck current-context first; name local clusters clearly
Using kubectl run for everythingNothing is recorded, so it cannot be reproducedMove to YAML manifests as soon as the experiment works
Practice
  1. Create a local cluster with your chosen tool and list its nodes.
  2. Run an nginx pod, find its IP with kubectl describe, then delete it.
Key takeaways
  • kind, minikube, k3d, and Docker Desktop all give you a real local cluster.
  • kubectl follows verb resource name, and get plus describe answer most questions.
  • Always know which context and namespace a command will hit.
