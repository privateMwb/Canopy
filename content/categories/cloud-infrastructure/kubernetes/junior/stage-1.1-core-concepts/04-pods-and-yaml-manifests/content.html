Pods & YAML Manifests

A pod is the smallest thing Kubernetes runs, and a YAML manifest is how you describe it.

§1What a Pod Is

A pod wraps one or more containers that must run together. They share a network identity (one IP address, so they reach each other on localhost) and can share storage volumes. Most pods hold a single application container. Kubernetes schedules whole pods, never individual containers, and all containers in a pod land on the same node.

Pods are ephemeral. When one dies it is not repaired in place; it is replaced by a new pod with a new IP. That is the reason higher-level objects like Deployments, covered next stage, exist.

§2Reading a Manifest

Kubernetes objects are described in YAML. This is a complete pod:

apiVersion: v1
kind: Pod
metadata:
  name: web
  labels:
    app: web
spec:
  containers:
    - name: nginx
      image: nginx:1.27
      ports:
        - containerPort: 80

Every manifest has the same four top-level fields:

FieldMeaning
apiVersionWhich version of which API group defines this kind
kindThe type of object: Pod, Deployment, Service, and so on
metadataIdentity: name, namespace, labels, annotations
specThe desired state, whose shape depends on the kind

Objects also get a status field, filled in by Kubernetes, describing what is actually true right now. You write spec; the cluster writes status.

§3Applying It

kubectl apply -f pod.yaml
kubectl get pod web
kubectl describe pod web
kubectl logs web
kubectl port-forward pod/web 8080:80     # then open http://localhost:8080
kubectl delete -f pod.yaml

port-forward tunnels a local port to the pod, which is the simplest way to reach it while no Service exists.

YAML is strict about spaces Indentation is structure, tabs are not allowed, and a list item starts with a dash. Most "my manifest does nothing" problems are a misplaced indent. kubectl apply --dry-run=client -f pod.yaml checks a file without creating anything.

§4Common Mistakes

MistakeWhat HappensFix
Using the latest tagDifferent nodes can pull different images, and rollbacks are unclearPin an explicit version tag, or better, a digest
Putting several unrelated apps in one podThey scale and fail togetherOne pod per application; add extra containers only for tightly coupled helpers
Expecting a bare pod to come back after a node failureIt is simply goneRun pods through a Deployment or Job
Practice
  1. Write a pod manifest for busybox that runs sleep 3600, apply it, and open a shell inside it.
  2. Break the YAML on purpose by mis-indenting containers, and read the error kubectl gives you.
Key takeaways
  • A pod is one or more tightly coupled containers sharing a network identity.
  • Every manifest has apiVersion, kind, metadata, and spec.
  • Bare pods are ephemeral and not rescheduled, so real apps use higher-level objects.
