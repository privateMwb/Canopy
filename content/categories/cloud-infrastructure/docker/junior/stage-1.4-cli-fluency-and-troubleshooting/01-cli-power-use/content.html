CLI Power Use

A handful of flags for formatting, filtering, and inspecting turn the Docker CLI from a wall of text into a precise tool.

§1Formatting and Filtering Output

Most listing commands accept --format with Go templates and --filter to narrow results:

docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker ps -a --filter status=exited
docker images --filter dangling=true
docker ps -q                       # IDs only, handy for scripting
docker stop $(docker ps -q)        # stop everything running

You can also set a default psFormat in ~/.docker/config.json if the standard docker ps is too wide for your terminal.

§2Inspecting State

docker inspect returns the full JSON description of any object, and --format extracts one field:

docker inspect web --format '{{.State.Status}}'
docker inspect web --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'
docker inspect web --format '{{json .Config.Env}}'
docker top web                     # processes inside
docker stats --no-stream           # CPU, memory, network and disk I/O snapshot
docker diff web                    # files changed in the container's writable layer

docker diff is a quick way to discover where an app is writing data it should not be.

Remove everything for a projectdocker compose down

Add --help to anything: docker run --help is the fastest reference you have, and every subcommand documents its own flags.

Learn to read inspect When a container misbehaves, the answer is almost always in docker inspect: the actual environment, mounts, command, restart count, and exit code. Look at .State first, then .Config, then .Mounts.

§4Common Mistakes

MistakeWhat HappensFix
Parsing docker ps output with awkBreaks when columns shiftUse --format or -q
Running docker stop $(docker ps -q) on a shared hostStops other people's containersFilter by name, label, or Compose project
Guessing what config a container hasDebugging the wrong assumptionsdocker inspect shows what was actually applied
Practice
  1. Make docker ps print only name, image, and status in a table using --format.
  2. Use docker inspect --format to print the IP address, exit code, and restart count of a container.
Key takeaways
  • --format and --filter make output scriptable and readable.
  • docker inspect is the source of truth for what a container is actually running with.
  • --help on any subcommand is the fastest reference.
