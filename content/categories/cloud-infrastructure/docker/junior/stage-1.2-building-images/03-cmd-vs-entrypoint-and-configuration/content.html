CMD vs. ENTRYPOINT & Configuration

CMD supplies a default command that is easy to override, ENTRYPOINT fixes the executable, and the exec form makes both behave predictably with signals.

§1Shell Form vs. Exec Form

Both CMD and ENTRYPOINT come in two forms:

CMD node server.js            # shell form: runs via /bin/sh -c "node server.js"
CMD ["node", "server.js"]     # exec form: runs node directly as PID 1

Prefer the exec form. In shell form, /bin/sh is PID 1 and your app is a child, so a docker stop SIGTERM goes to the shell and often never reaches the app, leaving Docker to wait ten seconds and then kill it. The exec form needs no shell, but it also does no variable expansion, so CMD ["echo", "$HOME"] prints the literal text.

§2How CMD and ENTRYPOINT Combine

ENTRYPOINT is the program; CMD is its default arguments. Arguments after the image name in docker run replace CMD but append to ENTRYPOINT.

ENTRYPOINT ["python", "manage.py"]
CMD ["runserver", "0.0.0.0:8000"]
docker run web                 # python manage.py runserver 0.0.0.0:8000
docker run web migrate         # python manage.py migrate
docker run --entrypoint sh -it web    # replace the entrypoint itself

Use ENTRYPOINT when the image behaves like a single tool; use only CMD when users should be able to run anything else (for example, a shell for debugging).

§3ENV vs. ARG

Two ways to parameterize a build, with very different lifetimes:

ARGENV
AvailableDuring the build onlyBuild and the running container
Set with--build-arg NAME=valueENV NAME=value in the Dockerfile, or -e at run time
Persists in imageNot as an environment variable (but visible in history)Yes
ARG APP_VERSION=dev
ENV APP_ENV=production
RUN echo "building $APP_VERSION"
docker build --build-arg APP_VERSION=1.4.2 -t app .
Do not pass secrets through ARG or ENV Build arguments and environment variables are recorded in image metadata and visible with docker history or docker inspect. A later stage covers build secrets, which are designed not to leak.

§4Common Mistakes

MistakeWhat HappensFix
Shell-form CMD for a long-running appSIGTERM never reaches the app and shutdown is slowUse the exec form with a JSON array
Expecting $VAR expansion in exec formThe literal string $VAR is passedUse a shell explicitly (["sh", "-c", "..."]) or read the variable in the app
Putting secrets in ARGValue is retrievable from the image historyUse runtime configuration or BuildKit secrets
Practice
  1. Build the same app with shell-form and exec-form CMD, run each, and time how long docker stop takes.
  2. Create an image with an ENTRYPOINT and a default CMD, then run it with and without extra arguments.
Key takeaways
  • Use the exec form (JSON array) so the app receives signals directly.
  • ENTRYPOINT is the program, CMD the overridable default arguments.
  • ARG lives only at build time; ENV persists, and neither is a place for secrets.
