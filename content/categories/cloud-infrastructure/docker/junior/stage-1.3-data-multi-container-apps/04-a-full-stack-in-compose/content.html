A Full Stack in Compose

A real development stack needs health checks and startup ordering, a fast edit loop, and a clean way to reset.

§1Waiting for Dependencies

depends_on only waits for a container to start, not to be ready. Use a health check and a condition.

services:
  db:
    image: postgres:16
    environment: { POSTGRES_PASSWORD: devpass }
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 3s
      retries: 10
  api:
    build: .
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

Applications should also retry their database connection, because networks and dependencies fail at runtime too.

§2A Fast Development Loop

  api:
    build: .
    volumes:
      - ./src:/app/src              # bind mount: edits appear instantly
    command: npm run dev            # a watcher that reloads on change

Newer Compose versions also offer docker compose watch, which syncs or rebuilds on file changes.

§3An App, Database, and Cache

  cache:
    image: redis:7
    command: ["redis-server", "--maxmemory", "64mb", "--maxmemory-policy", "allkeys-lru"]
  api:
    environment:
      REDIS_URL: redis://cache:6379

§4Resetting and Debugging

docker compose down -v && docker compose up -d --build   # clean slate
docker compose logs --tail 100 api
docker compose run --rm api npm test                     # one-off command in a new container

§5Differences From Production

Compose on a laptop is for development and small deployments. Production usually needs separate secrets, resource limits, logging, and orchestration.

The key insight "Started" is not "ready". Health checks give your stack a real definition of working.

§6Common Mistakes

MistakeWhat HappensFix
depends_on without a health conditionThe app starts before the database accepts connectionsAdd a health check and service_healthy
Bind-mounting over node_modules or installed packagesThe container sees an empty or wrong folderUse an anonymous volume or mount only source folders
Treating the development Compose file as productionMissing limits, secrets, and monitoringMaintain a separate production configuration
Practice
  1. Build an app, database, and cache stack with health checks, and prove the app waits for the database.
  2. Make a change to source on the host and see it reflected in the running container without rebuilding.
Key takeaways
  • depends_on with health checks controls readiness, not just start order.
  • Bind mounts and watchers give a fast development loop.
  • Know which parts of a dev stack are not suitable for production.
