Installing Docker & Running Your First Container

Five commands cover most of what you do on day one: run a container, list it, read its output, stop it, and remove it.

§1Getting Docker

On macOS and Windows, install Docker Desktop (or another engine, covered in stage 1.4). On Linux, install Docker Engine from your distribution or Docker's official repository. Then verify both the client and the background daemon are working:

docker version         # client and server (daemon) sections should both appear
docker run hello-world

hello-world is a tiny image that prints a message and exits. If you see the greeting, the whole chain works: the client talked to the daemon, which found no local copy of the image, pulled it from Docker Hub, created a container, ran it, and streamed the output back.

§2The Everyday Five

docker run -d --name web -p 8080:80 nginx   # start nginx in the background
docker ps                                   # list running containers
docker logs web                             # see what it printed
docker stop web                             # ask it to shut down
docker rm web                               # delete the stopped container

Walk through the flags: -d detaches (runs in the background), --name gives you a handle instead of a random one, and -p 8080:80 maps host port 8080 to container port 80. Visit http://localhost:8080 while it runs and you will see the nginx welcome page.

§3Foreground, Interactive, and Throwaway

Without -d, docker run stays attached and shows output in your terminal; Ctrl+C stops it. For a shell inside a fresh container, combine -i (keep input open) and -t (allocate a terminal), and add --rm so it deletes itself on exit:

docker run -it --rm alpine sh
/ # cat /etc/os-release
/ # exit
Read the daemon, not just the client docker is only a client. If you see "Cannot connect to the Docker daemon", the daemon is not running (start Docker Desktop or the service) or your user lacks permission to reach it. The client being installed proves nothing about the daemon.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting -d for a serverYour terminal is stuck attached to the containerPress Ctrl+C, or rerun with -d
Running without --nameRandom names like quirky_turing make commands awkwardName anything you intend to manage
Reusing a name for a new docker run"Conflict: container name already in use"docker rm the old one first, or pick a new name
Practice
  1. Start nginx on host port 9090, confirm it in a browser, read its logs, then stop and remove it.
  2. Run docker run -it --rm alpine sh, create a file inside, exit, run it again, and observe that the file is gone.
Key takeaways
  • docker run creates and starts a container; ps, logs, stop, and rm manage it.
  • -p HOST:CONTAINER publishes a port, -d detaches, and --rm cleans up automatically.
  • The client and the daemon are separate; most "Docker is broken" errors are about reaching the daemon.
