What Containers Are (and Aren't)

A container is an ordinary process that the operating system isolates, which makes it far lighter than a virtual machine.

§1The Problem Containers Solve

An app needs a specific runtime, libraries, and configuration. Works on your laptop, fails on the server: the environments differ. A container packages the app with its dependencies so it runs the same everywhere.

§2Containers vs. Virtual Machines

A virtual machine runs a full guest operating system on virtualized hardware. A container runs on the host's kernel and uses kernel features to give each process its own view of files, processes, and network.

  • VM: minutes to start, gigabytes in size, strong isolation.
  • Container: milliseconds to start, megabytes in size, lighter isolation because the kernel is shared.
VM:         app → guest OS → hypervisor → hardware
Container:  app → container runtime → host kernel → hardware

§3Images and Containers

An image is a read-only template: files plus metadata about how to start. A container is a running (or stopped) instance of an image. One image can start many containers.

§4What Docker Is

Docker is a toolset for building images and running containers. Others (Podman, containerd) follow the same open standards, so skills transfer.

§5Common Misunderstandings

Containers are not tiny VMs. A Linux container needs a Linux kernel (on Mac and Windows, Docker runs a hidden Linux VM). Containers are also not automatically secure, since they share a kernel.

The key insight A container is a process with a restricted view of the system, started from an image. Remember "process", and most behavior makes sense.

§6Common Mistakes

MistakeWhat HappensFix
Treating a container like a VM you log in to and tinker withChanges vanish when it is replacedChange the image, not the running container
Assuming containers are fully isolatedA kernel flaw or bad config can break outApply least privilege and keep hosts patched
Expecting Linux containers to run natively on any OSOn Mac and Windows they run inside a Linux VMKnow the layer you are on

Key takeaways
  • A container is an isolated process sharing the host kernel.
  • An image is a template, and containers are instances of it.
  • Containers are lighter than VMs, but isolation is weaker.
