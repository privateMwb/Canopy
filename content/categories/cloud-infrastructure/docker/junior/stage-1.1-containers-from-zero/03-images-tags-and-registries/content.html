Images, Tags & Registries

An image reference such as nginx:1.27 names a repository and a tag, and a tag is only a movable label, so the digest is what truly identifies an image.

§1Anatomy of an Image Reference

A full reference looks like registry/namespace/repository:tag. Most parts have defaults, so nginx really means docker.io/library/nginx:latest.

ReferenceMeans
nginxDocker Hub official image, tag latest
nginx:1.27-alpineSame repository, a specific variant
myorg/api:2.4.1A user or organization namespace on Docker Hub
ghcr.io/myorg/api:2.4.1A different registry (GitHub Container Registry)

§2Pulling and Inspecting

docker pull postgres:16        # download without running
docker images                  # list local images (also: docker image ls)
docker image inspect postgres:16 --format '{{.Id}}'
docker rmi postgres:16         # remove a local image

docker run pulls automatically if the image is missing, but it will not refresh an existing tag for you. Pulling latest last month and running it today runs last month's copy until you docker pull again.

§3Tags Move, Digests Do Not

A tag is a pointer that the publisher can reassign at any time; latest is not special, merely a default name. A digest is the SHA-256 hash of the image content and can never point at anything else.

docker pull nginx:1.27
docker images --digests nginx
docker run nginx@sha256:<digest-from-above>    # exactly this content, forever

A registry is just a server that stores and serves images. Docker Hub is the default; others include GitHub Container Registry, Amazon ECR, and Google Artifact Registry.

Never treat latest as "newest" latest only means "whatever the publisher last tagged that way", which may be old, may be a different major version tomorrow, and may differ between machines that pulled on different days. Pin real version tags in anything you share.

§4Common Mistakes

MistakeWhat HappensFix
Relying on latestDifferent machines run different versionsPin an explicit version tag
Assuming a pulled tag auto-updatesYou keep running a stale imagedocker pull again, then recreate the container
Treating tags as immutableA tag can be repointed and silently change your basePin by digest where reproducibility matters
Practice
  1. Pull alpine:3.20 and alpine:latest, then compare their sizes and image IDs in docker images.
  2. Find the digest of an image you have pulled and run the container by digest instead of tag.
Key takeaways
  • A reference is registry/namespace/repository:tag, with Docker Hub and latest as the defaults.
  • Tags are movable labels; digests are immutable content hashes.
  • docker run does not update an image you already have, so pull deliberately.
