Working Inside Containers

You interact with a running container by executing commands in it, publishing its ports, and feeding it configuration through environment variables.

§1Running Commands in a Live Container

docker exec starts an additional process inside an already-running container, which is the standard way to look around or run a one-off task:

docker run -d --name db -e POSTGRES_PASSWORD=devpass postgres:16
docker exec -it db psql -U postgres        # interactive client inside the container
docker exec db ls /var/lib/postgresql/data   # one-off command, output returned

Use exec for inspection and maintenance, not for permanent changes: anything you install this way disappears when the container is replaced.

§2Publishing Ports

A container's ports are private by default. -p HOST:CONTAINER forwards a host port to one inside the container.

docker run -d -p 8080:80 nginx              # all host interfaces
docker run -d -p 127.0.0.1:8081:80 nginx    # localhost only
docker port <name>                          # show the mappings

Binding to 127.0.0.1 keeps a development database off your network. A bare -p 5432:5432 publishes on all interfaces, which on a laptop may mean everyone on the café Wi-Fi.

§3Environment Variables

Many images are configured through environment variables, set with -e or loaded from a file:

docker run -d -e POSTGRES_PASSWORD=devpass -e POSTGRES_DB=app postgres:16
docker run --env-file ./app.env myimage
docker exec <name> env        # see what the container actually received

Read each image's documentation page (usually on Docker Hub) for its supported variables and defaults; for example, the Postgres image refuses to start without a password setting.

Variables are visible, not secret Anyone who can run docker inspect on a container can read its environment. Fine for local development; a later stage covers safer ways to deliver real credentials.

§4Common Mistakes

MistakeWhat HappensFix
Using exec on a stopped container"Container is not running"Start it first, or use docker run for a new one
Forgetting -i/-t for a shellThe shell exits immediately or shows no promptdocker exec -it <name> sh
Publishing the port in the wrong directionReversing HOST:CONTAINER connects to nothingRemember: left is your machine, right is the container
Practice
  1. Start Postgres with a password, exec into psql, create a table, and list it.
  2. Start the same image twice on different host ports and confirm both answer.
Key takeaways
  • docker exec runs extra processes in a running container; changes made that way are temporary.
  • -p HOST:CONTAINER publishes ports, and binding to 127.0.0.1 keeps them local.
  • Configure images with -e or --env-file, and check the image documentation for the names.
