Single Host, Compose, or an Orchestrator?

One well-run host with Compose goes further than most teams expect, and the step up to an orchestrator should be driven by needs, not fashion.

§1What One Host Can Do

Compose on a single server can run a real production workload: restart policies, health checks, resource limits, reverse proxy with TLS, backups, and zero-downtime-ish updates.

docker compose pull && docker compose up -d --remove-orphans
docker compose ps

Strengths: simple, cheap, easy to debug, and few moving parts.

§2Where It Runs Out

  • High availability: one host is a single point of failure.
  • Scale: you need more capacity than one machine.
  • Automated placement and self-healing across machines.
  • Rolling deployments and canaries with traffic control.
  • Many teams and services needing isolation, quotas, and shared tooling.

§3The Options

  • Docker Swarm: simple clustering built into Docker. Small ecosystem and slow momentum, but easy for modest needs.
  • Kubernetes: the standard orchestrator. Powerful, with a large ecosystem and real operational cost.
  • Managed container services (ECS, Cloud Run, Azure Container Apps): run containers without managing clusters.
  • Nomad: a simpler scheduler for containers and other workloads.
  • PaaS (Fly.io, Render, Heroku-style): you provide an image, they run it.

§4Deciding

Need high availability or more than one machine?  no → one host, Compose
yes → Do you want to operate a cluster?            no → managed container service / PaaS
yes, with many teams and services                   → Kubernetes

Count the cost of operating the platform: upgrades, security, networking, and the people who understand it.

The key insight Choose the simplest platform that meets your availability and scale needs, and be honest about who will run it at 3 a.m.

§5Common Mistakes

MistakeWhat HappensFix
Adopting Kubernetes for two services and one engineerOperations overwhelm the teamStart with Compose or a managed service
Staying on one host after high availability became a requirementOne failure takes everything downMove before the outage teaches you
Choosing a platform by resume valueWrong tool and unhappy teamChoose by requirements and operating capacity
Practice
  1. Write the requirements that would make you leave a single Compose host, and measure how far you are from them.
  2. Compare a managed container service and Kubernetes for your application on cost, effort, and risk.
Key takeaways
  • A single host with Compose is a valid production platform for many workloads.
  • Orchestrators solve availability, scale, and multi-team problems at a cost.
  • Choose by requirements and operating capacity.
