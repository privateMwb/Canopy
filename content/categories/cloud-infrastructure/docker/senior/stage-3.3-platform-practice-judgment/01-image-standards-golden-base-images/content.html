Image Standards & Golden Base Images

A small set of maintained base images, with clear rules, saves every team from solving the same security and update problems.

§1Golden Base Images

A golden image is a company-approved base: patched, scanned, minimal, with the right CA certificates, a non-root user, and sensible defaults. Teams build from these rather than from random public images.

FROM registry.example.com/base/node:22-slim-2025-03@sha256:...

§2What a Standard Covers

  • Approved bases by language, with an owner for each.
  • Update cadence: rebuild weekly, and out of band for critical CVEs.
  • Naming and tagging: version, date, and digest conventions.
  • Required labels (owner, source repository, support contact).
  • Security rules: non-root, no secrets, scanned clean to an agreed threshold.
  • Build rules: multi-stage, pinned, BuildKit, and reproducible where possible.
LABEL org.opencontainers.image.source="https://github.com/example/app" \
      org.opencontainers.image.revision="${GIT_SHA}" \
      com.example.owner="payments-team"

§3Making Standards Followed

Standards that depend on goodwill fail. Provide:

  • Templates and a paved path that is easier than the alternative.
  • Linters (hadolint) and policy checks (Conftest, OPA) in CI.
  • Admission policy to block non-compliant images at deploy.
  • Automated updates that open pull requests when a base changes.
hadolint Dockerfile
conftest test Dockerfile --policy policy/

§4Handling Exceptions

Teams will have real needs. Allow a documented exception with an owner and an expiry, and review them. Too many exceptions mean the standard needs to change.

The key insight A standard succeeds when the compliant way is also the easiest way. Provide the paved road, then enforce it.

§5Common Mistakes

MistakeWhat HappensFix
Publishing a policy document with no toolingCompliance depends on memoryProvide templates and automated checks
One giant base image for everythingLarge images and too many packagesOffer a few focused bases
No process for exceptionsTeams quietly bypass the standardAllow time-boxed, reviewed exceptions
Practice
  1. Define a golden base for one language, with its tag policy and update schedule.
  2. Write three lint or policy rules that enforce your standard automatically.
Key takeaways
  • Golden images centralize patching and security decisions.
  • Standards need templates, automated checks, and enforcement to work.
  • Handle exceptions explicitly, with owners and expiry.
