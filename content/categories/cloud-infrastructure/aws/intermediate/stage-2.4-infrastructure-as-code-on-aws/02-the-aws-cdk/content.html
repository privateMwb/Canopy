The AWS CDK

The CDK lets you define infrastructure with real code, then synthesizes it to CloudFormation for deployment.

§1Constructs and Stacks

A CDK app is made of constructs: reusable building blocks at three levels. L1 constructs map directly to CloudFormation resources, L2 add sensible defaults and helper methods, and L3 (patterns) assemble whole architectures.

import * as cdk from 'aws-cdk-lib';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import * as ecs from 'aws-cdk-lib/aws-ecs';
import * as patterns from 'aws-cdk-lib/aws-ecs-patterns';

class WebStack extends cdk.Stack {
  constructor(scope: cdk.App, id: string) {
    super(scope, id);
    const vpc = new ec2.Vpc(this, 'Vpc', { maxAzs: 2 });
    new patterns.ApplicationLoadBalancedFargateService(this, 'Web', {
      cluster: new ecs.Cluster(this, 'Cluster', { vpc }),
      taskImageOptions: { image: ecs.ContainerImage.fromRegistry('nginx') },
    });
  }
}

§2The Workflow

cdk init app --language typescript
cdk bootstrap aws://123456789012/eu-west-1   # one-time per account/region
cdk synth      # produce the CloudFormation template
cdk diff       # compare with what is deployed
cdk deploy

cdk diff is your change-set preview. Bootstrapping creates the roles and bucket the CDK needs to deploy.

§3Strengths and Cautions

  • Loops, conditionals, functions, and types reduce repetition and catch errors earlier.
  • L2 constructs may create more resources, such as IAM roles, than you expect; read the synthesized template.
  • Logical IDs derive from construct paths, so renaming or moving a construct can replace the resource.
  • Test with assertions on the synthesized template.
Always read what it synthesizes The CDK hides detail, not consequences. Run cdk diff and skim the generated template for IAM and replacement changes before every deploy.

Practice
  1. Create a CDK app with a bucket and a Lambda function and run cdk diff and cdk deploy.
  2. Write one assertion test on the synthesized template.
Key takeaways
  • The CDK synthesizes CloudFormation from code using constructs at three levels.
  • Use cdk diff to preview changes and keep construct IDs stable.
  • Code gives abstraction and tests, but read the output.
