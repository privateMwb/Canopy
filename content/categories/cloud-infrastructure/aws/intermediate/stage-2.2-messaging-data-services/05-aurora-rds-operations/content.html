Aurora & RDS Operations

Aurora is AWS's cloud-built relational engine, and running any managed database well means understanding backups, replicas, failover, and connections.

§1Aurora Architecture

Aurora separates compute from a shared, distributed storage layer that keeps six copies of data across three AZs. A cluster has one writer and up to fifteen read replicas that share the same storage, so replicas have low lag and any one can be promoted on failure. It is compatible with MySQL and PostgreSQL.

  • The cluster endpoint always points to the writer.
  • The reader endpoint load-balances across replicas.
  • Aurora Serverless v2 scales capacity up and down within a range you set.

§3Failover and Connection Management

On writer failure, Aurora promotes a replica, typically within a minute or so, and the cluster endpoint updates. Applications must retry connections and respect DNS changes. At scale, thousands of short-lived connections (especially from Lambda) overwhelm a database.

aws rds create-db-proxy --db-proxy-name app-proxy \
  --engine-family POSTGRESQL \
  --auth file://auth.json \
  --role-arn arn:aws:iam::123456789012:role/rds-proxy \
  --vpc-subnet-ids subnet-aaa subnet-bbb

RDS Proxy pools connections, keeps them through failovers, and can reduce failover impact on your app. Test failover for real: apps often hold connections to the old writer too long.

Practice failing over Failover that has never run is a hope, not a plan. Trigger one in a test environment and see how your application's connection handling behaves.

§4Common Mistakes

MistakeWhat HappensFix
Connecting to an instance endpoint instead of the cluster endpointApp breaks after failoverUse cluster and reader endpoints
Sending reads to the writer onlyWriter overloaded while replicas idleUse the reader endpoint for read traffic
Lambda opening a connection per invocationMax connections exhaustedUse RDS Proxy and reuse connections
Practice
  1. Create an Aurora cluster with one replica and force a failover.
  2. Restore a point-in-time copy and verify the data.
Key takeaways
  • Aurora shares distributed storage across AZs with one writer and many readers.
  • Restores create new clusters; failover moves the writer endpoint.
  • Use RDS Proxy and retry logic to handle connections and failovers.
