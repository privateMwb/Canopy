Containers on AWS: ECS & Fargate

ECS orchestrates containers on AWS, Fargate removes the servers underneath, and EKS offers managed Kubernetes.

§2Fargate vs. EC2 Launch Type

With Fargate you specify CPU and memory per task and AWS runs the compute: no patching hosts or choosing instance types. With the EC2 launch type you manage a fleet of instances, gaining cost control at scale, GPUs, or special configurations at the price of operational work.

Two roles matter: the execution role lets ECS pull images and write logs; the task role is what your application code uses to call AWS.

§3Where EKS Fits

EKS runs the Kubernetes control plane for you. Choose it when you need Kubernetes itself: portability, an existing ecosystem, or team skills. Choose ECS when you want a simpler, AWS-native option. Images for either typically live in ECR, the private container registry.

Execution role vs. task role The execution role is for ECS to start your task; the task role is for your code. Putting application permissions on the wrong one is a frequent first error.

§4Common Mistakes

MistakeWhat HappensFix
Using one role for both execution and taskOver-broad access or startup failuresKeep them separate and minimal
Using the latest image tagUnclear what is deployed and no clean rollbackDeploy immutable, versioned tags
Tasks in public subnets with public IPs by defaultUnnecessary exposurePlace tasks in private subnets behind a load balancer
Practice
  1. Push an image to ECR and run it as an ECS service on Fargate behind an ALB.
  2. Stop one task and watch the service replace it.
Key takeaways
  • ECS runs tasks defined by task definitions and kept alive by services.
  • Fargate removes host management; EC2 launch type trades effort for control.
  • Use ECS for simplicity and EKS when you need Kubernetes.
