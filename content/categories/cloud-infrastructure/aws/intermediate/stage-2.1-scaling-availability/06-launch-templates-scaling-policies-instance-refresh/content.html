Launch Templates, Scaling Policies & Instance Refresh

Launch templates define what each instance looks like, scaling policies define when to change capacity, and instance refresh rolls out changes safely.

§1Launch Templates

A launch template stores the AMI, instance type, security groups, IAM instance profile, and user data. It is versioned, so an ASG can pin a version or follow $Latest or $Default. Launch configurations are the older mechanism and should not be used for new work.

aws ec2 create-launch-template --launch-template-name web \
  --launch-template-data file://web-template.json

§2Scaling Policy Types

TypeHow it worksUse when
Target trackingHolds a metric near a targetMost workloads; simplest
Step scalingDifferent adjustments for different alarm sizesNeed non-linear response
ScheduledChanges capacity at set timesPredictable daily or weekly patterns
PredictiveForecasts from historyRecurring patterns that need early capacity

Set a warm-up time so new instances do not count toward metrics before they are ready, and a cooldown or scale-in protection where flapping would hurt.

§3Instance Refresh

After you publish a new launch template version, an instance refresh replaces instances in batches while keeping a minimum healthy percentage.

aws autoscaling start-instance-refresh --auto-scaling-group-name web-asg \
  --preferences '{"MinHealthyPercentage":90,"InstanceWarmup":120}'

Pair it with a health check and, if supported in your setup, automatic rollback, so a bad image stops the rollout instead of replacing the whole fleet.

Roll out like a deploy Replacing every server is a deployment. Do it in small batches with health gating, exactly as you would for application code.

§4Common Mistakes

MistakeWhat HappensFix
Scale-in removing instances mid-requestDropped connectionsUse connection draining and scale-in protection where needed
No warm-up timeOver-scaling from metrics of cold instancesSet the warm-up to match startup time
Refreshing with 0% minimum healthyFull outage during rolloutKeep a minimum healthy percentage
Practice
  1. Create a new launch template version with a changed AMI and run an instance refresh with 90% minimum healthy.
  2. Add a scheduled action that raises capacity before a known daily peak.
Key takeaways
  • Launch templates are the versioned recipe for an ASG's instances.
  • Choose policy types by workload shape: target tracking by default.
  • Use instance refresh with health gating to roll out new images safely.
