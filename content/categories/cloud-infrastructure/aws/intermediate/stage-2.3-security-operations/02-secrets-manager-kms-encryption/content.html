Secrets Manager, KMS & Encryption

KMS manages encryption keys and Secrets Manager stores and rotates credentials, so neither lives in your code or images.

§1Encryption at Rest and in Transit

At rest means data is encrypted on disk; most AWS storage services support it, often by default. In transit means TLS between clients and services. You usually want both, and you can enforce transport encryption with a bucket policy condition on aws:SecureTransport.

§2KMS Keys

A KMS key never leaves the service in plaintext. Services request encryption and decryption through it, governed by the key policy and IAM.

Key typeWho manages itUse
AWS ownedAWS (invisible to you)Default for some services
AWS managed (aws/s3, etc.)AWS, in your accountSimple encryption with less control
Customer managedYou: policy, rotation, deletionControl, auditing, cross-account sharing

Envelope encryption is the usual mechanism: KMS generates a data key, the data is encrypted with that key locally, and the key itself is stored encrypted under the KMS key.

aws kms create-key --description "app data key"
aws kms create-alias --alias-name alias/app-data --target-key-id <key-id>
aws kms enable-key-rotation --key-id <key-id>

§3Secrets Manager

Secrets Manager stores secrets encrypted with KMS, controls access through IAM, and can rotate supported credentials automatically (RDS has built-in rotation). Applications fetch the secret at run time.

aws secretsmanager get-secret-value --secret-id prod/app/db \
  --query SecretString --output text

Parameter Store (in Systems Manager) is a cheaper option for plain configuration and simple secrets, without built-in rotation workflows.

Deleting a key deletes the data If you schedule a KMS key for deletion and it completes, everything encrypted only under that key is unrecoverable. Use the waiting period and check key usage first.

§4Common Mistakes

MistakeWhat HappensFix
Putting secrets in environment files or imagesSecrets leak through repositories and registriesFetch from Secrets Manager at run time via a role
Key policy that locks out everyoneKey becomes unusableKeep the account root principal enabled in key policies
No rotationCompromised credentials stay validEnable rotation for keys and supported secrets
Practice
  1. Store a database secret in Secrets Manager and read it from an EC2 instance using a role.
  2. Create a customer managed key, encrypt an S3 bucket with it, and review the CloudTrail entries.
Key takeaways
  • KMS keys never leave the service; services use envelope encryption through them.
  • Secrets Manager stores and rotates credentials fetched at run time via IAM.
  • Key deletion is irreversible, so guard it.
