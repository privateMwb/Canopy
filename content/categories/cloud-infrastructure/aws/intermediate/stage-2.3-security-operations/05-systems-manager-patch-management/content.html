Systems Manager & Patch Management

Systems Manager lets you run commands, open shells, and patch fleets of instances without exposing any inbound ports.

§1Why Systems Manager

The SSM Agent on an instance makes an outbound connection to Systems Manager. With an instance role that includes AmazonSSMManagedInstanceCore, you can manage it without SSH keys or open port 22, and every session is logged.

aws ssm start-session --target i-0123456789abcdef0
aws ssm send-command --document-name AWS-RunShellScript \
  --targets Key=tag:Environment,Values=dev \
  --parameters commands="uptime"

Instances in private subnets need a route to SSM, through NAT or VPC endpoints for ssm, ssmmessages, and ec2messages.

§2Patch Manager

Patch Manager scans instances against a patch baseline (which patches are approved and when) and installs them in a maintenance window. You group instances with tags and report compliance.

ConceptMeaning
Patch baselineRules for approved patches and delay
Maintenance windowScheduled time to apply changes
Patch group / tagsWhich instances belong together
Compliance reportWhich instances are missing patches

§3Other Useful Capabilities

  • Session Manager replaces bastion hosts and SSH.
  • Parameter Store holds configuration values.
  • Run Command and Automation run repeatable runbooks.
  • Fleet Manager and Inventory show what is installed where.
No inbound ports, still fully managed Removing SSH removes a whole class of attack. Systems Manager gives you shell access, audit logs, and patching through outbound-only connections.

§4Common Mistakes

MistakeWhat HappensFix
Instance role missing SSM permissionsInstance never appears as managedAttach AmazonSSMManagedInstanceCore
Private subnet without a route to SSMAgent can't registerAdd NAT or VPC endpoints
Patching production with no window or testingUnexpected restartsUse baselines, windows, and staged patching
Practice
  1. Connect to a private instance with Session Manager with port 22 closed.
  2. Run a patch scan and read the compliance report.
Key takeaways
  • SSM Agent plus an instance role enables access with no inbound ports.
  • Patch Manager uses baselines, windows, and tags for controlled patching.
  • Prefer Session Manager over SSH and bastions.
