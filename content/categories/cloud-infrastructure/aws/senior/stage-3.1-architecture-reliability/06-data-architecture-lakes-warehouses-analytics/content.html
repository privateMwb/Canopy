Data Architecture: Lakes, Warehouses & Analytics

A data lake stores raw data cheaply in S3, a warehouse serves fast structured analytics, and choosing between them is mostly about workload shape and governance.

§1Lake, Warehouse, and Lakehouse

Data lakeData warehouse
DataRaw and varied: files, logs, JSON, ParquetModeled, structured tables
SchemaApplied on readDefined on write
Typical storeS3Redshift
StrengthCheap, flexible, any engineFast, concurrent SQL and BI

A lakehouse blends them: open table formats such as Apache Iceberg on S3, queried by several engines, with warehouse-like features.

§3Design Choices That Matter

  • Store as columnar, compressed formats (Parquet, ORC), not raw CSV or JSON, to cut scan cost and time.
  • Partition by commonly filtered columns, such as date, so queries read less data.
  • Organize zones: raw, cleaned, curated, with different access and retention.
  • Govern with Lake Formation, classify sensitive data, and log access.
  • Use Athena for ad-hoc and infrequent queries; use Redshift when dashboards and many users hit the same data constantly.
Cost follows bytes scanned In Athena, a query that scans less data is cheaper and faster. Columnar formats and partitions are the main levers, long before any query tuning.

§4Common Mistakes

MistakeWhat HappensFix
Querying raw CSV or JSON at scaleSlow, expensive scansConvert to partitioned Parquet
No catalog or ownershipNobody trusts or finds the dataUse the Glue catalog and assign data owners
Loading everything into a warehouse by defaultHigh cost for rarely used dataKeep cold data in the lake; load what is hot
Practice
  1. Convert a CSV dataset to partitioned Parquet and compare Athena scanned bytes for the same query.
  2. Draw the zones and access rules for a lake serving analysts and data scientists.
Key takeaways
  • Lakes store flexible raw data; warehouses serve fast structured analytics.
  • S3, Glue, Athena, Redshift, and Lake Formation cover storage, catalog, query, and governance.
  • Parquet and partitions drive Athena cost and speed.
