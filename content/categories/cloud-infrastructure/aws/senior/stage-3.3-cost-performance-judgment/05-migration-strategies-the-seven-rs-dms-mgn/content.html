Migration Strategies: The Seven Rs, DMS & MGN

Migration is a portfolio decision: for each workload you choose one of seven strategies, then move in waves that limit risk.

§1The Seven Rs

StrategyMeaningEffort
RetireSwitch it off; not neededLowest
RetainLeave where it is for nowNone
RehostLift and shift to EC2 as-isLow
RelocateMove at hypervisor level (e.g. VMware Cloud on AWS)Low
RepurchaseReplace with SaaSMedium
ReplatformLift and reshape: e.g. move DB to RDSMedium
Refactor / re-architectRebuild cloud-nativeHighest

Most portfolios are a mix; discovery often finds a surprising number of systems to retire.

§2Tools

ToolPurpose
Application Discovery Service / Migration HubInventory and track migration progress
Application Migration Service (MGN)Continuous block-level replication of servers, then cutover with minimal downtime
Database Migration Service (DMS) and Schema Conversion ToolReplicate and convert databases, including ongoing change capture
DataSync, Snow familyMove large file and bulk data sets

§3Waves and Cutover

  • Assess: inventory, dependencies, and business criticality; map every workload to an R.
  • Build the landing zone first: accounts, network, identity, and guardrails.
  • Migrate in waves, starting with low-risk systems to build skill and tooling.
  • Test the cutover repeatedly with replicas; define rollback criteria and keep the source until confident.
  • Optimize after moving: rightsize and modernize once stable, not during the move.
Wave 1: internal tools (low risk)  → learn the process
Wave 2: supporting services
Wave 3: critical systems with rehearsed cutover + rollback
Move first, modernize second Doing a rehost and a redesign in one step doubles the risk. Land safely, then improve with real data on how the system behaves.

§4Common Mistakes

MistakeWhat HappensFix
Skipping dependency mappingSystems break after cutoverDiscover and map dependencies first
Migrating before the landing zone existsUnsecured, inconsistent environmentBuild accounts, network, and guardrails first
No rollback planStuck mid-cutoverKeep the source and define rollback criteria
Practice
  1. Classify ten sample workloads into the seven Rs with a one-line reason each.
  2. Outline wave plan and cutover steps for a database moving with DMS.
Key takeaways
  • The seven Rs map each workload to a strategy from retire to refactor.
  • MGN replicates servers; DMS replicates and converts databases.
  • Migrate in waves with a landing zone, rehearsed cutovers, and rollback.
