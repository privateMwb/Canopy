Compliance, Data Protection & Incident Response

Compliance is proving controls work, data protection is knowing what you hold and how it's guarded, and incident response is what happens when both are tested.

§1Compliance and Evidence

AWS provides compliance reports through AWS Artifact and certifies its own side of the shared responsibility model; you still must show your controls. Audit Manager and Security Hub standards help collect continuous evidence, and Config conformance packs bundle rules for frameworks.

§2Data Classification and Protection

  • Classify data (public, internal, confidential, regulated) and tie controls to each class.
  • Use Macie to discover sensitive data in S3.
  • Encrypt by class with customer managed keys where required; restrict by region for residency rules.
  • Define retention and deletion, and use S3 Object Lock where immutability is required.
  • Limit who and what can read the data: least privilege, VPC endpoints, and access logging.

§3Incident Response Basics

AWS describes a lifecycle of preparation, detection and analysis, containment, eradication and recovery, and post-incident learning.

Contain  → isolate: deny-all security group, disable keys, attach a quarantine SCP/policy
Preserve → snapshot disks and memory, export logs before changing anything
Analyze  → CloudTrail, VPC Flow Logs, GuardDuty findings, who/what/when
Eradicate→ rotate credentials, rebuild from known-good images
Recover  → restore service, monitor for recurrence
Learn    → blameless review, fix root causes

Prepare before you need it: a dedicated forensics or security account, pre-approved roles, runbooks, and practice through game days.

Rebuild compromised instances rather than cleaning them, and rotate every credential the attacker may have touched.

Preserve, then contain, then fix Evidence disappears when you terminate or modify things hastily. Isolate first, snapshot and export logs, and only then rebuild.

§4Common Mistakes

MistakeWhat HappensFix
No incident plan until an incidentChaos and slow responseWrite runbooks and rehearse them
Terminating a compromised instance immediatelyLost forensic evidenceIsolate and snapshot first
Not rotating credentials after a compromiseAttacker keeps accessRotate keys and sessions the attacker could reach
Practice
  1. Write a one-page response runbook for a suspected compromised instance.
  2. Classify five data types your system holds and list the control for each class.
Key takeaways
  • Compliance needs your own evidence; AWS covers only its side.
  • Classification drives encryption, access, residency, and retention.
  • Incident response is preparation plus contain, preserve, analyze, eradicate, recover, learn.
