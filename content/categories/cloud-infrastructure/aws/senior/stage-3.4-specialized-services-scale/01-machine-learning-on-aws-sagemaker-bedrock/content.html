Machine Learning on AWS: SageMaker & Bedrock

AWS offers managed services for building and training your own models (SageMaker) and for using foundation models through an API (Bedrock).

§1Bedrock: Foundation Models as a Service

Amazon Bedrock provides access to foundation models from several providers through one API, with no infrastructure to run. Typical features include text and image generation, embeddings, Knowledge Bases for retrieval-augmented generation (RAG), Guardrails for content and safety controls, and agent tooling.

import boto3, json
br = boto3.client('bedrock-runtime', region_name='us-east-1')
resp = br.converse(
    modelId='<model-id>',
    messages=[{'role': 'user', 'content': [{'text': 'Summarize this ticket: ...'}]}],
    inferenceConfig={'maxTokens': 300},
)
print(resp['output']['message']['content'][0]['text'])

Model availability, IDs, and pricing vary by region and change often, so check the current console and documentation.

§3Choosing and Operating

  • Prebuilt AI services (Textract, Rekognition, Transcribe, Comprehend) when a ready-made capability fits.
  • Bedrock when a foundation model solves it and you want minimal ops.
  • SageMaker when you need custom training, specific models, or control over serving.
  • Keep data private: use VPC endpoints, encryption, and know how each service handles your data.
  • Watch cost: idle endpoints and large training instances bill continuously; evaluate quality, latency, and token cost before committing.
  • Add evaluation, logging, and human review where errors matter.
Start with the highest-level service that works Each step down, from prebuilt AI to Bedrock to SageMaker, gives more control and more work. Move down only when the higher level can't meet the need.

Key takeaways
  • Bedrock offers foundation models by API; SageMaker supports custom model lifecycle.
  • Choose the highest-level service that meets requirements.
  • Control cost, data handling, and quality explicitly.
