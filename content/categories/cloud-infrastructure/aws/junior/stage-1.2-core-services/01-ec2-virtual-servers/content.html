EC2: Virtual Servers

EC2 rents you virtual servers; you choose the size, the starting image, the network rules, and how you log in.

§1Instances, Types, and AMIs

An instance is a virtual server launched from an AMI (Amazon Machine Image: the OS and preinstalled software). The instance type sets CPU, memory, and network, and the name encodes it: in m7g.large, m is the family (general purpose), 7 the generation, g a Graviton (Arm) processor, and large the size.

FamilyGood for
tBurstable, low-cost general use
mBalanced general purpose
cCompute-heavy

§2Launching and Connecting

aws ec2 run-instances \
  --image-id ami-0abcdef1234567890 \
  --instance-type t3.micro \
  --key-name my-key \
  --security-group-ids sg-0123456789abcdef0 \
  --subnet-id subnet-0123456789abcdef0 \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=demo}]'

A key pair lets you SSH in; the private key downloads once and cannot be retrieved again. Alternatively, Systems Manager Session Manager gives shell access with no open port or key, which is the better habit.

§3Pricing and Lifecycle

On-demand instances bill per second while running. A stopped instance stops compute charges but you still pay for attached EBS volumes. A terminated instance is gone, and its root volume is deleted by default. Other pricing options (Savings Plans, Reserved, Spot) come later, once usage is predictable.

A public IPv4 address is charged hourly, and a normal public IP changes when you stop and start; an Elastic IP stays fixed.

Servers are cattle, not pets Treat an instance as replaceable: keep configuration in code or an AMI and data on separate storage, so losing one instance is an inconvenience, not an incident.

§4Common Mistakes

MistakeWhat HappensFix
Losing the private key fileYou cannot SSH in, and the key cannot be re-downloadedUse Session Manager, or keep keys safely stored
Leaving instances running after a labHourly charges keep accruingTerminate what you no longer need
Opening SSH to 0.0.0.0/0Constant brute-force attemptsRestrict to your IP or use Session Manager
Practice
  1. Launch a t3.micro, connect to it, and install a web server.
  2. Stop it, start it again, and note what changed about its public IP.
Key takeaways
  • An instance combines an AMI, an instance type, networking, and a way to log in.
  • Stopped instances still cost storage; terminated ones are gone.
  • Prefer Session Manager over open SSH, and treat servers as replaceable.
