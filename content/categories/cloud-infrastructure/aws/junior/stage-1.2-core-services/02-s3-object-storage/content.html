S3: Object Storage

S3 stores objects (files plus metadata) in buckets, with very high durability, many storage classes, and strong controls over who can read them.

§1Buckets and Objects

A bucket has a globally unique name and lives in one Region. An object is identified by a key (such as images/logo.png); the slashes are just part of the key, with the console showing them as folders. S3 offers strong read-after-write consistency.

aws s3 mb s3://my-unique-bucket-name
aws s3 cp report.pdf s3://my-unique-bucket-name/reports/
aws s3 ls s3://my-unique-bucket-name/reports/

§2Storage Classes

ClassUse for
StandardFrequently accessed data
Standard-IA / One Zone-IAInfrequent access, lower storage price, retrieval fee
Intelligent-TieringUnknown or changing access patterns
Glacier tiersArchives, with retrieval times from minutes to hours

Lifecycle rules can move or expire objects automatically as they age.

§3Access and Versioning

New buckets are private and have Block Public Access on by default; leave it on unless you deliberately host public content (and prefer CloudFront for that). Access is granted through IAM policies and bucket policies.

aws s3api put-bucket-versioning --bucket my-unique-bucket-name \
  --versioning-configuration Status=Enabled

With versioning, overwriting or deleting keeps older versions, so accidental changes can be undone. Encryption at rest is applied by default with S3-managed keys.

Public buckets are a choice Nearly all S3 data leaks come from someone deliberately loosening access. Keep Block Public Access on at the account level so one bucket policy mistake cannot expose data.

§4Common Mistakes

MistakeWhat HappensFix
Turning off Block Public Access to "make it work"Data becomes world-readableFix the policy or IAM role instead; use CloudFront for public sites
No versioning on important dataOverwrites and deletes are permanentEnable versioning and lifecycle rules for old versions
Storing everything in Standard foreverHigher cost than neededUse lifecycle rules and Intelligent-Tiering
Practice
  1. Create a bucket, enable versioning, upload a file twice, and list the versions.
  2. Add a lifecycle rule moving objects to a cheaper class after 30 days.
Key takeaways
  • S3 stores objects by key in regional buckets with high durability.
  • Pick storage classes by access pattern and automate transitions with lifecycle rules.
  • Keep buckets private by default and use versioning to recover from mistakes.
