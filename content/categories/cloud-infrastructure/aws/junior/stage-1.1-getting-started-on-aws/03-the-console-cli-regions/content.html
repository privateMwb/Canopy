The Console, CLI & Regions

You can drive AWS through the web console, the command line, or SDKs, and almost everything you create lives in one specific Region.

§1Console, CLI, and SDKs

The Management Console is best for exploring and learning. The AWS CLI scripts the same operations, and SDKs (Python's boto3, JavaScript, Java, and others) call the same APIs from code. Every route ends at the same HTTPS API, so anything you can click you can automate.

aws --version
aws sts get-caller-identity   # who am I, in which account?
aws ec2 describe-instances --region eu-west-1

§2Configuring the CLI

Credentials and defaults live in ~/.aws/credentials and ~/.aws/config, organized into named profiles.

aws configure --profile dev
# AWS Access Key ID: ...
# Default region name: eu-west-1

aws s3 ls --profile dev
export AWS_PROFILE=dev        # default for this shell

Always run aws sts get-caller-identity when unsure which account and identity the CLI is using.

§3Regions: The Classic Mistake

A Region is a geographic area such as us-east-1 or eu-west-1. Most resources are regional and invisible from other regions. IAM, Route 53, and CloudFront are global-style services, but EC2, S3 buckets' data, RDS, and Lambda sit in one region.

  • The console shows one region at a time in the top-right selector.
  • "My instance vanished" usually means you are looking at the wrong region.
  • Pick regions for latency, price, service availability, and data residency rules.
Check the region first Before concluding a resource is missing or an error is mysterious, confirm the region in the console selector or in your CLI profile. It is the most common cause of confusion.

§4Common Mistakes

MistakeWhat HappensFix
Creating resources in the wrong regionThey are invisible when you look elsewhere and may cost money unnoticedSet a default region per profile and confirm it
Not knowing which identity the CLI usesCommands hit the wrong accountRun sts get-caller-identity before changes
Clicking everything in the consoleWork is not repeatableMove repeatable work to CLI or code early
Practice
  1. Install the CLI, configure a profile, and run aws sts get-caller-identity.
  2. Create a free resource in two regions and find each in the console and with --region.
Key takeaways
  • The console, CLI, and SDKs all use the same underlying API.
  • Use named profiles and verify your identity with sts get-caller-identity.
  • Most resources are regional; check the region first when something seems missing.
