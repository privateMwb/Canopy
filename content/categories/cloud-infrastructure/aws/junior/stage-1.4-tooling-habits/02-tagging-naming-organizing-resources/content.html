Tagging, Naming & Organizing Resources

Tags are key-value labels that make resources searchable, billable by owner, and safe to clean up, if you apply them consistently.

§1What Tags Do

A tag is a key and value attached to a resource, such as Owner=alice or Environment=dev. Tags support cost allocation, access control conditions, automation ("stop all dev instances at night"), and cleanup.

aws ec2 create-tags --resources i-0123456789abcdef0 \
  --tags Key=Owner,Value=alice Key=Environment,Value=dev Key=Project,Value=shop

§2A Minimal Standard

TagMeaningExample
OwnerPerson or team to askplatform-team
EnvironmentLifecycle stagedev, staging, prod
ProjectWhat it belongs toshop
CostCenterWhere the bill goes1234

Pick a small set, fixed capitalization, and allowed values. Tag keys are case-sensitive, so owner and Owner are different tags.

§3Making Tags Stick

  • Activate tags as cost allocation tags in Billing so they show up in Cost Explorer.
  • Apply tags at creation through templates or code, not by hand afterwards.
  • Use tag policies in Organizations and Config rules to detect untagged resources.
  • Adopt readable names such as shop-prod-web-01 alongside tags.
Untagged means unowned When the bill spikes, the first question is whose resource it is. A tag answers in seconds; no tag means an investigation.

§4Common Mistakes

MistakeWhat HappensFix
Inconsistent tag keys (Owner vs owner)Reports split and filters miss resourcesDefine a standard and enforce it
Not activating cost allocation tagsCosts cannot be grouped by tagActivate the keys in the Billing console
Tagging by hand after the factGaps and driftTag at creation in code or templates
Practice
  1. Define a four-tag standard and apply it to every resource in a test account.
  2. Find untagged resources with Resource Groups Tag Editor.
Key takeaways
  • Tags make ownership, cost, and automation possible.
  • Keep the standard small, consistent, and case-correct.
  • Apply tags at creation and enforce with policy.
