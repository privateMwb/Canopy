Preprocessors & PostCSS

Preprocessors and PostCSS add features and compatibility at build time, but native CSS now covers much of what made them essential.

§1What Sass Added

Sass was created when CSS lacked variables, nesting, and mixins. It compiles .scss to plain CSS.

$accent: #15803d;

@mixin focus-ring { outline: 2px solid $accent; outline-offset: 2px; }

.btn {
  background: $accent;
  &:hover { background: darken($accent, 6%); }
  &:focus-visible { @include focus-ring; }
}

Sass still offers mixins, functions, loops, and partial imports, which CSS can't do natively.

§2What Native CSS Now Does

FeatureNative CSS
VariablesCustom properties (live, cascading)
NestingNative & nesting in current browsers
Color functionscolor-mix(), relative colors, oklch()
Mathcalc(), min(), max(), clamp()
Splitting files@import (slow without bundling), or a bundler
.btn {
  background: var(--accent);
  &:hover { background: color-mix(in oklch, var(--accent), black 10%); }
  &:focus-visible { outline: 2px solid var(--accent); }
  @media (min-width: 40em) { padding-inline: 1.5rem; }
}

For a new project you may need no preprocessor at all. For existing Sass codebases, there is usually no rush to migrate.

§3PostCSS and the Build Step

PostCSS is a plugin pipeline that transforms CSS. It parses the stylesheet into a tree and lets plugins rewrite it.

// postcss.config.js
module.exports = {
  plugins: [
    require("postcss-import"),      // inline @import files
    require("autoprefixer"),        // add vendor prefixes based on target browsers
    require("cssnano"),             // minify
  ],
};

Tools like Lightning CSS and esbuild do bundling, minification, nesting down-leveling, and prefixing in one fast step. Define the browsers you support in a browserslist file so every tool agrees.

Add tools only for a reason Every build step is something to maintain. If native CSS plus a minifier gets you what you need, stop there.

§4Common Mistakes

MistakeWhat HappensFix
Deep Sass nesting (4+ levels)Generates high-specificity, long selectorsKeep nesting shallow, ideally 2 levels
Using Sass variables for values that need to change at runtimeCompiled away, so themes can't switchUse custom properties
Copying prefix lists by handOutdated and bloatedUse Autoprefixer with a browserslist
Practice
  1. Rewrite a small Sass component using native nesting and custom properties.
  2. Set up PostCSS with autoprefixer and a browserslist, and compare the output.
Key takeaways
  • Native CSS now covers variables, nesting, and many color functions.
  • Sass still offers mixins and functions; PostCSS is for transforms and compatibility.
  • Add build tools only when they solve a real problem.
