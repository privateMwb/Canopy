:has(), :is() & :where()

:has() selects an element based on what it contains, and :is() and :where() group selectors with very different effects on specificity.

§1The Parent Selector: :has()

:has() matches an element if it contains, or is followed by, something matching the argument. It's the long-awaited parent selector, and much more.

.card:has(img) { grid-template-columns: 10rem 1fr; }     /* only cards with an image */
label:has(input:disabled) { opacity: .6; }
form:has(:invalid) button[type="submit"] { opacity: .5; }
section:has(> h2 + p) { margin-block: 2rem; }
body:has(dialog[open]) { overflow: hidden; }       /* lock scrolling behind a modal */
li:has(+ li:hover) { transform: translateY(-1px); } /* previous sibling effect */

:has() is supported in current browsers. Its specificity is that of its most specific argument. Avoid complex arguments over large parts of the DOM, since they are costlier to evaluate.

§2Grouping: :is() and :where()

Both take a selector list and match any of them, so you can avoid repeating long prefixes.

/* before */
article h1, article h2, article h3 { margin-block-end: .5em; }

/* after */
article :is(h1, h2, h3) { margin-block-end: .5em; }

/* :where() does the same with zero specificity */
:where(ul, ol) { padding-inline-start: 1.25rem; }
Pseudo-classSpecificity
:is(a, b)That of the most specific selector in the list
:where(a, b)Always zero
:not(a)That of its argument
:has(a)That of its argument

§3Using Zero Specificity on Purpose

:where() is excellent for base and reset styles that any later rule can override without a fight.

:where(a) { color: var(--link); text-underline-offset: .15em; }
:where(h1, h2, h3) { line-height: 1.2; }

.nav a { color: inherit; }   /* overrides the base link color easily */

Another useful property: if one selector in a plain comma list is invalid, the whole rule is dropped. Inside :is() and :where(), invalid selectors are simply ignored, which makes them forgiving.

Quantifying power :is() takes on the specificity of its strongest argument, so :is(#a, .b) counts as an ID. Reach for :where() when you want styles that are easy to override.

§4Common Mistakes

MistakeWhat HappensFix
Using :is() with an ID in the list for convenienceThe entire rule gets ID-level specificityRemove the ID, or use :where()
Writing expensive :has() selectors on bodyStyle recalculation costs on large pagesScope it to the smallest ancestor
Nesting :has() inside another :has()It is not allowed, so the selector is invalid and the rule is droppedFlatten it into a single :has() with a combined argument
Practice
  1. Use :has() so a form group highlights when its input is invalid, with no JavaScript.
  2. Convert a long comma list of heading selectors into :is(), and a reset into :where().
Key takeaways
  • :has() selects by contents or following siblings.
  • :is() keeps the highest specificity in its list; :where() is always zero.
  • Use :where() for easily overridden defaults.
