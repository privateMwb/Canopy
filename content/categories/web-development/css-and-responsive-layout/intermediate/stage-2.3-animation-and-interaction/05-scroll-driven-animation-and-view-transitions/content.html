Scroll-Driven Animation & View Transitions

Scroll-driven animations and View Transitions let CSS link motion to scroll position and animate between pages or states, with little or no JavaScript.

§1Scroll-Driven Animations

Instead of time, an animation's progress can follow scroll. animation-timeline: scroll() tracks a scroll container, and view() tracks an element as it moves through the viewport.

/* a reading progress bar */
@keyframes grow { from { transform: scaleX(0); } to { transform: scaleX(1); } }
.progress {
  position: fixed; inset: 0 0 auto 0; height: 4px;
  transform-origin: left;
  animation: grow linear both;
  animation-timeline: scroll(root);
}

/* reveal as an element enters the viewport */
.reveal {
  animation: rise linear both;
  animation-timeline: view();
  animation-range: entry 0% cover 30%;
}

Scroll-driven animations run off the main thread when they use compositor properties. Browser support is growing but not universal, so wrap them in @supports (animation-timeline: scroll()) and make sure the content works without them.

§2View Transitions

The View Transitions API captures the old and new state of the page and animates between them. In a single-page app, wrap the DOM update; for multi-page sites, opt in with CSS.

/* same-document: JavaScript wraps the update */
document.startViewTransition(() => updateTheDOM());

/* cross-document (MPA): opt in on both pages */
@view-transition { navigation: auto; }

/* name an element so it morphs between states */
.hero-img { view-transition-name: hero; }

::view-transition-old(root) { animation: fade-out .2s ease both; }
::view-transition-new(root) { animation: fade-in .2s ease both; }

Each view-transition-name must be unique on the page at any moment. Same-document transitions are supported in current major browsers, while cross-document support is newer, so check before depending on it.

§3Using Them Responsibly

  • Treat both as enhancements: the page must work and make sense with no motion.
  • Respect prefers-reduced-motion by disabling or simplifying them.
  • Keep durations short; navigation shouldn't feel slower.
  • Don't hide content until it scrolls into view in a way that breaks if animations are unsupported or off.
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*), ::view-transition-old(*), ::view-transition-new(*) { animation: none; }
}
Check support, then enhance Both features are evolving. Use @supports or feature detection, and verify the experience in a browser that lacks them.

§4Common Mistakes

MistakeWhat HappensFix
Hiding content until a scroll animation reveals itWithout support or with reduced motion, it stays invisibleMake the final state the default and animate toward it, inside @supports
Reusing the same view-transition-name on several elementsThe transition fails or is skippedGive each a unique name
Ignoring reduced-motion preferencesLarge motion can cause discomfortTurn the effects off in a media query
Practice
  1. Add a scroll-driven reading progress bar to an article, with a graceful no-support fallback.
  2. Add a cross-fade view transition between two pages of a small site.
Key takeaways
  • animation-timeline ties animation progress to scroll or element visibility.
  • View Transitions animate between states or pages, using named elements.
  • Both are enhancements: feature-detect and respect reduced motion.
