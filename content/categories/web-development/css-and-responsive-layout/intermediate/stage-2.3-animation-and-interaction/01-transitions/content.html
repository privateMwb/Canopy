Transitions

A transition smooths the change between two states by animating the property over time, and getting the duration and easing right is most of the craft.

§1The Basics

Declare a transition on the base state so it plays in both directions. When the property changes, the browser interpolates instead of jumping.

.btn {
  background: #15803d;
  transform: translateY(0);
  transition: background-color .2s ease, transform .2s ease;
}
.btn:hover, .btn:focus-visible {
  background: #166534;
  transform: translateY(-1px);
}

The four parts of transition are the property, duration, timing function, and delay. List only the properties you intend to animate; transition: all animates things you didn't expect and costs more.

§2Timing and Easing

Timing functionFeels likeUse for
ease-outStarts fast, settles gentlyThings entering or responding to input
ease-inStarts slow, ends fastThings leaving the screen
ease-in-outSlow, fast, slowMoves across the screen
linearConstant speedColor cycles, progress
cubic-bezier(...) / linear(...)Custom curvesBrand-specific motion, springs

As a rule of thumb, small UI changes take 100–200ms, larger movements 250–400ms. Longer feels sluggish, and anything that blocks the user's next action should be quicker.

§3What Can and Can't Transition

Only properties with interpolable values animate: numbers, lengths, colors, transforms. display and height: auto traditionally could not.

/* newer: animate to and from auto sizes and display where supported */
.panel { interpolate-size: allow-keywords; transition: height .25s ease; }
.panel.closed { height: 0; }

@starting-style { .toast { opacity: 0; transform: translateY(8px); } }
.toast { transition: opacity .25s, transform .25s; }

@starting-style lets an element transition in when it first appears, and transition-behavior: allow-discrete lets display and overlay flip at the right moment. These are newer features, so use them as enhancements.

Always include focus Pair every :hover effect with :focus-visible so keyboard users get the same feedback. And remember hover does not exist on touch devices.

§4Common Mistakes

MistakeWhat HappensFix
Using transition: allAnimates unintended properties and wastes workList specific properties
Placing the transition only on :hoverIt animates in but snaps back on exitPut it on the base state
Animating height from a fixed value to auto the old wayIt jumps instead of animatingUse grid-template-rows tricks or interpolate-size, where supported
Very long durations on frequent interactionsThe interface feels slowKeep common UI feedback under about 200ms
Practice
  1. Add transitions to a button's background and transform, and test hover and keyboard focus.
  2. Make a toast that fades and slides in on appearance using @starting-style.
Key takeaways
  • Put transition on the base state, and list specific properties.
  • Use short durations and ease-out for entering motion.
  • Pair hover effects with :focus-visible.
