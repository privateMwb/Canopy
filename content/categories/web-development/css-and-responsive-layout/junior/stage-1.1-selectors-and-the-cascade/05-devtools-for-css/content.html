DevTools for CSS

Browser DevTools let you see which rules apply, why one lost, and try changes live, which turns CSS debugging from guessing into reading.

§1Inspect and Read the Styles Pane

Right-click an element and choose Inspect. The Styles pane lists every rule that matches, most specific first. Overridden declarations are shown with a strikethrough, and a warning icon explains declarations that have no effect.

  • Click a rule's file and line number to jump to its source.
  • Hover a value to see a color swatch or the computed size.
  • Check the Computed tab to see the final value and trace which rule supplied it.

§2Toggle, Edit, and Try

Tick a checkbox beside any declaration to disable it, or click a value and use the arrow keys to nudge it. Click + to add a rule, and use the :hov panel to force :hover, :focus, or :active states.

/* experiment live, then copy what works back into your stylesheet */
.card { padding: 1rem; }
.card { padding: 1.5rem; }   /* edited in DevTools */

Edits live in the browser only and vanish on reload, which makes DevTools a safe sandbox. Copy winning changes back to your source files.

§3A Debugging Routine

When a style isn't applying, ask the questions in order.

  1. Is the element the one I think it is? (Inspect it.)
  2. Is my rule listed at all? If not, check the selector and that the stylesheet loaded.
  3. Is it crossed out? Another rule with higher specificity or a later position won.
  4. Is it greyed out or flagged? The property doesn't apply in this context, such as top on a static element.
  5. Is the value invalid? An invalid value is dropped, and DevTools marks it.

The Box Model diagram at the bottom of the Computed tab shows the content, padding, border, and margin sizes, and the Layout tab visualizes Flexbox and Grid.

Outline everything To see what's taking up space, temporarily add * { outline: 1px solid red; }. Unlike border, outline doesn't change layout, so you see the real boxes.

§4Common Mistakes

MistakeWhat HappensFix
Editing only in DevToolsChanges disappear on reloadCopy the fix into your source files
Ignoring a strikethroughYou don't learn why the rule lostFind the rule that overrides it
Testing only the default stateHover, focus, and active styles stay uncheckedForce states with the :hov panel
Practice
  1. Pick a rule that isn't applying on a real site and use the Styles pane to find out why.
  2. Use the :hov panel to force :focus on a link and inspect its focus style.
Key takeaways
  • The Styles pane shows matched rules, crossed-out losers, and warnings.
  • Edit live to experiment, then copy changes back to source.
  • Debug in order: right element, rule present, overridden, invalid.
