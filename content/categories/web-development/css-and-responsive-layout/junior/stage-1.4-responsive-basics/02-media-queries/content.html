Media Queries

Media queries apply CSS only when conditions like viewport width or user preference match, and the best breakpoints come from your content, not from device lists.

§1Width Queries

Use min-width for mobile-first, adding styles from a width upward. Using em or rem units ties breakpoints to the user's font size, so layouts adapt when text is enlarged.

@media (min-width: 40em) { /* 640px at default size */
  .cards { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 64em) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}

/* modern range syntax */
@media (width >= 40em) and (width < 64em) { ... }

Keep min-width and max-width queries from overlapping, and don't mix both approaches in one stylesheet unless you have to.

§2Content-Driven Breakpoints

Don't chase specific devices; there are too many. Instead, resize the window and add a breakpoint where the layout starts to look wrong: lines too long, cards too cramped, a nav that wraps.

ApproachResult
Breakpoints at "iPhone", "iPad", "laptop"Brittle and quickly outdated
Breakpoints where the content breaksWorks on every device, including future ones

Aim for few breakpoints. Many modern layouts need two or three because flexible units and Grid do most of the work.

§3Preference and Feature Queries

Media queries also detect user settings and capabilities, which is often more valuable than width.

@media (prefers-color-scheme: dark)   { :root { --bg: #15171c; --ink: #edebe4; } }
@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }
@media (hover: hover) and (pointer: fine) { .card:hover { transform: translateY(-2px); } }
@media print { nav, footer { display: none; } }

Respecting prefers-reduced-motion is an accessibility must, and hover: hover keeps hover effects off touch devices.

Breakpoints in em Browsers evaluate em in media queries against the *browser's default* font size, not your CSS. That's exactly what you want: layouts respond to users who have enlarged their default text.

§4Common Mistakes

MistakeWhat HappensFix
Using px breakpoints tied to a list of devicesBreaks when text is zoomed or new devices arriveUse content-driven breakpoints, ideally in em
Mixing min-width and max-width queries haphazardlyOverlapping rules that are hard to reason aboutPick mobile-first min-width and stay consistent
Ignoring user preference queriesDark-mode and reduced-motion users get a worse experienceAdd prefers-color-scheme and prefers-reduced-motion
Practice
  1. Resize a layout slowly and mark the widths where it breaks, then add one media query for each.
  2. Add a dark-mode palette and a reduced-motion rule with media queries.
Key takeaways
  • Write min-width queries in em, and place them where content breaks.
  • Keep the number of breakpoints low.
  • Use preference queries for color scheme, motion, and hover capability.
