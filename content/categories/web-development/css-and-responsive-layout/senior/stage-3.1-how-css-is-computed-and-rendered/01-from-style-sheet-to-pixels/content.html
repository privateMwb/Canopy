From Style Sheet to Pixels

Between a stylesheet and the pixels on screen lie five stages, parse, style, layout, paint, and composite, and each change you make restarts the pipeline at a different point.

§1The Pipeline

  1. Parse CSS into rules, building the CSSOM.
  2. Style: match selectors to elements and compute every property's final value (cascade, inheritance, var(), relative units resolved).
  3. Layout: compute each box's size and position.
  4. Paint: record drawing instructions in layers (backgrounds, borders, text, shadows).
  5. Composite: rasterize layers and combine them on the GPU, applying transforms and opacity.

The value pipeline inside style has stages too: *declared* → *cascaded* → *specified* → *computed* → *used* → *actual*. em becomes a length at the computed stage, and % widths become pixels only at the used stage, after layout.

This table is the basis for nearly every CSS performance decision. Cheaper stages are earlier in the list of *skipped* work: the best change is one that only needs compositing.

§3Style Calculation Costs

Selector matching is cheap in modern engines, which match right to left and use hash tables for ids, classes, and tags. What matters more is how much of the DOM has to be re-matched.

  • A class change near the root can invalidate styles for a huge subtree.
  • Engines use invalidation sets to limit work, but broad selectors like :has() on body, or * combined with attributes, weaken that.
  • Custom property changes on :root cascade to every element that uses them.
  • Measure with DevTools: the Recalculate Style event shows elements affected and time spent.
Think in stages Before asking "is this CSS slow?", ask "which stage does this change force, and for how many elements?" That question points straight at the fix.

Practice
  1. Record a Performance trace of a page interaction and label the Recalculate Style, Layout, Paint, and Composite events.
  2. Change one property three ways (left, margin-left, transform) and compare which pipeline stages appear.
Key takeaways
  • Parse, style, layout, paint, and composite are the stages, and changes restart at different ones.
  • Geometry changes force layout; transforms and opacity can skip to compositing.
  • Measure how much work each stage does before optimizing.
