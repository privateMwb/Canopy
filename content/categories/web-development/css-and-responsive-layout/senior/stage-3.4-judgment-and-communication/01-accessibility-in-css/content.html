Accessibility in CSS

CSS decides whether focus is visible, text is readable, motion is safe, and layouts survive zoom and forced colors, so accessibility is partly a CSS discipline.

§1Focus, Contrast, and Targets

Never remove focus indication without replacing it. Use :focus-visible to show rings for keyboard users without distracting mouse users.

:focus-visible {
  outline: 3px solid var(--focus, #1d4ed8);
  outline-offset: 2px;
}
button:focus:not(:focus-visible) { outline: none; }   /* only if :focus-visible is supported */

a { text-decoration: underline; text-underline-offset: .15em; }    /* don't rely on color alone */
.btn { min-block-size: 44px; min-inline-size: 44px; }
RequirementGuideline (WCAG 2.2)
Text contrast4.5:1 for normal text, 3:1 for large text
UI component and focus indicator contrast3:1 against adjacent colors
Target sizeAt least 24 by 24 CSS px (AA); about 44 px recommended
Don't convey meaning by color aloneAdd text, icons, or patterns

§2Motion, Zoom, and Reflow

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
html { font-size: 100%; }              /* respect the user's default size */
body { line-height: 1.5; }
p, li { max-inline-size: 70ch; overflow-wrap: break-word; }

Content must reflow at 320 CSS px wide (400% zoom) with no two-dimensional scrolling, except for things like data tables and maps. Text spacing overrides (letter, word, line, and paragraph spacing) must not clip content, so avoid fixed heights on text containers.

§3Forced Colors and Other Preferences

In Windows High Contrast and similar modes, the browser replaces your colors with a system palette. Things that rely on background color or box-shadow for meaning can disappear.

.btn { border: 1px solid transparent; }          /* a transparent border becomes visible in forced colors */
@media (forced-colors: active) {
  .tab[aria-selected="true"] { outline: 2px solid Highlight; }
  .icon { forced-color-adjust: auto; }
}
@media (prefers-contrast: more) { :root { --line: #000; } }
@media (prefers-color-scheme: dark) { :root { color-scheme: dark; } }

Use system color keywords such as Highlight, ButtonText, and Canvas inside forced-colors, and test it using DevTools emulation. And use a visually-hidden class, not display: none, for text that must stay available to screen readers.

Test with your keyboard and zoom Unplug the mouse, Tab through the page, zoom to 400%, and turn on forced colors. These four checks take two minutes and catch most CSS accessibility bugs.

§4Common Mistakes

MistakeWhat HappensFix
Setting outline: none globallyKeyboard users can't see where they areStyle :focus-visible clearly instead
Using color alone to show errors or linksColorblind users miss the cueAdd text, icons, or underlines
Fixing the height of text containersText clips with larger fonts or spacingUse min-height and let content grow
Hiding content with display: none when it should be readRemoved from the accessibility treeUse a visually-hidden class when the text must remain available
Practice
  1. Audit one page for focus visibility, contrast, and target size, and fix every failure in CSS.
  2. Test a page at 400% zoom, with forced colors, and with reduced motion, and record what breaks.
Key takeaways
  • Keep strong :focus-visible styles, sufficient contrast, and large targets.
  • Respect reduced motion, zoom, text spacing, and reflow.
  • Support forced colors and other preference media queries.
