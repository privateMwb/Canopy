Internationalization & Accessibility

Accessibility and localization depend on each other. A screen reader pronounces text correctly only if the language is marked, and a layout that works in English can fail in Arabic or German without anyone noticing.

§1Language Declaration

Two criteria concern language: 3.1.1 Language of Page (Level A) and 3.1.2 Language of Parts (Level AA). Screen readers use the language attribute to choose a voice and pronunciation rules, and translation and spell-check tools depend on it too.

Use BCP 47 language tags
<html lang="pt-BR">

Mark a passage in another language
<p>The slogan <span lang="fr">liberté, égalité, fraternité</span> appeared.</p>

A language switcher: each option in its own language, with lang and hreflang
<nav aria-label="Language">
  <a href="/en/" lang="en" hreflang="en">English</a>
  <a href="/es/" lang="es" hreflang="es">Español</a>
  <a href="/ar/" lang="ar" hreflang="ar">العربية</a>
</nav>
  • Use language names, not flags, to identify languages. Flags stand for countries, not languages.
  • Localize everything users hear, including aria-label text, alt text, error messages, and live region announcements.
  • Mark brand names or code that should not be translated, using translate="no".

§2Right-to-Left and Mixed Direction

Languages such as Arabic and Hebrew read right to left. Set the direction with dir, and use logical CSS properties, which follow the reading direction instead of the physical screen.

<html lang="ar" dir="rtl">

Physical properties break in RTL
.card { margin-left: 1rem; padding-left: 1rem; text-align: left; }

Logical properties adapt automatically
.card { margin-inline-start: 1rem; padding-inline-start: 1rem; text-align: start; }

Isolate user-generated text so it does not scramble surrounding direction
<p>Comment by <bdi>مريم</bdi>: great article.</p>

Mirror directional icons (back arrows, progress indicators) in RTL, but not ones that show real-world things such as a clock or a media play button. Check that focus order, reading order, and keyboard arrow behavior also follow the logical direction.

§3Layout, Reading Level, and Culture

Translated text is a stress test for the criteria on resizing and spacing.

  • Text expansion: German or Finnish can run 30 percent or more longer than English. Fixed-width buttons and containers clip, so use flexible layouts, as the criteria on resize, reflow, and text spacing require.
  • Scripts: Chinese, Japanese, and Korean, and scripts like Thai or Devanagari, need different line heights and fonts, and may not support bold or italic as in Latin text.
  • Reading level: plain language matters in every language. Machine translation can raise complexity, so have a fluent reviewer check it.
  • Formats: dates, numbers, currencies, and phone numbers vary by locale, and ambiguity (is 03/04 March or April?) confuses readers. Use the user's locale.
  • Culture: metaphors, icons, and gestures do not always translate. Test with native speakers, including users of assistive technology.

Test each localized version, not just the default. An accessible English page does not guarantee an accessible one in another language.

The key insight Treat every language as a first-class version of the product, with its own accessibility checks. The same bug is often invisible in English and severe in another language.

§4Common Mistakes

MistakeWhat HappensFix
Missing or wrong lang attributeScreen readers use the wrong pronunciation, making text unintelligibleSet lang on the page, and on passages in other languages
Using margin-left and text-align: left everywhereRTL layouts become misaligned and brokenUse logical properties such as margin-inline-start and text-align: start
Translating visible text but not aria-label or altScreen reader users hear the wrong languageLocalize all accessible names, alt text, and announcements
Practice
  1. Switch a page you built to dir="rtl" and fix three layout problems using logical properties.
  2. Replace a few strings with a long translation (German or Finnish) and find where text clips or overlaps. Fix one with a flexible layout.
Key takeaways
  • Set lang on the page and on foreign passages, and localize every accessible name and announcement.
  • Use dir and logical CSS properties for right-to-left languages, and isolate mixed-direction text with bdi.
  • Test every language version for text expansion, scripts, reading level, and cultural fit.
