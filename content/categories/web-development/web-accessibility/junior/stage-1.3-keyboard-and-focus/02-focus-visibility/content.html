Focus Visibility

Keyboard users navigate by watching where focus is. Take that indicator away and the page becomes a maze with the lights off. Making focus obvious is cheap, and removing it is a classic accessibility bug.

§1Never Remove Focus Without Replacing It

Browsers draw a default focus ring on focused elements. Designers sometimes dislike its look and remove it with a single line of CSS, which breaks the page for every keyboard user.

/* Bad: focus is now invisible */
button:focus { outline: none; }
* { outline: 0; }

WCAG Success Criterion 2.4.7 (Level AA) requires that a keyboard focus indicator be visible. If you restyle focus, you must provide something at least as visible as what you removed.

§2Designing a Strong Focus Style

Use the :focus-visible selector. It shows the indicator when the browser decides a user needs it (typically keyboard navigation), and avoids showing a ring on mouse clicks. A good indicator is easy to see against both the element and its background.

:focus-visible {
  outline: 3px solid #1D4ED8;
  outline-offset: 2px;
}

/* On a dark background, use a contrasting color or a double ring */
.dark :focus-visible {
  outline-color: #FFFFFF;
  box-shadow: 0 0 0 5px #1D4ED8;
}
  • Aim for a contrast ratio of at least 3:1 between the indicator and the colors next to it.
  • Make it thick enough to see, commonly 2 to 3 pixels, and offset it so it does not blend into the element.
  • Prefer outline over box-shadow alone. Outlines still show in Windows high contrast and forced colors modes, while shadows are removed.
  • Keep the style consistent across the site so users learn what to look for.

§3When Focus Gets Hidden

Even with a good style, something may cover the focused element. Sticky headers and cookie banners are common culprits. WCAG 2.2 added Success Criterion 2.4.11 (Focus Not Obscured, Minimum, Level AA): a focused element must not be entirely hidden behind author-created content.

/* Leave room for a sticky header when tabbing or jumping to anchors */
html { scroll-padding-top: 5rem; }

/* A shadow ring for looks, plus a transparent outline that forced colors mode turns visible */
:focus-visible {
  box-shadow: 0 0 0 3px #1D4ED8;
  outline: 3px solid transparent;
}

After you style focus, test by tabbing through the whole page, then again with the browser zoomed to 200%, where overlaps are most likely to appear.

The key insight A designer's "clean" look is never a reason to remove focus. If the default ring does not suit the design, replace it with something better. Never replace it with nothing.

§4Common Mistakes

MistakeWhat HappensFix
Removing the outline with outline: noneKeyboard users cannot see where they areRestyle with :focus-visible instead of removing it
A faint, low-contrast focus colorTechnically present but impossible to see in practiceUse at least 3:1 contrast against adjacent colors
Sticky headers covering focused itemsThe focused element scrolls out of sight behind the headerUse scroll-padding-top and test while tabbing
Practice
  1. Search a stylesheet for outline: none or outline: 0. Replace each with a visible :focus-visible style.
  2. Tab through a page twice, at 100% and at 200% zoom. Note every place where focus is hard to see or hidden behind another element.
Key takeaways
  • Never remove the focus indicator without a visible replacement (WCAG 2.4.7).
  • Use :focus-visible with a thick, high-contrast outline, aiming for at least 3:1 against nearby colors.
  • Make sure sticky or overlapping content never fully hides the focused element.
