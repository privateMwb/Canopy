Skip Links & Bypass Blocks

Every page repeats the same header and menu. Without a shortcut, a keyboard user must tab through all of it again on every page. A skip link is a tiny feature that saves that effort.

§1Why Bypass Blocks Exist

Imagine a site with 40 links in its header. A mouse user ignores them in a glance. A keyboard user pressing Tab has to pass all 40 before reaching the content, on every single page.

WCAG Success Criterion 2.4.1 (Level A) requires a way to bypass blocks of content that repeat across pages. The most common and most visible solution is a skip link: the first focusable element on the page, which jumps straight to the main content.

§2Building a Skip Link

A skip link is an ordinary link to an ID on the page. It is normally hidden off screen, and appears when it receives keyboard focus.

<body>
  <a class="skip-link" href="#main">Skip to main content</a>
  <header>...</header>
  <main id="main" tabindex="-1">
    <h1>Page title</h1>
  </main>
</body>

.skip-link {
  position: absolute;
  top: 0; left: 0;
  transform: translateY(-120%);
  padding: 0.75rem 1rem;
  background: #fff; color: #000;
}
.skip-link:focus {
  transform: translateY(0);
}
  • Put the link first in the DOM so it is the first Tab stop.
  • Hide it with a transform or off-screen positioning, not display: none, which would also remove it from the Tab order.
  • Make sure it becomes visible when focused, with a strong style.
  • Add tabindex="-1" to the target so focus moves reliably in all browsers.

§3Other Ways to Bypass

Skip links are not the only technique, and they work best alongside the others.

TechniqueWho benefits
Skip linkSighted keyboard users, switch users, and screen reader users
Landmarks (main, nav)Screen reader users who jump between regions
HeadingsScreen reader users who list or step through headings
Collapsible navigationEveryone, by shortening what must be traversed

Landmarks and headings can satisfy the criterion on their own for assistive technology, but sighted keyboard users cannot see them. A visible-on-focus skip link covers that gap.

How to test Load a page, press Tab once, and look. A skip link should appear. Press Enter and check that the next Tab press lands inside the main content, not back in the header.

§4Common Mistakes

MistakeWhat HappensFix
Hiding the link with display: noneThe link is removed from the Tab order and never appearsPosition it off screen, then reveal it on :focus
The link target is not focusableIn some browsers focus stays on the link and the next Tab goes back to the headerAdd tabindex="-1" to the target element
A skip link that never becomes visibleSighted keyboard users see focus vanishGive .skip-link:focus a clear visible style
Practice
  1. Add a skip link to a page you have built, and test it with the keyboard alone.
  2. Check three well-known sites for a skip link by pressing Tab as soon as the page loads. Note which have one and how it looks.
Key takeaways
  • Repeated blocks need a bypass mechanism (WCAG 2.4.1), most commonly a skip link.
  • A skip link is the first focusable element, hidden until focused, and targets the main content.
  • Landmarks and headings help assistive technology, and a skip link helps sighted keyboard users.
