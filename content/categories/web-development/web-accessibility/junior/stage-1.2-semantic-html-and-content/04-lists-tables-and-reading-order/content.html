Lists, Tables & Reading Order

Screen readers announce structure as well as text. Real lists and tables carry that structure, and a logical source order keeps it all reading the way it looks.

§1Real Lists

When items belong together, mark them up as a list. A screen reader announces something like "list, five items", and lets users skip the whole thing or move item by item. Paragraphs with dashes or line breaks give none of that.

ElementUse for
ulItems where order does not matter
olSteps or ranked items where order matters
dlTerms and their descriptions, or name-value pairs
<ol>
  <li>Preheat the oven.</li>
  <li>Mix the dry ingredients.</li>
  <li>Bake for 25 minutes.</li>
</ol>

<!-- Navigation menus are lists of links too -->
<nav aria-label="Primary">
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/guides">Guides</a></li>
  </ul>
</nav>

§2Data Tables

Use tables for data, never for layout. A well-built data table lets a screen reader announce the row and column headers as the user moves through the cells.

<table>
  <caption>Quarterly sales by region (thousand units)</caption>
  <thead>
    <tr>
      <th scope="col">Region</th>
      <th scope="col">Q1</th>
      <th scope="col">Q2</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">North</th>
      <td>120</td>
      <td>140</td>
    </tr>
  </tbody>
</table>
  • caption gives the table a name and purpose.
  • th with scope="col" or scope="row" ties each data cell to its headers.
  • For complex tables with merged or multi-level headers, use id and headers, or simplify the table by splitting it.
  • Avoid empty cells with no meaning, and keep merged cells to a minimum.

§3Reading Order Follows the Source

Assistive technology reads and tabs through content in DOM order, not the order you see on screen. CSS can reposition elements visually (with order, grid placement, or absolute positioning), but the underlying order does not change.

<div class="cards">
  <a href="/c">Third card</a>   <!-- DOM order: 1 -->
  <a href="/a">First card</a>   <!-- DOM order: 2 -->
</div>

.cards { display: flex; }
.cards a:nth-child(1) { order: 2; }   /* Looks second, tabs first */
.cards a:nth-child(2) { order: 1; }

When the visual and DOM order disagree, keyboard focus jumps around and the page reads in a confusing sequence. The fix is almost always to reorder the HTML so the source matches the intended reading order.

The key insight If you can read the page in the same order with CSS turned off, and the structure still makes sense, you have done most of the work. Semantic structure should hold up on its own.

§4Common Mistakes

MistakeWhat HappensFix
Faking lists with line breaks or dashesNo "list of five items" announcement, and no list navigationUse ul, ol, and li
Using tables for page layoutScreen readers announce misleading table structureUse CSS Grid or Flexbox for layout, tables only for data
Reordering content only with CSSFocus and reading order no longer match the visual orderChange the HTML order to match the intended order
Practice
  1. Find a bulleted layout on a page you know and check whether it uses real list markup. Rewrite any that does not.
  2. Build a small table of your own data with a caption, column headers, and row headers, and listen to how a screen reader reads a cell.
Key takeaways
  • Use real lists for related items and real tables, with caption and th, for data.
  • Never use tables for layout.
  • Assistive technology follows DOM order, so put the source in the order users should read it.
