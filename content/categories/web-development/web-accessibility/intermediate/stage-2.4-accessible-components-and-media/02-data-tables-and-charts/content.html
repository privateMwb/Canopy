Data Tables & Charts

Data is where sighted users glance and everyone else gets stuck. Tables need real structure, and charts need a text equivalent that gives the same insight, not just a vague description.

§1Tables That Work at Scale

The basics from earlier, caption plus th with scope, carry over. Real data tables add features that need attention. For sortable columns, mark the current sort order with aria-sort on the header, and put a button inside the header so it is operable.

<table>
  <caption>Q3 revenue by region</caption>
  <thead>
    <tr>
      <th scope="col" aria-sort="none"><button>Region</button></th>
      <th scope="col" aria-sort="descending"><button>Revenue</button></th>
    </tr>
  </thead>
  <tbody>
    <tr><th scope="row">North</th><td>$4.2M</td></tr>
    <tr><th scope="row">South</th><td>$3.1M</td></tr>
  </tbody>
</table>

<!-- Wide tables: make the scroll container focusable, named, and keyboard-scrollable -->
<div role="region" aria-labelledby="cap" tabindex="0" style="overflow-x: auto;">
  <table>...</table>
</div>

Update aria-sort to ascending or descending on the active header, and none on the others, whenever the sort changes. Also announce the change with a live region, since the table updates silently.

§2Charts: Give the Insight in Text

A chart communicates a conclusion: a trend, a comparison, an outlier. A useful text alternative states that conclusion and offers the data, rather than describing the picture ("a line chart with blue and orange lines").

  1. Summary: one or two sentences stating the main takeaway.
  2. Data: a table with the underlying numbers, visible or in a disclosure.
  3. Visual hooks: direct labels, patterns, and enough contrast that the chart works on its own.
<figure>
  <svg role="img" aria-labelledby="c-title c-desc" viewBox="0 0 400 200">
    <title id="c-title">Monthly sales, January to June</title>
    <desc id="c-desc">Sales rose steadily from 120 units in January to 310 in June, with the largest jump in April.</desc>
    ...
  </svg>
  <figcaption>Monthly sales rose 158% over six months.</figcaption>
  <details>
    <summary>View data as a table</summary>
    <table>...</table>
  </details>
</figure>

§3Interactive and Complex Charts

Interactive charts with hover tooltips and zoom need extra care, because a pointer is usually assumed.

  • Make data points reachable by keyboard, using arrow keys between points, and show the same details on focus as on hover.
  • Do not rely on color alone. Vary shape, dash pattern, or labels, and keep 3:1 contrast against the background for marks.
  • Prefer simpler charts. A clear bar chart with direct labels beats an elaborate one that needs a legend and hover.
  • Offer a data table or download as an alternative for large or dense datasets.
  • If you use a charting library, check its accessibility documentation and test with a keyboard and a screen reader.

The same applies to maps and dashboards. Always ask: what decision does this visualization support, and can a person reach that decision without seeing it?

The key insight The best alternative for a chart is a short statement of its meaning, plus the data. Describing the chart's appearance helps no one. Describing what it shows helps everyone.

§4Common Mistakes

MistakeWhat HappensFix
A chart with alt="chart" or nothingBlind users get no information from it at allState the takeaway, and provide the data in a table
Sortable tables that do not expose the sort stateUsers cannot tell how the data is orderedUse aria-sort and a button in each sortable header
Charts that rely on colors in a legendUnreadable with color blindness or in grayscaleLabel directly, and vary pattern or shape
Practice
  1. Take a chart from a report and write a one-sentence summary that states its main finding, followed by the data as an HTML table.
  2. Make a table's columns sortable using buttons in headers and aria-sort, and verify that a screen reader announces the sort order.
Key takeaways
  • Data tables need captions, header associations, and exposed sort state, and wide tables need a focusable scroll region.
  • A chart's text alternative should state its conclusion, with the underlying data available as a table.
  • Interactive charts need keyboard access and must not depend on color alone.
