Time Limits & Re-authentication

Some people need more time to read, type, or operate a control. A session that expires without warning, or a form that loses everything on timeout, punishes exactly the users who are already working hardest.

§1Who Needs More Time

People using screen readers, switch devices, or voice control often take longer to complete a task. So do people with cognitive disabilities, people reading in a second language, and anyone interrupted mid-task. WCAG 2.2.1 Timing Adjustable (Level A) requires that when a page has a time limit set by the content, users can adjust it.

OptionWhat the user can do
Turn offDisable the time limit before it starts
AdjustChange the limit to at least ten times the default
ExtendBe warned before time runs out, with at least 20 seconds to extend, and be able to do so at least ten times with a simple action

Exceptions include real-time events such as an auction, limits that are essential to the activity, and limits longer than 20 hours.

§2A Session Timeout Warning

Most real sites meet this with a warning dialog shortly before a session expires, which lets users stay signed in with one action. The dialog should be announced to screen reader users and be operable by keyboard.

<dialog id="timeout" role="alertdialog" aria-labelledby="t-title" aria-describedby="t-desc">
  <h2 id="t-title">Your session is about to expire</h2>
  <p id="t-desc">You will be signed out in 2 minutes unless you continue.</p>
  <button id="stay">Stay signed in</button>
  <button id="out">Sign out</button>
</dialog>

<script>
  const dlg = document.getElementById('timeout');
  function warn() { dlg.showModal(); }              // focus moves into the dialog
  document.getElementById('stay').onclick = () => {
    refreshSession();                                // extend with a simple action
    dlg.close();
    scheduleWarning();
  };
</script>

The default focus lands inside the dialog, so the message is announced. Closing it returns focus to where the user was, so no work is lost.

§3Protecting Work and Re-authentication

Even with warnings, sessions end. Two stronger criteria describe the ideal. 2.2.6 Timeouts (Level AAA) says users should be told how long inactivity lasts before data loss. 2.2.5 Re-authenticating (Level AAA) says that after a session expires, users can sign in again and continue without losing data.

  • Save drafts automatically on long forms, either locally or on the server.
  • After re-authentication, return users to the same place with their data intact.
  • Say up front if a form has a limit: "This form times out after 20 minutes of inactivity".
  • Do not set short limits just to be safe. Make them as long as the security needs allow.
// Keep an unsaved draft so a timeout does not destroy the user's work
form.addEventListener('input', () => {
  sessionStorage.setItem('draft', JSON.stringify(Object.fromEntries(new FormData(form))));
});
The key insight Time pressure is a barrier by itself. The best fix is to avoid needless limits, and the second best is to warn early, make extending trivial, and protect everything the user typed.

§4Common Mistakes

MistakeWhat HappensFix
Logging users out with no warningWork is lost, and users with slower input have no chance to reactWarn before expiry and let users extend with one action
A timeout warning that is not announced or reachableScreen reader and keyboard users never see itUse a dialog that takes focus and works with the keyboard
Discarding form data on re-authenticationUsers must start long tasks againPreserve data, and return users to where they left off
Practice
  1. List every time limit you can find in a product you use (sessions, carts, codes). Which warn you, and which let you extend?
  2. Prototype a timeout warning dialog and test it with a keyboard and a screen reader.
Key takeaways
  • Content-set time limits must be turn-off-able, adjustable, or extendable (WCAG 2.2.1).
  • Warn before a session ends, make extending easy, and ensure the warning is announced and keyboard-operable.
  • Protect user data across timeouts and re-authentication.
