ARIA Roles, States & Properties

ARIA lets you describe custom interfaces to assistive technology when HTML alone cannot. It changes what is announced, but it adds no behavior of its own, so it needs careful use.

§1What ARIA Does and Does Not Do

WAI-ARIA (Accessible Rich Internet Applications) is a set of attributes that add information to the accessibility tree: what something is, what it is called, and what state it is in. Think of it as labels on the box. It does not add focus, keyboard handling, or styling. A div role="button" announces as a button, but does not respond to Enter or Space until you write that code.

ARIA has three building blocks:

KindMeaningExamples
RolesWhat an element isbutton, dialog, tablist, alert, navigation
PropertiesRelatively stable characteristicsaria-label, aria-labelledby, aria-describedby, aria-controls, aria-haspopup
StatesConditions that change as the user interactsaria-expanded, aria-checked, aria-selected, aria-pressed, aria-disabled, aria-invalid

§2Naming and Describing

Three properties supply names and descriptions, and they are used constantly:

  • aria-label supplies a name as a string, for controls with no visible text.
  • aria-labelledby points to the ID of an element whose text is the name, which is better when the label is already visible.
  • aria-describedby points to supporting text, such as a hint or an error, read after the name.
<nav aria-label="Breadcrumb">
  <ol>
    <li><a href="/">Home</a></li>
    <li><a href="/guides" aria-current="page">Guides</a></li>
  </ol>
</nav>

<section aria-labelledby="deals-h">
  <h2 id="deals-h">Today's deals</h2>
  ...
</section>

<button aria-describedby="del-hint">Delete account</button>
<p id="del-hint">This cannot be undone.</p>

aria-current marks the current item in a set, such as the current page in navigation, so the information is not conveyed by styling alone.

§3Keeping States Up to Date

A state attribute is a promise about what is true right now. When the interface changes, your script must update the attribute too, or the announcement becomes a lie.

<button type="button" aria-expanded="false" aria-controls="faq-1" id="faq-btn">
  What is your return policy?
</button>
<div id="faq-1" hidden>
  You can return items within 30 days.
</div>

<script>
  const btn = document.getElementById('faq-btn');
  const panel = document.getElementById('faq-1');
  btn.addEventListener('click', () => {
    const open = btn.getAttribute('aria-expanded') === 'true';
    btn.setAttribute('aria-expanded', String(!open));   // keep the state honest
    panel.hidden = open;
  });
</script>

Be careful with aria-hidden="true". It removes an element and everything inside it from the accessibility tree. Use it for purely decorative content, and never on something focusable, because users could tab to an element that the screen reader cannot see.

The key insight ARIA changes the description, not the reality. Every role you add creates an obligation to supply the matching keyboard behavior and to keep states in sync with what is on screen.

§4Common Mistakes

MistakeWhat HappensFix
Adding role="button" to a div and stopping thereIt is announced as a button but cannot be focused or activated by keyboardUse a native button, or add focus and key handling
Forgetting to update aria-expanded or aria-selectedScreen reader users hear the wrong stateUpdate state attributes in the same code that changes the UI
Using aria-hidden="true" on focusable contentKeyboard users land on an element that assistive technology ignoresHide with hidden or inert instead, or remove it from the Tab order too
Practice
  1. Build a disclosure button with aria-expanded and aria-controls. Check that a screen reader announces "expanded" and "collapsed" as you toggle it.
  2. Inspect a navigation bar. Where could aria-current="page" replace a purely visual "active" style?
Key takeaways
  • ARIA exposes roles, properties, and states to assistive technology, but adds no behavior.
  • Use aria-label, aria-labelledby, and aria-describedby to name and describe, and keep state attributes in sync with the interface.
  • Never put aria-hidden="true" on focusable elements.
