TanStack Query

TanStack Query turns server data into a few declarative hooks. Queries read and cache data, mutations change it, and invalidation keeps the screen honest afterward.

§1Setting Up and Reading with useQuery

Install @tanstack/react-query, create a QueryClient (which holds the cache), and provide it at the top of the app.

import { QueryClient, QueryClientProvider, useQuery } from "@tanstack/react-query";

const queryClient = new QueryClient({
  defaultOptions: { queries: { staleTime: 30_000, retry: 2 } },
});

root.render(
  <QueryClientProvider client={queryClient}>
    <App />
  </QueryClientProvider>
);

function Todos() {
  const { data, isPending, isError, error, isFetching } = useQuery({
    queryKey: ["todos"],
    queryFn: async ({ signal }) => {
      const res = await fetch("/api/todos", { signal });      // signal enables auto-cancellation
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      return res.json();
    },
  });

  if (isPending) return <p>Loading...</p>;
  if (isError) return <p role="alert">{error.message}</p>;
  return (
    <>
      {isFetching && <small>Refreshing...</small>}
      <ul>{data.map((t) => <li key={t.id}>{t.title}</li>)}</ul>
    </>
  );
}
  • queryKey identifies the data. Include every variable the query depends on: ["todos", { status, page }]. A change in the key triggers a new fetch (and caches each key separately).
  • queryFn must return a promise that throws on failure: check res.ok yourself, as fetch will not.
  • isPending means no data yet; isFetching means a request is in flight (including background refreshes). Showing both avoids spinners when you already have data to show.
  • staleTime (default 0) is how long data counts as fresh. gcTime is how long unused data stays in the cache.

§2Changing Data with useMutation

Reads use useQuery; writes (create, update, delete) use useMutation. A mutation does not run automatically: you call mutate from an event handler. After it succeeds, invalidate the queries whose data is now out of date, and the library refetches those that are on screen.

import { useMutation, useQueryClient } from "@tanstack/react-query";

function AddTodo() {
  const queryClient = useQueryClient();

  const addTodo = useMutation({
    mutationFn: async (title) => {
      const res = await fetch("/api/todos", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ title }),
      });
      if (!res.ok) throw new Error("Could not add");
      return res.json();
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["todos"] });     // refetch the list
    },
  });

  return (
    <form onSubmit={(e) => {
      e.preventDefault();
      addTodo.mutate(new FormData(e.currentTarget).get("title"));
      e.currentTarget.reset();
    }}>
      <input name="title" required />
      <button disabled={addTodo.isPending}>{addTodo.isPending ? "Adding..." : "Add"}</button>
      {addTodo.isError && <p role="alert">{addTodo.error.message}</p>}
    </form>
  );
}

invalidateQueries matches by key prefix: invalidating ["todos"] also refreshes ["todos", { page: 2 }]. This is why a hierarchical key design pays off.

§3Keys, Organization, and Habits

// a key factory keeps keys consistent and invalidation easy
export const todoKeys = {
  all: ["todos"],
  list: (filters) => [...todoKeys.all, "list", filters],
  detail: (id) => [...todoKeys.all, "detail", id],
};

// custom hooks hide the plumbing from components
export function useTodo(id) {
  return useQuery({ queryKey: todoKeys.detail(id), queryFn: () => getTodo(id), enabled: id != null });
}

queryClient.invalidateQueries({ queryKey: todoKeys.all });           // everything about todos
queryClient.prefetchQuery({ queryKey: todoKeys.detail(5), queryFn: () => getTodo(5) });   // warm the cache on hover
  • Wrap queries in custom hooks (useTodos, useTodo) so components never see keys or fetch code.
  • Use enabled to wait for a dependency: enabled: Boolean(userId).
  • By default, queries refetch on window focus, reconnect, and mount when stale: this is a feature, not a bug. Tune it with staleTime rather than disabling it.
  • Install the React Query DevTools to see keys, freshness, and cache contents live.
  • Do not copy data into useState; read it directly and derive from it.
  • Treat an error from a mutation as UI to show, and a failed query as something to retry or display.
The key is the dependency array of server data Anything that changes what you would fetch belongs in the queryKey. Get the key right, and caching, refetching, and deduplication follow automatically.

§4Common Mistakes

MistakeWhat HappensFix
Leaving a variable out of the queryKeyDifferent inputs share one cache entry; wrong data showsInclude every value the query function uses
A queryFn that does not throw on HTTP errorsErrors are cached as successful dataThrow when !res.ok
Forgetting to invalidate after a mutationThe list does not show the changeCall invalidateQueries (or update the cache) in onSuccess
Copying data into local stateLocal copy goes stale and ignores refetchesUse data directly; derive values from it
Practice
  1. Add TanStack Query to a project and convert one useEffect fetch into a useQuery with a custom hook.
  2. Add a create mutation that invalidates the list, and watch the list refresh in the React Query DevTools.
  3. Create a key factory for one resource and use it for a list, a detail query, and an invalidation.
Key takeaways
  • useQuery reads and caches data by key; useMutation writes it; invalidateQueries refreshes affected data.
  • Put every dependency of a query in its key, and make queryFn throw on failure.
  • Hide queries behind custom hooks and tune freshness with staleTime rather than disabling refetching.
