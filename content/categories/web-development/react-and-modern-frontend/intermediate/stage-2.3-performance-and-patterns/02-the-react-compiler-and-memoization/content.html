The React Compiler & Memoization

The React Compiler adds memoization for you at build time, so most manual useMemo, useCallback, and memo calls become unnecessary. It rewards code that follows the rules, and a few cases still need your attention.

§1What the Compiler Does

The React Compiler is a build-time tool that analyzes your components and hooks and automatically inserts memoization, caching values and skipping re-renders where the inputs have not changed. It works at a finer grain than hand-written memo: it can memoize parts within a component, even after an early return, which manual hooks cannot.

// you write plain code
function ProductList({ products, onAdd }) {
  const sorted = [...products].sort(byPrice);
  return (
    <ul>
      {sorted.map((p) => (
        <ProductRow key={p.id} product={p} onAdd={() => onAdd(p.id)} />
      ))}
    </ul>
  );
}

// the compiler, at build time, caches `sorted` and the row elements,
// recomputing only when `products` or `onAdd` change: no useMemo/useCallback/memo written

It is installed as a Babel plugin (babel-plugin-react-compiler), enabled through your build tool's React plugin, and it works with React 17 and later (with a small runtime package for versions before 19). You can adopt it incrementally, by directory, or opt a component out with the "use no memo" directive.

// vite.config.js
import react from "@vitejs/plugin-react";
export default {
  plugins: [react({ babel: { plugins: [["babel-plugin-react-compiler", {}]] } })],
};

// opt a component out while debugging
function Legacy() {
  "use no memo";
  /* ... */
}

§2What Is Still on You

The compiler assumes your code follows the Rules of React: components and hooks are pure during render, props and state are never mutated, and hooks are called unconditionally. If a component breaks those rules, the compiler skips optimizing it (it bails out rather than risk changing behavior) and the ESLint plugin reports why.

  • Do not mutate props, state, or values created earlier in render. Compiled code that mutates can produce stale UI.
  • Keep render pure: no reading mutable globals or ref.current, and no side effects in the body.
  • Dependencies still matter in effects. The compiler memoizes values, but useEffect dependency arrays are still your responsibility, and you may still need useMemo/useCallback to give an effect a stable dependency or to control exactly when an effect fires.
  • It does not fix structural problems: state held too high, a giant unvirtualized list, or an expensive algorithm remain slow.
  • It does not make slow code fast, it avoids repeating work; an expensive function that must run is still expensive.
// the compiler cannot safely optimize this (mutation during render), and it will skip the component
function Bad({ items }) {
  items.sort(byName);                         // mutates a prop
  return <List items={items} />;
}

// pure version: compiler-friendly
function Good({ items }) {
  const sorted = [...items].sort(byName);
  return <List items={sorted} />;
}

§3Working with the Compiler

SituationWhat to do
Writing new codeWrite plain code; skip useMemo/useCallback/memo unless profiling shows a need
Existing manual memoizationLeave it; the compiler works with it. Remove gradually only when you can verify behavior
A component is not optimizedRun the ESLint plugin (eslint-plugin-react-hooks includes compiler rules) and fix the reported rule violations
An effect fires too oftenCheck its dependencies; use useMemo/useCallback or restructure so the dependency is stable
Debugging odd behaviorAdd "use no memo" to the component to compare behavior with and without compilation
  • Check what was compiled in React DevTools: compiled components show a "Memo ✨" badge.
  • Adopt incrementally: start with a small directory, run your tests and profile, then widen.
  • The compiler reduces the need for micro-optimizations, but it does not replace understanding why components render, the earlier lessons still apply.
  • The compiler is relatively new, and details change between releases. Check the official docs for current setup and supported versions.
Write simple, pure React The best way to benefit from the compiler is to follow the Rules of React: pure render, no mutation, unconditional hooks. Do that, and memoization becomes the compiler's job instead of yours.

§4Common Mistakes

MistakeWhat HappensFix
Mutating props or state in renderCompiler skips the component or produces stale outputCopy before changing; keep render pure
Adding useMemo everywhere alongside the compilerClutter with no benefitWrite plain code; memoize only for proven effect-dependency or perf reasons
Expecting the compiler to fix state placed too high or giant listsApp stays slowFix structure and virtualize
Ignoring compiler lint warningsComponents silently left unoptimizedFix the reported rule violation
Practice
  1. Enable the compiler in a small project and check which components show the "Memo" badge in DevTools.
  2. Introduce a mutation in render, and see the lint warning and the lost optimization; then fix it.
  3. Profile a component before and after enabling the compiler and compare the number of re-renders.
Key takeaways
  • The compiler adds fine-grained memoization at build time, reducing manual memo, useMemo, and useCallback.
  • It relies on pure, mutation-free code and skips components that break the rules.
  • Effect dependencies, structure, and expensive algorithms are still your responsibility.
