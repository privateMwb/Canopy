useRef & the DOM

Most of the time React owns the DOM, but sometimes you must reach an element directly to focus it, scroll it, or measure it. useRef is the tool, and it also holds values that should survive renders without causing them.

§1Refs Hold a Value Without Re-rendering

useRef(initial) returns an object { current: initial } that persists across renders. Unlike state, changing ref.current does not trigger a re-render. That makes refs useful for values React does not need to display: timer ids, previous values, or whether something already happened.

import { useRef, useState } from "react";

function Stopwatch() {
  const [elapsed, setElapsed] = useState(0);
  const intervalRef = useRef(null);                  // not shown on screen, so a ref

  function start() {
    intervalRef.current = setInterval(() => setElapsed((s) => s + 1), 1000);
  }
  function stop() {
    clearInterval(intervalRef.current);
  }

  return (
    <>
      <p>{elapsed}s</p>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
    </>
  );
}

§2Reaching the DOM

Attach a ref to a JSX element with the ref attribute. After React commits the DOM, ref.current points to the real element. It is null before that, so use it in event handlers and effects, not during render.

function SearchBar() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus();                        // focus on mount
  }, []);

  function clear() {
    inputRef.current.value = "";
    inputRef.current.focus();
  }

  return (
    <>
      <input ref={inputRef} placeholder="Search" />
      <button onClick={clear}>Clear</button>
    </>
  );
}

Common reasons to use a DOM ref are focusing an input, scrolling an element into view (ref.current.scrollIntoView()), measuring size with getBoundingClientRect(), controlling a <video>, and integrating with a non-React library such as a chart or map.

§3Using Refs Safely

  • Treat refs as an escape hatch. If you can do it with props and state, do that. Do not use refs to read or set values you could keep in state.
  • Do not change DOM that React manages (adding or removing children, changing text) through a ref: React will not know and may overwrite or crash. Focus, scroll, and measure are safe because they do not change what React renders.
  • Do not read or write ref.current during render, except to initialize it. It makes components unpredictable.
  • In React 19, ref is a normal prop for function components, so a component can accept ref and pass it to an inner element. In older versions, forwardRef was required.
  • For lists of refs, use a ref callback (ref={(el) => ...}) rather than calling useRef in a loop, which breaks the rules of hooks.
// React 19: ref is just a prop
function TextInput({ ref, ...props }) {
  return <input ref={ref} {...props} />;
}

function Form() {
  const ref = useRef(null);
  return (
    <>
      <TextInput ref={ref} />
      <button onClick={() => ref.current.focus()}>Focus</button>
    </>
  );
}
State for what you show, refs for what you hold If a value appears on screen, use state so that React updates it. If it is something the component only needs to remember (a timer id, a DOM node), a ref is the right place.

Practice
  1. Add a button that focuses an input, and focus it automatically on mount with an effect.
  2. Build a "scroll to top" button using a ref and scrollIntoView.
  3. Store a timer id in a ref to build a start/stop countdown that cleans up on unmount.
Key takeaways
  • useRef holds a value across renders without causing re-renders.
  • Attach refs to elements to focus, scroll, or measure the real DOM after commit.
  • Treat refs as an escape hatch: do not manage React-controlled DOM through them.
