useEffect

Rendering must be pure, but real apps also need to talk to things outside React: the network, timers, the browser title. useEffect is the place for that work, and its dependency array decides when it runs.

§1What an Effect Is For

An effect is code that synchronizes your component with something outside React. It runs after React has committed the render to the screen, so it never blocks painting. Typical uses are subscribing to a WebSocket, setting up a timer, changing document.title, or connecting to a non-React library.

import { useEffect, useState } from "react";

function Title({ count }) {
  useEffect(() => {
    document.title = `Count: ${count}`;       // sync the browser tab with state
  });                                          // no array: runs after every render

  return <p>{count}</p>;
}

Think of an effect as describing *what to keep in sync*, not *when to run*. React decides when to run it, based on whether the values it uses have changed.

§2The Dependency Array

The second argument controls when the effect re-runs. React compares each dependency with its value from the previous render and re-runs the effect if any changed.

FormRuns
useEffect(fn)After every render
useEffect(fn, [])Once, after the first render (on mount)
useEffect(fn, [a, b])On mount, and whenever a or b changes
useEffect(() => {
  document.title = `${user.name} (${unread})`;
}, [user.name, unread]);                       // list everything the effect reads

The rule is simple: list every reactive value (props, state, and variables derived from them) that the effect uses. Do not leave them out to "stop it from running", and do not guess. The react-hooks/exhaustive-deps ESLint rule finds omissions for you, and you should treat its warnings as bugs. If the dependency list causes a problem, the fix is almost always to change the code, not the list.

§3Running Twice in Development

In development, StrictMode mounts every component, unmounts it, and mounts it again, running each effect an extra time. This is deliberate: it exposes effects that cannot cleanly start, stop, and start again, which is exactly what happens in real apps when a user navigates away and back. If your effect misbehaves when it runs twice, it is missing a cleanup.

useEffect(() => {
  const id = setInterval(() => console.log("tick"), 1000);
  return () => clearInterval(id);              // cleanup: stop what you started
}, []);
  • The function you return from an effect is its cleanup. React runs it before the next run of the effect, and when the component unmounts.
  • Effects are not event handlers. If something happens because the user did something (clicked Save), do it in the handler, not in an effect.
  • Effects cannot be async directly (the function would return a promise instead of a cleanup). Define an async function inside and call it.
  • An effect that sets state with no sensible dependencies can create an infinite loop, since each update causes another render.
Describe the sync, not the schedule Ask "what outside thing must match my state?" and "what values does it read?" The dependency array is simply that second answer.

§4Common Mistakes

MistakeWhat HappensFix
Leaving out dependencies to avoid re-runsThe effect uses stale values and shows old dataList everything it reads; restructure the code if needed
Using an effect to respond to a clickExtra renders, confusing flowDo it directly in the event handler
No cleanup for timers or subscriptionsDuplicates and leaks, visible in StrictModeReturn a cleanup function
Making the effect function asyncReact warns: it must return nothing or a functionCall an async function declared inside the effect
Practice
  1. Write a component that sets document.title from a prop using the correct dependency array.
  2. Create a clock that updates every second, with a cleanup, and verify with StrictMode that there is only one active interval.
  3. Turn on the exhaustive-deps lint rule and fix every warning it reports in a small project.
Key takeaways
  • Effects synchronize a component with external systems after render.
  • List every reactive value the effect uses in its dependency array.
  • Return a cleanup function for anything you start; StrictMode double-runs effects to check this.
