Components & Props

Components take inputs called props and return UI. Passing data down through props, and treating that data as read-only, is how every React app is assembled.

§1Function Components and Props

A component is a JavaScript function that returns JSX. It receives one argument, an object called props, holding whatever the parent passed in as attributes. Destructuring the argument is the usual style.

function Avatar({ name, size = 48, url }) {      // size has a default
  return <img src={url} alt={name} width={size} height={size} />;
}

function Team() {
  return (
    <div>
      <Avatar name="Ada" url="/ada.png" />
      <Avatar name="Lin" url="/lin.png" size={72} />
    </div>
  );
}

Pass strings with quotes, and everything else (numbers, booleans, objects, functions) with braces. A prop written with no value, like <Button disabled />, means true.

  • Component names start with a capital letter; that is how React tells them from HTML tags.
  • Define components at the top level of a file, never inside another component.
  • One component per responsibility; if it is hard to name, it is probably doing too much.

§2Props Are Read-Only

A component must never change its own props. Data flows one way: from parent to child. If a child needs to change something, the parent passes a function down and the child calls it (you will use this heavily in the next stage).

function Price({ amount }) {
  amount = amount * 1.2;           // reassigning a local copy is allowed but confusing
  props.amount = 0;                // never mutate props

  return <p>{amount}</p>;
}

// better: derive a new value
function Price({ amount }) {
  const withTax = amount * 1.2;
  return <p>{withTax.toFixed(2)}</p>;
}

Components should also be pure during rendering: given the same props, return the same JSX, and do not change variables outside themselves. This is what lets React call a component again whenever it needs to.

§3children and Composition

Whatever you put between a component's tags arrives as the special children prop. This lets you build generic wrappers (cards, layouts, modals) that do not need to know their content.

function Card({ title, children }) {
  return (
    <section className="card">
      <h3>{title}</h3>
      {children}
    </section>
  );
}

<Card title="Shipping">
  <p>Free over $50.</p>
  <button>Details</button>
</Card>

Prefer composition (components containing other components) to long lists of configuration props. A Card that accepts children is more flexible than one with showButton, buttonLabel, showFooter, and ten more props. You can also pass JSX as a regular prop (<Layout sidebar={<Nav />} />) when a component has several slots.

const props = { name: "Ada", url: "/ada.png" };
<Avatar {...props} size={64} />      // spread: pass an object's fields as props
Data down, events up Parents give children data through props. Children tell parents things happened by calling functions the parent passed down. Keep that direction in mind and most structure questions answer themselves.

§4Common Mistakes

MistakeWhat HappensFix
Defining a component inside another componentIt is recreated every render; state resets and performance suffersMove it to the top level of the file
Mutating a prop (props.items.push(x))Silent bugs and UI that does not updateTreat props as read-only; copy before changing
Forgetting braces on non-string props (count="5")You pass the string "5"Use count={5}
Adding a prop for every variationA component with 15 props nobody understandsUse children and composition
Practice
  1. Build a Button with label, variant (default "primary"), and disabled props, and render three different ones.
  2. Create a Panel that accepts children and use it to wrap two different pieces of content.
  3. Refactor a component with five boolean props into smaller composed components.
Key takeaways
  • Components are functions that take a props object and return JSX.
  • Props are read-only and flow from parent to child.
  • children and composition give flexible, reusable building blocks.
