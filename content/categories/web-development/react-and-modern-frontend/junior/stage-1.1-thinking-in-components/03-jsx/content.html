JSX

JSX looks like HTML inside JavaScript, but it is JavaScript. A few rules, and the idea that {} opens a window back into JavaScript, explain nearly every error beginners hit.

§1What JSX Is

JSX is a syntax extension that your build tool turns into plain function calls. <h1 className="title">Hi</h1> becomes roughly jsx("h1", { className: "title", children: "Hi" }), which returns a plain object describing an element. That is why JSX can appear anywhere a value can: in variables, arguments, conditions, and return statements.

const heading = <h1 className="title">Hi</h1>;      // a value, not a string

function Greeting() {
  const badge = <span>new</span>;
  return <p>Welcome {badge}</p>;
}

§2Expressions in Curly Braces

Inside JSX, curly braces switch back to JavaScript. You can put any expression (something that produces a value) in them: variables, calculations, function calls, and ternaries. You cannot put a statement such as if or for directly in braces.

const user = { name: "Ada", points: 120 };
const avatar = "/img/ada.png";

return (
  <article>
    <img src={avatar} alt={`Photo of ${user.name}`} />
    <h2>{user.name.toUpperCase()}</h2>
    <p>{user.points * 2} bonus points</p>
    <p>{user.points > 100 ? "Gold" : "Silver"} member</p>
    <p>{new Date().getFullYear()}</p>
  </article>
);

Use quotes for fixed string attributes (alt="logo") and braces for anything computed (src={avatar}). Never wrap braces in quotes: src="{avatar}" is the literal text {avatar}.

React escapes values placed in braces, so {userInput} is rendered as text, not as HTML. That protects you from most injection bugs. There is an escape hatch, dangerouslySetInnerHTML, whose name is the warning: avoid it unless the HTML is sanitized.

§3The Rules That Surprise Beginners

RuleExample
Return one root element (or a fragment)<>...</> wraps siblings without adding a DOM node
Close every tag<img />, <input />, <br />
Use className, not class<div className="card">
Use htmlFor, not for<label htmlFor="email">
Attributes are camelCaseonClick, tabIndex, autoFocus
style takes an objectstyle={{ color: "red", fontSize: 18 }}
Comments use braces{/* a comment */}
function Profile() {
  return (
    <>
      <h1 className="title">Ada</h1>
      <label htmlFor="bio">Bio</label>
      <textarea id="bio" />
      <p style={{ color: "gray", marginTop: 8 }}>Mathematician</p>
      {/* the double braces are braces plus an object */}
    </>
  );
}

A multi-line return needs parentheses, or JavaScript inserts a semicolon after return and your component returns undefined. Components may also return null to render nothing.

function Broken() {
  return
    <h1>Never shown</h1>;     // returns undefined: parentheses are missing
}
Braces open a window into JavaScript Everything between { and } is an ordinary JavaScript expression. If you can put it on the right side of const x =, you can put it in braces.

Practice
  1. Write a ProductCard that shows a name, a price formatted with toFixed(2), and a "Sale" label via a ternary.
  2. Fix this snippet by hand: <div class="a"><img src="x.png"><label for="n">Name</label></div>.
  3. Render a user-supplied string containing <b>hi</b> and observe that React shows it as text.
Key takeaways
  • JSX is JavaScript in disguise; each tag becomes an element object.
  • Curly braces hold expressions, never statements.
  • Use className, htmlFor, camelCase attributes, one root (or a fragment), and closed tags.
