What React Is & Why It Exists

React lets you describe what the screen should look like for a given set of data, and takes care of updating the page when that data changes. That one idea replaces a great deal of manual DOM code.

§1The Problem: Keeping the DOM in Sync

In plain JavaScript you update the page by hand: find an element, change its text, add a class, remove a node. For a small page that is fine. As an app grows, you end up with many places that change the same piece of UI, and bugs appear when one of them forgets to run. This style is called imperative: you write the steps.

// imperative: every change is a manual instruction
function addTodo(text) {
  todos.push(text);
  const li = document.createElement("li");
  li.textContent = text;
  list.append(li);
  count.textContent = todos.length + " items";
  emptyMessage.hidden = true;           // forget one of these and the UI is wrong
}

Each new feature (delete, edit, filter) must remember to update the list, the count, and the empty message. The more places data is shown, the more places can disagree.

§2The React Idea: UI as a Function of State

React is declarative: you describe the UI for the current data, and React works out what to change. You write a component, a function that returns the markup for the data it is given. When the data changes, React calls it again and updates only the parts of the real page that differ.

function TodoList({ todos }) {
  return (
    <section>
      <p>{todos.length} items</p>
      {todos.length === 0 && <p>Nothing to do.</p>}
      <ul>
        {todos.map((t) => <li key={t.id}>{t.text}</li>)}
      </ul>
    </section>
  );
}

There is no "update the count" step. The count is part of the description, so it can never be out of date. This is the mental model the whole course builds on: UI = f(state).

§3Components and the Virtual DOM

A React app is a tree of components. Small components (a button, a card) are combined into larger ones (a list, a page). Each one is reusable and responsible for its own piece of the screen.

When state changes, React re-runs the affected components and compares the new output with the previous output, an internal description of the UI often called the virtual DOM. It then applies only the differences to the real DOM, a process called reconciliation. You never write that diffing code, and it is usually fast enough that you do not think about it.

Plain JavaScriptReact
You update the DOM step by stepYou describe the result; React updates the DOM
State lives in variables and the DOMState lives in one place and the UI follows it
Reuse by copying markup or writing helpersReuse by composing components
No built-in structureA shared model: components, props, state

React is a library for building user interfaces, not a full framework. It does not decide how you route, fetch data, or style. You will choose those tools yourself (and later see frameworks like Next.js that make those choices for you). React also runs outside the browser, for example with React Native for mobile apps.

The one sentence to remember You do not tell React *how* to change the page. You tell it what the page should look like right now, given the data, and React makes the page match.

§4Common Mistakes

MistakeWhat HappensFix
Thinking React is a full frameworkYou look for built-in routing or data fetching and do not find itAdd libraries (React Router, TanStack Query) or use a framework such as Next.js
Mixing manual DOM edits with ReactReact overwrites your changes on the next renderLet React own the DOM; reach for refs only when you must
Believing the virtual DOM makes everything instantly fastSlow components still make a slow appKeep components cheap and measure before optimizing
Putting all the UI in one giant componentHard to read, test, and reuseSplit into small, focused components
Practice
  1. Take a small plain-JavaScript to-do script and list every line that updates the DOM. Which of those could be removed if the UI were described from the data?
  2. Sketch a login page as a tree of components (page, form, input, button) on paper.
  3. In your own words, explain the difference between imperative and declarative UI to a friend.
Key takeaways
  • React is declarative: describe the UI for the current state and React updates the DOM.
  • Apps are trees of small, reusable components, each returning markup for its data.
  • React is a UI library; routing, data fetching, and styling are separate choices.
