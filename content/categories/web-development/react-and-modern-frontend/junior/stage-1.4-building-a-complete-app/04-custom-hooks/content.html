Custom Hooks

When several components need the same stateful logic, copying it is a mistake. A custom hook packages that logic into a function you can reuse, while each component still gets its own state.

§1Extracting Logic into a Hook

A custom hook is a regular JavaScript function whose name starts with use and that calls other hooks. It shares logic, not state: every component that calls the hook gets its own independent copy of the state inside it.

// before: this logic is copy-pasted into every component that fetches
function Users() {
  const [data, setData] = useState(null);
  const [status, setStatus] = useState("loading");
  useEffect(() => { /* fetch, set data, set status ... */ }, []);
  /* ... */
}

// after: one reusable hook
function useFetch(url) {
  const [state, setState] = useState({ status: "loading", data: null, error: null });

  useEffect(() => {
    const controller = new AbortController();
    setState({ status: "loading", data: null, error: null });

    fetch(url, { signal: controller.signal })
      .then((res) => {
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return res.json();
      })
      .then((data) => setState({ status: "success", data, error: null }))
      .catch((err) => {
        if (err.name !== "AbortError") setState({ status: "error", data: null, error: err.message });
      });

    return () => controller.abort();
  }, [url]);

  return state;
}

function Users() {
  const { status, data, error } = useFetch("/api/users");
  if (status === "loading") return <p>Loading...</p>;
  if (status === "error") return <p role="alert">{error}</p>;
  return <ul>{data.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}

The component now describes what it wants (users) instead of how to fetch them. The hook can be improved in one place and every component benefits.

§2More Examples

// a boolean toggle
function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn((v) => !v), []);
  return [on, toggle];
}

// state that persists in localStorage
function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    try {
      const raw = localStorage.getItem(key);
      return raw === null ? initial : JSON.parse(raw);
    } catch {
      return initial;
    }
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}

const [theme, setTheme] = useLocalStorage("theme", "light");

// track something in the browser
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const onResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, []);
  return width;
}

§3Rules and Good Habits

  • Name it useSomething. The linter and other developers rely on the prefix to know the rules of hooks apply.
  • Follow the rules of hooks: call hooks only at the top level of a component or another hook, never inside conditions, loops, or nested functions.
  • Return what is useful: an array for two or three values ([value, setValue]), an object when there are several and names help.
  • Share logic, not just code: if the function does not use any hook, it is an ordinary helper and should not start with use.
  • Keep hooks focused. useFetch and useDebounced are better than one useEverything.
  • Test them with a small test component or the renderHook helper from React Testing Library.
  • Before writing your own data-fetching hook for a real project, consider whether TanStack Query already does it better.
Hooks share logic, not state If two components call useToggle(), each has its own on value. To share the actual value between components, lift the state up or use context.

§4Common Mistakes

MistakeWhat HappensFix
Naming a hook without the use prefixLinter cannot check the rules; confusionName it useSomething
Expecting two components to share a hook's stateEach gets its own copyLift state up or use context
Calling hooks conditionally inside a custom hook"Rendered more hooks than during the previous render"Call every hook unconditionally, at the top
Building a giant all-purpose hookHard to understand and reuseExtract small, focused hooks
Practice
  1. Extract fetching logic from two components into a shared useFetch hook with loading, error, and success states.
  2. Write useLocalStorage and use it to remember a theme choice across reloads.
  3. Write useDebounced(value, delay) and use it in a search box.
Key takeaways
  • A custom hook is a function starting with use that reuses stateful logic between components.
  • Each component calling a hook gets its own state; hooks share logic, not data.
  • Keep hooks small and focused, and follow the rules of hooks inside them.
