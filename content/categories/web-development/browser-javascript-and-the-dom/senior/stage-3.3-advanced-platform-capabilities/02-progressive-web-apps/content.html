Progressive Web Apps

A Progressive Web App is an ordinary website that can be installed, launched like an app, and work offline. The pieces are small, and the real skill is knowing when installability is worth it.

§1What Makes a PWA

"PWA" is not a single API. It is a set of capabilities that, together, let a site behave like an installed app: a web app manifest, a service worker for offline support, and HTTPS. Browsers use these to offer an install option and to run the site in its own window with an icon on the home screen or desktop.

<link rel="manifest" href="/manifest.webmanifest">
<meta name="theme-color" content="#15803D">

// manifest.webmanifest
{
  "name": "Canopy Notes",
  "short_name": "Notes",
  "start_url": "/?source=pwa",
  "scope": "/",
  "display": "standalone",
  "background_color": "#F7F6F1",
  "theme_color": "#15803D",
  "icons": [
    { "src": "/icons/192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/icons/maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ],
  "shortcuts": [{ "name": "New note", "url": "/new" }]
}

display: "standalone" removes the browser chrome; a maskable icon lets the OS crop the icon into its own shape. Installability criteria differ between browsers and change over time, so check the Application → Manifest panel in DevTools, which lists exactly what is missing.

§2Installing and Behaving Like an App

Chromium browsers fire beforeinstallprompt, which you can capture to offer an install button at a sensible moment. Safari and Firefox have different flows (Safari uses *Add to Home Screen*), so never make install a requirement.

let deferred;
window.addEventListener("beforeinstallprompt", (e) => {
  e.preventDefault();                       // hold the browser's default prompt
  deferred = e;
  installBtn.hidden = false;
});
installBtn.addEventListener("click", async () => {
  deferred.prompt();
  const { outcome } = await deferred.userChoice;   // "accepted" | "dismissed"
  deferred = null;
  installBtn.hidden = true;
});
window.addEventListener("appinstalled", () => track("installed"));

// detect that you are running as an installed app
const isInstalled = matchMedia("(display-mode: standalone)").matches || navigator.standalone;

Once installed, users expect app behavior: it should open to something useful offline, handle the Back button sensibly, respect safe areas (env(safe-area-inset-*)), avoid tiny tap targets, and not feel like a webpage inside a frame.

§3Push, Badges, and Reality Checks

Installed PWAs can use more of the platform. Web Push lets a service worker receive a message from your server and show a notification even when no page is open. The flow has several parts, and each is a point of failure and a privacy decision.

// page: after a user action, subscribe
const reg = await navigator.serviceWorker.ready;
const sub = await reg.pushManager.subscribe({
  userVisibleOnly: true,                              // required: every push must show a notification
  applicationServerKey: VAPID_PUBLIC_KEY,
});
await fetch("/api/push/subscribe", { method: "POST", body: JSON.stringify(sub), headers: { "Content-Type": "application/json" } });

// sw.js: receive and show
self.addEventListener("push", (e) => {
  const data = e.data?.json() ?? { title: "Update", body: "" };
  e.waitUntil(self.registration.showNotification(data.title, { body: data.body, tag: data.tag, data: { url: data.url } }));
});
self.addEventListener("notificationclick", (e) => {
  e.notification.close();
  e.waitUntil(clients.openWindow(e.notification.data.url));
});

navigator.setAppBadge?.(3);                           // badge the app icon where supported
  • Decide if you need it. A PWA adds a service worker, a manifest, and an update flow to maintain. If your site is mostly content with no offline need, a fast normal site may serve users better.
  • Support varies: iOS requires installation to the home screen for push, and some capabilities (background sync, certain device APIs) are absent on some platforms. Always feature-detect.
  • Ask for push permission only after a user action and with a clear benefit, never on first load.
  • Test installation on real devices and measure installs, retention, and offline use rather than assuming value.
Progressive means optional A PWA must be an enhancement: the site works normally in any browser, and installability, push, and offline are added where supported. Feature-detect everything and never gate core functionality behind them.

§4Common Mistakes

MistakeWhat HappensFix
No maskable iconThe OS crops or letterboxes the icon awkwardlyProvide a maskable icon with a safe zone
Prompting for push notifications on first visitUsers deny; browsers may suppress future promptsAsk after a relevant action with explained value
Assuming every browser supports the same install flowNo install button on Safari/Firefox; broken expectationsFeature-detect and provide instructions where needed
Skipping the offline experienceInstalled app shows a dinosaur page without a connectionPrecache a shell and an offline fallback
Practice
  1. Add a manifest and icons to a small app, and use DevTools' Manifest panel to confirm it is installable.
  2. Build an in-app install button using beforeinstallprompt, hidden on browsers that do not fire it.
  3. Write down, for a product you know, whether a PWA is worth it, with the evidence you would need to decide.
Key takeaways
  • A PWA is a manifest, a service worker, and HTTPS, enabling install, offline, and app-like windows.
  • Install and push flows differ by browser: feature-detect, ask at the right moment, and never gate core features.
  • A PWA is a maintenance commitment; adopt it where installability and offline use bring real value.
