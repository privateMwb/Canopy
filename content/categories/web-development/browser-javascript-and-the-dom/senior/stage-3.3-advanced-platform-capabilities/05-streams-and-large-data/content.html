Streams & Large Data

Waiting for a whole response before using any of it wastes time and memory. The Streams API lets you process data as it arrives, in pieces, with automatic handling of speed mismatches between producer and consumer.

§1Why Streams

Without streams, await res.json() or await res.text() buffers the entire body in memory before you see any of it. For large downloads, logs, AI responses, or file uploads, that means long waits for first content and high peak memory. A stream delivers the data in chunks, so you can show results, parse, or write to disk while the rest is still arriving.

const res = await fetch("/api/large-export");
const reader = res.body.getReader();            // res.body is a ReadableStream of Uint8Array chunks
const decoder = new TextDecoder();

let received = 0;
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  received += value.length;
  progress.value = received / Number(res.headers.get("content-length") ?? 0);
  output.append(decoder.decode(value, { stream: true }));   // stream: true handles split characters
}

Note { stream: true } on the decoder: a multi-byte character (an emoji, an accented letter) can be split across two chunks, and the decoder needs to know more is coming.

§2Pipes, Transforms, and Backpressure

The real power is composing streams. A ReadableStream produces data, a TransformStream changes it, and a WritableStream consumes it. pipeThrough and pipeTo connect them and handle backpressure automatically: if the consumer is slow, the pipeline tells the producer to pause, so memory does not balloon.

// decompress, decode, and split into lines, all incrementally
const lines = (await fetch("/logs.ndjson.gz")).body
  .pipeThrough(new DecompressionStream("gzip"))
  .pipeThrough(new TextDecoderStream())
  .pipeThrough(splitLines());

// a custom transform
function splitLines() {
  let buffer = "";
  return new TransformStream({
    transform(chunk, controller) {
      buffer += chunk;
      const parts = buffer.split("\n");
      buffer = parts.pop();                         // keep the incomplete last line
      for (const line of parts) controller.enqueue(line);
    },
    flush(controller) { if (buffer) controller.enqueue(buffer); },
  });
}

for await (const line of lines) render(JSON.parse(line));   // ReadableStream is async-iterable in modern browsers

CompressionStream and DecompressionStream compress and decompress with no library, and TextDecoderStream handles the text decoding, so a few lines replace what used to need a dependency and a full buffer.

§3Real Uses and Pitfalls

Streams matter most when data is large, slow, or unbounded.

  • Streaming responses: render AI or server-sent text as it arrives (for await over res.body with a TextDecoderStream).
  • Large files: read a File with file.stream(), hash or upload it in slices instead of loading it into memory; use the File System Access API or Origin Private File System to write incrementally.
  • Parsing big formats: process NDJSON, CSV, or logs line by line; update the UI progressively, in batches, rather than per line.
  • Cancellation: pass an AbortSignal to fetch, or call reader.cancel(), so you stop downloading data you no longer need.
  • Uploads: streaming request bodies (fetch with a ReadableStream, requires duplex: "half" and HTTP/2+) are supported only in some browsers; feature-detect.
  • Memory discipline: a stream only helps if you do not collect everything yourself afterwards. Appending every chunk to an array defeats the purpose.
// upload a large file in slices with progress, never holding it all in memory
async function upload(file, signal) {
  const CHUNK = 5 * 1024 * 1024;
  for (let offset = 0; offset < file.size; offset += CHUNK) {
    const slice = file.slice(offset, offset + CHUNK);          // a Blob view, not a copy
    await fetch(`/upload?offset=${offset}`, { method: "PUT", body: slice, signal });
    progress.value = Math.min(1, (offset + CHUNK) / file.size);
  }
}

// tee: consume one stream twice (e.g. display and cache)
const [forScreen, forCache] = res.body.tee();
Do not collect what you streamed If you push every chunk into an array and join them at the end, you have the memory cost of the non-streaming version and more code. Process each chunk, keep only what you need, and let backpressure do its job.

§4Common Mistakes

MistakeWhat HappensFix
Decoding chunks with new TextDecoder().decode(chunk) without stream: trueCharacters split across chunks are corruptedUse { stream: true } or TextDecoderStream
Awaiting res.json() on a huge responseLong wait and a large memory spikeStream and parse incrementally (e.g. NDJSON)
Ignoring cancellationDownloads continue after the user navigated awayPass an AbortSignal and cancel the reader
Updating the DOM for every single lineMain thread is overwhelmedBatch updates (per frame or per N items)
Practice
  1. Fetch a large NDJSON file and render rows progressively using pipeThrough and a line-splitting transform.
  2. Hash a 500 MB file by reading file.stream() in chunks and show progress without exhausting memory.
  3. Add cancellation to a streaming download and verify in the Network panel that transfer stops.
Key takeaways
  • Streams deliver data in chunks, cutting time-to-first-content and peak memory for large data.
  • pipeThrough/pipeTo compose producers and transforms with automatic backpressure.
  • Stream end to end: decode correctly, batch UI work, support cancellation, and never re-buffer everything.
