The Event Object

Every handler receives an event object describing what happened and where. Knowing target, currentTarget, and preventDefault lets you write handlers that react to the right thing.

§1What the Event Object Contains

The browser passes an Event to your handler as its first argument. Its type depends on the event: a click gives a MouseEvent, a key press a KeyboardEvent, and so on, but they all share a base set of properties.

PropertyMeaning
typeThe event name, such as "click"
targetThe element where the event originated
currentTargetThe element the listener is attached to
timeStampWhen the event happened
defaultPreventedWhether preventDefault() was called
isTrustedtrue if the user caused it, false if script did
document.addEventListener("click", (e) => {
  console.log(e.type);           // "click"
  console.log(e.target);         // the thing you actually clicked
  console.log(e.currentTarget);  // document
});

§2target vs. currentTarget

These two differ whenever the event happens on a descendant of the element holding the listener. target is the deepest element that received the event. currentTarget is always the element your code is attached to.

<ul id="menu">
  <li><button>Open</button></li>
  <li><button>Close</button></li>
</ul>

menu.addEventListener("click", (e) => {
  console.log(e.target);        // the <button> that was clicked
  console.log(e.currentTarget); // the <ul>: always
});

This distinction is the basis of event delegation, which you will meet in the next lesson. For now, remember that currentTarget is stable and target varies. If the click lands on an icon inside a button, target may be the icon, so use target.closest("button") to find the control you care about.

§3preventDefault and stopPropagation

Many events have a default action built into the browser: following a link, submitting a form, toggling a checkbox. Calling event.preventDefault() cancels that action while still letting your code run.

link.addEventListener("click", (e) => {
  e.preventDefault();         // stay on the page
  openInModal(link.href);
});

form.addEventListener("submit", (e) => {
  e.preventDefault();         // do not reload the page
  save(new FormData(form));
});

stopPropagation() is different: it stops the event from travelling on to other elements. It does not cancel the default action, and the two are independent. Use stopPropagation sparingly, because it can silently break analytics and other code listening higher up the tree.

Some events (such as scroll and touchstart) are not cancelable, and listeners marked { passive: true } promise never to call preventDefault, which lets the browser scroll smoothly without waiting for your code.

Remember the pair target answers "what was actually hit?" and currentTarget answers "where is my listener?" Confusing them is the most common event bug.

§4Common Mistakes

MistakeWhat HappensFix
Using this/target inside an arrow function handler for the listener elementGets the wrong element or undefinedUse event.currentTarget
Forgetting preventDefault() on a submit handlerThe page reloads and your work is lostCall it first in the handler
Using stopPropagation() to "fix" a bubbling problemBreaks other listeners and is hard to debugCheck event.target instead
Calling preventDefault() in a passive listenerIgnored, with a console warningRemove passive, or avoid cancelling
Practice
  1. Attach one click listener to a list and log both target and currentTarget when you click different children.
  2. Make a link that logs a message and does not navigate, then make it navigate only when Ctrl/Cmd is held (e.ctrlKey).
  3. Intercept a form's submit, read its fields with FormData, and log them without reloading.
Key takeaways
  • The event object tells you what happened, where it started (target), and where your listener is (currentTarget).
  • preventDefault() cancels the browser's default action; stopPropagation() only stops travel.
  • Prefer inspecting target to blocking propagation.
