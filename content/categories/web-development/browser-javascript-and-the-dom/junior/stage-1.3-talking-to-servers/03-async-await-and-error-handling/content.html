async/await & Error Handling

async and await let you write asynchronous code that reads like ordinary step-by-step code. Combined with try/catch, they make failure handling clear, and they keep a failed request from breaking the page.

§1async and await

An async function always returns a promise. Inside it, await pauses that function until a promise settles, then gives you its value (or throws its error). Other code on the page keeps running while it waits.

async function loadUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return await res.json();            // the returned value becomes the promise value
}

loadUser(7).then((u) => console.log(u.name));

await only works inside an async function or at the top level of a module. Forgetting it is easy to do and produces a promise where you expected a value: const user = loadUser(7) gives you Promise {<pending>}.

§2try / catch / finally

Wrap the awaited calls in try/catch. A rejected promise turns into a thrown error you can catch, and finally is the place for cleanup that must run either way, such as hiding a spinner.

async function showProfile(id) {
  spinner.hidden = false;
  try {
    const user = await loadUser(id);
    render(user);
  } catch (err) {
    errorBox.textContent = "Could not load the profile. Try again.";
    console.error(err);                 // keep details for developers
  } finally {
    spinner.hidden = true;              // runs on success and on failure
  }
}

Show the user something useful and log the technical detail separately. Never leave the interface stuck on "Loading..." because an error skipped the cleanup.

§3Sequential vs. Parallel

Each await waits before the next line starts. Independent requests should therefore start together and be awaited together with Promise.all, which finishes when all succeed and rejects as soon as one fails.

// slow: second request waits for the first
const user = await loadUser(7);
const posts = await loadPosts(7);

// fast: both run at once
const [user2, posts2] = await Promise.all([loadUser(7), loadPosts(7)]);

// when partial results are fine
const results = await Promise.allSettled([loadUser(7), loadPosts(7)]);
results.forEach((r) => console.log(r.status, r.value ?? r.reason));

A common trap is using await inside forEach: the callback is async but forEach does not wait for it. Use a for...of loop for sequential work or Promise.all(items.map(...)) for parallel work.

Handle failure on purpose Every network call can fail. Decide what the user should see for each failure, put cleanup in finally, and make sure a failure in one part of the page does not take down the rest.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting awaitYou get a pending promise instead of the valueAdd await, or return the promise
Awaiting independent requests one by oneThe page is slower than it needs to beStart them together with Promise.all
Using await inside forEachLoop finishes before the work doesUse for...of or Promise.all(map(...))
Empty catch {} blocksErrors vanish and bugs are impossible to findShow a message and log the error
Practice
  1. Rewrite a then chain from the previous lesson with async/await and try/catch/finally.
  2. Fetch two independent endpoints sequentially and then in parallel; measure each with console.time.
  3. Make a loader that shows a spinner, and prove (by forcing a failure) that finally always hides it.
Key takeaways
  • async functions return promises; await unwraps them and turns rejection into a thrown error.
  • Use try/catch/finally so failures are handled and cleanup always runs.
  • Start independent requests together with Promise.all; do not await them one at a time.
