fetch & Promises

fetch asks a server for data without reloading the page. It returns a promise, so you also need to understand the small set of promise ideas that make asynchronous code work.

§1Promises in One Page

A promise is an object that stands for a value that is not available yet. It is in one of three states: *pending*, *fulfilled* with a value, or *rejected* with an error. You attach handlers with then (success) and catch (failure).

const p = new Promise((resolve, reject) => {
  setTimeout(() => resolve("done"), 500);
});

p.then((value) => console.log(value))      // "done" after 0.5s
 .catch((err) => console.error(err))
 .finally(() => console.log("always runs"));

Each then returns a new promise, which is what makes chaining possible: whatever you return from a handler becomes the value for the next one, and a thrown error skips ahead to the next catch.

§2Making a Request with fetch

fetch(url, options) returns a promise that resolves to a Response as soon as the headers arrive. The body is read with a second promise, such as res.json() or res.text().

fetch("https://api.example.com/users/7")
  .then((res) => res.json())
  .then((user) => console.log(user.name))
  .catch((err) => console.error("failed", err));

// sending data
fetch("/api/notes", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Buy milk" }),
});

The body can be read once. If you need it twice, call res.clone() first. Common readers are json(), text(), blob(), and arrayBuffer().

§3The Big Gotcha: HTTP Errors Do Not Reject

fetch rejects its promise only when the request itself fails, such as a network outage, DNS failure, or a CORS block. A 404 or 500 response is still a successful *fetch*, so the promise fulfills. You must check the status yourself.

fetch("/api/missing")
  .then((res) => {
    if (!res.ok) {                        // ok is true for 200-299
      throw new Error(`HTTP ${res.status}`);
    }
    return res.json();
  })
  .then(render)
  .catch(showError);                      // now 404s land here too

Wrapping this in a small helper means you write the check once:

function getJSON(url) {
  return fetch(url).then((res) => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  });
}
fetch only rejects on network failure A 404 or 500 fulfills the promise. Always check res.ok before you parse the body, or your catch will never see server errors.

Practice
  1. Fetch a public JSON API and log one field using only then/catch.
  2. Request a URL that returns a 404 and show that the promise still fulfills, then handle it with a res.ok check.
  3. Write postJSON(url, data) that stringifies the data, sets headers, and rejects on any non-2xx status.
Key takeaways
  • A promise represents a future value; then, catch, and finally handle the outcome.
  • fetch resolves when headers arrive; read the body with a second promise.
  • HTTP error statuses do not reject: check res.ok yourself.
