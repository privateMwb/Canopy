URLs, History & Routing Basics

The URL is state you can read, change, and share. The location object and the History API let a single page behave like many without a full reload.

§1The URL and location

new URL() parses a URL into parts, and location is the same information for the current page. URLSearchParams handles the query string safely, including encoding.

const url = new URL("https://shop.com/items?cat=books&page=2#reviews");
url.pathname;                    // "/items"
url.searchParams.get("cat");     // "books"
url.hash;                        // "#reviews"

const params = new URLSearchParams(location.search);
params.get("page");              // "2" (a string)
params.set("page", "3");
params.toString();               // "cat=books&page=3"

location.href = "/login";        // navigate (adds a history entry)
location.replace("/login");      // navigate without a Back entry
location.reload();

Use URLSearchParams rather than splitting strings yourself; it handles encoding (%20, & inside values) correctly.

§2The History API

history.pushState(state, "", url) changes the address bar and adds a history entry without loading the page. history.replaceState changes the current entry instead. When the user presses Back or Forward, the browser fires a popstate event and you update the page to match.

function go(path) {
  history.pushState({}, "", path);
  render(path);
}

window.addEventListener("popstate", () => {
  render(location.pathname + location.search);
});

// update a filter in the URL without adding history noise
const u = new URL(location.href);
u.searchParams.set("q", "dom");
history.replaceState({}, "", u);

pushState never triggers popstate itself, only navigating through history does, so you call render yourself after pushing. Keep each URL meaningful: someone who copies it and opens it fresh should see the same view.

§3A Minimal Router

A client-side router is a small loop: intercept link clicks, push the new URL, render by path, and render again on popstate.

const routes = {
  "/": () => "<h1>Home</h1>",
  "/about": () => "<h1>About</h1>",
};

function render() {
  const view = routes[location.pathname] ?? (() => "<h1>Not found</h1>");
  document.querySelector("#app").innerHTML = view();   // static strings only
}

document.addEventListener("click", (e) => {
  const a = e.target.closest("a[data-link]");
  if (!a) return;
  e.preventDefault();
  history.pushState({}, "", a.getAttribute("href"));
  render();
});
window.addEventListener("popstate", render);
render();

This works only if the server also returns your app for those paths. If someone loads /about directly and the server answers 404, the router never starts, so static hosts need a fallback to index.html. Hash routing (#/about) avoids that requirement because the fragment is never sent to the server.

Put shareable state in the URL Search terms, filters, selected tabs, and page numbers belong in the query string. It makes the Back button, bookmarks, and shared links all work with no extra code.

§4Common Mistakes

MistakeWhat HappensFix
Parsing the query string with splitBreaks on encoded characters and & in valuesUse URLSearchParams
Expecting pushState to fire popstateThe view does not update after a pushCall your render function after pushing
Using location.href for every filter changePage reloads and history fills upUse replaceState for small updates
Deep links returning 404 from the serverDirect visits to /about failConfigure a fallback to index.html, or use hash routing
Practice
  1. Build a search box that stores its term in ?q= using replaceState and restores it from the URL on load.
  2. Make a three-view mini site with the minimal router above, and confirm Back and Forward work.
  3. Print every part of new URL(location.href), then add a query parameter containing spaces and & to see encoding in action.
Key takeaways
  • URL and URLSearchParams parse and build URLs correctly; location navigates.
  • pushState/replaceState change the URL without reloading, and popstate handles Back/Forward.
  • A router needs server cooperation for deep links, or hash-based URLs.
