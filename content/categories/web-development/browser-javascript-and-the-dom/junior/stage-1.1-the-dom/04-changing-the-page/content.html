Changing the Page

Once you have an element, you can change its text, attributes, classes, and styles, or create and insert entirely new elements. Choosing the safe tool for each job keeps your pages fast and free of injection bugs.

§1Text and HTML

textContent sets the text of an element and treats the value as plain text. innerHTML parses the value as HTML. The difference is a security boundary.

const out = document.querySelector("#out");

out.textContent = "Hello <b>world</b>";   // shows the tags literally
out.innerHTML = "Hello <b>world</b>";     // renders bold text

const name = new URLSearchParams(location.search).get("name");
out.textContent = name;     // safe even if name contains <script>
out.innerHTML = name;       // XSS: attacker-controlled HTML runs

Use textContent for anything that came from a user, a URL, or an API. Use innerHTML only with markup you wrote yourself.

§2Attributes, Classes, and Styles

Attributes are read and written with getAttribute, setAttribute, and removeAttribute. Many have matching properties (el.id, input.value, a.href), which are usually more convenient.

For styling, change classes rather than writing styles directly. Your CSS stays in stylesheets and your script just flips state.

const btn = document.querySelector("#save");

btn.setAttribute("aria-busy", "true");
btn.disabled = true;

btn.classList.add("loading");
btn.classList.remove("primary");
btn.classList.toggle("active");          // add if absent, remove if present
btn.classList.contains("loading");       // true

btn.dataset.userId = "42";               // <button data-user-id="42">
btn.style.setProperty("--progress", "60%");   // for CSS variables

data-* attributes are the standard place to attach small pieces of information to an element, and dataset converts data-user-id to userId for you.

§3Creating and Inserting Elements

Build elements with createElement, fill them in, and insert them with append, prepend, before, after, or replaceWith. Remove with remove().

const li = document.createElement("li");
li.textContent = "New item";
li.classList.add("todo");

document.querySelector("#list").append(li);

const copy = li.cloneNode(true);   // true = copy the children too
li.after(copy);

li.remove();

When adding many items, build them in a DocumentFragment (or collect them in an array) and insert once. One insertion means one update to the page instead of many.

const frag = document.createDocumentFragment();
for (const text of ["a", "b", "c"]) {
  const li = document.createElement("li");
  li.textContent = text;
  frag.append(li);
}
list.append(frag);   // a single insertion

A <template> element is a good alternative for repeated markup: write the HTML once, then clone template.content for each item.

Never trust the string Every time you assign to innerHTML, ask where the string came from. If any part of it is user input, use textContent or build elements with createElement instead.

§4Common Mistakes

MistakeWhat HappensFix
Setting innerHTML with user inputCross-site scripting: attacker code runs on your pageUse textContent or createElement
Writing el.style.color throughout the scriptStyling is scattered and hard to changeToggle classes and style them in CSS
Appending in a loop and re-reading layout each timeSlow, janky updates on long listsUse a fragment and append once
Using el.className = "x" to add a classErases every other class on the elementUse classList.add
Practice
  1. Write addItem(text) that creates an <li>, sets its text safely, and appends it to a list.
  2. Add a data-id to each item and read it back with dataset.
  3. Insert 1,000 list items two ways (one at a time, and via a fragment) and compare with console.time.
Key takeaways
  • textContent is safe for untrusted text; innerHTML parses markup and is an injection risk.
  • Change classes and attributes, not inline styles, to reflect state.
  • Create elements with createElement and insert them in as few operations as you can.
