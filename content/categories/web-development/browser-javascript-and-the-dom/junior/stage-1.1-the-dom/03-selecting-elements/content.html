Selecting Elements

Before you can change an element you have to find it. querySelector and querySelectorAll cover almost every case, but the shape of what they return matters.

§1querySelector and querySelectorAll

Both take any CSS selector. querySelector returns the first match or null. querySelectorAll returns a NodeList of all matches, which is empty (never null) if there are none.

const title = document.querySelector("#title");
const firstCard = document.querySelector(".card");
const links = document.querySelectorAll("nav a[href^='/docs']");

const input = document.querySelector("form input[name='email']");

Because the argument is a CSS selector, everything you know from stylesheets works: classes, ids, attributes, descendant and child combinators, :not(), :first-child, and so on. You can also call the methods on any element to search only inside it.

const list = document.querySelector("#results");
const items = list.querySelectorAll("li");   // only inside #results

§2Older Methods, and Why They Differ

You will still see getElementById, getElementsByClassName, and getElementsByTagName. getElementById is fine and fast. The others return live collections.

MethodReturnsLive?
querySelectorOne element or nullNo
querySelectorAllNodeListNo (static snapshot)
getElementByIdOne element or nulln/a
getElementsByClassNameHTMLCollectionYes
el.childrenHTMLCollectionYes

A live collection updates itself when the DOM changes. A static one is fixed at the moment you asked. Live collections cause subtle bugs in loops that add or remove elements:

const live = document.getElementsByClassName("item");
for (const el of live) {
  el.remove();           // the collection shrinks while you iterate
}                        // so every other element is skipped

const snap = document.querySelectorAll(".item");
snap.forEach((el) => el.remove());   // safe: the list does not change

§3Working with the Results

NodeList has forEach and is iterable with for...of, but it is not an array. If you need map, filter, or find, convert it.

const prices = [...document.querySelectorAll(".price")]
  .map((el) => Number(el.textContent.replace("$", "")));

const total = prices.reduce((sum, n) => sum + n, 0);

Always handle the missing case. A null from querySelector is the most common runtime error in beginner DOM code.

const banner = document.querySelector(".banner");
banner?.classList.add("visible");   // optional chaining: does nothing if null

if (!banner) {
  console.warn("no .banner on this page");
}
A good default Reach for querySelector and querySelectorAll first. They accept the selectors you already know and return static results, which avoids live-collection surprises.

Practice
  1. Select every external link on a page (a[href^='http']) and add a rel attribute to each one.
  2. Reproduce the live-collection bug with getElementsByClassName, then fix it two different ways.
  3. Write a helper $(selector, root = document) that returns the first match, and $$ that returns an array.
Key takeaways
  • querySelector returns one element or null; querySelectorAll returns a static NodeList.
  • getElementsBy* and children are live: they change as the DOM changes.
  • Always plan for a missing element, and convert to an array when you need array methods.
