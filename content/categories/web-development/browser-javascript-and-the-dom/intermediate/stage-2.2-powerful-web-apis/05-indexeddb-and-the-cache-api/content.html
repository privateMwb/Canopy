IndexedDB & the Cache API

When localStorage is too small or too simple, IndexedDB stores structured data and files, and the Cache API stores whole HTTP responses. Together they make apps that keep working with a poor connection.

§1IndexedDB Basics

IndexedDB is a transactional, asynchronous database in the browser. It stores JavaScript objects (including blobs and typed arrays) in object stores, with optional indexes for fast lookups, and its quotas are measured in hundreds of megabytes or more rather than 5 MB. The raw API is event-based and verbose, so many projects use a tiny wrapper such as idb, shown below.

import { openDB } from "idb";           // small promise wrapper over IndexedDB

const db = await openDB("notes-app", 1, {
  upgrade(db) {                          // runs on first open or version bump
    const store = db.createObjectStore("notes", { keyPath: "id" });
    store.createIndex("byUpdated", "updatedAt");
  },
});

await db.put("notes", { id: crypto.randomUUID(), text: "Hello", updatedAt: Date.now() });

const all = await db.getAll("notes");
const recent = await db.getAllFromIndex("notes", "byUpdated");   // sorted by date
await db.delete("notes", someId);

Schema changes happen only in the upgrade callback, controlled by the version number you pass. Bump it and add the new store or index there; never try to alter structure elsewhere.

§2Transactions and Gotchas

Every read or write happens inside a transaction, which succeeds or fails as a unit. A transaction auto-commits when there is no pending request, so do not await unrelated async work (like a fetch) inside it, or it will close early and the next operation throws TransactionInactiveError.

const tx = db.transaction(["notes", "outbox"], "readwrite");
await Promise.all([
  tx.objectStore("notes").put(note),
  tx.objectStore("outbox").add({ type: "create", note }),
  tx.done,                                  // resolves when committed
]);

// BAD: tx would auto-commit during the fetch
// const tx = db.transaction("notes", "readwrite");
// const res = await fetch(...);            // too late
// tx.objectStore("notes").put(await res.json());
  • Data is per-origin and can be evicted under storage pressure unless you call navigator.storage.persist().
  • Use navigator.storage.estimate() to see usage and quota.
  • Keys can be strings, numbers, dates, or arrays; they sort by type then value.
  • Handle upgradeneeded/blocked events when several tabs hold older versions open.

§3The Cache API

The Cache API stores Request/Response pairs. It was designed for service workers but is available from page script, too. It is ideal for caching static assets and API responses so they can be served without the network.

const cache = await caches.open("api-v1");

await cache.add("/api/config");                       // fetch and store
await cache.put("/data.json", await fetch("/data.json"));

const hit = await cache.match("/api/config");
if (hit) console.log(await hit.json());

// a simple cache-first helper
async function cachedFetch(url) {
  const c = await caches.open("api-v1");
  const cached = await c.match(url);
  if (cached) return cached;
  const fresh = await fetch(url);
  if (fresh.ok) c.put(url, fresh.clone());           // clone: a body can be read once
  return fresh;
}

await caches.delete("api-v0");                        // remove an old version

§4Common Mistakes

MistakeWhat HappensFix
Awaiting a fetch inside a transactionTransactionInactiveError: the transaction auto-committedFetch first, then open the transaction and write
Changing the schema outside upgradeStores or indexes do not existBump the version and use upgrade
Forgetting response.clone() before cachingBody already consumed; empty responsePut a clone in the cache, return the original
Treating the browser as permanent storageData lost on eviction or clearingSync important data to a server
Practice
  1. Create an IndexedDB store of notes with an index on updatedAt and list them newest first.
  2. Reproduce the TransactionInactiveError by awaiting a fetch inside a transaction, then fix it.
  3. Write a cache-first cachedFetch helper and verify in DevTools (Application tab) that entries are stored and served.
Key takeaways
  • IndexedDB stores structured data asynchronously and transactionally; schema changes live in upgrade.
  • Keep transactions short and never await unrelated async work inside them.
  • The Cache API stores HTTP responses; choose storage by data shape, and remember it can be evicted.
