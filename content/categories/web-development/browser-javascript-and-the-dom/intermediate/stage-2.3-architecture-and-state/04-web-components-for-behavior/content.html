Web Components for Behavior

Custom elements let you package markup and behavior into a new HTML tag that works in any page or framework. Used for behavior first, they are a lightweight way to organize interactive code.

§1Custom Elements

A custom element is a class that extends HTMLElement, registered under a name that contains a hyphen. Once registered, the browser upgrades every matching tag in the page, including ones added later.

class CopyButton extends HTMLElement {
  connectedCallback() {                        // element was added to the DOM
    this.addEventListener("click", this.#copy);
  }
  disconnectedCallback() {                     // removed: clean up
    this.removeEventListener("click", this.#copy);
  }
  #copy = async () => {
    await navigator.clipboard.writeText(this.getAttribute("text") ?? "");
    this.dispatchEvent(new CustomEvent("copied", { bubbles: true }));
  };
}
customElements.define("copy-button", CopyButton);

<copy-button text="npm install vite"><button>Copy</button></copy-button>

This pattern, sometimes called progressive enhancement, is powerful: the markup inside works as plain HTML if the script fails to load, and the custom element adds behavior on top. Notice that it needs no framework, and each instance manages its own listeners.

§2Lifecycle and Attributes

The browser calls lifecycle callbacks you define. Use connectedCallback for setup (it can run more than once if the element moves), disconnectedCallback for cleanup, and attributeChangedCallback to react to attributes you list in observedAttributes.

class TabList extends HTMLElement {
  static observedAttributes = ["selected"];

  connectedCallback() {
    this.addEventListener("click", (e) => {
      const tab = e.target.closest("[role=tab]");
      if (tab) this.setAttribute("selected", tab.dataset.id);   // state lives in an attribute
    });
    this.#sync();
  }
  attributeChangedCallback() { this.#sync(); }

  #sync() {
    const id = this.getAttribute("selected");
    for (const t of this.querySelectorAll("[role=tab]")) {
      t.setAttribute("aria-selected", String(t.dataset.id === id));
    }
  }
}
customElements.define("tab-list", TabList);

Reflecting state in attributes makes components inspectable in DevTools and styleable with CSS (tab-list[selected="2"]). You can also expose properties and methods on the class for script to call.

§3Shadow DOM, and When to Use It

Shadow DOM gives an element a private DOM subtree, with its own scoped styles that do not leak in or out. It is ideal for widgets that must look the same on any page. The cost is that outside CSS cannot reach inside (except through CSS variables and ::part), and form participation and accessibility need more care.

class UserBadge extends HTMLElement {
  constructor() {
    super();
    const root = this.attachShadow({ mode: "open" });
    root.innerHTML = `
      <style>
        :host { display: inline-flex; gap: .5rem; }
        .name { font-weight: 600; color: var(--badge-color, #1C1F26); }
      </style>
      <slot name="avatar"></slot><span class="name"><slot></slot></span>`;
  }
}
customElements.define("user-badge", UserBadge);
  • For behavior that enhances existing markup, you often do not need Shadow DOM at all.
  • Use <slot> to let users supply their own content inside a shadow tree.
  • Expose styling through CSS custom properties (--badge-color) and ::part().
  • Choose a framework if you need heavy reactivity; use custom elements when you need portable pieces.
Start with behavior, add Shadow DOM when you need isolation A custom element without Shadow DOM is just a named place to attach behavior to normal markup. That alone removes a lot of ad hoc querySelector wiring.

§4Common Mistakes

MistakeWhat HappensFix
Defining a custom element name without a hyphencustomElements.define throwsUse names like my-widget
Adding listeners in connectedCallback and never removing themDuplicates when the element moves; leaksRemove in disconnectedCallback, or use an AbortController
Reading attributes in the constructorAttributes may not exist yetRead them in connectedCallback
Using Shadow DOM for everythingGlobal styles and forms stop workingUse it only when you need style isolation
Practice
  1. Build a <copy-button> custom element that copies text and dispatches a copied event.
  2. Make a <tab-list> that stores the selected tab in an attribute and updates aria-selected.
  3. Wrap a small card in Shadow DOM with a slot and a CSS variable for its accent color.
Key takeaways
  • A custom element is a class registered with customElements.define under a hyphenated name.
  • Use connectedCallback, disconnectedCallback, and observedAttributes to manage setup, cleanup, and reactions.
  • Shadow DOM isolates styles and markup, but is optional: use it when isolation is worth the trade-offs.
