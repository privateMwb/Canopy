Promises in Depth

Beyond then and catch, promises offer combinators for running work in parallel, handling partial failure, and racing deadlines. Knowing exactly how each behaves, and how rejections go unhandled, prevents subtle bugs.

§1Chaining and Error Flow

Each then returns a new promise. If a handler returns a value, the next promise fulfills with it; if it returns a promise, the chain waits for it; if it throws, the chain rejects and skips to the next catch. A catch that returns normally *recovers* the chain.

fetchUser()
  .then((u) => fetchPosts(u.id))        // returns a promise: chain waits
  .then((posts) => posts.filter(isPublic))
  .catch((err) => {
    console.error(err);
    return [];                          // recover with a default
  })
  .then((posts) => render(posts))       // runs on success or after recovery
  .finally(() => hideSpinner());

A frequent bug is forgetting to return the inner promise, which makes the outer chain continue before the inner work finishes.

§2The Four Combinators

Each combinator takes an iterable of promises and returns one promise. They differ in when they settle and what they do with failure.

MethodFulfills whenRejects when
Promise.allAll fulfill (array of values, in order)Any rejects (first reason)
Promise.allSettledAll settle (array of {status, value|reason})Never
Promise.raceFirst to settle, if fulfilledFirst to settle, if rejected
Promise.anyFirst to fulfillAll reject (AggregateError)
const [user, posts] = await Promise.all([getUser(), getPosts()]);   // need both

const results = await Promise.allSettled(urls.map((u) => fetch(u)));
const ok = results.filter((r) => r.status === "fulfilled").map((r) => r.value);

const fastest = await Promise.any([fetch(mirrorA), fetch(mirrorB)]);   // first success

const timeout = new Promise((_, rej) => setTimeout(() => rej(new Error("slow")), 3000));
const data = await Promise.race([fetch("/api"), timeout]);              // deadline

Promise.all fails fast but does not cancel the other promises; they keep running and their results are discarded. Cancellation is the next lesson's topic.

§3Unhandled Rejections

A rejected promise that has no handler becomes an unhandled rejection. The browser reports it in the console and fires a unhandledrejection event on window. It usually means a bug: a missing catch, a forgotten await, or a promise created and dropped.

async function save() { throw new Error("nope"); }

save();                        // unhandled: nobody awaited or caught it
button.onclick = () => save(); // also unhandled

window.addEventListener("unhandledrejection", (e) => {
  reportError(e.reason);       // log it centrally
  e.preventDefault();          // suppress the default console error
});

Treat the global handler as a safety net for logging, not as a substitute for handling errors where they occur. In an event handler, either await inside a try/catch or attach .catch().

button.addEventListener("click", async () => {
  try {
    await save();
  } catch (err) {
    showError(err);
  }
});

// also useful: a promise that is already settled
Promise.resolve(42);   Promise.reject(new Error("x"));
Pick the combinator by failure behavior Ask "what should happen if one fails?" all fails together, allSettled reports each outcome, race is about the first result either way, and any is about the first success.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting to return a promise inside thenThe chain does not wait; ordering bugsreturn it (or use await)
Using Promise.all when partial results are acceptableOne failure discards all successesUse Promise.allSettled
Assuming Promise.race cancels the loserThe slower request keeps runningUse AbortController to cancel
Firing a promise-returning function and ignoring itUnhandled rejection and silent failureawait it, or add .catch
Practice
  1. Fetch five URLs with Promise.allSettled and print how many succeeded and failed.
  2. Write withTimeout(promise, ms) using Promise.race, and test it with a slow request.
  3. Add a global unhandledrejection listener, then trigger a rejection to see it fire.
Key takeaways
  • Return values and promises flow down a chain; a throw skips to the next catch.
  • all, allSettled, race, and any differ in when they settle and how they treat failure.
  • Never leave a promise unobserved: handle it, or log it through unhandledrejection.
