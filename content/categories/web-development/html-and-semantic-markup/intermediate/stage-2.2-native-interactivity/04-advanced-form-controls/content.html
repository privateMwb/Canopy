Advanced Form Controls

range, color, file, progress, meter, and output cover specialized input, and inputmode fixes mobile keyboards.

§1Specialized Inputs

These types give users purpose-built controls with no extra code.

<label for="vol">Volume</label>
<input id="vol" type="range" name="vol" min="0" max="100" value="40">

<label for="accent">Accent color</label>
<input id="accent" type="color" name="accent" value="#15803d">

<label for="avatar">Profile photo</label>
<input id="avatar" type="file" name="avatar" accept="image/*">

<label for="docs">Documents</label>
<input id="docs" type="file" name="docs" accept=".pdf,.docx" multiple>

A range slider shows no value by default; pair it with an <output> or visible text. accept hints at allowed file types but isn't enforced; validate uploads on the server.

§2progress, meter, and output

<progress> shows how far a task has gone. <meter> shows a value within a known range, such as disk usage. <output> holds a calculated result and is announced as a live region.

<progress value="70" max="100">70%</progress>

<meter min="0" max="100" low="25" high="75" optimum="10" value="82">82%</meter>

<form oninput="total.value = Number(a.value) + Number(b.value)">
  <input id="a" type="number" value="2"> +
  <input id="b" type="number" value="3"> =
  <output name="total" for="a b">5</output>
</form>

Omit value on progress for an indeterminate state ("working"). Use progress for tasks and meter for measurements; they aren't interchangeable.

§3Mobile Keyboards with inputmode

inputmode picks the on-screen keyboard without changing validation or semantics. It is useful where type="number" is wrong, such as codes and ZIP numbers.

<input name="zip" inputmode="numeric" pattern="[0-9]{5}" autocomplete="postal-code">
<input name="amount" inputmode="decimal">
<input name="q" type="search" enterkeyhint="search">

enterkeyhint changes the label of the Enter key, such as "Go" or "Search", on mobile keyboards.

Native controls are accessible by default A browser range or file input already works with the keyboard and assistive tech. Custom replacements must rebuild all of that, so start native and style around it.

§4Common Mistakes

MistakeWhat HappensFix
Treating accept as securityUsers can upload any file typeValidate type and size server-side
Using meter for task progressWrong semantics, wrong announcementUse progress for tasks, meter for measurements
Using type="number" for postal codes or card numbersDrops leading zeros, adds spinnersUse text with inputmode="numeric"
Practice
  1. Build a settings form with a volume range that updates an output, and a color picker.
  2. Make an upload field restricted to images and test it on a phone.
Key takeaways
  • Use range, color, and file for specialized input; label them all.
  • progress is a task, meter is a gauge, and output is a live result.
  • inputmode selects the right mobile keyboard without changing validation.
