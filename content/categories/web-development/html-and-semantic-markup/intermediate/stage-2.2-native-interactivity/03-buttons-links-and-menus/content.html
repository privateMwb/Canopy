Buttons, Links & Menus

A link goes somewhere and a button does something; mixing them up breaks keyboards, screen readers, and expectations, and menus follow the same rule.

§1Buttons vs. Links

The test is simple: does activating it change the URL or load a new resource? Use <a href>. Does it act on the current page, such as open, submit, toggle, or delete? Use <button>.

<a href><button>
PurposeNavigatePerform an action
Activated byEnterEnter and Space
Open in new tabYes (middle-click, context menu)No
Announced asLinkButton
<a href="/pricing/">View pricing</a>
<button type="button" id="copy">Copy link</button>

§2Navigation Menus

A site menu is a list of links inside <nav>. It doesn't need menu roles; that ARIA vocabulary is for application-style menus such as a text editor's File menu. Using role="menu" on website navigation changes how screen readers behave and requires full arrow-key handling.

<nav aria-label="Primary">
  <ul>
    <li><a href="/" aria-current="page">Home</a></li>
    <li><a href="/learn/">Learn</a></li>
    <li><a href="/about/">About</a></li>
  </ul>
</nav>

aria-current="page" tells screen reader users which link is the current page, and you can style it with [aria-current="page"].

§3Dropdown Disclosure Navigation

For a dropdown, use the disclosure pattern: a button that toggles a nested list of links, with aria-expanded reflecting its state.

<li>
  <button aria-expanded="false" aria-controls="sub">Products</button>
  <ul id="sub" hidden>
    <li><a href="/products/a/">Product A</a></li>
    <li><a href="/products/b/">Product B</a></li>
  </ul>
</li>

Toggle the hidden attribute and aria-expanded in a click handler, and close on Escape. Don't open on hover alone; touch and keyboard users can't hover.

Never a href="#" A link that goes nowhere is a button wearing the wrong costume. It scrolls to the top, adds history entries, and announces the wrong role.

§4Common Mistakes

MistakeWhat HappensFix
Using <div onclick> for a navigation itemNot focusable, no link role, can't open in a new tabUse <a href>
Using role="menu" for website navigationScreen readers switch modes and expect arrow-key behaviorUse a list of links; reserve menu for app menus
Showing submenus only on :hoverUnreachable by keyboard and touchUse a button disclosure that toggles on click
Forgetting type="button" inside formsThe button submits the formSet type explicitly
Practice
  1. Audit a page and convert every clickable div and a href="#" into the right element.
  2. Build a two-level site menu using a disclosure button with aria-expanded.
Key takeaways
  • Links navigate; buttons act.
  • Site navigation is a list of links in nav with aria-current for the current page.
  • Dropdowns use a disclosure button, not hover and not role="menu".
