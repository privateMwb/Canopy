Autofill & Autocomplete

The autocomplete attribute tells browsers exactly what a field is, so they can fill it correctly, and reducing typing is an accessibility requirement as well as a convenience.

§1Tell the Browser What the Field Means

Browsers guess from names and labels, but autocomplete removes the guessing. Values are standardized tokens.

<form>
  <input name="name"    autocomplete="name">
  <input name="email"   type="email" autocomplete="email">
  <input name="tel"     type="tel"   autocomplete="tel">
  <input name="addr"    autocomplete="street-address">
  <input name="city"    autocomplete="address-level2">
  <input name="zip"     autocomplete="postal-code">
  <input name="country" autocomplete="country">
</form>

Set autocomplete="off" only where it truly harms, such as one-time codes in some contexts. Browsers often ignore off for login and address fields anyway.

§2Passwords and One-Time Codes

Use the right tokens so password managers behave: username, current-password, new-password, and one-time-code.

<!-- sign in -->
<input name="user" autocomplete="username">
<input name="pw" type="password" autocomplete="current-password">

<!-- sign up or change password -->
<input name="pw" type="password" autocomplete="new-password">

<!-- SMS code -->
<input name="otp" inputmode="numeric" autocomplete="one-time-code">

new-password lets the manager suggest a strong password, and one-time-code lets a phone offer the SMS code automatically.

§3Sections, Billing, and Shipping

Prefix tokens with shipping or billing, or use a section- prefix, when one page has several address sets.

<input name="s_addr" autocomplete="shipping street-address">
<input name="b_addr" autocomplete="billing street-address">
<input name="cc" inputmode="numeric" autocomplete="cc-number">
<input name="exp" autocomplete="cc-exp">

WCAG success criterion 1.3.5 (Identify Input Purpose) requires fields that collect personal information to expose their purpose, and autocomplete is the way to meet it.

Less typing, fewer errors People with motor or cognitive disabilities benefit most from autofill, but so does everyone on a phone. Always set autocomplete on personal-data fields.

§4Common Mistakes

MistakeWhat HappensFix
Disabling autocomplete everywhereSlows users and fails accessibility guidanceLeave it on and set correct tokens
Using made-up values like autocomplete="my-field"Browsers ignore invalid tokensUse the standard token list
Using the same name across billing and shipping with no section tokenBrowser autofills the wrong addressPrefix tokens with shipping or billing
Practice
  1. Add correct autocomplete tokens to a checkout form and test autofill in two browsers.
  2. Build sign-in and sign-up forms with the right password tokens and confirm a password manager recognizes them.
Key takeaways
  • Use standard autocomplete tokens on every personal-data field.
  • current-password, new-password, and one-time-code help managers and phones.
  • Autofill supports accessibility requirements and cuts form errors.
