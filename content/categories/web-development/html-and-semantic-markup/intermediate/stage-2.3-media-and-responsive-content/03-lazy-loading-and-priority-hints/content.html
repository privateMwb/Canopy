Lazy Loading & Priority Hints

Tell the browser which images can wait and which are urgent: loading, fetchpriority, and decoding shift bandwidth to what users see first.

§1Lazy Loading

loading="lazy" defers off-screen images and iframes until the user scrolls near them. It needs no JavaScript and cuts initial page weight sharply on long pages.

<img src="gallery-12.jpg" alt="Fern in morning light"
     width="800" height="600" loading="lazy">

<iframe src="https://example.com/embed" title="Demo"
        loading="lazy" width="600" height="400"></iframe>

Always include width and height with lazy images, so the browser can reserve space before they load.

§2Do Not Lazy-Load the Hero

The image that appears first in the viewport, usually called the LCP (Largest Contentful Paint) element, should load as early as possible. Lazy-loading it delays the metric you most want to improve. Use fetchpriority="high" to push it up the queue.

<img src="hero-1600.jpg" alt="Canopy at dawn"
     width="1600" height="900"
     fetchpriority="high">

fetchpriority accepts high, low, and auto. Use high for one or two critical images, and low for ones that matter less, such as an off-screen carousel image that can't be lazy-loaded.

§3Decoding and Preloading

decoding="async" lets the browser decode an image off the main thread, so it doesn't block other rendering. For an image discovered late, such as a CSS background that is your LCP, you can preload it.

<img src="thumb.jpg" alt="" width="200" height="200" decoding="async">

<link rel="preload" as="image" href="/img/hero-1600.jpg" fetchpriority="high">

Preload sparingly. Every preload competes with other critical resources, and wasting it can make things slower.

Above the fold: eager. Below the fold: lazy. The first screenful should load normally (and the LCP image with high priority). Everything that requires scrolling is a candidate for loading="lazy".

§4Common Mistakes

MistakeWhat HappensFix
Adding loading="lazy" to every imageThe hero loads late and LCP gets worseLeave above-the-fold images eager
Lazy-loading without dimensionsContent jumps as images arriveSet width and height
Marking many images fetchpriority="high"Nothing stands out; priorities lose meaningUse it for one or two critical resources
Practice
  1. Run Lighthouse on a long page, then add loading="lazy" to below-the-fold images and compare transfer sizes.
  2. Find the LCP element in DevTools and add fetchpriority="high" to it.
Key takeaways
  • loading="lazy" defers off-screen images; never use it on the LCP image.
  • fetchpriority="high" raises the priority of one or two critical images.
  • Dimensions plus lazy loading avoid layout shift.
