Editor, DevTools & Validation

Three tools turn guessing into debugging: a good editor, the browser's developer tools, and the W3C validator.

§1Set Up an Editor

Any plain-text editor works, but a code editor such as VS Code adds syntax highlighting, auto-closing tags, and formatting. Save files as UTF-8 with the .html extension, and install a live-preview or run a small local server so changes show immediately.

# serve the current folder at http://localhost:8080
python3 -m http.server 8080

§2DevTools: Inspect, Edit, Compare

Press F12 (or right-click → Inspect). The Elements panel shows the live DOM, which can differ from your file if the parser corrected a mistake or JavaScript changed something. You can edit text and attributes there to experiment; changes disappear on reload.

  • Elements — inspect and tweak the DOM and styles.
  • Console — warnings and errors from scripts and the parser.
  • Network — every request, status code, and size.
  • Lighthouse / Accessibility — quick audits and the accessibility tree.

View Source (Ctrl+U) shows the original response. Comparing it with the Elements panel is the quickest way to spot what the browser changed.

§3Validate Your Markup

The W3C Markup Validator (validator.w3.org) checks a URL, an upload, or pasted code against the HTML standard. Errors point to line and column numbers; fix the first one and revalidate, because one mistake often causes a cascade.

<!-- typical errors the validator catches -->
<p>Unclosed paragraph
<img src="a.png">                 <!-- Error: missing alt -->
<ul><p>text</p></ul>          <!-- Error: p not allowed in ul -->
<a href="x"><a href="y">..</a></a>  <!-- Error: a inside a -->

A page that "looks fine" can still be invalid. Validity does not guarantee quality, but it removes a class of cross-browser surprises and catches accessibility slips such as missing alt.

Fix the first error first The parser often misreads everything after one mistake. Resolve errors from the top of the report down and revalidate each time.

§4Common Mistakes

MistakeWhat HappensFix
Debugging by only staring at the source fileYou miss what the parser actually builtCheck the live DOM in the Elements panel
Editing in DevTools and forgetting to copy the change backThe fix vanishes on reloadMake changes in your editor; use DevTools only to experiment
Ignoring validator warningsSubtle problems such as a missing lang persistTreat errors as must-fix and read warnings before dismissing them
Practice
  1. Introduce three deliberate errors in a page, run it through the validator, and fix them one at a time.
  2. Find the Network panel's entry for your HTML file and note its status code and Content-Type.
Key takeaways
  • Use View Source for what was sent and the Elements panel for what the browser built.
  • Run the validator regularly and fix errors from the top down.
  • Run a local server rather than opening file:// paths.
