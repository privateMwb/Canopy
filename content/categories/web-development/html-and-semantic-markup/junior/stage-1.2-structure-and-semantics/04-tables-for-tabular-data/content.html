Tables for Tabular Data

Tables are for data with rows and columns, and with a few extra elements they become fully navigable for screen reader users.

§1Structure a Real Table

A well-formed table has a <caption>, a header group, and a body. Each header cell is a <th> with a scope saying whether it labels a column or a row.

<table>
  <caption>Monthly rainfall (mm)</caption>
  <thead>
    <tr><th scope="col">City</th><th scope="col">Jan</th><th scope="col">Feb</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Seattle</th><td>145</td><td>108</td></tr>
    <tr><th scope="row">Phoenix</th><td>24</td><td>26</td></tr>
  </tbody>
</table>

With scope, a screen reader announces "Seattle, Jan, 145" so the listener always knows which row and column a cell belongs to.

§2Spanning and Footers

colspan and rowspan let a cell cover several columns or rows. Use them sparingly, because complex spans make tables hard to navigate. <tfoot> holds summary rows such as totals.

<tr><th scope="row" colspan="2">Total</th><td>169</td></tr>

If a table needs several layers of spans, consider splitting it into two simpler tables.

§3When Not to Use a Table

Tables describe relationships in data, not page layout. Using them to position a header, sidebar, and content was common in the 1990s and is now an accessibility and responsiveness problem. Use CSS Grid or Flexbox for layout.

  • Use a table for schedules, comparisons, price lists, statistics.
  • Don't for multi-column page layout, aligning a form, or arranging a gallery.
  • A list of labeled items that does not have columns is usually a <dl> or <ul>.

For wide tables on phones, wrap the table in a container with overflow-x: auto so it scrolls instead of breaking the page.

Headers are what make a table a table Without <th> and scope, a table is just cells. Always mark header cells so that every data cell can be tied to its row and column labels.

§4Common Mistakes

MistakeWhat HappensFix
Using <td> styled bold instead of <th>No header relationships for assistive techUse <th scope="col"> or <th scope="row">
Skipping <caption>Users lack a quick description of what the table isAdd a concise caption as the first child
Building page layout with tablesNot responsive, confusing to screen readersUse CSS Grid or Flexbox
Practice
  1. Build a table of your weekly schedule with a caption, column headers, and row headers.
  2. Add a total row using tfoot, then explain why you did or did not need colspan.
Key takeaways
  • Use tables for tabular data only, never for layout.
  • Mark headers with th and scope, and add a caption.
  • Keep spans minimal; split complex tables.
