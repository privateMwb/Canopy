Custom Elements

Custom elements let you define your own tags with a class and lifecycle callbacks, using only platform APIs.

§1Defining an Element

A custom element is a class that extends HTMLElement, registered with customElements.define(). The tag name must contain a hyphen, which guarantees it won't collide with future built-in elements.

class RatingStars extends HTMLElement {
  connectedCallback() {
    const value = Number(this.getAttribute("value") ?? 0);
    this.textContent = "★".repeat(value) + "☆".repeat(5 - value);
    this.setAttribute("role", "img");
    this.setAttribute("aria-label", `${value} out of 5`);
  }
}
customElements.define("rating-stars", RatingStars);

Usage is plain HTML: <rating-stars value="4"></rating-stars>. Because the platform upgrades elements that already exist in the DOM, the tag can appear before the definition is loaded.

§2Lifecycle Callbacks and Attributes

CallbackRuns when
constructor()The element is created or upgraded; don't read attributes or touch children yet
connectedCallback()It is inserted into a document; set up here
disconnectedCallback()It is removed; clean up listeners and timers
attributeChangedCallback(name, old, new)An observed attribute changes
adoptedCallback()It moves to another document
class RatingStars extends HTMLElement {
  static observedAttributes = ["value"];
  attributeChangedCallback() { this.render(); }
  get value() { return Number(this.getAttribute("value") ?? 0); }
  set value(v) { this.setAttribute("value", String(v)); }
  connectedCallback() { this.render(); }
  render() { /* update DOM from this.value */ }
}

Reflect important state to attributes and properties so the element works from markup, from JavaScript, and from CSS attribute selectors.

§3Autonomous vs. Customized Built-ins

An autonomous element (<my-card>) extends HTMLElement and is supported everywhere. A customized built-in extends a native element, such as HTMLButtonElement, and is used with is="...", which would inherit native behavior and accessibility.

class FancyButton extends HTMLButtonElement {}
customElements.define("fancy-button", FancyButton, { extends: "button" });
// <button is="fancy-button">Go</button>

Safari does not support customized built-ins, so for cross-browser code you'll typically use autonomous elements and handle accessibility yourself, or wrap a native element inside.

Progressive enhancement fits here Put meaningful fallback content between the tags so the page is usable before JavaScript registers the element (:not(:defined) in CSS targets elements still waiting).

§4Common Mistakes

MistakeWhat HappensFix
Reading attributes or adding children in the constructorViolates the spec for created elements; fails when parsed from HTMLDo setup in connectedCallback
Forgetting disconnectedCallback cleanupLeaked listeners and timersRemove what you added
Choosing a tag name without a hyphendefine throws an errorUse a name like app-card
Practice
  1. Build a <rating-stars> element that responds to attribute changes and exposes a value property.
  2. Use :not(:defined) in CSS to style the fallback state before the element is registered.
Key takeaways
  • Define with a class and customElements.define; names need a hyphen.
  • Use lifecycle callbacks: set up in connectedCallback, clean up in disconnectedCallback.
  • Reflect state to attributes, and keep fallback content for when scripts haven't run.
