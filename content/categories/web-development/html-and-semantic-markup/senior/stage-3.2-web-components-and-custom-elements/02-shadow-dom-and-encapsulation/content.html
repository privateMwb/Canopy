Shadow DOM & Encapsulation

Shadow DOM gives a component its own scoped markup and styles, with deliberate holes for customization through slots, parts, and custom properties.

§1Attaching a Shadow Root

attachShadow() creates a separate DOM subtree. Styles inside don't leak out, and page styles don't reach in. Selectors and querySelector from the outside don't see into it.

class InfoBox extends HTMLElement {
  constructor() {
    super();
    const root = this.attachShadow({ mode: "open" });
    root.innerHTML = `
      <style>
        :host { display: block; border: 1px solid #ccc; padding: 1rem; }
        h2 { margin: 0 0 .5rem; }   /* only affects this shadow tree */
      </style>
      <h2><slot name="title">Notice</slot></h2>
      <slot></slot>`;
  }
}
customElements.define("info-box", InfoBox);

mode: "open" lets element.shadowRoot reach in; "closed" hides it. Closed mode offers little real protection and makes debugging and testing harder, so open is the usual choice.

§2Slots Project Light DOM

A <slot> is a placeholder where the component's children appear. Users write content in the normal (light) DOM, and it's rendered inside the shadow tree.

<info-box>
  <span slot="title">Heads up</span>
  <p>This content is slotted in.</p>
</info-box>

Slotted nodes stay in the light DOM, so the page's own CSS can still style them, and they're still part of the accessibility tree in their rendered position.

§3Controlled Styling Hooks

Encapsulation is intentional, so the component must expose ways to be customized.

MechanismHow it works
CSS custom propertiesInherited values pass through the boundary: --accent: teal;
::part()The component marks elements with part="label", and the page styles x-el::part(label)
:host, :host(.x), ::slotted()Style the component itself and its slotted children from inside
:host-context()Style based on ancestors (limited support, so avoid)
/* inside the shadow root */
:host { --accent: #0f766e; }
button { background: var(--accent); }
/* page CSS */
info-box { --accent: #b91c1c; }
info-box::part(label) { font-weight: 700; }
Encapsulation is not a security boundary Shadow DOM prevents *accidental* style and DOM collisions. Anything on the page, including open shadow roots, remains reachable by scripts.

§4Common Mistakes

MistakeWhat HappensFix
Expecting global CSS to style inside the shadow rootStyles don't applyExpose custom properties or ::part
Using querySelector from outside to find shadow contentReturns nullQuery the shadowRoot, or expose methods and events
Using closed mode for "security"Little protection, and harder testingUse open
Practice
  1. Build an <info-box> with named and default slots, then theme it using a custom property and a ::part.
  2. Show that a page-level h2 { color: red } does not affect a heading in the shadow tree.
Key takeaways
  • attachShadow scopes markup and styles to the component.
  • Slots render light DOM content inside the shadow tree.
  • Expose theming through custom properties and ::part, deliberately.
