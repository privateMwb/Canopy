Error Recovery & Quirks Mode

Browsers forgive markup mistakes by spec, and the doctype decides which of three layout modes applies.

§1Common Recovery Behaviors

The spec defines recovery for many mistakes, and recognizing them speeds up debugging.

InputWhat the parser does
<p> inside <p>Closes the first paragraph, starts a new one
<div> inside <p>Closes the <p> first
Stray </p>Creates an empty <p></p>
Text directly inside <table>Moves it before the table ("foster parenting")
<tr> without <tbody>Inserts an implied <tbody>
Misnested <b><i></b></i>Repairs via the adoption agency algorithm
Missing <html>, <head>, <body>Creates them
<table>
  Orphan text
  <tr><td>cell</td></tr>
</table>

§2Standards, Quirks, and Almost-Standards Mode

Before CSS was standardized, browsers implemented quirky layout. To avoid breaking old pages, modern browsers keep those behaviors behind a mode switch chosen by the doctype.

ModeTriggered byEffect
No-quirks (standards)<!DOCTYPE html>Spec-compliant layout
Limited-quirks (almost standards)Certain old transitional doctypesStandards, except a few line-height details in table cells
QuirksMissing or very old doctypeLegacy box model and sizing behaviors

Check document.compatMode: "CSS1Compat" means standards mode and "BackCompat" means quirks.

§3Forgiveness Has Limits

Recovery rules make pages display, not behave correctly. Repaired DOMs can differ between your expectation and reality, and CSS and scripts attach to the repaired tree. A single stray tag can change which element a selector matches.

console.log(document.compatMode);   // "CSS1Compat" is what you want

Treat validator errors as defects, even when the page looks fine. They're often the source of intermittent bugs.

One line prevents a mode <!DOCTYPE html> at the very top of the file, with nothing before it, keeps you in standards mode. Very old browsers could even be pushed into quirks mode by a comment before it.

§4Common Mistakes

MistakeWhat HappensFix
Omitting the doctypeQuirks mode, with different box sizingAlways put <!DOCTYPE html> first
Relying on <tbody> not being there in selectorsCSS and JS miss because tbody was auto-insertedWrite selectors against the DOM, not the source
Using text directly in tablesIt jumps outside the tableWrap in a cell or a caption
Practice
  1. Create a page with no doctype and print document.compatMode; add the doctype and compare.
  2. Write a table with stray text and a missing tbody, then inspect the resulting DOM.
Key takeaways
  • The parser's recovery behavior is specified: closing, inserting, and foster parenting.
  • The doctype selects between no-quirks, limited-quirks, and quirks mode.
  • Repaired markup can still break selectors and scripts, so validate.
