Parser-Blocking Resources

Synchronous scripts and stylesheets stall the parser or rendering, and the spec gives you precise tools to control both.

§1What Blocks the Parser

A classic <script> blocks the parser: it must download and execute before parsing continues, because it may call document.write() or change the DOM. A stylesheet blocks rendering, and also blocks any script after it, since that script might read computed styles.

ResourceBlocks parsing?Blocks rendering?
<script src>YesYes, indirectly (nothing after it is built)
<script defer> or type="module"NoNo
<script async>No while downloading; pauses parser when it executesNo
<link rel="stylesheet">NoYes
<img>NoNo

§2The Script Ordering Trap

A script placed after a stylesheet waits for that stylesheet. Placing scripts that don't need styles *before* the CSS, or using defer, avoids the pause.

<!-- slow: script waits for CSS to finish -->
<link rel="stylesheet" href="/big.css">
<script src="/app.js"></script>

<!-- better -->
<link rel="stylesheet" href="/big.css">
<script src="/app.js" defer></script>

§3Techniques to Unblock

  • Use defer for page scripts and async for independent ones.
  • Inline a small critical CSS block and load the rest with media tricks or rel="preload".
  • Avoid document.write(); browsers may refuse to run it on slow connections.
  • Use blocking="render" only when you deliberately want a script or stylesheet to hold rendering until it loads.
  • Reduce third-party tags, which are the most common source of parser blocking.
<link rel="preload" href="/rest.css" as="style" onload="this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="/rest.css"></noscript>

Verify with the DevTools Performance panel, looking for long gaps in the main thread under Parse HTML, and the Network panel's Priority and waterfall columns.

Critical path thinking List every resource needed for first paint. Each one is on the critical path, so ask of each: can it be smaller, later, inlined, or removed?

§4Common Mistakes

MistakeWhat HappensFix
Synchronous third-party scripts in the headA slow vendor freezes your pageLoad asynchronously, or after first paint
Loading all CSS as one render-blocking fileRendering waits for rules the page doesn't useSplit critical CSS and defer the remainder
Using async where order mattersRace conditions between scriptsUse defer or modules
Practice
  1. Take a page with three synchronous scripts and convert them to defer; measure First Contentful Paint before and after.
  2. Identify the critical CSS for one page and inline it.
Key takeaways
  • Classic scripts block parsing; stylesheets block rendering, and scripts wait for them.
  • defer, async, modules, and media-scoped CSS reduce blocking.
  • Think in critical resources, and measure with DevTools.
