CRUD End to End

Create, read, update, and delete with validation.

§1The Four Operations Together

CRUD (create, read, update, delete) is the backbone of most apps. In a full-stack framework each operation has a natural home: reads happen in Server Components, and writes happen in Server Actions followed by a revalidation.

OperationWhere it livesThen
CreateServer Action from a formRevalidate the list, redirect or reset
ReadAsync Server ComponentRender directly; use notFound() if missing
UpdateServer Action with the record's idRevalidate list and detail pages
DeleteServer Action from a small form or buttonRevalidate, then redirect if on the detail page

§2An End-to-End Slice

// app/tasks/actions.ts
"use server";
import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";

export async function createTask(formData: FormData) {
  await db.task.create({ data: { title: String(formData.get("title")) } });
  revalidatePath("/tasks");
  redirect("/tasks");
}

export async function toggleTask(id: string, done: boolean) {
  await db.task.update({ where: { id }, data: { done } });
  revalidatePath("/tasks");
}

export async function deleteTask(id: string) {
  await db.task.delete({ where: { id } });
  revalidatePath("/tasks");
}

To pass an id to an action from a form, use action={deleteTask.bind(null, task.id)} or a hidden input. Binding keeps the id out of user-editable form fields.

§3Handling the Edge Cases

  • Not found: reading a record that doesn't exist should call notFound(), not crash.
  • Empty state: show a helpful message when the list is empty.
  • Deleting twice or concurrently: operations should fail gracefully, not throw an unhandled error.
  • Optimistic UI: useOptimistic can show a change instantly while the server confirms it.
The loop to remember Mutate on the server, revalidate the affected data, and let the framework re-render. If a change doesn't show up, the missing step is almost always revalidation.

§4Common Mistakes

MistakeWhat HappensFix
Trusting an id sent from the client for ownershipUsers can edit or delete other people's recordsCheck that the record belongs to the current user (lesson 2.1.3)
Forgetting the empty and not-found statesBlank screens or unhandled errorsDesign for zero items and missing records
Hard-deleting data you may need laterAccidental, unrecoverable data lossConsider soft deletes or confirmations for important data
Practice
  1. Build a complete task list with create, toggle, edit, and delete, all through Server Actions.
  2. Add notFound() handling for a detail page and an empty-state message for the list.
Key takeaways
  • Reads live in Server Components; writes live in Server Actions followed by revalidation.
  • Bind ids to actions rather than trusting editable form fields.
  • Handle empty, missing, and concurrent states, not just the happy path.
