Static vs. Dynamic Rendering

When pages are built, and when they are built per request.

§1Two Moments to Render

A page's HTML can be produced at build time (static) or at request time (dynamic). Static pages are generated once, served from a CDN, and are extremely fast. Dynamic pages are generated for each request, so they can depend on who is asking.

StaticDynamic
When HTML is madeAt build (or on revalidation)On every request
SpeedServed from CDN edgeWaits for server work
Per-user contentNoYes
Good forMarketing pages, docs, blog postsDashboards, carts, personalised feeds

§2What Makes a Route Dynamic

The framework decides automatically. A route becomes dynamic when it uses a request-time API: reading cookies(), headers(), or searchParams, or when it fetches data that must stay uncached. Otherwise it is rendered statically at build time.

import { cookies } from "next/headers";

export default async function Page() {
  const theme = (await cookies()).get("theme");   // request-time API → dynamic
  return <p>Theme: {theme?.value ?? "default"}</p>;
}

You can also force the behaviour with route segment config, such as export const dynamic = "force-dynamic", though letting the framework infer it is usually better. The exact defaults shift between framework versions, so check the build output to see what each route actually became.

§3Static Params for Dynamic Routes

A route like /blog/[slug] can still be static if you tell the framework which slugs exist ahead of time.

export async function generateStaticParams() {
  const posts = await getAllPosts();
  return posts.map((p) => ({ slug: p.slug }));   // one static page per post
}
Read the build output After npm run build, the route table marks each page as static or dynamic. That table is the ground truth, so if a page you expected to be static is dynamic, look for a cookies(), headers(), or searchParams call.

§4Common Mistakes

MistakeWhat HappensFix
Reading cookies() in a shared layoutEvery page under that layout turns dynamicRead request data only in the routes or components that need it
Expecting per-user data on a static pageEveryone sees the same HTMLMake the route dynamic, or load user data on the client
Forgetting generateStaticParamsDynamic-segment pages render on demand instead of at build timeReturn the known params so they are pre-rendered
Practice
  1. Create one static page and one that reads cookies(), build the app, and confirm how each is classified.
  2. Add generateStaticParams to a blog route and verify that the posts appear in the build output.
Key takeaways
  • Static pages are built ahead of time and served fast; dynamic pages render per request.
  • Using request-time APIs such as cookies() makes a route dynamic.
  • generateStaticParams pre-renders pages for dynamic segments.
