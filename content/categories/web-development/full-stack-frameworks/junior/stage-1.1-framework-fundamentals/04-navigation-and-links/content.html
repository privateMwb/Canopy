Navigation & Links

Client-side navigation, prefetching, and loading states.

§1The Link Component

Use <Link> from next/link for internal navigation instead of a plain <a>. It performs a client-side transition, so the page swaps without a full reload and shared layouts stay mounted.

import Link from "next/link";

<Link href="/blog/hello-world">Read the post</Link>
<Link href={{ pathname: "/search", query: { q: "next" } }}>Search</Link>

§2Prefetching

When a <Link> scrolls into the viewport in production, the framework prefetches the route in the background, so a click often feels instant. Static routes are prefetched in full, while dynamic routes are typically prefetched only up to the nearest loading boundary. Prefetching is disabled in development, which is another reason to judge performance on a production build.

§3Programmatic Navigation and Active State

In a Client Component, useRouter lets you navigate from code, for instance after a form succeeds. usePathname tells you the current path so you can highlight the active link. On the server, use redirect() to send the user elsewhere.

"use client";
import { useRouter, usePathname } from "next/navigation";

const router = useRouter();
router.push("/dashboard");        // add a history entry
router.replace("/login");         // swap the current entry
const pathname = usePathname();   // "/blog/hello-world"

§4Loading States

Navigation to a dynamic route can take time while data loads. A loading.tsx file beside a route shows a fallback instantly while the real page streams in. Lesson 1.2.4 covers loading and error UI in detail.

Links are real anchors <Link> renders an <a> tag, so it works with middle-click, 'open in new tab', and crawlers. Reach for router.push only when navigation follows an action, not as a replacement for links.

§5Common Mistakes

MistakeWhat HappensFix
Using <a href> for internal pagesA full page reload, losing client state and speedUse <Link> for internal routes
Using router.push for ordinary navigationNo prefetching, and poor accessibility and SEORender a <Link>; use the router after actions
Judging link speed in dev modePrefetching is off, so it feels slower than productionTest with build and start
Practice
  1. Build a navigation bar that highlights the current page using usePathname.
  2. Add a loading.tsx to a slow route and watch how the transition changes in a production build.
Key takeaways
  • <Link> gives client-side transitions and prefetching while staying a real anchor tag.
  • Use useRouter for navigation after actions and redirect() on the server.
  • loading.tsx makes slow navigations feel responsive.
