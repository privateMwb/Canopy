Optimizing LCP

Largest Contentful Paint can be split into four parts. Find which part is large, and you know exactly where to spend your effort.

§1The Four Parts of LCP

LCP is the time until the largest element in the viewport is rendered, usually a hero image, a video poster, or a big block of text. It is easier to fix once broken into phases.

PhaseWhat happensTypical cause when long
Time to First ByteRequest to first byte of HTMLSlow server, redirects, no caching
Resource load delayFirst byte until the LCP resource starts loadingLate discovery: CSS background, JS-inserted image, lazy loading
Resource load durationDownloading the LCP resourceHuge image, wrong format, no compression, contention
Element render delayResource arrives until it is paintedRender-blocking CSS or JS, client-side rendering

In many slow pages, the biggest slice is load delay, not download time. The browser simply found the image late. Chrome DevTools and web-vitals attribution both report these phases.

§2Finding Your LCP Element and Its Breakdown

import { onLCP } from 'web-vitals/attribution';

onLCP(({ value, attribution }) => {
  console.log('LCP', value);
  console.log('element:', attribution.element);            // CSS selector of the LCP element
  console.log('resource:', attribution.url);               // the image URL, if any
  console.log('TTFB:', attribution.timeToFirstByte);
  console.log('load delay:', attribution.resourceLoadDelay);
  console.log('load duration:', attribution.resourceLoadDuration);
  console.log('render delay:', attribution.elementRenderDelay);
});

Don't assume which element is the LCP. It can differ between desktop and mobile, and between pages. Check it for each page type that matters.

§3Fixing Each Phase

  • TTFB: cache HTML, use a CDN, remove redirects, speed up the backend. (A later lesson.)
  • Load delay: make the image discoverable in the HTML as an <img> with a real src, add fetchpriority="high", never loading="lazy" on it, and avoid setting it from JavaScript.
  • Load duration: use a modern format, serve a right-sized image with srcset, compress it, and serve it from a CDN.
  • Render delay: remove render-blocking CSS and JavaScript, and avoid client-side rendering the main content.
<!-- Before: discovered only after CSS loads, then lazy-loaded -->
<div class="hero" style="background-image:url(hero.jpg)"></div>

<!-- After: in the HTML, prioritized, right-sized, modern format -->
<img src="hero-800.avif"
     srcset="hero-400.avif 400w, hero-800.avif 800w, hero-1600.avif 1600w"
     sizes="100vw" fetchpriority="high" width="1600" height="700" alt="...">
The key insight Don't optimize 'LCP' in general. Break it into its four phases, find the largest, and fix that one. Then re-measure, because the largest phase changes.

§4Common Mistakes

MistakeWhat HappensFix
Compressing the image harder when the delay is discoveryEffort doesn't move the slow phaseLook at the phase breakdown first
Using a CSS background for the heroThe browser discovers it lateUse an <img> in the HTML
Lazy loading the LCP imageIt is deliberately delayedLoad eagerly with high priority
Practice
  1. Measure the LCP phases of a page using web-vitals attribution. State which phase is largest.
  2. Apply one fix aimed at that phase and report the before and after LCP.
Key takeaways
  • LCP has four phases: TTFB, load delay, load duration, and render delay.
  • Late discovery and render-blocking are very common, so don't assume it's the image size.
  • Fix the biggest phase first and re-measure.
