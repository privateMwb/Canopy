Prioritizing the Work

When everything is slow, you can't fix everything. Prioritizing is choosing the few changes that move the most users the furthest for the least effort.

§1Score by Impact, Reach, and Effort

A long audit produces dozens of findings. Without a method, teams fix whatever is easiest or most interesting. A simple scoring habit keeps attention on value.

FactorQuestion
ImpactHow much does this improve the metric for the users it touches?
ReachHow many users, or how much of the important traffic, does it touch?
EffortHow long will it take, and what will it cost to build and maintain?
ConfidenceHow sure are we of the impact estimate?
RiskWhat could go wrong, and how reversible is it?
// A rough priority score
// score = (impact x reach x confidence) / effort
// e.g. preload hero image:  (0.8s LCP x 90% of mobile visits x 0.9) / 0.5 days = high
// e.g. rewrite the router:   (0.3s x 100% x 0.4) / 20 days = low

The numbers are estimates and the point is the ordering, not false precision. Writing the estimates down exposes the assumptions behind them, and lets others challenge them.

§2Start From Evidence and Outcomes

  • Use field data to find where users hurt. Rank pages by traffic and by how far they miss thresholds, with the largest gap times the largest audience first.
  • Weight by business value. A checkout page matters more than an about page with the same traffic, because slowness there costs more per visit.
  • Diagnose before prescribing. Break the metric into phases, so you fix the dominant cause, not a plausible one.
  • Prefer fixes that attack the biggest phase over fixes on a phase that is already small.
  • Look for multipliers. A fix in a shared layout, component, or CDN rule improves many pages at once.
Typically high priorityTypically lower priority
Late-discovered or lazy-loaded LCP imageShaving bytes from an already-small file
Large render-blocking resources on the main templateMicro-optimizing a function that runs for 2 ms
A heavy third-party tag on every pageRewriting in a faster framework for its own sake
Uncached HTML or static assetsPerfecting rarely visited pages

§3Sequencing and Staying Honest

  1. Quick wins first, to build momentum and show results, as long as they are real wins.
  2. Then structural changes that need more time but unlock lasting gains.
  3. Measure after each change so you learn which estimates were right, and adjust the plan.
  4. Keep a visible backlog with scores, so choices are transparent and revisable.
  5. Say no explicitly. Record what you chose not to do and why, so it is a decision rather than an omission.

Be honest about uncertainty. If an estimate is a guess, label it low confidence and consider a small experiment before a big investment. The most expensive mistake is a long project aimed at the wrong bottleneck.

The key insight Prioritization is the work. A perfectly executed fix to the wrong problem is a waste, and a modest fix to the dominant one can be the biggest win of the year.

§4Common Mistakes

MistakeWhat HappensFix
Fixing items in audit order or by easeEffort goes where value isn'tScore by impact, reach, effort, and confidence
Ignoring traffic and business valueA slow, rarely used page gets priorityWeight by audience and value of the page
Committing to a large project on a guessThe wrong bottleneck consumes monthsTest the hypothesis cheaply first
Practice
  1. Take an audit with ten findings and score each for impact, reach, effort, and confidence. Produce a ranked list.
  2. Choose the top three and write the metric you will check to confirm each worked.
Key takeaways
  • Score work by impact, reach, effort, confidence, and risk, and keep the estimates visible.
  • Start from field data and business value, and attack the dominant phase of the metric.
  • Sequence quick wins then structural work, measure each, and record what you chose not to do.
