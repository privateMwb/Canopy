Set Operations, CASE & Handling NULLs

UNION stacks result sets, CASE adds conditional logic inside a query, and COALESCE handles missing values: the glue that makes real reports possible.

§1Set Operations

Set operations combine the results of two queries that have the same number and compatible types of columns.

SELECT email FROM customers
UNION                            -- combine, remove duplicates
SELECT email FROM newsletter_subscribers;

SELECT email FROM customers
INTERSECT                        -- only emails in both
SELECT email FROM newsletter_subscribers;

SELECT email FROM customers
EXCEPT                           -- in customers but not in subscribers
SELECT email FROM newsletter_subscribers;

UNION removes duplicates, which requires extra sorting or hashing. If you know there are none (or don't care), use UNION ALL, which is faster. (EXCEPT is called MINUS in Oracle.)

§2CASE: Conditional Expressions

CASE is SQL's if/else. It evaluates conditions top to bottom and returns the first match.

SELECT name, price,
  CASE
    WHEN price < 10  THEN 'budget'
    WHEN price < 50  THEN 'standard'
    ELSE                  'premium'
  END AS tier
FROM products;

Combined with aggregates, CASE creates conditional counts, a pattern you'll use constantly:

SELECT
  COUNT(*)                                          AS total_orders,
  SUM(CASE WHEN total > 100 THEN 1 ELSE 0 END)      AS big_orders,
  SUM(CASE WHEN status = 'refunded' THEN total END) AS refunded_amount
FROM orders;

§3Handling NULL: COALESCE and NULLIF

COALESCE(a, b, c) returns the first argument that isn't NULL. It supplies defaults for missing data.

SELECT name, COALESCE(phone, 'no phone') AS phone FROM customers;

-- Treat a missing discount as zero so arithmetic works
SELECT total - COALESCE(discount, 0) AS payable FROM orders;

-- NULLIF turns a value INTO null: handy to avoid division by zero
SELECT revenue / NULLIF(visits, 0) AS revenue_per_visit FROM daily_stats;

Remember that any arithmetic with NULL produces NULL, so total - discount is NULL whenever discount is. COALESCE is the fix.

§4Putting It Together: A Small Report

SELECT
  strftime('%Y-%m', o.placed_at) AS month,
  COUNT(*)                                         AS orders,
  ROUND(SUM(o.total), 2)                           AS revenue,
  COUNT(DISTINCT o.customer_id)                    AS buyers,
  SUM(CASE WHEN o.total >= 100 THEN 1 ELSE 0 END)  AS big_orders
FROM orders o
GROUP BY month
ORDER BY month;

Joins, grouping, CASE, and aggregates compose well: most dashboards are variations on this shape.

The key insight NULL propagates: any arithmetic or concatenation touching NULL gives NULL. Decide for each nullable column what a missing value should mean in your results, and use COALESCE to say so explicitly.

§5Common Mistakes

MistakeWhat HappensFix
Using UNION when UNION ALL is enoughNeedless sort/dedupe work on large resultsUse UNION ALL unless you need duplicates removed
Set-operation queries with mismatched columnsError, or values silently combined in the wrong columnsMatch column count, order, and types explicitly
CASE branches in the wrong orderAn earlier, broader condition catches rows firstOrder from most specific to most general
Dividing by a column that can be zeroDivision-by-zero errorDivide by NULLIF(col, 0) and handle the resulting NULL
Practice
  1. Label each product as 'budget', 'standard', or 'premium' with CASE, then count how many products fall in each tier using GROUP BY on the label.
  2. Write a query listing customers with their phone number, showing 'unknown' where it's missing, and a second query returning emails in customers but not in newsletter_subscribers.
Key takeaways
  • UNION, INTERSECT, and EXCEPT combine result sets; prefer UNION ALL when duplicates don't matter.
  • CASE adds conditional logic, and with SUM or COUNT it builds conditional aggregates.
  • COALESCE and NULLIF make NULL handling explicit instead of accidental.
