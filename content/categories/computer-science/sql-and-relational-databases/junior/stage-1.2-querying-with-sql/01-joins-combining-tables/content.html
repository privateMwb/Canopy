Joins: Combining Tables

A join combines rows from two tables whenever a condition matches, which is how the relationships you modeled with foreign keys turn back into useful answers.

§1INNER JOIN: Only the Matches

The examples use customers(id, name) and orders(id, customer_id, total). An INNER JOIN returns a row for each pair of rows that satisfy the ON condition. Rows with no partner on the other side are dropped.

SELECT c.name, o.id AS order_id, o.total
FROM customers AS c
JOIN orders    AS o ON o.customer_id = c.id     -- JOIN means INNER JOIN
ORDER BY c.name, o.id;

Table aliases (c, o) keep the query short and make it clear which table each column comes from. A customer with three orders appears three times; a customer with no orders doesn't appear at all.

§2LEFT JOIN: Keep Everything from One Side

A LEFT JOIN keeps every row from the left table, filling the right table's columns with NULL when there is no match. It answers "show me all customers, with their orders if any".

SELECT c.name, o.id AS order_id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id;

-- A classic use: find rows with NO match (the "anti-join")
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;                 -- customers who never ordered

RIGHT JOIN is the mirror image (and rarely needed; just swap the table order). FULL OUTER JOIN keeps unmatched rows from both sides.

§3Reasoning About Joins

A helpful mental model: a join first pairs rows, then filters by ON.

customers          orders                 INNER JOIN result
 1 Ada     ─┬─►   101  cust=1  45.00      Ada   101  45.00
            └─►   102  cust=1  12.50      Ada   102  12.50
 2 Alan            (none)                 (Alan missing)
 3 Grace   ───►   103  cust=3  99.99      Grace 103  99.99

Joining across several tables is just repeating the pattern: FROM a JOIN b ON ... JOIN c ON .... Each join adds columns from one more table. A CROSS JOIN has no condition and pairs every row with every row (rarely what you want by accident).

§4Filtering with LEFT JOIN: ON vs. WHERE

With an outer join, where you put a condition changes the meaning.

-- Keeps all customers; only counts orders over 50
SELECT c.name, o.id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id AND o.total > 50;

-- Looks similar, but drops customers with no big order entirely
SELECT c.name, o.id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.total > 50;

In the second query the WHERE rejects the NULL rows the outer join produced, quietly turning it back into an inner join.

The key insight Decide first which table's rows must always appear. That table goes on the preserved side of a LEFT JOIN, and conditions on the other table belong in ON, not WHERE.

§5Common Mistakes

MistakeWhat HappensFix
Joining without an ON condition (or with a wrong one)Every row pairs with every row: a huge, meaningless resultJoin on the foreign key; sanity-check row counts
Filtering the right table in WHERE after a LEFT JOINUnmatched rows vanish; the join behaves like INNERPut the condition in ON, or test IS NULL deliberately
Ambiguous column names (id in two tables)Error, or the wrong column is selectedQualify columns with table aliases
Expecting one row per customer after joining ordersCustomers repeat once per order, inflating counts and sumsAggregate (next lesson) or join to a pre-aggregated subquery
Practice
  1. Write queries on customers and orders for: customers with their orders, all customers including those with none, and only the customers with no orders.
  2. Add an order_items(order_id, product_id, qty) table and a products table. Write a four-table join listing customer name, product name, and quantity.
Key takeaways
  • INNER JOIN keeps matches only; LEFT JOIN keeps every left row and fills gaps with NULL.
  • A LEFT JOIN plus IS NULL finds rows that have no match.
  • Outer-join conditions in WHERE can silently turn them into inner joins.
