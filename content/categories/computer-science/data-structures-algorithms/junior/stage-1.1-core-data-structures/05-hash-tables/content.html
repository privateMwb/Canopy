Hash Tables

O(1) average lookup, how hashing makes that possible, and the cases where it breaks down.

§1The Core Idea

A hash table maps keys to values by running each key through a hash function that produces an index into an underlying array. Looking up a key means recomputing its hash and jumping straight to that index — no searching required, which is why average-case lookup is O(1).

d = {{}}
d["apple"] = 3        # O(1) average — hash("apple") determines where this is stored
d["apple"]             # 3 — O(1) average lookup

§2Collisions — When Two Keys Hash the Same

Different keys can produce the same hash (a collision). Common strategies: chaining (each array slot holds a small list of all keys that landed there) or open addressing (probe for the next free slot). Either way, collisions are handled automatically by the hash table implementation — but they're the reason worst-case lookup isn't actually O(1).

§3Average Case vs. Worst Case

CaseLookup complexityWhen it happens
AverageO(1)Hash function spreads keys evenly, few collisions
WorstO(n)Many keys collide into the same slot (rare with a good hash function)

§4What Makes a Good Hash Function

A good hash function distributes keys evenly across the available slots, and is fast to compute. A poor one (e.g. always returning the same value) would turn every lookup into a worst-case O(n) search through a collision chain — this is why real hash table implementations invest heavily in their hash functions.

§5What Hash Tables Can't Do

No ordering Hash tables don't preserve any natural ordering of keys (beyond implementation-specific insertion order in some languages). If you need sorted iteration or range queries ("all keys between X and Y"), a hash table is the wrong structure — a balanced tree is usually the right one.

§6Common Mistakes

MistakeWhat HappensFix
Assuming hash table lookup is always O(1)Surprised by worst-case behavior under heavy collisionsUnderstand O(1) as the average case, not a guarantee
Using a hash table when you need sorted/range queriesNo efficient way to do itUse a balanced tree or sorted structure instead
Practice
  1. Implement a simple hash table using chaining (an array of lists) with insert and lookup operations.
  2. In one or two sentences, explain why a hash table can't efficiently answer "give me all keys between 10 and 20."
Key takeaways
  • Hash tables map keys to array indices via a hash function, giving O(1) average-case lookup.
  • Collisions (two keys hashing the same) are handled via chaining or open addressing, and are why worst-case lookup is O(n).
  • Hash tables don't support ordering or range queries — use a tree-based structure for those.
