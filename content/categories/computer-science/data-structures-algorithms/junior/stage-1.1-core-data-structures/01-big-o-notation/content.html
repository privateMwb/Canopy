Big O Notation

Measuring how an algorithm's time and space needs grow as input size grows — the language every later lesson is written in.

§1What Big O Actually Measures

Big O describes how an algorithm's running time (or memory use) grows as the input size n grows — not the exact number of operations, but the shape of growth. It answers "if I double the input, roughly how much more work is this?"

§2The Common Complexity Classes

O(1)        # constant — same work regardless of input size
O(log n)    # logarithmic — work grows very slowly (binary search)
O(n)        # linear — work grows proportionally to input
O(n log n)  # "linearithmic" — most efficient general-purpose sorts
O(n²)       # quadratic — nested loops over the same input
O(2ⁿ)       # exponential — work doubles with every additional input element

§3Reading Code for Complexity

# O(n) — one pass through the array
for item in array:
    process(item)

# O(n²) — a loop inside a loop, each over the same input
for i in array:
    for j in array:
        compare(i, j)

A single loop over the input is usually O(n). A loop nested inside another loop over the same input is usually O(n²). This pattern-matching gets you most of the way to estimating complexity without formal proof.

§4Why "Approximately" Is the Point

Big O drops constants and lower-order terms An algorithm doing exactly 3n + 7 operations is still O(n) — the 3 and the 7 don't change how it scales as n grows huge, which is the only thing Big O cares about. This is deliberate: it's a tool for comparing growth, not for predicting exact runtime.

§5Time vs. Space Complexity

Big O applies to memory too, not just time. An algorithm might be fast (O(n) time) but memory-hungry (O(n) extra space for a lookup table) — real decisions often trade one against the other, and both are worth stating explicitly.

§6Common Mistakes

MistakeWhat HappensFix
Confusing O(n) with "n operations exactly"Misunderstanding what the notation actually promisesRemember it describes growth rate, not an exact count
Only ever stating time complexityMissing memory costs that matter just as much in practiceState both time and space complexity when it's relevant
Practice
  1. State the time complexity of a function that finds the maximum value in an unsorted array.
  2. State the time complexity of a function with two separate (not nested) loops, each over the full input.
  3. Explain, in one sentence, why O(2n) is written simply as O(n).
Key takeaways
  • Big O describes how work grows as input size grows, not an exact operation count.
  • A single loop over the input is usually O(n); nested loops over the same input are usually O(n²).
  • Complexity applies to both time and space — real algorithm choices often trade one against the other.
