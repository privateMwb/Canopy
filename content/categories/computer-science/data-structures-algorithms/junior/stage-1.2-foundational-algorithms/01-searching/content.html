Searching

Linear search vs. binary search, and the sorted-input assumption binary search depends on.

§1Linear Search — Check Everything

def linear_search(arr, target):
    for i, val in enumerate(arr):
        if val == target:
            return i
    return -1

Linear search checks every element until it finds a match (or runs out). It works on any array, sorted or not, but is O(n) — no shortcuts.

§2Binary Search — Halve the Search Space Each Step

def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

Binary search checks the middle element; if the target is smaller, it discards the entire right half, and vice versa — eliminating half the remaining possibilities with every comparison. This gives O(log n), dramatically faster than linear search on large inputs.

§3The Catch: It Needs Sorted Input

Binary search's one requirement Binary search only works correctly on sorted data — the "discard half" logic depends entirely on knowing which half the target must be in, which only holds if the array is ordered. Running binary search on unsorted data gives wrong, unpredictable results, not an error.

§4When Sorting First Is (and Isn't) Worth It

ScenarioBetter approach
Searching once, data unsortedLinear search — sorting first (O(n log n)) costs more than one O(n) search
Searching many times, data unsortedSort once (O(n log n)), then binary search each time (O(log n))
Data already sortedBinary search, always

§5Common Mistakes

MistakeWhat HappensFix
Using binary search on unsorted dataWrong results, silently — no error raisedConfirm the data is sorted before using binary search
Off-by-one errors in the lo/hi boundsMissing the target or infinite loopCarefully trace a small example by hand to verify boundary logic
Practice
  1. Trace binary search by hand searching for 7 in [1, 3, 5, 7, 9, 11], writing out lo, hi, mid at each step.
  2. Explain, in one sentence, why binary search needs sorted input but linear search doesn't.
Key takeaways
  • Linear search is O(n) and works on any array; binary search is O(log n) but requires sorted input.
  • Binary search eliminates half the remaining possibilities with each comparison.
  • Sort-then-binary-search only pays off when you're searching the same data multiple times.
