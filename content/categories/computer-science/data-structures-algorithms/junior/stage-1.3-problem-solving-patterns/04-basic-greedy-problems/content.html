Basic Greedy Problems

Making the locally-best choice at each step — and learning when that actually leads to the globally-best answer.

§1The Greedy Idea

A greedy algorithm makes the choice that looks best right now, at each step, without reconsidering it later — no backtracking, no exploring alternatives. It's simple and fast, but only correct for problems where local optimality actually leads to global optimality.

§2A Worked Example: Making Change

def min_coins(amount, coins):   # coins sorted descending, e.g. [25, 10, 5, 1]
    count = 0
    for coin in coins:
        count += amount // coin
        amount %= coin
    return count

Always use the largest coin that fits, as many times as possible, then move to the next smaller coin. For standard currency denominations this gives the true minimum — but the greedy choice isn't always correct, which is the whole point of the next section.

§3When Greedy Fails

A coin system where greedy breaks With coins [1, 3, 4] and a target of 6: greedy picks 4, then 1, then 1 — three coins. The actual optimal answer is 3 + 3 — two coins. Greedy's "biggest coin first" choice wasn't globally optimal here, because this coin system doesn't have the structural property standard currency does.

§4A Worked Example Where Greedy Does Work: Interval Scheduling

# maximize the number of non-overlapping intervals you can select
def max_non_overlapping(intervals):
    intervals.sort(key=lambda x: x[1])   # sort by END time
    count = 0
    last_end = float("-inf")
    for start, end in intervals:
        if start >= last_end:
            count += 1
            last_end = end
    return count

Always picking the interval that ends soonest (among remaining valid options) provably maximizes how many non-overlapping intervals you can fit — this is a case where the greedy choice genuinely is globally optimal, and it can be proven.

§5How to Know If Greedy Will Work

Greedy only works when the problem has two properties: optimal substructure (an optimal solution to the whole problem contains optimal solutions to subproblems) and the greedy-choice property (a locally optimal choice leads to a globally optimal solution). Without a reason to believe both hold, assume greedy might not work — and check against a brute-force solution on small examples.

§6Common Mistakes

Assuming greedy always finds the optimal answerSilently wrong results on problems without the greedy-choice propertyVerify against brute force on small cases before trusting a greedy approach
Sorting by the wrong key (e.g. start time instead of end time for interval scheduling)Greedy choice stops being correct even on a problem where greedy does applyCarefully justify which sort order actually produces the greedy-optimal choice
Practice
  1. Using the coin system [1, 3, 4], find the true minimum coins for amount 6 by trying combinations, and compare to what the greedy approach gives.
  2. Explain, in one or two sentences, why sorting intervals by end time (not start time) is the key to the interval-scheduling example.
Key takeaways
  • Greedy algorithms make the locally-best choice at each step, without reconsidering it.
  • This only produces a globally optimal answer for problems with the greedy-choice property — not all problems have it.
  • When unsure, verify a greedy approach against brute force on small examples before trusting it.
