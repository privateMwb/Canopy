Knapsack Patterns

0/1 knapsack and its variants — the template underlying a huge class of "choose items under a constraint" DP problems.

§1The Classic Problem

Given items each with a weight and a value, and a knapsack with a maximum weight capacity, choose which items to include to maximize total value without exceeding the weight limit. "0/1" means each item is either fully included or fully excluded — no partial items.

§2The DP Solution

def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for w in range(capacity + 1):
            if weights[i - 1] <= w:
                dp[i][w] = max(
                    dp[i - 1][w],                                      # don't take item i
                    values[i - 1] + dp[i - 1][w - weights[i - 1]]      # take item i
                )
            else:
                dp[i][w] = dp[i - 1][w]   # item i too heavy to even consider
    return dp[n][capacity]

dp[i][w] represents the best value achievable using the first i items within weight limit w. At each item, decide: take it (if it fits) or leave it — exactly the same "two choices per step" shape as the house-robber problem, now with a weight constraint.

§3Why This Template Shows Up Everywhere

A huge number of problems are secretly knapsack in disguise: "can you partition this array into two equal-sum halves," "minimum coins to make change," "maximum items selectable under a budget." Recognizing the underlying shape — choosing a subset under a constraint to optimize some value — is more valuable than memorizing the exact code.

§4Variants Worth Knowing

VariantKey difference
0/1 KnapsackEach item used at most once
Unbounded KnapsackEach item can be used unlimited times (e.g. coin change)
Subset SumA special case: does any subset sum to exactly a target value?

§5Common Mistakes

MistakeWhat HappensFix
Not recognizing a problem as knapsack-shapedMissing a clean DP solution, resorting to slower brute forceLook for "choose a subset under a constraint to optimize a value" as the signal
Using 0/1 knapsack's iteration order for an unbounded variant (or vice versa)Allows (or disallows) reusing items incorrectlyConfirm whether items can repeat, and adjust the loop structure accordingly
Practice
  1. Trace the knapsack DP table by hand for items with weights [1,3,4] and values [15,20,30], capacity 4.
  2. Explain, in one or two sentences, why subset sum is a special case of knapsack.
Key takeaways
  • Knapsack problems choose a subset of items under a constraint to maximize (or achieve) some value.
  • The core DP decision at each item is the same shape as house-robber: take it, or don't.
  • Many problems are knapsack in disguise — recognizing the underlying shape matters more than memorizing code.
