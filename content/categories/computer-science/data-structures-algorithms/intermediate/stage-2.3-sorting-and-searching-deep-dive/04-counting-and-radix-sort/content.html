Counting & Radix Sort

Sorting faster than O(n log n) — when the data lets you skip comparisons entirely.

§1The O(n log n) Lower Bound — and How to Beat It

Comparison-based sorts (merge sort, quick sort) can't do better than O(n log n) in the worst case — that's a proven mathematical limit for sorting by comparing elements. Counting and radix sort beat this by not comparing elements at all; they exploit specific structure in the data instead.

§2Counting Sort

def counting_sort(arr, max_val):
    counts = [0] * (max_val + 1)
    for x in arr:
        counts[x] += 1
    result = []
    for val, count in enumerate(counts):
        result.extend([val] * count)
    return result

Count how many times each value appears, then reconstruct the sorted array directly from those counts — O(n + k), where k is the range of possible values. No comparisons at all.

§3The Catch: It Needs a Known, Limited Range

Why this isn't a universal replacement Counting sort is only efficient when the range of values (k) is reasonably small relative to n. Sorting ages 0-120 works great; sorting arbitrary 64-bit integers doesn't — the counts array would be absurdly large. This is the specific structure the algorithm depends on.

§4Radix Sort — Extending the Idea to Bigger Numbers

# conceptual: sort by each digit, least significant first, using a stable sort each pass
for digit_place in [1, 10, 100, ...]:
    arr = counting_sort_by_digit(arr, digit_place)

Radix sort applies counting sort repeatedly, one digit position at a time, from least to most significant — using a stable sort at each pass is essential, or earlier digit orderings get destroyed. This extends counting sort's reach to larger numbers without needing a counts array the size of the full value range.

§5When These Actually Win

ScenarioBest choice
Sorting ages, grades, small integer rangesCounting sort — O(n + k), beats O(n log n)
Sorting large integers or strings with fixed-width digitsRadix sort
General-purpose, unknown/arbitrary dataMerge sort or quick sort

§6Common Mistakes

MistakeWhat HappensFix
Using counting sort on data with a huge value rangeEnormous, wasteful counts arrayOnly use counting sort when the range is small relative to n
Using an unstable sort within radix sort's digit passesBreaks the ordering from previous digit passesAlways use a stable sort for each digit pass in radix sort
Practice
  1. Use counting sort to sort [4, 2, 2, 8, 3, 3, 1] by hand, writing out the counts array first.
  2. Explain, in one or two sentences, why counting sort isn't a universal replacement for comparison-based sorts.
Key takeaways
  • Counting and radix sort beat the O(n log n) comparison-sort limit by not comparing elements at all.
  • Counting sort needs a known, reasonably small value range to be efficient.
  • Radix sort extends the idea to larger numbers by sorting digit by digit, using a stable sort at each pass.
