Binary Search on the Answer

Using binary search on a range of possible answers, not just a sorted array of data.

§1A Different Way to Use Binary Search

Binary search doesn't have to search a literal array. If a problem's answer lies somewhere in a range of numbers, and you can check "is this candidate answer good enough?" efficiently, binary search can narrow in on the exact right answer — even without any array to search.

§2The Pattern

def binary_search_on_answer(lo, hi, is_feasible):
    while lo < hi:
        mid = (lo + hi) // 2
        if is_feasible(mid):
            hi = mid        # mid works — try for something even better
        else:
            lo = mid + 1     # mid doesn't work — need something bigger
    return lo

This requires one key property: the feasibility check must be monotonic — if a value works, every "better" value in the same direction also works. Without that, binary search's "discard half" logic doesn't hold.

§3A Worked Example: Minimum Capacity to Ship Packages

# can all packages ship within `days` days, given a ship capacity?
def can_ship(weights, days, capacity):
    needed_days = 1
    current_load = 0
    for w in weights:
        if current_load + w > capacity:
            needed_days += 1
            current_load = 0
        current_load += w
    return needed_days <= days

def min_capacity(weights, days):
    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = (lo + hi) // 2
        if can_ship(weights, days, mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

There's no array of "candidate capacities" to search — just a range of possible values. If capacity X works, any larger capacity also works (monotonic), so binary search narrows in on the smallest capacity that still works.

§4Recognizing This Pattern

The signal to look for "Minimum/maximum X such that condition Y holds" is the classic phrasing for this pattern — especially when brute-force checking every possible X would be too slow, but checking whether one specific X works is fast and the feasibility is monotonic.

§5Common Mistakes

MistakeWhat HappensFix
Applying this pattern when feasibility isn't actually monotonicBinary search gives wrong resultsVerify the "if X works, does every larger/smaller X also work" property first
Setting the search range (lo, hi) incorrectlyMisses the true answer entirelyCarefully derive valid bounds for the answer from the problem constraints

Key takeaways
  • Binary search can search a range of possible answers, not just a literal sorted array.
  • This requires the feasibility check to be monotonic — if one value works, every value further in the same direction also works.
  • "Minimum/maximum X such that condition Y holds" is the typical phrasing that signals this pattern.
