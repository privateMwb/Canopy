Topological Sort

Ordering tasks with dependencies — when it's possible, and when a cycle makes it not.

§1The Problem

Given tasks with dependencies ("B must happen after A"), topological sort produces a valid order where every task comes after everything it depends on. This only works on a directed acyclic graph (DAG) — a graph with directed edges and no cycles.

§2DFS-Based Topological Sort

def topological_sort(graph):
    visited = set()
    stack = []

    def dfs(node):
        visited.add(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                dfs(neighbor)
        stack.append(node)   # add AFTER exploring all dependencies

    for node in graph:
        if node not in visited:
            dfs(node)

    return stack[::-1]   # reverse — last-finished nodes have no remaining dependents

A node gets added to the result only after all its dependents have been fully explored — which is exactly why reversing the finish order gives a valid topological order.

§3Why Cycles Make This Impossible

The fundamental limit If task A depends on B, and B depends on A, there's no valid order — whichever comes first violates the other's dependency. A topological sort only exists if the dependency graph is acyclic; detecting a cycle during the sort is how you discover the dependencies are contradictory.

§4A Real Example: Course Scheduling

courses = {{
    "Calc2": ["Calc1"],
    "Calc1": [],
    "Physics2": ["Calc1", "Physics1"],
    "Physics1": [],
}}
# a valid order: Calc1, Physics1, Calc2, Physics2 (or similar)

Course prerequisites are a textbook example — courses are nodes, "requires" relationships are directed edges, and a valid semester-by-semester plan is exactly a topological order.

§5Common Mistakes

MistakeWhat HappensFix
Running topological sort on a graph with a cycle, without detecting itProduces an invalid or incomplete order silentlyDetect cycles explicitly (e.g. track nodes currently "in progress" during DFS)
Forgetting to reverse the DFS finish orderDependencies come out backwardRemember nodes finish last-dependency-first — reverse at the end
Practice
  1. Given tasks {{"B": ["A"], "C": ["A", "B"], "A": []}}, produce a valid topological order by hand.
  2. Explain, in one or two sentences, why a cycle in the dependency graph makes topological sort impossible.
Key takeaways
  • Topological sort orders tasks so every task comes after its dependencies — only possible on a directed acyclic graph.
  • DFS-based topological sort reverses the order nodes finish being explored.
  • A cycle in the dependency graph means no valid order exists at all.
