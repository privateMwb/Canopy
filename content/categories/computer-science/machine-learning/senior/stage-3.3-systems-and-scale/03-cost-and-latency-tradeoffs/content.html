Cost & Latency Tradeoffs

The real-world constraints that shape production ML systems as much as accuracy does.

§1Accuracy Isn't the Only Metric That Matters

A model that's 2% more accurate but 10x slower and 10x more expensive to run isn't automatically the right choice for production — it depends entirely on what the system actually needs. Cost and latency are real constraints, not afterthoughts.

§2Latency Budgets

Use caseTypical latency tolerance
Real-time fraud check during checkoutTens of milliseconds
Chat assistant responseUnder a few seconds
Nightly batch reportMinutes to hours — latency barely matters

The acceptable latency defines which models are even viable options. A large, highly-accurate model might be the right call for a batch job and completely wrong for a checkout-flow fraud check.

§3Cost at Scale

A model costing $0.01 per prediction sounds trivial — until it's running a million times a day. Production ML cost decisions usually happen at this multiplied scale, not per-call, which is why compression techniques (previous lesson) and smaller models often win out over marginally-more-accurate large ones.

§4Common Tradeoff Levers

  • Model size: smaller models are cheaper and faster, usually somewhat less accurate.
  • Caching: repeated or similar requests can skip computation entirely.
  • Batching: grouping requests improves throughput, at the cost of some added latency per individual request.
  • Async/batch processing: moving non-urgent predictions off the real-time path entirely.

§5Common Mistakes

MistakeWhat HappensFix
Optimizing purely for accuracy during model selectionA model that's technically "best" but unusable in productionWeigh accuracy against latency and cost requirements from the start
Not measuring cost at realistic production scaleBudget surprises once traffic growsEstimate cost per prediction multiplied by expected real volume
Practice
  1. For a real-time recommendation system, list the latency and cost constraints you'd expect, and how they'd shape model choice.
  2. In one or two sentences, explain why batching improves throughput but can hurt individual-request latency.
Key takeaways
  • Accuracy alone doesn't determine the right model for production — latency and cost are real constraints.
  • Latency budgets differ hugely by use case, and define which models are even viable.
  • Cost decisions happen at multiplied production scale, not per individual prediction.
