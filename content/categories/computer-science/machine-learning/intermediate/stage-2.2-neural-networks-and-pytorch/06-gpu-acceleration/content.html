GPU Acceleration

Why GPUs train neural networks so much faster than CPUs, and the practical mechanics of using one.

§1Why GPUs, Specifically

Neural network training is dominated by matrix multiplication — the same operation, repeated millions of times, on independent chunks of data. CPUs are built for fast sequential logic; GPUs are built for exactly this kind of massively parallel, repetitive math, often 10-100x faster for training.

§2Moving Data to the GPU

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

model = model.to(device)
X_train = X_train.to(device)
y_train = y_train.to(device)

Both the model and the data need to live on the same device — a common and confusing error is a model on the GPU trying to process data still sitting on the CPU, or vice versa.

§3What Actually Speeds Up

The speedup comes specifically from parallelizable operations — matrix multiplications, convolutions. Small models, or code with a lot of sequential Python logic between tensor operations, may see little benefit from a GPU; the data-transfer overhead can even make it slower for tiny workloads.

§4Batch Size and GPU Memory

GPUs have fixed memory. Larger batch sizes use that parallel hardware more efficiently (faster training) but use more memory — "CUDA out of memory" errors are the classic sign a batch size is too large for the available GPU.

§5Common Mistakes

MistakeWhat HappensFix
Model on GPU, data still on CPU (or vice versa)RuntimeError: expected all tensors to be on the same deviceMove both model and data with .to(device) consistently
Batch size too large for available GPU memoryCUDA out of memoryReduce batch size, or use gradient accumulation

  1. Write the device-detection and .to(device) lines needed to make a training script GPU-aware, falling back to CPU automatically.
  2. In one sentence, explain why matrix multiplication specifically benefits so much from GPU parallelism.
Key takeaways
  • GPUs accelerate training because neural networks are dominated by parallelizable matrix math.
  • Model and data must be moved to the same device, consistently, or operations will fail.
  • Batch size trades off GPU utilization against memory — "out of memory" means it's too large for the hardware.
