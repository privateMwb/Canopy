Data Leakage

The subtle ways information from the future — or from the test set — sneaks into training, and how to catch it before it fools you.

§1What Leakage Actually Is

Data leakage happens when information that wouldn't be available at real prediction time ends up influencing the model during training. The model looks great in testing and then falls apart in production, because it secretly learned to cheat.

§2The Obvious Case

# predicting whether a loan defaults, using a column that's only known AFTER default happens
features = ["income", "credit_score", "days_late_on_payment"]
# "days_late_on_payment" wouldn't exist yet at the time you'd actually make this prediction

This one is easy to catch once you think about timing: would this feature actually be known at the moment you'd need to make the prediction? If not, it's leakage.

§3The Subtle Case — Preprocessing Before Splitting

# WRONG — scaler sees the test set's distribution before the split even happens
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)              # fit on ALL data, including future test set
X_train, X_test, y_train, y_test = train_test_split(X_scaled, y)

# RIGHT — fit the scaler on training data only, then apply it to test data
X_train, X_test, y_train, y_test = train_test_split(X, y)
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)   # fit only on train
X_test_scaled = scaler.transform(X_test)          # apply the same transform, don't refit

Even something as innocuous as scaling can leak information: if you compute the mean/std across the full dataset before splitting, the test set's statistics have quietly influenced your training data.

§4Duplicate Rows Across the Split

If the same (or a near-identical) example appears in both train and test sets — common with time-series data split randomly instead of chronologically, or datasets with duplicate entries — the model effectively "sees the answer" during evaluation.

The timing test For any feature, ask: "at the real moment I'd need to make this prediction, would I actually have this value?" If the honest answer is no, or "only sometimes," that feature is a leakage risk.

§5Common Mistakes

MistakeWhat HappensFix
Fitting scalers/encoders before splittingTest set statistics leak into trainingAlways split first, fit preprocessing only on train
Including a target-derived featureNear-perfect, fake-looking accuracyTrace each feature back to whether it's truly available pre-prediction
Random splitting on time-series dataModel "sees the future"Split chronologically — train on earlier data, test on later
Practice
  1. Given a dataset predicting hospital readmission, list two features that might be leakage risks and explain why.
  2. Rewrite a preprocessing pipeline that currently scales before splitting so it scales after.
Key takeaways
  • Leakage is information the model wouldn't really have at prediction time, sneaking in during training.
  • Always split before fitting any preprocessing step, not after.
  • Time-series data needs a chronological split, not a random one.
