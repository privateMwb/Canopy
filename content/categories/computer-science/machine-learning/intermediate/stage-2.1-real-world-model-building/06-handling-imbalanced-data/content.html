Handling Imbalanced Data

When one class vastly outnumbers another, and the techniques that keep a model from just ignoring the minority class.

§1Why Imbalance Is a Problem

If 98% of transactions aren't fraud, a model that predicts "not fraud" for everything scores 98% accuracy while catching zero actual fraud. Standard training tends to favor the majority class, since that's where most of the "reward" for correct predictions comes from.

§2Class Weights — the Simplest Fix

from sklearn.linear_model import LogisticRegression

model = LogisticRegression(class_weight="balanced")
model.fit(X_train, y_train)

class_weight="balanced" tells the model to penalize mistakes on the minority class more heavily, roughly proportional to how rare it is. Often the single easiest, lowest-risk fix to try first.

§3Resampling — Oversampling and Undersampling

# oversampling: duplicate (or synthesize) minority-class examples
from imblearn.over_sampling import SMOTE
X_resampled, y_resampled = SMOTE().fit_resample(X_train, y_train)

# undersampling: drop some majority-class examples
from imblearn.under_sampling import RandomUnderSampler
X_resampled, y_resampled = RandomUnderSampler().fit_resample(X_train, y_train)

Oversampling (including SMOTE, which generates synthetic minority examples rather than just duplicating) gives the model more minority-class signal to learn from. Undersampling throws away majority-class data to balance the ratio — simpler, but wastes data.

Resample training data only Resampling must happen after the train/test split, and only on the training set. Resampling before splitting (or resampling the test set) creates a leakage-like problem — the test set should always reflect the real, imbalanced distribution you'll see in production.

§4Choosing the Right Metric

On imbalanced data, accuracy is nearly meaningless (as covered in Precision and Recall). Precision, recall, F1, and the confusion matrix matter far more here — always check those before accuracy on an imbalanced problem.

§5Common Mistakes

MistakeWhat HappensFix
Resampling before the train/test splitSynthetic/duplicated examples leak across the splitSplit first, resample only the training set
Judging the model by accuracyA useless majority-only model looks greatUse precision, recall, F1, or the confusion matrix instead
Oversampling so aggressively the minority class dominatesCan flip the problem — now majority class gets missedAim for a more moderate balance, validate on the real distribution
Practice
  1. Given a dataset with 95%/5% class imbalance, train a model with class_weight="balanced" and one without it.
  2. Compare precision and recall (not accuracy) between the two.
  3. In one sentence, explain why the test set shouldn't be resampled.
Key takeaways
  • Imbalanced data makes accuracy misleading — a model can look great while being useless on the minority class.
  • class_weight="balanced" is the simplest first fix; resampling (SMOTE, undersampling) are stronger options.
  • Only ever resample the training set, after splitting, never the test set.
