Global Traffic: Anycast, GeoDNS & CDNs

Sending users to a nearby healthy location cuts latency and survives regional failures, and DNS, routing, and caching each provide a different tool for it.

§1DNS-Based Steering

The simplest way to direct users is DNS: the authoritative server returns different answers depending on who asks.

  • GeoDNS: answer with the region nearest the resolver's location
  • Latency-based: answer with the region measured to be fastest
  • Weighted: split traffic by percentage, useful for gradual migrations
  • Health-based failover: stop returning the address of a failed region

The limits matter. DNS sees the resolver's address, not the user's, so steering is only as good as the resolver's proximity (some resolvers pass a truncated client subnet to help). And answers are cached for the TTL, so failover is never instant: clients keep using the old address until their cached record expires, and some ignore TTLs.

§2Anycast

With anycast, the same IP address is announced from many locations through BGP routing. Each user's packets follow the routing system to the topologically nearest announcing site, with no DNS trickery. If a site fails and withdraws its announcement, traffic shifts to the next nearest within seconds.

203.0.113.10 announced from  Frankfurt, Singapore, Virginia
User in Berlin     → routed to Frankfurt
User in Jakarta    → routed to Singapore
# Frankfurt withdraws the route → Berlin users now reach Virginia or Singapore.

Anycast suits short, stateless exchanges, which is why DNS resolvers and CDNs use it. Long-lived TCP connections are riskier, since a routing change mid-connection can send packets to a different site that has no state for it. Anycast also absorbs DDoS traffic across many sites rather than concentrating it.

§3CDNs and Origins

A content delivery network places caching servers near users. A request hits the nearest edge; on a cache hit, it's answered locally, and on a miss, the edge fetches from the origin and stores it according to the caching headers you set (Stage 2.2). Many CDNs add an origin shield, a middle tier that collapses misses so the origin sees each object once rather than once per edge.

curl -sI https://cdn.example.com/app.js | grep -i -E 'x-cache|age|cf-ray|via'
# HIT vs MISS, and Age in seconds, show how the edge handled the request

CDNs also terminate TLS close to the user, which shortens handshakes, absorb traffic spikes and attacks, and can serve stale content when the origin is down.

§4Failover in Practice

MechanismFailover speedCaveat
DNS with short TTLSeconds to minutes (when clients honor TTL)Cached answers and resolver behavior vary
Anycast withdrawalSecondsMid-connection flows may break
Load balancer health checksSeconds, within one regionDoesn't help if the whole region fails

Real multi-region designs combine them: anycast or GeoDNS to pick a region, a regional load balancer to pick an instance, and a CDN in front for cacheable content. Test failover regularly, because untested failover paths tend not to work.

The key insight Every traffic-steering method has a delay or an accuracy limit. DNS is cached, anycast follows BGP, and CDNs follow cache headers. Know each one's failure behavior before you rely on it.

§5Common Mistakes

MistakeWhat HappensFix
Expecting DNS failover to be instantClients keep using the old address until the TTL expiresUse short TTLs for failover records, and combine with other mechanisms
Using anycast for long-lived stateful connections without planningRouting changes can break connectionsKeep state shared across sites, or use it for short exchanges
Caching personalized pages at the CDNOne user's page is shown to anotherMark private responses private or no-store, and vary correctly
Practice
  1. Use dig from two different resolvers on a CDN-hosted site and compare the addresses returned. Explain the difference.
  2. Design failover for a service in two regions, stating how each failure (instance, region, DNS) is detected and how long recovery takes.
Key takeaways
  • GeoDNS and latency routing steer by resolver location, with failover limited by TTL caching.
  • Anycast routes users to the nearest site by BGP and shifts quickly when a site withdraws.
  • CDNs cache near users and shield the origin; combine all three and test failover.
