Packets, Frames & Encapsulation

Data is wrapped in a new header at each layer on the way down and unwrapped on the way up, so the same bytes carry several layers' worth of instructions.

§1Encapsulation

When a program sends data, each layer adds a header, and the link layer adds a trailer too. This wrapping is called encapsulation. The receiver peels the layers off in reverse.

Application:   [ HTTP request                                    ]
Transport:    [ TCP hdr ][ HTTP request                         ]   segment
Internet:     [ IP hdr  ][ TCP hdr ][ HTTP request              ]   packet
Link:    [Eth hdr][ IP hdr ][ TCP hdr ][ HTTP request ][Eth trailer]   frame
NameLayerTypical header size
Segment (TCP) / datagram (UDP)Transport20+ bytes (TCP), 8 bytes (UDP)
PacketInternet20 bytes (IPv4 minimum), 40 (IPv6)
FrameLink14-byte Ethernet header plus a 4-byte trailer

In casual speech 'packet' is used for all of these, but the distinction helps when you read a capture.

§2What Each Header Carries

  • Ethernet: destination and source MAC, and a type field saying what's inside (IPv4, IPv6, ARP)
  • IP: source and destination IP, time-to-live (TTL), the protocol of the payload (6 = TCP, 17 = UDP)
  • TCP: source and destination port, sequence and acknowledgment numbers, flags such as SYN and ACK, the window size
  • Application: whatever the protocol defines, such as the HTTP request line and headers

Every layer reads only its own header and treats everything after it as opaque payload. A router needs the IP header but never reads the TCP header; a firewall that filters by port reads further.

§3MTU and Segment Size

A link has a maximum transmission unit (MTU), the largest packet it can carry. Standard Ethernet allows 1500 bytes. With 20 bytes of IP and 20 of TCP header, a TCP segment can carry at most 1460 bytes of data, the maximum segment size (MSS). Larger data is split across many packets.

ip link show eth0 | grep mtu          # mtu 1500
sudo tcpdump -nn -i any -c 5 'tcp port 443'   # watch real packets; -nn skips name lookups

Headers are overhead. A tiny 10-byte message in a TCP/IP/Ethernet frame carries 54 bytes of headers around it, which is why chatty protocols with small messages waste bandwidth.

Connection to later lessons MTU limits come back in Stage 3.3, where a mismatch between a path's real MTU and what endpoints assume causes one of the most confusing network failures: connections that work for small requests and hang on large ones.

§4Common Mistakes

MistakeWhat HappensFix
Using 'packet' for everything in a captureConfusion about which header is being discussedUse segment, packet, and frame for transport, internet, and link
Ignoring header overhead for small messagesSurprise at low efficiency for tiny writesBatch small messages, or use a protocol designed for them
Assuming one send equals one packetA large write is split, and small writes may be combinedTCP is a byte stream; the OS decides how to divide it
Practice
  1. Use tcpdump -nn -c 5 while loading a page and identify the IP and TCP headers of one packet.
  2. Compute the total bytes on the wire for a 100-byte HTTP request in a single TCP/IPv4/Ethernet frame (ignore options).
Key takeaways
  • Each layer wraps data in its own header on the way down and removes it on the way up.
  • Segment, packet, and frame name the transport, internet, and link layers' units.
  • The MTU caps packet size, and TCP's MSS is the MTU minus the IP and TCP headers.
