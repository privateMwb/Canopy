Layers & the Network Stack

Networking is built as a stack of layers, each doing one job and relying on the layer below, so you can change one without rewriting the others.

§1Why Layers

Sending a web page across the world involves radio or cable signals, addressing, routing, reliable delivery, encryption, and the request itself. No single piece of software does all of it. Instead, each layer solves one problem and offers a simple service to the layer above. HTTP doesn't need to know whether the bytes travel over Wi-Fi or fiber, and Wi-Fi doesn't need to know what an HTTP request is.

Each layer on the sender adds its own information, and the matching layer on the receiver reads it. Layer 4 on one machine is talking to layer 4 on the other, even though the data physically passes through every layer in between.

§2The TCP/IP Model

LayerJobExamples
ApplicationWhat the program saysHTTP, DNS, SMTP, TLS (conceptually here)
TransportDelivery between two programsTCP, UDP, QUIC
InternetDelivery between two hosts across networksIP, ICMP
LinkDelivery across one local networkEthernet, Wi-Fi, ARP

The seven-layer OSI model splits this further: physical, data link, network, transport, session, presentation, and application. People still say 'layer 2' for the link layer, 'layer 3' for IP, 'layer 4' for TCP/UDP, and 'layer 7' for the application, so you need both vocabularies. The TCP/IP model is what the internet actually runs.

§3Seeing the Layers in One Command

curl -v https://example.com 2>&1 | head -30

# Look for these in the output:
#   * Trying 93.184.215.14:443     <- layer 3 (IP address) and layer 4 (port 443, TCP)
#   * SSL connection using TLS...  <- encryption between transport and application
#   > GET / HTTP/2                 <- layer 7, the actual request

Each line of that output belongs to a different layer, and a failure at any one of them looks different. 'Could not resolve host' is a naming problem, 'connection refused' is a transport problem, and a 404 is an application answer from a server that was reachable all along.

The key insight Layers let you localize a problem. When something fails, the first question is always 'at which layer?' Everything in this course, from DNS to TLS to APIs, fits somewhere in this stack.

§4Common Mistakes

MistakeWhat HappensFix
Treating 'the network' as one thingYou can't tell whether DNS, routing, TCP, or the app is at faultAsk which layer is failing, and test each with its own tool
Confusing OSI and TCP/IP layer numbersMix-ups in conversation about 'layer 3' vs 'layer 4'Memorize: L2 link, L3 IP, L4 TCP/UDP, L7 application
Assuming a lower layer provides what only a higher one doesExpecting IP to guarantee delivery or orderIP is best-effort; reliability comes from TCP at layer 4
Practice
  1. Run curl -v https://example.com and label each line of output with the layer it belongs to.
  2. For each failure, name the most likely layer: 'no route to host', 'connection reset', 'certificate has expired', '503 Service Unavailable'.
Key takeaways
  • The network is a stack of layers, each solving one problem for the layer above.
  • TCP/IP has four layers, and OSI has seven; the numbers L2, L3, L4, and L7 are common shorthand.
  • Diagnosing a failure starts with finding which layer it belongs to.
