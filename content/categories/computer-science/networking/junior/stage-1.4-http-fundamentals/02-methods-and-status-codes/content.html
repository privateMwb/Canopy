Methods & Status Codes

The method says what the client wants to do, and the status code says how it went, and both carry meaning that clients, caches, and proxies rely on.

§1Methods

MethodPurposeSafeIdempotent
GETRetrieve a resourceYesYes
HEADLike GET, headers onlyYesYes
POSTCreate or trigger an actionNoNo
PUTReplace a resource entirelyNoYes
PATCHModify part of a resourceNoNot guaranteed
DELETERemove a resourceNoYes
OPTIONSAsk what's allowed (used by CORS)YesYes

Safe means the request doesn't change server state, so a crawler may call it freely. Idempotent means sending it many times has the same effect as once, which makes it safe to retry after a timeout. Sending a DELETE twice leaves the same end state, but sending a POST twice may create two records.

§2Status Code Classes

ClassMeaningCommon codes
1xxInformational101 Switching Protocols
2xxSuccess200 OK, 201 Created, 204 No Content
3xxRedirection301 Moved Permanently, 302 Found, 304 Not Modified
4xxClient error400 Bad Request, 401, 403, 404, 409 Conflict, 429 Too Many Requests
5xxServer error500, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout
curl -s -o /dev/null -w '%{http_code}\n' https://example.com/missing    # 404

The first digit is what clients and monitors key on. 4xx means 'you can fix this by changing the request', and 5xx means 'the server failed', which is often worth retrying.

§3Codes That Get Confused

  • 401 vs. 403: 401 means 'not authenticated' (no or bad credentials); 403 means 'authenticated, but not allowed'
  • 301 vs. 302: 301 is permanent and may be cached forever; 302 is temporary. Use 307 and 308 when the method must be preserved on redirect
  • 200 vs. 201 vs. 204: 201 for a created resource, ideally with a Location header; 204 for success with no body
  • 502 vs. 504: 502 means a gateway got an invalid response from upstream; 504 means the upstream took too long

Using codes precisely lets clients react correctly without parsing error text: retry on 503, re-authenticate on 401, give up on 404.

The key insight Methods and status codes are a shared vocabulary. Proxies, caches, browsers, and retry logic act on them without understanding your application, so using them correctly is how your service plays well with all of those.

§4Common Mistakes

MistakeWhat HappensFix
Returning 200 with an error message in the bodyMonitors, caches, and clients treat it as successUse the appropriate 4xx or 5xx status code
Using GET for actions that change dataCrawlers, prefetchers, and caches trigger it unintentionallyUse POST, PUT, or DELETE for state changes
Retrying non-idempotent requests blindlyDuplicate orders or chargesRetry only idempotent methods, or use idempotency keys
Practice
  1. For each scenario, choose the method and status code: creating a user, deleting a user who doesn't exist, a logged-in user reading another user's private data.
  2. Use curl -I on three URLs and explain each status code you receive.
Key takeaways
  • Methods describe intent; safe and idempotent properties determine what may be cached or retried.
  • Status classes: 2xx success, 3xx redirect, 4xx client error, 5xx server error.
  • Use precise codes, such as 401 vs. 403 and 502 vs. 504, so that clients can react automatically.
