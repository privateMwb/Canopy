DNS: Turning Names into Addresses

DNS is a distributed, cached database that maps names people use to the addresses networks need.

§1The Hierarchy

DNS names read right to left through a tree. For www.example.com: the root, then com, then example, then www. No single server knows everything. Instead, responsibility is delegated: root servers know who runs each top-level domain, TLD servers know who runs each domain, and an authoritative server holds the actual records for a zone.

Your device doesn't walk this tree itself. It asks a recursive resolver, usually run by your ISP or a public service, which does the work and caches the answer.

dig example.com                  # ask your resolver; look at ANSWER and Query time
dig +trace example.com           # follow the delegation from the root down
dig @8.8.8.8 example.com         # ask a specific resolver

§2Record Types

TypeMapsExample use

TXTName → textSPF, domain verification

A name can't have a CNAME alongside other records, which is why you can't normally put a CNAME at a bare domain such as example.com.

§3Caching and TTL

Each record carries a TTL, the number of seconds it may be cached. Caching happens in the browser, the OS, and the resolver, so most lookups never reach an authoritative server. The trade-off: a long TTL reduces load and speeds lookups, but changes propagate slowly, because old answers remain cached until they expire.

dig +noall +answer example.com
# example.com.  3600  IN  A  93.184.215.14     <- 3600 = TTL in seconds

DNS normally uses UDP port 53 because the question and answer are small, falling back to TCP for large responses. A lookup is usually the first step before any connection, so a slow resolver slows everything.

The key insight 'It's always DNS' is a joke for a reason. A stale cache, a wrong record, or an unreachable resolver makes a healthy service look down. Test name resolution separately from connectivity.

§4Common Mistakes

Practice
  1. Use dig +trace on a domain and list each server asked in order, from root to authoritative.
  2. Run dig twice on the same name and compare the TTL and query time. Explain the difference.
Key takeaways
  • DNS is a delegated hierarchy; a recursive resolver does the lookups and caches results.
  • Common record types are A, AAAA, CNAME, MX, TXT, and NS.
  • TTL controls how long answers are cached, trading change speed for load and latency.
