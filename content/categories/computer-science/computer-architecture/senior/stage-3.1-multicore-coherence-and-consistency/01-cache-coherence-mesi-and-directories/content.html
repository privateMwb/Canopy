Cache Coherence: MESI & Directories

Each core has private caches, so the hardware must make sure that two cores never see different values for the same memory location, and it does so one cache line at a time.

§1The Coherence Problem

If core A and core B both cache the line holding a variable x, and A writes to x, B's copy is now stale. Without a protocol, B could keep reading the old value forever. A cache coherence protocol guarantees that all cores agree on the value of any single memory location, so programs see a consistent memory.

Coherence works on whole cache lines (64 bytes), not individual variables. This is the root of both its correctness and its performance quirks.

§2The MESI Protocol

Each line in each cache is in one of four states.

StateMeaningCan read?Can write?
Modified (M)This cache has the only copy, and it differs from memoryYesYes
Exclusive (E)This cache has the only copy, identical to memoryYesYes (silently becomes M)
Shared (S)Several caches may hold identical copiesYesNo: must first invalidate others
Invalid (I)The line is not valid hereNoNo
Event                         Core A   Core B   What happened
-----------------------------------------------------------------------
A reads X                      E        I       no other copies: Exclusive
B reads X                      S        S       both now share a clean copy
A writes X                     M        I       A invalidates B's copy first
B reads X                      S        S       A supplies the data (and writes it back); both Shared

A write to a Shared line needs a read-for-ownership (RFO) or invalidate message, so that every other copy is invalidated before the write proceeds. Variants exist: AMD uses MOESI, which adds an *Owned* state so a dirty line can be shared without writing it to memory first, and Intel uses MESIF, adding a *Forward* state so exactly one sharer responds to requests.

§3Snooping vs. Directories

  • Snooping: every cache watches a shared bus or ring and reacts to other cores' requests. Simple and low latency for a few cores, but broadcast traffic grows with core count
  • Directory-based: a directory records which caches hold each line, so messages go point-to-point only to the cores involved. It scales to many cores and multiple sockets, at the cost of extra lookups

Real chips combine them: the shared L3 often keeps a snoop filter or directory that tracks which private caches hold each line, so requests aren't broadcast to every core. Across sockets, directory-style protocols carry the traffic over the interconnect.

# Coherence is invisible to your code, but its effects show up in counters:
perf stat -e cache-misses,cache-references ./prog
# See also 'perf c2c', covered in the next lesson, which attributes contended lines.

It's worth separating two ideas that are often confused. Coherence is about the order of writes to a *single location*. Consistency, covered shortly, is about the order of accesses to *different locations*.

The key insight Coherence makes private caches behave like one shared memory, at the cost of moving ownership of a line between cores every time it is written. Any data written by one core and read by another pays for that transfer.

§4Common Mistakes

MistakeWhat HappensFix
Assuming coherence makes sharing freeEach handoff of a modified line costs a cache-to-cache transferMinimize writes to shared data
Confusing coherence with consistencyExpecting coherent caches to order writes to different variablesCoherence is per location; ordering across locations is the memory model
Reasoning about sharing in bytesThe hardware tracks 64-byte linesThink about which variables share a line
Practice
  1. Trace the MESI states of one line on three cores for: core 0 reads, core 1 reads, core 2 writes, core 0 reads.
  2. Explain why a store to a line in the Shared state is slower than a store to a line in the Modified state.
Key takeaways
  • Coherence keeps all cores' views of each memory location consistent, per cache line.
  • MESI's Modified, Exclusive, Shared, and Invalid states govern who may read or write a line.
  • Snooping broadcasts and suits few cores; directories track sharers and scale to many.
