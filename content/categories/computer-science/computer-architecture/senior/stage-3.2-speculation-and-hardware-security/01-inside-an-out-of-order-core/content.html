Inside an Out-of-Order Core

A modern core is a pipeline of specialized stages, a front end that supplies instructions and a back end that executes them, and its bottleneck can sit in either half.

§1Front End and Back End

FRONT END                          BACK END
fetch -> branch predictor          rename / allocate -> scheduler -> execution ports
      -> decode (-> uop cache)                                    -> load/store units
      -> queue of micro-ops   ------>   reorder buffer  <---- results ----> retire
  • Fetch and predict: reads instruction bytes from the L1 instruction cache, guided by the branch predictor to know where to go next
  • Decode: converts instructions, especially complex x86 ones, into simple internal micro-operations (uops). A uop cache keeps already decoded uops, skipping the decoders for hot loops
  • Rename and allocate: assigns physical registers and reorder-buffer slots, a few uops per cycle (4 to 8 on current designs, which is the machine's width)
  • Scheduler: holds uops until their operands are ready, then sends them to a free execution port
  • Execution units: integer ALUs, address-generation units for loads and stores, floating-point and vector units, and branch units
  • Retire: commits completed uops in program order

§2Latency and Throughput of Instructions

Each instruction type has a latency (cycles from inputs ready to result ready) and a throughput (how many can start per cycle), set by how many suitable units there are.

OperationTypical latency (cycles)Typical throughput (per cycle)
Integer add13–4
64-bit integer multiply31
Integer divide (64-bit)About 10–40, varies by CPUWell below 1
FP add3–42
FP fused multiply-add42
L1 load4–52–3
Branch (predicted)11–2

These are approximate figures for recent x86 cores, and exact numbers vary by microarchitecture. Accurate tables are published by Agner Fog and at uops.info. Division is a classic trap: it is much slower than other arithmetic, so dividing by a constant or by a power of two is optimized by compilers into multiplies and shifts.

The final stage of this course turns this classification into a method, top-down analysis, which attributes lost cycles to exactly these categories.

The key insight A core can be limited by supply of instructions, by the speed of its execution units, by waiting for data, or by wasted speculation. Which one it is determines what to fix.

§4Common Mistakes

MistakeWhat HappensFix
Treating all instructions as one cycleDivision and other long-latency operations dominate unexpectedlyLook up latency and throughput for the operations in your hot loop
Ignoring code sizeLarge hot code overflows the instruction cache or uop cacheKeep hot paths compact, and be wary of aggressive inlining and unrolling
Assuming IPC can reach machine widthDependencies and misses keep it far lowerUse counters to see which category leaks cycles
Practice
  1. Look up the latency and throughput of integer divide and multiply for a CPU you use, and estimate the cost difference.
  2. Classify each: a loop of dependent FP adds, a function with random branches, a scan of a huge array. Which of the five bottleneck types fits?
Key takeaways
  • The front end supplies uops and the back end renames, schedules, executes, and retires them.
  • Each operation has a latency and a throughput; division and dependent chains are slow.
  • Bottlenecks are front-end bound, back-end bound (memory or core), bad speculation, or retiring.
