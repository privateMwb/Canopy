Power, Frequency & the End of Free Speedups

Clock rates stopped climbing around 2005 because power and heat grew faster than speed, and that single constraint explains why modern chips add cores instead of gigahertz.

§1Why Power Limits Speed

A chip's dynamic power is roughly proportional to capacitance × voltage² × frequency. To run faster, the supply voltage generally has to rise as well, so power grows far faster than frequency, close to its cube over a useful range.

P  ~  C * V^2 * f          # dynamic power
raising f usually requires raising V, so P grows roughly like f^3

# Lower both voltage and frequency by 15%:
power = 0.85^3 = 0.61  ->  39% less power for 15% less speed

A chip's heat has to be removed, and there's a limit to how much a small piece of silicon can dissipate, on the order of 100 watts per square centimeter before cooling becomes impractical. That is the power wall.

§2The Turn to Multicore

For decades, Dennard scaling let each shrink in transistor size cut voltage so that power per area stayed roughly constant, and clocks rose with every generation. Around the mid-2000s, voltage scaling stalled, leakage grew, and clock rates plateaued near 3 to 5 GHz. Designers responded by spending the extra transistors on more cores instead.

# One core at full speed vs. two cores at 85% speed (illustrative, ideal parallel work)
one core,  100% freq:  performance 1.00,  power 1.00
two cores,  85% freq:  performance 1.70,  power 2 * 0.61 = 1.23

Two slower cores beat one fast core on throughput for the same rough power, if the work parallelizes. This is the engine behind today's many-core CPUs, and it is why Amdahl's law now matters for every programmer.

§3What Modern Chips Do About It

  • Dynamic frequency and voltage scaling: cores speed up when few are busy, and slow down when many are, to stay within a power budget (turbo boost)
  • Thermal throttling: if temperature rises too high, the chip lowers its clock, so sustained performance can be below burst performance
  • Dark silicon: not every transistor can be active at once within the power budget, so chips use heterogeneous parts that are switched on only when needed
  • Specialization: efficient accelerators for common tasks, such as video, cryptography, and machine learning, which do far more per watt than a general core
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq     # current clock of core 0, in kHz
grep MHz /proc/cpuinfo | head                                  # clock of each core
sensors                                                        # temperatures, if lm-sensors is installed

The consequence for software: single-thread speed now improves slowly, mostly through better IPC. Faster programs now require parallelism, better locality, and sometimes specialized hardware.

The key insight Performance used to arrive for free with each chip generation. Now it has to be earned: by exposing parallelism, using the memory hierarchy well, and matching work to hardware.

§4Common Mistakes

MistakeWhat HappensFix
Expecting next year's CPU to run single-threaded code much fasterClock rates have been flat for about two decadesPlan on parallelism and efficiency, not clock gains
Benchmarking only short burstsTurbo clocks inflate results that sustained load can't holdMeasure at steady state, including thermal behavior
Treating all cores as equally availablePower budgets and heterogeneity change per-core speedCheck the real clock under your actual load
Practice
  1. Run an all-core CPU stress test and watch /proc/cpuinfo MHz fall as load rises. Compare with a single-core test.
  2. If voltage must scale linearly with frequency, what is the power ratio for a core run at 70% frequency?
Key takeaways
  • Dynamic power grows roughly with f³, so higher clocks quickly become unaffordable.
  • The power wall ended clock scaling around 2005 and drove the move to multicore and specialization.
  • Software now has to supply parallelism and locality, since single-thread gains are modest.
