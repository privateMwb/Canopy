RISC vs. CISC: x86-64, ARM & RISC-V

Instruction sets differ in how much each instruction does, but a modern x86 core and an ARM core look much more alike inside than their instruction sets suggest.

§1Two Design Philosophies

RISCCISC
Instruction lengthFixed (such as 32 bits)Variable (x86: 1 to 15 bytes)
Memory accessOnly through load and storeMany instructions take memory operands
Instruction complexitySimple, one small operationSome do several steps
RegistersMany general-purposeHistorically fewer
Decode hardwareSimpleMore complex
ExamplesARM, RISC-V, MIPSx86, x86-64

The RISC idea, from the 1980s, was that simple, regular instructions are easy to decode and pipeline, and that compilers can use them well. CISC dates from the era when memory was scarce and dense instructions saved space.

§2The Families You'll Meet

  • x86-64 (Intel and AMD): the desktop and server standard for decades. It has 16 general-purpose 64-bit registers and a huge, backward-compatible instruction set
  • ARM (AArch64): 31 general-purpose 64-bit registers and fixed 32-bit instructions. It dominates phones and is now in laptops (Apple silicon) and servers
  • RISC-V: an open ISA, free to implement without licensing, with a small base set and optional extensions, such as M (multiply and divide), F and D (floating point), C (compressed instructions), and V (vectors)

An ISA (instruction set architecture) is the contract between software and hardware: the instructions, registers, and memory model that programs can rely on. A microarchitecture is a particular way of building a chip that implements an ISA. Many different designs implement x86-64, from low-power cores to server chips.

§3The Line Has Blurred

Modern x86 cores decode complex instructions into simpler internal micro-operations (uops) and run those on an RISC-like out-of-order engine. So the CISC–RISC difference matters mostly at the decoder and for code density, and much less for peak performance.

# Check what your machine reports
uname -m                 # x86_64, aarch64, riscv64
lscpu | head -20         # model, cores, cache sizes, supported instruction extensions
grep -m1 flags /proc/cpuinfo    # x86 feature flags such as avx2, avx512f

ISA choices still matter in practice: software ecosystem (what runs natively), power efficiency, licensing, and extension availability, such as which SIMD widths are present. A program must be compiled for its target ISA, and a fast x86 binary may not run at all on an ARM board.

The key insight The ISA defines what software sees, and the microarchitecture decides how fast it runs. Two chips with the same ISA can differ enormously in speed, and two with different ISAs can perform similarly.

§4Common Mistakes

MistakeWhat HappensFix
Treating 'RISC is faster' as a ruleModern cores of both types decode into internal operationsCompare actual chips on actual workloads
Assuming a binary is portable across ISAsIt fails to run, or runs only under emulationBuild for each target, or use multi-arch packaging
Equating ISA with performanceMicroarchitecture, caches, and process technology dominateLook at measured results, not instruction set names
Practice
  1. Run uname -m and lscpu on two machines you have. List the ISA and notable extensions for each.
  2. Compile the same function for x86-64 and for RISC-V (or ARM) on Compiler Explorer, and compare the instruction counts.
Key takeaways
  • RISC favors fixed-size, simple, register-based instructions; CISC allows variable, richer ones.
  • x86-64, ARM, and RISC-V are the main ISAs, and RISC-V is open and modular.
  • Modern x86 cores translate to internal micro-ops, so the practical gap is smaller than the labels suggest.
