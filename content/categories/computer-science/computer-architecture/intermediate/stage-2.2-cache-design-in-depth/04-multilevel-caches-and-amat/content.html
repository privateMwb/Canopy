Multilevel Caches & AMAT

Real CPUs stack several caches, and the average access time across levels is computed by nesting the same formula once per level.

§1Why Several Levels

A single cache can't be both large enough to hold the working set and fast enough to answer in a cycle or two, because a larger memory array has longer wires and more delay. So CPUs use a hierarchy: a tiny, fast L1, a larger, slower L2, and a bigger, shared L3.

LevelTypical sizeHit latencyScope
L1 (split I and D)32–64 KiB3–5 cyclesPer core
L2256 KiB–2 MiB12–15 cyclesPer core (or shared by a few)
L3 (last-level cache)Several to tens of MiB40–60 cyclesShared across cores

Each level filters accesses for the next. If L1 hits 95% of the time, L2 sees only 5% of accesses, and so on.

§2Computing AMAT Across Levels

Nest the formula: the miss penalty of one level is the AMAT of the level below it.

AMAT = L1 hit time + L1 miss rate * (L2 hit time + L2 local miss rate * DRAM time)

# L1: 4 cycles, 5% miss. L2: 14 cycles, 20% of the accesses it receives miss. DRAM: 200 cycles.
AMAT = 4 + 0.05 * (14 + 0.20 * 200)
     = 4 + 0.05 * (14 + 40)
     = 4 + 2.7
     = 6.7 cycles

The local miss rate is misses per access *to that level*. The global miss rate is misses per access *from the CPU*. Here, L2's global miss rate is 0.05 × 0.20 = 1%. Without the L2, AMAT would be 4 + 0.05 × 200 = 14 cycles, so the L2 more than halves it.

§3Design Choices and Reading Your Own CPU

  • Inclusive caches keep every line of an inner level also in the outer one, which simplifies coherence but wastes capacity
  • Exclusive caches keep each line in one level only, saving space
  • Non-inclusive (NINE) designs, common today, make no guarantee either way
  • Shared L3 lets one core use all of it when others are idle, but cores compete when all are busy
  • Victim caches hold recently evicted lines, cheaply catching conflict misses
lscpu | grep -E 'L1d|L1i|L2|L3'
lscpu -C                                 # sizes, ways, sets, and sharing
perf stat -e L1-dcache-load-misses,LLC-load-misses ./prog

Because L3 is shared, a program's cache performance can depend on what its neighbors are doing. A noisy neighbor thrashing the L3 will slow others, which is a common reason benchmarks vary on shared servers.

The key insight Each cache level exists to absorb the misses of the one above it. Judge a level by how much it cuts the AMAT, not by its hit rate in isolation.

§4Common Mistakes

MistakeWhat HappensFix
Confusing local and global miss ratesL2 looks terrible (20% miss) even though only 1% of accesses reach DRAMState which denominator you are using
Assuming L3 is privateSharing means contention from other coresTest under realistic co-running load
Quoting hit rates without the miss penaltyThey hide cost differences between levelsUse AMAT to combine hit time, rate, and penalty
Practice
  1. Compute AMAT for L1 3 cycles, 4% miss; L2 12 cycles, 25% local miss; DRAM 180 cycles.
  2. What is L2's global miss rate in the previous exercise, and what fraction of accesses reaches DRAM?
Key takeaways
  • Several cache levels exist because size and speed trade off.
  • AMAT nests: each level's miss penalty is the AMAT of the next level.
  • Local miss rate counts per level's accesses; global counts per CPU access.
