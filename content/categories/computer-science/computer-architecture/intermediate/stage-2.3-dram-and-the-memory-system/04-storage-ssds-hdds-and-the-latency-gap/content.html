Storage: SSDs, HDDs & the Latency Gap

Below DRAM, storage is about a thousand times slower, and the physics of flash and spinning disks explains both their numbers and their odd behaviors.

§1Spinning Disks

A hard disk reads data from a spinning platter using a moving head. Reaching a random location costs a seek (moving the head, about 3 to 10 ms) plus rotational latency, the wait for the data to pass under the head. At 7,200 RPM, a full rotation takes 8.33 ms, so the average rotational wait is half that, about 4.2 ms.

7200 RPM = 120 rotations/s -> 8.33 ms per rotation -> average wait 4.17 ms
random read  = seek (~4-9 ms) + rotation (~4 ms) = roughly 8-13 ms
sequential   = 100-250 MB/s once the head is positioned

# So random 4 KiB reads give only ~100 IOPS, while sequential reads stream fast.

Hard disks reward sequential access heavily, which shaped decades of storage design, from log-structured writes to B-trees laid out for large blocks.

§2Flash and SSDs

An SSD stores data in NAND flash cells, with no moving parts. Reads are fast, around 20 to 100 microseconds, but flash has quirks.

  • Pages and blocks: data is read and written in pages (4 to 16 KiB), but erased only in whole blocks of hundreds of pages. You can't overwrite in place
  • Flash translation layer (FTL): the SSD's controller maps logical addresses to physical pages, redirecting each write to a fresh page and cleaning up old ones later
  • Garbage collection and write amplification: moving live data to free blocks means the SSD writes more internally than the host asked for
  • Wear: each cell survives a limited number of erase cycles, from a few hundred to a few thousand depending on type, so SSDs spread writes and publish endurance ratings (TBW)
  • Parallelism: many flash chips and channels work at once, so SSDs reach full speed only with many requests in flight (high queue depth)

§3The Latency Gap and Living With It

DRAM is about 100 ns and an NVMe read about 50 µs: a factor of roughly 500 to 1,000. The OS hides much of this with the page cache, keeping recently used file data in DRAM, so repeated reads are served from memory.

fio --name=randread --rw=randread --bs=4k --iodepth=32 --size=1G --runtime=10 --time_based
# Shows IOPS and latency percentiles for random reads at queue depth 32
iostat -x 1                     # utilization, queue depth, and await times per device
free -h                         # 'buff/cache' is file data held in DRAM
  • Writes need durability: fsync forces data to the device, and it is much slower than a cached write
  • Batch and queue: issue many I/Os at once so the SSD's parallelism is used
  • Keep hot data in memory, and design for sequential access where possible, even on SSDs
  • Expect tail latencies: garbage collection can make occasional operations far slower than the average

The gap between DRAM and storage is the same hierarchy idea as before, one level further down, and the same principles of locality, batching, and caching apply.

The key insight Storage speed depends on both the technology and how you use it. A hard disk is 100 times worse at random than sequential access, while an SSD is fast at random access only if you keep many requests in flight.

§4Common Mistakes

Assuming an SSD overwrites in placeMisreading write behavior and wearRemember pages, blocks, the FTL, and write amplification
Testing an SSD with one request at a timeThroughput looks far below the specificationMeasure with realistic queue depths
Treating write() as durableData may be lost on a crashUse fsync (or equivalent) where durability is needed
Practice
  1. Compute the average rotational latency of a 15,000 RPM disk.
  2. Run fio random reads at queue depths 1 and 32 on an SSD and explain the difference in IOPS.
Key takeaways
  • Hard disks pay seek and rotational latency, so random access is about 100 times slower than sequential.
  • SSDs read fast but erase by block, using an FTL, garbage collection, and wear leveling.
  • NVMe parallelism needs high queue depth; the page cache hides much of the DRAM-to-storage gap.
