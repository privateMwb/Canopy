DRAM: Rows, Banks & Refresh

Main memory is built from tiny leaky capacitors organized in rows, and the way you access them, within an open row or not, changes the speed of each access.

§1How a DRAM Cell Works

A DRAM bit is a single transistor and a capacitor: charged means 1, discharged means 0. It's dense and cheap, which is why gigabytes fit on a module, but the charge leaks away within milliseconds. So the memory controller must refresh every row regularly, standardly within a 64 ms window, by reading and rewriting it. SRAM, used in caches, stores each bit in about six transistors that hold their value without refresh, so it is faster and far larger per bit.

Refresh isn't free. While a row is refreshing it can't be read, which adds occasional latency spikes and a small bandwidth tax.

§2Channels, Banks, Rows, and the Row Buffer

channel -> DIMM -> rank -> chip -> bank -> row x column

# A bank is a 2D array. Reading a bit means:
1. ACTIVATE  open a whole row: copy it into the bank's row buffer     (tRCD)
2. READ      pick the wanted columns from the row buffer              (CL)
3. PRECHARGE close the row so another can be opened                   (tRP)

The row buffer (sense amplifiers) holds the whole open row, around 8 KiB across a rank. Accessing another column of an already-open row is a row hit and is fast. Accessing a different row requires closing the old one and opening the new, which is a row conflict.

CaseWhat happensDDR4-3200 CL22 example
Row hitColumn read onlyAbout 14 ns (CL)
Row empty (bank idle)ACTIVATE then readAbout 28 ns (tRCD + CL)
Row conflictPRECHARGE, ACTIVATE, readAbout 41 ns (tRP + tRCD + CL)

At a 1,600 MHz memory clock, 22 cycles is 13.75 ns, so CL, tRCD, and tRP each cost about 14 ns. The total latency a CPU sees, around 70 to 100 ns, adds the cache lookups, the memory controller queue, and the trip across the bus.

§3What This Means for Programs

  • Sequential access stays inside open rows, so it is mostly row hits, and it benefits from the full bandwidth
  • Random access opens a new row nearly every time, so it pays the longer row-miss latency
  • Banks work in parallel: a controller can open a row in one bank while reading from another, so spreading accesses across banks keeps the bus busy
  • Controllers reorder requests to favor row hits, while keeping fairness
sudo dmidecode -t memory | grep -E 'Type:|Speed|Size'      # DIMM type, speed, and sizes
sudo lshw -class memory                                       # more detail

Frequently seen labels such as DDR4-3200 CL16 describe data rate (3200 mega-transfers per second) and CAS latency in memory-clock cycles. A higher data rate with a proportionally higher CL gives the same absolute latency but more bandwidth.

The key insight DRAM is fastest when you stay in the row you opened. The row buffer is a small cache inside the memory, which is why access pattern matters even below the CPU's caches.

§4Common Mistakes

Assuming DRAM latency is constantIt varies several-fold with row hit or conflict, and queueingThink of access pattern, not a single latency number
Comparing memory by data rate aloneCL changes absolute latencyCompare CAS latency in nanoseconds (CL / clock) as well as MT/s
Ignoring refresh in tail latencyOccasional stalls appear in precise timingExpect small periodic delays on any DRAM system
Practice
  1. Convert DDR5-4800 CL40 to an absolute CAS latency in nanoseconds. (Memory clock is half the data rate.)
  2. Explain why scanning a 1 GiB array sequentially is faster per byte than reading 1 GiB at random 64-byte locations.
Key takeaways
  • DRAM cells leak and need refresh; caches use faster, larger SRAM instead.
  • Accesses to an open row are fast, and row conflicts add precharge and activate time.
  • Sequential patterns get row hits and bank parallelism, while random patterns pay more per access.
