Control Hazards & Branch Prediction

A branch's outcome isn't known until the pipeline has already fetched the instructions after it, so CPUs guess, and the quality of the guess decides performance.

§1The Control Hazard

When the CPU fetches a branch, it doesn't yet know whether the branch will be taken, nor where to. By the time the condition is evaluated in EX, the pipeline has already fetched the next few instructions, which may be the wrong ones.

beq x1, x2, target   IF  ID  EX  ...          # outcome known here, in EX
next1                    IF  ID  ...           # fetched speculatively: right or wrong?
next2                        IF  ...

If the guess was wrong, those instructions must be flushed, and fetching restarts from the correct address. In a 5-stage pipe the loss is a couple of cycles. In a modern deep, wide core, a misprediction penalty of 15 to 20 cycles is typical, during which several instructions per cycle of work is thrown away.

§2Predicting Branches

Static prediction uses a fixed rule, such as 'backward branches are taken (loops), forward branches are not'. Dynamic prediction learns from history.

A simple dynamic design is a table of 2-bit saturating counters, indexed by the branch's address. The counter moves up on taken and down on not-taken, and its top bit gives the prediction.

StatePredictionAfter 'taken'After 'not taken'
Strongly not-taken (00)Not takenWeakly not-takenStrongly not-taken
Weakly not-taken (01)Not takenWeakly takenStrongly not-taken
Weakly taken (10)TakenStrongly takenWeakly not-taken
Strongly taken (11)TakenStrongly takenWeakly taken

The two-bit design needs two wrong outcomes in a row to flip its prediction. For a loop branch that is taken nine times then not taken once, a one-bit predictor would mispredict twice per loop run, while the two-bit counter mispredicts only on the exit.

§3Beyond Simple Counters

  • Global history predictors look at the outcomes of recent branches, not just this one, and catch correlated patterns such as 'if A was taken then B is taken'
  • Modern predictors (TAGE-style and perceptron-based designs) combine several history lengths and reach accuracy well above 95% on many programs
  • Branch target buffer (BTB): caches the target address of taken branches, so the front end can redirect fetch without waiting for decode
  • Return address stack: predicts the target of ret using a stack of return addresses pushed by calls
perf stat -e branches,branch-misses ./prog
#   branch-misses / branches = misprediction rate

Mispredictions cost roughly misses × penalty cycles. At a 1% misprediction rate with one branch per five instructions and an 18-cycle penalty, that adds about 0.036 cycles per instruction, which is noticeable on a core that otherwise reaches an IPC near 3.

The key insight The CPU doesn't wait for branches; it bets on them. Predictable branches cost almost nothing, and unpredictable ones can cost a 15 to 20 cycle flush every time.

§4Common Mistakes

MistakeWhat HappensFix
Ignoring data-dependent branches in hot loopsRandom outcomes defeat the predictorMake branches predictable, or replace them with branchless code
Assuming all branches cost the sameWell-predicted branches are nearly free, mispredicted ones are very expensiveMeasure the misprediction rate, not just the branch count
Over-unrolling or inlining without checkingCode growth can hurt the instruction cache and BTBBenchmark the changes
Practice
  1. Trace a 2-bit counter, starting at strongly not-taken, through the outcomes T T T N T T T N, and count mispredictions.
  2. For a loop that runs 8 iterations each time it is entered, how many mispredictions per entry would a 1-bit and a 2-bit predictor make?
Key takeaways
  • Branches resolve after later instructions are already fetched, so CPUs predict them.
  • A misprediction flushes the pipeline and costs about 15 to 20 cycles on modern cores.
  • Dynamic predictors learn per-branch and global history, and typical accuracy exceeds 95%.
