The Five-Stage Pipeline

Pipelining overlaps the steps of different instructions like an assembly line, so a CPU can finish about one instruction every cycle even though each one takes several.

§1Splitting an Instruction Into Stages

In the classic RISC design, executing an instruction is split into five stages, each taking one clock cycle:

StageNameWork done
IFInstruction fetchRead the instruction at the PC
IDDecode / register readDecode and read source registers
EXExecuteALU operation or address calculation
MEMMemory accessLoad or store data
WBWrite backWrite the result to a register

Without pipelining, the CPU would finish all five stages for one instruction before starting the next. With pipelining, as soon as an instruction moves from IF to ID, the next instruction enters IF.

§2The Pipeline Diagram

cycle:       1    2    3    4    5    6    7    8
instr 1:    IF   ID   EX   MEM  WB
instr 2:         IF   ID   EX   MEM  WB
instr 3:              IF   ID   EX   MEM  WB
instr 4:                   IF   ID   EX   MEM  WB
# From cycle 5 on, one instruction completes every cycle.

Each instruction still takes 5 cycles from start to finish. Its latency is unchanged. But the throughput rises to nearly one instruction per cycle, so for 100 instructions the pipelined machine needs about 5 + 99 = 104 cycles instead of 500, a speedup of about 4.8×. In the ideal case, the speedup approaches the number of stages.

§3What Limits the Pipeline

  • Clock speed is set by the slowest stage. Balanced stages let the clock run as fast as the longest one allows. Splitting stages further, a deeper pipeline, allows a faster clock
  • Pipeline registers between stages hold each instruction's in-flight state, adding a small overhead per stage
  • Hazards disrupt the ideal flow, and a deeper pipeline pays more for each one
  • Diminishing returns: Intel's Pentium 4 used 20 to 31 stages to chase clock rate and lost efficiency to hazards and power, and later designs settled on roughly 14 to 20 stages

Real CPUs are far more complex than five stages, but this model captures why they overlap work and what can go wrong.

The key insight Pipelining improves throughput, not latency. It works because stages are independent hardware, and it breaks down whenever one instruction needs something another hasn't finished producing.

§4Common Mistakes

MistakeWhat HappensFix
Believing a pipeline makes each instruction fasterSingle-instruction latency stays the same or grows slightlyPipelining raises the rate of completion, not individual time
Assuming ideal speedup equals the stage count in practiceHazards and stalls reduce itAccount for stall cycles in CPI
Making the pipeline arbitrarily deepEach hazard costs more cycles, and power risesBalance clock gains against misprediction and stall penalties
Practice
  1. For a 5-stage pipeline running 1,000 independent instructions, compute total cycles and the speedup over a non-pipelined machine that takes 5 cycles each.
  2. Draw the pipeline diagram for four instructions and mark which stage each is in during cycle 5.
Key takeaways
  • A five-stage pipeline overlaps IF, ID, EX, MEM, and WB of consecutive instructions.
  • Throughput approaches one instruction per cycle, while per-instruction latency is unchanged.
  • The slowest stage sets the clock, and hazards reduce the ideal gain.
