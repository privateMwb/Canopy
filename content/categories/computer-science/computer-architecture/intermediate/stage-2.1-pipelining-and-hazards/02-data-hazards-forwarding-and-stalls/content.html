Data Hazards, Forwarding & Stalls

When an instruction needs a result that an earlier one hasn't produced yet, the pipeline must wait or shortcut, and the shortcut is a key piece of CPU design.

§1The Read-After-Write Hazard

A data hazard occurs when instructions depend on one another's results. The common case is read-after-write (RAW): the second instruction reads a register that the first writes.

add x1, x2, x3        # writes x1
sub x4, x1, x5        # reads x1: depends on the add

In the pipeline, add writes x1 in its WB stage (cycle 5), but sub wants to read x1 in its ID stage (cycle 3). Without any fix, sub would read a stale value.

§2Stalling vs. Forwarding

The simplest fix is to stall: hold sub in place until add has written back.

# Without forwarding: the dependent instruction waits (stalls) for the write-back
add x1,x2,x3   IF  ID  EX  MEM WB
sub x4,x1,x5       IF  --  --  ID  EX  MEM WB       # two stall cycles

Better is forwarding (also called bypassing): the value exists at the end of add's EX stage, so extra wires route the ALU output directly to the input of the next instruction's EX stage, without waiting for write-back.

# With forwarding: no stall for back-to-back ALU instructions
add x1,x2,x3   IF  ID  EX  MEM WB
sub x4,x1,x5       IF  ID  EX  MEM WB             # x1 forwarded from add's EX output

§3The Load-Use Hazard

Forwarding can't fix everything. A load's data isn't available until the end of its MEM stage, one cycle later than an ALU result.

lw  x1, 0(x2)  IF  ID  EX  MEM WB
add x3, x1, x4     IF  ID  --  EX  MEM WB         # one unavoidable stall: data arrives after MEM

This load-use hazard costs one stall cycle even with full forwarding. Compilers reduce the penalty with instruction scheduling: placing an independent instruction between the load and its use so the slot isn't wasted.

# Before scheduling: stalls          # After: independent work fills the gap
lw  x1, 0(x2)                          lw  x1, 0(x2)
add x3, x1, x4    (1 stall)          addi x6, x6, 1        # independent instruction
addi x6, x6, 1                         add x3, x1, x4       # x1 is ready, no stall

In out-of-order CPUs, later lessons show hardware does this reordering dynamically, which hides many such hazards automatically.

The key insight Forwarding turns most data hazards into no-ops, but a dependency chain still limits how fast a sequence can run. Long chains of dependent instructions are the pipeline's enemy.

§4Common Mistakes

MistakeWhat HappensFix
Ignoring dependency chains in tight loopsA serial chain runs at the latency of each operation, not the throughputBreak long chains with independent work or multiple accumulators
Assuming forwarding removes all stallsLoads still cost a cycle on useSchedule independent work after loads
Forgetting that deeper pipelines lengthen stallsMore stages means more cycles per hazardWeigh frequency gains against hazard penalties
Practice
  1. Draw pipeline diagrams for lw x1,0(x2); add x3,x1,x4; sub x5,x3,x6 with full forwarding, and count the stall cycles.
  2. Reorder a short instruction sequence of your own to remove a load-use stall without changing its result.
Key takeaways
  • RAW hazards occur when an instruction needs an earlier instruction's result.
  • Forwarding passes results directly between stages and removes most stalls.
  • A load followed immediately by its use still stalls one cycle, and scheduling can hide it.
