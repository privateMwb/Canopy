Coroutines, Generators & Async

Coroutines, generators, and async functions can pause and resume, which a compiler implements by turning the function into a state machine or by capturing its continuation.

§1Suspendable functions

Normal functions run to completion. A coroutine can yield, give control back to its caller, and later resume exactly where it left off, with all its locals intact.

// hypothetical Twig extension
fn count_to(n) {
  let i = 1;
  while (i <= n) {
    yield i;
    i = i + 1;
  }
}

let g = count_to(3);
print next(g);    // 1
print next(g);    // 2

The same mechanism underlies generators (producing a sequence lazily), async/await (pausing while waiting for I/O), and cooperative multitasking.

§2Compiling to a state machine

One implementation strategy needs no special runtime support. The compiler rewrites the function into a state machine: an object holding all locals plus a state number saying where to resume.

fn count_to(n) { ... }     becomes

struct CountTo { state, n, i }

def CountTo.resume(self):
    match self.state:
        0:  self.i = 1; goto loop_check
        1:  self.i = self.i + 1; goto loop_check
    loop_check:
        if self.i <= self.n:
            self.state = 1
            return Yielded(self.i)
        return Done

Locals that live across a yield move from the stack to the object, since the stack frame won't survive. Locals not live across any yield can stay on the stack. Liveness analysis from Stage 2.4 decides which. The transform is mechanical but intricate, especially with loops and try blocks that span yields.

§3Continuations and async

The other strategy is to give the runtime the ability to capture a function's execution state and restore it later.

  • Stackful coroutines: each coroutine gets its own stack, and switching changes the stack pointer. Flexible (any call depth can yield) but costs memory per coroutine.
  • Stackless coroutines: the state machine approach. Cheap, but only the function itself can yield, not its callees.

Async/await is the same transformation applied to I/O. await x means 'suspend until x is ready, and let something else run meanwhile.'

async fn fetch_both(a, b) {
  let x = await get(a);       // suspends here; scheduler runs other tasks
  let y = await get(b);
  return x + y;
}

Each await becomes a state-machine state, and a scheduler (an event loop) resumes the machine when the awaited operation completes. This is how one thread can handle thousands of concurrent connections.

The key insight A suspended function is just data: its locals and where to resume. Whether you store that data in a generated object or a separate stack is the design choice.

§4Common Mistakes

MistakeWhat HappensFix
Keeping a suspended function's locals on the real stackThe frame is gone when the function resumes, and locals read garbageMove locals live across a yield into the state object
Forgetting try/finally across a yieldCleanup runs too early or neverTreat the handler region as part of the saved state
Using stackful coroutines for tens of thousands of tasksStack memory dominatesUse stackless coroutines, or small growable stacks
Practice
  1. Transform the count_to generator into the state-machine form by hand, listing which locals move into the object.
  2. Compare stackful and stackless coroutines for a web server handling 100,000 connections, and say which you'd pick and why.
Key takeaways
  • Suspendable functions pause with their locals intact and resume where they stopped.
  • Stackless coroutines compile to state machines; stackful ones switch stacks.
  • Async/await is the same mechanism driven by an event loop.
