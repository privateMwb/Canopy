Instruction Selection

Instruction selection chooses real machine instructions for each IR operation, and the choice matters because one machine instruction can often do the work of several IR ones.

§1From IR to machine instructions

The IR has operations like add, load, and branch. A real CPU has its own instruction set with its own quirks. Instruction selection maps one to the other. The simplest approach picks one machine instruction per IR instruction.

IR:        t3 = add t1, t2
x86-64:    mov  rax, [t1]
           add  rax, [t2]
           mov  [t3], rax
RISC-V:    add  x5, x6, x7

Even that exposes target differences. x86-64 instructions often overwrite one of their operands and can read memory directly. RISC-V is a load/store design: arithmetic works only on registers.

§2Patterns and addressing modes

Real instruction sets have instructions that fuse several simple operations. Good selection finds them.

IR:      t1 = mul i, 8
         t2 = add base, t1
         t3 = load t2

x86-64:  mov rax, [base + i*8]     # one instruction does mul, add, and load

Compilers represent this as tree pattern matching: each machine instruction is a pattern over IR trees, with a cost, and the selector covers the tree with the cheapest set of patterns.

pattern: Load(Add(base, Mul(index, Const(8))))  →  mov dst, [base + index*8]   cost 1
pattern: Add(a, b)                               →  add dst, a, b               cost 1
pattern: Mul(a, Const(c))                        →  imul dst, a, c              cost 1

A simple greedy selector takes the biggest matching pattern first (maximal munch). Optimal selection uses dynamic programming over the tree. Production compilers often generate their selectors from a declarative description of the target.

§3Constants, comparisons, and branches

Many details are target-specific:

  • Immediates: small constants can sit inside the instruction. Large ones need a separate load, or several instructions to build.
  • Comparisons: x86-64 sets flags, then a conditional jump reads them; RISC-V fuses compare and branch.
  • Division and multiplication: division is slow, so a divide by a constant becomes a multiply and shift; multiplying by a power of two becomes a shift.
IR:       t = div x, 8
x86-64:   sar rax, 3         # only valid for signed values if rounding is handled

Whether that rewrite is correct depends on rounding for negative numbers, so a naive pattern would be a bug. Instruction selection is where the target's exact semantics must be respected.

The key insight Selection is pattern matching with costs. The compiler's job is to cover the IR with the cheapest machine instructions, and the target's quirks decide what 'cheap' means.

§4Common Mistakes

MistakeWhat HappensFix
Emitting one machine instruction per IR instruction alwaysSlow code that misses fused addressing modesMatch larger patterns like address computations first
Assuming signed division by a power of two is just a shiftNegative results round the wrong wayAdd the correction for negative values, or leave it to a divide
Hard-coding the target into the IRAdding a second target means redesigning the IRKeep the IR target-neutral and put target knowledge in the selector
Practice
  1. Write tree patterns and costs for three x86-64 or RISC-V instructions, and use maximal munch to cover load(add(p, mul(i, 4))).
  2. Explain why x / 8 can't be a plain arithmetic shift for negative x, and write the instruction sequence that fixes it.
Key takeaways
  • Instruction selection maps IR operations onto the target's real instructions.
  • Tree-pattern matching with costs finds fused instructions like complex addressing modes.
  • Target semantics, such as rounding and flags, decide which rewrites are correct.
