Compiling the AST to Bytecode

The bytecode compiler walks the AST once, emitting instructions for each node and patching jumps whose targets aren't known yet.

§1Expressions and variables

Expression code generation is a post-order walk: emit the operands, then the operator.

def compile_expr(e):
    match e:
        Literal(v):      emit(PUSH_CONST, constant(v))
        Variable(n):     emit(LOAD_LOCAL, slot_of(n))
        Binary(l, op, r):
            compile_expr(l); compile_expr(r); emit(OP[op])
        Unary(op, x):    compile_expr(x); emit(UNARY_OP[op])
        Assign(n, v):    compile_expr(v); emit(STORE_LOCAL, slot_of(n))

slot_of uses the resolver's work from Stage 2.1. Each local variable gets a stack slot at compile time, so there are no names or environments at run time. A let allocates the next free slot, and leaving a block frees its slots.

§2Jumps and patching

For an if, the compiler must jump over the then branch, but doesn't know how far until it has compiled it. The standard solution is backpatching: emit the jump with a placeholder, remember its address, and fill in the offset afterward.

def compile_if(cond, then, other):
    compile_expr(cond)
    jump_else = emit_jump(JUMP_IF_FALSE)       # placeholder offset
    compile_stmt(then)
    jump_end = emit_jump(JUMP)
    patch_jump(jump_else)                      # else starts here
    if other: compile_stmt(other)
    patch_jump(jump_end)

def patch_jump(at):
    code[at + 1 : at + 3] = write_u16(len(code) - (at + 3))

while jumps backward instead: remember the address of the loop's start, and emit a JUMP back to it at the end of the body.

def compile_while(cond, body):
    top = len(code)
    compile_expr(cond)
    exit_j = emit_jump(JUMP_IF_FALSE)
    compile_stmt(body)
    emit_jump_back(top)
    patch_jump(exit_j)

§3Short-circuit and the stack discipline

            emit(POP)
            compile_expr(r)
            patch_jump(skip)

Every expression must leave exactly one value on the stack, and every statement must leave the stack as it found it. Expression statements end with POP. Keeping that discipline makes the stack depth predictable, so the compiler can compute a maximum depth per function and the VM can allocate it once.

The key insight The compiler does the work the tree-walker did at run time (name lookup, deciding control flow) once, up front. What's left for the VM is a flat loop over instructions.

§4Common Mistakes

MistakeWhat HappensFix
Computing a forward jump's offset before compiling the bodyYou guess wrong, or hard-code a size that breaks laterEmit a placeholder and patch it afterward
Forgetting POP after an expression statementThe stack grows on every statement, and leaks across loop iterationsMake every statement stack-neutral
Measuring jump offsets from the wrong placeJumps land one instruction early or lateDefine offsets relative to the end of the jump instruction and use it consistently
Practice
  1. Write the compiler case for Break, which must jump to the end of the nearest loop; decide how to patch it when the loop's end isn't known yet.
  2. Compile if (a < b) { print a; } else { print b; } by hand into bytecode, showing the jump offsets.
Key takeaways
  • Expression compilation emits operands first and the operator last.
  • Forward jumps are emitted with placeholders and patched when the target is known.
  • Every expression leaves one value, every statement leaves the stack balanced.
