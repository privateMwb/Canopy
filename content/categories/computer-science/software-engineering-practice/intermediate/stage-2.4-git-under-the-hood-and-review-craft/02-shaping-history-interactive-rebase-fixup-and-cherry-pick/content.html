Shaping History: Interactive Rebase, Fixup & Cherry-Pick

Interactive rebase lets you tidy a branch before sharing it: squash noise, reorder steps, and reword messages so the history tells a clear story.

§1Interactive Rebase

git rebase -i opens a to-do list of your commits and lets you decide what happens to each. Edit the list, save, and Git replays the commits with your changes.

git rebase -i HEAD~4          # rewrite the last four commits

pick   a1b2c3 Add retry logic
fixup  d4e5f6 typo
reword 7a8b9c Fix bug
squash 0f1e2d tweak test
drop   3c4d5e debug print
  • pick: keep it as is
  • reword: keep the change, edit the message
  • squash: merge into the previous commit and combine the messages
  • fixup: merge into the previous commit and discard this message
  • drop: delete the commit
  • reorder: move the lines

§2Fixup and Autosquash

A smoother workflow: when you notice a mistake in an earlier commit, record the fix as a fixup of that commit, and let Git place it for you.

git commit --fixup a1b2c3         # tagged to fix commit a1b2c3
git rebase -i --autosquash main   # fixups slide into place automatically

This keeps your working loop fast, since you commit freely, and still leaves a tidy series for reviewers.

§3Cherry-Pick and the Golden Rule

Cherry-pick copies one commit onto another branch as a new commit with the same change. It's the tool for moving a bug fix to a release branch.

git switch release/1.4
git cherry-pick 3f2a1c9       # apply that one fix here

The golden rule of rewriting: never rewrite history that others have pulled. Rebasing your own unpublished branch is safe and encouraged. Rewriting a shared branch forces everyone else to untangle diverged copies. When you must force-push your own pushed branch, use the safer form:

git push --force-with-lease      # refuses if someone else pushed meanwhile
A good workflow Commit freely while you work, then shape the series before opening the pull request. Once reviewers have seen it, add new commits instead of rewriting.

§4Common Mistakes

MistakeWhat HappensFix
Rebasing a branch others are usingTheir copies diverge and merges get messyRewrite only unshared commits; use merge or revert on shared ones
git push --force on a shared branchOverwrites teammates' commitsUse --force-with-lease, and only on your own branches
Squashing everything into one commit by habitLoses useful step-by-step historySquash noise, but keep meaningful logical steps
Practice
  1. Make five messy commits and rewrite them into three clean ones with interactive rebase.
  2. Use --fixup and --autosquash to repair a mistake in an earlier commit.
  3. Cherry-pick a fix from main onto a throwaway release branch.
Key takeaways
  • Interactive rebase reorders, squashes, rewords, and drops commits.
  • Fixup plus autosquash keeps your working loop fast and the history clean.
  • Never rewrite history others have; cherry-pick moves a single change.
