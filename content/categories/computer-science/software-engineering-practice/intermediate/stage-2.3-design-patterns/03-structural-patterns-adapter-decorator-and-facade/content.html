Structural Patterns: Adapter, Decorator & Facade

Structural patterns are about wrapping and composing objects so that incompatible pieces fit together, extra behavior can be added, or a messy subsystem hides behind a clean face.

§1Adapter: Make It Fit

An adapter converts one interface into another that callers expect. It is the pattern to use at the boundary with a third-party library or a legacy API, so your code depends on your own interface, not theirs.

class PaymentGateway:                    # the interface your code wants
    def charge(self, cents, card_token): ...

class StripeAdapter(PaymentGateway):     # hides Stripe's particular API
    def __init__(self, client): self.client = client
    def charge(self, cents, card_token):
        r = self.client.PaymentIntent.create(amount=cents, source=card_token)
        return r["id"]

# switching provider = write another adapter; nothing else changes

§2Decorator: Add Behavior by Wrapping

A decorator wraps an object with the same interface and adds behavior before or after delegating. Because wrappers stack, you can combine features freely without a subclass for every combination.

class LoggingGateway(PaymentGateway):
    def __init__(self, inner): self.inner = inner
    def charge(self, cents, card_token):
        log.info("charging %s", cents)
        return self.inner.charge(cents, card_token)

class RetryingGateway(PaymentGateway):
    def __init__(self, inner): self.inner = inner
    def charge(self, cents, card_token):
        for attempt in range(3):
            try: return self.inner.charge(cents, card_token)
            except TransientError: pass
        raise

gateway = LoggingGateway(RetryingGateway(StripeAdapter(client)))

Python's @decorator syntax is a related language feature that applies the same idea to functions.

§3Facade: One Simple Door

A facade gives a simple interface to a complex subsystem. Callers use one method instead of coordinating five classes.

class Checkout:                        # facade
    def __init__(self, cart, pricing, payments, inventory, mailer): ...
    def place_order(self, user):
        total = self.pricing.total(self.cart)
        self.inventory.reserve(self.cart)
        receipt = self.payments.charge(user, total)
        self.mailer.send_receipt(user, receipt)
        return receipt

checkout.place_order(user)          # callers don't see the five steps

A facade doesn't remove the complexity, but it contains it in one place and stops it from spreading to every caller.

The key insight Adapters change an interface, decorators keep the interface and add behavior, and facades simplify one. Knowing which problem you have tells you which wrapper to write.

§4Common Mistakes

MistakeWhat HappensFix
Letting a third-party API leak through the codeChanging providers means editing hundreds of placesAdapt it once at the boundary behind your own interface
Subclassing for each combination of featuresClass explosion (LoggedRetryingGateway...)Stack decorators instead
A facade that grows into a god classIt does the work itself rather than coordinatingKeep it thin; it delegates to the real objects
Practice
  1. Write an adapter for a library you use and make your code depend only on the interface.
  2. Add logging and caching to a service using two decorators.
  3. Create a facade for a three-step process your callers currently orchestrate by hand.
Key takeaways
  • Adapter converts an interface.
  • Decorator adds behavior by wrapping with the same interface.
  • Facade offers one simple door to a complex subsystem.
