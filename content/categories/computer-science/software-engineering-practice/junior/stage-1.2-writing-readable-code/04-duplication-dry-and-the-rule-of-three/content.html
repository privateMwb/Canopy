Duplication, DRY & the Rule of Three

DRY says not to repeat knowledge, but copying a few lines is sometimes cheaper than the wrong abstraction. The skill is knowing the difference.

§1What DRY Really Means

Don't Repeat Yourself is about duplicated *knowledge*: one fact or rule that lives in several places and must be changed in all of them. If the tax rate appears in four files, that is a bug waiting to happen.

# knowledge repeated: change the rate and you must find every copy
total_a = price * 1.2
total_b = cost * 1.2
total_c = fee * 1.2

# one source of truth
VAT_RATE = 0.20
def with_vat(amount): return amount * (1 + VAT_RATE)

§2Coincidental Duplication

Two pieces of code can look alike without being the same idea. A shipping-cost formula and a discount formula might both multiply and round today, yet change for entirely different reasons. Merging them couples two things that should evolve separately.

The test is: would these two always change together? If a change to one would never require changing the other, the similarity is coincidental, and leaving them separate is correct.

§3The Rule of Three

Wait for the third occurrence before abstracting. With one case you don't know what varies; with two you are guessing; with three the pattern is real and you can see what the parameters should be.

# first and second time: tolerate the copy
# third time: the shape is clear, so extract it
def paginate(items, page, size=20):
    start = (page - 1) * size
    return items[start:start + size]

A wrong abstraction is harder to remove than duplication, because every caller is now bent around it. When a shared function grows boolean flags and special cases to suit different callers, inline it back and start over.

The key insight Duplication is cheap to fix later and expensive abstractions are not. When unsure, wait.

§4Common Mistakes

MistakeWhat HappensFix
Merging code that only looks alikeA shared function accumulates flags and exceptions for each callerAsk whether they change for the same reason; if not, keep them apart
Abstracting after the first repeatYou guess the wrong parameters and bend later cases to fitWait for three real examples
Ignoring true duplicated rulesA rule changes in one place and the copies are forgottenGive each business rule a single home with a clear name
Practice
  1. Find a constant or rule that appears in three places and give it one home.
  2. Find two similar functions and decide whether they would always change together.
  3. Find a shared helper with flag arguments and consider inlining it.
Key takeaways
  • DRY is about duplicated knowledge, not duplicated text.
  • Similar-looking code that changes for different reasons should stay separate.
  • Wait for three occurrences; the wrong abstraction costs more than a copy.
