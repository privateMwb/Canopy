Small Functions with One Job

Short functions are easier to understand, test, and reuse, but the real rule isn't a line count. It's that each function does one thing.

§1One Job, One Level

A function should do one thing, and do it at a single level of abstraction. A function that validates input, calculates a price, writes to a database, and sends an email is four jobs wearing one name.

# before: parse, validate, calculate, save, notify, all in one
def checkout(form):
    ...80 lines...

# after: reads like an outline
def checkout(form):
    order = parse_order(form)
    validate(order)
    total = calculate_total(order)
    save_order(order, total)
    send_receipt(order)

§2How to Split a Function

Look for blocks separated by blank lines or introduced by a comment. A comment that says # calculate the total is a function name waiting to be written. Extract the block, give it that name, and the comment becomes unnecessary.

def total_with_tax(items, rate):
    # sum prices
    subtotal = 0
    for item in items:
        subtotal += item.price * item.qty
    # apply tax
    return subtotal * (1 + rate)

# extracted: each piece has a name instead of a comment
def subtotal(items):
    return sum(i.price * i.qty for i in items)

def total_with_tax(items, rate):
    return subtotal(items) * (1 + rate)

§3Arguments and Side Effects

Functions are easiest to use with few arguments. Zero to two is ideal; past three, the arguments probably belong together in an object. Boolean flags are a warning sign too, since render(page, True) says nothing, and often means the function does two things.

render(page, True, False)                 # what do these mean?
render_preview(page)                     # clearer: separate functions
render(page, RenderOptions(dark=True))   # or a named options object
A practical test If you can't describe what a function does in one short sentence without using the word "and," it probably does more than one thing.

§4Common Mistakes

MistakeWhat HappensFix
Splitting by line count aloneFunctions are chopped into meaningless pieces that must be read togetherSplit by purpose; every piece should have a name worth reading
Boolean flag argumentsCallers can't tell what True means and the function branches internallyMake two functions, or pass a named option
Hidden side effects in functions with innocent namesget_user() that also updates a database surprises callersKeep queries free of side effects; name the ones that change things
Practice
  1. Take a long function and extract three named helpers, keeping its tests green.
  2. Find a function with a boolean flag and split it into two.
  3. Write a one-sentence description for five functions. Which need an 'and'?
Key takeaways
  • One function, one job, one level of abstraction.
  • A comment explaining a block is usually a function name in disguise.
  • Keep argument counts low and side effects visible in the name.
