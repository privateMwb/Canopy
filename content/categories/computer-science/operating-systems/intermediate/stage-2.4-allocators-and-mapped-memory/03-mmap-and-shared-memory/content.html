mmap & Shared Memory

mmap maps a file or a fresh region directly into your address space, and with the right flags, two processes can share the same memory.

§1Mapping a File

mmap asks the kernel to map a file's contents into your address space. You then read and write the file as if it were an array, with no read or write calls. Pages are loaded on demand through the page-fault mechanism, and the kernel handles caching.

#include <sys/mman.h>
#include <fcntl.h>
#include <sys/stat.h>

int fd = open("data.bin", O_RDONLY);
struct stat st;  fstat(fd, &st);

char *p = mmap(NULL, st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
if (p == MAP_FAILED) { perror("mmap"); return 1; }

char first = p[0];            // triggers a page fault, loads that page
munmap(p, st.st_size);
close(fd);                    // the mapping stays valid after close

For large files, this avoids copying data into a user buffer, and random access is natural. For small sequential reads, plain read is often as fast.

§2Private vs. Shared Mappings

FlagWritesVisible to other processes?
MAP_PRIVATECopy-on-write; never go back to the fileNo
MAP_SHAREDWritten through to the file (and shared memory)Yes
MAP_ANONYMOUSBacked by zeroed memory, not a fileOnly if shared via fork

malloc for large blocks uses an anonymous private mapping, and shared libraries are mapped from files. Use msync to force changes in a shared file mapping to disk.

§3Shared Memory Between Processes

To share memory between unrelated processes, create a named shared-memory object with shm_open, size it, and map it with MAP_SHARED. Each process maps the same object and sees the same bytes.

int fd = shm_open("/demo", O_CREAT | O_RDWR, 0600);
ftruncate(fd, 4096);                      // set the size
int *shared = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
                   MAP_SHARED, fd, 0);
shared[0] = 42;                           // another process mapping /demo sees 42
// Cleanup: munmap(...); shm_unlink("/demo");

Shared memory is the fastest IPC, since no copying occurs, but the kernel provides no synchronization. Processes need their own, such as semaphores or a mutex created with PTHREAD_PROCESS_SHARED inside the shared region.

Gotcha If the underlying file shrinks while it's mapped, touching pages past the new end raises SIGBUS. Mapped I/O errors, such as a failing disk, also appear as signals rather than error codes.

§4Common Mistakes

MistakeWhat HappensFix
Sharing data in shared memory without synchronizationRaces between processes corrupt the dataUse process-shared mutexes or semaphores
Putting pointers inside shared memoryEach process may map it at a different addressStore offsets from the base instead of raw pointers
Forgetting shm_unlinkNamed objects persist until reboot or removalUnlink the name when no longer needed
Practice
  1. Write two programs: one writes a counter into shm_open memory and another reads it. Add a semaphore so they don't race.
  2. Compare the speed of reading a 1 GiB file with read into a buffer versus mmap, sequentially and randomly.
Key takeaways
  • mmap maps files or anonymous memory into your address space, loaded lazily by page faults.
  • MAP_SHARED makes writes visible to others; MAP_PRIVATE makes them copy-on-write.
  • Shared memory is fast but needs explicit synchronization and offset-based references.
