Page Replacement Algorithms

When RAM is full and a page is needed, the OS must pick a victim, and a good choice can mean the difference between smooth and thrashing.

§1The Policies

A replacement policy picks which page to evict. Here is the standard reference string 7 0 1 2 0 3 0 4 2 3 0 3 2 with 3 frames:

PolicyRuleFaults
FIFOEvict the oldest-loaded page10
LRUEvict the least recently used page9
OPTEvict the page used furthest in the future7

OPT is optimal but needs knowledge of the future, so it serves only as a benchmark. LRU approximates it by assuming the recent past predicts the near future, which works well because of locality.

§2Making LRU Practical: Clock

True LRU would need to record every memory access, which hardware doesn't provide. The Clock algorithm uses the hardware accessed bit instead. Frames form a circle with a hand. To pick a victim, the hand sweeps: if a page's accessed bit is 1, clear it and move on; if 0, evict it.

while (true) {
    if (frame[hand].accessed == 0) { evict(frame[hand]); break; }
    frame[hand].accessed = 0;      // give it a second chance
    hand = (hand + 1) % nframes;
}

Pages used since the last sweep survive; the rest are candidates. Real kernels refine this with separate active and inactive lists and prefer evicting clean pages, since dirty ones must be written to disk first.

§3Belady's Anomaly

Giving a process more frames should reduce faults. For FIFO it can do the opposite. On the string 1 2 3 4 1 2 5 1 2 3 4 5, FIFO causes 9 faults with 3 frames and 10 faults with 4 frames.

# Same string, LRU
#   3 frames: 10 faults    4 frames: 8 faults   (more memory helps)

LRU and OPT never show this behavior, because their resident set with N frames is always a subset of the set with N+1. This is one reason FIFO is rarely used alone.

Gotcha When the working set of all processes exceeds RAM, every access causes a fault and the system spends its time moving pages instead of running code. That is thrashing, and no replacement policy can fix it; only more memory or less work can.

§4Common Mistakes

MistakeWhat HappensFix
Assuming more frames always means fewer faultsFIFO can fault more with extra memoryUse stack-type policies such as LRU, or verify empirically
Evicting dirty pages without considering write costEach eviction needs a disk writePrefer clean victims when possible
Treating OPT as an implementable policyIt requires future knowledgeUse it only as the lower bound to compare other policies against
Practice
  1. Trace FIFO, LRU, and OPT by hand on the string 1 2 3 2 4 1 5 2 1 2 3 with 3 frames.
  2. Explain why clearing the accessed bit as the clock hand passes gives a page a 'second chance'.
Key takeaways
  • LRU approximates the optimal policy by using recent history; OPT needs the future.
  • Clock approximates LRU using the hardware accessed bit.
  • FIFO can suffer Belady's anomaly, and thrashing means the working set doesn't fit.
