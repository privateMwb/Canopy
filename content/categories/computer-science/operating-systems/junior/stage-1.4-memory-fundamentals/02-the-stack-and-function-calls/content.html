The Stack & Function Calls

Each function call pushes a frame onto the stack holding its locals and return address, and understanding that frame explains recursion limits and a class of security bugs.

§1What a Stack Frame Holds

On a call, the CPU pushes the return address, the place to resume after the function finishes. The function then reserves space for saved registers, any parameters that spill from registers, and its local variables. All of this together is a stack frame. When the function returns, the frame is discarded by moving the stack pointer back.

int add(int a, int b) {
    int sum = a + b;     // sum lives in add's frame
    return sum;
}

int main(void) {
    int x = add(2, 3);   // frame for add pushed, then popped
    return x;
}

Frames stack up: main, then add above it. A deeper call chain uses more stack.

§2Recursion and Stack Overflow

Each recursive call adds a frame. Linux gives the main thread an 8 MB stack by default, so runaway recursion eventually hits the limit and crashes with a segmentation fault.

int depth(int n) { return depth(n + 1) + 1; }   // no base case: crash

# See and change the limit
ulimit -s          # 8192 (KB)

Big local arrays are the other way to overflow. char buf[10000000]; inside a function can exhaust the stack in a single call.

§3Why Buffer Overflows Matter

Locals sit right next to saved control data. Writing past the end of a local buffer can overwrite the return address, letting an attacker redirect execution. Modern defenses include stack canaries, non-executable stacks, and ASLR, but the root fix is bounds-checked code.

void greet(const char *name) {
    char buf[16];
    strcpy(buf, name);   // no length check: input over 15 bytes overflows
}
// Safer: snprintf(buf, sizeof buf, "%s", name);
Connection to later lessons Threads each get their own stack, which is why locals are naturally thread-safe while globals are not. Stage 3.3 revisits stack canaries and ASLR as layers of defense.

§4Common Mistakes

MistakeWhat HappensFix
Recursing without a reachable base caseStack overflow and a crashDefine the base case first and make sure every call moves toward it
Allocating huge arrays as localsStack overflow on a single callUse the heap for large buffers
Using strcpy or gets on fixed buffersOverflow of adjacent stack dataUse length-checked functions such as snprintf and fgets
Practice
  1. Write a recursive function that counts down from N. Find roughly the N at which your system overflows the stack.
  2. Use gdb and bt to print the call stack at a breakpoint inside a nested function call.
Key takeaways
  • Each call creates a frame with the return address, saved state, and locals.
  • Deep recursion and large local arrays can overflow a limited stack.
  • Unchecked writes to local buffers can corrupt control data, a classic security hole.
