Dynamic Allocation: malloc & free

The heap lets you request memory at runtime that outlives any one function, and in return you must release it exactly once.

§1Requesting and Releasing Memory

malloc(n) returns a pointer to at least n bytes of uninitialized heap memory, or NULL on failure. free(p) returns it. calloc zeroes the memory, and realloc resizes a block.

#include <stdlib.h>
#include <string.h>

int *make_array(size_t n) {
    int *a = malloc(n * sizeof *a);   // sizeof *a survives type changes
    if (!a) return NULL;              // always check
    memset(a, 0, n * sizeof *a);
    return a;
}

int main(void) {
    int *arr = make_array(100);
    // ... use arr ...
    free(arr);                        // exactly once
    arr = NULL;                       // avoid reuse of a dead pointer
}

malloc gives you uninitialized bytes, so reading them before writing yields garbage.

§2Ownership

Every allocation needs exactly one owner responsible for freeing it. Decide who owns the memory when you write the function, and document it.

// Caller owns the result and must free it
char *read_line(FILE *f);

// Callee only borrows; caller keeps ownership
size_t count_words(const char *text);

Functions that return allocated memory should say so in their name or comment. Most leaks and double frees come from two parts of a program each believing the other will clean up.

§3Growing a Buffer

realloc may move the block, so always assign the result to a temporary first.

int *tmp = realloc(arr, new_n * sizeof *arr);
if (!tmp) { free(arr); return -1; }   // arr is still valid if realloc failed
arr = tmp;

Growing by doubling, rather than by a fixed step, keeps the amortized cost of appends low.

The key insight malloc and free are library functions, not system calls. They manage a pool of memory obtained from the kernel in larger chunks, which is why freeing small blocks usually doesn't shrink the process. Stage 2.4 opens that up.

§4Common Mistakes

MistakeWhat HappensFix
Not checking malloc for NULLDereferencing NULL crashes the programCheck every allocation, and handle failure
Writing p = realloc(p, n)If it fails, you lose the original pointer and leak itAssign to a temporary, then replace p on success
Using sizeof(pointer) instead of sizeof(*pointer)The block is only 8 bytes, not the array sizeUse sizeof *p multiplied by the count
Practice
  1. Write a dynamic array of ints that doubles its capacity when full, with push, get, and destroy.
  2. For three functions you've written, state who owns each pointer it takes or returns.
Key takeaways
  • Check malloc for NULL and free every block exactly once.
  • Give each allocation a single, clearly documented owner.
  • Use a temporary pointer when calling realloc.
