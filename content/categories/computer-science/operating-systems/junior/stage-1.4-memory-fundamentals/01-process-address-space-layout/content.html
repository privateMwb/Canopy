Process Address Space Layout

Every process sees memory divided into regions for code, data, heap, and stack, and knowing which region a variable lives in explains most memory behavior.

§1The Regions

RegionHoldsGrows?
Text (code)Machine instructions, read-onlyFixed
Data / BSSGlobal and static variablesFixed
HeapMemory from mallocUpward, on demand
StackLocal variables and call framesDownward, per call

The data segment holds globals with initial values; BSS holds globals initialized to zero, which the OS provides without storing zeros in the executable. Between heap and stack lies a large unused gap, and shared libraries and memory-mapped files are placed in the middle.

§2Where Does This Variable Live?

int counter = 5;              // data segment
int zeros[1000];              // BSS
const char *msg = "hi";       // pointer in data; string literal in read-only text

void f(void) {
    int local = 1;            // stack
    static int calls = 0;     // data: lives for the whole run
    int *p = malloc(100);     // p is on the stack; the 100 bytes are on the heap
    free(p);
}

Notice the last line: the pointer p and the memory it points to live in different regions with different lifetimes.

§3Looking at a Real Process

size ./a.out                  # text, data, bss sizes of the binary
cat /proc/self/maps           # live memory map of a process
# Each line: address range, permissions (r/w/x), and what backs it

With ASLR (address space layout randomization), the stack, heap, and libraries are placed at randomized addresses on each run, so the same program prints different pointer values each time.

The key insight Lifetime follows region: stack data dies when the function returns, heap data lives until freed, and globals live for the whole program. Most memory bugs are a mismatch between what you assumed and where the data actually lives.

§4Common Mistakes

MistakeWhat HappensFix
Returning the address of a local variableThe stack frame is gone, so the pointer danglesReturn heap memory, a static, or copy the value out
Writing to a string literalThe text region is read-only, so the program crashesCopy the literal into a char[] before modifying it
Printing pointers and expecting stable valuesASLR changes them each runNever rely on absolute addresses staying the same
Practice
  1. Print the addresses of a global, a local, a heap pointer, and a function. Order them from lowest to highest and match them to regions.
  2. Run cat /proc/self/maps twice. What changes between runs, and what does that tell you about ASLR?
Key takeaways
  • A process's memory is split into text, data/BSS, heap, and stack.
  • The region a variable lives in determines its lifetime.
  • ASLR randomizes layout, so addresses are not stable between runs.
