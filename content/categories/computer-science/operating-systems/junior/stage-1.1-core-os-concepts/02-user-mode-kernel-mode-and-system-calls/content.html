User Mode, Kernel Mode & System Calls

The CPU runs in two privilege levels, and a system call is the controlled doorway a program uses to ask the kernel for help.

§1Two Privilege Levels

Modern CPUs have a hardware mode bit. In kernel mode the CPU may execute any instruction and touch any memory or device. In user mode it may not. Programs run in user mode, so a buggy or hostile program cannot overwrite another program's memory or reprogram a disk controller.

Trying a privileged operation in user mode makes the CPU raise an exception, and the kernel typically terminates the offender. That's where an ordinary Segmentation fault comes from.

§2Crossing the Boundary: System Calls

A program can't call kernel code like a normal function, because that would let it jump anywhere in privileged code. Instead, it executes a special instruction (syscall on x86-64) that switches to kernel mode and jumps to a fixed entry point the kernel chose at boot.

#include <unistd.h>

int main(void) {
    // write(fd, buffer, length) is the system call wrapper
    write(1, "hello\n", 6);   // fd 1 is standard output
    return 0;
}

The kernel looks up the system call number in a table, validates every argument (is this pointer really in your memory?), does the work, then returns to user mode with a result or an error code.

§3Why Syscalls Cost Something

Crossing the boundary is not free. The CPU saves state, switches stacks, and the kernel checks arguments; afterward, caches and branch predictors may be colder. A syscall costs hundreds of nanoseconds or more, versus a couple of nanoseconds for a normal function call.

# Slow: one syscall per byte
for each byte: write(fd, &byte, 1)

# Fast: buffer in user space, one syscall per 4096+ bytes
fwrite(buffer, 1, 4096, file)
Connection to later lessons Interrupts and exceptions use the same user-to-kernel switch. A page fault in Stage 2.3 is the hardware calling the kernel on your behalf, with no syscall instruction involved.

§4Common Mistakes

MistakeWhat HappensFix
Making one syscall per tiny operationPrograms spend most of their time crossing the kernel boundaryBuffer in user space; use fwrite or batch your own writes
Ignoring a syscall's return valueErrors such as a full disk or a closed pipe go unnoticedCheck for -1 and read errno
Believing user mode means slower codeConfusion about where time goesPure computation runs at full speed in either mode; only privileged operations require the kernel
Practice
  1. Look up the x86-64 Linux syscall numbers for read, write, and exit. Which registers carry the arguments?
  2. Time writing 1 MB to /dev/null one byte at a time versus 4096 bytes at a time. How large is the gap?
Key takeaways
  • User mode restricts what a program can do; kernel mode has no restrictions.
  • A system call is a controlled, validated entry into the kernel through a fixed entry point.
  • Each syscall has real cost, so batch your work and check every return value.
