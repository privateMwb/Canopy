Hash Functions: What They Guarantee

A cryptographic hash turns any input into a short fixed fingerprint, and its security rests on three specific properties that older algorithms no longer satisfy.

§1What a Hash Function Does

A hash function maps input of any size to a fixed-size output called a digest. The same input always gives the same digest, and a tiny change to the input changes the whole output, known as the avalanche effect.

$ echo -n 'hello' | sha256sum
2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
$ echo -n 'hellp' | sha256sum
fdd7585e08c4e2afd71dcabdb4636c89d557a3f42db9e2040c8bbd1708aa4ce7   # completely different

§2The Three Security Properties

PropertyMeaningWhy it matters
Preimage resistanceGiven a digest, you can't find an input that produces itDigests don't reveal what was hashed
Second-preimage resistanceGiven an input, you can't find a different one with the same digestA file can't be swapped for another with the same hash
Collision resistanceYou can't find any two inputs with the same digestSignatures over hashes can't be forged by crafting matching documents

With an n-bit digest, collisions can be found in about 2^(n/2) work through the birthday effect, so SHA-256 gives roughly 128 bits of collision security.

§3Which Algorithms to Use

  • SHA-256 and SHA-512 (SHA-2) and SHA-3: current, safe for general-purpose hashing.
  • BLAKE2 and BLAKE3: fast modern alternatives.
  • MD5 and SHA-1: practical collision attacks exist, so never use them where an attacker might craft inputs, such as signatures and certificates. They remain in legacy checksums only.

Also remember that a fast hash is the wrong tool for passwords, which Stage 1.3 explains.

No secret, no authentication A hash is computed without a key, so anyone can compute the same digest for any input. It detects accidents, but it can't prove who produced the data. Proof of origin needs a MAC or a signature (Stage 2.1).

§4Common Mistakes

MistakeWhat HappensFix
Using MD5 or SHA-1 for security decisionsAttackers can craft colliding inputsUse SHA-256 or newer for anything security relevant
Assuming a hash hides small inputsShort or guessable inputs are brute-forced by trying every candidateDon't hash low-entropy secrets with a fast hash
Truncating digests to save spaceCollision resistance drops sharplyKeep the full digest unless you've analyzed the loss
Practice
  1. Hash the same file with sha256sum and md5sum, change one byte, and compare how the output changes.
  2. Explain in two sentences why collision resistance matters for a signed document but preimage resistance matters for stored digests.
Key takeaways
  • A hash is deterministic, fixed-size, and changes completely with any input change.
  • Preimage, second-preimage, and collision resistance are the properties that matter.
  • Prefer SHA-2, SHA-3, or BLAKE, and avoid MD5 and SHA-1 for security.
