Deserialization, Templates & XML Pitfalls

Some of the worst server bugs come from a parser or deserializer that quietly does far more than the developer intended, from running code to reading files.

§1Unsafe Deserialization

Some serialization formats can describe arbitrary objects, and rebuilding them can run code. Python's pickle, Java's native object serialization, and PHP's unserialize have all led to remote code execution when fed attacker data.

import pickle, json
pickle.loads(untrusted)        # can run attacker-chosen code during loading

json.loads(untrusted)          # data only: dicts, lists, strings, numbers

Use plain data formats (JSON) for anything crossing a trust boundary, and validate the structure afterward. If you must use a rich format, sign it first with a MAC and verify before parsing, since the parsing is the dangerous step.

§2Server-Side Template Injection

Template engines evaluate expressions. The bug appears when user input becomes part of the template source instead of a value passed into it.

# Vulnerable: user text becomes template code
render_template_string("Hello " + name)         # name = "{{ 7*7 }}" evaluates to 49

# Safe: user text is data
render_template_string("Hello {{ name }}", name=name)

A harmless 7*7 probe becomes full code execution in many engines. Never build templates from user input, and use sandboxed rendering where users must author templates.

§3XML External Entities (XXE)

XML can define entities that pull in external content. A parser that resolves them lets an attacker read local files, make the server issue requests (SSRF), or exhaust memory with nested entities (a "billion laughs" attack).

from defusedxml import ElementTree      # safe-by-default wrapper
tree = ElementTree.fromstring(untrusted_xml)

Disable DTDs and external entity resolution in your XML parser, or use a library that does so by default.

The common thread In each case, a feature intended for convenience (object reconstruction, expressions, entities) is reachable by attacker data. Ask of every parser: what can this format make the server do, and is that ever safe to expose?

§4Common Mistakes

MistakeWhat HappensFix
Deserializing untrusted data with pickle or native object streamsRemote code executionUse JSON and validate the result
Concatenating user input into a template stringAttacker expressions run on the serverPass user input as variables, never as template source
Using default XML parser settingsExternal entities read files or reach internal URLsDisable DTDs and external entities, or use a hardened parser
Practice
  1. Replace a use of pickle.loads on network data with JSON and a schema check.
  2. Test a template endpoint with {{ 7*7 }} as input in a local app and confirm the safe version prints it literally.
Key takeaways
  • Rich serialization formats can execute code; use data-only formats for untrusted input.
  • Keep user input out of template source.
  • Turn off external entities and DTDs when parsing XML.
