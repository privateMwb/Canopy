Modules, Environments & Safe Changes

Modules let you reuse infrastructure code, environments let you promote it safely, and the review process is what keeps changes from breaking production.

§1Reusable Modules

A Terraform module is a folder of resources with inputs and outputs, a function for infrastructure. Define "a network" or "a service with a load balancer" once and use it for every environment, rather than copying hundreds of lines.

module "network" {
  source   = "./modules/network"
  env      = var.env
  vpc_cidr = "10.20.0.0/16"
}

module "app" {
  source     = "./modules/app"
  env        = var.env
  subnet_ids = module.network.private_subnet_ids
  image      = var.image
}

§2Environments

Keep staging and production as the same code with different inputs. Two common layouts are a directory per environment that calls shared modules, or one configuration with a variable file per environment. Either way, separate state, so a staging experiment can never touch production resources.

infra/
  modules/
    network/  app/  database/
  envs/
    staging/   main.tf  staging.tfvars  (state: staging.tfstate)
    production/ main.tf  prod.tfvars    (state: production.tfstate)

§3Safe Change Process

Treat infrastructure changes like deployments. Plan in the pull request, review the plan, apply from the pipeline after approval, and protect risky resources from accidental destruction. Make changes in small steps, and apply to staging first.

resource "aws_db_instance" "main" {
  # ...
  deletion_protection = true
  lifecycle {
    prevent_destroy = true           # plan fails if this would be destroyed
  }
}
# pipeline: terraform plan on every PR -> comment the plan -> apply on merge
Blast radius Always ask "if this change goes wrong, what is the worst that happens?" Smaller state files, separate environments, and protected resources all exist to shrink that answer.

§4Common Mistakes

MistakeWhat HappensFix
Copy-pasting environments instead of using modulesCopies drift apart and bugs are fixed in one place onlyExtract a module and pass inputs
Sharing state between staging and productionA staging mistake can modify productionUse separate state and separate credentials
Applying from laptopsNo audit trail, and different tool versionsApply from the pipeline with pinned versions
Practice
  1. Extract a repeated block of resources into a module and use it in two environments.
  2. Add prevent_destroy to a critical resource and observe what terraform destroy does.
Key takeaways
  • Modules package reusable infrastructure, and environments are the same code with different inputs.
  • Separate state and credentials per environment limit the blast radius.
  • Plan in the pull request, apply from the pipeline, and protect critical resources.
