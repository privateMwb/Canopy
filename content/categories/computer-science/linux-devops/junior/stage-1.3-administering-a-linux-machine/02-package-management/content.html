Package Management

A package manager installs software, tracks every file it put on disk, and handles dependencies and upgrades, so you almost never build things by hand.

§1What a Package Manager Does

A package is an archive of files plus metadata: name, version, dependencies, and install scripts. A repository is a signed collection of packages that the manager downloads from. Debian and Ubuntu use apt with .deb packages. Fedora, RHEL, and Rocky use dnf with .rpm packages.

# Debian / Ubuntu
sudo apt update                  # refresh the package index
sudo apt install nginx           # install with dependencies
apt search redis                 # find packages
sudo apt remove nginx            # remove, keep config
sudo apt purge nginx             # remove including config

# Fedora / RHEL
sudo dnf install nginx
sudo dnf upgrade

apt update only refreshes the list of available versions. It does not upgrade anything. apt upgrade is the step that installs newer versions.

§2Inspecting What Is Installed

Because the manager records every file, you can ask which package owns a file, and list what a package installed. This is invaluable when debugging.

dpkg -L nginx                    # files installed by nginx (Debian)
dpkg -S /usr/sbin/nginx          # which package owns this file?
apt show nginx                   # version, dependencies, description
apt list --installed | grep ssl
rpm -ql nginx                    # same idea on RPM systems

§3Repositories, Trust, and Pinning

Repositories are configured under /etc/apt/sources.list.d/ (or /etc/yum.repos.d/). Third-party repos need their signing key, which proves packages were not tampered with. Add only sources you trust, because package install scripts run as root.

apt policy nginx                 # candidate version and its source
sudo apt install nginx=1.24.0-2ubuntu7   # pin an exact version
sudo apt-mark hold nginx         # stop automatic upgrades of it
sudo apt autoremove              # remove orphaned dependencies
Packages vs. curl | bash Installing through a package manager gives you signed artifacts, a record of every file, clean removal, and security updates. Piping a script from the internet into a shell gives you none of that, so use it only for sources you have actually vetted.

§4Common Mistakes

MistakeWhat HappensFix
Running apt install without apt update firstInstalls an outdated version or fails with "not found"Update the index first
Adding a third-party repo without checking itIts packages run install scripts as rootVerify the vendor and use its signed key
Deleting files by hand instead of removing the packageLeaves orphaned config and breaks the package databaseUse apt remove or apt purge
Practice
  1. Install a package, list the files it added, and find which package owns /bin/ls.
  2. Pin a package to its current version and verify it is held back during an upgrade.
Key takeaways
  • Package managers track every installed file and resolve dependencies for you.
  • update refreshes the index, and upgrade actually installs newer versions.
  • Only add repositories you trust, because package scripts run with root privileges.
