Searching & Viewing: grep, find & less

find locates files by their properties, grep locates text inside them, and less lets you read the results without opening an editor.

§1find: Search by Property

find walks a directory tree and tests each file against conditions. You can combine tests by name, type, size, age, and owner, then run an action.

find . -name "*.log"                    # by name (quote the pattern!)
find /var/log -type f -size +10M        # files larger than 10 MB
find . -mtime -1                        # modified in the last day
find . -name "*.tmp" -delete            # act on each match
find . -name "*.sh" -exec chmod +x {} + # run a command on matches

Quote patterns like "*.log" so the shell does not expand them first. Otherwise a matching file in the current directory silently changes what find receives.

§2grep: Search Inside Files

grep prints lines matching a pattern. The flags you will use constantly are -i (ignore case), -r (recurse), -n (line numbers), -v (invert), -c (count), and -E (extended regular expressions).

grep -rn "TODO" src/                    # recursive, with line numbers
grep -i "error" app.log                 # case-insensitive
grep -v "^#" config.conf                # lines that are not comments
grep -E "timeout|refused" app.log       # either word
grep -c "404" access.log                # count matching lines

A match's exit code is 0 and no match is 1. Scripts rely on this, as the exit-code lesson shows later.

§3Reading Output with less

less shows a file one screen at a time without loading it all. Inside it, /word searches forward, n jumps to the next match, G goes to the end, g to the start, and q quits. less +F app.log follows a growing file like tail -f.

less /var/log/syslog
tail -n 50 app.log                      # last 50 lines
tail -f app.log                         # follow new lines as they arrive
head -n 5 data.csv                      # first 5 lines
The key insight Use find when the question is about the file (name, size, age) and grep when it is about the contents. Combining them, with find ... -exec grep ... or grep -r, covers most searching you will ever do.

§4Common Mistakes

MistakeWhat HappensFix
Leaving find patterns unquotedThe shell expands the glob and find gets the wrong argumentsQuote: -name "*.log"
Running find ... -delete firstDeletes everything that matches, including surprisesRun without -delete first and read the list
Using cat on a huge fileFloods the terminal and hides what you wantedUse less, head, tail, or grep
Practice
  1. Find every file under /etc modified in the last 7 days.
  2. Count how many lines containing "ERROR" appear in each .log file in a directory.
Key takeaways
  • find searches by file properties, and grep searches text inside files.
  • Quote patterns so the shell does not expand them before the command sees them.
  • Preview with less, head, and tail instead of dumping whole files.
