Navigating the Filesystem & the FHS

Linux organizes everything into one tree rooted at /, and the Filesystem Hierarchy Standard (FHS) tells you where each kind of file lives.

§1Paths and the Working Directory

Every process has a current working directory. A path starting with / is absolute (from the root); anything else is relative to where you are. . means the current directory, .. the parent, and ~ your home directory.

pwd                      # print working directory
cd /var/log              # absolute path
cd ../lib                # relative: up one, then into lib
cd ~                     # home directory
cd -                     # back to the previous directory
ls -lah                  # long format, hidden files, human sizes

The shell expands ~ and wildcards like *.txt before the command runs, so ls never sees the *. This matters in the quoting lessons later.

§2The Directory Tree

There is no C: drive. Every disk and partition is mounted somewhere in the one tree. The top-level directories follow a convention:

  • /etc is system-wide configuration, as plain text files.
  • /var is data that changes while running: logs in /var/log, caches, spools, databases.
  • /usr is installed programs and libraries; /usr/bin holds most commands.
  • /home is user files; /root is the root user's home.
  • /tmp is scratch space that may be cleared on reboot.
  • /proc and /sys are not real files: the kernel exposes live process and hardware state through them.
  • /dev holds device files such as /dev/null and /dev/sda.
cat /etc/os-release      # which distro and version is this?
df -h                    # mounted filesystems and free space
du -sh /var/log/*        # what is using space under /var/log?
ls /proc/self            # the shell's own process, as files

§3Finding Your Way Around

Two commands answer "where is this thing?" which shows which executable the shell will run, and type also reveals aliases and builtins. The PATH variable is the ordered list of directories searched.

echo $PATH
which python3            # first match on PATH
type cd                  # "cd is a shell builtin"
ls -ld /usr/bin /etc     # -d: show the directory itself, not its contents
The key insight Because /proc and /sys are windows into the kernel, the same tools you use on files (cat, ls, grep) work on live system state. The OS track's "everything is a file" lesson is what you are using here.

§4Common Mistakes

MistakeWhat HappensFix
Running rm -rf with a typo in a pathDeletes the wrong tree, and there is no trash canUse ls on the exact path first, and quote variables
Editing files in /usr by handA package upgrade overwrites your changePut configuration in /etc, never in package-owned files
Assuming /tmp persistsData disappears after a reboot or cleanup jobKeep anything you need in /var or your home directory
Practice
  1. From your home directory, reach /var/log using one absolute and one relative path.
  2. Use du and sort -h to find the three largest directories under /usr.
Key takeaways
  • Linux has one directory tree; disks are mounted into it rather than getting drive letters.
  • The FHS tells you where to look: config in /etc, changing data in /var, programs in /usr.
  • /proc and /sys expose kernel state as files you can read.
