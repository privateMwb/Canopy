Pipes, Redirection & Streams

Every command has three standard streams, and pipes and redirection let you connect them to files and to each other.

§1Three Streams

Each process starts with stdin (file descriptor 0), stdout (1), and stderr (2). Normal output goes to stdout; errors and diagnostics go to stderr. They look identical in a terminal but are separate channels, which is the point.

ls /etc /nonexistent > out.txt        # stdout to a file; the error still shows
ls /etc /nonexistent > out.txt 2> err.txt
ls /etc /nonexistent > all.txt 2>&1   # both streams to one file
command >> log.txt                    # append instead of overwrite
sort < unsorted.txt                   # read stdin from a file

Order matters in > all.txt 2>&1: it means "point stdout at the file, then point stderr at wherever stdout now goes".

§2Pipes: Small Tools, Chained

A pipe | connects one command's stdout to the next command's stdin. Each tool does one thing, and the pipeline does the whole job.

# the 5 most common client IPs in an access log
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5

ps aux | grep nginx                   # find a process
journalctl -u myapp | grep -i error | wc -l

The commands in a pipeline run concurrently, not one after another. Data streams through as it is produced, so you can process files bigger than memory.

§3Useful Plumbing

tee copies a stream to a file and passes it on. /dev/null discards anything written to it. xargs turns lines on stdin into arguments for a command.

make 2>&1 | tee build.log             # see output and save it
command 2>/dev/null                   # silence errors
find . -name "*.bak" | xargs rm       # fragile: breaks on spaces
find . -name "*.bak" -print0 | xargs -0 rm   # safe with odd filenames
Why stderr is separate If errors went to stdout, a pipeline like cmd | grep foo would feed error text into the next tool and corrupt your data. Keeping stderr separate is what lets pipelines stay clean while you still see problems.

§4Common Mistakes

MistakeWhat HappensFix
Writing 2>&1 > fileStderr goes to the terminal, because it was duplicated before stdout movedWrite > file 2>&1
Using > where >> was meantOverwrites the existing fileUse >> to append, or check first
Piping filenames with spaces into xargsNames split into pieces and the wrong files are touchedUse -print0 with xargs -0
Practice
  1. Run a command that produces both output and errors, and capture each into a separate file.
  2. Build a one-line pipeline that lists the ten largest files under a directory.
Key takeaways
  • Streams 0, 1, and 2 are stdin, stdout, and stderr, and each can be redirected independently.
  • A pipe connects stdout to stdin, and the commands in it run at the same time.
  • Redirection order matters: > file 2>&1 and 2>&1 > file behave differently.
