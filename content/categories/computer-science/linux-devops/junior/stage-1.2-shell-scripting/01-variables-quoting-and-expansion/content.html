Variables, Quoting & Expansion

The shell rewrites your command line in several passes before running it, and quoting decides which of those rewrites happen.

§1Variables and Expansion

Assign with no spaces around =, and read with $. Braces mark where the name ends. $(...) substitutes a command's output, and $((...)) does integer arithmetic.

name="web-01"
echo "host: $name"           # host: web-01
echo "${name}_backup"        # web-01_backup
today=$(date +%F)            # command substitution
echo $((3 * 7))              # 21
echo "${LOGDIR:-/var/log}"   # default if LOGDIR is unset or empty

Variables are untyped strings. Environment variables are the ones marked with export, which child processes inherit; plain shell variables are not passed on.

§2Quoting Rules

Without quotes, the shell splits the result of an expansion on whitespace and expands wildcards in it. Double quotes keep the value as one word but still allow $ expansion. Single quotes block everything.

file="my report.txt"
touch $file                  # BUG: creates "my" and "report.txt"
touch "$file"                # correct: one file

echo "$HOME"                 # expanded
echo '$HOME'                 # literal text: $HOME
echo "cost: \$5"             # backslash escapes a single character

§3Globs and Arrays

A glob like *.log is expanded by the shell into matching filenames. Bash arrays hold lists of words safely, and "${arr[@]}" expands to one word per element with spaces preserved.

for f in *.log; do echo "$f"; done
servers=("web 1" "web-2" "db-1")
for s in "${servers[@]}"; do echo "$s"; done   # three items, not four
echo "${#servers[@]}"        # 3: the element count
Quote every expansion Make "$var" and "$(cmd)" your default. The unquoted form is only right when you specifically want word splitting, which is rare. Most "works on my machine" shell bugs are filenames with spaces.

§4Common Mistakes

MistakeWhat HappensFix
Spaces around = as in x = 5The shell runs a command named x with argumentsWrite x=5 with no spaces
Leaving $var unquotedValues with spaces or * split or expand unexpectedlyQuote it: "$var"
Using single quotes and expecting expansion'$name' prints literallyUse double quotes when you need $ to expand
Practice
  1. Create a file called my notes.txt using a variable, and delete it using the same variable, quoted correctly.
  2. Loop over an array of three paths, one containing a space, and print each on its own line.
Key takeaways
  • The shell expands variables, commands, and globs before the program ever runs.
  • Double quotes preserve a value as one word, and single quotes keep it completely literal.
  • Quote every $variable unless you deliberately want it split.
