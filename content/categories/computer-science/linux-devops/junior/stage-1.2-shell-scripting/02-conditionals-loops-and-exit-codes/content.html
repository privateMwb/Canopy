Conditionals, Loops & Exit Codes

Every command returns an exit code, and shell conditionals and loops are built on that one contract: 0 means success, anything else means failure.

§1Exit Codes

A command's exit status is stored in $?. By convention 0 is success, 1 is a general error, 2 is misuse, 126 is "found but not executable", 127 is "command not found", and 128 plus N means "killed by signal N".

ls /etc >/dev/null; echo $?          # 0
ls /nonexistent 2>/dev/null; echo $? # 2
grep -q "root" /etc/passwd && echo "found"
grep -q "nobody-here" /etc/passwd || echo "missing"

&& runs the next command only if the previous succeeded, and || only if it failed. They give you short conditional chains without if.

§2if and Tests

if runs a command and checks its exit status. The test [[ ... ]] in bash (or [ ... ] in POSIX sh) is simply a command that returns 0 or 1.

if [[ -f "$config" ]]; then
  echo "config exists"
elif [[ -d "$config" ]]; then
  echo "that is a directory"
else
  echo "missing"
fi

[[ "$count" -gt 10 ]]         # numeric compare: -eq -ne -lt -gt -le -ge
[[ "$name" == web-* ]]        # string compare with a glob pattern
[[ -z "$var" ]]               # true if empty
if systemctl is-active --quiet nginx; then echo up; fi

Inside [[ ]], use == and != for strings and -eq, -lt, etc. for numbers. Comparing numbers with > compares them as text, so 10 sorts before 9.

§3Loops

for iterates over a list, while repeats until a command fails, and while read is the standard way to process input line by line.

for host in web-01 web-02 db-01; do
  ssh "$host" uptime
done

i=0
while [[ $i -lt 3 ]]; do
  echo "try $i"; i=$((i + 1))
done

while IFS= read -r line; do
  echo "got: $line"
done < hosts.txt
The key insight Shell has no booleans. "True" means "exited with 0". This is why if grep -q pattern file works, and why every script you write should return a meaningful exit code too.

§4Common Mistakes

MistakeWhat HappensFix
Using > to compare numbers inside [[ ]]Strings are compared alphabetically, so 10 is less than 9Use -gt, -lt, or (( )) for numbers
Forgetting spaces inside [[ ]]A syntax error or the wrong testPut spaces: [[ -f "$f" ]]
Reading lines with plain readBackslashes and leading spaces are mangledUse while IFS= read -r line
Practice
  1. Write a loop that checks whether each of three hostnames responds to ping -c1, and prints up or down.
  2. Write a snippet that exits with code 3 if a required file is missing.
Key takeaways
  • Exit code 0 is success, and anything else is failure; $? holds the last one.
  • if tests a command's exit status, and [[ ]] is just a command that tests conditions.
  • Use while IFS= read -r to process input line by line safely.
