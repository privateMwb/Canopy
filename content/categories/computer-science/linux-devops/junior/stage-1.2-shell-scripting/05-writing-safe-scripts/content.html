Writing Safe Scripts

By default a shell script keeps going after errors, so a safe script opts into strict behavior, cleans up after itself, and gets checked by a linter.

§1Strict Mode

Three settings catch most silent failures. set -e exits on a failed command, set -u treats unset variables as errors, and set -o pipefail makes a pipeline fail if any stage fails, not only the last.

#!/usr/bin/env bash
set -euo pipefail

cd "$BUILD_DIR"                  # -u: stops here if BUILD_DIR is unset
rm -rf ./dist                    # safe: the cd above must have succeeded
grep "needle" missing.txt | sort # pipefail: the failed grep fails the line

set -e has edge cases: it does not trigger inside if conditions or on the left of && and ||. It helps, but it is not a replacement for checking critical steps yourself.

§2Cleaning Up with trap

trap runs a command when the script exits or receives a signal. This is the right place to remove temporary files so they are deleted even when the script fails.

tmpdir=$(mktemp -d)
cleanup() { rm -rf "$tmpdir"; }
trap cleanup EXIT                # runs on normal exit, error, or Ctrl+C

cp important.db "$tmpdir/"
# ... work in $tmpdir ...

Always create temporary files with mktemp. Predictable names such as /tmp/work allow collisions between runs and are a security risk.

§3Linting and Defensive Habits

ShellCheck is a static analyzer that finds unquoted variables, bad tests, and portability problems. Run it locally and in CI. Also validate inputs early, and never build rm commands from unchecked variables.

shellcheck deploy.sh             # reports each issue with a code like SC2086
rm -rf "${TARGET:?TARGET is not set}/cache"   # refuses to run if empty
[[ "$1" =~ ^[a-z0-9-]+$ ]] || { echo "bad name" >&2; exit 2; }
The expensive typo rm -rf "$DIR/" with DIR unset becomes rm -rf /. The ${DIR:?} form and set -u exist precisely to stop this class of mistake.

§4Common Mistakes

MistakeWhat HappensFix
Writing scripts with no set -euo pipefailFailures are ignored and later steps run on bad stateStart every script with strict mode
Cleaning up at the end of the script onlyAn error or Ctrl+C skips the cleanupRegister the cleanup with trap ... EXIT
Creating /tmp/myscript.tmp by handName clashes and symlink attacksUse mktemp and mktemp -d
Practice
  1. Run ShellCheck on an old script of yours and fix every warning, noting which ones were real bugs.
  2. Write a script that makes a temp directory, fails halfway on purpose, and still removes the directory.
Key takeaways
  • set -euo pipefail turns silent failures into immediate, visible ones.
  • trap ... EXIT guarantees cleanup, even when the script fails or is interrupted.
  • Lint with ShellCheck, validate inputs, and guard destructive commands with ${VAR:?}.
