Routing, History & Browser APIs

The URL is part of your app's state, and the browser already has APIs for navigation, visibility, and observation that you can use without adding a library.

§1Client-Side Routing and the History API

A single-page app changes the visible "page" without a full reload by updating the URL with history.pushState and re-rendering. Intercept link clicks, listen to popstate for Back/Forward, and make sure every route also works on a direct load (the server must serve your app for those paths).

function navigate(path) {
  history.pushState({}, "", path);          // change URL, no reload
  render(location.pathname);
}
document.addEventListener("click", (e) => {
  const a = e.target.closest("a[data-link]");
  if (a) { e.preventDefault(); navigate(a.getAttribute("href")); }
});
window.addEventListener("popstate", () => render(location.pathname));   // back / forward

const routes = { "/": Home, "/about": About };
function render(path) { app.replaceChildren((routes[path] ?? NotFound)()); }
render(location.pathname);

§2URL as State

Anything a user might want to bookmark, share, or return to belongs in the URL: filters, search terms, page numbers, the selected item. URL and URLSearchParams make this safe.

const params = new URLSearchParams(location.search);
const q = params.get("q") ?? "";
const page = Number(params.get("page") ?? 1);

function setQuery(q) {
  const url = new URL(location.href);
  url.searchParams.set("q", q);
  url.searchParams.delete("page");
  history.replaceState({}, "", url);        // replace: don't spam the Back button
}
// Never concatenate user text into a URL by hand: encodeURIComponent or URLSearchParams

§3Platform APIs You Don't Need a Library For

IntersectionObserver reports when elements enter the viewport — lazy loading and infinite scroll without scroll listeners. ResizeObserver reports size changes. The Page Visibility API tells you when the tab is hidden, and BroadcastChannel syncs tabs.

const io = new IntersectionObserver((entries) => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    e.target.src = e.target.dataset.src;     // lazy-load the image
    io.unobserve(e.target);
  }
}, { rootMargin: "200px" });
document.querySelectorAll("img[data-src]").forEach((img) => io.observe(img));

document.addEventListener("visibilitychange", () => {
  if (document.hidden) pausePolling(); else resumePolling();
});
navigator.clipboard.writeText("copied");     // needs a secure context + user gesture

Check support on MDN before depending on a newer API, and feature-detect (if ("IntersectionObserver" in window)) when you must support older browsers.

Test the direct load A route that works when you click to it but 404s on refresh means the server isn't configured to fall back to index.html for client-side paths.

MistakeWhat HappensFix
Router works on click but 404s on reloadServer doesn't know client routesConfigure a fallback to index.html

Attaching scroll listeners for lazy loadingRuns constantly; jankyUse IntersectionObserver
Practice
  1. Build a three-route page with pushState navigation, working Back/Forward, and a not-found view.
  2. Lazy-load a grid of images with IntersectionObserver and verify in the Network panel that off-screen images aren't requested.
Key takeaways
  • Client routing = pushState + popstate + rendering by path; the server must fall back to your app.
  • Put shareable state in the URL using URL and URLSearchParams.
  • Observers and other built-in APIs replace many scroll and resize hacks.
