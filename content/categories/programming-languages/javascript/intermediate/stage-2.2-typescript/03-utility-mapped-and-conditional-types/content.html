Utility, Mapped & Conditional Types

Instead of copying and editing types by hand, derive new ones from existing types so the two can never drift apart.

§1Built-in Utility Types

TypeScript ships with helpers that transform object types. Using them keeps one source of truth: change User and everything derived from it updates.

type User = { id: number; name: string; email: string; password: string };

type PublicUser = Omit<User, "password">;            // everything except password
type Login = Pick<User, "email" | "password">;       // only these keys
type UserDraft = Partial<User>;                      // every field optional
type FullUser = Required<UserDraft>;                 // every field required
type ReadonlyUser = Readonly<User>;
type UserById = Record<number, User>;                // dictionary type

type Fn = (a: string) => number;
type Out = ReturnType<Fn>;                           // number
type Args = Parameters<Fn>;                          // [a: string]
type Resolved = Awaited<Promise<string>>;            // string

§2Mapped Types and keyof

A mapped type loops over the keys of another type and builds a new one. keyof T produces the union of its keys; T[K] looks up a property's type. This is how Partial and Readonly are written.

type Keys = keyof User;                               // "id" | "name" | "email" | "password"

type MyPartial<T> = { [K in keyof T]?: T[K] };         // make everything optional
type Nullable<T> = { [K in keyof T]: T[K] | null };

type Handlers = {
  [K in "click" | "hover" as `on${Capitalize<K>}`]: () => void;   // key remapping
};
// { onClick: () => void; onHover: () => void }

const routes = { home: "/", about: "/about" } as const;
type Route = (typeof routes)[keyof typeof routes];      // "/" | "/about" — derived from a value

§3Conditional Types

T extends U ? X : Y chooses a type based on another type. With infer you can pull a piece out of a type. They power utilities like ReturnType — most application code uses them sparingly.

type IsString<T> = T extends string ? true : false;
type A = IsString<"x">;     // true
type B = IsString<42>;      // false

type ElementOf<T> = T extends (infer E)[] ? E : never;
type N = ElementOf<number[]>;   // number

type NonNull<T> = T extends null | undefined ? never : T;   // distributes over unions
type C = NonNull<string | null>;                            // string

If a conditional type takes you more than a few minutes to read, consider whether a simpler design (an overload, a union, or a plain interface) would do. Cleverness has a maintenance cost.

Derive, don't duplicate Every hand-copied type is a future mismatch. Use typeof on a real value, and Pick/Omit/Partial on an existing type, so there is only one place to edit.

§4Common Mistakes

MistakeWhat HappensFix
Redefining a similar type by handThe two copies drift apart over timeDerive with Pick, Omit, or typeof
Forgetting as const on a config objectValues widen to string, losing literalsAdd as const before deriving types from it
Writing deeply nested conditional types for application codeUnreadable errors, slow compilePrefer simpler unions or overloads
Practice
  1. Given a Product type, derive ProductSummary (id and title only) and ProductUpdate (all fields optional except id).
  2. From const colors = { red: "#f00", blue: "#00f" } as const, derive a ColorName union and a ColorValue union.
Key takeaways
  • Pick, Omit, Partial, Required, Record, and ReturnType derive types from one source of truth.
  • Mapped types iterate keyof T; typeof on a value derives a type from data.
  • Conditional types are powerful but should stay rare in application code.
