The Node Runtime

Node wraps the V8 engine with APIs for files, networking, and processes — plus an event loop that makes non-blocking I/O the default.

§1What Node Adds

Node has no DOM, but it provides built-in modules imported with the node: prefix (node:fs, node:path, node:http, node:os, node:crypto), a global process, and — in current versions — fetch, AbortController, and structuredClone just like the browser.

import { readFile, writeFile } from "node:fs/promises";
import path from "node:path";
import { fileURLToPath } from "node:url";

const here = path.dirname(fileURLToPath(import.meta.url));   // ESM has no __dirname
const text = await readFile(path.join(here, "data.json"), "utf8");
await writeFile("out.txt", "hello\n");

process.argv.slice(2);          // command-line arguments
process.env.PORT ?? 3000;       // environment variables
process.exit(1);                // exit code: 0 = success

§2Sync, Callbacks, and Promises

Most Node APIs come in three forms. Use the promise version (node:fs/promises) by default. The Sync versions block the event loop — fine in a startup script, harmful inside a server handling requests.

import fs from "node:fs";
import fsp from "node:fs/promises";

fs.readFileSync("a.txt", "utf8");              // blocks everything
fs.readFile("a.txt", "utf8", (err, text) => {}); // callback style
await fsp.readFile("a.txt", "utf8");           // promise style — preferred

// Handle the failure you expect
try { await fsp.access("config.json"); }
catch (e) { if (e.code !== "ENOENT") throw e; }   // ENOENT = no such file

§3Streams and Process Lifecycle

Don't read a 2 GB file into memory — stream it. pipeline connects streams and propagates errors and cleanup. Handle signals so your process can shut down cleanly.

import { createReadStream, createWriteStream } from "node:fs";
import { createGzip } from "node:zlib";
import { pipeline } from "node:stream/promises";

await pipeline(
  createReadStream("big.log"),
  createGzip(),
  createWriteStream("big.log.gz"),
);                                              // constant memory, errors handled

process.on("SIGINT", async () => {              // Ctrl+C
  await server.close();
  process.exit(0);
});
process.on("unhandledRejection", (err) => { console.error(err); process.exit(1); });

Node is single-threaded for your JavaScript, but file and network I/O are done by the operating system and a thread pool, which is why a server can handle thousands of connections at once.

Server rule Never use *Sync APIs or long CPU loops inside a request handler. One blocked handler delays every other request, because they share a single JavaScript thread.

§4Common Mistakes

MistakeWhat HappensFix
Using readFileSync in a request handlerBlocks all other requests while it readsUse fs/promises and await
Using __dirname in an ES moduleReferenceErrorDerive it from import.meta.url
Reading a huge file with readFileMemory spike or crashStream it with pipeline
Practice
  1. Write a script that reads a JSON file given as a command-line argument and prints the number of top-level keys; exit with code 1 and a message if the file is missing.
  2. Gzip a large file with pipeline and compare the memory use with a readFile-based version.
Key takeaways
  • Node provides modules like fs, path, http, and a process global — same language, new host APIs.
  • Prefer promise APIs; never use Sync calls where concurrency matters.
  • Stream large data with pipeline, and handle signals for clean shutdown.
