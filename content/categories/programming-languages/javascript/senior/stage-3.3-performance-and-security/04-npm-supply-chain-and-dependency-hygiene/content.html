npm Supply Chain & Dependency Hygiene

Every dependency is code you run with your own privileges — so choosing, pinning, and auditing what you install is part of shipping securely.

§1The Risk

A typical app pulls in hundreds of packages through transitive dependencies. Attackers exploit that with typosquatting (lodahs), compromised maintainer accounts, malicious updates to previously good packages, dependency confusion (a public package that shadows a private name), and install scripts that run arbitrary code the moment you npm install.

# package.json lifecycle scripts run automatically on install:
#   "preinstall" / "install" / "postinstall"
# That means `npm install some-package` can run code on your laptop and CI runner.

# Block them by default, then allow only what's needed
# npm install --ignore-scripts
# npm config set ignore-scripts true

# See what you actually depend on
# npm ls --all | wc -l
# npm explain left-pad          # why is this installed?

§2Lockfiles, Auditing, and Updates

The lockfile records exact versions and integrity hashes, so installs are reproducible and tampering is detectable. Use npm ci in CI. Audit for known vulnerabilities, and update on purpose and in small steps with a bot (Dependabot, Renovate), reading the changelog of anything important.

# npm ci                        # install exactly the lockfile; fails on mismatch
# npm audit --omit=dev          # known vulnerabilities in production dependencies
# npm audit signatures          # verify registry signatures and provenance attestations
# npm outdated                  # what could be updated
# npm install pkg@1.2.3 --save-exact

# Review before updating: what changed in the tarball?
# npm diff --diff=pkg@1.2.3 --diff=pkg@1.2.4

# Newly published versions deserve a cooling-off period before you adopt them: many malicious
# releases are detected and removed within days. Some tools support a minimum release age setting.

Not every npm audit finding is exploitable in your usage — triage by whether the vulnerable code path is reachable. But a pile of unreviewed warnings trains everyone to ignore the next one.

§3Deciding What to Depend On

Treat adding a dependency as a decision with a cost: maintenance, update churn, supply-chain exposure, and bundle size. Ask the questions before npm install:

  • Can the platform or about 20 lines of my own code do this? (structuredClone, fetch, Array.prototype.at, crypto.randomUUID)
  • Is it actively maintained, widely used, and published with provenance? How many dependencies does it bring along?
  • Does it need install scripts or native binaries?
  • How hard is it to remove later? Wrap it behind your own small interface so it stays swappable.
// Wrap third-party libraries behind your own function
// date.js — the only file that imports the library
import { format } from "date-fns";
export const formatDate = (d) => format(d, "yyyy-MM-dd");

// Use publish-time protections on your own packages: 2FA on npm accounts,
// trusted publishing (provenance) from CI, and scoped, short-lived tokens
Reproducible installs If two machines can produce different node_modules from the same repo, you can't tell whether a bug or a compromise came from your code or from drift. The lockfile plus npm ci closes that gap.

§4Common Mistakes

MistakeWhat HappensFix
Running npm install instead of npm ci in CICan silently update versions; not reproducibleUse npm ci and commit the lockfile
Blindly accepting every Dependabot or npm audit fix changeBreaking or malicious changes slip inReview diffs and changelogs; test; update in small batches
Adding a package for something trivialMore attack surface and maintenance for little valuePrefer platform features or a few lines of your own code
Practice
  1. Run npm ls --all on a project, count the transitive dependencies, and pick one you could remove or replace with platform features.
  2. Set up a CI step that uses npm ci, runs npm audit --omit=dev, and fails on high-severity findings; document how you'd triage an alert.
Key takeaways
  • Dependencies run with your privileges — install scripts, typosquats, and hijacked packages are real attack paths.
  • Pin with a lockfile, install with npm ci, audit, and update deliberately after reading diffs.
  • Prefer platform features, vet maintenance and provenance, and wrap libraries behind your own interface.
