Values, Types & Coercion

JavaScript has seven primitive types plus objects, and the language will silently convert between them unless you use strict equality.

§1Primitives and Objects

The primitives are string, number, boolean, undefined, null, bigint, and symbol. They are immutable and compared by value. Everything else — arrays, functions, dates — is an object, compared by reference.

typeof "hi"        // "string"
typeof 42          // "number"
typeof 10n         // "bigint"
typeof undefined   // "undefined"
typeof null        // "object"   <- a historical bug, never fixed
typeof [1, 2]      // "object"
typeof (() => 1)   // "function"

Array.isArray([1, 2]) // true — the reliable array check

All numbers are 64-bit floats, so 0.1 + 0.2 is 0.30000000000000004. Use integers (cents, not dollars) or BigInt when exactness matters.

§2null vs. undefined

undefined means "no value has been assigned": a variable declared without a value, a missing property, a function that returns nothing. null is a deliberate "no value" that you assign yourself.

let a;
console.log(a);            // undefined
const user = { name: "Ana" };
console.log(user.age);     // undefined (missing property)

let selected = null;       // deliberately empty
console.log(null == undefined);  // true
console.log(null === undefined); // false

§3Coercion and ==

When operands have different types, == converts them using a long list of rules; === never converts. The + operator is the other trap: if either side is a string, it concatenates.

1 == "1"          // true   (string -> number)
0 == false        // true
"" == 0           // true
null == 0         // false  (null only == undefined)

1 + "2"           // "12"   (concatenation)
"5" - 2           // 3      (- only does math)
Number("42px")    // NaN
Number("  42 ")   // 42
NaN === NaN       // false  — use Number.isNaN(x)

Convert explicitly with Number(x), String(x), and Boolean(x) so the intent is visible, and default to === and !==.

Rule of thumb Use === everywhere. The one common exception is x == null, which is a compact way to check for both null and undefined.

§4Common Mistakes

MistakeWhat HappensFix
Using typeof x === "object" to detect objectsAlso true for null and arraysCheck x !== null too, or use Array.isArray
"10" + 5 when you want mathGives "105"Convert first: Number("10") + 5
Comparing to NaN with ===Always falseUse Number.isNaN(x)
Practice
  1. Predict, then check in the console: [] + [], [] == false, "b" + "a" + +"a" + "a". Explain each result.
  2. Write toNumber(input) that returns a number or null for blank or non-numeric strings, with no use of ==.
Key takeaways
  • Primitives are compared by value; objects by reference; typeof null is a known quirk.
  • == coerces by complicated rules — default to ===.
  • Convert types explicitly with Number(), String(), and Boolean().
