References, Copies & Immutability

Assigning an object copies the reference, not the object — so understanding shallow versus deep copies is essential to avoiding shared-state bugs.

§1Assignment Shares Objects

Primitives are copied by value. Objects and arrays are held by reference: two variables can point to the same object, and a change through one is visible through the other.

let x = 1;
let y = x;
y = 2;
console.log(x);        // 1 — primitives are copied

const a = { n: 1 };
const b = a;           // same object
b.n = 2;
console.log(a.n);      // 2

{ n: 1 } === { n: 1 }; // false — different objects
const list = [1, 2];
function addOne(arr) { arr.push(1); }   // mutates the caller's array
addOne(list);
console.log(list);     // [1, 2, 1]

§2Shallow Copies

Spread, Object.assign, slice, and Array.from copy only the top level. Nested objects remain shared between the original and the copy.

const original = { name: "Ana", address: { city: "Lyon" } };
const copy = { ...original };

copy.name = "Bo";              // original.name stays "Ana"
copy.address.city = "Paris";   // original.address.city is now "Paris" too!

const arr = [[1], [2]];
const arrCopy = [...arr];
arrCopy[0].push(9);            // arr[0] changed as well

§3Deep Copies and Immutability

structuredClone makes a true deep copy of plain data, handling nested objects, arrays, Maps, Sets, Dates, and cycles. It cannot clone functions or class instances' methods. The old JSON.parse(JSON.stringify(x)) trick loses Dates, undefined, and more.

const deep = structuredClone(original);
deep.address.city = "Rome";    // original is unaffected

// Immutable-style updates: copy each level you change
const next = {
  ...original,
  address: { ...original.address, city: "Rome" },
};

const frozen = Object.freeze({ a: 1, nested: { b: 2 } });
frozen.a = 5;                  // ignored (TypeError in strict mode)
frozen.nested.b = 3;           // allowed — freeze is shallow

Treating data as immutable — producing new objects instead of editing in place — makes changes easy to track and is the foundation of state management in UI frameworks.

Debugging tip If changing one thing changes another, you almost certainly have two names for one object. a === b tells you whether two variables are the same reference.

§4Common Mistakes

MistakeWhat HappensFix
Treating const copy = original as a copyBoth names refer to one objectUse spread or structuredClone
Mutating function argumentsThe caller's data changes unexpectedlyCopy first, or return a new value
Using JSON.parse(JSON.stringify(x)) for deep copyDrops undefined, functions, and turns Dates into stringsUse structuredClone(x)
Practice
  1. Write setCity(user, city) that returns an updated copy of a nested user object without changing the original; prove it with === checks.
  2. Show a case where { ...obj } fails to protect the original, then fix it with structuredClone.
Key takeaways
  • Objects and arrays are assigned by reference; primitives by value.
  • Spread and slice are shallow — nested data stays shared.
  • Use structuredClone for deep copies and build new objects instead of mutating.
