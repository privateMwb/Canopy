Objects, Destructuring & Spread

Objects are keyed collections; destructuring and spread let you pull data out and build modified copies concisely.

§1Creating and Accessing Objects

Object literals support shorthand properties, computed keys, and shorthand methods. Use dot access for fixed names and brackets for dynamic ones.

const name = "Ana", age = 30;
const key = "role";
const user = {
  name,                   // shorthand for name: name
  age,
  [key]: "admin",         // computed key
  greet() { return `Hi ${this.name}`; },
};

user.name;                // "Ana"
user["age"];              // 30
user.missing;             // undefined
"name" in user;           // true
delete user.age;

Object.keys(user);        // ["name", "role", "greet"]
Object.entries(user);     // [["name", "Ana"], ...]
Object.fromEntries([["a", 1], ["b", 2]]);  // { a: 1, b: 2 }

§2Destructuring

Destructuring unpacks properties or array items into variables, with renaming, defaults, and nesting. It works in function parameters too, which makes options objects pleasant to read.

const { name, role = "guest", address: { city } = {} } = user;
const { name: userName } = user;          // rename

const [first, , third, ...others] = [1, 2, 3, 4, 5];
let a = 1, b = 2;
[a, b] = [b, a];                          // swap

function connect({ host, port = 80, secure = false } = {}) {
  return `${secure ? "https" : "http"}://${host}:${port}`;
}
connect({ host: "example.com" });         // "http://example.com:80"

§3Spread and Rest for Objects

Spread copies an object's own enumerable properties into a new one. Later keys win, which makes it ideal for "copy with changes". The copy is shallow: nested objects are still shared.

const base = { theme: "dark", size: 12 };
const updated = { ...base, size: 14 };        // { theme: "dark", size: 14 }
const merged = { ...defaults, ...overrides }; // overrides win

const { password, ...safeUser } = user;       // rest: everything but password

const withoutKey = Object.fromEntries(
  Object.entries(user).filter(([k]) => k !== "role")
);

Use Object.hasOwn(obj, key) rather than obj.hasOwnProperty(key) to test for an own property.

Watch out Spread order matters: { ...a, ...b } lets b overwrite a, but { ...b, ...a } does the opposite. Put defaults first and overrides last.

§4Common Mistakes

MistakeWhat HappensFix
Destructuring null or undefinedTypeError: Cannot destructureProvide a default: const { x } = obj ?? {}
Assuming { ...obj } is a deep copyNested objects are still shared with the originalSpread each nested level, or use structuredClone
Using an object key that is not a valid identifier with dot syntaxSyntax errorUse brackets: obj["first-name"]
Practice
  1. Write pick(obj, keys) that returns a new object with only the listed keys.
  2. Write a function renderCard({ title, subtitle = "", tags = [] }) and call it with a partial object.
Key takeaways
  • Shorthand properties, computed keys, and Object.entries cover most object work.
  • Destructuring (with renames and defaults) extracts data and documents function inputs.
  • Spread makes shallow copies and merges; later keys override earlier ones.
