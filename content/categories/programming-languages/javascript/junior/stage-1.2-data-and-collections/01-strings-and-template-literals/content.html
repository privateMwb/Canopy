Strings & Template Literals

Strings are immutable sequences of UTF-16 code units, with a rich set of methods and template literals for building text cleanly.

§1Working with Strings

Strings are immutable: every method returns a new string and leaves the original alone. Index with [] or .at() (which accepts negative numbers).

const s = "  Hello, World  ";
s.trim();                    // "Hello, World"
s.trim().toLowerCase();      // "hello, world"
"a,b,c".split(",");          // ["a", "b", "c"]
["a", "b"].join("-");        // "a-b"
"hello".slice(1, 3);         // "el"
"hello".at(-1);              // "o"
"hello".includes("ell");     // true
"hello".startsWith("he");    // true
"abc".padStart(5, "0");      // "00abc"
"ha".repeat(3);              // "hahaha"
"a-b-c".replaceAll("-", "+"); // "a+b+c"

const t = "hi";
t[0] = "H";                  // silently ignored (throws in strict mode)

§2Template Literals

Backticks give you interpolation with ${}, multi-line strings, and no escaping of quotes. Any expression works inside ${}.

const name = "Ana", items = 3;
const msg = `Hi ${name}, you have ${items} item${items === 1 ? "" : "s"}.`;

const html = `
  <ul>
    <li>${name}</li>
  </ul>`;

// Number formatting belongs to Intl, not hand-rolled string code
(1234567.891).toLocaleString("en-US");              // "1,234,567.891"
new Intl.NumberFormat("en-US", { style: "currency", currency: "USD" }).format(9.5); // "$9.50"

§3Unicode and Building Text Safely

JavaScript strings are UTF-16, so characters outside the basic plane (most emoji) take two code units. length counts code units, not characters. Iterating with for...of or spreading walks code points.

const s = "a😀";
s.length;                    // 3  (😀 is two code units)
[...s].length;               // 2  (code points)
s.codePointAt(1);            // 128512
"é".normalize("NFD").length; // 2 — e plus a combining accent
"é".normalize("NFC").length; // 1

Never build HTML or SQL by gluing user input into strings. Insert text with element.textContent = value and use parameterized queries; interpolating untrusted text into markup is how XSS and injection happen.

Remember Because strings are immutable, building one in a loop with += creates many intermediates. For a lot of pieces, collect them in an array and join once — it is both clearer and usually faster.

§4Common Mistakes

MistakeWhat HappensFix
Calling s.toUpperCase() and ignoring the results is unchangedAssign it: s = s.toUpperCase()
Using .length as a character count for emoji textCounts UTF-16 units, so it's too largeUse [...s].length or Intl.Segmenter
Putting user input into a template string and assigning it to innerHTMLScript injection (XSS)Use textContent, or escape the input
Practice
  1. Write titleCase(str) that capitalizes the first letter of each word without mutating the input.
  2. Write truncate(str, n) that cuts to n characters and adds …, then test it with a string containing an emoji.
Key takeaways
  • Strings are immutable; methods return new strings.
  • Template literals handle interpolation and multi-line text; use Intl for numbers and dates.
  • length counts UTF-16 code units, and untrusted text must never be inserted as HTML.
