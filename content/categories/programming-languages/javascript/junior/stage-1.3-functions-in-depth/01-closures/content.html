Closures

A closure is a function that keeps access to the variables of the scope where it was created, even after that scope has finished running.

§1Functions Remember Their Scope

When a function is created, it captures a reference to the variables around it. Calling it later still reads and writes those variables — they aren't copied, and they aren't destroyed while the function is reachable.

function makeCounter() {
  let count = 0;                 // private to each counter
  return () => ++count;
}

const a = makeCounter();
const b = makeCounter();
a(); a();                        // 1, 2
b();                             // 1 — separate closure, separate count
// There is no way to touch `count` from outside.

§2Practical Uses

Closures give you private state, function factories, and partial application without needing classes. Many common utilities are closures: once, debounce, and memoization.

function once(fn) {
  let called = false, result;
  return (...args) => {
    if (!called) { called = true; result = fn(...args); }
    return result;
  };
}
const init = once(() => { console.log("setup"); return 42; });
init(); init();                  // logs "setup" a single time

function debounce(fn, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), ms);
  };
}

§3The Loop-Variable Bug

With var, a loop has one shared variable, so every callback created inside it sees the final value. let creates a new binding for each iteration, which is why modern code rarely hits this.

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));   // 3, 3, 3
}
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j));   // 0, 1, 2
}

// The pre-ES6 workaround: an IIFE creating a new scope per iteration
for (var k = 0; k < 3; k++) {
  ((n) => setTimeout(() => console.log(n)))(k);
}

Because closures hold references, a closure that captures a large object keeps it alive. That's usually fine, but it is the root of many memory leaks (revisited in the senior track).

The key insight A closure captures variables, not values. If the variable changes later, the closure sees the new value — which is both its power and the source of the loop bug.

§4Common Mistakes

MistakeWhat HappensFix
Creating callbacks in a var loopAll callbacks see the loop's final valueUse let
Expecting a closure to snapshot a valueIt sees later changes to the variableCopy the value into a new const inside the loop
Keeping a closure around that captures a huge objectObject can't be garbage collectedCapture only what you need, or release the reference

  1. Write makeAccount(balance) returning deposit, withdraw, and getBalance, with the balance impossible to change directly.
  2. Write memoize(fn) that caches results by argument using a closure over a Map.
Key takeaways
  • A closure is a function plus the variables of the scope it was created in.
  • Closures enable private state, factories, once, debounce, and memoization.
  • They capture variables by reference, which explains the var loop bug.
