async/await & fetch

async/await lets you write promise-based code that reads top to bottom, and fetch is the built-in way to call an HTTP API.

§1async and await

An async function always returns a promise. Inside it, await pauses *that function* until a promise settles, then gives you the value (or throws the rejection). The rest of the program keeps running while it waits.

async function loadUserPosts(id) {
  try {
    const user = await getUser(id);
    const posts = await getPosts(user);
    return posts.length;
  } catch (err) {
    console.error("failed:", err);
    return 0;
  }
}

loadUserPosts(1).then((n) => console.log(n));
// Top-level await works in ES modules:  const data = await load();

§2Calling an API with fetch

fetch returns a promise for a Response. Important: it only rejects on network failure. A 404 or 500 still resolves, so check response.ok. Parsing the body is another async step.

async function getJson(url) {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

const todo = await getJson("https://jsonplaceholder.typicode.com/todos/1");

await fetch("/api/todos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Write lesson" }),
});

§3Sequential vs. Parallel

Each await waits for the previous one. If two requests don't depend on each other, start both first, then await them together with Promise.all.

// Slow: total time = a + b
const a = await getJson("/a");
const b = await getJson("/b");

// Fast: total time = max(a, b)
const [a2, b2] = await Promise.all([getJson("/a"), getJson("/b")]);

// await inside forEach does NOT wait — use for...of or Promise.all
for (const id of ids) await save(id);                   // one at a time
await Promise.all(ids.map((id) => save(id)));           // all at once

Promise.all rejects as soon as any input rejects. The next stages cover allSettled, cancellation, and limiting concurrency.

The big fetch gotcha fetch doesn't throw on HTTP errors. A 404 or 500 is a *successful* fetch from the promise's point of view — always check res.ok.

§4Common Mistakes

MistakeWhat HappensFix
Not checking res.okError pages are parsed as if they were dataThrow when !res.ok
Awaiting independent requests one after anotherNeedlessly slowStart together with Promise.all
Using await inside arr.forEach(async ...)forEach doesn't wait; the code continues earlyUse for...of or Promise.all(arr.map(...))
Practice
  1. Write getJson(url) that throws on non-OK responses, then fetch two URLs in parallel and print both results.
  2. Add try/catch around a call that fails (bad URL) and show the user-facing message in the page instead of the console.
Key takeaways
  • async functions return promises; await pauses only that function.
  • fetch resolves for HTTP errors — check res.ok and parse the body with res.json().
  • Use Promise.all for independent requests instead of awaiting them sequentially.
