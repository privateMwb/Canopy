Iterating, Comparable & Comparator

Collections can be walked with a for-each loop or an Iterator, and sorting objects requires telling Java how they should be ordered, either naturally with Comparable or case by case with Comparator.

§1Iteration

The for-each loop works on anything that implements Iterable. Under the hood it uses an Iterator, which you can use directly when you need to remove elements safely during traversal.

List<String> names = new ArrayList<>(List.of("Ada", "Bob", "Cy"));
for (String n : names) { System.out.println(n); }

Iterator<String> it = names.iterator();
while (it.hasNext()) {
    if (it.next().startsWith("B")) it.remove();       // the safe way to delete while iterating
}

Map<String, Integer> m = Map.of("a", 1, "b", 2);
for (String key : m.keySet()) { }
for (int v : m.values()) { }
m.forEach((k, v) -> System.out.println(k + "=" + v));

§2Natural Order with Comparable

A class that has one obvious ordering implements Comparable<T> with a compareTo method that returns a negative number, zero, or a positive number. Collections.sort, List.sort(null), and TreeSet use it.

public class Version implements Comparable<Version> {
    private final int major, minor;
    public Version(int major, int minor) { this.major = major; this.minor = minor; }

    @Override public int compareTo(Version o) {
        int c = Integer.compare(major, o.major);          // never subtract: it can overflow
        return c != 0 ? c : Integer.compare(minor, o.minor);
    }
}

List<Version> vs = new ArrayList<>(List.of(new Version(1, 9), new Version(1, 2)));
Collections.sort(vs);                                      // [1.2, 1.9]

compareTo should be consistent with equals: if a.compareTo(b) == 0, then a.equals(b) should be true. Otherwise TreeSet will treat "different" objects as duplicates.

§3Many Orders with Comparator

When there are several valid orderings, or you can't change the class, supply a Comparator. Build one with Comparator.comparing and chain tie-breakers with thenComparing.

record Person(String name, int age) { }

List<Person> people = new ArrayList<>(List.of(
    new Person("Bob", 30), new Person("Ada", 30), new Person("Cy", 25)));

people.sort(Comparator.comparing(Person::age));                       // by age
people.sort(Comparator.comparing(Person::age).reversed());            // oldest first
people.sort(Comparator.comparingInt(Person::age)
                      .thenComparing(Person::name));                  // age, then name
people.sort(Comparator.comparing(Person::name, String.CASE_INSENSITIVE_ORDER));
people.sort(Comparator.comparing(Person::name,
                      Comparator.nullsLast(Comparator.naturalOrder())));

Sorting is stable for objects (List.sort and Collections.sort use a stable merge-based sort), so equal elements keep their original relative order.

Never subtract to compare return a - b; looks clever but overflows for large or opposite-sign values and gives the wrong answer silently. Use Integer.compare(a, b) or Comparator.comparingInt.

§4Common Mistakes

MistakeWhat HappensFix
Removing from a list inside a for-eachConcurrentModificationExceptionUse Iterator.remove() or removeIf
Writing compareTo as a - bOverflow gives wrong orderingUse Integer.compare
compareTo inconsistent with equalsTreeSet drops "distinct" items that compare as equalCompare all fields that equals uses
Sorting a list of objects that aren't ComparableClassCastExceptionPass a Comparator, or implement Comparable
Comparing by a nullable fieldNullPointerException while sortingWrap with Comparator.nullsFirst or nullsLast
Practice
  1. Sort a list of Employee records by department, then by salary descending, then by name, using thenComparing.
  2. Implement Comparable for a Card class (rank, then suit) and sort a shuffled deck.
  3. Write a TreeSet<String> with String.CASE_INSENSITIVE_ORDER and observe how it treats "a" and "A".
Key takeaways
  • For-each uses Iterator; use the iterator or removeIf to delete during traversal.
  • Comparable defines one natural ordering; Comparator defines any number of external orderings.
  • Build comparators with comparing and thenComparing, and never compare numbers by subtracting.
