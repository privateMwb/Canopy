Control Flow & Methods

Conditionals, loops, and methods let a program make decisions and repeat work, and modern switch expressions make multi-way decisions far safer than the old statement form.

§1Conditionals and Loops

if/else, for, while, and do/while behave as in most C-family languages. The condition must be a real boolean; Java will not treat 0 or null as false. The enhanced for loop walks any array or collection without an index.

int score = 82;
if (score >= 90) {
    System.out.println("A");
} else if (score >= 80) {
    System.out.println("B");
} else {
    System.out.println("keep going");
}

for (int i = 0; i < 3; i++) { System.out.println(i); }

int[] nums = {4, 8, 15};
for (int n : nums) { System.out.println(n); }    // for-each

int tries = 0;
while (tries < 3) { tries++; }

break leaves the loop, continue skips to the next iteration. Always use braces, even for one-line bodies; leaving them out is how "goto fail"-style bugs happen.

§2switch Expressions

The old switch statement falls through to the next case unless you remember break. The modern switch expression uses ->, has no fall-through, and produces a value. The compiler checks that every possible input is covered.

enum Day { MON, TUE, SAT, SUN }

String kind = switch (day) {
    case SAT, SUN -> "weekend";
    case MON, TUE -> "weekday";
};                                  // no default needed: all enum values covered

int len = switch (word) {
    case "one" -> 3;
    case "three" -> 5;
    default -> { 
        System.out.println("unknown word");
        yield -1;                   // yield returns a value from a block
    }
};

§3Methods

A method has a return type, a name, parameters, and a body. Java is pass-by-value: the method gets a copy of each argument. For a reference, the copy is a copy of the pointer, so the method can change the object it points to, but it cannot make the caller's variable point somewhere else.

static int max(int a, int b) { return a > b ? a : b; }

static void rename(StringBuilder sb) { sb.append("!"); }     // mutates the shared object
static void reassign(StringBuilder sb) { sb = new StringBuilder("x"); }  // caller unaffected

static int sum(int... values) {     // varargs
    int t = 0;
    for (int v : values) t += v;
    return t;
}

Overloading lets several methods share a name if their parameter lists differ; the compiler picks one at compile time based on the argument types.

Pass-by-value, always Java never passes variables by reference. When you pass an object, you pass a copy of the pointer. Both pointers reach the same object, so mutations are visible, but reassigning the parameter is not.

§4Common Mistakes

MistakeWhat HappensFix
Using = instead of == in a conditionCompile error for most types; a silent bug with booleanCompare with ==, and keep conditions simple
Old-style switch without breakExecution falls through into the next caseUse arrow-form cases, which never fall through
Off-by-one in a for loop boundArrayIndexOutOfBoundsException or a missed elementUse i < arr.length, or a for-each loop
Expecting a method to reassign the caller's variableThe caller's variable is unchangedReturn the new value and assign it at the call site
Skipping braces on if bodiesA second line looks guarded but isn'tAlways write the braces
Practice
  1. Write static String fizzBuzz(int n) returning "Fizz", "Buzz", "FizzBuzz", or the number as a string, using a switch expression or if-chain. Print 1 to 30.
  2. Write static int sum(int... values) and call it with zero, one, and many arguments.
  3. Write two methods, one that appends to a StringBuilder and one that reassigns it, and explain the difference in what the caller sees.
Key takeaways
  • Conditions must be boolean, and switch expressions with -> avoid fall-through and can be checked for completeness.
  • Java is strictly pass-by-value; for objects the value is a reference.
  • Overloads are chosen at compile time from the declared argument types.
