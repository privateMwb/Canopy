Types, Variables & Operators

Java has eight primitive types that hold raw values and a much larger world of reference types that point to objects, and mixing them up is the source of many early bugs.

§1Primitives and References

The primitives are byte, short, int, long, float, double, char, and boolean. A primitive variable holds the value itself. Everything else (String, arrays, every class you write) is a reference type: the variable holds a pointer to an object on the heap, or null.

int count = 3;                 // the value 3 lives in the variable
double price = 19.99;
char grade = 'A';              // single quotes: char; double quotes: String
boolean done = false;
long big = 3_000_000_000L;     // L suffix required beyond the int range

String name = "Ada";           // reference to a String object
String none = null;            // points to nothing
var total = 42;                // var infers int; the type is still static

int is 32 bits (about ±2.1 billion) and long is 64 bits. Underscores in numeric literals are just for readability. var lets the compiler infer a local variable's type; Java stays statically typed, because the type is fixed at compile time.

§2Conversions

Going from a smaller type to a larger one (widening) is automatic. Going the other way (narrowing) can lose information, so you must write a cast and accept the risk.

int i = 7;
double d = i;                  // widening: fine
int back = (int) 9.99;         // narrowing: truncates to 9, no rounding
long l = 1L << 40;
int bad = (int) l;             // overflows silently: 0
int half = 7 / 2;              // 3 — integer division truncates
double real = 7 / 2.0;         // 3.5 — one double operand makes it floating-point

§3Overflow and Floating Point

Integer arithmetic wraps around without any error. Integer.MAX_VALUE + 1 is Integer.MIN_VALUE. If you need to detect overflow, use Math.addExact and friends, which throw ArithmeticException. Floating point is binary, so many decimals cannot be represented exactly.

int max = Integer.MAX_VALUE;
System.out.println(max + 1);              // -2147483648
System.out.println(Math.addExact(max, 1)); // throws ArithmeticException
System.out.println(0.1 + 0.2);            // 0.30000000000000004

For money, avoid double; use BigDecimal or store whole cents in a long.

Primitives vs. references == on primitives compares values. == on references compares identity: whether both variables point at the very same object. That is why strings are compared with equals, which the next lessons return to.

§4Common Mistakes

MistakeWhat HappensFix
Dividing two ints and expecting a fraction7 / 2 gives 3Make one operand a double: 7 / 2.0
Ignoring overflowA large sum silently becomes negativeUse long, or Math.addExact to fail loudly
Comparing doubles with ==0.1 + 0.2 == 0.3 is falseCompare with a tolerance, or use BigDecimal
Using double for moneyRounding errors accumulateUse BigDecimal or integer cents
Forgetting L on a big literalinteger number too large compile errorWrite 3_000_000_000L
Practice
  1. Predict, then run: System.out.println(10 / 4), 10 / 4.0, 10 % 4, (int) 3.99, and (char) ('a' + 1).
  2. Write a loop that doubles an int starting from 1 and prints each value. Note what happens after 30 doublings, then switch to Math.multiplyExact.
Key takeaways
  • Primitives store values; reference types store a pointer to an object or null.
  • Widening is automatic; narrowing needs a cast and can silently lose data.
  • Integer overflow wraps silently; use the *Exact methods when it matters, and never use double for money.
