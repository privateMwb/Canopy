The Streams API

A stream describes a pipeline of operations over a sequence of data, which is evaluated lazily when you ask for a result, and it is clearer than a loop for filter-map-collect work but not for everything.

§1Source, Intermediate Operations, Terminal Operation

A stream pipeline has three parts: a source (a collection, array, or generator), zero or more intermediate operations that each return another stream, and one terminal operation that produces the result. Nothing runs until the terminal operation is called.

List<String> words = List.of("apple", "fig", "banana", "kiwi", "cherry");

List<String> result = words.stream()
    .filter(w -> w.length() > 3)           // intermediate
    .map(String::toUpperCase)              // intermediate
    .sorted()                              // intermediate
    .toList();                             // terminal: [APPLE, BANANA, CHERRY, KIWI]

long count = words.stream().filter(w -> w.startsWith("b")).count();
boolean anyShort = words.stream().anyMatch(w -> w.length() < 4);   // short-circuits
Optional<String> first = words.stream().filter(w -> w.contains("r")).findFirst();

Common intermediate operations are filter, map, flatMap, distinct, sorted, limit, skip, and peek. Common terminal operations are forEach, collect, toList, reduce, count, min/max, anyMatch/allMatch/noneMatch, and findFirst.

§2Laziness and Single Use

Because intermediate operations are lazy, the stream processes elements one at a time through the whole pipeline, and short-circuiting operations stop early. A stream can be consumed only once; reusing it throws IllegalStateException.

Stream.of("a", "bb", "ccc", "dddd")
      .filter(s -> { System.out.println("filter " + s); return s.length() > 1; })
      .map(s -> { System.out.println("map " + s); return s.toUpperCase(); })
      .findFirst();                         // prints filter a, filter bb, map bb, then stops

Stream<String> s = words.stream();
s.count();
// s.count();                               // IllegalStateException: already consumed

§3Numbers, flatMap, and reduce

Primitive streams (IntStream, LongStream, DoubleStream) avoid boxing and add sum, average, and range. flatMap flattens a stream of collections into one stream. reduce folds elements into a single value.

int total = IntStream.rangeClosed(1, 100).sum();                        // 5050
double avg = words.stream().mapToInt(String::length).average().orElse(0);
List<Integer> flat = Stream.of(List.of(1, 2), List.of(3), List.<Integer>of())
                           .flatMap(List::stream).toList();             // [1, 2, 3]
int sumSquares = Stream.of(1, 2, 3).reduce(0, (acc, n) -> acc + n * n); // 14

§4When Not to Use a Stream

Streams shine for transformations of data. They are a poor fit when you need to mutate local state, use indexes, break out early with complex conditions, or deal with checked exceptions. Don't put side effects in map or filter; use forEach only at the end.

// clearer as a loop:
int sum = 0;
for (int i = 0; i < arr.length; i++) { if (i % 2 == 0) sum += arr[i]; }

// bad: side effect inside a stream
List<String> out = new ArrayList<>();
words.stream().filter(w -> w.length() > 3).forEach(out::add);   // prefer .toList()

Parallel streams (parallelStream()) split work across the common thread pool. They help only for large, CPU-bound, side-effect-free work on easily split data; for small or I/O-bound tasks they are usually slower and can hurt other work sharing the pool. Measure before using them.

A stream is a recipe, not a collection Building a pipeline does no work and stores no data. This is what makes streams efficient, and why a pipeline with no terminal operation silently does nothing.

§5Common Mistakes

MistakeWhat HappensFix
Forgetting a terminal operationNothing happens at allEnd with toList(), collect, count, etc.
Reusing a streamIllegalStateExceptionCreate a new stream from the source each time
Putting side effects in map or filterOrder-dependent behavior, and broken under parallelismKeep intermediate operations pure
Using parallelStream() by defaultSlower for small data and starves the shared poolMeasure first, and use only for heavy CPU work
Forcing complex logic into a long chainUnreadableExtract named methods or write a loop
Practice
  1. Given a list of Order records, find the total of all orders above 100 using a stream, then write the same thing as a loop and compare readability.
  2. Use flatMap to produce all distinct words from a list of sentences.
  3. Add peek calls to a pipeline with limit(2) to see exactly which elements get processed.
Key takeaways
  • A pipeline is source, intermediate operations, and one terminal operation; nothing runs until the terminal call.
  • Streams are lazy, single-use, and should keep intermediate steps free of side effects.
  • Choose a stream when it expresses a transformation clearly, and a loop when it doesn't.
