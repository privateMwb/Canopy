Collectors & Optional in Depth

Collectors turn a stream into a map, a grouping, or a summary, and Optional is best used by composing it with map, flatMap, and orElse rather than unwrapping it with get().

§1Collecting to Collections

Stream.toList() returns an unmodifiable list. For other shapes, use collect with a Collector from the Collectors class.

record Employee(String name, String dept, double salary) { }
List<Employee> staff = List.of(
    new Employee("Ada", "Eng", 150), new Employee("Bob", "Eng", 120),
    new Employee("Cy", "Ops", 90), new Employee("Di", "Ops", 100));

Set<String> depts = staff.stream().map(Employee::dept).collect(Collectors.toSet());
Map<String, Double> salaryByName = staff.stream()
    .collect(Collectors.toMap(Employee::name, Employee::salary));
String names = staff.stream().map(Employee::name).collect(Collectors.joining(", ", "[", "]"));

toMap throws IllegalStateException on a duplicate key unless you supply a merge function as a third argument.

§2groupingBy and partitioningBy

groupingBy buckets elements by a classifier and, with a downstream collector, summarizes each bucket. partitioningBy splits into exactly two groups, true and false.

Map<String, List<Employee>> byDept = staff.stream()
    .collect(Collectors.groupingBy(Employee::dept));

Map<String, Long> countByDept = staff.stream()
    .collect(Collectors.groupingBy(Employee::dept, Collectors.counting()));

Map<String, Double> avgSalary = staff.stream()
    .collect(Collectors.groupingBy(Employee::dept, Collectors.averagingDouble(Employee::salary)));

Map<String, List<String>> namesByDept = staff.stream()
    .collect(Collectors.groupingBy(Employee::dept,
             Collectors.mapping(Employee::name, Collectors.toList())));

Map<String, Optional<Employee>> topPaid = staff.stream()
    .collect(Collectors.groupingBy(Employee::dept,
             Collectors.maxBy(Comparator.comparingDouble(Employee::salary))));

Map<Boolean, List<Employee>> highLow = staff.stream()
    .collect(Collectors.partitioningBy(e -> e.salary() >= 110));

Map<String, Double> sorted = staff.stream()                // keep a specific map type
    .collect(Collectors.groupingBy(Employee::dept, TreeMap::new,
             Collectors.summingDouble(Employee::salary)));

Other useful collectors include summarizingDouble (count, sum, min, average, max in one pass), reducing, collectingAndThen, filtering, and flatMapping. In recent JDKs, Stream.mapMulti and gatherers extend what a pipeline can do when the built-in operations fall short.

§3Optional, Composed

The point of Optional is to avoid the isPresent()/get() pair, which is just a null check wearing a costume. Instead, describe what to do with a value, and let the Optional handle emptiness.

Optional<Employee> maybe = staff.stream().filter(e -> e.name().equals("Cy")).findFirst();

String dept = maybe.map(Employee::dept).orElse("unknown");
double pay = maybe.map(Employee::salary).orElseGet(() -> expensiveDefault());   // lazy default
Employee e = maybe.orElseThrow(() -> new NoSuchElementException("Cy not found"));
maybe.ifPresentOrElse(x -> System.out.println(x.name()), () -> System.out.println("none"));

Optional<String> email = findUser(id).flatMap(User::email);   // email() itself returns Optional
Optional<Employee> either = maybe.or(() -> findBackup());
Optional<Employee> highEarner = maybe.filter(x -> x.salary() > 100);
List<String> present = Stream.of(maybe, Optional.<Employee>empty())
                             .flatMap(Optional::stream).map(Employee::name).toList();

Use orElse for cheap constant defaults and orElseGet when the default is expensive to compute, because orElse(x) evaluates x even when the value is present.

map vs. flatMap Use map when the function returns a plain value; use flatMap when it returns another Optional (or stream). Mapping with a function that returns Optional gives you the awkward Optional<Optional<T>>.

§4Common Mistakes

MistakeWhat HappensFix
Collectors.toMap with duplicate keysIllegalStateException: Duplicate keyProvide a merge function, or use groupingBy
Calling isPresent() then get()Verbose and no better than a null checkUse map, orElse, ifPresentOrElse
orElse(expensiveCall())The call runs even when a value existsUse orElseGet(() -> expensiveCall())
Using map where flatMap is neededA nested Optional<Optional<T>>Use flatMap
Expecting groupingBy to return a sorted or ordered mapUnspecified HashMap orderingPass a map factory such as TreeMap::new
Practice
  1. From a list of transactions, produce a Map<String, Double> of total spent per customer, then print the top three customers.
  2. Use partitioningBy to split numbers into primes and non-primes, and counting() as the downstream collector.
  3. Rewrite a chain of null checks like a != null && a.b() != null && a.b().c() != null as an Optional pipeline.
Key takeaways
  • groupingBy and partitioningBy with downstream collectors replace most hand-written aggregation loops.
  • toMap needs a merge function when keys can repeat.
  • Compose Optionals with map, flatMap, filter, or, and orElseGet instead of isPresent() and get().
