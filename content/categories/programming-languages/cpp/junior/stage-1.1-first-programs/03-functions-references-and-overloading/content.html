Functions, References & Overloading

How you pass an argument decides whether a function copies it, can change it, or only reads it, and the signature should say which.

§1Pass by Value, Reference, and Const Reference

By default C++ copies arguments. A reference parameter is an alias for the caller's object, so no copy is made and writes are visible to the caller.

void byValue(int x)         { x += 1; }       // changes the copy only
void byRef(int& x)          { x += 1; }       // changes the caller's variable
void byConstRef(const int& x) { /* read-only */ }

int n{1};
byValue(n);   // n still 1
byRef(n);     // n now 2

The convention to memorize: small cheap types (int, double, pointers) go by value; larger objects you only read go by const T&; objects the function must modify go by T&.

double average(const std::vector<double>& v);   // no copy of the vector
void   sortInPlace(std::vector<double>& v);     // clearly mutates

A const T& can bind to a temporary, so average({1.0, 2.0}) works. A non-const T& cannot.

§2Returning Values

Return by value. Modern compilers avoid the copy, and returning a local by reference is a bug because the local is destroyed on return.

std::string greet(const std::string& name) { return "Hello, " + name; }

const std::string& bad() { std::string s{"x"}; return s; }   // dangling reference

§3Default Arguments and Overloading

Default arguments go in the declaration. Overloading lets several functions share a name when their parameter lists differ.

void print(int x)          { std::cout << "int " << x << '\n'; }
void print(double x)       { std::cout << "double " << x << '\n'; }
void print(const std::string& s) { std::cout << "string " << s << '\n'; }

print(3);       // int
print(3.0);     // double
print("hi");    // string, via implicit conversion from const char*
void connect(const std::string& host, int port = 80);

The compiler picks the best match: exact match first, then promotions, then conversions. If two overloads are equally good the call is ambiguous and does not compile. The return type is never part of overload resolution.

The key insight A function signature is documentation. const T& says "I only read this," T& says "I will change this," and plain T says "I need my own copy."

§4Common Mistakes

MistakeWhat HappensFix
Passing a large std::vector by valueA full copy on every callUse const std::vector<T>&
Returning a reference to a local variableDangling reference; undefined behaviorReturn by value
Overloading on print(int) and print(long) then calling print(3u)Ambiguous call errorAdd an exact overload or cast the argument
Practice
  1. Write swap(int&, int&) and use it. Then explain why a by-value version cannot work.
  2. Overload area for a circle (one double) and a rectangle (two doubles).
  3. Make bad() above compile with warnings on, and read what the compiler says about it.
Key takeaways
  • Pass cheap types by value, read-only objects by const T&, and mutated objects by T&.
  • Return by value; never return a reference to a local.
  • Overloads are chosen by arguments only, and equal matches make a call ambiguous.
