Maps, Sets & Unordered Containers

The standard library offers sorted and hashed associative containers, and picking between them is about ordering needs and key properties.

§1std::map and std::set

std::map<K, V> stores key-value pairs sorted by key, usually as a balanced tree. std::set<K> stores sorted unique keys. Lookup, insert, and erase are O(log n), and iteration visits keys in order.

#include <map>
std::map<std::string, int> age;
age["Ada"] = 36;
age.insert({"Alan", 41});
for (const auto& [name, years] : age)        // structured bindings
    std::cout << name << ' ' << years << '\n';   // in sorted key order

operator[] inserts a default value if the key is missing, which is handy for counting but surprising for lookups.

std::map<std::string, int> count;
count["x"]++;                    // creates "x" with 0, then increments
age.at("nobody");                // throws instead of inserting
if (auto it = age.find("Ada"); it != age.end())
    std::cout << it->second << '\n';       // lookup without inserting

§2Unordered Containers

std::unordered_map and std::unordered_set use hashing: average O(1) lookup, with no ordering of elements. They have the same interface, so switching is usually a one-line change.

#include <unordered_map>
std::unordered_map<std::string, int> freq;
for (const std::string& w : words) ++freq[w];
if (freq.contains("the")) { /* C++20 */ }

Hashed containers need a hash for the key and operator==. Standard types like int and std::string already have them; for your own key type you must supply a hash.

§3Choosing

  • Sorted iteration, range queries (lower_bound), or keys with only < defined: std::map / std::set.
  • Fastest average lookup with no ordering needed: std::unordered_map / std::unordered_set.
  • Small collections: a sorted std::vector is often faster than either, because of cache locality.
  • Duplicate keys: std::multimap and std::multiset.

Ordered maps need a strict weak ordering on the key (< that is consistent), and an inconsistent comparator causes undefined behavior.

The key insight Default to std::unordered_map for pure lookup and std::map when order matters. Neither is right when the data is small, so measure before agonizing.

§4Common Mistakes

MistakeWhat HappensFix
Using m[key] just to check whether a key existsSilently inserts a default entryUse find, contains, or count
Modifying a key inside a mapKeys are const; the tree order would breakErase and re-insert with the new key
Using a custom struct as an unordered key with no hashCompile errorSpecialize std::hash or supply a hash functor
Practice
  1. Count word frequencies from standard input in an unordered_map, then copy the results into a std::vector and sort by count.
  2. Write a lookup that reports "missing" without adding the key to the map.
Key takeaways
  • map/set are sorted, O(log n); unordered_* are hashed, average O(1), unordered.
  • operator[] inserts missing keys; use find or at to read safely.
  • Pick by ordering needs, key properties, and measurement, not habit.
