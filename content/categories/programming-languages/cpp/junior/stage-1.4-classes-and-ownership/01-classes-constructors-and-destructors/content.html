Classes, Constructors & Destructors

A class bundles data with the functions that keep it valid, and its constructor and destructor define exactly when an object's life begins and ends.

§1Defining a Class

A struct and a class are the same except for default access: struct members are public, class members are private. Use class when the type has an invariant to protect.

class Account {
public:
    Account(std::string owner, double balance)
        : owner_{std::move(owner)}, balance_{balance} {}   // member initializer list
    void deposit(double amount) { balance_ += amount; }
    double balance() const { return balance_; }            // const: doesn't modify
    const std::string& owner() const { return owner_; }
private:
    std::string owner_;
    double balance_;
};
Account a{"Ada", 100.0};
a.deposit(25);

Trailing _ on private members is a common convention to tell members from parameters.

§2Initializer Lists and Member Order

Members are initialized before the constructor body runs, in the order they are declared in the class, not the order in the initializer list. Assigning in the body means default-constructing first, then assigning, which is wasteful and impossible for const and reference members.

class Bad {
    std::string name_;
public:
    Bad(const std::string& n) { name_ = n; }     // default-construct, then assign
};
class Good {
    std::string name_;
public:
    Good(std::string n) : name_{std::move(n)} {} // constructed directly
};

You can also give members defaults at the declaration (int count_{0};), which every constructor then uses unless it overrides them.

§3explicit and Delegation

Mark single-argument constructors explicit so they can't be used for silent conversions. A constructor can delegate to another to avoid repeating logic.

class Meters {
public:
    explicit Meters(double v) : value_{v} {}
    Meters() : Meters{0.0} {}                    // delegating constructor
private:
    double value_;
};
// Meters m = 5.0;     // error because of explicit
Meters m{5.0};         // fine

§4Destructors and Lifetime

The destructor runs when an object's lifetime ends: at the end of its scope for locals, when its owner is destroyed for members, or on delete for heap objects. Members are destroyed in reverse declaration order after the destructor body. Most classes need no hand-written destructor, because members clean themselves up.

The key insight Establish the class invariant in the constructor and maintain it in every public function. If a constructor can't establish it, throw, so no half-built object ever exists.

Practice
  1. Write a Rectangle class with a constructor that rejects non-positive sides by throwing, plus area() const.
  2. Add prints to a constructor and destructor and create three objects in nested scopes. Confirm the order.
Key takeaways
  • Initialize members in the initializer list; they're built in declaration order.
  • Mark getters const and single-argument constructors explicit.
  • Constructors establish invariants and destructors release resources, and members clean up after themselves.
