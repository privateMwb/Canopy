Smart Pointers

Smart pointers are RAII wrappers around heap objects, and choosing between them is how you state in code who owns what.

§1unique_ptr: Exclusive Ownership

std::unique_ptr<T> owns an object alone and deletes it when it goes out of scope. It has no overhead over a raw pointer, and it cannot be copied, only moved.

#include <memory>
auto p = std::make_unique<Widget>(42);     // construct and own
p->run();
auto q = std::move(p);                     // ownership transfers; p is now null
std::unique_ptr<int[]> arr = std::make_unique<int[]>(10);   // array form

This is the default choice for any heap object. Returning a unique_ptr from a function hands ownership to the caller.

std::unique_ptr<Shape> makeShape(std::string_view kind);   // caller owns result
void consume(std::unique_ptr<Shape> s);     // takes ownership
void inspect(const Shape& s);               // just looks; pass the object, not the smart pointer

§2shared_ptr: Shared Ownership

std::shared_ptr<T> keeps a reference count; the object is destroyed when the last owner goes away. Use it when several parts of a program truly share an object's lifetime.

auto a = std::make_shared<Config>();
auto b = a;                                // count is now 2
std::cout << a.use_count() << '\n';        // 2
b.reset();                                 // count is 1; Config lives on

The count is atomic, so copies cost something, and shared ownership makes lifetimes harder to reason about. Don't reach for it by habit.

§3weak_ptr: Breaking Cycles

If two objects hold shared_ptrs to each other, neither count reaches zero, and both leak. A std::weak_ptr observes an object without owning it.

struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;              // back-link doesn't keep the node alive
};
if (auto sp = weak.lock()) { /* object still alive: use sp */ }

lock() returns a shared_ptr, which is empty if the object is gone.

§4Which One?

  • Owns alone: unique_ptr.
  • Genuinely shared lifetime: shared_ptr (created with make_shared).
  • Observes without owning: weak_ptr, a raw pointer, or a reference.
  • Function only uses the object: take T& or T*, not a smart pointer.
The key insight A raw pointer in modern C++ means "I don't own this." The ownership is stated by the smart pointer type, which makes ownership visible in every signature.

§5Common Mistakes

MistakeWhat HappensFix
Creating two shared_ptrs from the same raw pointerTwo separate counts; double deleteUse make_shared, or copy the existing shared_ptr
Passing shared_ptr everywhere "to be safe"Hidden cost and murky lifetimesUse unique_ptr, and pass references to callees
Cycles of shared_ptrMemory leak, no destructors runMake one direction a weak_ptr
Practice
  1. Write a factory returning std::unique_ptr<Shape> and store several in a std::vector.
  2. Build a parent/child tree where children point back to the parent with weak_ptr, and verify with a destructor print that everything is freed.
Key takeaways
  • unique_ptr is the default owner; it's free and move-only.
  • shared_ptr is for truly shared lifetime, and weak_ptr breaks cycles.
  • Pass references or raw pointers to functions that don't take ownership.
