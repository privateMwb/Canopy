C++ vs. Rust & Other Choices

Choosing C++ is an engineering decision with real costs and benefits, and you should be able to argue for or against it using the actual strengths of each option.

§1What C++ Is Good At

  • Performance control: predictable memory layout, no mandatory garbage collector, zero-overhead abstractions, direct access to SIMD and the hardware.
  • Ecosystem and reach: decades of libraries, game engines, browsers, databases, compilers, HFT, embedded, and scientific code, with direct interop with C.
  • Existing codebases: rewriting millions of lines is rarely worth it, and incremental modernization is.
  • Mature tooling: several compilers, sanitizers, profilers, debuggers, and platform support from microcontrollers to supercomputers.
  • Abstraction power: templates, RAII, and value semantics let you build safe, fast libraries.

§2What It Costs

  • Memory-safety bugs (use-after-free, buffer overflows, data races) are a large share of serious vulnerabilities in big C and C++ codebases. Safe subsets exist but aren't enforced by the language.
  • Complexity: decades of features, many ways to do each thing, and subtle rules (value categories, ADL, UB).
  • Build and dependency pain: slow builds, no universal package manager, and ABI fragility.
  • Long tails of bad examples online, written in older styles.

§3Rust

Rust offers C++-class performance with memory and data-race safety enforced at compile time through ownership, borrowing, and lifetimes in safe code, plus a built-in build tool and package manager (Cargo) and no undefined behavior in safe Rust.

  • Rust's wins: safety by default, sum types and pattern matching, modern tooling, fearless concurrency, strong choices for security-sensitive new components.
  • Rust's costs: a steep borrow-checker learning curve, a smaller (but growing) ecosystem, slower compile times in some projects, less mature interop with existing C++ (improving: cxx, bindgen, and Crubit), and fewer engineers available in some domains.
  • C++'s counterpoints: enormous existing code and expertise, templates and compile-time power, constexpr, mature game/graphics/HPC ecosystems, and active safety work (hardening, profiles, contracts, std::span, sanitizers).

§4Other Options

  • C: smallest, simplest, ubiquitous ABI; but manual everything.
  • Go: simple concurrency, fast builds, garbage collected; good for network services where latency pauses are acceptable.
  • Java/C#: managed runtimes, huge libraries; great for business applications; less control of memory.
  • Python plus C++ extensions: productivity for orchestration, C++ for the hot loops.
  • Zig, Swift, Carbon, and others occupy neighboring niches with different tradeoffs.

§5Deciding

Ask concrete questions instead of picking a side: 1. What are the hard constraints: latency, memory, real time, hardware access, existing libraries? 2. What does a bug cost, in security, safety, and money? 3. What does the team know, and can hire? 4. Is this new code or a change to an existing C++ system? 5. How will it interoperate with what's already there? Often the right answer is mixed: keep a C++ core and write new security-critical parsers in Rust, or bind a C++ engine to a Python front end.

The key insight Be able to argue both sides. A senior engineer states the decision criteria and the cost of being wrong, instead of defending a favorite language on reflex.

§6Common Mistakes

MistakeWhat HappensFix
Choosing a language by benchmark headlinesPerformance usually depends on design, not the language aloneMeasure your workload and weigh safety, team, and ecosystem
Proposing a full rewrite for safety aloneCost, risk, and lost features outweigh the gainModernize incrementally, harden, and write new risky components in a safer language
Dismissing C++ safety work as "just use smart pointers"Misses lifetime, aliasing, and concurrency errorsCombine safe idioms, sanitizers, hardening, and analysis
Practice
  1. Pick a component (an image decoder, a network service, a game loop) and write a one-page recommendation for C++ vs. Rust with the decision criteria stated.
  2. Write the strongest argument for the language you would not choose, then answer it.
Key takeaways
  • C++ wins on performance control, ecosystem, and existing code; it costs safety, complexity, and tooling friction.
  • Rust enforces memory and thread safety at compile time, at the cost of learning curve and interop maturity.
  • Decide on constraints, bug costs, team, and interoperability, and be prepared to argue both sides.
