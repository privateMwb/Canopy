lvalues, rvalues & Value Categories

Every expression is either something with an identity you can name and reuse, or a temporary that is about to disappear, and move semantics is built on telling them apart.

§1lvalues and rvalues

An lvalue is an expression that refers to an object with a name or address, so it persists beyond the expression. An rvalue is a temporary, or a value you've marked as no longer needed.

int x{5};
x;              // lvalue: has a name and an address
&x;             // fine: can take its address
x + 1;          // rvalue: a temporary result
// &(x + 1);    // error: can't take the address of an rvalue
std::string s{"a"};
s + "b";        // rvalue: a temporary string
std::move(s);   // rvalue (an xvalue): "treat s as expiring"

A simple test: *can you take its address?* If yes, it's an lvalue.

§2References That Bind to Each

A function can tell, through its parameter type, whether it was handed an lvalue or an rvalue.

void f(const std::string&) { std::cout << "lvalue or anything\n"; }
void f(std::string&&)      { std::cout << "rvalue\n"; }

std::string s{"x"};
f(s);                      // lvalue ref overload
f(std::string{"tmp"});     // rvalue reference overload
f(std::move(s));           // rvalue reference overload: s is now "movable from"

T&& on a concrete type is an rvalue reference. It only binds to rvalues, which tells the function "this object is going away, so you may steal its guts."

§3A Named rvalue Reference Is an lvalue

Inside the function, a parameter has a name, so it is an lvalue even when its type is T&&.

void g(std::string&& s) {
    f(s);              // calls the lvalue overload! s has a name
    f(std::move(s));   // now calls the rvalue overload
}

This surprises almost everyone once. Naming something makes it persistent, and you must explicitly say "I'm done with this" with std::move.

§4What std::move Really Does

std::move does not move anything. It is a cast to an rvalue reference, giving permission to treat the object as expiring. The actual stealing is done by a move constructor or move assignment that accepts the rvalue.

std::string a{"hello"};
std::string b = std::move(a);    // b's move constructor takes a's buffer
// a is now valid but unspecified: don't rely on its value, only assign to it or destroy it
The key insight After std::move(x), treat x as empty. It is safe to destroy or assign to, and unsafe to read. Calling std::move on something you use again is almost always a bug.

§5Common Mistakes

MistakeWhat HappensFix
Calling std::move on a const objectMoves silently turn into copies, since a const object can't be stolen fromDon't move from const objects
Using a variable after std::moveReads an unspecified (often empty) valueDon't touch it until you reassign it
Believing T&& parameter is an rvalue inside the functionIt's an lvalue because it has a nameUse std::move(param) to pass it on as an rvalue
Practice
  1. Write overloads of describe for int&, const int&, and int&&, and call each with a variable, a const variable, and a literal.
  2. Move a std::string into another and print the size of the source. What do you observe?
Key takeaways
  • lvalues have names and addresses; rvalues are temporaries or objects marked as expiring.
  • std::move is a cast that grants permission to move, and doesn't move anything itself.
  • A named T&& variable is an lvalue; a moved-from object is valid but unspecified.
