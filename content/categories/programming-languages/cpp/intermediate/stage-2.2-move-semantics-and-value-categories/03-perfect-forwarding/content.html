Perfect Forwarding

Perfect forwarding passes an argument on to another function exactly as it was received, lvalue as lvalue and rvalue as rvalue, with no extra copies.

§1The Problem

A wrapper function that takes its argument by value or const& can't preserve whether the caller passed a temporary.

void sink(std::string&& s) { /* wants to steal */ }
template <typename T>
void wrapper(const T& x) { sink(x); }   // error: x is an lvalue, can't bind to &&

Writing separate overloads for every combination of lvalue and rvalue parameters explodes with each argument.

§2Forwarding References

In a function template, T&& where T is deduced is a *forwarding reference* (also called a universal reference). It binds to anything and remembers what it bound to.

template <typename T>
void wrapper(T&& x);
std::string s{"a"};
wrapper(s);                  // T = std::string&, x is std::string&
wrapper(std::string{"b"});   // T = std::string,  x is std::string&&

The deduced T encodes the category: an lvalue argument deduces T as an lvalue reference, and reference collapsing turns T&& into T&. This only applies when T is deduced for this call; void f(std::string&&) or std::vector<T>&& are plain rvalue references.

§3std::forward

Inside the wrapper, x has a name, so it's an lvalue. std::forward<T>(x) casts it back to what it originally was: an rvalue if T is a non-reference type, otherwise an lvalue.

template <typename T>
void wrapper(T&& x) { sink(std::forward<T>(x)); }

template <typename T, typename... Args>
std::unique_ptr<T> makeUnique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

This is the core of std::make_unique, std::make_shared, emplace_back, and std::thread's constructor: they build an object in place from the caller's arguments without extra copies.

§4std::move vs. std::forward

  • std::move(x) always casts to rvalue. Use it when you know you're done with x.
  • std::forward<T>(x) casts to rvalue only if the original argument was an rvalue. Use it only on forwarding-reference parameters, once.
template <typename T>
void store(T&& item) { items_.push_back(std::forward<T>(item)); }   // copy or move as appropriate

Forward each argument once; forwarding the same variable twice may move from it the first time.

The key insight T&& means "rvalue reference" only on a concrete type. On a deduced template parameter it means "anything, and remember which." std::forward is how you honor that memory.

§5Common Mistakes

MistakeWhat HappensFix
Using std::move on a forwarding referenceSteals from the caller's lvaluesUse std::forward<T>
Forwarding an argument and then using it againMay read a moved-from objectForward as the final use
Overloading a T&& template with other constructorsThe greedy template wins for many callsConstrain it with a concept
Practice
  1. Write a timeCall(f, args...) wrapper that forwards its arguments to f and returns the result.
  2. Use emplace_back and push_back with a type that prints in its copy and move constructors, and compare the output.
Key takeaways
  • T&& with a deduced T is a forwarding reference that binds to both lvalues and rvalues.
  • Use std::forward<T> to pass arguments along unchanged, once.
  • This is how make_unique and emplace_back avoid extra copies.
