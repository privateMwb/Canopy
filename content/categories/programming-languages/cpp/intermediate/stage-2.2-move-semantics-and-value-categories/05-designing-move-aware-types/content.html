Designing Move-Aware Types

A type that is cheap and safe to move behaves well inside every standard container, and the key is noexcept.

§1Why noexcept Matters

When std::vector reallocates, it must transfer elements to a new buffer. If a move could throw halfway, the old buffer is already damaged and the strong exception guarantee (nothing changes on failure) would be lost. So vector uses std::move_if_noexcept: it moves only if the move constructor is noexcept, otherwise it copies.

struct Slow {
    Slow(Slow&&) { /* not noexcept */ }          // vector will COPY on growth
    Slow(const Slow&);
};
struct Fast {
    Fast(Fast&&) noexcept { /* ... */ }          // vector will move on growth
    Fast(const Fast&);
};
static_assert(std::is_nothrow_move_constructible_v<Fast>);

Forgetting noexcept doesn't give an error, only a silent slowdown.

§2Making Moves noexcept

Moves usually just swap pointers and handles, which can't throw, so mark them noexcept. If a move would allocate or call something that can throw, reconsider the design: either make the move not allocate (leave the source empty) or accept copying.

class Name {
    std::string s_;
public:
    Name(Name&& o) noexcept : s_{std::move(o.s_)} {}
    Name& operator=(Name&& o) noexcept { s_ = std::move(o.s_); return *this; }
};

std::string and std::vector have noexcept moves, so members of those types give you a noexcept move by default under the Rule of Zero.

§3Swap and Strong Guarantees

A noexcept swap lets you build assignment with copy-and-swap, which gives the strong guarantee: do all the risky work (the copy) first, then commit with non-throwing operations.

friend void swap(Buffer& a, Buffer& b) noexcept {
    using std::swap;
    swap(a.data_, b.data_);
    swap(a.n_, b.n_);
}
Buffer& operator=(Buffer o) noexcept { swap(*this, o); return *this; }   // one function for copy and move

§4Move-Only Types

Some resources can't be copied: a std::unique_ptr, a thread, a file handle. Delete copying and provide moves. These types still work in containers and algorithms, just by moving.

class Handle {
public:
    Handle(const Handle&) = delete;
    Handle& operator=(const Handle&) = delete;
    Handle(Handle&&) noexcept;
    Handle& operator=(Handle&&) noexcept;
};
std::vector<Handle> v;          // fine: vector moves elements
The key insight Test, don't assume. Add static_assert(std::is_nothrow_move_constructible_v<T>) next to your type and the compiler guards the performance promise for you.

Practice
  1. Create a type that counts copies and moves, put 100 into a vector with and without noexcept on the move, and compare the counts.
  2. Add static_asserts for nothrow move construction and assignment to the Buffer class.
Key takeaways
  • std::vector moves elements on growth only if the move constructor is noexcept.
  • Moves should be noexcept, and verified with static_assert.
  • Move-only types delete copying and still work in standard containers.
