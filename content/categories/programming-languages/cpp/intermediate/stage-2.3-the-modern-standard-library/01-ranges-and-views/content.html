Ranges & Views

C++20 ranges let you chain filters and transforms with |, evaluating lazily without building intermediate containers.

§1Range Algorithms

A range is anything with begin() and end(). The std::ranges algorithms accept a whole container, so the iterator pair disappears.

#include <ranges>
#include <algorithm>
std::vector<int> v{5, 2, 9, 1};
std::ranges::sort(v);
auto it = std::ranges::find(v, 9);
bool any = std::ranges::any_of(v, [](int x) { return x > 8; });
std::ranges::sort(people, {}, &Person::age);       // sort by a member via a projection

The third argument is a projection: a function applied to each element before comparing, which often removes the need for a lambda.

§2Views

A view is a lightweight, non-owning description of a sequence. It does no work until you iterate, and it never copies the elements.

namespace v = std::views;
std::vector<int> nums{1, 2, 3, 4, 5, 6, 7, 8};
auto result = nums
    | v::filter([](int x) { return x % 2 == 0; })      // 2 4 6 8
    | v::transform([](int x) { return x * x; })        // 4 16 36 64
    | v::take(3);                                      // 4 16 36
for (int x : result) std::cout << x << ' ';

Nothing happens at the pipeline line; each element flows through filter, transform, and take one at a time when the loop asks for it. That makes infinite sequences possible.

for (int x : v::iota(1) | v::filter(isPrime) | v::take(10)) std::cout << x << ' ';

Other useful views: drop, reverse, keys, values, elements<N>, split, join, take_while, and enumerate (C++23).

§3Materializing Results

To get a container, collect the view. C++23 has std::ranges::to; before that, construct from iterators.

auto squares = nums | v::transform([](int x) { return x * x; })
                    | std::ranges::to<std::vector>();     // C++23

§4Lifetime and Laziness Pitfalls

A view refers to the original data and computes on demand, so two things go wrong: the underlying container must outlive the view, and a view over a temporary dangles. Also, lazy filter and transform re-run the lambda each time you iterate.

auto bad = std::vector<int>{1, 2, 3} | v::transform(f);   // underlying vector is destroyed at the semicolon

Changing the source container while a view over it is alive can invalidate it, as with iterators.

The key insight A pipeline reads left to right as a description of the transformation: "evens, squared, first three." Because nothing is computed until iteration, you pay only for the elements you consume.

§5Common Mistakes

MistakeWhat HappensFix
Building a view over a temporary containerDangling viewKeep the container in a named variable
Iterating an expensive lazy view several timesThe lambdas run again each timeMaterialize into a vector once
Modifying the source container during iterationInvalidated iteratorsDon't change it, or collect first
Practice
  1. Use a pipeline to print the squares of the odd numbers from 1 to 20.
  2. Sort a vector of records by a string member using a projection, with no lambda.
  3. Generate the first ten Fibonacci numbers lazily using iota and transform or a custom generator.
Key takeaways
  • Range algorithms take whole containers, and projections replace many comparator lambdas.
  • Views are lazy, non-owning pipelines composed with |.
  • A view must not outlive its source, and nothing is computed until you iterate.
