span, string_view & Non-Owning Types

std::span and std::string_view are cheap borrowed windows onto existing data, ideal for parameters, with strict rules about how long they stay valid.

§1std::span

A std::span<T> is a pointer plus a length that refers to contiguous elements owned by something else. One function can then accept a C array, a std::array, or a std::vector with no copy and no template.

#include <span>
double average(std::span<const double> data) {
    double sum{};
    for (double d : data) sum += d;
    return data.empty() ? 0.0 : sum / data.size();
}
double raw[]{1, 2, 3};
std::array<double, 2> arr{4, 5};
std::vector<double> vec{6, 7, 8};
average(raw); average(arr); average(vec);

Use std::span<const T> to promise you won't modify the elements and std::span<T> when you will. A span doesn't own anything, and copying it is trivial.

§2Subviews

Slicing a span costs nothing, since it just adjusts the pointer and length.

std::span<int> s{vec};
auto firstThree = s.first(3);
auto lastTwo = s.last(2);
auto middle = s.subspan(1, 3);        // offset 1, count 3

Operator [] is unchecked, so validate sizes before indexing.

§3The Borrowing Rules

Non-owning types (span, string_view, iterators, range views, raw pointers and references) are all borrows. A borrow is valid only while the owner is alive and has not reallocated.

std::span<int> dangling() {
    std::vector<int> v{1, 2, 3};
    return v;                          // span of a vector that is destroyed
}
std::vector<int> v{1, 2, 3};
std::span<int> s{v};
v.push_back(4);                        // may reallocate: s now dangles

Where borrows are safe and where they are not:

  • Function parameters: safe, since the caller's data outlives the call.
  • Local variables used briefly: safe if the owner is in scope and unchanged.
  • Return values and members: risky. Document the lifetime, or return an owning type.

§4Choosing the Parameter Type

  • Read-only text: std::string_view.
  • Read-only sequence: std::span<const T>.
  • Need to mutate in place: std::span<T>.
  • Need to own or keep the data: std::string or std::vector<T>.
The key insight Borrowed types make interfaces flexible and fast, but they move the burden of lifetime onto the programmer. Take them as parameters freely; return or store them only with a clear owner in mind.

§5Common Mistakes

MistakeWhat HappensFix
Returning a span or view of a localDangling; undefined behaviorReturn the owning container by value
Storing a span as a class memberDangles if the owner is destroyed or reallocatedStore the owner, or make the lifetime relationship explicit
Passing a temporary to a function that stores the spanDangles after the full expression endsPass named objects, or have the function copy
Practice
  1. Write std::span<const int> longestRun(std::span<const int>) and check that its result is only valid while the input is.
  2. Convert a function taking const std::vector<int>& to take std::span<const int> and call it with a C array.
Key takeaways
  • span and string_view are pointer-plus-length borrows; they accept many container types.
  • Use them as parameters; be careful returning or storing them.
  • push_back or destruction of the owner invalidates the view.
