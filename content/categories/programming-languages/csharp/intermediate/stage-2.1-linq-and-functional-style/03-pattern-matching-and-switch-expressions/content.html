Pattern Matching & Switch Expressions

Patterns let you test the shape of a value and extract data from it in one expression, replacing chains of if and casts.

§1Type, Constant, and Relational Patterns

static string Describe(object o) => o switch
{
    null => "nothing",
    int n when n < 0 => "negative int",
    int n => $"int {n}",
    string { Length: 0 } => "empty string",
    string s => $"string of {s.Length}",
    IEnumerable<int> xs => $"{xs.Count()} ints",
    _ => o.GetType().Name
};

static string Grade(int score) => score switch
{
    >= 90 => "A",
    >= 80 => "B",
    >= 70 => "C",
    _ => "F"
};

int n tests the type and binds a variable. >= 90 is a relational pattern. Arms are evaluated top to bottom and the first match wins, so put specific cases before general ones. when adds an extra condition.

§2Property, Positional, and Logical Patterns

record Order(string Status, decimal Total, Customer Customer);
record Customer(string Tier);

static decimal Discount(Order o) => o switch
{
    { Status: "Cancelled" } => 0m,
    { Customer.Tier: "Gold", Total: > 100 } => 0.15m,   // extended property pattern
    { Total: >= 50 and < 100 } => 0.05m,
    { Total: > 0 } or { Status: "Gift" } => 0.02m,
    _ => 0m
};

record Point(int X, int Y);
static string Quadrant(Point p) => p switch
{
    (0, 0) => "origin",
    (> 0, > 0) => "first",
    (< 0, > 0) => "second",
    _ => "other"
};

if (obj is not null and { Length: > 3 }) { }
if (input is "y" or "yes") { }

A property pattern ({ Total: > 100 }) tests members. A positional pattern uses a record's deconstruction. and, or, and not combine patterns, and a list pattern such as [var first, .., var last] matches sequences by position.

§3Exhaustiveness

The compiler analyzes a switch expression and warns if some input isn't covered. For enums and sealed hierarchies you can often avoid a catch-all, which means adding a new case later produces a warning at every switch that needs updating.

abstract record Shape;
sealed record Circle(double R) : Shape;
sealed record Square(double S) : Shape;

static double Area(Shape s) => s switch
{
    Circle c => Math.PI * c.R * c.R,
    Square q => q.S * q.S,
    _ => throw new ArgumentException("Unknown shape")   // required for open hierarchies
};

Because Shape is an open hierarchy (anyone can derive from it), the compiler still wants a default arm. A switch over an enum is closer to truly exhaustive, though a value cast from an integer can still escape, so the compiler still emits a run-time throw for it.

The key insight Patterns turn "check the type, cast it, then check a property" into one declarative expression. Put the rules in table order, with the most specific first, and let the compiler warn you about the gaps.

§4Common Mistakes

MistakeWhat HappensFix
Putting a general arm before a specific oneThe specific arm is unreachable (compile error or warning)Order arms from most specific to least
Adding a _ arm to every switch over your own enumNew enum members silently fall through to the defaultOmit it for closed sets so the compiler flags missing cases
Long when clauses containing real logicHard to read, and pattern advantages are lostExtract the condition into a named method or a property pattern
Practice
  1. Rewrite a method with several if (x is Foo f) ... else if (x is Bar b) checks as a switch expression.
  2. Write a shipping-cost function with a switch expression over an order's weight (relational), country (property), and express flag (logical patterns).
Key takeaways
  • Type, property, relational, and logical patterns test shape and extract data concisely.
  • Switch expression arms run top to bottom, with the first match winning.
  • Exhaustiveness checking helps you find unhandled cases, so keep catch-alls only where needed.
