Iterators & yield

An iterator method uses yield return to produce a sequence one element at a time, on demand, without building the whole collection.

§1yield return

static IEnumerable<int> Evens(int max)
{
    for (int i = 0; i <= max; i += 2)
        yield return i;          // hand back one value, then pause here
}

foreach (var n in Evens(10))
    Console.Write(n + " ");      // 0 2 4 6 8 10

var firstThree = Evens(1_000_000).Take(3).ToList();   // computes only 3 items

A method containing yield return returns an IEnumerable<T> without running any of its body at the call. Each time the consumer asks for the next item, the body resumes after the last yield and runs to the next one. yield break ends the sequence early.

§2Lazy Pipelines and Infinite Sequences

static IEnumerable<string> ReadLinesLazily(string path)
{
    using var reader = new StreamReader(path);
    string? line;
    while ((line = reader.ReadLine()) is not null)
        yield return line;       // one line in memory at a time
}

static IEnumerable<long> Fibonacci()
{
    long a = 0, b = 1;
    while (true) { yield return a; (a, b) = (b, a + b); }   // infinite, but fine when lazy
}

var big = ReadLinesLazily("huge.log").Where(l => l.Contains("ERROR")).Take(10);

Because evaluation is lazy, you can process files larger than memory and define infinite sequences, as long as the consumer stops (Take, First, or a break). The using inside the iterator is disposed when enumeration finishes or the consumer disposes the enumerator.

§3What the Compiler Generates

The compiler rewrites an iterator method into a hidden state machine class that implements IEnumerator<T>. Local variables become fields, and a state number records which yield to resume after. You never write MoveNext and Current by hand.

  • Argument validation in an iterator is deferred too. To throw eagerly, split it into a normal method that validates and then calls a private iterator.
  • You can't use yield inside a try with a catch, or in a method with ref parameters.
  • The iterator's state is tied to one enumeration; each foreach over the returned IEnumerable gets a fresh enumerator.
public static IEnumerable<int> Evens(int max)
{
    if (max < 0) throw new ArgumentOutOfRangeException(nameof(max));  // runs at call time
    return EvensCore(max);
}
private static IEnumerable<int> EvensCore(int max) { /* yield loop */ yield break; }
The key insight yield trades a collection for a procedure that produces items on request. Use it when the data is large, expensive, or infinite, and a plain list when you need to index, count, or re-read the result cheaply.

§4Common Mistakes

MistakeWhat HappensFix
Validating arguments inside the iterator bodyThe exception appears only when someone first enumeratesUse a wrapper method that validates, then returns the iterator
Enumerating a lazy file reader twiceThe file opens and is read twice (or fails if it's gone)Materialize with ToList() if you need two passes
Building a List just to return it from a method that could yieldExtra memory and no early exitYield when callers often take only part of the data
Practice
  1. Write IEnumerable<T> Chunk<T>(IEnumerable<T>, int size) as an iterator, then compare with the built-in Chunk.
  2. Write an infinite Primes() iterator and print the first 20 using Take(20).
Key takeaways
  • yield return produces items on demand; nothing runs until enumeration starts.
  • Laziness lets you stream huge data and define infinite sequences.
  • The compiler builds a state machine for you, and argument checks need a separate wrapper to run eagerly.
