Tasks & async/await Fundamentals

async and await let a method wait for slow work, such as I/O, without blocking a thread, while the code still reads top to bottom.

§1The Problem and the Shape

A web request or file read can take milliseconds to seconds, and during that time the CPU has nothing to do. If a thread sits blocked waiting, you've wasted it, and a server can run out of threads. Asynchronous code releases the thread while it waits and picks the work back up when the result is ready.

static async Task<string> DownloadAsync(HttpClient http, string url)
{
    string body = await http.GetStringAsync(url);   // thread is free while waiting
    return body.ToUpperInvariant();
}

var text = await DownloadAsync(http, "https://example.com");   // top-level await

An async method returns a Task (no result), a Task<T> (a result), or a ValueTask<T>. By convention the name ends in Async. Callers await it to get the result, and async spreads "all the way up" through the call chain.

§2What a Task and await Really Are

A Task is an object representing work that will finish later, with a result, an exception, or cancellation. It is not a thread. await task checks whether the task is already done. If so, it continues synchronously. If not, it returns control to the caller and registers the rest of the method as a continuation. When the task completes, the continuation runs, and the compiler's state machine remembers where you were.

Task<string> t = DownloadAsync(http, url);   // starts running; no thread blocked
DoOtherWork();                                  // runs while the download is in progress
string result = await t;                        // now wait for it

var a = DownloadAsync(http, url1);              // start both
var b = DownloadAsync(http, url2);
string[] both = await Task.WhenAll(a, b);       // wait for both to finish, concurrently

§3Exceptions, Return Types, and CPU Work

  • An exception thrown inside an async method is stored in the Task and rethrown at the await, so an ordinary try/catch works around it.
  • Return Task, never void, for async methods, except for event handlers (next lesson explains why).
  • await Task.Delay(1000) is the async version of Thread.Sleep.
  • Task.Run(() => ...) moves CPU-bound work to the thread pool. Don't use it to wrap I/O that already has an async API, since you'd just burn a thread.
try
{
    var data = await LoadAsync();
}
catch (HttpRequestException ex)
{
    Console.WriteLine($"Request failed: {ex.Message}");
}

int answer = await Task.Run(() => HeavyComputation());   // CPU-bound work off the caller's thread
The key insight await doesn't make anything run in the background. It means "don't block this thread while that finishes." Async helps with waiting; it does nothing to make computation faster.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting to await a TaskThe code races ahead, and exceptions go unobservedAwait every task, or deliberately collect and WhenAll them
awaiting in a loop when the operations are independentTotal time is the sum of all waitsStart them all and use Task.WhenAll
Wrapping an async I/O API in Task.RunA thread is blocked doing what the async API avoidsCall the async method directly
Practice
  1. Write an async method that downloads two URLs, first sequentially and then with Task.WhenAll. Time both.
  2. Throw an exception inside an async method and catch it at the await. Then remove the await and see what changes.
Key takeaways
  • A Task represents future completion; await frees the thread while waiting.
  • Exceptions travel through the Task and rethrow at await.
  • Use WhenAll for independent work, and Task.Run only for CPU-bound work.
