Strings & Interpolation

Strings are immutable and culture-aware by default, which affects how you build, compare, and format them.

§1Immutable Strings

A string never changes after it's created. Every operation such as Replace, Trim, or + returns a new string and leaves the original untouched.

string s = "  hello  ";
s.Trim();              // result discarded; s is unchanged
s = s.Trim();          // reassign to keep the result
Console.WriteLine(s.ToUpper());  // HELLO
Console.WriteLine(s[0]);         // h
Console.WriteLine(s.Length);     // 5

Immutability makes strings safe to share across code and threads, and it's why a loop that does s += x thousands of times allocates thousands of intermediate strings.

§2Interpolation, Formatting, and StringBuilder

var name = "Ada"; var total = 1234.5m;
string msg = $"{name} owes {total:C2}";      // currency format
string hex = $"{255:X}";                       // FF
string padded = $"{name,-10}|{total,10:N1}|";  // alignment
string raw = """
    Multi-line text with "quotes" is fine.
    """;

Interpolated strings ($"...") embed expressions directly, with optional ,alignment and :format parts. Raw string literals (three or more quotes) skip escape sequences. When you build a string in a loop, use StringBuilder, which appends into a growable buffer:

var sb = new StringBuilder();
foreach (var line in lines) sb.AppendLine(line);
string result = sb.ToString();

// or just join:
string csv = string.Join(",", values);

§3Comparison and Culture

Many string methods use the current culture unless told otherwise, so the same code can behave differently on a machine set to Turkish or German. Two rules cover most cases:

  • For comparing identifiers, keys, and protocol text, pass StringComparison.Ordinal or OrdinalIgnoreCase.
  • For text shown to users, culture-aware formatting is correct. For data written to files or sent over a network, pass CultureInfo.InvariantCulture.
string.Equals(a, b, StringComparison.OrdinalIgnoreCase);
var dict = new Dictionary<string,int>(StringComparer.OrdinalIgnoreCase);

double d = 1234.5;
d.ToString(CultureInfo.InvariantCulture);  // "1234.5" everywhere
double.Parse("1234.5", CultureInfo.InvariantCulture);
The key insight A string method that returns a string never edits the original. If the result isn't assigned to something, the call did nothing.

§4Common Mistakes

MistakeWhat HappensFix
Concatenating with += in a large loopQuadratic copying and many allocationsUse StringBuilder or string.Join
Comparing with ToLower() ==Allocates extra strings and breaks under some culturesUse Equals(..., StringComparison.OrdinalIgnoreCase)
Parsing or writing numbers with the current cultureDecimal commas break files and APIs on other machinesPass CultureInfo.InvariantCulture for machine-readable data
Practice
  1. Write a method that takes a list of names and returns "Ada, Grace and Linus" style output using string.Join and interpolation.
  2. Print 1234567.891 with ToString("N2") under new CultureInfo("de-DE") and InvariantCulture. Explain the difference.
Key takeaways
  • Strings are immutable, so string methods return new strings.
  • Use interpolation for readability and StringBuilder or Join for building in loops.
  • Compare with an explicit StringComparison, and use invariant culture for machine-readable data.
