Types, Variables & Value vs. Reference Types

Every C# type is either a value type or a reference type, and that choice decides what assignment, passing to a method, and comparison actually do.

§1Variables and Built-in Types

C# is statically typed: every variable has a type the compiler checks. var lets the compiler infer the type from the right-hand side, but the variable is still strongly typed.

int count = 3;
double price = 9.99;
decimal money = 19.99m;   // use decimal for currency
bool done = false;
char letter = 'A';
string name = "Ada";
var total = count * price; // inferred as double
const int MaxItems = 10;   // compile-time constant

Use decimal for money, because double is binary floating point and can't represent values like 0.1 exactly. Integer arithmetic silently wraps on overflow unless you opt into checked contexts, so choose long when values may grow large.

§2Value Types and Reference Types

A value type variable holds its data directly. Assigning it copies the data. All of the numeric types, bool, char, enum, and every struct are value types. A reference type variable holds a reference to an object on the managed heap. Assigning it copies the reference, so both variables point at the same object. Classes, arrays, string, and delegates are reference types.

struct PointS { public int X; }
class PointC { public int X; }

var a = new PointS { X = 1 };
var b = a;          // copies the data
b.X = 99;
Console.WriteLine(a.X); // 1

var c = new PointC { X = 1 };
var d = c;          // copies the reference
d.X = 99;
Console.WriteLine(c.X); // 99

§3Stack, Heap, and Method Arguments

The common summary is "value types live on the stack, reference types on the heap." It's a useful start, but it's only partly true: a value type inside a class field lives inside that heap object, and the garbage collector reclaims heap objects automatically. What always holds is the copy behavior above.

That behavior carries over to method calls. Arguments are passed by value by default, which for a reference type means the reference is copied. The method can mutate the object but can't repoint your variable. The ref and out modifiers pass a variable by reference.

static void Bump(PointS p) { p.X++; }        // changes a copy
static void Bump(ref PointS p) { p.X++; }    // changes the caller's variable
static bool TryParse(string s, out int n) => int.TryParse(s, out n);
The key insight Ask "what does = copy?" Value types copy the data, and reference types copy the reference. Most surprises with shared state and "my change didn't stick" come from forgetting which one you have.

§4Common Mistakes

MistakeWhat HappensFix
Using double for moneyRounding errors such as 0.1 + 0.2 != 0.3Use decimal for currency
Assuming a copied class instance is independentMutating the "copy" changes the originalCreate a real copy (a copy method or a record with-expression) when you need independence
Mutating a struct held in a collection or readonly fieldThe change applies to a temporary copy and is lostKeep structs small and immutable, or replace the whole element
Practice
  1. Predict the output of the struct and class examples above, then change PointS to a class and rerun. What changed, and why?
  2. Write a method Swap(ref int a, ref int b). Then try it without ref and explain why the swap fails.
Key takeaways
  • Value types copy their data on assignment; reference types copy the reference.
  • Arguments are passed by value unless you use ref or out, and for reference types the value is the reference.
  • Use decimal for money and small immutable structs for simple values; use classes for objects with identity.
