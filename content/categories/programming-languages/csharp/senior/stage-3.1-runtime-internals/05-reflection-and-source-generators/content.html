Reflection & Source Generators

Reflection inspects types while the program runs, which is powerful and slow. Source generators move that work to compile time.

§1What Reflection Does and Costs

Type t = typeof(Customer);
foreach (PropertyInfo p in t.GetProperties())
    Console.WriteLine($"{p.Name}: {p.PropertyType.Name}");

object? instance = Activator.CreateInstance(t);
t.GetProperty("Name")!.SetValue(instance, "Ada");
var method = t.GetMethod("Validate");
method?.Invoke(instance, null);

var attr = t.GetCustomAttribute<TableAttribute>();   // read metadata

Reflection lets code discover types, members, and attributes at run time, which is how serializers, DI containers, ORMs, and test runners work. It costs: lookups and invocations are many times slower than direct calls, they allocate (object[] for arguments), and the compiler can't check them, so a typo in "Nmae" fails only when that line runs. It also defeats trimming and Native AOT, because the linker can't tell which members are needed.

§2Making Reflection Cheaper

  • Cache the metadata: GetProperties() once per type, not per object.
  • Compile a delegate: build an accessor with Delegate.CreateDelegate or an expression tree once, then call it at near-direct speed.
  • Prefer interfaces and generics over reflection when you control the types.
  • Use nameof instead of string literals for member names, so renames stay in sync.
private static readonly Func<Customer, string> GetName =
    (Func<Customer, string>)Delegate.CreateDelegate(
        typeof(Func<Customer, string>), typeof(Customer).GetProperty(nameof(Customer.Name))!.GetMethod!);

string name = GetName(customer);   // one reflection lookup at startup, fast calls afterward

§3Source Generators

A source generator is a compiler plug-in that inspects your code during the build and emits additional C# source. What reflection would do at run time, the generator does once at compile time, producing ordinary, fast, trimmer-safe code.

// System.Text.Json source generation: no reflection at run time
[JsonSerializable(typeof(Customer))]
[JsonSerializable(typeof(List<Order>))]
internal partial class AppJsonContext : JsonSerializerContext { }

string json = JsonSerializer.Serialize(customer, AppJsonContext.Default.Customer);
var back = JsonSerializer.Deserialize(json, AppJsonContext.Default.Customer);

// Other generators in the box: [GeneratedRegex], [LoggerMessage], [LibraryImport]
[GeneratedRegex(@"^\d{4}-\d{2}-\d{2}$")]
private static partial Regex IsoDate();

The built-in generators are the ones you'll use most: System.Text.Json contexts, [GeneratedRegex] (a regex compiled to C# code), [LoggerMessage] (allocation-free logging), and [LibraryImport] (P/Invoke marshalling). You can write your own with IIncrementalGenerator in a separate analyzer project. Tradeoffs: faster start, no reflection, AOT-friendly, and the generated code is inspectable, but generators add build complexity and are harder to write and debug than reflection.

The key insight Reflection decides at run time what the code should do, and source generators decide at compile time. When the set of types is known at build time, generate; when it truly isn't, reflect, and cache.

§4Common Mistakes

MistakeWhat HappensFix
Calling GetProperty or Invoke in a hot loopSlow, allocating codeCache PropertyInfos and compile delegates once
Using reflection-based serialization in a Native AOT or trimmed appMissing members or runtime failuresUse System.Text.Json source generation
Writing member names as stringsRenames silently break reflection codeUse nameof, or avoid reflection through generics and generators
Practice
  1. Serialize 100,000 objects with default System.Text.Json and again with a source-generated context. Compare time and allocations.
  2. Replace a new Regex(...) in a hot path with [GeneratedRegex] and open the generated code (Analyzers, Dependencies, in your IDE).
Key takeaways
  • Reflection inspects types at run time, but it is slow, allocating, unchecked, and hostile to trimming and AOT.
  • Cache reflection results and compile delegates when you must use it.
  • Source generators emit plain C# at build time, giving reflection-free, AOT-friendly code for JSON, regex, and logging.
