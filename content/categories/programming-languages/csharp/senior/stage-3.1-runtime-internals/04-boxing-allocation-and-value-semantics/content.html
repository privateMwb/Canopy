Boxing, Allocation & Value Semantics

Many allocations in C# don't have a new next to them. Learning to see them is the first step to removing the ones that matter.

§1Boxing

Boxing wraps a value type in a heap object so it can be treated as object or an interface. Unboxing copies it back out. Each box is an allocation.

int n = 42;
object o = n;                       // boxing: allocates
int m = (int)o;                     // unboxing

IComparable c = n;                  // boxing
string s = string.Format("{0}", n);  // boxes n into an object[] parameter
var list = new ArrayList(); list.Add(5);   // boxes (use List<int>)

// enum.HasFlag on older runtimes, and calling GetType() or ToString() on a struct that
// doesn't override it, can box. Generic constraints avoid it:
static bool Eq<T>(T a, T b) where T : IEquatable<T> => a.Equals(b);   // no boxing for structs

// Captures 'factor' -> allocates a closure object on every call
IEnumerable<int> Scale(IEnumerable<int> xs, int factor) => xs.Select(x => x * factor);

// A static lambda cannot capture, so the compiler caches one delegate
Func<int, int> square = static x => x * x;

§3Finding Allocations and Value Semantics

Don't guess: measure. The tools, from quick to detailed:

  • GC.GetAllocatedBytesForCurrentThread() before and after a block gives an exact byte count for that thread.
  • BenchmarkDotNet's [MemoryDiagnoser] reports allocations and GC counts per operation.
  • dotnet-counters shows the live allocation rate, and dotnet-trace can capture allocation events.
  • Visual Studio and Rider have allocation profilers, and analyzers (for example the ClrHeapAllocationAnalyzer extension) flag likely allocations as you type.
long before = GC.GetAllocatedBytesForCurrentThread();
RunWorkload();
long bytes = GC.GetAllocatedBytesForCurrentThread() - before;
Console.WriteLine($"{bytes:N0} bytes allocated");

Value semantics avoid heap allocations when the data is small. A readonly struct holding two ints costs nothing on the heap, while a class costs an object header plus fields. But large structs are copied on every pass, and mutable structs invite bugs. Pass larger structs with in or ref readonly to avoid copies, and only optimize paths a profiler proves are hot.

The key insight Optimize allocations only where a measurement says they matter. A hidden allocation in a method that runs twice a day costs nothing, while the same one in a loop running a million times a second is the bottleneck.

§4Common Mistakes

MistakeWhat HappensFix
Rewriting code to avoid allocations without measuringLess readable code with no real gainProfile first, then fix the top offenders
Using non-generic collections (ArrayList, Hashtable)Every value-type element is boxedUse List<T> and Dictionary<TKey,TValue>
Large mutable structs passed by valueRepeated copying, and mutations that disappearUse classes, or readonly struct with in parameters
Practice
  1. Use GetAllocatedBytesForCurrentThread to measure a loop that calls string.Format("{0}", i) a million times, then rewrite it with interpolation of a span-based formatter and compare.
  2. Find every closure in a small method by reading its decompiled form in SharpLab, and rewrite one with a static lambda.
Key takeaways
  • Boxing allocates when a value type is treated as object or an interface; generics and constraints avoid it.
  • Closures, LINQ, string operations, params, and async state machines are common hidden allocation sources.
  • Measure with allocation counters and BenchmarkDotNet before optimizing.
