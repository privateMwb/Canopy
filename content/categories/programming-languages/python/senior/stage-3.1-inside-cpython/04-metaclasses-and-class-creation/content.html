Metaclasses & Class Creation

Classes are objects created by type, and a metaclass customizes that creation, though simpler hooks handle nearly every real need.

§1Classes Are Objects

A class statement creates an object, an instance of type. You can do the same call by hand.

def greet(self):
    return f"Hi, {self.name}"

Person = type("Person", (object,), {"greet": greet, "species": "human"})
p = Person()
p.name = "Ana"
print(p.greet(), type(p), type(Person))   # Hi, Ana <class '__main__.Person'> <class 'type'>

type(name, bases, namespace) is what the class statement ends up calling. The class of a class is its metaclass, type by default.

§2Writing a Metaclass

A metaclass subclasses type and can intercept class creation.

class RegistryMeta(type):
    registry = {}

    def __new__(mcls, name, bases, namespace):
        cls = super().__new__(mcls, name, bases, namespace)
        if bases:                          # skip the base class itself
            RegistryMeta.registry[name] = cls
        return cls

class Plugin(metaclass=RegistryMeta):
    pass

class CsvExport(Plugin): ...
class JsonExport(Plugin): ...

print(list(RegistryMeta.registry))        # ['CsvExport', 'JsonExport']

It works, but it forces a metaclass onto every subclass, and two libraries with different metaclasses can't be combined without a conflict.

§3Simpler Alternatives

Python added hooks that cover most of what people once wrote metaclasses for.

class Plugin:
    registry = {}

    def __init_subclass__(cls, **kwargs):      # runs when a subclass is created
        super().__init_subclass__(**kwargs)
        Plugin.registry[cls.__name__] = cls

class CsvExport(Plugin): ...

# Descriptors get __set_name__; a class decorator can modify a class after creation
def add_repr(cls):
    cls.__repr__ = lambda self: f"{cls.__name__}({self.__dict__})"
    return cls

Prefer, in order: a plain function or class, a class decorator, __init_subclass__, __set_name__, and a metaclass last.

§4When a Metaclass Is Warranted

  • Controlling the class namespace before the body runs (__prepare__), as in enums, which preserve definition order and reject duplicates.
  • Changing how class calls work (__call__, e.g. for singletons).
  • Framework-level behavior that must apply to every subclass in a way a hook can't express, as in abc.ABCMeta, Enum, and ORM model classes.
from abc import ABC, abstractmethod

class Shape(ABC):                  # ABC uses ABCMeta underneath
    @abstractmethod
    def area(self): ...

# Shape() raises TypeError: can't instantiate abstract class

Application code almost never needs one. If you can't explain why __init_subclass__ won't do, don't write a metaclass.

The key insight "Metaclasses are deeper magic than 99% of users should ever worry about." The goal of this lesson is to read a metaclass in someone else's framework, not to write your own.

§5Common Mistakes

MistakeWhat HappensFix
Writing a metaclass when __init_subclass__ or a decorator would doNeedless complexity and metaclass conflictsTry the simpler hook first
Combining classes with different metaclassesTypeError: metaclass conflictDerive a combined metaclass, or avoid mixing
Forgetting super().__new__ in a metaclassClass creation breaks or returns NoneAlways call and return the result of super().__new__(...)
Practice
  1. Create a class dynamically with type(...), then write the equivalent class statement and compare __dict__ contents.
  2. Rewrite the RegistryMeta plugin example using __init_subclass__ and list what you gain.
Key takeaways
  • Classes are objects built by type(name, bases, namespace); a metaclass customizes that process.
  • __init_subclass__, __set_name__, and class decorators cover most needs without a metaclass.
  • Reserve metaclasses for framework-level cases like ABCMeta, enums, and ORM models.
