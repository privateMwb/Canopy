Making Python Faster

Most speedups come from a better algorithm or data structure, then built-ins and libraries, long before any exotic tool.

§11. Fix the Algorithm

Changing the complexity class dwarfs every micro-optimization. The classic case is membership testing:

# O(n * m): scans the whole list for every item
common = [x for x in a if x in b_list]

# O(n + m): hash lookups
b_set = set(b_list)
common = [x for x in a if x in b_set]

Other high-value moves: use a dict as an index instead of searching, sort once instead of repeatedly, collections.deque instead of list.pop(0), "".join(parts) instead of repeated +=, and heapq for "top k."

§22. Use Built-ins and the Standard Library

Built-ins like sum, min, max, sorted, any, all, and the str methods run in C and beat equivalent Python loops.

total = 0
for n in numbers:            # slower
    total += n

total = sum(numbers)         # faster, and clearer

Comprehensions are generally faster than building a list with repeated append calls. Local variable access is faster than global access, so inside a hot loop, bind a function to a local name only if the profiler tells you it matters.

§33. Cache Repeated Work

from functools import lru_cache

@lru_cache(maxsize=1024)
def parse_rule(text):
    ...                      # expensive pure computation

Avoid recomputing values inside loops: hoist invariant work (such as a compiled regex via re.compile) out.

§44. Move the Loop into C

For numerical work, vectorize: use NumPy or pandas so loops run in compiled code over whole arrays.

import numpy as np

xs = np.arange(1_000_000)
ys = xs * 2 + 1             # one fast operation; no Python-level loop

Typically this is 10x to 100x faster than the equivalent Python for loop.

§55. Only Then Go Further

  • Concurrency: threads or asyncio for I/O waits; processes for CPU-bound parallel work.
  • Native acceleration: Cython, Numba, or a Rust/C extension for a small hot function (Stage 3.2).
  • Interpreter improvements: each CPython release has been getting faster, so upgrading Python is a free win. An experimental JIT exists in recent versions.
  • A different tool: if the whole system needs raw speed, perhaps Python isn't the right choice for that component.
The key insight The order matters: algorithm, then built-ins, then caching, then vectorization, then concurrency, then native code. Each step is more complex and more costly to maintain than the last.

§6Common Mistakes

MistakeWhat HappensFix
Micro-optimizing a loop with a bad algorithmTiny gains while the O(n²) remainsFix the complexity first
Caching results of functions with side effectsStale or skipped behaviorCache only pure functions
Looping over NumPy arrays element by elementSlower than plain listsUse vectorized operations
Practice
  1. Take a function that finds duplicate items with nested loops, rewrite it with a set, and time both on 10,000 items.
  2. Replace a Python loop that sums squares of a million numbers with a NumPy expression and report the speedup.
Key takeaways
  • Better algorithms and data structures give the largest speedups.
  • Built-ins, caching, and vectorization move work out of the interpreter's slow path.
  • Reach for concurrency and native code only after profiling shows they're needed.
