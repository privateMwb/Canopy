Linting, Formatting & CI

Automated formatting, linting, and continuous integration make quality checks a habit enforced by machines instead of a debate in code review.

§1Formatting and Linting with ruff

ruff is a fast tool that both lints (finds likely bugs and style issues) and formats code. A formatter ends style arguments by having one answer.

python -m pip install ruff
ruff format .             # reformat files in place
ruff check .              # lint
ruff check . --fix        # apply safe automatic fixes
# pyproject.toml
[tool.ruff]
line-length = 88
target-version = "py310"

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP"]   # pycodestyle, pyflakes, isort, bugbear, pyupgrade

Typical findings: unused imports and variables, undefined names, mutable default arguments, bare except, and unsorted imports. Black is another widely used formatter, and Flake8 and isort are older tools that ruff replaces.

§2Pre-commit Hooks

pre-commit runs checks automatically on git commit, so problems never reach the repository.

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.8.0            # pin the version you actually use
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
python -m pip install pre-commit
pre-commit install         # register the git hook
pre-commit run --all-files

Hooks give fast local feedback. They can be skipped (git commit --no-verify), so CI must repeat them.

§3Continuous Integration

CI runs your checks on every push and pull request, on a clean machine, across the Python versions you support. A GitHub Actions workflow:

# .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.10", "3.11", "3.12", "3.13"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
      - run: python -m pip install -e ".[dev]"
      - run: ruff check .
      - run: ruff format --check .
      - run: mypy src
      - run: pytest --cov=myapp

Make the pipeline the gate: protect the main branch so changes merge only when CI is green.

§4Keeping It Fast and Trusted

  • Cache dependencies, and run the quickest checks (format, lint) first.
  • Fix or delete flaky tests promptly. A suite people re-run "until it passes" stops being believed.
  • Run the same commands locally that CI runs, ideally through one entry point such as a Makefile, nox, or tox configuration.
The key insight Automate whatever you'd otherwise mention in a code review. Reviewers should spend their attention on design and correctness, not on indentation and import order.

§5Common Mistakes

MistakeWhat HappensFix
Relying only on local hooksContributors can bypass themRun the same checks in CI and require them to pass
Enabling every lint rule at onceA flood of noisy warnings that people ignoreStart with a small rule set and expand deliberately
Testing only one Python version in CIBreakage on versions you claim to supportUse a matrix over supported versions
Practice
  1. Add ruff, mypy, and pytest to a project's pyproject.toml and run them locally with one command.
  2. Write a GitHub Actions workflow that runs the checks on two Python versions and make a deliberately failing commit to see it go red.
Key takeaways
  • A formatter plus a linter (ruff) removes style debates and catches common bugs.
  • pre-commit gives fast local feedback; CI is the authoritative gate.
  • Test across supported Python versions and keep the pipeline fast and trustworthy.
