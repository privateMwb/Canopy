Iterators & the Iteration Protocol

A for loop calls iter() to get an iterator and next() until it raises StopIteration, and any object can join in by implementing two methods.

§1What a for Loop Does

An iterable is anything you can pass to iter(). An iterator is the object returned, which produces one value per next() call and raises StopIteration when exhausted. This loop:

for x in [10, 20]:
    print(x)

is equivalent to:

it = iter([10, 20])
while True:
    try:
        x = next(it)
    except StopIteration:
        break
    print(x)

Iterators are single-use: once exhausted, they stay exhausted. Lists, dicts, strings, files, and range are iterables that hand out fresh iterators each time.

it = iter("ab")
print(next(it), next(it))    # a b
print(next(it, "done"))      # done  (default avoids StopIteration)
print(list(it))              # []   already consumed

§2Writing an Iterator Class

An iterator implements __iter__ (returning itself) and __next__. An iterable implements __iter__ (returning a new iterator).

class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value

print(list(Countdown(3)))    # [3, 2, 1]

This class is its own iterator, so it can be looped only once. A reusable container instead returns a new iterator from __iter__ each time it's called.

class Playlist:
    def __init__(self, songs):
        self._songs = songs

    def __iter__(self):
        return iter(self._songs)     # fresh iterator per loop

§3Tools That Consume Iterators

list(), tuple(), sum(), max(), sorted(), " ".join(), unpacking, and in all accept any iterable. zip, map, filter, and enumerate return lazy iterators, not lists, so nothing is computed until you pull values.

squares = map(lambda n: n * n, range(1_000_000))   # instant: nothing computed yet
print(next(squares), next(squares))                 # 0 1
The key insight Iteration is a protocol, not a type. Anything that implements __iter__ works in for loops, comprehensions, sum, and unpacking, with no inheritance required.

§4Common Mistakes

MistakeWhat HappensFix
Looping twice over an iterator or zip objectThe second loop sees nothingConvert to a list if you need multiple passes
Returning self from __iter__ on a container classThe container can be iterated only onceReturn a new iterator each call
Forgetting StopIteration in __next__An infinite loopRaise it when the data runs out
Practice
  1. Write an iterator class Fibonacci(limit) that yields Fibonacci numbers up to limit.
  2. Demonstrate that map(str, [1, 2, 3]) can only be consumed once, then fix it so it can be reused.
Key takeaways
  • for calls iter() then next() until StopIteration.
  • Iterators are single-use; iterables produce a fresh iterator each time.
  • Implement __iter__ and __next__ to make your own types work with every iteration tool.
