Closures & Decorators

Functions are objects that can capture variables from their surroundings, and decorators are functions that wrap other functions to add behavior.

§1First-Class Functions and Closures

A function can be passed around like any value. An inner function can close over variables from its enclosing function, remembering them after the outer function returns.

def make_multiplier(n):
    def multiply(x):
        return x * n          # n is captured from the enclosing scope
    return multiply

double = make_multiplier(2)
print(double(5))              # 10
print(double.__closure__[0].cell_contents)   # 2

To rebind (not just read) an enclosing variable, declare it nonlocal.

def counter():
    count = 0
    def next_value():
        nonlocal count
        count += 1
        return count
    return next_value

§2Decorators

@decorator above a function is shorthand for func = decorator(func). A decorator takes a function and returns a replacement, usually one that wraps the original.

import time

def timed(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper

@timed
def slow_sum(n):
    return sum(range(n))

slow_sum(10_000_000)

Using *args, **kwargs lets the wrapper accept whatever the original does.

§3Preserving Metadata with functools.wraps

Without care, the wrapper replaces the original's __name__ and docstring, which confuses debuggers and documentation tools. functools.wraps copies them over.

from functools import wraps

def timed(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        ...
        return func(*args, **kwargs)
    return wrapper

§4Decorators with Arguments

A decorator that takes arguments is a function that returns a decorator, so there are three nested levels.

from functools import wraps

def retry(times):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == times:
                        raise
        return wrapper
    return decorator

@retry(times=3)
def fetch():
    ...

@retry(times=3) first calls retry(3), which returns the real decorator that is then applied to fetch.

The key insight A decorator runs once, at definition time, to build the wrapper. The wrapper runs on every call. Keeping those two moments straight explains nearly every decorator bug.

§5Common Mistakes

MistakeWhat HappensFix
Omitting @wraps(func)Wrapped functions lose their name and docstringAlways apply functools.wraps
Forgetting return in the wrapperThe decorated function returns NoneReturn func(*args, **kwargs)
Writing @retry instead of @retry(3) for a parametrized decoratorThe function is passed as the argument and calls breakMatch the decorator's form: with parentheses when it takes arguments
Practice
  1. Write a @logged decorator that prints the function name, arguments, and return value on every call.
  2. Write @cache_results that stores return values in a dict keyed by the arguments, then compare it to functools.lru_cache.
Key takeaways
  • Closures capture variables from the enclosing scope; use nonlocal to rebind them.
  • @dec means func = dec(func), and wrappers should use *args, **kwargs.
  • Apply functools.wraps to preserve the wrapped function's metadata.
