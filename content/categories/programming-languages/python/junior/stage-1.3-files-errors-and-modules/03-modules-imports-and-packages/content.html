Modules, Imports & Packages

A module is a .py file you can import, and a package is a folder of modules, which is how scripts grow into projects.

§1Importing

import x binds the module; from x import name binds one thing from it. Python caches modules in sys.modules, so a module's top-level code runs only on the first import.

import math
from pathlib import Path
from collections import defaultdict as dd   # alias

print(math.sqrt(16))

Prefer import module or from module import specific_name over from module import *, which pollutes your namespace.

§2How import Finds Code

Python searches the directories in sys.path in order: the script's directory, standard library locations, then installed packages (site-packages). If two files share a name, the earlier directory wins, so don't name your own file random.py or json.py.

import sys
print(sys.path[0])        # the script's directory
import math
print(math.__file__)      # where this module lives (built-in modules may lack it)

§3The __main__ Guard

When a file runs directly, __name__ is "__main__"; when it's imported, __name__ is the module's name. The guard lets one file act as both a library and a script.

# textutils.py
def shout(s):
    return s.upper() + "!"

def main():
    print(shout("hello"))

if __name__ == "__main__":
    main()

Now python3 textutils.py prints HELLO!, but import textutils defines shout without printing anything.

§4Packages

A directory containing modules becomes a package; an __init__.py file marks it explicitly and runs on import.

shop/
    __init__.py
    cart.py
    pricing.py
main.py
# main.py
from shop import cart
from shop.pricing import apply_discount

Inside a package, relative imports like from . import pricing or from .cart import Cart refer to siblings. Run packaged code with python3 -m shop.cli from the project root so imports resolve correctly.

The key insight Importing runs code. Keep top-level statements in a module limited to definitions, and put anything that does real work behind if __name__ == "__main__":.

Practice
  1. Split a single script into utils.py and main.py, with a __main__ guard in utils.py that demos the functions.
  2. Create a two-module package and import from it using both import package.module and from package import module.
Key takeaways
  • Importing executes a module once and caches it in sys.modules.
  • sys.path determines what import finds, and your filenames can shadow the standard library.
  • Use if __name__ == "__main__": so a file works as both script and importable module.
