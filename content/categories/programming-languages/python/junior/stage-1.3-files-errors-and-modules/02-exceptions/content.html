Exceptions

Exceptions signal that something went wrong, and try/except lets you handle the failures you can actually recover from.

§1try / except / else / finally

Code in try runs; if it raises, the first matching except handles it. else runs only if nothing was raised. finally always runs, for cleanup.

def read_age(text):
    try:
        age = int(text)
    except ValueError:
        print("not a number:", text)
        return None
    else:
        return age          # only when conversion succeeded
    finally:
        print("done checking")

Handle specific exception types, and keep the try block as small as possible so you know which line failed.

§2Catching Too Much

A bare except: or except Exception: swallows bugs you didn't anticipate, including typos and logic errors. Catch only what you can meaningfully handle.

# Bad: hides every problem
try:
    result = process(data)
except Exception:
    pass

# Good: specific, with a response
try:
    with open(path, encoding="utf-8") as f:
        text = f.read()
except FileNotFoundError:
    text = ""
except PermissionError as err:
    print(f"cannot read {path}: {err}")
    raise

A bare raise inside except re-raises the current exception with its original traceback.

§3Raising Your Own

Use raise to signal invalid input or states. Define a custom exception class when callers need to catch your errors specifically.

class InsufficientFunds(Exception):
    pass

def withdraw(balance, amount):
    if amount <= 0:
        raise ValueError("amount must be positive")
    if amount > balance:
        raise InsufficientFunds(f"need {amount - balance} more")
    return balance - amount

try:
    withdraw(10, 50)
except InsufficientFunds as err:
    print("declined:", err)

To chain a cause, use raise NewError("...") from original, which keeps both tracebacks.

The key insight Python style favors EAFP, "easier to ask forgiveness than permission": try the operation and handle failure, rather than checking every precondition first, which can also go stale between the check and the action.

§4Common Mistakes

MistakeWhat HappensFix
Writing a bare except:Catches KeyboardInterrupt and hides bugsCatch specific types

Putting a large block inside tryYou can't tell which line raisedWrap only the risky line, and use else for the rest
Practice
  1. Write safe_int(text, default=0) that returns the integer, or the default when the text isn't valid.
  2. Define a ValidationError and raise it from a function that checks a username (length, allowed characters).
Key takeaways
  • Catch specific exceptions you can handle; let unexpected ones propagate.
  • else runs on success and finally always runs, which suits cleanup.
  • Raise exceptions to signal problems, and define custom classes when callers need to tell them apart.
