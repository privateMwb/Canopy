Configuration & Secrets

Functions need API keys and settings, and those should live outside your source code, with secrets stored in a secret manager.

§1Parameters

Use parameterized configuration for non-secret settings.

import { defineString, defineInt } from "firebase-functions/params";

const region = defineString("TARGET_REGION", { default: "us-central1" });
const maxItems = defineInt("MAX_ITEMS", { default: 100 });

export const f = onRequest((req, res) => res.json({ max: maxItems.value() }));

Values can come from .env files in the functions folder, such as .env.dev and .env.prod, picked by the active project alias, or from prompts at deploy time. Call .value() only inside the function body, not at the top level.

§2Secrets

API keys and passwords go in Secret Manager, never in .env files or code.

firebase functions:secrets:set STRIPE_KEY       # prompts for the value
import { defineSecret } from "firebase-functions/params";
const stripeKey = defineSecret("STRIPE_KEY");

export const charge = onCall({ secrets: [stripeKey] }, async (request) => {
  const stripe = new Stripe(stripeKey.value());
  // ...
});

A secret is available only to functions that list it in secrets, and the value is injected at runtime. Rotate a secret by setting a new version and redeploying.

§3Global Options and Cold Starts

import { setGlobalOptions } from "firebase-functions/v2";
setGlobalOptions({ region: "europe-west1", maxInstances: 10 });

Choose a region close to your database. maxInstances caps how far a function can scale, which also caps your bill during a traffic spike or a loop. A new instance has a cold start delay; minInstances keeps some warm at a cost.

Secrets never go in git If a key was ever committed, treat it as leaked and rotate it. Removing it from the latest commit does not remove it from history.

§4Common Mistakes

MistakeWhat HappensFix
Putting API keys in .env files that are committedKeys leak through the repositoryUse defineSecret and Secret Manager
Reading a parameter's .value() at the top levelError at deploy because the value is not yet availableRead it inside the function
No maxInstances on a function that calls a paid APIA loop or spike causes a huge billSet a sensible cap
Practice
  1. Store a fake API key as a secret and read it inside a callable function.
  2. Set maxInstances and region globally and confirm in the console.
Key takeaways
  • Use params for settings and Secret Manager for secrets.
  • Only functions that declare a secret can read it.
  • Set region and instance caps to control latency and cost.
