Cloud Messaging

Firebase Cloud Messaging (FCM) delivers push notifications to web, iOS, and Android clients through one API.

§1Getting a Token

Each app installation has an FCM registration token. The client requests permission, gets the token, and saves it to your database tied to the user.

import { getMessaging, getToken, onMessage } from "firebase/messaging";

const permission = await Notification.requestPermission();
if (permission === "granted") {
  const token = await getToken(getMessaging(), { vapidKey: "YOUR_WEB_PUSH_KEY" });
  await setDoc(doc(db, "users", uid, "tokens", token), { createdAt: serverTimestamp() });
}

onMessage(getMessaging(), (payload) => showToast(payload.notification.title));   // app in foreground

On the web you also need a service worker file named firebase-messaging-sw.js at your site root to receive messages when the page is closed. On iOS, push requires an Apple Push Notification service key uploaded to Firebase.

§2Sending

Messages are sent from trusted code, such as a function, or from the console for tests.

import { getMessaging } from "firebase-admin/messaging";

await getMessaging().send({
  token,
  notification: { title: "New message", body: "Alice: hi" },
  data: { roomId: "r1" },
});

await getMessaging().send({ topic: "news", notification: { title: "Update available" } });

A notification message is shown by the system when the app is in the background. A data message is delivered to your code to handle. You can send to one token, many tokens, or a topic that clients subscribe to.

§3Keeping Tokens Healthy

Tokens change and expire. Refresh and store them when the app starts, save one per device, and delete tokens that FCM reports as unregistered after a send fails with messaging/registration-token-not-registered. Respect permission: ask at a moment when the benefit is clear, not on first load.

Permission is earned A blocked notification permission is hard to recover. Ask after the user does something that makes notifications obviously useful.

§4Common Mistakes

MistakeWhat HappensFix
Asking for permission on first page loadMost users decline, and the prompt may not returnAsk in context, after a user action
Never removing dead tokensSends fail and waste timeDelete tokens FCM reports as not registered
Sending from client codeAnyone could send notifications to your usersSend only from a function or other trusted server
Practice
  1. Set up the service worker, get a token on the web, and send yourself a test message from the console.
  2. Write a function that sends a notification when a new message document is created.
Key takeaways
  • FCM uses per-device registration tokens that you store and refresh.
  • Send from trusted code; use notification messages, data messages, or topics.
  • Ask for permission in context and prune dead tokens.
