Realtime Database vs. Firestore

Firebase has two databases. The Realtime Database came first and stores one big JSON tree; Firestore is newer and stores documents in collections.

§1The Realtime Database Model

Everything lives in a single JSON tree, and you read and write by path.

import { getDatabase, ref, set, push, onValue, update } from "firebase/database";

const db = getDatabase();
await set(ref(db, "users/alice"), { name: "Alice", online: true });
await push(ref(db, "messages"), { from: "alice", text: "hi" });   // push makes a unique, time-ordered key
await update(ref(db), { "users/alice/online": false });          // update several paths at once

onValue(ref(db, "messages"), (snap) => console.log(snap.val()));

Reading a node downloads its entire subtree, so a deep, wide tree makes reads expensive.

§2How They Differ

In practiceRealtime DatabaseFirestore
Data modelOne JSON treeCollections of documents
QueryingSort and filter on one propertyMultiple filters, composite indexes
ReadsDownload a whole subtreeReturn only the documents requested
PricingMostly bandwidth and storagePer document operation
RulesCascade down the treeApply per matched document
ScaleSingle region instance, sharded by handScales automatically

§3Choosing

Choose Firestore for most new apps: it queries better and scales without manual sharding. Choose the Realtime Database when you need very low latency for tiny, frequent updates such as presence, cursors, or live game state, or when you will move large amounts of data cheaply because you pay by bandwidth. You can use both in one project, and many apps do for exactly that reason.

Two databases, one project Using Firestore for your main data and the Realtime Database for presence is common and sensible, since each does the job it is best at.

§4Common Mistakes

MistakeWhat HappensFix
Deeply nesting data in the Realtime DatabaseReading one node downloads huge subtreesKeep the tree flat and reference by ID
Picking Realtime Database for relational queriesYou cannot filter on several fieldsUse Firestore for rich queries
Assuming Realtime Database rules work like Firestore'sA permissive parent rule grants access to childrenRemember that rules cascade down the tree
Practice
  1. Write a message to the Realtime Database with push and watch it with onValue.
  2. For a chat app with online indicators, decide which data goes in which database and justify it.
Key takeaways
  • The Realtime Database is one JSON tree; Firestore is documents and collections.
  • Realtime Database wins at tiny, high-frequency updates; Firestore wins at queries and scale.
  • Mixing both in one project is normal.
