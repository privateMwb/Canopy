Cloud Storage for Firebase

Cloud Storage holds user-uploaded files such as photos and documents, with its own security rules separate from Firestore's.

§1Uploading and Downloading

import { getStorage, ref, uploadBytes, uploadBytesResumable,
         getDownloadURL, deleteObject } from "firebase/storage";

const storage = getStorage();
const fileRef = ref(storage, `users/${uid}/avatar.jpg`);

await uploadBytes(fileRef, file);                 // simple upload of a File or Blob
const url = await getDownloadURL(fileRef);        // a long-lived URL for <img src>

// with progress
const task = uploadBytesResumable(fileRef, file);
task.on("state_changed", (s) => console.log(s.bytesTransferred / s.totalBytes));

await deleteObject(fileRef);

Storage is organized as paths in a bucket, like folders, and each file keeps its own metadata such as contentType and size.

§2Storage Rules

Storage has its own rules file, storage.rules, deployed with firebase deploy --only storage. The syntax resembles Firestore's.

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /users/{userId}/{allPaths=**} {
      allow read: if request.auth != null;
      allow write: if request.auth != null
        && request.auth.uid == userId
        && request.resource.size < 5 * 1024 * 1024
        && request.resource.contentType.matches('image/.*');
    }
  }
}

Always check size and content type on writes, or users can upload huge or unexpected files.

§3Download URLs Are Capabilities

A download URL contains a secret token, and anyone who has the URL can open the file without signing in, regardless of rules. That is fine for avatars and public images. For private files, do not store or share the download URL; fetch the file with getBytes or getBlob, which are subject to rules, or generate short-lived signed URLs from a server.

Rules guard the bucket, not the URL A leaked download URL bypasses rules. Treat each one as a password to that file and do not put them in places users can share.

§4Common Mistakes

MistakeWhat HappensFix
Allowing uploads with no size or type limitUsers can fill your storage with huge or executable filesCheck request.resource.size and contentType in rules
Storing private documents behind plain download URLsAnyone with the link can read themUse rule-checked reads or signed URLs
Using the original filename as the pathCollisions overwrite files; odd characters cause bugsUse a unique name such as a generated ID
Practice
  1. Upload an image to users/{uid}/avatar.jpg and show it with its download URL.
  2. Add a rule that rejects uploads over 2 MB and prove it with an oversized file.
Key takeaways
  • Cloud Storage keeps files in a bucket, organized by path, with its own rules.
  • Validate user, size, and content type in the rules.
  • A download URL grants access to anyone who holds it.
