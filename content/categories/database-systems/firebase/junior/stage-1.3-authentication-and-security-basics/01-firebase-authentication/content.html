Firebase Authentication

Firebase Authentication handles sign-up, sign-in, password storage, and tokens, so you never store a password yourself.

§1Enabling Providers

In the console, open Authentication → Sign-in method and enable the providers you want. Each user gets a stable uid, which becomes the key you use in your database and rules.

  • Email and password: the simplest, with built-in email verification and reset
  • Social: Google, Apple, GitHub, and others, usually through a popup or redirect
  • Anonymous: a real uid without any sign-up, useful for try-before-you-register
  • Phone: one-time codes by SMS

§2Signing Up and In

import { getAuth, createUserWithEmailAndPassword, signInWithEmailAndPassword,
         signInWithPopup, GoogleAuthProvider, signInAnonymously } from "firebase/auth";

const auth = getAuth();

const cred = await createUserWithEmailAndPassword(auth, "ana@example.com", "s3cret-pass");
console.log(cred.user.uid);

await signInWithEmailAndPassword(auth, "ana@example.com", "s3cret-pass");

await signInWithPopup(auth, new GoogleAuthProvider());

await signInAnonymously(auth);

Failures throw errors with a code such as auth/wrong-password or auth/email-already-in-use. Show friendly messages by switching on that code rather than printing the raw error.

§3What the Tokens Do

After sign-in the SDK holds an ID token, a signed JWT that proves who the user is. It refreshes automatically about every hour. The SDK attaches it to requests to Firestore, Storage, and Functions, and security rules read it as request.auth. You rarely handle tokens by hand.

The uid is your key Use user.uid as the document ID or owner field for per-user data. Never use the email address as a key: it can change, and it is not what rules can trust.

§4Common Mistakes

MistakeWhat HappensFix
Showing raw error messagesUsers see technical text and attackers learn which emails existMap error.code to friendly, safe messages
Enabling a provider but not adding the app's domainPopup sign-in fails with an unauthorized-domain errorAdd your domain under Authentication → Settings → Authorized domains
Storing the password in your databaseA serious breach risk and unnecessaryLet Firebase Authentication hold credentials
Practice
  1. Enable email and Google sign-in and build a small form that signs a user up and in.
  2. Sign in anonymously and print the uid; refresh the page and check it persists.
Key takeaways
  • Firebase Authentication provides identities and a stable uid per user.
  • The SDK keeps and refreshes the ID token automatically.
  • Handle failures by error code, and never roll your own password storage.
