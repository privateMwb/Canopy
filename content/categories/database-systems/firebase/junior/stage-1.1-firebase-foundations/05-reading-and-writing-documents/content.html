Reading & Writing Documents

Four write calls and two read calls cover most Firestore work, and each behaves differently when the document does or does not exist.

§1Writing

import { doc, collection, setDoc, addDoc, updateDoc, deleteDoc,
         serverTimestamp, increment } from "firebase/firestore";

// setDoc: you choose the ID. Overwrites the whole document by default.
await setDoc(doc(db, "users", "alice"), { name: "Alice", age: 31 });

// setDoc with merge: only touches the fields you list
await setDoc(doc(db, "users", "alice"), { age: 32 }, { merge: true });

// addDoc: Firestore chooses the ID and returns a reference
const ref = await addDoc(collection(db, "notes"), {
  text: "Buy milk",
  createdAt: serverTimestamp(),
});
console.log(ref.id);

// updateDoc: changes fields; fails if the document does not exist
await updateDoc(doc(db, "users", "alice"), { age: increment(1), "address.city": "Porto" });

// deleteDoc: removes the document; succeeds even if it was already gone
await deleteDoc(doc(db, "notes", ref.id));

§2Reading

import { getDoc, getDocs } from "firebase/firestore";

const snap = await getDoc(doc(db, "users", "alice"));
if (snap.exists()) {
  console.log(snap.id, snap.data());
}

const all = await getDocs(collection(db, "notes"));
all.forEach((d) => console.log(d.id, d.data()));

getDoc always resolves, even for a missing document, so check snap.exists() before using snap.data().

§3What Each Call Gives Back

  • setDoc, updateDoc, deleteDoc resolve with nothing useful
  • addDoc resolves with the new document's reference
  • getDoc gives a snapshot with .exists(), .data(), and .id
  • getDocs gives a query snapshot you can loop over
Overwrite versus merge setDoc without merge replaces the entire document and silently erases any field you left out. Use updateDoc or setDoc with merge: true when you mean to change only some fields.

§4Common Mistakes

MistakeWhat HappensFix
Using setDoc to change one fieldEvery other field is deletedUse updateDoc or { merge: true }
Calling updateDoc on a document that may not existError: No document to updateUse setDoc with merge to create or update
Reading, adding one, and writing back a counterTwo clients overwrite each other's changeUse increment() so the server applies the change
Practice
  1. Create a user document, then change one field without losing the others, in two different ways.
  2. Write a function that reads a document and prints a friendly message when it does not exist.
Key takeaways
  • setDoc replaces unless you pass merge; updateDoc changes fields but requires the document to exist.
  • addDoc generates the ID and returns a reference.
  • getDoc resolves even for missing documents, so always check exists().
