Connecting a Web App

Connecting a web app means registering it in the console, pasting its config object into your code, and initializing the SDK modules you need.

§1Install and Initialize

Register a web app in the console to get a config object, then initialize once at startup.

npm install firebase
// firebase.js
import { initializeApp } from "firebase/app";
import { getFirestore } from "firebase/firestore";
import { getAuth } from "firebase/auth";

const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "my-app.firebaseapp.com",
  projectId: "my-app",
  storageBucket: "my-app.firebasestorage.app",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abc123",
};

const app = initializeApp(firebaseConfig);
export const db = getFirestore(app);
export const auth = getAuth(app);

§2The Modular SDK

Since version 9 the web SDK is modular: you import only the functions you call, and bundlers drop the rest. Every function takes the service instance as its first argument, such as doc(db, ...) or signOut(auth). Older tutorials show the namespaced style (firebase.firestore()); it still exists as a compat layer but new code should use the modular imports.

§3Is the Config a Secret?

No. The apiKey here only identifies your project to Google's servers. It is not a credential and ships inside every client bundle. Anyone can read it, so it protects nothing.

What actually protects your data is security rules and, for server-side access, service account credentials. Those service account keys are secrets and must never appear in client code or a public repository.

Public config, private keys The web config object is safe to commit. A service account JSON file is not. If a file contains a private_key, it is a secret.

§4Common Mistakes

MistakeWhat HappensFix
Believing the apiKey needs hiding and not writing rulesThe app is wide open while the key is hiddenPut your effort into security rules
Initializing the app in every fileError: a Firebase App named '[DEFAULT]' already existsInitialize once in a shared module and import db and auth from it
Mixing compat and modular importsConfusing errors and a larger bundleUse the modular API throughout
Practice
  1. Register a web app, create firebase.js as above, and log db.type to confirm it initialized.
  2. Search your project for the words private_key to check no service account key is committed.
Key takeaways
  • Initialize the SDK once and export the service instances.
  • The modular SDK imports individual functions and takes the service as the first argument.
  • The web config is public; service account keys and rules are what matter for security.
