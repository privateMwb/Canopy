Queries & Filters

A Firestore query selects documents from one collection with where filters, and every filter must be answerable from an index.

§1Building a Query

import { collection, query, where, getDocs } from "firebase/firestore";

const q = query(
  collection(db, "products"),
  where("category", "==", "books"),
  where("price", "<", 20)
);
const snap = await getDocs(q);
snap.forEach((d) => console.log(d.id, d.data()));

Supported operators are ==, !=, <, <=, >, >=, in, not-in, array-contains, and array-contains-any. An empty result is not an error: you get a snapshot with snap.empty === true.

§2Arrays, in, and or

where("tags", "array-contains", "sale")               // array includes this value
where("tags", "array-contains-any", ["sale", "new"])  // includes any of these
where("status", "in", ["open", "pending"])            // field equals any of these

import { or, and } from "firebase/firestore";
query(col, or(where("status", "==", "open"), where("priority", "==", "high")))

in and array-contains-any accept a limited list of values (30 at the time of writing), and or queries are expanded into several queries behind the scenes.

§3What Firestore Won't Do

Firestore only runs queries it can serve from an index, so some things are simply not supported:

  • No full-text or substring search (contains, LIKE '%x%')
  • No joins across collections
  • No filtering on a field that is absent from the document (missing fields are not indexed)

Prefix matching works with a range trick: where("name", ">=", "Al") combined with where("name", "<", "Al\uf8ff").

Queries scale with results A Firestore query costs time and money in proportion to the documents it returns, not the size of the collection. That is why it needs an index for every filter and refuses queries it cannot serve efficiently.

§4Common Mistakes

MistakeWhat HappensFix
Expecting where("title", "contains", ...)No such operator existsUse prefix ranges, or add a search service for real text search
Querying a field some documents lackThose documents never appear in resultsWrite the field on every document, using null when empty
Forgetting != and not-in skip missing fieldsDocuments without the field are excludedStore an explicit value so they match
Practice
  1. Write a query for books under $20 that are in stock, then another that matches either of two categories.
  2. Add three documents and use a prefix range to find names starting with a chosen two letters.
Key takeaways
  • A query combines where filters against one collection and returns whole documents.
  • Operators include in, not-in, and array operators, but there is no substring search or join.
  • Documents missing a field never match filters on it.
