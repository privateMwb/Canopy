Composite Indexes & Query Limits

Firestore keeps an index for every query it can answer, creating simple ones automatically and asking you to define the multi-field ones.

§1Single-Field and Composite Indexes

For every field, Firestore automatically maintains a single-field index, which is why one filter or one orderBy just works. A query that combines several fields, such as an equality filter on one field plus an orderBy on another, needs a composite index you create.

// needs a composite index on (category ASC, price ASC)
query(col, where("category", "==", "books"), orderBy("price"))

§2Reading the Error

When an index is missing, the SDK throws an error that includes a link:

FirebaseError: The query requires an index. You can create it here:
https://console.firebase.google.com/v1/r/project/my-app/firestore/indexes?create_composite=...

Open the link, confirm, and wait for the index to build (seconds for small collections, longer for large ones). Better still, add it to firestore.indexes.json so it is versioned and deployable.

{
  "indexes": [
    {
      "collectionGroup": "products",
      "queryScope": "COLLECTION",
      "fields": [
        { "fieldPath": "category", "order": "ASCENDING" },
        { "fieldPath": "price", "order": "ASCENDING" }
      ]
    }
  ]
}
firebase deploy --only firestore:indexes

§3Limits to Remember

  • Each index adds storage and slows writes slightly, since every write updates every relevant index
  • Filtering on several fields with different inequality or range conditions has historically been restricted; newer Firestore versions allow it but require the matching composite index
  • Queries are always scoped to one collection (or a collection group, covered later)
Indexes are the contract If a query works in development against tiny data, it will work at any scale as long as its index exists. The index requirement is Firestore keeping its performance promise, not a nuisance.

§4Common Mistakes

MistakeWhat HappensFix
Copying an index into the console but not the fileThe next teammate or environment hits the same errorAdd it to firestore.indexes.json and deploy
Querying production before the index finishes buildingQueries fail during the buildWait for the index to show as enabled
Creating indexes you never useExtra write cost and storageRemove unused composites
Practice
  1. Write a query that needs a composite index, run it, and follow the error link to create the index.
  2. Move that index into firestore.indexes.json and deploy it with the CLI.
Key takeaways
  • Single-field indexes are automatic; multi-field queries need composite indexes.
  • The error message contains a link that creates the exact index required.
  • Keep indexes in firestore.indexes.json so they are versioned and repeatable.
