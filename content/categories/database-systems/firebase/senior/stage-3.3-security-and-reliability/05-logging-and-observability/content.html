Logging & Observability

Problems in a serverless system are found through logs, metrics, and alerts, so you design them before an incident, not during it.

§1Structured Logging

Use the functions logger so entries are structured and searchable in Cloud Logging.

import * as logger from "firebase-functions/logger";

export const onOrderCreated = onDocumentCreated("orders/{id}", async (event) => {
  logger.info("order received", { orderId: event.params.id, userId: event.data.data().userId });
  try {
    await process(event);
  } catch (err) {
    logger.error("order processing failed", { orderId: event.params.id, error: err.message });
    throw err;
  }
});

Log identifiers and outcomes, not secrets or personal data. Include a correlation ID (such as the order ID or event ID) so you can follow one request through several functions.

§2Finding and Reading Logs

firebase functions:log --only onOrderCreated

In the Google Cloud console, Logs Explorer supports queries such as severity>=ERROR and jsonPayload.orderId="o123". Error Reporting groups repeated exceptions automatically.

§3Alerts and Dashboards

Create alerting policies in Cloud Monitoring on signals such as function error rate, latency, instance count, and Firestore read and write rates. Also alert on billing anomalies. For client apps, Crashlytics reports crashes and Performance Monitoring shows slow screens and network calls. A short dashboard with the few numbers that tell you the system is healthy beats a hundred charts nobody reads.

Decide what you'll need to know Before launch, write the three questions you will ask during an incident and make sure a log, metric, or alert answers each.

§4Common Mistakes

MistakeWhat HappensFix
Logging with console.log of free textHard to search and filterUse structured logs with fields
Logging secrets or personal dataLeaks through logs and breaks privacy rulesLog identifiers only and redact sensitive values
No alert on function errors or spendYou learn about problems from users or the billCreate alerting policies for errors, latency, and cost
Practice
  1. Add structured logs with a correlation ID to one function and find them in Logs Explorer.
  2. Create an alert that fires when a function's error rate rises above a threshold.
Key takeaways
  • Use structured logs with correlation IDs, and keep secrets out of them.
  • Logs Explorer, Error Reporting, and alerts surface problems early.
  • Add Crashlytics and Performance Monitoring for client-side visibility.
