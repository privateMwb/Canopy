Admin SDK & Privileged Access

The Admin SDK acts with full privileges and ignores security rules, so the credentials and code that use it are your most sensitive assets.

§1What It Can Do

Server code using firebase-admin can read and write any Firestore data, manage users and claims, send messages, and access Storage, all without rules. In Cloud Functions it picks up credentials automatically from the function's service account, so you do not handle keys.

import { initializeApp } from "firebase-admin/app";
initializeApp();                       // uses the runtime's default credentials

§2Least Privilege

The default compute service account is often over-privileged (broad editor access). Better practice:

  • Give each function group its own dedicated service account with only the IAM roles it needs, such as roles/datastore.user for Firestore access
  • Avoid downloading service account key files; if one is unavoidable, store it in Secret Manager, rotate it, and never commit it
  • On CI and local machines, prefer short-lived credentials through Application Default Credentials or workload identity, instead of long-lived key JSON
  • Limit who has Owner or Editor on the project; use specific roles like Viewer for most people

§3Making Admin Code Safe

Because admin code ignores rules, it must do its own authorization. In a callable function, check request.auth and permissions before touching data. Validate inputs, scope queries to the caller's tenant, and log administrative actions with who, what, and when. Keep privileged functions small and reviewed carefully, and avoid generic "run this query" endpoints that accept arbitrary paths from clients.

Admin means you are the rules Once code bypasses rules, every check that rules would have made must be made in the code. Missing one is a vulnerability.

§4Common Mistakes

MistakeWhat HappensFix
Using a downloaded service account key in the repo or clientFull project compromise if leakedUse default credentials in Cloud Functions and secret storage elsewhere
Giving every function the default editor service accountA bug in one function can modify any resourceUse dedicated accounts with minimal roles
Accepting a document path from the client and using it with AdminClients can read or write anywhereBuild paths on the server from validated inputs
Practice
  1. List which of your functions use the Admin SDK and write the authorization check each one performs.
  2. Create a dedicated service account with only Firestore access and deploy a function with it.
Key takeaways
  • The Admin SDK bypasses rules, so its code must authorize on its own.
  • Use least-privilege service accounts and avoid key files.
  • Never let clients choose arbitrary paths for privileged operations.
