Replica Sets & Elections

A replica set is a group of MongoDB servers holding the same data, with one primary taking writes and the rest following, and elections choose a new primary when it disappears.

§1Members and Roles

A replica set normally has an odd number of voting members, at least three, so a majority can always be formed.

RoleHolds dataVotesCan be primary
PrimaryYesYesIt is the primary
SecondaryYesYesYes, if elected
ArbiterNoYesNo
Hidden / delayed secondaryYesYes (usually)No, by priority 0
rs.initiate({ _id: "rs0", members: [
  { _id: 0, host: "db1:27017", priority: 2 },
  { _id: 1, host: "db2:27017" },
  { _id: 2, host: "db3:27017" }
] })
rs.status()          // each member's state, health, and lag
rs.conf()            // the configuration, including priority and votes

All writes go to the primary, and the secondaries copy them. At most 50 members exist in a set, and at most 7 of them vote.

§2Heartbeats and Elections

Members exchange heartbeats every 2 seconds. If a secondary has not heard from the primary for the election timeout (10 seconds by default), it may call an election.

  1. The candidate asks the others for votes.
  2. A member votes yes if the candidate's oplog is at least as up to date as its own, and it has not already voted in this term.
  3. A candidate with votes from a majority of voting members becomes primary.
  4. The old primary, if it comes back, sees the higher term and steps down.

Higher priority makes a member more likely to win. Priority 0 means it can never become primary.

§3Why a Majority

Requiring a majority means that during a network split only one side can elect a primary, which prevents two primaries accepting conflicting writes.

A primary that cannot reach a majority steps down and becomes a secondary, so it stops accepting writes. For this reason, spread members across at least three failure domains, such as three zones, so that no one zone holds a majority.

The key insight Availability for writes needs a majority of voters alive and connected. Place the voters so that the failure you most fear cannot take a majority with it.

§4Common Mistakes

MistakeWhat HappensFix
An even number of voting membersNo extra fault tolerance, and ties are possibleUse an odd number
Two data centers with the majority in oneLosing that site stops writes everywherePut a tie-breaking member in a third location
Relying on an arbiter for data safetyAn arbiter votes but stores nothingPrefer a data-bearing member
Practice
  1. Draw a five-member set across three zones and list which failures it survives.
  2. Start a local three-member set, stop the primary, and watch the election with rs.status().
Key takeaways
  • A replica set has one primary for writes and secondaries that copy it.
  • Elections need a majority of voters, which avoids two primaries.
  • Place members across at least three failure domains.
