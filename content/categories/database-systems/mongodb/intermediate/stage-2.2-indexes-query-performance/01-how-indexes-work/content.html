How Indexes Work

A MongoDB index is a B-tree of key values pointing back to documents, and understanding its structure explains both why reads get fast and what each index costs on writes.

§1An Index Is a Sorted Structure

An index stores the values of the indexed fields in sorted order, each with a pointer to its document. Because it is a B-tree, finding one value, or a range, takes a handful of steps rather than a pass over every document.

db.users.createIndex({ age: 1 })
// index entries, sorted:  (18 -> doc7) (21 -> doc2) (21 -> doc9) (30 -> doc1) ...
db.users.find({ age: { $gte: 21, $lt: 30 } })    // walk to 21, read until 30

The same sorted order serves equality, range queries, and sorts on the indexed field. It cannot help a query that does not use the leading indexed field.

§2Multikey Indexes

When you index an array field, MongoDB creates one entry per element. This is called a multikey index.

// { _id: 1, tags: ["db", "nosql"] }
db.posts.createIndex({ tags: 1 })
// entries: ("db" -> 1) ("nosql" -> 1)
db.posts.find({ tags: "nosql" })              // uses the index

A compound index may include at most one array field, since combining two arrays would produce a combinatorial number of entries.

§3What an Index Costs

  • Writes: every insert and delete updates every index on the collection, and an update touches the indexes of the fields it changes.
  • Memory: indexes you use often should fit in RAM, or reads turn into disk reads.
  • Disk: each index has its own storage.
db.users.stats().indexSizes            // bytes per index
db.users.aggregate([{ $indexStats: {} }])   // how often each index is used

$indexStats shows which indexes are never used, which are candidates for removal.

The key insight A collection with ten indexes pays ten times the index maintenance on every write. Each index must earn its place by serving a real query.

§4Common Mistakes

MistakeWhat HappensFix
Adding an index for every query ideaSlow writes and memory pressureKeep indexes tied to real queries and drop unused ones
Expecting an index on a to help a query on bThe query scans the collectionIndex the fields you actually filter on
Indexing a low-selectivity field alone (such as a boolean)Little benefit, since half the collection still matchesCombine it into a compound index with a selective field
Practice
  1. Create an index on a tags array, and use explain to show that a tag query uses it.
  2. Use $indexStats on a test collection to identify an index that nothing queries.
Key takeaways
  • An index is a sorted B-tree of keys with pointers to documents.
  • Indexing an array creates an entry per element, called a multikey index.
  • Each index speeds reads and slows writes, so keep only the useful ones.
