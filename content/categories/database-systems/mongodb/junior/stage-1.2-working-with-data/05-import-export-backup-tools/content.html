Import, Export & Backup Tools

The MongoDB Database Tools move data in and out: mongoimport and mongoexport handle readable formats, while mongodump and mongorestore handle backups.

§1mongoimport and mongoexport

These tools work with JSON, CSV, and TSV, which makes them ideal for loading sample data or exchanging data with other systems.

mongoimport --uri "mongodb://localhost:27017/shop" --collection products --file products.json --jsonArray
mongoimport --uri "$MONGODB_URI" --collection people --type csv --headerline --file people.csv
mongoexport --uri "$MONGODB_URI" --collection products --query '{"stock":{"$gt":0}}' --out in-stock.json

CSV import has no types, so values arrive as strings unless you pass --columnsHaveTypes with a typed header. JSON export uses Extended JSON, which keeps types such as dates ({"$date": "..."}), and plain JSON would not.

§2mongodump and mongorestore

mongodump writes a binary BSON copy of your data, preserving types and indexes, and mongorestore reads it back.

mongodump --uri "$MONGODB_URI" --db shop --out ./backup
mongodump --uri "$MONGODB_URI" --db shop --archive=shop.gz --gzip

mongorestore --uri "mongodb://localhost:27017" --drop ./backup           # --drop replaces existing collections
mongorestore --uri "mongodb://localhost:27017" --archive=shop.gz --gzip --nsFrom "shop.*" --nsTo "shop_copy.*"

The --nsFrom and --nsTo options restore into a different database name, which is a safe way to test a backup.

§3Choosing the Right Tool

GoalTool
Load a JSON or CSV filemongoimport
Hand someone readable datamongoexport
Back up or clone a databasemongodump and mongorestore
Back up a very large production clusterSnapshots or Atlas backups (covered later)
The key insight mongodump is a logical backup that reads documents through the database, so it is fine for small and medium data and for moving data between environments, but slow for large deployments.

§4Common Mistakes

MistakeWhat HappensFix
Restoring over a live database without thinkingDuplicate key errors, or data silently keptRestore into a new name, or use --drop deliberately
Importing CSV and expecting numbersEvery field is a stringUse typed headers, or convert after import
Never testing a restoreYou find out the backup is broken during an incidentRestore into a scratch database regularly
Practice
  1. Export a collection to JSON, import it into a new database, and compare document counts.
  2. Dump a database with --gzip, restore it under a different name, and verify an index survived.
Key takeaways
  • mongoimport and mongoexport exchange readable JSON and CSV, and mongodump and mongorestore copy BSON.
  • CSV imports are untyped, so check and convert the types afterward.
  • A backup is only real once you have restored it somewhere.
