Validation & JSON Schema

MongoDB is flexible by default, but you can attach a JSON Schema to a collection so it rejects documents that break your rules.

§1Why Validate

Without validation, any document goes into any collection. A typo such as emial or a string where a number belongs is stored happily and breaks code later. Schema validation lets you require the fields and types that matter and leave the rest open.

§2Writing a $jsonSchema Validator

Attach the rules when you create the collection, using the $jsonSchema operator.

db.createCollection("users", {
  validator: { $jsonSchema: {
    bsonType: "object",
    required: ["email", "age"],
    properties: {
      email: { bsonType: "string", pattern: "^.+@.+$" },
      age:   { bsonType: "int", minimum: 13, maximum: 120 },
      role:  { enum: ["user", "admin"] },
      tags:  { bsonType: "array", items: { bsonType: "string" } }
    }
  } },
  validationLevel: "strict",
  validationAction: "error"
})
db.users.insertOne({ email: "ada@example.com", age: 30 })   // ok
db.users.insertOne({ email: "ada@example.com" })            // fails: "Document failed validation"

Fields you do not list are still allowed unless you set additionalProperties: false.

§3Rolling Out to Existing Data

  • validationAction: "error" rejects bad writes, and "warn" allows them but logs a warning. Start with warn to see what would fail.
  • validationLevel: "strict" checks all inserts and updates. "moderate" checks updates only for documents that already pass, so old invalid documents can still be edited.
db.runCommand({ collMod: "users", validator: { $jsonSchema: { /* new rules */ } }, validationLevel: "moderate", validationAction: "warn" })
db.users.find({ $jsonSchema: { /* same rules */ } })                          // documents that pass
db.users.find({ $nor: [{ $jsonSchema: { /* same rules */ } }] })            // documents that fail
The key insight Validation guards the database boundary, so every writer, including scripts and other services, follows the same rules. It complements checks in application code and does not replace them.

§4Common Mistakes

MistakeWhat HappensFix
Requiring bsonType: "int" and sending a JavaScript numberThe driver may send a double and the write failsUse "number", or send Int32 values from your driver
Turning on strict error validation over messy dataExisting documents cannot be updatedStart with moderate and warn, clean up, then tighten
Over-constraining everythingEvery change needs a schema changeValidate the fields that must always be right
Practice
  1. Write a validator for a products collection requiring sku, a numeric price of at least 0, and an optional tags array of strings. Try three bad inserts.
  2. Add the validator to an existing collection with warn, then find the documents that would fail.
Key takeaways
  • $jsonSchema validators enforce required fields, types, and ranges while leaving other fields free.
  • validationAction and validationLevel let you roll validation out safely on existing data.
  • Validation protects every writer, not just the one application you control.
