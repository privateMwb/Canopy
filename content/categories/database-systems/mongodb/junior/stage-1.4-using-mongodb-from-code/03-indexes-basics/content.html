Indexes Basics

An index lets MongoDB find documents without scanning the whole collection, and a few simple index types cover most beginner needs.

§1Why Indexes Exist

Without an index, a query examines every document in the collection, which is called a collection scan and takes time proportional to the collection size. An index is a sorted structure over one or more fields that lets MongoDB jump to the matching documents.

db.users.find({ email: "ada@example.com" })                 // scans every user without an index
db.users.createIndex({ email: 1 })                          // 1 ascending, -1 descending
db.users.find({ email: "ada@example.com" }).explain("executionStats")    // now uses an IXSCAN

Every collection already has an index on _id.

§2Unique and TTL Indexes

A unique index rejects a second document with the same value, which is how you enforce things like unique emails.

db.users.createIndex({ email: 1 }, { unique: true })
db.users.insertOne({ email: "ada@example.com" })
db.users.insertOne({ email: "ada@example.com" })     // E11000 duplicate key error

A TTL index deletes documents automatically after a time, which suits sessions, tokens, and temporary data.

db.sessions.createIndex({ createdAt: 1 }, { expireAfterSeconds: 3600 })   // delete about an hour after createdAt

The TTL cleanup runs about once a minute in the background, so expiry is not instant.

§3The Cost of Indexes

Indexes are not free. Every insert, update of an indexed field, and delete also updates each index, and indexes take disk space and cache memory. Index the fields your frequent queries filter and sort on, and do not index everything. You can list and remove indexes:

db.users.getIndexes()
db.users.dropIndex("email_1")
The key insight Indexes trade write speed and memory for read speed. Create the ones your real queries need and no more.

§4Common Mistakes

MistakeWhat HappensFix
No index on a field used in frequent queriesCollection scans that get slower as data growsIndex the filtered fields, and check with explain
Indexing every fieldSlow writes and wasted memoryIndex only what queries use
Building a unique index on data that has duplicatesThe build failsFind and fix duplicates first
Practice
  1. Insert 100,000 documents, time a query by one field, then create an index and time it again, comparing explain output.
  2. Create a TTL index on a sessions collection and confirm that old documents disappear.
Key takeaways
  • An index avoids scanning the whole collection by keeping a sorted structure on one or more fields.
  • Unique indexes enforce uniqueness, and TTL indexes expire documents automatically.
  • Each index speeds reads but costs write time and memory.
