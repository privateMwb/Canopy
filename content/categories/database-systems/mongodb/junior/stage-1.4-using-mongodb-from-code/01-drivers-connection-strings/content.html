Drivers & Connection Strings

Application code talks to MongoDB through an official driver, configured by a connection string, using one shared client with a connection pool.

§1The Connection String

A connection string packs the host, credentials, and options into one URI. There are two forms: mongodb:// for explicit hosts, and mongodb+srv://, which looks up the hosts through DNS and is what Atlas gives you.

mongodb://user:pass@host1:27017,host2:27017/shop?replicaSet=rs0&retryWrites=true&w=majority
mongodb+srv://user:pass@cluster0.abc.mongodb.net/shop?retryWrites=true&w=majority

Options after the ? configure behavior such as replicaSet, w (write concern), maxPoolSize, and authSource.

§2Connecting from Code

Drivers exist for every major language. In Node.js:

import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGODB_URI);   // create ONE client for the whole app
await client.connect();

const products = client.db("shop").collection("products");
await products.insertOne({ sku: "NB-1", name: "Notebook" });
const one = await products.findOne({ sku: "NB-1" });

// on shutdown
await client.close();

§3Pooling

A MongoClient manages a connection pool: it opens a set of connections and reuses them. Creating a new client per request defeats the pool and floods the server with new connections, so create one client at startup and share it. In serverless environments, keep the client in a module-level variable so warm invocations reuse it.

§4Handling Secrets

The connection string contains a password, so it is a secret.

  • Read it from an environment variable or a secrets manager, never from source code or Git.
  • Use a separate user and string for each environment.
  • URL-encode special characters in the password.
The key insight One long-lived client per process, configured from the environment, is the pattern that works everywhere.

§5Common Mistakes

MistakeWhat HappensFix
Creating a client for every requestConnection storms and slow requestsCreate one client and reuse it
Hardcoding the connection stringCredentials leak through version controlUse environment variables or a secret store
Calling client.close() after each operationThe next call fails or reconnectsClose only on application shutdown
Practice
  1. Write a small script that connects using MONGODB_URI from the environment, inserts one document, reads it back, and closes the client.
  2. Show how you would structure a module so every file shares one client.
Key takeaways
  • A connection string carries hosts, credentials, and options, and mongodb+srv:// resolves hosts through DNS.
  • Create one MongoClient per process, because it holds a connection pool.
  • Keep the connection string out of source control.
