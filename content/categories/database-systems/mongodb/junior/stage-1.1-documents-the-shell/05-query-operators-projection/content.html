Query Operators & Projection

Operators such as $gt, $in, and $or express conditions inside a filter, and projection controls which fields come back.

§1Comparison and Logical Operators

Operators start with $ and wrap the value they apply to. Several conditions in one filter are combined with AND.

db.products.find({ price: { $gte: 2, $lt: 5 } })           // 2 <= price < 5
db.products.find({ sku: { $in: ["NB-1", "PN-3"] } })       // any of these
db.products.find({ stock: { $ne: 0 } })                    // not equal
db.products.find({ $or: [{ stock: 0 }, { price: { $gt: 10 } }] })
db.products.find({ $and: [{ price: { $gt: 1 } }, { price: { $lt: 3 } }] })
OperatorMeaning
$eq, $neequal, not equal
$gt, $gte, $lt, $ltecomparisons
$in, $ninvalue in or not in a list
$and, $or, $nor, $notlogic
$exists, $typefield presence and BSON type

Writing the same field twice in one object ({ price: {...}, price: {...} }) keeps only the last, so use one operator object or $and.

§2Existence, Type, and Regex

db.products.find({ discontinued: { $exists: false } })     // field is absent
db.products.find({ price: { $type: "string" } })           // find mistyped data
db.products.find({ name: { $regex: /^note/i } })           // prefix match, case-insensitive

A regex anchored at the start (^note) can use an index. An unanchored one must scan every value.

§3Projection

By default you get whole documents. A projection is the second argument of find and lists the fields to include (1) or exclude (0). You cannot mix both, except for _id.

db.products.find({}, { name: 1, price: 1 })          // _id is included by default
db.products.find({}, { name: 1, price: 1, _id: 0 })  // drop _id
db.products.find({}, { stock: 0 })                   // everything except stock
The key insight Projection reduces data sent over the network and, with the right index, can avoid reading documents at all. Return only what the caller needs.

§4Common Mistakes

MistakeWhat HappensFix
Mixing inclusion and exclusion in a projectionThe query errorsChoose one style (only _id: 0 may be combined with inclusion)
Querying { price: "5" } when it is stored as a numberNo match: types differMatch the stored type, and fix mistyped data
Unanchored regex on a big collectionFull scan of every valueAnchor with ^, or use a text or search index
Practice
  1. Find products priced between 1 and 3 with stock above 100, returning only name and price.
  2. Write one query using $or and another using $in that return the same documents.
Key takeaways
  • Operators like $gt, $in, and $or go inside the filter, and multiple fields mean AND.
  • $exists and $type help find missing or mistyped data.
  • Projection returns only the fields you list, so send less data.
