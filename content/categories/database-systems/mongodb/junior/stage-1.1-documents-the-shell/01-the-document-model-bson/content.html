The Document Model & BSON

MongoDB stores data as documents: ordered sets of named fields that can hold nested objects and arrays, serialized in a binary format called BSON.

§1From Rows to Documents

A relational row is flat: one value per column, and related data lives in other tables. A MongoDB document is a self-contained record made of field and value pairs, and a value can itself be another document or an array. One document can hold what would take several joined tables.

{
  _id: ObjectId("66a1f0c2e4b0a1b2c3d4e5f6"),
  name: "Ada Lovelace",
  email: "ada@example.com",
  address: { city: "London", country: "UK" },
  interests: ["mathematics", "engines"],
  joined: ISODate("2026-01-15T09:30:00Z")
}

Documents are grouped into collections, which play the role of tables. Documents in one collection do not have to share a shape, though in practice most collections hold documents that look alike.

§2JSON on the Surface, BSON Underneath

What you type and read in the shell looks like JSON, but MongoDB stores and transmits BSON (Binary JSON). BSON exists because JSON is too limited for a database: it has no date type, no distinction between integers and floats, and no binary data.

Types matter for queries: the string "42" and the number 42 are different values, and a query for one will not match the other.

§3Field Order, Names, and Limits

BSON preserves field order, and two documents with the same fields in a different order are not equal when compared as whole documents. Field names are strings, and there are a few conventions to follow: avoid starting a name with $, avoid . in names, and keep names short, because every document stores its field names again. A single document may be at most 16 MB.

db.users.find({ address: { city: "London", country: "UK" } })   // matches: same fields, same order
db.users.find({ address: { country: "UK", city: "London" } })   // no match: order differs
The key insight A document is the unit MongoDB reads, writes, and updates atomically. Deciding what belongs together in one document is the core skill of the whole course, and everything later builds on it.

§4Common Mistakes

MistakeWhat HappensFix
Storing numbers as strings ("42")Sorting is lexicographic and comparisons like $gt give surprising resultsStore numbers as numbers and dates as Date
Using a double for moneyRounding errors such as 0.1 + 0.2Use Decimal128 or integer cents
Using very long field namesEvery document repeats them, wasting storage and cacheKeep names short and clear
Practice
  1. Write a document for a book with a title, an array of authors, a nested publisher object, and a publication date. Which BSON type is each field?
  2. In the shell, insert { n: 1 } and { n: "1" }, then run db.test.find({ n: 1 }). Explain the result.
Key takeaways
  • A document is a set of ordered fields whose values can be nested documents or arrays.
  • MongoDB stores BSON, which adds real types such as dates, decimals, and ObjectId to what JSON offers.
  • Types and field order affect matching, so store each value in the type you intend to query by.
