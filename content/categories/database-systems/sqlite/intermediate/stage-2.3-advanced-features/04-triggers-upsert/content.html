Triggers & UPSERT

Triggers run SQL automatically when data changes, and UPSERT lets one statement insert a row or update the existing one.

§1Triggers

CREATE TABLE audit (id INTEGER PRIMARY KEY, tbl TEXT, row_id INTEGER, action TEXT, at TEXT DEFAULT (datetime('now')));

CREATE TRIGGER product_audit_update AFTER UPDATE ON product
BEGIN
  INSERT INTO audit (tbl, row_id, action) VALUES ('product', old.id, 'update');
END;

Triggers can fire BEFORE, AFTER, or INSTEAD OF (for views) an INSERT, UPDATE, or DELETE. Inside the body, old and new refer to the row. WHEN adds a condition, and UPDATE OF col limits it to certain columns.

CREATE TRIGGER stamp AFTER UPDATE ON note
WHEN new.body IS NOT old.body
BEGIN
  UPDATE note SET updated_at = datetime('now') WHERE id = new.id;
END;

Be careful with triggers that update the same table, which can recurse. SQLite disables recursive triggers by default.

§2Raising Errors

CREATE TRIGGER no_negative BEFORE UPDATE ON account
WHEN new.balance < 0
BEGIN SELECT RAISE(ABORT, 'balance cannot be negative'); END;

§3UPSERT

INSERT INTO counter (name, n) VALUES ('visits', 1)
ON CONFLICT (name) DO UPDATE SET n = n + 1;

INSERT INTO setting (key, value) VALUES ('theme', 'dark')
ON CONFLICT (key) DO UPDATE SET value = excluded.value WHERE value IS NOT excluded.value;

excluded holds the row you tried to insert. The ON CONFLICT column must have a unique constraint or index.

§4Where Triggers Help and Hurt

They suit audit trails, keeping derived data in sync, and rules the database must enforce for every client. They hide logic, so document them and test them, because they run even for changes made from a shell.

The key insight A trigger enforces a rule for every writer. Use it for invariants, and keep business workflows in application code.

§5Common Mistakes

MistakeWhat HappensFix
Heavy logic inside triggersHidden, slow, and hard to debugKeep triggers short and focused
Updating the same table in an AFTER UPDATE trigger without a guardRepeated updates, or recursion if enabledAdd a WHEN condition
ON CONFLICT on a column with no unique indexAn error at parse or run timeDefine a unique constraint first
Practice
  1. Build an audit trail with triggers for insert, update, and delete on one table, and test it.
  2. Write an upsert-based counter and run it 1,000 times from concurrent connections.
Key takeaways
  • Triggers run BEFORE, AFTER, or INSTEAD OF data changes and see old and new.
  • RAISE can block bad changes at the database level.
  • ON CONFLICT DO UPDATE implements insert-or-update atomically.
