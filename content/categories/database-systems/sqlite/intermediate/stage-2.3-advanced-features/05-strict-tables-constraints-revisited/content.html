STRICT Tables & Constraints Revisited

STRICT tables and well-chosen constraints turn a permissive engine into one that protects your data as firmly as stricter databases do.

§1What STRICT Changes

CREATE TABLE person (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  age INTEGER,
  photo BLOB
) STRICT;

INSERT INTO person (name, age) VALUES ('Ada', 'forty');
-- Runtime error: cannot store TEXT value in INTEGER column person.age

In a STRICT table, each column must have one of INT, INTEGER, REAL, TEXT, BLOB, or ANY. Values that cannot convert to the column type are rejected. A value such as '42' is still converted to integer 42 for an INTEGER column, since affinity applies.

§2Adding Rules STRICT Does Not Cover

CREATE TABLE booking (
  id INTEGER PRIMARY KEY,
  starts_at TEXT NOT NULL CHECK (starts_at GLOB '????-??-??T??:??:??Z'),
  ends_at   TEXT NOT NULL,
  status    TEXT NOT NULL CHECK (status IN ('pending', 'confirmed', 'cancelled')),
  is_paid   INTEGER NOT NULL DEFAULT 0 CHECK (is_paid IN (0, 1)),
  CHECK (ends_at > starts_at)
) STRICT;

Booleans, enumerations, formats, and cross-column rules need CHECK constraints. With foreign keys enabled and NOT NULL where appropriate, the schema describes valid data.

§3Migrating an Existing Table

You cannot add STRICT with ALTER TABLE. Create a new strict table, copy the data (fixing bad rows), and swap.

BEGIN;
CREATE TABLE person_new (id INTEGER PRIMARY KEY, name TEXT NOT NULL, age INTEGER) STRICT;
INSERT INTO person_new SELECT id, name, CAST(age AS INTEGER) FROM person;
DROP TABLE person;
ALTER TABLE person_new RENAME TO person;
COMMIT;

§4Compatibility

STRICT needs SQLite 3.37 or later, and older tools may not open such a database. Check every program and driver that touches the file.

The key insight Constraints are free documentation that the engine enforces. Put the rules in the schema so every client follows them.

§5Common Mistakes

MistakeWhat HappensFix
Using ANY for every columnYou lose the benefit of strictnessChoose a real type per column
Skipping CHECK for booleans and enumsInvalid values appearConstrain them explicitly
Opening a STRICT database with an old SQLiteIt fails to read the schemaCheck minimum versions everywhere
Practice
  1. Convert a loosely typed table to STRICT and list which rows had to be fixed.
  2. Add CHECK constraints for a status enum and a date range, and write tests that try to violate each.
Key takeaways
  • STRICT makes column types enforced rules.
  • Use CHECK for booleans, enums, formats, and cross-column rules.
  • Convert existing tables by copying into a new strict table.
