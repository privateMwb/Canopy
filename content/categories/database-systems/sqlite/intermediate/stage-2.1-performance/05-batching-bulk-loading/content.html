Batching & Bulk Loading

Loading a million rows takes seconds instead of minutes once you batch work into transactions and reuse prepared statements.

§1The Recipe

con = sqlite3.connect("big.db")
con.execute("PRAGMA journal_mode = WAL")
con.execute("PRAGMA synchronous = NORMAL")
rows = ((i, f"user{i}", i % 100) for i in range(1_000_000))
with con:
    con.executemany("INSERT INTO account (id, name, age) VALUES (?, ?, ?)", rows)

One transaction, one prepared statement, many executions. Avoid committing per row.

§2Further Speed-Ups

  • Create indexes after loading. Building an index once from sorted data is faster than updating it a million times.
  • Insert in primary-key order when you can, which keeps B-tree inserts efficient.
  • Use multi-row inserts INSERT ... VALUES (...), (...), ... within parameter limits.
  • Temporarily relax settings for a disposable import, such as synchronous = OFF on a fresh file you can rebuild.
DROP INDEX IF EXISTS idx_account_name;
-- bulk load here
CREATE INDEX idx_account_name ON account (name);
ANALYZE;

§3Parameter Limits

SQLITE_MAX_VARIABLE_NUMBER is 32,766 by default in recent versions, and the host program may set it lower, so do not build giant IN (...) lists or enormous multi-row inserts.

§4Verify

SELECT count(*) FROM account;
PRAGMA integrity_check;
The key insight Most of the speed comes from doing less work per row: one transaction, one prepared statement, and indexes built last.

§5Common Mistakes

MistakeWhat HappensFix
Committing after every rowEach commit forces a disk syncUse one transaction per batch
Loading into a table with many indexesEvery insert updates every indexCreate indexes after the load
Building a huge IN list from application dataYou hit the parameter limitUse a temporary table and join
Practice
  1. Load 1,000,000 rows three ways (per-row commit, one transaction, one transaction with indexes created after) and record each time.
  2. Replace a large IN (...) query with a temp table join.
Key takeaways
  • Batch inserts into one transaction with a prepared statement.
  • Create indexes after loading, and insert in key order if possible.
  • Mind parameter limits, and verify the result after a bulk load.
