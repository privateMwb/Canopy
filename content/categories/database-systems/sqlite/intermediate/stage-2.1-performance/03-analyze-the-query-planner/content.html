ANALYZE & the Query Planner

The query planner picks plans from statistics, and ANALYZE gives it better numbers to choose with.

§1What ANALYZE Does

ANALYZE;                         -- gather statistics for all tables
PRAGMA optimize;                 -- analyze only where it seems useful
SELECT * FROM sqlite_stat1;      -- the results

sqlite_stat1 records how many rows a table has and how selective each index is (the average number of rows per distinct key prefix). Without statistics the planner uses general guesses.

§2Why It Matters

If a column has only two distinct values, an index on it is nearly useless, but the planner cannot know that without statistics. After ANALYZE it may choose a different index or a scan, and the difference can be dramatic for joins.

§3Running It Regularly

SQLite recommends running PRAGMA optimize just before closing a long-lived connection, and periodically on long-running processes (for example every few hours). It is cheap because it only analyzes tables that changed substantially.

PRAGMA optimize;                 -- on close
PRAGMA optimize=0x10002;         -- on open, inspect everything

§4Helping the Planner Directly

SELECT * FROM a JOIN b ON a.id = b.a_id WHERE likelihood(a.flag = 1, 0.01);
SELECT * FROM item INDEXED BY idx_items_cat_price WHERE category = 'pen';

likelihood() tells the planner how often a condition is true, and INDEXED BY forces an index. Both are last resorts, because they hard-code assumptions that may become wrong as data changes.

The key insight Good statistics fix most "wrong plan" problems without any hints. Hints are for when statistics are not enough.

§5Common Mistakes

MistakeWhat HappensFix
Never running ANALYZE on a large databaseThe planner guesses and picks poor join ordersRun PRAGMA optimize regularly
Forcing indexes with INDEXED BY firstA hint breaks when data changesFix statistics and indexes before using hints
Analyzing right after loading only a few rowsStatistics describe an unrepresentative tableAnalyze after the data has realistic volume
Practice
  1. Compare the query plan of a join before and after ANALYZE on a table with skewed values.
  2. Add PRAGMA optimize to your application's shutdown path.
Key takeaways
  • ANALYZE stores table and index statistics in sqlite_stat1.
  • PRAGMA optimize keeps statistics fresh at low cost.
  • Hints such as INDEXED BY are a last resort.
