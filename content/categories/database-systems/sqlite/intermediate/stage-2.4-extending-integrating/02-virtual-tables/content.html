Virtual Tables

A virtual table looks like a table but gets its rows from code, which is how full-text search, R-Tree, and many extensions work.

§1What They Are

You query a virtual table with ordinary SQL, but a module supplies the data and handles MATCH, scans, and updates in its own way.

CREATE VIRTUAL TABLE doc_fts USING fts5(title, body);          -- full-text search
CREATE VIRTUAL TABLE place_idx USING rtree(id, min_x, max_x, min_y, max_y);   -- spatial index
SELECT * FROM pragma_table_info('product');                     -- table-valued function
SELECT * FROM generate_series(1, 5);                            -- with the series extension

§2R-Tree

INSERT INTO place_idx VALUES (1, 13.3, 13.5, 52.4, 52.6);
SELECT id FROM place_idx WHERE min_x <= 13.4 AND max_x >= 13.4 AND min_y <= 52.5 AND max_y >= 52.5;

It indexes bounding boxes, so range queries over locations or intervals are fast.

§3Other Examples

  • json_each and json_tree read JSON as rows.
  • The dbstat table reports the space used by each table and index.
  • The CSV extension queries a CSV file as a table.
  • Virtual tables can expose files, APIs, logs, or another database.

§4Limits

A virtual table has no built-in indexes you can create with CREATE INDEX, and the module decides what can be updated. Constraints, triggers, and transactions behave according to the module.

§5Writing Your Own

You can implement a module in C, and some languages offer wrappers, to expose application data as a table so SQL can join it with real tables.

The key insight A virtual table is an interface. If you can read your data as rows, SQL can query it.

§6Common Mistakes

MistakeWhat HappensFix
Expecting CREATE INDEX on a virtual tableNot supported by most modulesUse the module's own indexing
Assuming every virtual table supports writesMany are read-onlyCheck the module's documentation
Joining a virtual table to a huge table without checking the planA slow nested loopInspect EXPLAIN QUERY PLAN
Practice
  1. Create an R-Tree for 10,000 points and compare a box query with a plain table scan.
  2. Query pragma_table_info and dbstat to list columns and the largest tables.
Key takeaways
  • Virtual tables expose data from a module through ordinary SQL.
  • FTS5, R-Tree, json_each, and dbstat are built on them.
  • Their behavior depends on the module, so read its rules.
