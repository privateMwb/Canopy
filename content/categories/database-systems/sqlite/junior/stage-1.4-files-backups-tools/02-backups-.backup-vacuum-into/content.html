Backups: .backup & VACUUM INTO

Copying a live database file can produce a broken backup, so use SQLite's own commands, which take a consistent snapshot.

§1The .backup Command

.backup main backup.db                -- from the sqlite3 shell
sqlite3 app.db ".backup 'backup-$(date +%F).db'"

It uses the online backup API, copies pages while the database is in use, and restarts if another writer changes the source. The result is a consistent database file.

§2VACUUM INTO

VACUUM INTO 'compact-backup.db';

This writes a compacted copy to a new file. It produces a clean, defragmented backup in one statement, but the target must not already exist.

§3From Code

src = sqlite3.connect("app.db")
dst = sqlite3.connect("backup.db")
with dst:
    src.backup(dst)
dst.close()

§4Verifying a Backup

A backup is only useful if it opens and is intact.

PRAGMA integrity_check;               -- 'ok' means the structure is sound

Also compare row counts of key tables against the source.

§5Where to Put Backups

Store them off the machine, keep several generations, and name them with dates. Test restoring by opening one and running your application's checks against it.

The key insight A file copy is a backup only when nothing is writing. For a live database, use .backup, VACUUM INTO, or the backup API.

§6Common Mistakes

MistakeWhat HappensFix
cp app.db backup.db while the app is runningThe copy can be torn or missing WAL dataUse .backup or VACUUM INTO
Never checking the backupYou discover corruption when you need itRun PRAGMA integrity_check on each backup
Keeping backups next to the originalOne disk failure loses bothStore a copy elsewhere
Practice
  1. Take a backup of an active WAL-mode database with .backup, and verify it with PRAGMA integrity_check.
  2. Compare the size of a VACUUM INTO copy with the original after deleting many rows.
Key takeaways
  • Use .backup, VACUUM INTO, or the backup API for live databases.
  • VACUUM INTO writes a compacted copy to a new file.
  • Always verify backups with integrity_check and store them elsewhere.
