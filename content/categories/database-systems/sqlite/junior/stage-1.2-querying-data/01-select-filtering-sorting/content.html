SELECT, Filtering & Sorting

SELECT reads rows, WHERE filters them, ORDER BY sorts them, and LIMIT keeps only as many as you need.

§1The Basic Query

SELECT name, price_cents
FROM product
WHERE price_cents BETWEEN 100 AND 1000
  AND name LIKE 'P%'
ORDER BY price_cents DESC, name
LIMIT 10 OFFSET 20;

LIKE is case-insensitive for ASCII letters, with % for any run of characters and _ for one. GLOB is case-sensitive and uses * and ?.

§2Filtering Tools

WHERE category IN ('pen', 'ink')
WHERE discontinued IS NULL           -- never "= NULL"
WHERE price_cents IS NOT NULL
WHERE name IS 'Pen'                  -- IS works like = but treats NULL as a value
SELECT DISTINCT category FROM product;

NULL means unknown, so col = NULL is never true. Use IS NULL and IS NOT NULL.

§3Sorting and Paging

Without ORDER BY, row order is not guaranteed. LIMIT with a large OFFSET gets slower, because SQLite still walks past all the skipped rows. For paging, filter on the last value you saw.

SELECT id, name FROM product
WHERE id > :last_seen_id
ORDER BY id
LIMIT 20;

§4Expressions and Aliases

SELECT name, price_cents / 100.0 AS price, upper(name) AS shout
FROM product;
The key insight Always include ORDER BY when order matters, and prefer keyset paging (WHERE id > ?) over big offsets.

§5Common Mistakes

MistakeWhat HappensFix
Writing WHERE col = NULLReturns no rowsUse IS NULL
Relying on the "natural" order of rowsOrder can change as data or indexes changeAdd ORDER BY
Paging with a growing OFFSETLater pages are slowerUse keyset paging on an indexed column
Practice
  1. Write a query for the five most expensive products whose names contain "pen", sorted by price then name.
  2. Convert an OFFSET pagination query into keyset pagination.
Key takeaways
  • WHERE filters, ORDER BY sorts, and LIMIT caps the rows returned.
  • Use IS NULL, and remember LIKE is case-insensitive for ASCII.
  • Keyset paging scales better than large offsets.
