Parameterized Queries

Binding values as parameters, instead of pasting them into SQL text, is what prevents SQL injection and also speeds up repeated queries.

§1The Attack

name = request.args["name"]
con.execute(f"SELECT * FROM account WHERE name = '{name}'")      # never do this
# input:  x' OR '1'='1     →  returns every account

Building SQL by string concatenation lets input change the meaning of the statement.

§2Parameters

con.execute("SELECT * FROM account WHERE name = ?", (name,))              # positional
con.execute("SELECT * FROM account WHERE name = :n AND age > :a", {"n": name, "a": 18})   # named

The SQL text is parsed once, and the values are sent separately, so a value can never be interpreted as SQL.

§3What You Cannot Parameterize

Parameters stand in for values, not identifiers. You cannot bind a table name, column name, or ORDER BY direction.

allowed = {"name", "created_at"}
col = sort if sort in allowed else "name"             # allow-list, then format
con.execute(f"SELECT * FROM account ORDER BY {col}")

Use an allow-list of known names, never raw input.

§4Reuse

A prepared statement can be executed many times with different values, which saves parse time.

con.executemany("INSERT INTO product (name, price_cents) VALUES (?, ?)", rows)
The key insight Parameters are not just escaping. They keep data and code in separate channels, so no input can become SQL.

§5Common Mistakes

MistakeWhat HappensFix
Using f-strings or concatenation for valuesSQL injectionBind with ? or named parameters
Trying to bind a column nameIt becomes a string literal and does not workAllow-list identifiers and format them in
Escaping quotes by handEasy to miss casesAlways bind
Practice
  1. Demonstrate an injection on a naive query, then fix it with a bound parameter.
  2. Build a sortable query that accepts a column name safely.
Key takeaways
  • Bind values with ? or named parameters and never concatenate them into SQL.
  • You cannot bind identifiers, so use an allow-list.
  • Prepared statements are also faster for repeated queries.
