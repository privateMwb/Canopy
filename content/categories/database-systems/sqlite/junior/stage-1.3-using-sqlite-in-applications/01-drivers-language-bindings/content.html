Drivers & Language Bindings

Every major language can open a SQLite file, and the calls are nearly the same: connect, execute, fetch, and close.

§1Python

Python ships with the sqlite3 module in the standard library.

import sqlite3
con = sqlite3.connect("app.db")
con.row_factory = sqlite3.Row            # access columns by name
cur = con.execute("SELECT id, name FROM product WHERE price_cents > ?", (500,))
for row in cur.fetchall():
    print(row["id"], row["name"])
con.close()

§2JavaScript and Others

Node.js now includes a built-in node:sqlite module, and better-sqlite3 is a popular synchronous driver. Browsers can run SQLite compiled to WebAssembly. Go, Rust, Java, C#, Swift, and PHP all have bindings, and most mobile platforms bundle it.

import Database from "better-sqlite3";
const db = new Database("app.db");
const rows = db.prepare("SELECT id, name FROM product WHERE price_cents > ?").all(500);

§3Connections and Threads

A connection is cheap to open, but it holds a file lock while a transaction is active. Keep one connection per thread unless your driver documents otherwise, and close connections you no longer use. Python's default also controls whether a transaction is opened implicitly, so read how your driver handles commit.

with con:                                # commits on success, rolls back on error
    con.execute("INSERT INTO product (name, price_cents) VALUES (?, ?)", ("Pen", 120))

§4Choosing a Driver

Prefer the maintained, widely used driver for your language, check that it bundles a recent SQLite version, and check whether it is synchronous or asynchronous so it does not block your event loop.

The key insight Drivers wrap the same C library, so SQL behaves the same everywhere, but transaction defaults differ between drivers. Read yours.

§5Common Mistakes

MistakeWhat HappensFix
Sharing one connection between threads without checking the driver rulesCrashes or data racesUse a connection per thread or the documented thread mode
Not closing connectionsFile handles and locks leakUse context managers or finally blocks
Assuming the bundled SQLite supports new featuresOld versions lack RETURNING, STRICT, and othersPrint sqlite_version() and check
Practice
  1. Open the same database from two languages and read the same rows.
  2. Print SELECT sqlite_version(); from your driver and compare it with the version needed for STRICT tables.
Key takeaways
  • Drivers wrap the same engine with similar APIs across languages.
  • Use one connection per thread, and close connections reliably.
  • Check the bundled SQLite version before using newer features.
