Observability

An embedded database has no dashboard, so you add your own timing and counters to see slow queries and lock waits.

§1What to Measure

  • Query latency by statement or call site, with percentiles.
  • Lock waits and SQLITE_BUSY counts, and retries.
  • Transaction duration, especially writes.
  • WAL size and checkpoint behavior.
  • Database and WAL file sizes, free pages, and growth.
  • Cache behavior and rows scanned.

§2Instrumenting From Code

Wrap your database calls with timers, and log statements over a threshold with their parameters redacted.

def timed(con, sql, args=()):
    t = time.perf_counter()
    try:
        return con.execute(sql, args)
    finally:
        ms = (time.perf_counter() - t) * 1000
        metrics.timing("db.query_ms", ms)
        if ms > 50: log.warning("slow query %.1f ms: %s", ms, sql)

Drivers expose a trace or progress hook (set_trace_callback, sqlite3_trace_v2) for deeper logging in development.

§3Built-In Sources

PRAGMA wal_checkpoint(PASSIVE);          -- busy, log frames, checkpointed frames
PRAGMA page_count; PRAGMA freelist_count;
SELECT * FROM dbstat;                    -- space by table and index
.stats on                                -- shell: page reads and writes per query

sqlite3_stmt_status reports counts such as full-scan steps and sorts for a statement.

§4Finding the Cause of Slowness

Take the slow statement, read its EXPLAIN QUERY PLAN, check for scans and temp sorts, and verify statistics and indexes. For lock waits, log transaction durations to find the long writer holding the lock.

§5Alerts

Alert on rising p99 latency, any sustained SQLITE_BUSY, a growing WAL, free disk space, failed backups, and failed integrity checks.

The key insight Without server metrics, your application is the instrument. Time every call, and watch transaction length and file sizes.

§6Common Mistakes

MistakeWhat HappensFix
Logging slow queries with full parametersSensitive data lands in logsRedact or hash parameters
Ignoring the WAL sizeUnbounded growth fills the diskAlert on its size
Only looking at averagesRare long locks hideTrack p99 and maximum durations
Practice
  1. Add timing and a slow-query log to one data-access layer and review the top five slowest statements.
  2. Graph database size, WAL size, and free pages over a week of simulated use.
Key takeaways
  • Instrument queries, transactions, lock waits, and file sizes yourself.
  • Use dbstat, .stats, and statement status counters for detail.
  • Alert on latency percentiles, SQLITE_BUSY, WAL growth, disk space, and backup failures.
