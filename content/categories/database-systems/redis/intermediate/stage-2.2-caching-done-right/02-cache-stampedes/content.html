Cache Stampedes

When a hot key expires, many requests miss at once and hit the database together, which can take it down.

§1The Problem

A homepage query takes 800 ms and is cached for five minutes. At expiry, 2,000 concurrent requests all see a miss and all run the query. The database is overwhelmed, queries slow down, and more requests pile up.

§2Fix 1: A Lock Around the Rebuild

Only one request rebuilds the value; the rest wait briefly or serve stale data.

SET lock:rebuild:home 1 NX EX 10      # returns OK for exactly one caller
if (await redis.set(lockKey, "1", { NX: true, EX: 10 })) {
  const fresh = await loadFromDb();
  await redis.set(key, JSON.stringify(fresh), { EX: 300 });
  await redis.del(lockKey);
  return fresh;
}
await sleep(50);                       // others wait and retry the cache

Give the lock a TTL so a crashed rebuilder does not block everyone forever.

§3Fix 2: Refresh Before Expiry

Store a soft expiry inside the value. When a reader sees the soft expiry has passed, one reader refreshes in the background while everyone keeps getting the old value.

const { data, refreshAt } = JSON.parse(raw);
if (Date.now() > refreshAt && await redis.set(lockKey, "1", { NX: true, EX: 10 })) refreshInBackground();
return data;

§4Fix 3: Jitter and Warming

Add randomness to TTLs (next lesson), and pre-warm known hot keys before traffic arrives.

The key insight A stampede is a coordination problem. Anything that makes exactly one caller do the expensive work solves it.

§5Common Mistakes

MistakeWhat HappensFix
No lock around an expensive rebuildThousands of identical queries runUse SET NX EX as a rebuild lock
A lock with no expiryA crash blocks all rebuildsAlways set a lock TTL
Serving nothing while rebuildingLatency spikes during the refreshServe slightly stale data while one caller refreshes
Practice
  1. Write a load test with 500 concurrent readers of an expired key and count database queries with and without a lock.
  2. Add soft expiry to a cached value and verify only one refresh happens.
Key takeaways
  • Expiry of a hot key can trigger a stampede on the database.
  • Use a rebuild lock, or refresh early while serving the old value.
  • Always give locks a TTL.
