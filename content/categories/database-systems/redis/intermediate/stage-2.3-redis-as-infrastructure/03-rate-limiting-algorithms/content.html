Rate Limiting Algorithms

Fixed windows are simple but bursty, sliding windows are accurate but heavier, and token buckets allow controlled bursts.

§1Fixed Window

INCR rate:u1:202505141042
EXPIRE rate:u1:202505141042 60 NX

Cheap, but allows twice the limit around a boundary.

§2Sliding Window Log

Record each request time in a sorted set and count those in the last window.

ZREMRANGEBYSCORE rate:u1 0 (now-60000)
ZADD rate:u1 now "req-id"
ZCARD rate:u1                    # requests in the last 60 s
EXPIRE rate:u1 60

Accurate, but memory grows with the limit, since every request is stored. Run these in a script so they are atomic.

§3Token Bucket

A bucket refills at a steady rate and each request spends a token, so short bursts are allowed up to the bucket size.

-- KEYS[1]=bucket  ARGV: capacity, refill_per_sec, now_ms
local data = redis.call('HMGET', KEYS[1], 'tokens', 'ts')
local tokens = tonumber(data[1]) or tonumber(ARGV[1])
local ts = tonumber(data[2]) or tonumber(ARGV[3])
tokens = math.min(tonumber(ARGV[1]), tokens + (tonumber(ARGV[3]) - ts) / 1000 * tonumber(ARGV[2]))
local ok = tokens >= 1
if ok then tokens = tokens - 1 end
redis.call('HSET', KEYS[1], 'tokens', tokens, 'ts', ARGV[3])
redis.call('PEXPIRE', KEYS[1], 120000)
return ok and 1 or 0

Always use the server's or one shared clock source consistently, and return how long to wait when rejecting, such as a Retry-After value.

The key insight Pick the algorithm by the behavior you want: fixed for cheap and rough, sliding for exact, token bucket for smooth with bursts.

§4Common Mistakes

MistakeWhat HappensFix
Doing read then write in client codeConcurrent requests slip past the limitUse a script or an atomic command
Keys that never expireMemory leaks for every user ever seenSet a TTL on every limiter key
Rejecting with no hint to the clientClients retry immediately and make it worseReturn a retry delay
Practice
  1. Implement all three limiters and fire a burst of requests at each to compare the results.
  2. Add a Retry-After value to rejections.
Key takeaways
  • Fixed windows are cheap and bursty, sliding windows are exact and heavier.
  • Token buckets allow smooth rates with limited bursts.
  • Make the check atomic and always expire limiter keys.
