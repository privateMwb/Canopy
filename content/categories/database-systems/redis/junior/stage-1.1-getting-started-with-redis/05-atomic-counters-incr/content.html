Atomic Counters & INCR

Every Redis command is atomic, so INCR lets many clients count safely without locks or transactions.

§1Why Single Commands Are Atomic

Redis executes commands one at a time on its main thread. A command either runs completely or not at all, and no other client's command can run in the middle. That removes the classic read-modify-write race.

SET visits 0
INCR visits              # 1
INCRBY visits 10         # 11
DECR visits              # 10
INCRBYFLOAT price 0.5    # works on decimal numbers

If the key does not exist, INCR treats it as 0 and creates it. If the value is not an integer, the command returns an error.

§2The Race You Avoid

Reading a number, adding one in your application, and writing it back is not safe: two clients can read the same value and both write the same result, losing one update. INCR does the whole thing server-side.

# unsafe in application code:
#   n = GET visits ; SET visits n+1
# safe:
INCR visits

§3Counters With Expiry

A common pattern is a counter that resets on its own.

INCR rate:ip:203.0.113.5
EXPIRE rate:ip:203.0.113.5 60 NX     # set a TTL only if none exists (Redis 7+)

The NX option on EXPIRE sets the window only on the first request, so later requests do not extend it.

Gotcha A counter is only atomic per command. If you need to increment two keys together, or check a value and then change it, you need a transaction or a Lua script, covered in Level 2.

§4Common Mistakes

MistakeWhat HappensFix
Reading with GET, adding in code, writing with SETConcurrent clients overwrite each other's updatesUse INCR or INCRBY
INCR then EXPIRE where the second call can failThe key may never expireUse EXPIRE ... NX with the first increment, or a small script
Using INCR on a key holding textThe server returns an errorKeep counters in their own keys and prefixes
Practice
  1. Simulate 1,000 concurrent increments with a script and confirm the final value is exactly 1,000.
  2. Build a per-IP counter that allows 5 requests per minute using only INCR and EXPIRE.
Key takeaways
  • Single commands are atomic, so INCR replaces many locking schemes.
  • Never read, modify, and write a shared number from client code.
  • Pair counters with a TTL so windows reset themselves.
