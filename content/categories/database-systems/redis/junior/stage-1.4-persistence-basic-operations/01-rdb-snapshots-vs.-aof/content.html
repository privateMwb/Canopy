RDB Snapshots vs. AOF

Redis can write data to disk in two ways, snapshots and an append-only log, and each one loses a different amount on a crash.

§1RDB Snapshots

An RDB file is a compact point-in-time snapshot. Redis forks a child process and writes the whole dataset to dump.rdb at intervals.

save 3600 1        # snapshot if at least 1 change in an hour
save 300 100       # ... or 100 changes in 5 minutes

Snapshots are small and fast to restore, but you lose everything written since the last one if the server crashes.

§2The Append-Only File

With AOF, Redis logs every write command and replays the log on startup.

appendonly yes
appendfsync everysec    # always | everysec | no

everysec flushes once a second, so a crash loses at most about a second of writes. always flushes after every command and is much slower. no leaves flushing to the operating system.

§3Choosing

  • No persistence: pure cache, losing everything on restart is acceptable.
  • RDB only: fast restarts and backups, with minutes of possible loss.
  • AOF (everysec): the usual choice when data matters.
  • Both: AOF is used for recovery when both are enabled, and RDB remains handy for backups.
The key insight "Redis is persistent" is not a yes or no. It depends on the setting. Always know your maximum possible loss in seconds.

§4Common Mistakes

MistakeWhat HappensFix
Assuming data survives a restart with default settingsRecent writes, or all of them, may be goneCheck save, appendonly, and test a restart
appendfsync always on a busy serverThroughput drops sharplyUse everysec unless you can afford the cost
Never testing recoveryYou find out the backup is bad during an incidentRestart a test instance from your files regularly
Practice
  1. Write ten keys, kill the server abruptly with kill -9, restart, and note what survived under RDB-only and then AOF everysec.
  2. Compute the worst-case data loss for each of your persistence settings.
Key takeaways
  • RDB is a snapshot, AOF is a log of writes, and they can be combined.
  • appendfsync everysec limits loss to about a second.
  • Know and test your worst-case loss.
