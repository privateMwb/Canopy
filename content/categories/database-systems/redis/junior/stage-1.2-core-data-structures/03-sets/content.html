Sets

A set holds unique members with no order, and Redis can combine sets across keys with union, intersection, and difference.

§1Uniqueness and Membership

SADD tags:post:7 "redis" "cache" "redis"   # adds 2, the duplicate is ignored
SISMEMBER tags:post:7 "cache"              # 1
SMEMBERS tags:post:7
SCARD tags:post:7                          # size
SREM tags:post:7 "cache"

Adding, removing, and testing membership are constant time, no matter how large the set is.

§2Set Algebra Across Keys

SADD likes:alice 1 2 3 4
SADD likes:bob   3 4 5
SINTER likes:alice likes:bob     # {3, 4} common likes
SUNION likes:alice likes:bob     # {1, 2, 3, 4, 5}
SDIFF  likes:alice likes:bob     # {1, 2} only Alice
SINTERSTORE common likes:alice likes:bob

This is how you build "friends in common," tag filters ("posts tagged both redis and cache"), and "who has not seen this yet."

§3Random Picks

SRANDMEMBER returns random members without removing them, and SPOP removes and returns one. Both are useful for giveaways, sampling, and spreading work.

Gotcha SMEMBERS, SINTER, and SUNION return full results. On very large sets they block the server; use SSCAN to iterate, or SINTERCARD when you only need the count.

§4Common Mistakes

MistakeWhat HappensFix
Calling SMEMBERS on a huge setA long blocking call and a giant replyUse SSCAN or SCARD
Using a set when order mattersMembers come back in no guaranteed orderUse a sorted set or list
Intersecting very large sets in a hot pathThe command takes time proportional to the smallest setKeep the smallest set first, or precompute with SINTERSTORE
Practice
  1. Model post tags with sets, then find all posts that have both of two chosen tags.
  2. Use SINTERCARD to count common followers without returning them.
Key takeaways
  • Sets guarantee uniqueness and give constant-time membership tests.
  • SINTER, SUNION, and SDIFF combine sets across keys.
  • Iterate large sets with SSCAN rather than SMEMBERS.
