Leaderboards & Counting at Scale

Sorted sets turn rankings into a few commands, and probabilistic structures let you count huge sets with a tiny amount of memory.

§1Leaderboards

ZINCRBY leaderboard:2025-05 25 "player:77"
ZRANGE leaderboard:2025-05 0 9 REV WITHSCORES      # top 10
ZREVRANK leaderboard:2025-05 "player:77"           # my position
ZRANGE leaderboard:2025-05 4 8 REV WITHSCORES      # a window: ranks 5 to 9

To show a player their neighbors, read a window around their rank: get their rank, then ZRANGE from rank-2 to rank+2. Use one key per period, such as per month, and let old ones expire.

§2Counting Unique Items

A set of every visitor ID is exact but costs memory per member. HyperLogLog estimates unique counts in about 12 KB, whatever the size, with roughly 0.8% error.

PFADD visitors:2025-05-14 "u1" "u2" "u3"
PFCOUNT visitors:2025-05-14         # ≈ 3
PFMERGE visitors:week visitors:2025-05-13 visitors:2025-05-14

§3Choosing Exact or Approximate

Use a set when you need exact membership or need to list members. Use HyperLogLog when you only need "about how many," such as unique visitors per day. You cannot read members back out of a HyperLogLog.

The key insight Redis lets you trade a little accuracy for a lot of memory. For analytics dashboards, a 1% error is rarely worth gigabytes.

§4Common Mistakes

MistakeWhat HappensFix
One giant leaderboard that never resetsMemory and rank queries grow without boundUse time-boxed keys with TTLs
Using HyperLogLog and expecting exact countsEstimates are close but not exactUse a set when exactness matters
Trying to list who visited from a HyperLogLogIt stores no membersKeep a set if you need the members
Practice
  1. Build a monthly leaderboard and show the top 5 plus a given player's rank.
  2. Count 100,000 unique IDs in a set and in a HyperLogLog, and compare MEMORY USAGE.
Key takeaways
  • Sorted sets give you ranks and top-N with a handful of commands.
  • HyperLogLog counts unique items in constant memory with a small error.
  • Choose exact or approximate based on what the number is used for.
