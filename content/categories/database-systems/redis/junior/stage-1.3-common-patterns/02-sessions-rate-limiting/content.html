Sessions & Rate Limiting

Redis fits session storage and request limiting well because both need fast reads, atomic updates, and automatic expiry.

§1Sessions

A session ID goes in a cookie, and the session data goes in Redis, shared by every web server.

HSET sess:9f2c user_id 1001 role "admin" csrf "ab12"
EXPIRE sess:9f2c 1800            # 30-minute idle timeout
# on each request, extend the idle timeout:
EXPIRE sess:9f2c 1800

Use an unguessable random ID (at least 128 bits from a secure generator). Deleting the key logs the user out everywhere at once.

§2A Fixed-Window Rate Limiter

Count requests per user per time window, and reject once the count passes the limit.

INCR rate:user:1001:2025-05-14T10:42
EXPIRE rate:user:1001:2025-05-14T10:42 60 NX
# if the INCR result is greater than 100, reject the request

The window is a minute because the key name includes the minute and the key expires after 60 seconds.

§3A Known Weakness

Fixed windows allow bursts at the boundary: 100 requests at 10:42:59 and another 100 at 10:43:00 is 200 requests in two seconds. Level 2 covers sliding windows and token buckets.

Gotcha Rate limiting by IP alone breaks for users behind shared proxies and is easy to dodge. Combine IP, account, and API key where you can.

§4Common Mistakes

MistakeWhat HappensFix
Using a short sequential session IDAttackers guess other users' sessionsGenerate long random IDs
Never extending or setting a TTL on sessionsSessions never expire, and memory growsSet an idle timeout and refresh it
Calling INCR and EXPIRE separately and failing in betweenA counter with no expiry blocks the user foreverUse EXPIRE ... NX or a script
Practice
  1. Store a session as a hash with a 30-minute idle timeout and verify it disappears after expiry.
  2. Write a limiter that allows 5 login attempts per minute per IP and returns the seconds remaining.
Key takeaways
  • Sessions are hashes with an idle-timeout TTL and a random, unguessable ID.
  • Fixed-window limiting is INCR plus EXPIRE on a time-bucketed key.
  • Fixed windows allow boundary bursts, which better algorithms fix later.
