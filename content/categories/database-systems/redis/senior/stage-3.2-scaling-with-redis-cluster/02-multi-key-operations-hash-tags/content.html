Multi-Key Operations & Hash Tags

Commands that touch several keys only work when all the keys live in the same slot, and hash tags are how you arrange that.

§1The CROSSSLOT Error

MGET user:1 user:2
# (error) CROSSSLOT Keys in request don't hash to the same slot
SUNION set:a set:b            # same problem

Transactions, Lua scripts, and RENAME have the same restriction.

§2Hash Tags

If a key contains {...}, only the text inside the first braces is hashed. Keys with the same tag share a slot.

SET {user:1001}:profile "..."
SET {user:1001}:cart "..."
MGET {user:1001}:profile {user:1001}:cart       # works: same slot

§3Designing Around It

Group keys that are used together by an entity, such as a user or a tenant. Do not tag everything with one value, because then a single slot, and one node, takes all the traffic and memory: a hot shard.

EVAL "..." 2 {order:77}:items {order:77}:total   # script across keys of one order

§4When You Cannot Co-locate

Some operations span entities, such as a global leaderboard or a set intersection across users. Options: keep that data in one key (and accept it lives on one node), compute it in the application by fetching from several nodes, or run a separate non-clustered instance for it.

The key insight In Cluster, key naming is a data-placement decision. Choose hash tags to co-locate what you operate on together, and to spread everything else.

§5Common Mistakes

MistakeWhat HappensFix
Putting one constant in every hash tagAll data lands in one slotTag by entity id, not by feature
Assuming MGET works across any keysCROSSSLOT errors in productionTest in a real cluster, not standalone
Developing on standalone Redis onlyCode breaks when moved to ClusterTest against a cluster early
Practice
  1. Design keys for a shopping cart and an order so each entity's keys co-locate, and write a script that updates both.
  2. Reproduce CROSSSLOT, then fix it with a hash tag.
Key takeaways
  • Multi-key commands require all keys in one slot.
  • Hash tags force keys into the same slot.
  • Tag by entity so load spreads, and avoid a single hot slot.
