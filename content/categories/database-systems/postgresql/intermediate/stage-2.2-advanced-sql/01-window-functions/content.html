Window Functions

Window functions compute a value for each row using a set of related rows, without collapsing the result the way GROUP BY does.

§1OVER, PARTITION BY, and ORDER BY

An aggregate with GROUP BY returns one row per group. A window function keeps every row and adds a computed column based on a *window* of rows around it. The OVER clause defines the window: PARTITION BY splits rows into independent groups, and ORDER BY orders rows inside each group.

SELECT customer_id, placed_at, total,
       sum(total) OVER (PARTITION BY customer_id)                          AS customer_total,
       sum(total) OVER (PARTITION BY customer_id ORDER BY placed_at)       AS running_total,
       round(100 * total / sum(total) OVER (PARTITION BY customer_id), 1)  AS pct_of_customer
FROM orders;

Each order row remains in the output. Any aggregate (sum, avg, count, min, max) can be used as a window function by adding OVER (...).

§2Ranking and Offsets

Special window functions rank rows or look at neighbors.

SELECT name, department, salary,
       row_number() OVER w AS rn,         -- 1,2,3,4 (ties broken arbitrarily)
       rank()       OVER w AS rnk,        -- 1,2,2,4 (gaps after ties)
       dense_rank() OVER w AS drnk        -- 1,2,2,3 (no gaps)
FROM employees
WINDOW w AS (PARTITION BY department ORDER BY salary DESC);

SELECT day, revenue,
       revenue - lag(revenue) OVER (ORDER BY day)  AS change_vs_prev,
       lead(revenue) OVER (ORDER BY day)           AS next_day
FROM daily_revenue;

lag and lead read the previous or next row without a self join. ntile(4) splits rows into quartiles, and first_value / last_value read the edges of the window. A named WINDOW clause avoids repeating a definition.

To filter on a window result you need a subquery or CTE, since WHERE runs before windows are computed:

SELECT * FROM (
    SELECT *, row_number() OVER (PARTITION BY customer_id ORDER BY placed_at DESC) AS rn
    FROM orders
) t WHERE rn = 1;                         -- latest order per customer

§3Frames

With an ORDER BY, each row's window is by default every row from the start of the partition to the current row, which is what makes a running total. A frame clause lets you choose precisely.

SELECT day, revenue,
       avg(revenue) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS avg_7_day,
       sum(revenue) OVER (ORDER BY day ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS cumulative
FROM daily_revenue;

ROWS counts physical rows, RANGE groups rows with equal sort values, and GROUPS counts peer groups. One gotcha: with the default frame, last_value returns the current row (not the partition's last row), so give it an explicit frame to the end: ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING.

The key insight GROUP BY reduces rows; a window function annotates them. If you find yourself self-joining a table to compare each row with its neighbors or group totals, you probably want a window function.

§4Common Mistakes

MistakeWhat HappensFix
Filtering on a window function in WHEREError: window functions are not allowed in WHEREWrap the query in a subquery or CTE and filter outside
Relying on row_number() without a deterministic ORDER BYTies are broken arbitrarily and results change between runsAdd a unique tiebreaker column to ORDER BY
Using last_value with the default frameReturns the current row instead of the last in the partitionSpecify ROWS BETWEEN ... AND UNBOUNDED FOLLOWING
Practice
  1. For each customer, show every order with its running total and the previous order's amount using lag.
  2. Return the three highest-paid employees per department using dense_rank in a subquery.
  3. Compute a 7-day moving average of daily revenue with an explicit ROWS frame.
Key takeaways
  • OVER (PARTITION BY ... ORDER BY ...) computes per-row values from related rows without collapsing the result.
  • Use row_number, rank, lag, and lead for ranking, top-N per group, and comparisons with neighboring rows.
  • Filter on window results in an outer query, and set explicit frames for moving calculations.
