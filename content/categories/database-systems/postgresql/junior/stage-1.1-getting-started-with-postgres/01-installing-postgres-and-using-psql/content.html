Installing Postgres & Using psql

Postgres is a server you connect to, and psql is the command-line client that lets you talk to it, explore it, and script it.

§1Running a Server

Postgres runs as a long-lived server process that listens on a TCP port (5432 by default) and, on Unix systems, a local socket. Clients never touch the data files; they connect, send SQL, and read results. You can install it with your OS package manager, run it in a container, or use a managed service. For learning, a container is the cleanest option because you can throw it away.

docker run --name pg -e POSTGRES_PASSWORD=secret -p 5432:5432 -d postgres:18
docker exec -it pg psql -U postgres

On Debian or Ubuntu the packages are postgresql plus a version number, and the server starts as a system service. On macOS, Homebrew or Postgres.app both work. Whichever you pick, check the major version with SELECT version(); because features differ between versions.

§2Connecting with psql

psql takes the same connection parameters as every other Postgres client: host, port, database, and user. Anything you leave out falls back to environment variables (PGHOST, PGPORT, PGDATABASE, PGUSER) and then to defaults.

psql -h localhost -p 5432 -U postgres -d postgres
psql "postgresql://postgres:secret@localhost:5432/postgres"   # connection URI
psql -c "SELECT now();"                                         # one command, then exit
psql -f schema.sql                                              # run a script file

Inside psql, a statement ends with a semicolon. Without one, psql assumes you are still typing and shows a continuation prompt (postgres-#). Typing the semicolon, or \r to reset the buffer, gets you out.

§3Meta-Commands

Lines that start with a backslash are meta-commands: they are handled by psql itself, not sent to the server. They are the fastest way to explore an unfamiliar database.

CommandWhat it does
\lList databases
\c dbnameConnect to another database
\dtList tables in the search path
\d tablenameDescribe a table: columns, indexes, constraints
\dn, \duList schemas, list roles
\xToggle expanded (vertical) output for wide rows
\timingShow how long each statement took
\? and \h CREATE TABLEHelp for meta-commands and for SQL syntax
\qQuit

Put your preferred settings in ~/.psqlrc so every session starts the way you like, for example \x auto and \timing on.

The key insight psql has built-in SQL syntax help. \h UPDATE prints the full grammar for the statement, which is often faster than a web search and always matches your installed version.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting the trailing ;The prompt changes to -# and nothing runsAdd the semicolon, or \r to clear the query buffer
Publishing port 5432 on a public interface with a weak passwordThe database is reachable and guessable from the internetBind to localhost for development; use strong credentials and a firewall for anything shared
Using \d output as if it were SQLMeta-commands do not work in application code or in psql -c with other statements mixed inQuery information_schema or pg_catalog from code; keep \d for interactive use
Practice
  1. Start a Postgres container, connect with psql, and run SELECT version(); and SELECT current_database(), current_user;.
  2. Use \l, \dn, and \du to list what exists in a fresh server, then use \h CREATE TABLE to read the grammar.
  3. Create a ~/.psqlrc that turns on \timing and \x auto, then reconnect and confirm both apply.
Key takeaways
  • Postgres is a server; psql is one client, and any client connects with host, port, database, and user.
  • Meta-commands starting with \ are handled by psql and are for interactive exploration only.
  • A container makes a disposable, version-pinned practice server.
