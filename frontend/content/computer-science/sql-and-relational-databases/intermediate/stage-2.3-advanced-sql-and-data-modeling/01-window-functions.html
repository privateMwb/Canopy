Window Functions

Window functions compute a value for each row using a related set of rows, like a running total or a rank, without collapsing the rows the way GROUP BY does.

§1The Gap GROUP BY Leaves

GROUP BY turns many rows into one per group, so you lose the individual rows. But many questions need both: each order and the customer's total, each employee and their rank within the department. A window function adds a computed column while keeping every row.

SELECT id, customer_id, total,
       SUM(total) OVER (PARTITION BY customer_id) AS customer_total,
       total / SUM(total) OVER (PARTITION BY customer_id) AS share
FROM orders;

OVER (...) defines the window: which rows each row's calculation can see.

§2OVER, PARTITION BY, and ORDER BY

  • PARTITION BY splits rows into independent groups (like GROUP BY but without collapsing).
  • ORDER BY inside OVER orders the rows within each partition, and for aggregates it makes the calculation cumulative.
SELECT placed_at, total,
       SUM(total) OVER (ORDER BY placed_at) AS running_total,       -- cumulative
       AVG(total) OVER (ORDER BY placed_at
                        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS avg_7_orders   -- moving average
FROM orders;

The ROWS BETWEEN ... AND ... clause sets the frame: exactly which neighboring rows count.

§3Ranking and Navigation Functions

SELECT customer_id, id, total,
       ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY total DESC) AS rn,   -- 1,2,3,4 (no ties)
       RANK()       OVER (PARTITION BY customer_id ORDER BY total DESC) AS rnk,  -- 1,2,2,4 (ties, gaps)
       DENSE_RANK() OVER (PARTITION BY customer_id ORDER BY total DESC) AS drnk, -- 1,2,2,3 (ties, no gaps)
       LAG(total)   OVER (PARTITION BY customer_id ORDER BY placed_at) AS prev_total,
       LEAD(total)  OVER (PARTITION BY customer_id ORDER BY placed_at) AS next_total
FROM orders;

LAG and LEAD look at the previous and next rows in the window: perfect for "change since last month" calculations. NTILE(4) splits rows into quartiles; FIRST_VALUE and LAST_VALUE pick the window's ends.

§4The Top-N-per-Group Pattern

Window functions solve a classic problem that GROUP BY can't: the top 3 orders for each customer.

SELECT * FROM (
  SELECT o.*,
         ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY total DESC) AS rn
  FROM orders o
) ranked
WHERE rn <= 3;                  -- window functions can't appear in WHERE directly, so wrap them

Because window functions run after WHERE and GROUP BY, you filter on their results by wrapping the query in a subquery or CTE.

The key insight GROUP BY answers a question about groups; a window function answers a question about each row in the context of its group. If you need the detail and the summary together, reach for OVER.

§5Common Mistakes

MistakeWhat HappensFix
Using a window function in WHEREError: windows are computed after filteringWrap in a subquery or CTE, then filter
ORDER BY in OVER without understanding the default frameRunning totals where you expected a whole-partition totalOmit ORDER BY for totals; state the frame explicitly when it matters
Using RANK where ROW_NUMBER was neededTies return more rows than expected for top-NUse ROW_NUMBER for exactly N; RANK/DENSE_RANK when ties matter
Self-joins to get the previous rowSlow, hard-to-read SQLUse LAG / LEAD
Practice
  1. Write a query showing each order with its customer's running total over time and the difference from the customer's previous order using LAG.
  2. Return the top two products by revenue within each category. Do it once with ROW_NUMBER and once with DENSE_RANK; when do the answers differ?
Key takeaways
  • Window functions compute per-row values over a related set of rows without collapsing them.
  • PARTITION BY defines groups; ORDER BY and frames define running and moving calculations.
  • Filter on window results by wrapping the query in a subquery or CTE.
