SQL Basics: SELECT, WHERE & Sorting

SELECT is how you read data: choose columns, filter rows with WHERE, sort with ORDER BY, and cap the output with LIMIT.

§1The Shape of a Query

SQL is declarative: you describe the result you want, and the database decides how to compute it. A basic query has a few clauses, and they're written in this order:

SELECT name, price        -- which columns
FROM products             -- which table
WHERE price < 20          -- which rows
ORDER BY price DESC       -- what order
LIMIT 10;                 -- how many

SELECT * returns every column. It's fine for exploring, but in application code, list the columns you need.

§2Filtering with WHERE

WHERE keeps only rows for which its condition is true. Combine conditions with AND, OR, and NOT, and use parentheses when mixing them.

SELECT * FROM products WHERE price BETWEEN 5 AND 20;
SELECT * FROM products WHERE category IN ('books', 'stationery');
SELECT * FROM customers WHERE name LIKE 'A%';           -- starts with A
SELECT * FROM products WHERE (price < 5 OR price > 50) AND in_stock = 1;

LIKE matches patterns: % means any run of characters and _ means exactly one.

§3Sorting, Limiting, and Aliases

ORDER BY sorts by one or more columns, ascending by default. Without it, row order is not guaranteed, even if it looks stable in testing.

SELECT name, price * 1.2 AS price_with_tax   -- AS gives a column an alias
FROM products
ORDER BY price_with_tax DESC, name ASC
LIMIT 5 OFFSET 10;                           -- skip 10 rows, return the next 5

DISTINCT removes duplicate rows from the result: SELECT DISTINCT category FROM products;

§4Logical Order vs. Written Order

You write SELECT first, but the database conceptually evaluates the clauses in a different order, which explains many beginner errors.

1. FROM      -- find the table
2. WHERE     -- filter rows
3. SELECT    -- compute columns and aliases
4. ORDER BY  -- sort
5. LIMIT     -- cut

This is why you can't use a SELECT alias inside WHERE (the alias doesn't exist yet) but can use it in ORDER BY.

The key insight Without ORDER BY, a SELECT returns rows in whatever order is convenient for the database. Never rely on an implicit order, and always pair LIMIT with ORDER BY if you care which rows you get.

§5Common Mistakes

MistakeWhat HappensFix
LIMIT without ORDER BYDifferent rows can come back on different runsAlways add an explicit ORDER BY with a tiebreaker such as the id
Using an alias in WHEREError: the column doesn't exist at that stageRepeat the expression in WHERE, or wrap the query in a subquery
Combining AND and OR without parenthesesAND binds tighter, so the filter silently means something elseParenthesize any mix of the two
Shipping SELECT * in application codeAdding a column later changes results and wastes bandwidthName the columns you need
Practice
  1. Given a products(id, name, category, price) table, write queries for: the five cheapest products, all products whose name contains "pen", and the distinct categories in alphabetical order.
  2. Why might SELECT name FROM products WHERE price * 1.2 > 30 ORDER BY price * 1.2 be rewritten with an alias? Which clauses may use the alias?
Key takeaways
  • SELECT/FROM/WHERE/ORDER BY/LIMIT cover most basic reads.
  • SQL is declarative: you state the result, the database picks the method.
  • Row order is undefined unless you ask for it with ORDER BY.
