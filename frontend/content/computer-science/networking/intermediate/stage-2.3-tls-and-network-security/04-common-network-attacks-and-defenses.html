Common Network Attacks & Defenses

Most network attacks exploit protocols that trust too easily, and each has a matching defense built from things you've already learned.

§1Attacks Against the Local Network

AttackHow it worksDefense
ARP spoofingA device on the LAN falsely claims another's IP address, so traffic flows through itSwitch-level protections such as dynamic ARP inspection; encrypting traffic so interception reveals nothing
Rogue DHCPA fake DHCP server hands out a malicious gateway or DNSDHCP snooping on switches
EavesdroppingReading unencrypted traffic on shared Wi-FiTLS everywhere; VPNs on untrusted networks

These work because ARP and DHCP have no authentication; anyone on the local link can answer. The strongest general defense isn't trusting the local network, and assuming it could be hostile.

§2Attacks on Transport and Name Resolution

AttackHow it worksDefense
SYN floodOverwhelm a server with SYNs to exhaust its half-open connection tableSYN cookies, rate limiting, upstream filtering
TCP reset injectionForge RST packets to kill connectionsRandomized sequence numbers, TLS can't prevent a reset but limits impact
DNS cache poisoningTrick a resolver into caching a false answerRandom source ports and query IDs, DNSSEC validation, encrypted DNS (DoT/DoH)
Man-in-the-middleSit between client and server and relay or alter trafficTLS with proper certificate validation, HSTS

Sequence numbers and source ports are chosen unpredictably precisely so that an attacker who can't see the traffic can't forge it.

§3Denial of Service and Amplification

A DDoS attack overwhelms a service with traffic. Reflection and amplification attacks abuse UDP services: the attacker sends a small request with a forged source address, the victim's, to a public server such as an open DNS or NTP resolver, which sends a much larger reply to the victim.

  • Amplification factor: a small query yields a response many times larger, so a modest attacker bandwidth yields a flood
  • Defenses: networks should block spoofed source addresses at the edge (BCP 38), servers should not answer open queries from anyone, and responses should be rate-limited
  • Absorption: CDNs and scrubbing services with huge capacity absorb floods, and anycast spreads the load across sites
  • Application-layer limits: rate limiting, caching, and bot detection for HTTP floods
# Check your own exposure, on infrastructure you own:
ss -lunp                      # which UDP services are open?
# Public resolvers and time servers should not answer arbitrary external queries.

No single control is enough. Layer encryption, validation, rate limiting, and capacity, and design on the assumption that some layers will be attacked or bypassed.

The key insight Each attack maps onto a protocol weakness: no authentication on the LAN, predictable numbers, or replies bigger than requests. Understanding the weakness tells you the defense.

§4Common Mistakes

MistakeWhat HappensFix
Trusting the internal networkOne compromised device can intercept or spoof trafficEncrypt and authenticate internal traffic, too
Running open DNS or NTP resolversYour servers are used to attack othersRestrict recursion and monitoring commands to trusted clients
Ignoring certificate validation errors in codeSilently enables man-in-the-middle attacksKeep verification on; fix trust-store problems instead
Practice
  1. For each attack in the tables, name the protocol weakness it exploits.
  2. Explain how a SYN cookie lets a server avoid storing state for half-open connections.
Key takeaways
  • LAN attacks such as ARP spoofing and rogue DHCP exploit protocols with no authentication.
  • Unpredictable sequence numbers, ports, and query IDs prevent blind forgery; TLS and DNSSEC add authentication.
  • Amplification attacks need spoofed sources and open services, so filtering and closing resolvers matter.
