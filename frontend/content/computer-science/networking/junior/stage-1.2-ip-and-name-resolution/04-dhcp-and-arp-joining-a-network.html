DHCP & ARP: Joining a Network

Before a device can talk to anyone, it needs an IP address, a gateway, and a way to find its neighbors' MAC addresses, which DHCP and ARP provide.

§1DHCP: Getting an Address

A new device has no IP address and doesn't know anyone's. DHCP (Dynamic Host Configuration Protocol) assigns configuration automatically, in four steps often remembered as DORA:

  1. Discover: the client broadcasts 'is there a DHCP server?' (it has no address, so it uses 0.0.0.0 as source and broadcasts to 255.255.255.255)
  2. Offer: a server proposes an address and settings
  3. Request: the client asks to use the offered address
  4. Acknowledge: the server confirms, granting a lease for a set time

DHCP runs over UDP, with the server on port 67 and the client on port 68. The lease includes much more than an address: the subnet mask, the default gateway, and the DNS servers. Clients renew the lease before it expires, usually at the halfway point.

ip addr show wlan0             # the address DHCP assigned
resolvectl status | head       # DNS servers learned via DHCP
# If DHCP fails, the OS may self-assign a 169.254.x.x link-local address.

§2ARP: Finding a Neighbor's MAC Address

To send a packet to an IP address on the same subnet, the sender must know the destination's MAC address, since the link layer delivers frames by MAC. ARP (Address Resolution Protocol) maps one to the other. The sender broadcasts 'who has 192.168.1.1?' and the owner replies with its MAC address.

ip neigh                         # the ARP cache: IP -> MAC for neighbors
# 192.168.1.1 dev wlan0 lladdr 3c:22:fb:1a:2b:3c REACHABLE

Results are cached briefly so that ARP isn't repeated for each packet. ARP only operates within one subnet. To reach an address outside it, the host ARPs for its default gateway and sends the packet to the gateway's MAC address, with the real destination's IP address still inside.

§3Putting a New Device Online

  1. The device joins the Wi-Fi or plugs into Ethernet
  2. DHCP gives it an address, mask, gateway, and DNS servers
  3. It ARPs for the gateway's MAC address
  4. It asks DNS for a website's address
  5. It sends packets to the gateway, which routes them onward

ARP has no authentication, so any device on the local network can claim an address. This is the basis of ARP spoofing, which Stage 2.3 covers along with its defenses. IPv6 replaces ARP with a similar mechanism called Neighbor Discovery.

The key insight ARP is scoped to the local subnet. If a host can't reach anything off-subnet, check the gateway first: is the gateway configured, and does the host have its MAC address in ip neigh?

§4Common Mistakes

MistakeWhat HappensFix
Having two DHCP servers on one networkClients get conflicting or wrong settingsRun one authoritative server per subnet, or coordinate with failover
Assigning a static IP inside the DHCP poolAddress conflictsReserve static addresses outside the pool, or use DHCP reservations
Expecting ARP to cross routersARP broadcasts stay on one subnetRemember the host ARPs for the gateway, not the remote host
Practice
  1. Run ip neigh and find your gateway's MAC address. Compare it with the MAC shown for the gateway's interface on the router, if accessible.
  2. Describe what a device does, in order, from plugging in to loading its first web page, naming DHCP, ARP, and DNS.
Key takeaways
  • DHCP assigns an address, mask, gateway, and DNS servers through Discover, Offer, Request, and Acknowledge.
  • ARP maps an IP address to a MAC address within one subnet.
  • To reach another network, a host ARPs for its default gateway and sends the packet there.
