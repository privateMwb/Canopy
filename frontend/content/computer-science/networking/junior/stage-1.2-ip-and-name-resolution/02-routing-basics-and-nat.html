Routing Basics & NAT

Routers forward packets one hop at a time using a table of prefixes, and NAT lets many private devices share one public address.

§1The Routing Table and Longest Prefix Match

A host or router keeps a routing table: a list of destination prefixes and the next hop for each. When a packet arrives, the device picks the entry with the longest matching prefix, the most specific route.

ip route
# default via 192.168.1.1 dev wlan0          <- anything not matched below
# 192.168.1.0/24 dev wlan0 scope link       <- local network, deliver directly

# A router's table:
10.0.0.0/8    via A
10.1.0.0/16   via B
0.0.0.0/0     via C     # the default route
# A packet for 10.1.2.3 matches all three; /16 is longest, so it goes via B.

If the destination is on the local subnet, the host delivers directly. Otherwise, it sends the packet to its default gateway, which makes the next decision.

§2Hop by Hop and the TTL

No router knows the whole path. Each looks only at the destination and forwards to the next hop. To stop packets from looping forever, every IP packet has a time-to-live (TTL) that each router decrements. At zero, the router discards the packet and sends back an ICMP 'time exceeded' message. traceroute exploits this by sending packets with TTL 1, 2, 3, ..., and recording who answers.

traceroute -n example.com        # hop 1 = your router, hop 2 = ISP, ...

The path from you to a server and back may differ, since each direction is routed independently.

§3NAT: Many Devices, One Public Address

IPv4 has too few addresses for every device, so homes and companies use private addresses internally and a router performs network address translation. For outgoing traffic, it rewrites the source address to its own public address and picks a unique source port, recording the mapping.

# Router's NAT table (conceptual)
192.168.1.20:51234  <->  198.51.100.7:40001   -> server 203.0.113.9:443
192.168.1.21:51234  <->  198.51.100.7:40002   -> server 203.0.113.9:443

# Reply from server arrives at 198.51.100.7:40001; the router looks it up,
# rewrites the destination to 192.168.1.20:51234, and forwards it.

Consequences follow. Unsolicited inbound connections have no mapping, so they're dropped, which acts like an accidental firewall. Hosting a server behind NAT needs port forwarding. Peer-to-peer apps need tricks to traverse it. And many ISPs add carrier-grade NAT, putting several customers behind one public address.

Gotcha NAT breaks the end-to-end principle: the address a host sees for itself isn't the address the world sees. Protocols that embed IP addresses inside their payloads, and anything needing inbound connections, require special handling.

§4Common Mistakes

MistakeWhat HappensFix
Assuming the destination knows your private addressReplies and logs show the NAT's public address insteadLog the connecting address as seen by the server, and forward real client IP via headers if needed
Expecting inbound connections through NAT to workThe router has no mapping, so packets are droppedConfigure port forwarding, or use an outbound tunnel or relay
Believing traceroute shows the return pathThe reverse route may differTrace from both ends when diagnosing asymmetric problems
Practice
  1. Run ip route and traceroute -n to a public site. Identify your default gateway and the first hop beyond your home network.
  2. Given routes 10.0.0.0/8 via A, 10.8.0.0/16 via B, 10.8.4.0/24 via C, and default via D, where do packets for 10.8.4.9, 10.8.9.1, and 8.8.8.8 go?
Key takeaways
  • Routers pick the longest matching prefix and forward hop by hop; the TTL prevents loops.
  • The default route catches everything with no more specific match.
  • NAT shares one public address among many private hosts by rewriting addresses and ports, which blocks unsolicited inbound traffic.
