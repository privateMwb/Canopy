Ports, Listening & Connection States

Reading ss output turns TCP state names into a quick view of what a machine is serving, who is connected, and where things are stuck.

§1What's Listening

ss (or the older netstat) lists sockets. The most useful first command shows which programs are listening, and on which address.

ss -tlnp
# State   Recv-Q Send-Q  Local Address:Port   Process
# LISTEN  0      4096    0.0.0.0:22           sshd
# LISTEN  0      4096    127.0.0.1:5432       postgres

The local address matters. 0.0.0.0 means listening on every interface, reachable from other machines. 127.0.0.1 means loopback only, unreachable from outside, which is why a database bound there isn't exposed. lsof -i :8000 shows which process holds a given port.

§2The TCP States You'll See

StateMeaningConcern if many
LISTENWaiting for incoming connectionsNormal
SYN-SENTClient sent SYN, awaiting replyServer unreachable or filtered
SYN-RECVServer got SYN, sent SYN-ACKSYN flood or slow clients
ESTABLISHEDConnection open, data flowsNormal; count equals load
FIN-WAIT / TIME-WAITLocal side closed; waitingNormal for busy clients; port exhaustion risk
CLOSE-WAITPeer closed; local app hasn'tA bug: the application isn't calling close

CLOSE-WAIT deserves special attention. The kernel is waiting for your program to close its end, and a growing pile means a connection or file descriptor leak.

§3Ephemeral Ports and 'Address Already in Use'

Clients get a temporary ephemeral port for each outgoing connection, drawn from a range, on Linux by default 32768 to 60999. That limits one machine to roughly 28,000 simultaneous connections to a single destination address and port.

cat /proc/sys/net/ipv4/ip_local_port_range      # 32768 60999
ss -tan state established | wc -l                # connections open right now
ss -s                                            # summary of all socket states

'Address already in use' on startup means another socket holds that port, either a live listener or old connections in TIME_WAIT. Check ss -tlnp first, and use SO_REUSEADDR for the latter.

The key insight A socket's state tells you who is waiting for whom. Many SYN-SENT means the remote isn't answering; many CLOSE-WAIT means your own program forgot to close.

§4Common Mistakes

MistakeWhat HappensFix
Binding a service to 0.0.0.0 by accidentA private service becomes exposed on every interfaceBind internal services to 127.0.0.1 or a private interface
Ignoring CLOSE-WAIT buildupEventually the process runs out of file descriptorsFind and fix the missing close, usually in an error path
Reading TIME_WAIT as a leakThey age out on their own and are expectedOnly act if you run out of ephemeral ports
Practice
  1. Run ss -tlnp and list every listening service. Which are reachable only from localhost, and which from the network?
  2. Start the echo server twice on the same port. Read the error, then find the process holding the port with ss or lsof.
Key takeaways
  • ss -tlnp shows what's listening and on which address; 0.0.0.0 and 127.0.0.1 differ in who can connect.
  • Many CLOSE-WAIT sockets signal a local application bug.
  • Ephemeral ports bound the number of outbound connections to one destination.
