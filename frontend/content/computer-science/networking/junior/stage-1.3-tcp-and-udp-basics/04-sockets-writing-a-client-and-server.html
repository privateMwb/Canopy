Sockets: Writing a Client and Server

The sockets API is how programs use TCP and UDP, and a handful of calls is enough to build a working client and server.

§1The Server Side

A TCP server creates a socket, binds it to an address and port, marks it as listening, and then repeatedly accepts connections. Each accept returns a new socket for one client, while the original keeps listening.

import socket

srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)   # SOCK_STREAM = TCP
srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)  # allow quick restarts
srv.bind(("0.0.0.0", 8000))
srv.listen(128)                                            # backlog of waiting connections

while True:
    conn, addr = srv.accept()        # blocks until a client connects
    with conn:
        data = conn.recv(4096)       # up to 4096 bytes; may return fewer
        conn.sendall(data.upper())   # sendall loops until everything is sent

SO_REUSEADDR lets you restart the server immediately even while old connections sit in TIME_WAIT. Without it, you'd see 'Address already in use'.

§2The Client Side

import socket

c = socket.create_connection(("127.0.0.1", 8000))   # resolves, connects, handshakes
c.sendall(b"hello")
print(c.recv(4096))                                 # b'HELLO'
c.close()

connect triggers the three-way handshake. The OS picks a free source port for the client automatically.

§3Partial Reads, Framing, and Many Clients

Because TCP is a byte stream, a single recv may return part of a message, or two messages joined. Code that assumes otherwise works in testing on localhost and breaks on real networks.

def recv_exact(sock, n):
    buf = b""
    while len(buf) < n:
        chunk = sock.recv(n - len(buf))
        if not chunk:                      # empty bytes = peer closed the connection
            raise ConnectionError("closed early")
        buf += chunk
    return buf

# Framing: send a 4-byte length, then the payload
sock.sendall(len(msg).to_bytes(4, "big") + msg)
size = int.from_bytes(recv_exact(sock, 4), "big")
msg = recv_exact(sock, size)

The server above handles one client at a time. To serve several, start a thread per connection, or use an event loop such as selectors or asyncio. The system calls underneath are the same socket, bind, listen, accept, connect, send, and recv of the Berkeley sockets API in C.

Gotcha recv returning an empty result means the peer closed the connection, not 'no data yet'. A loop that treats it as 'try again' will spin at 100% CPU.

§4Common Mistakes

MistakeWhat HappensFix
Assuming recv(n) returns exactly n bytesTruncated or merged messagesLoop until you have the bytes you need, or use length-prefixed framing
Using send and ignoring its return valueOnly part of the data was sentUse sendall, or loop on the returned byte count
Binding to 127.0.0.1 and expecting remote accessOther machines can't connectBind to 0.0.0.0 (or a specific interface) to accept external connections
Practice
  1. Build the server and client above, then test the client by sending a 1 MB message. Does one recv get it all?
  2. Modify the server to handle several clients at once using a thread per connection.
Key takeaways
  • A TCP server calls bind, listen, and accept; a client calls connect.
  • recv may return any amount up to the limit, and an empty result means the peer closed.
  • Define message framing yourself because TCP carries bytes, not messages.
