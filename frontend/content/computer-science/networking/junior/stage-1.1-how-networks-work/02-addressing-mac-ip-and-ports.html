Addressing: MAC, IP & Ports

Three kinds of address each answer a different question: which device on this link, which host on the internet, and which program on that host.

§1Three Addresses, Three Questions

AddressSizeAnswersScope
MAC48 bits (3c:22:fb:1a:2b:3c)Which network interface on this local link?One local network; changes at every hop
IP32 bits (IPv4) or 128 bits (IPv6)Which host, anywhere on the internet?Whole path, source to destination
Port16 bits (0–65535)Which program on that host?One host
ip addr                  # interfaces, their MAC (link/ether) and IP (inet) addresses
ip link show eth0        # MAC address of one interface

A MAC address is assigned to a network interface and is used only to move a frame across a single local network. An IP address identifies the destination across many networks. A port picks which application receives the data once it arrives.

§2How They Change Along a Path

When your laptop sends a packet to a server on the other side of the world, the IP addresses stay the same from end to end (ignoring NAT, which you'll meet shortly). The MAC addresses change at every hop: first laptop to home router, then router to the next device, and so on. Each router strips the old link-layer frame and builds a new one for the next link.

laptop  ─────────►  router  ─────────►  ISP router  ──► ...  ──►  server
src IP: 192.168.1.20 ............................................ dst IP: 203.0.113.9
MAC:    laptop→router      router→ISP         ISP→next ...        (new at each hop)

§3Ports and the Connection 5-Tuple

Ports let one machine run many network programs at once. Servers listen on a well-known port, and clients use a temporary one chosen by the OS.

PortProtocol
22SSH
53DNS
80HTTP
443HTTPS
25SMTP

A connection is uniquely identified by five values, the 5-tuple: source IP, source port, destination IP, destination port, and protocol. That's why a server can hold thousands of connections to port 443 at once: each client has a different source address and port.

# Two browser tabs to the same server, same destination port, different source ports
192.168.1.20:51234  ->  203.0.113.9:443   (TCP)
192.168.1.20:51235  ->  203.0.113.9:443   (TCP)
The key insight A MAC address gets a frame to the next device, an IP address gets a packet to the right host, and a port gets the data to the right program. Mixing up these roles is the root of many networking misunderstandings.

§4Common Mistakes

MistakeWhat HappensFix
Thinking a MAC address travels end to endExpecting to see a remote server's MAC addressMAC addresses only matter on the local link; routers replace them at each hop
Believing a port belongs to a connectionConfusion about how many clients can use port 443A port belongs to a listening program; connections are identified by the full 5-tuple
Treating IP address as a stable identity of a person or deviceAddresses change with DHCP, NAT, and mobilityUse names and authentication for identity, not addresses
Practice
  1. Run ip addr and identify your machine's MAC address, IPv4 address, and IPv6 address, if any.
  2. Explain why a server on port 443 can serve 10,000 clients, though there is only one port 443.
Key takeaways
  • MAC addresses move frames across one link, IP addresses identify hosts end to end, and ports identify programs.
  • IP addresses stay constant along a path while MAC addresses change at every hop.
  • A connection is identified by its 5-tuple, not by a port alone.
