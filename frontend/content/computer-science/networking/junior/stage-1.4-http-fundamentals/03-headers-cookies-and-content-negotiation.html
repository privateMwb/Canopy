Headers, Cookies & Content Negotiation

Headers carry the metadata that lets clients and servers agree on formats, control caching, and, with cookies, remember who you are in a stateless protocol.

§1Common Headers

HeaderDirectionPurpose
HostRequestWhich site is being requested
User-AgentRequestWhat software is making the request
AcceptRequestFormats the client can handle
AuthorizationRequestCredentials, such as a bearer token
Content-TypeBothFormat of the body (application/json)
Content-LengthBothSize of the body in bytes
LocationResponseWhere to go for redirects, or the new resource
Cache-ControlBothCaching instructions

Header names are case-insensitive. Custom headers conventionally describe what they do, and responses often include X--style or vendor headers for tracing, such as a request ID.

§2Content Negotiation

A client states its preferences and the server chooses what to send.

GET /report HTTP/1.1
Host: api.example.com
Accept: application/json, text/csv;q=0.5        # prefers JSON; CSV acceptable at lower weight
Accept-Encoding: gzip, br                       # can decompress these
Accept-Language: en-US,en;q=0.8

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Content-Encoding: gzip                          # body is compressed

If a server can't supply any acceptable format, it can answer 406 Not Acceptable. Compression through Content-Encoding usually shrinks text responses by 70% or more at little cost.

§3Cookies: State on a Stateless Protocol

A server sets a cookie with Set-Cookie, and the browser returns it in a Cookie header on later requests to that site. This is how a login session persists.

HTTP/1.1 200 OK
Set-Cookie: session=a1b2c3; Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=3600

GET /account HTTP/1.1
Host: example.com
Cookie: session=a1b2c3
AttributeEffect
SecureSent only over HTTPS
HttpOnlyHidden from JavaScript, limiting theft through XSS
SameSiteControls sending on cross-site requests, limiting CSRF
Max-Age / ExpiresHow long the cookie lives
Domain / PathWhich requests include it

The cookie holds only an identifier. The real session data lives on the server, so the value should be random and unguessable.

Gotcha Set-Cookie without Secure, HttpOnly, and SameSite is a common cause of session theft. Treat those three attributes as the default for any login cookie.

§4Common Mistakes

MistakeWhat HappensFix
Sending a body with no Content-TypeThe receiver guesses the format and misparses itAlways set Content-Type to match the body
Storing sensitive data directly in a cookieThe user can read and edit itStore a random session ID and keep the data server-side
Omitting Secure on cookiesThe cookie travels in clear text over HTTPMark session cookies Secure and redirect to HTTPS
Practice
  1. Use curl -v -H 'Accept: application/json' against a site that supports several formats, and compare the responses.
  2. Inspect the cookies set by a login page in your browser's DevTools, and note each attribute.
Key takeaways
  • Headers carry metadata for formats, caching, credentials, and more.
  • Content negotiation uses Accept headers so that the server can pick a representation.
  • Cookies add state to HTTP and need Secure, HttpOnly, and SameSite for safety.
