Firewalls, Segmentation & VPNs

Network controls decide which traffic is allowed to flow where, and each protects against a specific set of problems while leaving others untouched.

§1Firewalls

A firewall permits or blocks traffic according to rules. A stateless filter judges each packet independently, by addresses, ports, and protocol. A stateful firewall tracks connections: once an outbound connection is allowed, the matching replies are allowed automatically, and unsolicited inbound packets are dropped. Most modern firewalls and cloud security groups are stateful.

# nftables: a minimal stateful host firewall
table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;     # default deny
    ct state established,related accept                  # replies to our own connections
    iif lo accept
    tcp dport { 22, 443 } accept                          # only what's needed
    icmp type { echo-request, destination-unreachable } accept
  }
}

The key principle is default deny: block everything, then allow specific, justified flows. Remember to filter egress (outbound) traffic too, since limiting where a compromised host can call out blocks data exfiltration and command-and-control traffic.

§2Segmentation

Network segmentation divides a network into zones with controlled paths between them, such as separate subnets for public web servers, application servers, and databases.

Internet ─► [ public subnet: load balancer ] ─► [ app subnet ] ─► [ data subnet: database ]
                      allow 443 only                allow 8080 from LB     allow 5432 from app only
                                                    no route from the internet

A web server compromise then doesn't give direct access to the database, because only the application tier may talk to it, and only on one port. Segmentation limits lateral movement, an attacker's hopping from one machine to the next. In cloud and container environments, security groups and network policies provide it at fine granularity, down to individual workloads.

§3VPNs

A VPN creates an encrypted tunnel across an untrusted network.

UseWhat it does
Remote accessA user's device joins the corporate network through an encrypted tunnel
Site-to-siteTwo networks are joined across the internet, as if directly connected
Privacy on untrusted networksProtects traffic from local eavesdroppers on public Wi-Fi

Common technologies include WireGuard, IPsec, and OpenVPN. Split tunneling sends only some traffic through the VPN, which saves bandwidth but means the rest isn't covered by the corporate controls.

A VPN protects data in transit and gates network entry. It doesn't make a compromised device safe, and once connected, a user often gets broad network access, which is exactly the implicit trust that zero trust tries to remove. Pair a VPN with segmentation, strong authentication, and per-application authorization, or replace broad VPN access with application-level access proxies.

sudo nft list ruleset            # see active firewall rules
sudo ss -tlnp                     # what's listening that rules should cover
The key insight Each control answers a narrow question: a firewall says which flows are permitted, segmentation limits how far a breach spreads, and a VPN protects the tunnel. None replaces authentication and authorization inside the application.

§4Common Mistakes

MistakeWhat HappensFix
Allowing 'any' rules during setup and leaving themPermanent, forgotten holesStart from default deny, add specific rules, and review them regularly
Filtering only inbound trafficCompromised hosts can freely call outRestrict egress to required destinations
Treating VPN access as full trustOne stolen credential reaches the whole networkSegment, require strong authentication, and authorize per application
Practice
  1. Write firewall rules for a web server that accepts HTTPS from anywhere and SSH only from one admin address, with default deny.
  2. Draw a three-tier network with the allowed flows labeled, and explain what an attacker who compromises the web tier can and cannot reach.
Key takeaways
  • Stateful firewalls with default deny and egress filtering control which flows are allowed.
  • Segmentation limits lateral movement by restricting paths between tiers.
  • VPNs protect transit and gate entry but don't make devices trustworthy, so pair them with other controls.
