Classification vs. Regression

Predicting a category instead of a number — a different kind of problem, with different tools.

§1Two Kinds of Predictions

Regression predicts a continuous number (exam score, house price). Classification predicts a category from a fixed set (spam/not spam, pass/fail, which digit is this). The target's nature decides which family of models applies.

§2Spotting Which One You Need

# regression: y is a continuous number
y = [50, 65.5, 80, 72.3]

# classification: y is one of a fixed set of labels
y = ["pass", "fail", "pass", "pass"]
y = [0, 1, 1, 0]   # classification labels can be numeric too — what matters is they're categories, not quantities
The real test Ask: "does it make sense to average these values?" Averaging exam scores makes sense (regression). Averaging "pass" and "fail" doesn't (classification) — even if you encode them as 0 and 1, 0.5 isn't a meaningful answer.

§3Binary vs. Multi-Class

Binary classification: exactly two categories (spam/not spam). Multi-class: three or more (which of 10 digits is this). The core ideas carry over, some techniques need small adjustments for more than two classes.

§4Common Mistakes

MistakeWhat HappensFix
Using regression metrics (MAE, R²) on a classification problemNumbers that don't mean anything meaningfulUse classification metrics instead — confusion matrix, precision, recall (next lessons)
Treating a numeric-coded category as a quantityE.g. averaging 0/1 labels and misreading the resultRemember the numbers are just category labels, not magnitudes
Practice
  1. For each: house price, customer churn (yes/no), temperature, species of flower — label it regression or classification.
  2. In one sentence, explain your reasoning for the trickiest one.
Key takeaways
  • Regression predicts a continuous number; classification predicts a category.
  • The "does averaging make sense?" test is a reliable way to tell them apart.
  • Classification labels can be numeric-coded, but they're still categories, not quantities.
