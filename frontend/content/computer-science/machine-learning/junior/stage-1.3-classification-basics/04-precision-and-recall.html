Precision and Recall

Why accuracy alone can lie to you, and the two metrics that reveal what it hides.

§1When Accuracy Lies

If 95% of emails are not spam, a model that predicts "not spam" for everything scores 95% accuracy — while being completely useless. Accuracy hides this when classes are imbalanced. Precision and recall don't.

§2Precision — "When It Says Yes, How Often Is It Right?"

Precision = TP / (TP + FP)

Of everything the model flagged as positive, what fraction actually was? Low precision means a lot of false alarms.

§3Recall — "Of All the Real Positives, How Many Did It Catch?"

Recall = TP / (TP + FN)

Of everything that actually was positive, what fraction did the model find? Low recall means it's missing real cases.

§4Computing Them

from sklearn.metrics import precision_score, recall_score, f1_score

precision_score(y_test, predictions)
recall_score(y_test, predictions)
f1_score(y_test, predictions)   # a single number balancing both
The trade-off Precision and recall usually pull against each other. A model tuned to catch every possible case (high recall) will also flag more false alarms (lower precision), and vice versa. Which one to prioritize depends entirely on the cost of each error type.

§5Common Mistakes

MistakeWhat HappensFix
Using accuracy on an imbalanced datasetA useless model can look greatCheck precision, recall, and the confusion matrix instead
Optimizing only for recall or only for precisionThe other one can collapse unnoticedLook at both, or use F1 as a balance between them

Key takeaways
  • Accuracy can be misleading on imbalanced data — a model can score high while being useless.
  • Precision: of predicted positives, how many were right. Recall: of real positives, how many were found.
  • They trade off against each other; which matters more depends on the cost of each mistake.
