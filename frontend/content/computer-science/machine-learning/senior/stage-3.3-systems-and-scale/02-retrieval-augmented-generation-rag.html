Retrieval-Augmented Generation (RAG)

Giving a language model access to specific, up-to-date information it wasn't trained on, by retrieving it at request time.

§1The Problem RAG Solves

A language model's knowledge is frozen at training time, and it can't know about your company's internal documents, or anything that happened after training. RAG works around this by retrieving relevant information at request time and feeding it to the model as context, rather than relying purely on what it memorized during training.

§2The Two-Stage Pipeline

# 1. Retrieve: find relevant documents for the query
relevant_docs = vector_db.search(query_embedding, top_k=5)

# 2. Generate: feed the retrieved context to the model alongside the question
prompt = f"Context: {{relevant_docs}}\n\nQuestion: {{query}}"
answer = language_model.generate(prompt)

§3Vector Search — How Retrieval Actually Works

Documents get converted into embedding vectors (the same concept from tokenization & embeddings, applied to whole passages rather than words), stored in a vector database. A query gets embedded the same way, and the database returns the documents whose vectors are closest — i.e., most semantically similar — to the query's vector.

§4Why This Beats Just Fine-Tuning

Fine-tuning on new dataRAG
Updating knowledgeRequires retrainingJust update the document database
Source attributionHard to trace an answer back to a sourceCan cite exactly which retrieved document was used
Cost to keep currentExpensive, repeated retrainingCheap — just re-index new documents

§5Common Mistakes

MistakeWhat HappensFix
Retrieving too many or irrelevant documentsImportant context gets buried, or the prompt exceeds length limitsTune top_k and retrieval quality carefully
Assuming RAG eliminates hallucination entirelyThe model can still ignore or misread retrieved contextRAG reduces, but doesn't fully eliminate, the risk of ungrounded answers

  1. Sketch the two-stage pipeline for a RAG system answering questions about a company's internal wiki.

Key takeaways
  • RAG retrieves relevant information at request time instead of relying solely on a model's frozen training knowledge.
  • Vector search finds semantically similar documents by comparing embedding vectors.
  • RAG is cheaper to keep current than fine-tuning, and allows citing exactly which source informed an answer.
