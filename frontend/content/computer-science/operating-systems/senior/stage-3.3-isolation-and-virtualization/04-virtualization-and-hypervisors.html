Virtualization & Hypervisors

A hypervisor lets several full operating systems share one machine, using hardware help to keep each guest isolated and nearly full speed.

§1Trap and Emulate

A hypervisor (virtual machine monitor) runs guest operating systems as if each had the machine to itself. A guest kernel expects to run in privileged mode and to control the MMU and devices, so the hypervisor must intercept those operations. The classic technique is trap-and-emulate: guest code runs directly on the CPU, but when it tries a privileged operation, the CPU traps to the hypervisor, which emulates the effect on a virtual copy of the hardware and resumes the guest.

TypeRuns onExamples
Type 1 (bare metal)Directly on hardwareXen, VMware ESXi, Hyper-V
Type 2 (hosted)On top of a host OSVirtualBox, VMware Workstation

Early x86 had instructions that behaved differently in user mode without trapping, which broke this approach. Software techniques like binary translation worked around it, until hardware support arrived.

§2Hardware Virtualization

Intel VT-x and AMD-V add a mode just for guests. Guest code, including the guest kernel, runs in a non-root mode where it believes it's in privileged mode, and a defined set of events cause a VM exit back to the hypervisor in root mode. Most instructions never exit, so computation runs at close to native speed.

grep -E -c '(vmx|svm)' /proc/cpuinfo     # > 0 means the CPU supports hardware virtualization
ls -l /dev/kvm                            # KVM available to user space (via QEMU)

Each VM exit costs on the order of microseconds, so the performance of a VM depends on how often it exits: for I/O, for example.

§3Virtualizing Memory and Devices

The guest kernel manages its own page tables, mapping guest-virtual to guest-physical addresses, but guest-physical isn't real RAM. The hypervisor maps guest-physical to host-physical. Hardware nested paging (Intel EPT, AMD NPT) performs both translations in a single walk.

# Two-dimensional page walk, worst case, with 4 levels each:
#   each of the 4 guest levels needs its address translated by 4 host levels,
#   plus the final access: (4+1) * (4+1) - 1 = 24 memory references

TLB misses are therefore more expensive in a VM, which is why huge pages matter even more there. Devices are usually presented as paravirtualized virtio devices, where the guest knows it's virtual and uses an efficient shared-memory queue instead of emulating a real network card instruction by instruction.

Connection to earlier lessons Nested paging is Stage 2.3's page table walk done twice, and huge pages from Stage 3.2 reduce its cost. VMs and containers solve different problems: a VM virtualizes hardware, a container virtualizes the OS view.

§4Common Mistakes

Practice
  1. Check whether your CPU supports VT-x/AMD-V, and whether /dev/kvm exists.
  2. Explain why a 2D page walk can need 24 memory references, and how a TLB hit avoids all of them.
Key takeaways
  • Hypervisors use trap-and-emulate, made efficient by hardware modes that cause VM exits only for sensitive operations.
  • Nested paging translates guest-virtual to guest-physical to host-physical, making TLB misses costlier.
  • Virtio devices and passthrough reduce I/O overhead; VMs isolate more strongly than containers.
