What Is a Process

A process is a running program plus everything the OS tracks about it: its memory, its registers, and its open resources.

§1Program vs. Process

A program is a file on disk: instructions and data, doing nothing. A process is that program in execution. You can start the same program three times and get three separate processes, each with its own state.

# One program, two processes with different PIDs
sleep 100 &
sleep 100 &
ps -o pid,ppid,comm -C sleep

Every process has a PID (process ID) and a PPID (its parent's PID). The parent/child links form the process tree you saw rooted at PID 1.

§2What a Process Owns

  • Address space: code, data, heap, and stack, private to this process
  • CPU state: program counter, stack pointer, and general registers
  • Open resources: the file descriptor table, current directory, and environment
  • Identity and permissions: PID, user ID, group ID
  • Scheduling info: priority and accumulated CPU time

The program counter holds the address of the next instruction. The stack pointer marks the top of the stack. When the OS pauses a process, it must save these so the process can later resume as if nothing happened.

§3The Process Control Block

The kernel keeps a record for each process called the process control block (PCB). On Linux it's a structure called task_struct. It holds the state, PID, saved registers, pointers to the memory map and open-file table, and the parent and children.

# Kernel-maintained view of one process
cat /proc/self/status | head -8
ls -l /proc/self/fd
cat /proc/self/maps | head -5
The key insight Isolation comes from ownership. Because each process has its own address space and descriptor table, one process's bug can't directly corrupt another's data.

§4Common Mistakes

MistakeWhat HappensFix
Using 'program' and 'process' interchangeablyConfusion about why two runs of one program don't share variablesProgram = file on disk, process = running instance with its own state
Assuming a PID is permanentPIDs get recycled after a process exitsNever store a PID long-term without checking the process still exists and is the one you meant
Thinking a child shares its parent's memoryExpecting writes in the child to appear in the parentEach process has a private address space; sharing needs explicit IPC
Practice
  1. Open /proc/self/status and find the PID, PPID, and memory usage lines. What does each one mean?
  2. Start two copies of the same program. List what is identical and what differs between them.
Key takeaways
  • A process is a program in execution with its own memory, CPU state, and resources.
  • The PCB is the kernel's record of everything it needs to pause and resume a process.
  • Processes are isolated because each owns a private address space.
