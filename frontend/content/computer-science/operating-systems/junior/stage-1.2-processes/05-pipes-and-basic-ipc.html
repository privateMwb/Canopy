Pipes & Basic IPC

Processes are isolated by design, so they need explicit channels to talk, and the pipe is the simplest one.

§1Why IPC Exists

Since each process has a private address space, one can't just read another's variables. Inter-process communication (IPC) mechanisms are the kernel-approved ways to pass data across that wall. Pipes, signals, sockets, shared memory, and message queues are all IPC.

A pipe is a kernel buffer with two ends: bytes written to the write end come out the read end, in order.

§2Creating and Using a Pipe

pipe() returns two file descriptors: fds[0] for reading and fds[1] for writing. Because fork copies descriptors, a parent and child can share a pipe.

int fds[2];
pipe(fds);

if (fork() == 0) {
    close(fds[0]);                 // child only writes
    write(fds[1], "hi parent", 9);
    _exit(0);
}
close(fds[1]);                     // parent only reads
char buf[32];
ssize_t n = read(fds[0], buf, sizeof buf);
write(1, buf, n);
wait(NULL);

Closing the unused ends matters. A reader only sees end-of-file once every write end is closed; a stray open write end means read blocks forever.

§3Redirecting with dup2: How Shells Build a | b

dup2(old, new) makes descriptor new refer to the same thing as old. To run ls | wc -l, the shell creates a pipe, forks twice, and in each child rewires stdout or stdin to the pipe before calling exec.

// In the child that will run ls:
dup2(fds[1], 1);   // stdout now goes into the pipe
close(fds[0]);
close(fds[1]);
execlp("ls", "ls", NULL);

// In the child that will run wc -l:
dup2(fds[0], 0);   // stdin now comes from the pipe
close(fds[0]);
close(fds[1]);
execlp("wc", "wc", "-l", NULL);

Neither ls nor wc knows a pipe exists. They just read fd 0 and write fd 1, which is why small tools combine so well.

Gotcha Pipes have a fixed capacity (64 KiB by default on Linux). A writer to a full pipe blocks until a reader drains it, so a program that writes forever while nobody reads will hang.

§4Common Mistakes

MistakeWhat HappensFix
Leaving extra pipe ends openread never returns end-of-file and the program hangsClose every unused end in every process, including after dup2
Assuming one write equals one readPipes are byte streams with no message boundariesUse framing such as lengths or delimiters if you need messages
Writing to a pipe with no readersThe writer receives SIGPIPE and diesHandle SIGPIPE or check for EPIPE
Practice
  1. Write a program where a parent sends a string to a child, and the child prints it in uppercase.
  2. Implement ls | wc -l in C using pipe, fork, dup2, and exec.
Key takeaways
  • A pipe is a kernel buffer with a read end and a write end, shared via fork.
  • Close unused pipe ends or readers will never see end-of-file.
  • Shells build pipelines by wiring dup2 between fork and exec.
