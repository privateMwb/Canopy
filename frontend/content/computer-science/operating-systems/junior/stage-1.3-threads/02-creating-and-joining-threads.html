Creating & Joining Threads

The pthreads API gives you a handful of functions to start a thread, pass it data, and wait for it to finish.

§1Create and Join

pthread_create starts a new thread running a function. pthread_join waits for it to finish and collects its return value, much like wait does for processes.

#include <pthread.h>
#include <stdio.h>

void *work(void *arg) {
    int id = *(int *)arg;
    printf("hello from thread %d\n", id);
    return NULL;
}

int main(void) {
    pthread_t t;
    int id = 1;
    pthread_create(&t, NULL, work, &id);
    pthread_join(t, NULL);   // wait before id goes out of scope
    return 0;
}

Compile with gcc -pthread file.c. A thread's function takes one void * and returns one void *; use a struct to pass more.

§2Passing Arguments Safely

The most common beginner bug is giving every thread a pointer to the same loop variable.

// BUG: all threads may see the final value of i
for (int i = 0; i < 4; i++)
    pthread_create(&t[i], NULL, work, &i);

// FIX: give each thread its own copy
int ids[4];
for (int i = 0; i < 4; i++) {
    ids[i] = i;
    pthread_create(&t[i], NULL, work, &ids[i]);
}
for (int i = 0; i < 4; i++) pthread_join(t[i], NULL);

The thread may not run until after the loop moves on, so it reads whatever i holds by then. Each thread needs data whose lifetime outlasts the call.

§3Return Values and Detaching

A thread can return a pointer through pthread_join. If you never need the result, call pthread_detach so its resources are freed automatically on exit. A thread that is neither joined nor detached leaks its resources, just like an unreaped zombie child.

pthread_t t;
pthread_create(&t, NULL, background_job, NULL);
pthread_detach(t);   // fire and forget: can no longer join

When main returns, the whole process exits and kills every remaining thread. Join the threads you care about first.

Gotcha pthread_create returns an error number directly; it does not set errno. Always check the return value, and remember pthread_join takes the thread handle, not a pointer to it.

§4Common Mistakes

MistakeWhat HappensFix
Passing &i of a loop variable to threadsThreads read a changed or out-of-scope valueGive each thread its own argument slot with a lifetime longer than the thread
Returning a pointer to a local variable from the threadThe pointer dangles once the thread's stack is goneReturn heap-allocated data or write results into caller-owned memory
Letting main exit while threads runWork is cut off mid-wayJoin all threads you depend on before returning
Practice
  1. Start four threads that each compute the sum of one quarter of a large array, then join them and add the partial sums.
  2. Reproduce the loop-variable bug on purpose, then fix it. Print each thread's received ID to show the difference.
Key takeaways
  • Use pthread_create to start and pthread_join to wait for a thread.
  • Give each thread an argument that outlives the call that created it.
  • Join or detach every thread; main returning ends the whole process.
