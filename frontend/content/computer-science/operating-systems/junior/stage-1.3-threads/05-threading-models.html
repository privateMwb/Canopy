Threading Models

Threads can be managed by the kernel, by a library in user space, or by a mix, and each choice changes what blocking and parallelism mean.

§1Kernel Threads and User Threads

A kernel-level thread is known to the OS: the scheduler sees it and can run it on any core. A user-level thread is managed entirely by a library; the kernel sees only one thread for the whole process.

PropertyKernel threadUser-level thread
Scheduled byThe OSA user-space library
Uses multiple coresYesNo, unless mapped to kernel threads
Switch costNeeds a kernel entryVery cheap, no syscall
One blocks on I/OOthers keep runningMay block the whole process

§2Mapping Models

  • Many-to-one: many user threads share one kernel thread. Cheap, but no parallelism, and one blocking call stalls all.
  • One-to-one: each user thread gets its own kernel thread. This is what Linux pthreads and Windows use.
  • Many-to-many: a pool of kernel threads runs a larger set of user threads. Flexible, but complex; Go's runtime works this way.

Today, most mainstream systems use one-to-one because it's simple and uses all cores. Languages that need millions of cheap tasks layer their own scheduler on top.

§3Seeing It on Your System

# Each pthread appears as its own kernel-visible task
ps -eLf | head
getconf GNU_LIBPTHREAD_VERSION

When you create 1,000 pthreads on Linux, you get 1,000 kernel threads, each with its own stack (commonly 8 MB of reserved virtual address space by default). That's why a thread per connection stops scaling at very large counts.

Connection to later lessons The limits of one-to-one threading are what motivate thread pools and event-driven I/O in Stage 3.1, and green threads and coroutines are a many-to-many design.

§4Common Mistakes

MistakeWhat HappensFix
Assuming every thread library uses kernel threadsExpecting parallel speedup from a many-to-one libraryCheck how the runtime maps threads to cores
Creating a thread per task for huge task countsMemory and scheduling overhead explodeReuse a bounded pool of threads
Blocking a many-to-one thread on a system callThe whole process stallsUse non-blocking I/O or a one-to-one mapping
Practice
  1. Create 100 threads that sleep, and use ps -eLf to confirm the kernel sees 100 tasks.
  2. Explain why a many-to-one model can't speed up a CPU-bound computation on a four-core machine.
Key takeaways
  • Kernel threads are scheduled by the OS and can run in parallel on multiple cores.
  • User-level threads are cheap but limited unless they map onto kernel threads.
  • One-to-one is the common default; pools and event loops handle very large concurrency.
