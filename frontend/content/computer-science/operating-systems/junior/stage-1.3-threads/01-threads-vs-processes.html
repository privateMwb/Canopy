Threads vs. Processes

Threads are separate flows of execution inside one process, sharing its memory, which makes them cheap to coordinate and easy to get wrong.

§1What Threads Share and Keep

A process can contain multiple threads. All threads in a process share the same address space, heap, global variables, and open file descriptors. Each thread has its own stack, its own registers (including the program counter), and its own thread ID.

Per process (shared)Per thread (private)
Code and global dataStack and local variables
HeapRegisters and program counter
Open file descriptorsThread ID and scheduling state
Process ID and permissionserrno value (thread-local)

§2Why Use Threads

Creating a thread is cheaper than creating a process, and switching between threads of one process avoids switching address spaces. Because memory is shared, threads can exchange data by simply reading and writing variables, with no pipe or copy.

# Linux: threads show up as lightweight tasks inside one process
ps -T -p $(pgrep -n firefox)    # each row is a thread (SPID)
ls /proc/self/task

Typical reasons: use several cores for one computation, keep a UI responsive while work runs in the background, or overlap waiting on I/O with other work.

§3The Tradeoff

Sharing memory is both the benefit and the hazard. One thread's wild write can corrupt data every other thread uses, and a crash in any thread takes down the whole process. Separate processes give strong isolation; threads give speed and convenience.

Creation costHigherLower

The key insight Threads don't make shared data safe; they make sharing the default. Every lesson in this stage is about handling that default responsibly.

§4Common Mistakes

MistakeWhat HappensFix
Assuming threads are always fasterContention and locking can make threaded code slower than single-threaded codeMeasure; use threads when work is parallel or overlaps waiting
Sharing stack addresses between threadsPointers to a finished thread's stack danglePass heap data or data that outlives the thread
Using threads where isolation mattersA bug in one component brings everything downUse separate processes for untrusted or crash-prone work
Practice
  1. List five resources shared between two threads of one process and three that are private to each thread.
  2. For a web browser tab, argue whether it should be a thread or a process, and what you'd lose with the other choice.
Key takeaways
  • Threads share memory and descriptors, but each has its own stack and registers.
  • Threads are cheaper to create and coordinate than processes.
  • Shared memory is both the speedup and the source of bugs.
