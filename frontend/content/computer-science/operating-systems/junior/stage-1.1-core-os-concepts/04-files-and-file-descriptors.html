Files & File Descriptors

In Unix, a file descriptor is a small integer that names an open file, pipe, socket, or device, and that single idea makes input and output uniform.

§1Everything Is a File

Unix gives files, terminals, pipes, sockets, and many devices the same interface: open, read, write, close. A program that reads bytes from a file can read bytes from a pipe or a network socket with the same code.

When you open something, the kernel creates an entry in an open-file table and returns a small non-negative integer, the file descriptor (fd). That integer is just an index into a per-process table; all real state lives in the kernel.

§2The Three Standard Descriptors

fdNameDefault target
0stdinKeyboard / terminal input
1stdoutTerminal output
2stderrTerminal output (for errors)

Every process starts with these three open, inherited from its parent. A new open returns the lowest unused descriptor, so the first file you open normally gets fd 3.

#include <fcntl.h>
#include <unistd.h>

int main(void) {
    int fd = open("data.txt", O_RDONLY);   // likely returns 3
    if (fd < 0) return 1;

    char buf[128];
    ssize_t n = read(fd, buf, sizeof buf);  // bytes actually read
    write(1, buf, n);                       // copy to stdout
    close(fd);                              // always release it
    return 0;
}

§3Redirection Is Just Swapping Descriptors

When a shell runs ls > out.txt, it opens out.txt and arranges for fd 1 to point at it before running ls. The ls program writes to fd 1 as usual and never knows the difference. The same trick connects programs with pipes, which you'll build in Stage 1.2.

ls > files.txt          # stdout -> file
ls nosuchdir 2> err.txt # stderr -> file
sort < files.txt        # stdin  <- file
ls 2>&1 | wc -l         # stderr joined to stdout, then piped
Gotcha Descriptors are a finite resource, typically 1,024 per process by default. A long-running program that opens files without closing them eventually fails with EMFILE: Too many open files.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting to close a descriptorDescriptor leak; eventually open failsClose every fd you open, or wrap it in a cleanup path
Assuming read returns the full requested countTruncated data and silent bugsread may return fewer bytes; loop until you have what you need or get 0 (end of file)
Writing errors to stdoutError text lands in the data stream and pollutes pipesSend diagnostics to fd 2 (stderr)
Practice
  1. Write a C program that copies one file to another using only open, read, write, and close.
  2. In a shell, explain the difference between cmd > out 2>&1 and cmd 2>&1 > out. Run both and compare.
Key takeaways
  • A file descriptor is an integer index into a per-process table of kernel-managed open files.
  • Files, pipes, sockets, and terminals share one read/write interface.
  • Redirection works by changing what fds 0, 1, and 2 point to before the program runs.
