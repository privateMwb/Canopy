Paging & Page Tables

Paging chops memory into fixed-size pages, and a page table says which physical frame each virtual page currently occupies.

§1Pages and Frames

Virtual memory is divided into pages and physical memory into frames of the same size, typically 4 KiB. Any page can go in any frame, so physical memory never needs to be contiguous and external fragmentation disappears.

A virtual address splits into two parts: the virtual page number (VPN), which selects the page, and the offset, the byte within it. With 4 KiB pages, the low 12 bits are the offset, because 2^12 = 4096.

§2Translating an Address by Hand

Suppose the page table maps virtual page 0 to frame 5 and virtual page 1 to frame 9. Translate virtual address 0x1A3C:

0x1A3C  =  0001 1010 0011 1100
offset  =  low 12 bits  =  0xA3C
VPN     =  remaining    =  0x1   (page 1)

page table[1] -> frame 9
physical = (frame 9 * 0x1000) + 0xA3C = 0x9000 + 0xA3C = 0x9A3C

The offset is unchanged by translation. Only the page number is replaced by a frame number.

§3What's in a Page Table Entry

FieldPurpose
Frame numberWhere the page lives in physical memory
Present bitIs the page in RAM right now? If 0, access causes a page fault
Read/write bitWrites to a read-only page cause a fault
User/supervisor bitWhether user-mode code may access it
Accessed bitSet by hardware on any access, used by replacement policies
Dirty bitSet by hardware on a write, so the OS knows the page must be saved before eviction
No-execute bitMarks data pages as non-executable

The Present, Accessed, and Dirty bits are the hardware's way of giving the OS the information it needs to manage memory without trapping on every access.

§4The Size Problem

A single flat table has one entry per virtual page. A 32-bit address space with 4 KiB pages has 2^20 pages, which at 4 bytes per entry is 4 MB per process, even if the process uses little memory. A 64-bit space makes a flat table impossible. The next lesson shows how real systems solve this.

# Page size on your system
getconf PAGESIZE     # usually 4096
The key insight Translation changes the page number and keeps the offset. Everything else about paging, from page tables to TLBs, is about doing that substitution quickly and storing the mapping compactly.

Practice

  2. How big is a flat page table for a 36-bit address space with 4 KiB pages and 4-byte entries?
Key takeaways
  • A virtual address is a page number plus an offset; translation replaces only the page number.
  • Page table entries hold the frame number plus present, permission, accessed, and dirty bits.
  • A flat page table is too large, which motivates multi-level tables.
