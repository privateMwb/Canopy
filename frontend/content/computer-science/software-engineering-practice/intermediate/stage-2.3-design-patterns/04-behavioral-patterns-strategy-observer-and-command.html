Behavioral Patterns: Strategy, Observer & Command

Behavioral patterns describe how objects share work and communicate. Three of them, Strategy, Observer, and Command, show up almost everywhere.

§1Strategy: Swap the Algorithm

A strategy pulls a varying piece of behavior out into a replaceable part, so you choose it at runtime instead of branching. In languages with first-class functions, the strategy is simply a function you pass in.

def price_with(strategy, base):
    return strategy(base)

regular   = lambda p: p
black_fri = lambda p: p * 0.7
member    = lambda p: p * 0.9

price_with(black_fri, 100)      # 70.0
price_with(member, 100)         # 90.0; no if/elif on customer type

§2Observer: Tell Whoever Cares

An observer (also called publish/subscribe) lets one object announce that something happened without knowing who is listening. Subscribers can be added or removed freely, so the publisher stays decoupled.

class OrderEvents:
    def __init__(self): self._listeners = []
    def subscribe(self, fn): self._listeners.append(fn)
    def publish(self, order):
        for fn in self._listeners: fn(order)

events = OrderEvents()
events.subscribe(send_confirmation_email)
events.subscribe(update_inventory)
events.subscribe(record_analytics)
events.publish(order)         # the order code knows none of them

The cost is that control flow becomes harder to follow: what happens when an order is placed is no longer in one place. Use it where decoupling is worth that price, and log events so you can trace them.

§3Command: Make an Action an Object

A command turns a request into an object, which means you can queue it, log it, retry it, or undo it later.

class RenameFile:
    def __init__(self, old, new): self.old, self.new = old, new
    def do(self):   os.rename(self.old, self.new)
    def undo(self): os.rename(self.new, self.old)

history = []
cmd = RenameFile("a.txt", "b.txt"); cmd.do(); history.append(cmd)
history.pop().undo()           # undo stack for free

Undo stacks, job queues, and macro recording are all commands under the hood.

The key insight All three patterns pull something variable out of a fixed flow: which algorithm (Strategy), who is notified (Observer), what action (Command).

§4Common Mistakes

MistakeWhat HappensFix
A Strategy class for a one-line functionBoilerplate for nothingPass a function where the language allows
Observers that call each other in a chainHard-to-trace control flow and surprising loopsKeep handlers independent and log published events
Forgetting to unsubscribe listenersMemory leaks and handlers firing on dead objectsProvide unsubscribe and clean up on shutdown
Practice
  1. Replace a chain of if customer_type == pricing branches with strategies.
  2. Add an event publisher to a class and subscribe two independent reactions.
  3. Implement undo for two operations using the command pattern.
Key takeaways
  • Strategy swaps an algorithm, often just by passing a function.
  • Observer decouples a publisher from its listeners.
  • Command makes actions into objects you can queue, log, and undo.
