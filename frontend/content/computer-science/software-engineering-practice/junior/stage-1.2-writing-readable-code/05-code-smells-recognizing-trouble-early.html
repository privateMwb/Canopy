Code Smells: Recognizing Trouble Early

A code smell is a surface sign that something deeper may be wrong. Learning to spot a few common ones teaches you where to look.

§1What a Smell Is

A smell is not a bug. The code works. It is a hint that the design is straining and will be painful to change. Smells are prompts to look closer, not rules that code must never break.

SmellWhat it looks likeUsual cure
Long functionDozens of lines, many levels of nestingExtract smaller named functions
Long parameter listFive or more arguments, often passed togetherGroup them into an object
Magic numbersif status == 3: or * 86400Named constants or enums
Duplicate codeThe same block pasted in several placesExtract, once the pattern is clear
Feature envyA method that mostly uses another object's dataMove it to that object
Deep nestingif inside if inside for inside ifGuard clauses, early return, extraction

§2Two Smells in Detail

Magic numbers hide meaning and scatter facts. Naming them fixes both.

# smell
if user.status == 3 and elapsed > 86400:
    ...

# cure
class Status: SUSPENDED = 3
SECONDS_PER_DAY = 86400
if user.status == Status.SUSPENDED and elapsed > SECONDS_PER_DAY:
    ...

Deep nesting makes control flow hard to follow. Guard clauses handle the unusual cases first and return early, leaving the main path flat.

# nested
def ship(order):
    if order.paid:
        if order.in_stock:
            if order.address:
                return send(order)
    return None

# flat: guard clauses
def ship(order):
    if not order.paid:     return None
    if not order.in_stock: return None
    if not order.address:  return None
    return send(order)

§3What to Do With a Smell

Smells guide refactoring, but don't fix every one on sight. Fix the ones in code you are about to change, and leave stable, untouched code alone. Always have a test before restructuring, so you know behavior didn't move.

Treat a smell as a question: why is this awkward? Often the answer shows a missing concept, such as the object that feature envy points to.

The key insight A smell is a reason to look, not an order to rewrite. Judge by whether the code is in your way, not by whether it is pretty.

§4Common Mistakes

MistakeWhat HappensFix
Rewriting everything that smellsRisky changes in code nobody needed to touchClean up the area you're working in, with tests
Ignoring smells completelySmall awkwardnesses compound into code nobody wants to editSpend a few minutes tidying as you go
Fixing a smell with no testBehavior changes silently during the cleanupWrite or confirm a test first, then restructure
Practice
  1. Scan a file for magic numbers and name five of them.
  2. Flatten a deeply nested function with guard clauses.
  3. Find one case of feature envy and move the method to where the data lives.
Key takeaways
  • Smells are hints that a design is straining, not bugs.
  • Learn the common ones: long functions, long parameter lists, magic numbers, nesting, feature envy.
  • Refactor smells you're touching anyway, and always under a test.
