curriculum / software engineering practice

From your first unit test to leading how a codebase evolves

Three levels, twelve stages — testing, version control, and design, built toward the judgment to refactor safely, choose when a pattern helps, and explain tradeoffs to the people who live with the code.

Checkpoints are deliberately unscaffolded. If you can finish one without hints, the stage actually landed, not just the following-along.

This track builds on the others instead of repeating them. Commits, branches, merge versus rebase, pull requests, undoing mistakes, and running tests in a CI pipeline are taught in Linux & DevOps; arrays, trees, and the structures underneath your code in Data Structures & Algorithms; reviewing code for vulnerabilities in Security. This track picks each of them up where it left off: how Git actually stores history, how a team shapes it, what a test suite should contain, and how code is designed to be changed.

Levels aren't strict walls. Code review appears at Junior as receiving feedback, returns at Intermediate as writing it, and comes back at Senior as setting a team's standards. Testing follows the same arc, from a single assertion to a suite strategy to testing in production. Revisiting a topic at a harder level is expected.

Senior is about judgment as much as technique. Knowing how to refactor, and deciding whether this system deserves a refactor, a rewrite, or to be left alone, are different skills, and the last stage is built around explaining that decision to the people who have to approve it.
