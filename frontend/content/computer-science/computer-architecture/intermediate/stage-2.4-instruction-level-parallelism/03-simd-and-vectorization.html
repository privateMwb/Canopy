SIMD & Vectorization

SIMD instructions apply one operation to many data elements at once, and getting your loops to use them is often the largest single speedup available on a modern core.

§1Wide Registers, Many Lanes

SIMD (single instruction, multiple data) uses wide registers divided into lanes, and one instruction operates on all lanes together. An AVX2 register holds 256 bits: eight 32-bit floats, so one add performs eight additions.

#include <immintrin.h>
void add(const float *a, const float *b, float *c, int n) {
    int i = 0;
    for (; i + 8 <= n; i += 8) {
        __m256 x = _mm256_loadu_ps(a + i);      // load 8 floats
        __m256 y = _mm256_loadu_ps(b + i);
        _mm256_storeu_ps(c + i, _mm256_add_ps(x, y));   // 8 adds in one instruction
    }
    for (; i < n; i++) c[i] = a[i] + b[i];     // leftover elements
}

In the best case, SIMD multiplies throughput by the lane count. In practice, the gain is limited by memory bandwidth, since a loop that streams through large arrays may already be bandwidth-bound in scalar form.

§2Auto-Vectorization

You rarely need to write intrinsics. At -O3 (and increasingly at -O2), compilers vectorize simple loops automatically. You can ask them what they did.

gcc -O3 -march=native -fopt-info-vec-optimized -c loop.c     # which loops were vectorized
gcc -O3 -march=native -fopt-info-vec-missed    -c loop.c     # why others were not
  • Aliasing: if the compiler can't prove a and b don't overlap, it may refuse to vectorize. Use restrict on pointers that don't alias
  • Loop-carried dependencies: if iteration i needs the result of iteration i−1, lanes can't run in parallel
  • Floating-point reductions: summing in a different order changes rounding, so it needs -ffast-math or explicit permission
  • Non-contiguous access: strided or indexed loads (gathers) are slow or unsupported
  • Control flow and function calls inside the loop can block vectorization, although masks can handle simple conditionals
void scale(float *restrict out, const float *restrict in, float k, int n) {
    for (int i = 0; i < n; i++) out[i] = in[i] * k;     // restrict: no aliasing, easily vectorized
}

§3Portability and Practical Notes

  • -march=native generates code for your current CPU, and the binary may crash with an illegal instruction on older machines. For distribution, target a baseline, or use runtime dispatch that picks an implementation after checking CPU features
  • Data should be contiguous and tightly packed, which connects back to data layout: a struct-of-arrays layout vectorizes far better than an array of structs
  • Wide vectors can raise power and, on some CPUs (notably older AVX-512 implementations), lower the clock
  • Libraries such as BLAS, memcpy, and compression and hashing code already contain tuned SIMD paths, and using them beats hand-written loops
grep -o -w -E 'avx2|avx512f|sse4_2|neon' /proc/cpuinfo | sort -u     # what your CPU supports
The key insight SIMD rewards data that's contiguous, aligned in a loop, and free of dependencies. The best way to get it is to write simple loops over simple arrays, and then check that the compiler used it.

§4Common Mistakes

MistakeWhat HappensFix
Passing aliasing pointers without restrictThe compiler assumes overlap and stays scalarAdd restrict where it is true, and verify with -fopt-info
Shipping -march=native binaries to other machinesIllegal instruction crashes on older CPUsBuild for a baseline, or dispatch at runtime
Using an array of structs for vectorizable fieldsLanes would need gathers across structsStore each field in its own array (struct of arrays)
Practice
  1. Write a loop that scales an array, compile it at -O3 with -fopt-info-vec, and confirm it vectorized. Then add an aliasing hazard and observe the change.
  2. Compare the throughput of a scalar loop, an auto-vectorized loop, and the intrinsics version above on a 1,000-element array that fits in L1.
Key takeaways
  • SIMD instructions process many lanes at once, such as eight floats per AVX2 op.
  • Compilers auto-vectorize simple loops, and aliasing, dependencies, and reductions can block it.
  • Check -fopt-info output, and be careful about -march=native portability.
