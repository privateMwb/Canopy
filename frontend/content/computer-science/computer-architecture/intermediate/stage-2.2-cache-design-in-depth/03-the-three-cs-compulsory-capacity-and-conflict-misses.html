The Three Cs: Compulsory, Capacity & Conflict Misses

Not all misses are alike, and sorting them by cause tells you which remedy, a bigger cache, more associativity, or different code, will actually help.

§1Three Causes of Misses

TypeCauseTypical remedy
Compulsory (cold)First ever access to a linePrefetching; larger lines; unavoidable otherwise
CapacityThe working set is bigger than the cacheA larger cache; smaller working set; blocking/tiling
ConflictToo many lines map to the same setMore associativity; change the layout or stride

Multicore systems add a fourth, coherence misses, caused by another core invalidating a line, covered in the senior stage.

§2Telling Them Apart

A way to classify misses in a simulator is to compare against idealized caches.

  • Count the first accesses to each line: those are compulsory misses
  • Simulate a fully associative cache of the same size. Misses beyond the compulsory ones are capacity misses
  • The extra misses in the real set-associative cache, beyond the fully associative case, are conflict misses

This is why a 2× bigger cache doesn't always help: if the misses are conflicts from a bad stride, it won't, while doubling the associativity or padding the data will.

§3Matching the Remedy to the Cause

Consider walking down a column of a 1024 × 1024 int matrix, so each row is 4096 bytes.

# Column walk, rows 4096 B apart, in a 32 KiB 8-way L1 (64 sets):
# every row maps to the same set -> conflict misses even though only 64 lines are touched.

// Fix 1: pad each row to break the alignment (1024+16 ints = 4160 bytes)
int a[1024][1024 + 16];

// Fix 2: change the loop order or tile it so that fewer rows are live at once

A big streaming scan, in contrast, is mostly compulsory misses with perhaps some capacity misses, and the remedy is the prefetcher, not associativity.

# On Linux, see which level is missing, then reason about the type
perf stat -e L1-dcache-load-misses,l2_rqsts.miss,LLC-load-misses ./prog
# (event names vary by CPU; list them with perf list)

Diagnosing the type first avoids wasted work. Buying more memory or rewriting an algorithm won't fix a conflict miss pattern that a one-line padding change would.

The key insight Ask 'why is it missing?' before 'how do I make it miss less?'. Compulsory, capacity, and conflict misses each respond to different fixes.

§4Common Mistakes

MistakeWhat HappensFix
Adding a bigger cache to cure conflict missesThe same set still overflowsChange the layout or stride, or raise associativity
Treating all misses as capacity problemsShrinking the working set doesn't help a stride conflictClassify misses before choosing a fix
Trying to remove compulsory misses with cachingThey happen on first access by definitionUse prefetching to hide, not remove, them
Practice
  1. Sketch a loop that suffers mainly capacity misses and one that suffers mainly conflict misses. For each, suggest one remedy.
  2. Extend a cache simulator to report compulsory, capacity, and conflict miss counts separately.
Key takeaways
  • Misses are compulsory, capacity, or conflict, and coherence adds a fourth type on multicore.
  • Classify by comparing with a fully associative cache of the same size.
  • Padding or changing strides cures conflicts; tiling cures capacity; prefetching hides compulsory misses.
