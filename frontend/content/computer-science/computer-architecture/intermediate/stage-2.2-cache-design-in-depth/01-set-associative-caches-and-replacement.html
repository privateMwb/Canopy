Set-Associative Caches & Replacement

A cache decides where a line may live using a few bits of its address, and the associativity of that rule determines how many lines can collide.

§1Splitting an Address

To look up a line, the cache splits the memory address into three fields: the offset picks the byte within a line, the index picks a set, and the tag is stored to identify which line occupies a slot.

|        tag        |  index  | offset |
 high bits          middle   low bits

# 32 KiB cache, 64-byte lines, 8-way set-associative:
lines   = 32768 / 64    = 512
sets    = 512 / 8       = 64
offset  = log2(64)      = 6 bits
index   = log2(64 sets) = 6 bits
tag     = the remaining address bits (36 bits for a 48-bit address)

On a lookup, the index selects a set, and the cache compares the tag against all the lines (ways) in that set in parallel. A match is a hit.

§2A Worked Example

Take address 0x1A2B3C with the cache above.

0x1A2B3C = ... 0010 1011 0011 1100  (low 16 bits 0x2B3C; low 12 bits are 0xB3C)

offset = low 6 bits  of 0xB3C = 111100   = 60
index  = next 6 bits (bits 11..6) = 101100 = 44
tag    = the rest = 0x1A2

# This address maps to set 44. It can occupy any of the 8 ways in that set.
OrganizationWaysBehavior
Direct-mapped1Each line has exactly one possible slot. Fast and simple, but prone to conflicts
N-way set-associativeNA line may sit in any of N slots in its set. Common: 4 to 16 ways
Fully associativeAll linesAny line can go anywhere. Flexible, but costly to search; used for small structures like TLBs

§3Replacement and the Power-of-Two Trap

When a set is full and a new line arrives, a replacement policy picks a victim. LRU (least recently used) evicts the line unused for longest, and tracking it exactly gets expensive as ways increase. Real caches use cheaper approximations such as pseudo-LRU, tree-based or bit-based, or even random replacement.

Because the index comes from fixed address bits, addresses spaced a power-of-two apart can all land in the same set. With 64 sets of 64-byte lines, any stride of 4096 bytes maps every access to one set.

// Walking a column of a matrix whose rows are 4096 bytes long (1024 ints):
for (int i = 0; i < 64; i++)
    s += a[i][0];             // every a[i][0] is 4096 bytes apart: all in set 0
// Only 8 ways in that set, so most of these 64 lines keep evicting each other.

The fix is to break the stride, for instance by padding each row by one cache line, so consecutive rows map to different sets.

The key insight Associativity trades hardware cost against conflict misses. Past about 8 ways the returns diminish, but a pathological stride can still defeat any cache by hammering a single set.

§4Common Mistakes

MistakeWhat HappensFix
Using power-of-two row lengths for large matricesConflict misses from many rows mapping to the same setsPad rows, such as to a size not divisible by the set-mapping period
Mixing up index and offset bitsWrong set computationsOffset = within-line bits; index = set-select bits above them
Assuming the cache is fully associativeUnderestimating conflict missesUse the real ways and set count for the level you target
Practice
  1. For a 64 KiB, 4-way cache with 64-byte lines, compute the number of sets and the index and offset widths.
  2. Compute the offset, index, and tag for address 0x0004_2C80 using the 32 KiB, 8-way cache above.
Key takeaways
  • An address splits into tag, index, and offset, and the index selects a set.
  • Associativity sets how many lines per set can coexist; direct-mapped has one, fully associative has all.
  • Power-of-two strides can pile accesses into one set, causing conflict misses.
