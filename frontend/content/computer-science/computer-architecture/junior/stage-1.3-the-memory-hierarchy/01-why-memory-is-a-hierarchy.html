Why Memory Is a Hierarchy

Fast memory is small and expensive, big memory is slow and cheap, so computers layer several kinds, and the gaps between layers are enormous.

§1The Speed and Size Tradeoff

No single technology is fast, large, and cheap at once. Registers and caches use fast but bulky SRAM cells placed right next to the cores. Main memory uses denser, slower DRAM. Storage uses flash or magnetic disks. A computer stacks them so that the most-used data sits in the fastest layer.

These are rough figures for recent desktop and server hardware, and exact numbers vary by chip, but the ratios hold. Each step down is typically 3 to 100 times slower and larger.

§2Making the Gap Feel Real

Scale time so that one CPU cycle is one second. A register access takes a second, an L1 hit a few seconds, a DRAM access about four minutes, an SSD read under two days, and a hard-disk seek about nine months.

1 cycle              =  1 second
L1 hit    (4 cycles)  =  4 seconds
DRAM      (240 cycles) =  4 minutes
SSD read  (150,000)    =  1.7 days
HDD seek  (24 million) =  9 months

A CPU that waits on DRAM for every access would spend almost all its time idle. The hierarchy exists to hide this gap, and it works because programs reuse data, as the next lesson explains.

§3Seeing Your Own Hierarchy

lscpu | grep -i -E 'cache|model name'      # L1d, L1i, L2, L3 sizes
lscpu -C                                    # cache details per level
getconf -a | grep -i CACHE                  # line size, associativity
cat /sys/devices/system/cpu/cpu0/cache/index0/size

Note that L1 is split into an instruction cache and a data cache, while L2 and L3 hold both. L1 and L2 are usually private to each core, and L3 is shared across the cores of a chip.

The key insight The memory hierarchy is the central fact of modern performance. Arithmetic is cheap; fetching the operands is what costs, and a program's speed is largely decided by which level its data lives in.

§4Common Mistakes

MistakeWhat HappensFix
Treating all memory accesses as equal costOptimizing instruction count while ignoring cache missesCount where data comes from, not only how much work is done
Mixing up size and speed rankingsExpecting a bigger cache to be fasterBigger levels are slower; that is the tradeoff
Assuming DRAM speed has kept up with CPUsMemory latency has improved far less than computeDesign for locality instead of hoping for faster RAM
Practice
  1. Run lscpu and fill in a table of the cache sizes of your machine. Which are private to a core and which are shared?
  2. Estimate how many cycles a 4 GHz CPU spends on a single 80 ns DRAM access.
Key takeaways
  • Memory is layered because speed, size, and cost trade off against each other.
  • Each level is roughly 3 to 100 times slower and larger, and DRAM costs hundreds of cycles.
  • L1 is split into instruction and data caches, with L2 private and L3 usually shared.
