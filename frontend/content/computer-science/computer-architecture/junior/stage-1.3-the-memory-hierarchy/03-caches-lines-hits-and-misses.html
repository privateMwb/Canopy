Caches: Lines, Hits & Misses

A cache keeps copies of recently used memory in fast storage, and its effectiveness is summarized by a hit rate and the average memory access time it produces.

§1Cache Lines

A cache doesn't store individual bytes; it stores lines (also called blocks), typically 64 bytes, aligned to 64-byte boundaries. When the CPU reads a byte that isn't cached, the whole 64-byte line containing it is fetched from the next level. So reading one int also brings in the 15 neighbors.

# Scanning an int array: 64-byte line = 16 ints
a[0]   -> miss: fetch the line holding a[0]..a[15]
a[1]   -> hit
...
a[15]  -> hit
a[16]  -> miss: fetch the next line
# Miss rate when scanning cold memory = 1/16 = 6.25%, before any prefetching helps.

§2Hits, Misses, and Average Access Time

A hit means the data is in the cache, and a miss means it must come from the next level. The hit rate is the fraction of accesses that hit. The key summary number is average memory access time (AMAT):

AMAT = hit time + miss rate * miss penalty

# L1: 1 ns hit, 5% miss rate, 80 ns to DRAM
AMAT = 1 + 0.05 * 80 = 5 ns

# Improve the miss rate to 1%:
AMAT = 1 + 0.01 * 80 = 1.8 ns

Notice how sensitive it is. Dropping the miss rate from 5% to 1% cuts the average access time by almost three times. Because the miss penalty is so large, even a few percent of misses dominates the total.

§3What Happens on a Miss

  1. The CPU requests an address, and the cache checks whether the line is present
  2. On a miss, the request goes to the next level (L2, L3, or DRAM)
  3. The line returns and is stored in the cache, possibly evicting another line
  4. The requested data goes to the CPU, and later accesses to that line hit

Misses are classified by cause. A compulsory miss is the first access to a line. A capacity miss occurs because the working set doesn't fit. A conflict miss occurs because several lines compete for the same cache location. The next stage of this course goes into each.

# Count real cache behavior of a program on Linux
perf stat -e cache-references,cache-misses,L1-dcache-loads,L1-dcache-load-misses ./prog

While a load is outstanding, an out-of-order core can keep executing independent instructions, hiding part of the penalty, which is why measured slowdowns are often smaller than the raw numbers suggest.

The key insight Because the miss penalty is 50 to 100 times the hit time, a small drop in miss rate buys a large speedup. Programs run well when almost every access hits.

§4Common Mistakes

MistakeWhat HappensFix
Thinking a 95% hit rate is nearly perfectThe 5% misses can still dominate the timeCompute AMAT, since the penalty is so large
Ignoring cache line granularityUsing one byte per 64-byte line wastes bandwidthPack data you use together onto the same line
Assuming a miss always stalls the CPU fullyOut-of-order cores overlap some missesUse measurements to see the real impact
Practice
  1. A cache has a 2 ns hit time, a 4% miss rate, and a 100 ns miss penalty. What is the AMAT? What if the miss rate is 2%?
  2. How many cache misses does a cold scan of a 1 MiB array of 4-byte ints cause, with 64-byte lines?
Key takeaways
  • Caches hold 64-byte lines, so one miss brings in neighboring data.
  • AMAT = hit time + miss rate × miss penalty, and it is very sensitive to the miss rate.
  • Misses are compulsory, capacity, or conflict, and each has different fixes.
