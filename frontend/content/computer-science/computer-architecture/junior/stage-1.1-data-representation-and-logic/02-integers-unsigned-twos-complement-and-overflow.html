Integers: Unsigned, Two's Complement & Overflow

Fixed-width integers wrap around instead of growing, and two's complement is the encoding that makes signed arithmetic work with the same adder.

§1Unsigned and Two's Complement

An unsigned n-bit integer represents 0 to 2^n − 1. To represent negative numbers, nearly all hardware uses two's complement: the top bit has weight −2^(n−1) instead of +2^(n−1).

8-bit patternUnsignedTwo's complement
0000 000000
0111 1111127127
1000 0000128−128
1111 1111255−1

An n-bit signed value ranges from −2^(n−1) to 2^(n−1) − 1, so 8 bits give −128 to 127. The range is asymmetric, with one more negative value than positive.

§2Negating a Number

To negate in two's complement, invert every bit and add 1.

# Negate 5 in 8 bits
5       = 0000 0101
invert  = 1111 1010
add 1   = 1111 1011     # this is -5

# Check: 5 + (-5) should be 0
  0000 0101
+ 1111 1011
= 1 0000 0000           # the carry out of bit 8 is discarded, leaving 0000 0000

The key advantage is that the same adder handles signed and unsigned numbers. Subtraction becomes addition of the negated value, so the hardware needs no separate subtractor. Sign extension widens a signed value by copying its top bit: 1111 1011 (−5 in 8 bits) becomes 1111 1111 1111 1011 in 16 bits, still −5.

§3Overflow

Results that don't fit wrap around. In 8 bits, 127 + 1 produces 1000 0000, which is −128 as a signed number. The CPU sets flags (or, in RISC-V, leaves detection to software) to say whether the result overflowed.

  • Unsigned overflow (carry out of the top bit): 255 + 1 wraps to 0
  • Signed overflow: adding two positives gives a negative, or two negatives gives a positive
  • Rule for signed overflow: it occurs only when both operands have the same sign and the result has a different one
#include <limits.h>
int a = INT_MAX;
a = a + 1;                // signed overflow: undefined behavior in C, so the compiler may assume it never happens

unsigned int u = UINT_MAX;
u = u + 1;                // well defined in C: wraps to 0

Overflow is a real source of security bugs, since a wrapped size calculation can allocate a buffer far smaller than intended. Check for overflow before it happens, or use compiler builtins such as __builtin_add_overflow.

The key insight Fixed-width integers are arithmetic modulo 2^n. Two's complement is simply a choice of which half of that circle you call 'negative'.

§4Common Mistakes

MistakeWhat HappensFix
Assuming signed overflow wraps in CThe compiler can optimize on the assumption it never occurs, producing surprising resultsUse unsigned types or check ranges before arithmetic
Comparing signed and unsigned values−1 converts to a huge unsigned number, so -1 < 1u is falseKeep types consistent, and enable compiler warnings for sign comparison
Forgetting the range asymmetry-INT_MIN overflows, since +2,147,483,648 doesn't fitHandle the minimum value as a special case
Practice
  1. Write −37 and 100 in 8-bit two's complement. Add them, and state whether signed overflow occurred.
  2. Explain why abs(INT_MIN) is a problem in a 32-bit signed integer.
Key takeaways
  • Two's complement gives the top bit a negative weight, so negation is invert-and-add-one.
  • One adder serves signed and unsigned arithmetic.
  • Overflow wraps; signed overflow is undefined behavior in C, so check before computing.
