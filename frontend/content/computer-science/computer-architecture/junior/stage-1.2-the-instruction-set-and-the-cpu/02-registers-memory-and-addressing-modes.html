Registers, Memory & Addressing Modes

Registers are the CPU's few, fast scratch slots, memory is the large, slow store, and addressing modes are the ways an instruction says where an operand lives.

§1The Register File

RISC-V has 32 integer registers, named x0 to x31, each 32 or 64 bits wide depending on the variant. Register x0 always reads as zero, which is handy for comparisons and moves. By convention, registers also have friendlier names for their role.

RegisterABI nameRole
x0zeroConstant 0
x1raReturn address
x2spStack pointer
x10–x17a0–a7Function arguments and return values
x5–x7, x28–x31t0–t6Temporaries (caller saves)
x8–x9, x18–x27s0–s11Saved registers (callee preserves)

Registers are inside the CPU, so reading one costs effectively nothing, usually under one cycle. That's why compilers work hard to keep hot values in registers, and why a function with too many live values 'spills' some to the stack.

§2Load/Store Architecture

In a load/store architecture such as RISC-V and ARM, arithmetic instructions work only on registers. To use memory, you first load a value into a register, and afterward store the result back.

# x = a[2] + 5, where a0 holds the address of an int array
lw   t0, 8(a0)       # load word from address a0 + 8 (a[2], 4 bytes per int)
addi t0, t0, 5       # add the immediate 5
sw   t0, 0(a1)       # store the word at the address in a1

Memory is byte-addressable: every byte has its own address, and a 32-bit word occupies four consecutive addresses. Most ISAs expect aligned accesses, so a word should start at an address divisible by 4.

§3Addressing Modes

An addressing mode is how an instruction specifies an operand. RISC-V keeps it simple, with few modes. x86-64 offers many.

ModeMeaningExample
RegisterThe operand is in a registeradd t0, t1, t2
ImmediateThe value is in the instruction itselfaddi t0, t0, 5
Base + offsetAddress = register + constantlw t0, 8(a0)
Base + index × scale + offset (x86)Address = base + index·scale + constantmov eax, [rdi + rcx*4 + 8]

The x86 form maps directly to array indexing: a[i] for 4-byte elements is [base + i*4], done in a single instruction. RISC-V needs a shift and an add first, which is a tradeoff of simpler hardware against more instructions.

The key insight Registers are tiny but nearly free, while memory is large but costs hundreds of cycles in the worst case. Most performance work comes down to using the registers well and touching memory sensibly.

§4Common Mistakes

MistakeWhat HappensFix
Thinking arithmetic can read memory directly (on load/store ISAs)Instruction sequences look needlessly longRemember: load, operate, store
Using an unaligned addressSlower accesses, or a fault on some CPUsKeep data aligned to its size
Forgetting x0 is always zeroWrites to it are silently discardedUse it as a free zero source and a discard destination
Practice
  1. Write the RISC-V instructions to load a[5] from an int array pointed to by a0 into t1. What offset do you use?
  2. Explain how the x86 instruction mov eax, [rdi + rcx*4] would be expressed in a RISC-V sequence.
Key takeaways
  • RISC-V has 32 registers, with x0 fixed at zero; registers are far faster than memory.
  • Load/store ISAs do arithmetic only on registers, using loads and stores for memory.
  • Addressing modes name operands: register, immediate, base plus offset, and in x86, scaled index.
