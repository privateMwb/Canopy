The Fetch-Decode-Execute Cycle

Every CPU repeats one loop forever: fetch the next instruction from memory, figure out what it asks for, and do it.

§1The Stored-Program Idea

In the von Neumann design, instructions and data live in the same memory. A program is just a sequence of numbers in memory that the CPU reads and carries out. A special register, the program counter (PC), holds the address of the next instruction.

loop forever:
    1. FETCH    instruction = memory[PC]
    2. DECODE   work out the operation and its operands
    3. EXECUTE  do the operation (use the ALU, read or write memory)
    4. UPDATE   PC = PC + 4      # next instruction, or a new address if it was a branch

Instructions are fixed 32-bit words in many ISAs, including RISC-V, so the PC usually advances by 4 bytes. A branch or jump instruction changes the PC to somewhere else, which is how loops and function calls work.

§2An Instruction Is Just Bits

An instruction is a number whose fields select the operation and its operands. In RISC-V, add x5, x6, x7 (set register 5 to registers 6 plus 7) is encoded as:

add x5, x6, x7
 funct7   rs2    rs1   funct3   rd    opcode
0000000  00111  00110   000    00101  0110011
                                       
= 0000 0000 0111 0011 0000 0010 1011 0011 = 0x007302B3

The control unit decodes these fields and sets control signals that route data: which registers feed the ALU, which operation it performs, and where the result goes. 'Decoding' is mostly looking at bit fields and switching multiplexers.

§3The Parts of a Simple CPU

ComponentJob
Program counterHolds the address of the next instruction
Register fileA small set of fast storage slots for operands and results
ALUPerforms arithmetic and logic
Control unitDecodes instructions and drives control signals
Memory interfaceLoads and stores data, and fetches instructions

A clock paces everything. At 3 GHz, the clock ticks three billion times per second, about 0.33 ns per cycle. A simple CPU might finish one instruction per few cycles, and later lessons show how pipelines and multiple units overlap many instructions to complete several per cycle.

The key insight A CPU is a loop that reads numbers from memory and treats them as commands. Everything else in this course is a way of making that loop faster or keeping it fed with data.

§4Common Mistakes

MistakeWhat HappensFix
Picturing the CPU as 'understanding' codeIt only executes encoded instructions one after anotherThink in terms of fields, registers, and the program counter
Forgetting that branches change the PCControl flow seems magicalLoops and calls are PC assignments
Assuming one instruction takes exactly one cycleReal instructions vary in latency, and cores overlap themDistinguish latency (time for one) from throughput (rate of completion)
Practice
  1. Decode the RISC-V instruction word 0x007302B3 back into its fields and registers.
  2. Trace the PC through a three-instruction program that ends with a branch back to the start.
Key takeaways
  • The CPU repeatedly fetches, decodes, executes, and updates the program counter.
  • Instructions are bit patterns that select operations and operands.
  • Branches work by writing a new address into the PC.
