The CPU Performance Equation

Execution time factors into three things, how many instructions run, how many cycles each takes, and how long a cycle lasts, and every optimization acts on one of them.

§1The Equation

CPU time = Instruction count  x  Cycles per instruction (CPI)  x  Clock period

         = IC * CPI / clock rate

# Example: 2 billion instructions, CPI = 1.5, 3 GHz clock
time = 2e9 * 1.5 / 3e9 = 1.0 second

CPI is the average number of clock cycles per instruction, and its inverse, IPC, is instructions per cycle. A modern core can sustain an IPC of 2 to 4 on friendly code and well under 1 on code that waits on memory.

§2What Controls Each Factor

FactorInfluenced by
Instruction countThe algorithm, the compiler, and the ISA
CPIMicroarchitecture, cache misses, branch mispredictions, dependencies
Clock rateCircuit design, process technology, power and heat limits

The factors are not independent. A faster clock can raise CPI, because memory takes the same absolute time, which is more cycles at a higher frequency. Adding SIMD instructions lowers instruction count, but each instruction may take longer. Optimization is about improving the product, not one term.

§3Comparing Machines Fairly

Clock rate alone is a poor predictor. Consider two CPUs running the same program with the same instruction count:

CPU A: 4.0 GHz, CPI 2.0  ->  time per instruction = 2.0 / 4.0e9 = 0.50 ns
CPU B: 3.0 GHz, CPI 1.2  ->  time per instruction = 1.2 / 3.0e9 = 0.40 ns

# B is 25% faster despite a lower clock, because it does more per cycle.

The same trap applies to 'MIPS' (millions of instructions per second), which ignores how much useful work each instruction does. The only fair comparison is time to finish the same workload.

perf stat -e cycles,instructions ./prog
#  instructions / cycles = IPC   (cycles / instructions = CPI)
The key insight Every speedup comes from fewer instructions, fewer cycles per instruction, or a faster clock. When someone claims an improvement, ask which of the three it changed, and whether the others got worse.

§4Common Mistakes

MistakeWhat HappensFix
Comparing CPUs by GHz aloneA lower-clock CPU with higher IPC can be fasterCompare time on the same workload
Using instruction count as a performance measureA program with fewer instructions can still be slowerInclude CPI: cache misses and stalls cost cycles
Optimizing one factor while ignoring the othersGains in one are canceled by losses in anotherMeasure total time after every change
Practice
  1. A program runs 5 × 10^9 instructions at CPI 0.8 on a 2.5 GHz CPU. Compute its time.
  2. Use perf stat on a program of yours and calculate its IPC. Is it above or below 1, and what does that suggest?
Key takeaways
  • CPU time = instruction count × CPI ÷ clock rate.
  • Algorithm and compiler set instructions, microarchitecture and memory set CPI, technology sets clock.
  • Compare machines by running time on the same workload, not by clock rate.
