Matrix Engines & Why ML Runs on Accelerators

Neural networks are mostly matrix multiplication, and hardware built for exactly that operation, at reduced precision, delivers far more arithmetic per watt than a general-purpose core.

§1Why Matrix Multiply Is Special

Multiplying two N×N matrices does about 2N³ arithmetic operations on only 3N² numbers, so there is a great deal of reuse of each value. Its arithmetic intensity, operations per byte moved, grows with N.

# FP16 (2 bytes per number), ideal reuse:
N = 4096:  FLOPs = 2 * 4096^3   = 1.37e11
           bytes = 3 * 4096^2 * 2 = 1.0e8
           intensity ~ 1,360 FLOP per byte      # very compute-heavy: the arithmetic units are the limit

N = 64:    FLOPs = 524,288    bytes = 24,576    intensity ~ 21 FLOP/byte

High intensity means a chip can keep its arithmetic units busy without needing huge memory bandwidth, so dedicating silicon to multiply-accumulate units pays off.

§2Tensor Cores and Systolic Arrays

  • Tensor cores (NVIDIA) and similar matrix units perform a small matrix multiply-accumulate, D = A × B + C, on a whole tile in one instruction, doing the work of dozens of ordinary multiply-adds at once
  • Systolic arrays, used in Google's TPUs, are grids of multiply-accumulate units through which data flows rhythmically. Each value is passed to a neighbor and reused many times without returning to memory, which saves energy, since data movement costs far more than arithmetic

Both reduce the largest cost in computing: moving operands. An ordinary instruction fetches two inputs, computes once, and stores a result. A matrix unit loads a tile once and performs hundreds of multiplies on it.

§3Reduced Precision

Neural networks tolerate low-precision numbers, so accelerators offer formats that trade precision for throughput and memory.

FormatBitsNotes
FP3232Standard single precision
FP16165-bit exponent, 10-bit mantissa; limited range
BF16168-bit exponent like FP32 (same range), 7-bit mantissa
FP8, INT88Much higher throughput; needs careful scaling

Typically, products are computed in low precision and accumulated in FP32 to limit rounding error. Each halving of bits roughly doubles the number of values per memory transfer and the arithmetic throughput, which is why lower precision is so attractive.

§4Not Everything Is Compute-Bound

Matrix-matrix multiplies are compute-bound, but many neural-network operations aren't. Elementwise operations and normalization do a few operations per element, and generating text one token at a time with a batch of one is a matrix-vector product: each weight is used for just 2 operations.

# Batch-1 LLM decoding, FP16 weights: about 2 FLOPs per 2-byte weight = 1 FLOP/byte.
# Every generated token must read all weights from memory once.
7B parameters * 2 bytes = 14 GB
at 1 TB/s memory bandwidth  ->  at most ~71 tokens/s     # set by bandwidth, not by FLOPs

That is why serving speed for small batches tracks memory bandwidth, and why batching requests, which raises the intensity by reusing each weight across many inputs, improves throughput. The ML category's lessons on transformers and inference show these same costs from the software side.

The key insight Matrix engines win by reusing each loaded value many times at low precision. When there's no reuse, as in batch-1 inference, the chip waits on memory like any other processor.

Practice
  1. Compute the arithmetic intensity of an N × N FP16 matrix multiply for N = 256 and N = 8192, assuming ideal reuse.
  2. A 13B-parameter model in FP16 is served at batch size 1 on a GPU with 2 TB/s bandwidth. Estimate the upper bound on tokens per second.
Key takeaways
  • Matrix multiply has high arithmetic intensity, so dedicated matrix units keep arithmetic busy.
  • Tensor cores and systolic arrays cut data movement by reusing tiles; lower precision multiplies throughput.
  • Batch-1 inference is bandwidth-bound, so speed follows memory bandwidth and batching helps.
