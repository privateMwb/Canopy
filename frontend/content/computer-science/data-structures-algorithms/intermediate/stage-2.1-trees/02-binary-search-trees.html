Binary Search Trees

Keeping a tree ordered, and what that ordering buys you.

§1The Ordering Rule

A binary search tree (BST) adds one rule to a binary tree: for every node, everything in its left subtree is smaller, and everything in its right subtree is larger. This single rule is what makes searching, inserting, and deleting all efficient.

§2Searching

def search(node, target):
    if node is None or node.value == target:
        return node
    if target < node.value:
        return search(node.left, target)
    return search(node.right, target)

At each node, the ordering rule tells you exactly which subtree the target must be in (if it exists) — exactly the same "eliminate half the possibilities" idea as binary search on a sorted array, just expressed as a tree walk.

§3Inserting

def insert(node, value):
    if node is None:
        return TreeNode(value)
    if value < node.value:
        node.left = insert(node.left, value)
    else:
        node.right = insert(node.right, value)
    return node

Insertion walks down the tree the same way search does, then adds a new node at the first empty spot — always a leaf position, never disturbing the existing structure.

§4Why Complexity Depends on Shape

Tree shapeSearch/insert complexity
BalancedO(log n) — height stays proportional to log n
Degenerate (effectively a line)O(n) — height equals n, just a linked list in disguise
The catch with plain BSTs Inserting already-sorted data into a plain BST produces a completely unbalanced tree — every node has only a right child, and performance degrades to that of a linked list. This is exactly the problem self-balancing trees (next lesson) exist to prevent.

§5Common Mistakes

MistakeWhat HappensFix
Assuming a BST is always O(log n)Surprised by O(n) behavior on adversarial or sorted inputO(log n) only holds if the tree stays reasonably balanced
Breaking the ordering rule during insert/deleteSearch starts returning wrong (or missing) resultsAlways maintain "left < node < right" at every node
Practice
  1. Insert the values [5, 3, 8, 1, 4] into an empty BST, one at a time, and draw the resulting tree.
  2. Insert [1, 2, 3, 4, 5] (already sorted) into an empty BST and describe the resulting shape.
Key takeaways
  • A BST maintains "left subtree smaller, right subtree larger" at every node.
  • This ordering lets search and insert eliminate half the remaining tree at each step — when the tree is balanced.
  • Inserting sorted data into a plain BST produces a degenerate, linked-list-like shape with O(n) operations.
