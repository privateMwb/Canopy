Dijkstra's Algorithm

Finding shortest paths in a weighted graph, as long as no edge weight is negative.

§1Why BFS Isn't Enough Anymore

BFS finds shortest paths by counting edges — correct only when every edge costs the same. Once edges have different weights (a map with varying road distances, for example), the "fewest edges" path isn't necessarily the "shortest total distance" path. Dijkstra's algorithm handles weighted edges correctly.

§2The Algorithm

import heapq

def dijkstra(graph, start):   # graph[node] = [(neighbor, weight), ...]
    distances = {{node: float("inf") for node in graph}}
    distances[start] = 0
    pq = [(0, start)]   # (distance, node)

    while pq:
        dist, node = heapq.heappop(pq)
        if dist > distances[node]:
            continue   # already found a better path to this node
        for neighbor, weight in graph[node]:
            new_dist = dist + weight
            if new_dist < distances[neighbor]:
                distances[neighbor] = new_dist
                heapq.heappush(pq, (new_dist, neighbor))

    return distances

A priority queue (min-heap) always processes the closest unprocessed node next — greedily committing to the shortest known distance so far, and relaxing (updating) neighbors' distances whenever a shorter path through the current node is found.

§3Why This Is a Greedy Algorithm

Dijkstra always finalizes the closest remaining node — the same "locally best choice" idea from the earlier greedy lesson. This works here specifically because, once a node's shortest distance is finalized, no future discovery can make it shorter — a guarantee that only holds when edge weights are non-negative.

§4The Negative-Weight Problem

Why Dijkstra breaks with negative edges If an edge can have negative weight, a path through it later could make an already-finalized node's distance smaller — directly violating the greedy assumption Dijkstra depends on. Graphs with negative edges need a different algorithm (Bellman-Ford, covered at the Senior level).

§5Common Mistakes

MistakeWhat HappensFix
Using Dijkstra on a graph with negative edge weightsSilently wrong shortest-path resultsUse Bellman-Ford instead when negative weights are possible
Not checking dist > distances[node] before processingRedundant work processing stale queue entriesSkip entries that are no longer the best known distance to that node
Practice
  1. Given a small weighted graph (4-5 nodes, your choice of weights), trace Dijkstra by hand from one starting node.
  2. Explain, in one or two sentences, why negative edge weights break Dijkstra's greedy assumption.
Key takeaways
  • Dijkstra's algorithm finds shortest paths in a weighted graph with non-negative edges, using a priority queue.
  • It's greedy — always finalizing the closest remaining node — which only works correctly without negative weights.
  • Graphs with negative edges need Bellman-Ford instead.
