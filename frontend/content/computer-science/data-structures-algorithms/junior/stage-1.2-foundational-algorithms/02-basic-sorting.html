Basic Sorting

Bubble, insertion, and selection sort — simple to understand, and why none of them scale.

§1Bubble Sort

def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]

Repeatedly steps through the array, swapping adjacent elements that are out of order. Each full pass "bubbles" the largest remaining element to its correct position. O(n²) in the typical and worst case.

§2Insertion Sort

def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key

Builds up a sorted portion one element at a time, inserting each new element into its correct position within the already-sorted part. Also O(n²) in general, but notably fast (close to O(n)) on data that's already nearly sorted.

§3Selection Sort

def selection_sort(arr):
    for i in range(len(arr)):
        min_idx = i
        for j in range(i + 1, len(arr)):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]

Repeatedly finds the minimum remaining element and swaps it into place. Always O(n²), regardless of how sorted the input already is — unlike insertion sort, it doesn't benefit from a head start.

§4Why These Don't Scale

All three are O(n²) — doubling the input roughly quadruples the work. For 1,000 elements that's a million operations; for 1,000,000 elements, a trillion. This is exactly why Stage 2.3 covers merge sort and quick sort, which achieve O(n log n) through a fundamentally different (divide-and-conquer) strategy.

§5Common Mistakes

MistakeWhat HappensFix
Using these sorts on large real-world datasetsUnacceptably slow at scaleReach for O(n log n) sorts (or a language's built-in sort) for anything nontrivial
Assuming all O(n²) sorts perform identicallyMissing that insertion sort is much faster on nearly-sorted dataKnow each algorithm's actual behavior, not just its worst-case label
Practice
  1. Trace insertion sort by hand on [5, 2, 4, 1, 3], showing the array after each outer loop iteration.
  2. Explain, in one or two sentences, why insertion sort is fast on nearly-sorted data but selection sort isn't.
Key takeaways
  • Bubble, insertion, and selection sort are all O(n²) and simple to implement.
  • Insertion sort is notably fast on nearly-sorted input; the other two aren't.
  • None of these scale to large datasets — that's what divide-and-conquer sorts solve.
