Recursion

Base cases, recursive cases, and learning to trace a call stack by hand.

§1The Two Parts Every Recursive Function Needs

def factorial(n):
    if n == 0:            # base case — stops the recursion
        return 1
    return n * factorial(n - 1)   # recursive case — calls itself on a smaller problem

Every correct recursive function has a base case (a condition simple enough to answer directly, no further recursion) and a recursive case (which calls itself on a smaller version of the problem, trusting that smaller call to work correctly).

§2Tracing the Call Stack

factorial(3)
= 3 * factorial(2)
= 3 * (2 * factorial(1))
= 3 * (2 * (1 * factorial(0)))
= 3 * (2 * (1 * 1))
= 6

Each call waits for the one below it to return before it can compute its own result — these waiting calls stack up in memory (the "call stack"), which is why very deep recursion can hit a stack overflow.

§3Trusting the Recursive Leap

The mental trick that makes recursion click Don't try to trace every single call in your head while writing the function. Instead, assume the recursive call already works correctly on the smaller input, and just verify: does combining that trusted result handle the current case correctly? This "trust the recursion" habit is the single biggest unlock for writing recursive code confidently.

§4Why Recursion Sometimes Beats Loops

Some problems — tree traversal, many divide-and-conquer algorithms — have a naturally recursive structure (small problems look like the big problem, just smaller). Forcing those into an explicit loop is often more complex than letting the recursion express the structure directly, even though a loop would use less memory.

§5Common Mistakes

MistakeWhat HappensFix
Missing or incorrect base caseInfinite recursion, eventually a stack overflowAlways verify the base case is reachable and correctly stops recursion
Recursive case doesn't actually shrink the problemSame infinite recursion issueConfirm each recursive call moves strictly closer to the base case
Practice
  1. Write a recursive function to compute the sum of a list of numbers.
  2. Trace your function by hand on [1, 2, 3], writing out each call and what it returns.
Key takeaways
  • Every recursive function needs a base case (stops recursion) and a recursive case (calls itself on a smaller problem).
  • Calls stack up in memory while waiting for smaller calls to return — deep recursion risks a stack overflow.
  • Trust that the recursive call already works on the smaller input, rather than mentally tracing every level.
