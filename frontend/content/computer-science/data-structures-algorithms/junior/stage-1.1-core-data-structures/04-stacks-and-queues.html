Stacks & Queues

LIFO and FIFO — two of the simplest structures, and the real problems each naturally fits.

§1Stacks — Last In, First Out

stack = []
stack.append(1)   # push
stack.append(2)
stack.pop()        # 2 — removes and returns the most recently added item

A stack only allows adding/removing from one end (the "top"). The most recently added item is always the first one removed — think of a stack of plates, or your browser's back button.

§2Queues — First In, First Out

from collections import deque
queue = deque()
queue.append(1)     # enqueue
queue.append(2)
queue.popleft()       # 1 — removes and returns the item that's been waiting longest

A queue adds at one end and removes from the other — the first item added is the first one out, like a real-world line. In Python, use collections.deque rather than a plain list for the "remove from front" operation — a list's pop(0) is O(n), while deque.popleft() is O(1).

§3What Each One Naturally Fits

StructureNatural use cases
StackUndo/redo, matching brackets, depth-first traversal, function call stacks
QueueTask scheduling, breadth-first traversal, anything processed in arrival order

§4A Worked Example: Balanced Brackets

def is_balanced(s):
    stack = []
    pairs = {{")": "(", "]": "[", "}}": "{{"}}
    for char in s:
        if char in "([{{":
            stack.append(char)
        elif char in ")]}}":
            if not stack or stack.pop() != pairs[char]:
                return False
    return not stack

Every opening bracket gets pushed; every closing bracket must match the most recently opened one — exactly the "last opened, first closed" behavior a stack naturally models.

§5Common Mistakes

MistakeWhat HappensFix
Using a plain Python list as a queue with pop(0)Silently O(n) per dequeue instead of O(1)Use collections.deque for queue behavior
Forgetting to check if the stack is empty before poppingRuntime error on an empty stackAlways check emptiness first, as in the balanced-brackets example
Practice
  1. Implement a function that checks whether a string of brackets is balanced, using a stack.
  2. Explain, in one sentence, why a queue models "fairness" (first come, first served) and a stack doesn't.
Key takeaways
  • A stack is last-in-first-out; a queue is first-in-first-out.
  • Stacks fit undo/redo and depth-first problems; queues fit scheduling and breadth-first problems.
  • Use deque, not a plain list, for O(1) queue operations in Python.
