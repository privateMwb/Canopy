Skip Lists

A probabilistic alternative to balanced trees, used in real systems like Redis.

§1The Core Idea

A skip list is a linked list with multiple "levels" — higher levels skip over many elements at once, acting as express lanes, while the bottom level is the full, ordered linked list. Searching starts at the top level and drops down whenever the next node would overshoot the target.

§2Why "Skipping" Gives Logarithmic Search

## Level 2: 1 -----------> 9 -------------> 21
## Level 1: 1 -----> 5 --> 9 -----> 15 ----> 21
## Level 0: 1 -> 3 -> 5 -> 7 -> 9 -> 12 -> 15 -> 19 -> 21

Searching for 15: start at level 2, jump to 9 (not past 15), drop to level 1, jump to 15 — found, in 3 hops instead of walking through every node. With the right level structure, this gives expected O(log n) search — the same complexity class as a balanced tree, through a completely different mechanism.

§3Building Levels Probabilistically

import random

def random_level(max_level, p=0.5):
    level = 1
    while random.random() < p and level < max_level:
        level += 1
    return level

Each new node is randomly assigned a height — roughly half of nodes reach level 2, a quarter reach level 3, and so on. There's no explicit rebalancing step (unlike AVL or red-black trees); the randomness itself keeps the structure statistically balanced over many insertions.

§4Why "Probabilistic" Instead of "Guaranteed"

The honest tradeoff Skip lists give expected O(log n) performance, not a hard worst-case guarantee like a balanced tree — an unlucky sequence of random level assignments could (rarely) produce a worse structure. In exchange, skip lists are significantly simpler to implement correctly than AVL or red-black tree rotation logic, which is a major part of their real-world appeal.

§5Where Skip Lists Are Actually Used

Redis uses skip lists for its sorted set data type specifically because of this simplicity-vs-strict-tree-rotations tradeoff — easier to implement correctly and reason about, with performance that's essentially equivalent in practice.

Key takeaways
  • Skip lists use multiple linked-list levels, with higher levels skipping over more elements, giving expected O(log n) search.
  • Node heights are assigned randomly — no explicit rebalancing step, unlike balanced trees.
  • They trade a hard worst-case guarantee for significantly simpler implementation — real systems like Redis use them for exactly this reason.
