Segment Trees

Answering range queries and updates in O(log n), built specifically for data that changes.

§1Why Prefix Sums Aren't Enough Here

Prefix sums answer range-sum queries in O(1) — but only for a static array. If the array changes (an update), rebuilding the prefix sum array costs O(n) every time. A segment tree supports both range queries and updates in O(log n), handling the case prefix sums can't.

§2The Structure

A segment tree is a binary tree where each node represents a range of the array — the root covers the whole array, each node's two children split its range in half, and leaves represent individual elements. Each node stores an aggregate (sum, min, max — whatever the query needs) of its range.

§3Building the Tree

def build(arr, tree, node, start, end):
    if start == end:
        tree[node] = arr[start]
        return
    mid = (start + end) // 2
    build(arr, tree, 2 * node, start, mid)
    build(arr, tree, 2 * node + 1, mid + 1, end)
    tree[node] = tree[2 * node] + tree[2 * node + 1]

Built recursively, bottom-up — each internal node's value is simply the combination of its two children, the same recursive "combine children" shape as tree DP.

§4Range Query

def query(tree, node, start, end, l, r):   # sum of arr[l..r]
    if r < start or end < l:
        return 0                              # completely outside range
    if l <= start and end <= r:
        return tree[node]                     # completely inside range
    mid = (start + end) // 2
    return (query(tree, 2 * node, start, mid, l, r) +
            query(tree, 2 * node + 1, mid + 1, end, l, r))

A query touches at most O(log n) nodes — each level of the tree contributes a bounded number of relevant nodes, which is what gives the logarithmic time bound.

§5Point Update

def update(tree, node, start, end, idx, value):
    if start == end:
        tree[node] = value
        return
    mid = (start + end) // 2
    if idx <= mid:
        update(tree, 2 * node, start, mid, idx, value)
    else:
        update(tree, 2 * node + 1, mid + 1, end, idx, value)
    tree[node] = tree[2 * node] + tree[2 * node + 1]   # recompute this node's aggregate

Updating one element only touches the O(log n) nodes on the path from the root to that leaf — every ancestor's aggregate gets recomputed on the way back up.

§6Common Mistakes

MistakeWhat HappensFix
Using a plain array/prefix sum when updates are frequentO(n) per update defeats the pointUse a segment tree whenever both range queries AND updates are needed
Incorrect range overlap logic in the query functionWrong aggregate returnedCarefully handle the three cases: no overlap, full overlap, partial overlap
Practice
  1. Build a segment tree by hand for [1, 3, 5, 7, 9, 11], drawing out the tree structure.
  2. Explain, in one or two sentences, why a segment tree query touches only O(log n) nodes.
Key takeaways
  • Segment trees support both range queries and point updates in O(log n), unlike static prefix sums.
  • Each node represents a range; leaves are individual elements, internal nodes aggregate their children.
  • Both queries and updates touch only O(log n) nodes, following paths through the tree.
