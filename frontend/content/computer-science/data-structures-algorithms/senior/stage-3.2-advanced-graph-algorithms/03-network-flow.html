Network Flow

Max flow / min cut — and the surprisingly wide range of problems it quietly solves.

§1The Core Problem

Given a directed graph where each edge has a capacity (maximum amount that can flow through it), and a source and sink node, find the maximum total flow that can travel from source to sink — think of it literally as water through pipes, each pipe with a maximum throughput.

§2The Ford-Fulkerson Idea

# conceptual — repeatedly find an "augmenting path" with available capacity, push flow along it
max_flow = 0
while augmenting_path_exists(graph, source, sink):
    path, bottleneck = find_path_and_bottleneck(graph, source, sink)
    for edge in path:
        edge.capacity -= bottleneck
        edge.reverse.capacity += bottleneck   # allows flow to be "undone" later if needed
    max_flow += bottleneck

Repeatedly find any path from source to sink with remaining capacity, push as much flow as the path's tightest (bottleneck) edge allows, and update capacities — including adding reverse-edge capacity, which lets a later iteration effectively reroute flow if a better overall solution requires it. Repeat until no augmenting path remains.

§3Max-Flow Min-Cut Theorem

A surprising, useful equivalence The maximum possible flow from source to sink always exactly equals the minimum total capacity of edges that, if removed, would disconnect source from sink (the "min cut"). This isn't just a mathematical curiosity — it means solving a max-flow problem also directly answers "what's the smallest set of connections to remove to fully disconnect two points," a genuinely different-sounding question.

§4Problems That Are Secretly Flow Problems

ProblemHow it maps to flow
Bipartite matchingSource connects to one side, sink to the other, capacity 1 per edge
Image segmentationPixels as nodes, min-cut separates foreground from background
Project selection with dependenciesMax profit under constraints, modeled as a flow network

Recognizing when a problem can be reframed as a flow network is often the hardest part — the algorithm itself is comparatively mechanical once the right graph is constructed.

§5Common Mistakes

MistakeWhat HappensFix
Forgetting reverse edges when pushing flowThe algorithm can get stuck in a suboptimal solutionAlways add capacity to the reverse edge when pushing flow forward
Not recognizing a problem can be modeled as flowMissing an elegant, efficient solutionWatch for "maximum matching," "minimum cut," or "bottleneck capacity" framing
Practice
  1. Given a small flow network (4-5 nodes, capacities of your choice), find the max flow by hand using the augmenting-path approach.
  2. Explain, in one or two sentences, what the max-flow min-cut theorem actually states.
Key takeaways
  • Network flow finds the maximum flow through a capacity-constrained graph from source to sink.
  • The max-flow min-cut theorem equates maximum flow to the minimum capacity needed to disconnect source from sink.
  • Many seemingly unrelated problems (matching, segmentation) can be reframed and solved as flow problems.
