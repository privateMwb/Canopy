Public-Key Cryptography & Key Exchange

Public-key cryptography solves the problem of two strangers sharing a secret over an open channel, using a key pair where one half can be published safely.

§1Key Pairs

A key pair is a public key you can share and a private key you never do. What one key does, only the other can undo or verify. The two main uses are key agreement or encryption (anyone can send you something only you can open) and signatures (only you can sign, anyone can verify).

§2Diffie-Hellman Key Exchange

Each side generates a key pair and shares only the public half. Each combines its own private key with the other's public key and arrives at the same shared secret, which an eavesdropper who sees only the public keys can't compute.

from cryptography.hazmat.primitives.asymmetric.x25519 import X25519PrivateKey
a = X25519PrivateKey.generate()
b = X25519PrivateKey.generate()
secret_a = a.exchange(b.public_key())
secret_b = b.exchange(a.public_key())
assert secret_a == secret_b        # same secret, never sent over the wire

The raw shared secret isn't used directly as a key; it goes through a key derivation function (Stage 2.2). If the key pairs are ephemeral (fresh per session), you get the forward secrecy described in the TLS lesson.

§3RSA and Elliptic Curves

RSAElliptic curves (X25519, P-256)
Hard problemFactoring large numbersDiscrete logarithm on a curve
Typical size2048 to 3072 bits and up256 bits for about the same strength
Speed and sizeLarger keys and signatures, slowerSmall, fast, widely preferred for new designs

Never use "textbook" RSA. Real use needs padding schemes (OAEP for encryption, PSS for signatures), which libraries provide.

§4Hybrid Encryption

Public-key operations are slow and handle small inputs, so real systems use them only to agree on a symmetric key, then encrypt the data with AEAD. TLS, PGP, and most messaging protocols follow this pattern.

What's missing A key exchange with nobody authenticating the keys is open to a man-in-the-middle, who runs one exchange with each side. Binding public keys to identities is the job of certificates and signatures.

§5Common Mistakes

MistakeWhat HappensFix
Using raw RSA without paddingTextbook RSA is malleable and insecureUse OAEP and PSS through a vetted library
Using a DH shared secret directly as a keyBiased or structured bits and no domain separationPass it through a KDF such as HKDF
Exchanging keys without authenticating themA man-in-the-middle sits between both partiesAuthenticate public keys with certificates, signatures, or out-of-band checks
Practice
  1. Run the X25519 example and print both secrets as hex to see that they match.
  2. Explain why a hybrid design uses public keys for the exchange and AES-GCM for the data.
Key takeaways
  • Key pairs let strangers agree on secrets and let owners sign, using public and private halves.
  • Elliptic curves give equal strength with much smaller keys than RSA.
  • Real systems use hybrid encryption, and unauthenticated key exchange is vulnerable to a man-in-the-middle.
