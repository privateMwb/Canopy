Multi-Factor Authentication & TOTP

A password alone can be guessed, phished, or leaked, so a second factor from a different category raises the cost of every one of those attacks.

§1Factors

FactorExampleWeakness
Something you knowPassword, PINGuessed, reused, phished
Something you havePhone, hardware keyLost or stolen
Something you areFingerprint, faceCan't be changed if leaked; local-only use is typical

Multi-factor authentication (MFA) combines at least two different categories. Two passwords are not two factors.

§2How TOTP Works

A time-based one-time password (TOTP), standardized in RFC 6238, is what authenticator apps display. At setup, the server and your app share a secret key, usually via a QR code. Afterwards both compute the same short code from that secret and the current time, with no network connection needed.

counter = floor(unix_time / 30)          # a new value every 30 seconds
code    = truncate(HMAC(secret, counter)) mod 10^6   # six digits

The server accepts the current code, and often one step either side to allow for clock drift. It must reject a code that was already used.

§3What MFA Does and Doesn't Stop

  • Stops most credential stuffing and password-only phishing, since a stolen password isn't enough.
  • Does not stop real-time phishing, where a fake site relays your password and TOTP code to the real site instantly. Passkeys (Stage 2.3) address this.
  • SMS codes are weaker than app-based or hardware factors, because phone numbers can be hijacked by SIM swapping.

Plan for recovery: offer one-time backup codes, store them hashed, and treat the recovery path as part of the attack surface.

Stage 2.1 connection TOTP is built on HMAC, a keyed hash. Once you've met message authentication codes, you'll see that the code is simply a MAC of the time, with the secret as the key.

§4Common Mistakes

MistakeWhat HappensFix
Accepting the same TOTP code repeatedlyA shoulder-surfed or phished code can be reused within its windowRecord the last accepted step and reject repeats
Making SMS the only second factorSIM swapping and interception bypass itPrefer authenticator apps or hardware keys, and offer them first
An easy recovery path that skips MFAAttackers use recovery to bypass the second factorMake recovery as strong as login
Practice
  1. Enable TOTP on an account you own, then explain what is shared at setup and what is computed at each login.
  2. List two attacks that MFA stops and one it does not.
Key takeaways
  • MFA combines factors from different categories: know, have, are.
  • TOTP derives a six-digit code from a shared secret and the clock, and each code should be accepted once.
  • MFA is strong against stolen passwords but not against real-time phishing.
