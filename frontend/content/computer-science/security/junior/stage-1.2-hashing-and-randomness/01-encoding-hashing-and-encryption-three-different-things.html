Encoding, Hashing & Encryption: Three Different Things

Encoding, hashing, and encryption all scramble data, but they answer different questions, and mixing them up is behind a surprising number of real vulnerabilities.

§1Three Tools, Three Jobs

ToolReversible?Needs a secret?Purpose
Encoding (Base64, URL, hex)Yes, by anyoneNoRepresent data in a format a system accepts
Hashing (SHA-256)No, one-wayNoA fixed-size fingerprint for integrity and lookup
Encryption (AES)Yes, with the keyYes, a keyKeep data confidential

§2Encoding Hides Nothing

Base64 exists so binary data survives text-only channels. Anyone can decode it, so it offers no secrecy at all.

$ echo -n 'admin:hunter2' | base64
YWRtaW46aHVudGVyMg==
$ echo 'YWRtaW46aHVudGVyMg==' | base64 -d
admin:hunter2

HTTP Basic authentication sends credentials exactly this way, which is why it's only acceptable over HTTPS.

§3Hashing Is One-Way, Encryption Is Two-Way

A hash has no key and no way back: you can compare hashes, but you can't recover the input. Encryption is meant to be undone by someone with the key. Choose by asking whether you ever need the original value back.

  • Need to check a value without storing it, such as a password or file integrity? Use a hash (with the right kind, covered in Stage 1.3).
  • Need to read the value later, such as a stored card or a message? Use encryption.
  • Just need to carry bytes through a text field? Use encoding, and don't call it security.
The giveaway question "Could someone without any secret reverse this?" If yes, it is encoding, not protection. Obfuscation like ROT13 or Base64 around a password is the same as storing the password.

§4Common Mistakes

MistakeWhat HappensFix
Base64-encoding secrets and calling it encryptedAnyone decodes it in one commandUse real encryption with a protected key, or avoid storing the secret
Storing recoverable passwords with encryptionA key leak exposes every passwordHash passwords with a slow password hash instead
Calling a hash "encrypted"Wrong tool is chosen, since you can't decrypt a hashPick by whether you need the original value back
Practice
  1. Decode a Base64 string from an HTTP Basic Authorization header by hand with base64 -d.
  2. For each, choose encoding, hashing, or encryption: storing a password, sending an image in JSON, saving a medical note.
Key takeaways
  • Encoding is for format, hashing is for fingerprints, and encryption is for secrecy.
  • Encoded data is readable by everyone and is not protected.
  • Ask whether you need the original back to choose between hashing and encryption.
