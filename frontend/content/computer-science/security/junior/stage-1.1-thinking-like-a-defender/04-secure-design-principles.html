Secure Design Principles

A handful of design principles prevent whole families of vulnerabilities, and they apply to every system from a login form to a cloud platform.

§1Least Privilege and Fail-Safe Defaults

Give every user, process, and service only the access its job requires, and nothing else. If something is compromised, the damage is limited to what it could already do. Fail-safe defaults mean the starting state is "no access": permission must be granted explicitly, so a forgotten rule fails closed.

# Fails open: anything not blocked is allowed
if user in blocked_users: deny()
else: allow()

# Fails safe: anything not allowed is denied
if user in allowed_users: allow()
else: deny()

§2Defense in Depth

Don't rely on one control. Layer independent defenses so that when one fails, another still stands: input validation, then parameterized queries, then a database account with minimal rights. An attacker has to beat every layer, and each layer should assume the previous one has failed.

§3Smaller Attack Surface and Simplicity

The attack surface is every place an attacker can interact with your system: endpoints, input fields, open ports, and dependencies. Remove what you don't need, since every feature is also a liability. Complex designs hide flaws, so the simpler mechanism you can explain in one paragraph is usually the safer one.

  • Complete mediation: check authorization on every access, not just the first.
  • Separation of duties: no single person or key can do something dangerous alone.
  • Don't rely on secrecy of design: assume attackers know how your system works; only keys and passwords should be secret.
Where this goes next The DevOps track applies least privilege to containers and hosts, and Networking applies it to firewalls and segmentation. These principles are the same idea at different layers.

§4Common Mistakes

MistakeWhat HappensFix
Running services as root or admin "for convenience"Any bug becomes full system compromiseCreate narrow accounts and grant only what's needed
Allow-by-default rulesAnything you forgot is openDeny by default and allow explicitly
One control guarding everythingA single bypass defeats the whole defenseAdd independent layers that don't share a failure mode
Practice
  1. Rewrite a permissive rule ("block these users") as a deny-by-default rule.
  2. List three features in an app you know that you could remove to shrink its attack surface.
Key takeaways
  • Grant least privilege and default to no access.
  • Layer independent defenses, and assume each one can fail.
  • Reduce the attack surface and prefer simple designs you can fully explain.
