Processes & Job Control

The shell can run programs in the foreground and background, list them, and stop them, using the process and signal ideas from the OS track.

§1Foreground, Background and Jobs

A command normally runs in the foreground and holds your terminal. Ending it with & starts it in the background. Ctrl+Z suspends the foreground job, and bg or fg resumes it in the background or foreground.

sleep 300 &              # start in the background; prints [1] 4821
jobs                     # list this shell's jobs
fg %1                    # bring job 1 to the foreground
# press Ctrl+Z to suspend, then:
bg %1                    # keep it running in the background

Jobs belong to your shell session. If you close the terminal, the shell sends them a hangup signal and they usually die. Use nohup or a terminal multiplexer such as tmux, or better, a proper service, for long-running work.

§2Inspecting Processes

Every process has a PID. ps gives a snapshot, and top or htop shows a live view. pgrep finds PIDs by name.

ps aux | head            # every process, with user, CPU, memory
ps -ef --forest          # parent/child tree
pgrep -a nginx           # PIDs and command lines matching "nginx"
top                      # live view; press q to quit
echo $?                  # exit code of the last command

Look at the STAT column in ps: R is running, S is sleeping, D is uninterruptible I/O wait, and Z is a zombie, a child that exited but has not been reaped.

§3Stopping Processes with Signals

kill does not necessarily kill. It sends a signal. The default, SIGTERM (15), asks the process to shut down cleanly. SIGKILL (9) cannot be caught and ends it immediately with no cleanup. Ctrl+C sends SIGINT.

kill 4821                # SIGTERM: please exit
kill -9 4821             # SIGKILL: last resort
kill -HUP 4821           # many daemons reload config on SIGHUP
pkill -f "python worker" # match by full command line
Try TERM before KILL SIGKILL skips the process's cleanup code, so it can leave temp files, locks, and half-written data behind. Send SIGTERM, wait a few seconds, and escalate to -9 only if it does not exit.

§4Common Mistakes

MistakeWhat HappensFix
Reaching for kill -9 firstNo cleanup runs; stale lock files or corrupted state remainSend SIGTERM first and escalate only if needed
Starting a long job with & and closing the terminalThe job receives SIGHUP and diesUse nohup, tmux, or run it as a service
Killing by name with a broad patternpkill python stops every Python process you ownCheck with pgrep -a first, and use a narrow pattern
Practice
  1. Start three sleep jobs in the background, list them, bring one to the foreground, and stop it with Ctrl+C.
  2. Find the PID of a running process, send it SIGTERM, and confirm its exit with ps.
Key takeaways
  • &, Ctrl+Z, bg, and fg control jobs inside one shell session.
  • kill sends signals; use SIGTERM to ask and SIGKILL only as a last resort.
  • ps and top show process state, including zombies and I/O wait.
