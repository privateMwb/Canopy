Files, Permissions & Ownership

Every file has an owner, a group, and three sets of read, write, and execute bits that decide who can do what.

§1Reading the Permission String

ls -l shows ten characters at the start of each line. The first is the type (- file, d directory, l symlink); the next nine are three triplets for the owner, the group, and others.

$ ls -l deploy.sh
-rwxr-xr--  1 alice devs  412 Oct 19 09:12 deploy.sh
#  ^^^ owner: rwx
#     ^^^ group: r-x
#        ^^^ others: r--

For files, r reads, w modifies, and x runs the file as a program. For directories, r lists names, w creates or deletes entries inside, and x lets you enter and access items by name. A directory without x is unusable even if you can read it.

§2Changing Permissions and Ownership

chmod changes the bits, either symbolically or with octal numbers where r=4, w=2, x=1. chown changes owner and group, and normally needs root.

chmod u+x deploy.sh          # add execute for the owner
chmod 640 notes.txt          # rw- r-- ---  (4+2, 4, 0)
chmod -R g+w shared/         # recursive: group can write
sudo chown alice:devs report.csv
umask                        # default bits removed from new files

New files are created with the default mode minus the umask. A umask of 022 turns a requested 666 into 644 for files and 777 into 755 for directories.

§3Special Bits

Three extra bits show up in real systems. setuid makes a program run as its owner (that is how passwd can edit protected files). setgid on a directory makes new files inherit its group, which is useful for shared project folders. The sticky bit on a directory like /tmp means only a file's owner can delete it.

ls -ld /tmp                  # drwxrwxrwt: the trailing t is the sticky bit
chmod g+s /srv/project       # new files inherit the group
find / -perm -4000 -type f 2>/dev/null   # list setuid programs
Never reach for 777 chmod 777 makes a file writable by everyone on the machine, and it almost always hides the real problem: the wrong owner or group. Fix ownership first, then grant the narrowest bits that work.

§4Common Mistakes

MistakeWhat HappensFix
Using chmod 777 to fix "permission denied"Any user or compromised process can modify the fileFind the right owner or group and grant minimal bits
Forgetting x on a directoryYou can list names but cannot cd in or open filesAdd x to directories, for example chmod 755 dir
Running a script without x or a shebang"Permission denied" or the wrong interpreter runs itchmod +x and start the file with #!/usr/bin/env bash
Practice
  1. Create a file, set it to 640, and confirm with ls -l that another user could not read it.
  2. Make a shared directory where every new file automatically belongs to the group devs.
Key takeaways
  • Permissions are three triplets (owner, group, others) of read, write, and execute.
  • On directories, x means "may enter", and w means "may create or delete entries".
  • Fix ownership before loosening permissions, and avoid 777.
