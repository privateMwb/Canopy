Functions & Arguments

Functions and positional arguments turn a pile of commands into a reusable tool with a clear interface.

§1Positional Parameters

A script receives its arguments as $1, $2, and so on. $0 is the script's name, $# the count, and "$@" expands to all arguments, each kept as a separate word.

#!/usr/bin/env bash
echo "script: $0"
echo "count:  $#"
echo "first:  ${1:-none}"
for arg in "$@"; do echo "arg: $arg"; done
shift                            # drop $1; $2 becomes $1

Prefer "$@" over $* when passing arguments on to another command. "$@" preserves each argument as a unit, even one containing spaces.

§2Functions

Functions take arguments the same way scripts do. local keeps variables from leaking out. A function "returns" an exit status; to produce a value, print it and capture it with $(...).

log() {
  local level="$1"; shift
  echo "[$(date +%T)] $level: $*" >&2
}

require_file() {
  [[ -f "$1" ]] || { log ERROR "missing $1"; return 1; }
}

count_lines() { wc -l < "$1"; }
n=$(count_lines /etc/passwd)
log INFO "passwd has $n lines"

Logging to stderr (>&2) keeps stdout free for data, so callers can capture the output without log noise mixed in.

§3Options with getopts

getopts parses short flags such as -v and -o file. A colon after a letter means that option takes a value.

verbose=0; output="out.txt"
while getopts "vo:h" opt; do
  case "$opt" in
    v) verbose=1 ;;
    o) output="$OPTARG" ;;
    h) echo "usage: $0 [-v] [-o file] input"; exit 0 ;;
    *) exit 2 ;;
  esac
done
shift $((OPTIND - 1))            # what is left are the non-option arguments
input="${1:?input file required}"
Design the interface first Decide the arguments, defaults, and exit codes before writing the body. ${1:?message} is a compact way to require an argument: the script stops with your message if it is missing.

§4Common Mistakes

MistakeWhat HappensFix
Using $* unquotedArguments are split on spaces and mergedUse "$@"
Forgetting local in functionsVariables overwrite globals and cause hard-to-trace bugsDeclare function variables with local
Printing logs to stdout from a function whose output is capturedThe log text becomes part of the returned valueSend logs to stderr with >&2
Practice
  1. Write a function usage and a script that prints it and exits with code 2 when called without arguments.
  2. Add -v and -o options with getopts to a script of your own.
Key takeaways
  • Scripts read arguments from $1, $2, and "$@", and functions work the same way.
  • Functions return an exit status; to return data, print it and capture it with $(...).
  • Send diagnostics to stderr so stdout stays clean for data.
