Registries, Tags & Image Hygiene

A registry stores and distributes images, and tags are mutable labels, so reliable deployments pin versions and digests rather than trusting latest.

§1Registries and Image Names

An image name is registry/namespace/repository:tag. With no registry given, Docker uses Docker Hub. Others include GitHub Container Registry (ghcr.io) and cloud registries. You tag a local image with the full name, log in, and push.

docker login ghcr.io
docker build -t ghcr.io/acme/shop:1.4.2 .
docker push ghcr.io/acme/shop:1.4.2
docker pull ghcr.io/acme/shop:1.4.2
docker tag shop:dev ghcr.io/acme/shop:sha-3f9c2e1   # add a second name

§2Tags Are Mutable, Digests Are Not

A tag is a pointer that anyone with push access can move. latest is just a tag, with no special meaning, and it does not mean "newest". A digest (sha256:...) identifies exact image content and can never change.

docker pull nginx:1.27
docker inspect --format '{{index .RepoDigests 0}}' nginx:1.27
# nginx@sha256:9a1f...c4

# deploy by digest: the content is guaranteed identical everywhere
docker run nginx@sha256:9a1f...c4

A good scheme tags each build with the Git commit SHA (immutable in practice) plus a human-friendly version for releases, and deploys one specific tag or digest.

§3Image Hygiene

Images accumulate. Remove unused ones locally, give CI-built images a retention policy in the registry, and scan images for known vulnerabilities before they ship.

docker image prune                       # dangling images
docker system prune -a --volumes         # aggressive; read the prompt first
docker scout cves shop:1.4.2             # or: trivy image shop:1.4.2
docker image ls --digests
Reproducibility is the goal "What exactly is running in production?" should have a one-line answer: an immutable tag or digest that maps to one commit. If the answer is "latest, probably", you cannot reproduce or roll back reliably.

§4Common Mistakes

MistakeWhat HappensFix
Deploying latestYou cannot tell what is running, and rollbacks are guessworkDeploy an explicit version tag or digest
Reusing a release tag for new contentHosts that cached the old image run different codeTreat release tags as immutable and publish a new one
Never pruning or scanningDisk fills and known CVEs ship to productionPrune regularly and scan in CI
Practice
  1. Tag an image with both a version and a commit SHA, push both to a registry, and verify they share one digest.
  2. Find the digest of a running container's image and pull the image by that digest.
Key takeaways
  • Image names are registry/namespace/repo:tag; pushing needs a login and a full name.
  • Tags can be moved, but digests identify exact content and cannot change.
  • Deploy specific versions or digests, never latest, and scan and prune images regularly.
