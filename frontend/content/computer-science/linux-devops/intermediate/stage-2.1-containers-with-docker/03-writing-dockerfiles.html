Writing Dockerfiles

A Dockerfile is a recipe of build steps, each of which produces a layer, that turns your application into a repeatable image.

§1The Core Instructions

Each instruction creates a layer. FROM picks the base image, WORKDIR sets the directory, COPY adds files, RUN executes a command at build time, and CMD or ENTRYPOINT defines what runs when a container starts.

# Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
USER 10001
CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]
docker build -t myapp:1.0 .
docker run --rm -p 8000:8000 myapp:1.0

EXPOSE only documents a port. It does not publish it. You still need -p at run time.

§2CMD vs. ENTRYPOINT, and Exec Form

ENTRYPOINT is the fixed program, and CMD supplies its default arguments (or the whole command when there is no entrypoint). Use the exec form, a JSON array, so your program becomes PID 1 and receives signals like SIGTERM directly. The shell form wraps it in /bin/sh -c, which often swallows them.

ENTRYPOINT ["python", "manage.py"]
CMD ["runserver", "0.0.0.0:8000"]
# docker run myapp               -> python manage.py runserver 0.0.0.0:8000
# docker run myapp migrate       -> python manage.py migrate

§3.dockerignore and Running as non-root

COPY . . sends everything in the build context, including .git, local secrets, and node_modules. A .dockerignore file excludes them, which makes builds faster and safer. Also avoid running as root inside the container.

# .dockerignore
.git
node_modules
*.log
.env
Dockerfile
Build time vs. run time RUN happens once while building the image, and CMD happens every time a container starts. Installing packages in CMD would reinstall on every start, and starting a server in RUN would hang the build.

§4Common Mistakes

MistakeWhat HappensFix
Using shell form CMD python app.pyThe shell is PID 1, signals are not forwarded, and docker stop waits 10 seconds then killsUse exec form: CMD ["python", "app.py"]
Copying secrets into the imageAnyone with the image can extract them from a layerInject secrets at run time, and use .dockerignore
Using FROM python with no tagThe base silently changes over timePin a specific version, such as python:3.12-slim
Practice
  1. Write a Dockerfile for a small web app, build it, and confirm the process runs as a non-root user with docker exec ... id.
  2. Switch a CMD from shell form to exec form and compare how quickly docker stop finishes.
Key takeaways
  • Each Dockerfile instruction makes a layer, and RUN happens at build time while CMD happens at start time.
  • Use exec form so your app is PID 1 and handles signals properly.
  • Pin base images, use .dockerignore, and run as a non-root user.
