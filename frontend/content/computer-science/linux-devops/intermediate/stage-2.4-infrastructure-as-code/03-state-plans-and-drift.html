State, Plans & Drift

Terraform remembers what it created in a state file, and the plan is the difference between your code, that state, and the real world.

§1What State Is

The state maps each resource in your code to the real object that Terraform created. Without it, Terraform could not tell whether a bucket already exists or must be created. State can contain sensitive values, so treat it as a secret and never commit it.

terraform state list                       # resources Terraform tracks
terraform state show aws_s3_bucket.backups
terraform show                             # full current state
cat .gitignore                             # must include *.tfstate and .terraform/

§2Remote State and Locking

A teammate and a pipeline cannot share a state file on one laptop. Store it in a remote backend, such as an object-storage bucket, with locking so two applies cannot run at once and corrupt it.

terraform {
  backend "s3" {
    bucket       = "acme-tfstate"
    key          = "prod/network.tfstate"
    region       = "eu-west-1"
    encrypt      = true
    use_lockfile = true                    # prevent concurrent applies
  }
}

Split state into several small units, for example by environment and by layer (network, data, apps). A single giant state makes every plan slow and every mistake dangerous.

§3Plans and Drift

Drift is when reality no longer matches the state, usually because someone changed something by hand. plan detects it by refreshing against the real world. Then you either update the code to accept the change or apply to put it back. You can also bring existing resources under management.

terraform plan                             # shows drift as proposed changes
terraform plan -refresh-only               # show drift without proposing code changes
terraform import aws_s3_bucket.legacy old-bucket-name
terraform apply -replace=aws_instance.web  # force a rebuild of one resource
The plan is your safety net The plan tells you exactly what will be created, changed, or destroyed before anything happens. In a pipeline, save the plan from the pull request and apply that exact plan after approval, so what was reviewed is what runs.

§4Common Mistakes

MistakeWhat HappensFix
Committing state to GitSecrets leak and teammates overwrite each other's stateUse an encrypted remote backend with locking
Editing resources manually in the consoleDrift, and a surprising plan laterChange them in code, or import and codify the change
One enormous state for everythingSlow plans and a large blast radiusSplit state by environment and component
Practice
  1. Move a local state file to a remote backend and confirm a second shell sees the same resources.
  2. Change a resource in the console, run terraform plan, and decide whether to accept or revert the drift.
Key takeaways
  • State maps your code to real resources, and it must be stored remotely, encrypted, and locked.
  • Drift is a difference between state and reality, and plan reveals it.
  • Split state into small units to limit slow plans and large blast radius.
