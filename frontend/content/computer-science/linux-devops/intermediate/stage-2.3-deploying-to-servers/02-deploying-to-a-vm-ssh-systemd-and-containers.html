Deploying to a VM: SSH, systemd & Containers

The simplest real deployment is a script that gets a tested image onto a server and restarts it safely, and it should be repeatable instead of hand-typed.

§1The Deployment Loop

The minimum is: connect, fetch the new version, start it, check that it works, and keep the old one until you are sure. Doing this by hand invites mistakes, so capture it in a script that the pipeline runs.

#!/usr/bin/env bash
set -euo pipefail
HOST="deploy@shop.example.com"
IMAGE="ghcr.io/acme/shop:${1:?usage: deploy.sh <tag>}"

ssh "$HOST" bash -s -- "$IMAGE" <<'REMOTE'
set -euo pipefail
IMAGE="$1"
docker pull "$IMAGE"
cd /opt/shop
echo "IMAGE=$IMAGE" > .env.deploy
docker compose --env-file .env.deploy up -d --remove-orphans
REMOTE

§2Verify Before You Trust

A deploy has not succeeded just because the commands returned 0. Wait for the app to report healthy, and fail the deploy, loudly, if it does not.

for i in {1..30}; do
  if curl -fsS https://shop.example.com/healthz >/dev/null; then
    echo "healthy"; exit 0
  fi
  sleep 2
done
echo "deploy failed health check" >&2
exit 1

Make the health endpoint meaningful. A /healthz that always returns 200 passes even when the database is unreachable. A shallow liveness check and a deeper readiness check serve different purposes.

§3Running It Under Supervision

Whether you run the app as a container with Compose or as a binary under systemd, make sure something restarts it if it crashes and starts it after a reboot. The service manager is the safety net beneath your deploy script.

# in compose.yaml
#   services:
#     shop:
#       image: ${IMAGE}
#       restart: unless-stopped
sudo systemctl enable docker           # containers come back after reboot
docker compose ps
docker compose logs --since 10m shop
Automate the boring, risky part A deployment script is a form of documentation that actually runs. Every manual step you move into it removes one way for a 2 a.m. deploy to go wrong.

§4Common Mistakes

MistakeWhat HappensFix
Treating exit code 0 as successThe app may be crashing right after startingPoll a real health endpoint and fail if it never passes
Pulling and restarting by hand over SSHSteps differ each time, and nobody knows what ranPut the steps in a script that CI executes
Not setting a restart policyA crash or reboot leaves the service downUse restart: unless-stopped or a systemd unit with Restart=
Practice
  1. Write a deploy script for a Compose app that pulls a given tag, restarts, and checks /healthz.
  2. Make the script fail on purpose by deploying a broken image, and confirm it reports the failure.
Key takeaways
  • A repeatable deploy script beats a sequence of commands typed from memory.
  • Success means the app is healthy, not that the commands finished.
  • Supervision (restart policies, systemd) keeps the service up after crashes and reboots.
