Register Allocation

Register allocation decides which values live in the CPU's few registers and which spill to memory, and it has a bigger effect on speed than almost any other back-end decision.

§1Too many values, too few registers

The IR has an unlimited supply of temporaries. A CPU has a small number of registers (16 general-purpose on x86-64, 31 on RISC-V and ARM64), and registers are much faster than memory. Register allocation assigns each temporary to a register, and when there aren't enough, spills some to the stack.

t1 = load a
t2 = load b
t3 = t1 + t2          # t1, t2 live here
t4 = load c
t5 = t3 * t4          # t3, t4 live here

Not every temporary needs its own register, since values can share one when they aren't live at the same time. Liveness, which you computed in Stage 2.4, drives this.

§2Live ranges and interference

A temporary's live range is the span from its definition to its last use. Two temporaries interfere if their ranges overlap, because they can't share a register.

        t1  t2  t3  t4  t5
  1: t1  ■
  2: t2  ■   ■
  3: t3  ·   ·   ■            (t1, t2 die here)
  4: t4          ■   ■
  5: t5          ·   ·   ■

For graph colouring, build an interference graph: a node per temporary and an edge between any two that interfere. A register assignment is then a colouring: adjacent nodes get different colours (registers). With k registers, you need a k-colouring.

def color(graph, k):
    stack = []
    while graph not empty:
        n = find node with degree < k           # always colourable later
        if none: n = pick_spill_candidate()      # potential spill
        stack.push(n); graph.remove(n)
    while stack:
        n = stack.pop(); graph.add_back(n)
        n.color = any color not used by n's neighbours

Finding a k-colouring is NP-hard in general, but this simplify-and-select heuristic works well in practice.

§3Linear scan and spilling

Graph colouring gives good results but is slow. Linear scan is the faster alternative, popular in JITs where compile time counts. It sorts live ranges by start and walks through them, giving each a register and freeing registers as ranges end.

def linear_scan(ranges, k):
    active = []
    for r in sorted(ranges, key=start):
        expire_old(active, r.start)           # free registers of ended ranges
        if len(active) == k:
            spill = longest_ending(active + [r])    # spill the one that ends last
            if spill != r: r.reg = spill.reg; active.remove(spill)
            spill.location = new_stack_slot()
        else:
            r.reg = free_register()
        if r.reg: active.add(r)

A spilled value lives in a stack slot: the compiler inserts a store after its definition and a load before each use. Spill code costs memory traffic, so good allocators try to spill values that are used rarely, especially not those inside inner loops.

The key insight Register allocation is graph colouring in disguise: values that are live at the same time conflict, and the register count is the number of colours. Everything else is heuristics for the case where colours run out.

§4Common Mistakes

MistakeWhat HappensFix
Spilling a value used inside a hot loopEvery iteration adds loads and stores and slows the program badlyWeight spill cost by loop depth and spill cold values first
Ignoring registers a call overwritesA value in a caller-saved register is lost after a callTreat calls as clobbering those registers (see calling conventions)
Allocating before the code is finalizedLater passes change live ranges and invalidate the assignmentRun allocation last, after the final optimization passes
Practice
  1. Build the interference graph for the five-instruction example and colour it with 2 registers; if it fails, decide which temporary to spill.
  2. Run linear scan by hand on four overlapping live ranges with k = 2 and show which range is spilled.
Key takeaways
  • Live ranges that overlap interfere and can't share a register.
  • Graph colouring gives good code; linear scan gives fast compilation.
  • Spilling puts values on the stack, so spill rarely used values, never loop-hot ones.
