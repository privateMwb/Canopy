Generational & Copying Garbage Collection

Copying and generational collectors exploit the fact that most objects die young, making allocation nearly free and collection cost proportional to what survives.

§1Copying collection

Mark-sweep touches every dead object during the sweep and leaves free memory scattered. A copying collector takes a different approach: split the heap into two halves (semispaces), allocate in one, and when it fills up, copy the live objects into the other and discard the old half whole.

def collect():
    swap(from_space, to_space)
    scan = free = to_space.start
    for root in roots(): root.value = forward(root.value)
    while scan < free:                     # Cheney's algorithm
        for field in object_at(scan).references:
            field.value = forward(field.value)
        scan += size_of(object_at(scan))

def forward(obj):
    if obj in to_space: return obj
    if obj.forwarding: return obj.forwarding      # already copied
    new = copy_to(free, obj); free += size(obj)
    obj.forwarding = new
    return new

Two benefits follow. Allocation becomes a pointer bump (add the size to a pointer, check the limit), and live objects end up packed together, which improves cache behaviour. The costs: half the memory sits idle, and every live object is copied on every collection.

§2The generational hypothesis

Measurements across many programs show the same pattern: most objects die young. A temporary array or closure is usually garbage almost immediately, while a small fraction live for a long time.

A generational collector uses that. It divides the heap into a small young generation (the nursery) and a larger old generation. New objects go to the nursery, and the collector frequently runs a minor collection that copies only the survivors out of it. Objects that survive a couple of rounds are promoted to the old generation, which is collected rarely.

allocate ─► nursery ─(survives)─► survivor space ─(survives again)─► old generation
              ▲ collected often, cheap, mostly garbage       ▲ collected rarely

Since the nursery is mostly garbage, a minor collection does little work, and pauses are short.

§3Write barriers

A minor collection only scans the nursery, but old objects can point into it. Those pointers are roots too. Scanning the whole old generation to find them would defeat the purpose.

The fix is a write barrier: code the compiler or VM runs on every pointer store, recording old-to-young pointers in a remembered set.

def write_field(obj, field, value):
    obj.fields[field] = value
    if is_old(obj) and is_young(value):
        remembered_set.add(obj)               # check this object during minor GC

def minor_collect():
    for root in roots() + remembered_set.fields(): root.value = forward(root.value)
    ...
    remembered_set.clear()

The barrier costs a few instructions on every pointer write. That price buys cheap, frequent minor collections. A missing barrier is a classic GC bug: an old object points to a young one that gets freed, and the program crashes much later.

The key insight A generational collector bets that most objects die young, and then arranges to do work only proportional to the survivors. The write barrier is the price of keeping that bet cheap.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting the write barrier on one kind of storeA young object referenced only by an old one is freedPut the barrier in every path that stores a pointer, including array writes and upvalue closes
Promoting objects after a single survivalShort-lived-but-not-instant objects fill the old generationRequire survival of a few minor collections first
Using fixed generation sizesPrograms with large live sets thrash, or small ones waste memorySize the nursery relative to cache and allocation rate, and the old generation to the live set
Practice
  1. Run Cheney's algorithm by hand on a small heap of five objects with two roots, showing the scan and free pointers.
  2. List every operation in the Twig VM that stores a reference into a heap object and therefore needs a write barrier.
Key takeaways
  • Copying collectors bump-allocate and only touch live objects, at the cost of half the heap.
  • Generational collectors exploit that most objects die young and collect the nursery often.
  • Write barriers track old-to-young pointers so minor collections stay cheap and correct.
