Implementing Generics: Monomorphization vs. Erasure

Generic code can be compiled once and shared, or copied for each type it's used with, and the choice trades code size, speed, and separate compilation against each other.

§1The problem

A generic function like first<T>(xs: [T]): T must work on [int], [str], and arrays of records. But at the machine level, those values have different sizes and need different instructions to copy or compare. The compiler has to decide how to produce code for all of them.

§2Monomorphization

Monomorphization generates a separate copy of the function for each distinct type it is used with.

first<int>([1, 2, 3])        →  first_int(xs)    // specialized, ints are 8 bytes
first<str>(["a", "b"])       →  first_str(xs)    // specialized for strings
def monomorphize(program):
    work = [main]
    done = {}
    while work:
        f = work.pop()
        for call in f.calls where call.callee.is_generic:
            key = (call.callee, call.type_args)
            if key not in done:
                done[key] = instantiate(call.callee, call.type_args)
                work.append(done[key])
  • Pros: each copy is fully specialized, so it is as fast as hand-written code, with no boxing and inline-friendly.
  • Cons: code size grows with the number of instantiations, compile time rises, and generics can't cross a separate-compilation boundary without exposing their source or IR.

§3Erasure and dictionary passing

Erasure compiles one copy that works for all types by making all values look alike, usually as uniform references. Primitive values are boxed (wrapped in a heap object) so everything is one pointer wide.

first(xs):   return xs.items[0]       // works for any T: just copies a pointer

Operations that depend on the type, such as comparison or hashing, can't be written once. Dictionary passing supplies them as hidden extra arguments.

fn max<T>(a: T, b: T, ord: Ordering<T>): T {
  if ord.less(a, b) { return b; } return a;
}
max(3, 4, int_ordering)
  • Pros: one copy of the code, small binaries, and generic functions can be compiled separately and called through a stable interface.
  • Cons: boxing costs memory and speed, calls through dictionaries are indirect, and the optimizer sees less.

Real systems blend them: erase by default and specialize hot paths, or monomorphize by default and fall back to erasure when instantiations explode.

The key insight Generic implementation is a three-way tradeoff between speed, binary size, and separate compilation. Language design choices, such as whether generics are first-class values, decide which strategies are even possible.

§4Common Mistakes

MistakeWhat HappensFix
Monomorphizing without limiting recursion through genericsInstantiations multiply forever (a generic function calling itself at a bigger type)Detect unbounded instantiation and report an error, or fall back to erasure
Boxing all primitives for erasure without noticing the costNumeric code becomes many times slowerSpecialize primitives, or add unboxed variants of containers
Forgetting to pass type-specific operations with erasureGeneric max can't compare, so you fall back to unsafe castsPass dictionaries, or restrict generics to operations that need none
Practice
  1. For first, max, and map, say which instantiations a program with [int], [str] and [[int]] would produce under monomorphization, and how many functions you'd have under erasure.
  2. Explain why a language that allows generic functions to be stored in variables and called at different types struggles with pure monomorphization.
Key takeaways
  • Monomorphization copies code per type: fastest, biggest, hardest across separate compilation.
  • Erasure shares one copy with uniform values and dictionaries: smaller and separable, slower.
  • Real systems mix both, and language rules decide what is possible.
