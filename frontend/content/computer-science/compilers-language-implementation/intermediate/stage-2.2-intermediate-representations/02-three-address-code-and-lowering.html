Three-Address Code & Lowering

Lowering flattens nested expressions and structured control flow into simple instructions that each do one thing.

§1Three-address code

In three-address code, each instruction has at most one operator and at most three addresses: two sources and one destination. Nested expressions are broken up using fresh temporaries.

source:   x = a * b + c * d;

TAC:      t1 = a * b
          t2 = c * d
          t3 = t1 + t2
          x  = t3

Order of evaluation is now explicit, and every intermediate value has a name. That name is exactly what an optimizer needs in order to say 'this value is used twice' or 'this value is never used'.

§2Lowering expressions

Lowering is a tree walk that returns the *name* of where the result lives, and emits instructions as a side effect.

# pseudocode
def lower_expr(e):
    match e:
        Literal(v):     return Const(v)
        Variable(n):    return var(n)
        Binary(l, op, r):
            a = lower_expr(l)
            b = lower_expr(r)
            t = new_temp()
            emit(t, op, a, b)
            return t
        Call(f, args):
            vals = [lower_expr(a) for a in args]
            t = new_temp()
            emit_call(t, lower_expr(f), vals)
            return t

The recursion order produces left-to-right evaluation, matching the Twig semantic rule, because lower_expr(l) always emits its instructions before lower_expr(r).

§3Lowering control flow

Structured if and while become labels and jumps.

while (i < n) { s = s + i; i = i + 1; }

L_top:   t1 = i < n
         branch t1, L_body, L_end
L_body:  s = s + i
         i = i + 1
         jump L_top
L_end:   ...

if is similar, with a branch to the two arms and a shared label after. Short-circuit operators also become branches, so the 'skip the right side' rule is now just a jump. for was already desugared to while, break becomes jump L_end, and return becomes a ret instruction.

def lower_while(cond, body):
    top, body_l, end = new_label(), new_label(), new_label()
    place(top)
    c = lower_expr(cond)
    emit_branch(c, body_l, end)
    place(body_l); lower_stmt(body); emit_jump(top)
    place(end)
The key insight Lowering makes everything the interpreter did implicitly (evaluation order, temporaries, loops) explicit as data. Once it is data, you can analyze and change it.

§4Common Mistakes

MistakeWhat HappensFix
Reusing one temporary for several valuesLater analysis cannot tell the values apart, and bugs appear in optimizationCreate a fresh temporary for every result
Evaluating arguments right to left because it's convenientOutput order changes for side effects, breaking the language rulesLower in the order the spec requires, and test it
Lowering and/or as plain operatorsThe right side runs even when it should be skippedLower them to a branch that skips the right side
Practice
  1. Lower x = f(a + 1) * g(b); to three-address code, naming every temporary.
  2. Lower if (a and b) { ... } else { ... } to labels and branches, showing why no single and instruction is needed.
Key takeaways
  • Three-address code has one operator per instruction and names every intermediate value.
  • Lowering returns the location of each result and emits instructions in evaluation order.
  • Structured control flow becomes labels, jumps, and branches.
