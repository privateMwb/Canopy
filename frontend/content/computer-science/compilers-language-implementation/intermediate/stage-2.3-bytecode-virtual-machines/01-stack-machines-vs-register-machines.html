Stack Machines vs. Register Machines

Stack machines and register machines are two designs for a VM's instructions, trading simpler code generation against fewer instructions to run.

§1Stack machines

A stack machine keeps temporaries on a stack. Instructions pop their operands and push their result, so they rarely need to name anything.

source:  print a * b + c;

PUSH a
PUSH b
MUL            # pops b, a; pushes a*b
PUSH c
ADD            # pops c, a*b; pushes sum
PRINT

Instructions are tiny, because most carry no operands, and code generation is almost a direct post-order walk of the AST. That is why stack VMs are the usual first choice.

§2Register machines

A register machine has numbered slots (virtual registers) and instructions name them explicitly.

MUL  r3, a, b        # r3 = a * b
ADD  r4, r3, c       # r4 = r3 + c
PRINT r4

Each instruction is larger, because it names its operands, but there are fewer of them. Three-address IR from Stage 2.2 maps onto this form almost directly.

  • Stack machine: simple compiler, compact code, more instructions per expression (many pushes and pops).
  • Register machine: more complex compiler (it must assign registers), larger instructions, fewer dispatches per operation.

Since the main cost in a VM is the dispatch of each instruction (next lesson), fewer instructions can be noticeably faster. Several real VMs moved from stack to register designs for that reason.

§3Choosing for Twig

For this course we build a stack VM first. It is the shortest path to a working system and makes the compiler easy to write and debug.

# per-expression code generation for a stack VM
def emit_expr(e):
    match e:
        Literal(v):  emit(PUSH_CONST, add_constant(v))
        Binary(l, op, r):
            emit_expr(l); emit_expr(r); emit(OPCODE_FOR[op])

Later, in the optimization stage and at Senior level, the register-based IR and the machine code back end take over the roles where register machines shine. The two styles are not rivals so much as tools for different layers.

The key insight A stack VM trades a bigger instruction count for a simpler compiler. A register VM does the reverse. Neither is better in general, so pick based on what is hardest to get right in your project.

§4Common Mistakes

MistakeWhat HappensFix
Assuming the stack machine must have a real stack of all valuesYou think compile-time evaluation order is limited by itThe stack is just where temporaries live; the compiler can reason about its depth
Choosing a register VM without a register allocator planRegisters get assigned in ad hoc ways and frames get hugeAllocate registers per function and reuse them once values die
Comparing speed by instruction count onlyYou miss dispatch cost and memory trafficMeasure on real programs
Practice
  1. Write stack-machine and register-machine code for x = (a + b) * (a - b); and count instructions in each.
  2. Say which style makes it easier to implement constant folding in the compiler, and why.
Key takeaways
  • Stack machines use implicit operands; register machines name them.
  • Stack code is simpler to generate; register code is shorter to run.
  • Twig's VM starts as a stack machine; register-style IR returns in later stages.
