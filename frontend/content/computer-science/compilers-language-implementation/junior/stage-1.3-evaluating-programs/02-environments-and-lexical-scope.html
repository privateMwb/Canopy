Environments & Lexical Scope

Variables live in environments, and a chain of environments is what makes nested scopes and shadowing work.

§1An environment is a map with a parent

To evaluate a variable we need to find its value. An environment is a table from names to values, plus a link to the enclosing environment.

struct Env { vars: Map<string, Value>, parent: Env? }

def define(env, name, value):  env.vars[name] = value

def lookup(env, name):
    e = env
    while e != nil:
        if name in e.vars: return e.vars[name]
        e = e.parent
    runtime_error("undefined variable '" + name + "'")

Looking up a name searches the innermost environment first, then each parent in turn. The first match wins, which is exactly lexical scoping: a name means the nearest enclosing declaration.

§2Blocks create scopes

Entering a block { ... } creates a fresh environment whose parent is the current one. Leaving the block throws it away.

        Let(name, init):
            define(env, name, eval(init))          # declares in the CURRENT scope

        Assign(name, value):
            assign(env, name, eval(value))         # finds an EXISTING variable

        Block(stmts):
            inner = Env(parent = env)
            for s in stmts: exec(s, inner)

def assign(env, name, v):
    e = env
    while e != nil:
        if name in e.vars: e.vars[name] = v; return
        e = e.parent
    runtime_error("assignment to undeclared variable '" + name + "'")

Declaration and assignment are different operations. let always creates a variable in the current scope. = searches outward for one that already exists.

§3Shadowing

An inner let with the same name hides the outer one for the rest of that block, without changing it.

let a = 1;
{
  let a = 2;       // shadows the outer a
  print a;         // 2
}
print a;           // 1

Because the inner block has its own environment, the outer a was never touched. Throwing the inner environment away on exit restores the old meaning automatically.

The key insight Scoping is not a special mechanism. It falls out of one rule: look in this environment, then its parent, then its parent's parent.

Practice
  1. Write a Twig program with three nested blocks that each declare x, and predict what each print x; outputs.
  2. Decide what let a = a; should do inside a block when an outer a exists, and implement your answer.
Key takeaways
  • An environment maps names to values and links to its parent.
  • Blocks and function calls each get a new environment; leaving them discards it.
  • let declares in the current scope, while assignment searches outward for an existing name.
