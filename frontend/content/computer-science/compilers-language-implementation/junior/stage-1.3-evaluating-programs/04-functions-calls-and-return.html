Functions, Calls & Return

A function call evaluates its arguments, binds them to parameters in a fresh environment, runs the body, and hands back whatever return produced.

§1Function values

In Twig, functions are values. Declaring one creates a function object and stores it in a variable.

struct Function { name, params, body, closure: Env }

        FnDecl(name, params, body):
            f = Function(name, params, body, closure = env)
            define(env, name, f)

The closure field records the environment where the function was defined. We will need it in the next lesson. For now it is just the scope the body should start from.

§2Calling

A call has four steps: evaluate the callee, evaluate each argument left to right, check the count, and run the body in a new environment.

        Call(callee, args):
            f = eval(callee)
            if not is_function(f): runtime_error("can only call functions")
            values = [eval(a) for a in args]               # left to right
            if len(values) != len(f.params):
                runtime_error("expected " + len(f.params) + " arguments")
            call_env = Env(parent = f.closure)
            for (p, v) in zip(f.params, values): define(call_env, p, v)
            try:
                exec_block(f.body, call_env)
            catch ReturnSignal as r:
                return r.value
            return nil                                     # fell off the end

A function that reaches the end without return produces nil, one of the language rules we fixed up front.

§3Return and the call stack

return is a non-local exit, like break, but it can leave several nested blocks and loops at once.

        Return(expr):
            v = eval(expr) if expr != nil else nil
            raise ReturnSignal(v)

Each Twig call becomes one host-language call to eval, so Twig's call stack lives on the host's stack. This makes recursion work with no extra effort, and also means that very deep Twig recursion overflows the host stack.

fn fact(n) { if (n <= 1) { return 1; } return n * fact(n - 1); }
print fact(5);       // 120

A real implementation tracks a call depth and raises a clean 'stack overflow' error at a fixed limit instead of letting the host crash.

Connection to later stages The call environment here becomes the stack frame of a bytecode VM in Stage 2.3, and the frame layout you choose there is exactly what a calling convention fixes in Stage 3.1.

§4Common Mistakes

MistakeWhat HappensFix
Starting the call environment from the caller's scopeThe body sees the caller's local variables (dynamic scoping)Parent the new environment on the function's closure, not the current env
Not checking argument countMissing parameters are undefined or extra arguments silently ignoredCheck len(args) against len(params) and raise an error
Using a plain return in the host without a signalreturn inside a nested loop or block only exits that inner partThrow ReturnSignal and catch it in the call
Practice
  1. Write a recursive Twig function that sums an array's first n elements (use a[i] once Stage 1.4 is done, or pass numbers for now), and trace the environments created for sum(3).
  2. Add a call-depth counter to the call code and raise a Twig error at depth 200.
Key takeaways
  • A function value pairs parameters and a body with the environment it was defined in.
  • A call evaluates arguments, creates a fresh environment, runs the body, and catches return.
  • Limit call depth so deep recursion is a clean error, not a host crash.
