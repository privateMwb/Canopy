Control Flow & Loops

If, while, and for are tree walks that decide which children to evaluate and how many times.

§1if and while

Control flow is where evaluation stops being 'evaluate all the children.' An if evaluates its condition, then only one branch.

        If(cond, then, other):
            if truthy(eval(cond)):   exec(then, env)
            elif other != nil:       exec(other, env)

        While(cond, body):
            while truthy(eval(cond)):
                exec(body, env)

truthy follows the Twig rule: only false and nil are falsy. Everything else, including 0 and the empty string, counts as true.

§2for is just while

Rather than teach the interpreter a new loop, the parser can desugar a for into a while. This is a common trick: reduce a new construct to ones the interpreter already handles.

for (let i = 0; i < 3; i = i + 1) { print i; }

# becomes
{
  let i = 0;
  while (i < 3) {
    print i;
    i = i + 1;
  }
}

Now the interpreter has no For node at all. The cost: errors and debugger output mention code the programmer didn't write, so spans on the desugared nodes should still point at the original for.

§3break

break has to leave the innermost loop from anywhere inside it, possibly through nested blocks. The interpreter's recursion makes this awkward, so a simple approach is to signal it with a special exception (or a flag in the result).

        Break:     raise BreakSignal()

        While(cond, body):
            try:
                while truthy(eval(cond)):
                    exec(body, env)
            catch BreakSignal:
                pass

return (next lesson) uses the same trick. Both are non-local exits: control jumps out through several levels of recursion to a place that has been waiting for it.

The key insight Control flow in a tree-walker is borrowed from the host language: Twig's while is the host's while. That is easy to write now, and it is exactly the thing a bytecode VM has to build from scratch in Stage 2.3.

§4Common Mistakes

MistakeWhat HappensFix
Treating 0 or "" as falsePrograms written for other languages' rules behave differently from the Twig specImplement truthy exactly as specified: only false and nil are falsy
Catching break outside the loop that owns itA break in an inner loop exits an outer one tooCatch the signal at the nearest enclosing While
Desugaring for without a new scopeThe loop variable leaks into the code after the loopWrap the desugared pieces in a block
Practice
  1. Write Twig programs that print the numbers 1 to 20 skipping multiples of 3, once with while and once with for.
  2. Add continue: say how you would implement it as a signal, and what it should do in a desugared for loop so the step still runs.
Key takeaways
  • if and while evaluate children conditionally or repeatedly; truthy decides.
  • Desugaring turns for into while so the interpreter stays small.
  • break and return are non-local exits implemented as signals caught by the owning construct.
