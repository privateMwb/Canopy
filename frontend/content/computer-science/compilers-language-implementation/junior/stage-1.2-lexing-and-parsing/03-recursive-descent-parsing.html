Recursive Descent Parsing

Recursive descent turns each grammar rule into a function, so the parser's structure matches the grammar's structure line for line.

§1One function per rule

Recall the layered expression grammar from Stage 1.1. A recursive descent parser gives each rule a function. A rule that mentions another rule becomes a call to that rule's function.

expr   = term   { ( "+" | "-" ) term } ;
term   = factor { ( "*" | "/" ) factor } ;
factor = NUMBER | "(" expr ")" ;

becomes

def expr():
    left = term()
    while check(PLUS) or check(MINUS):
        op = advance()
        right = term()
        left = Binary(left, op, right)
    return left

def term():
    left = factor()
    while check(STAR) or check(SLASH):
        op = advance()
        right = factor()
        left = Binary(left, op, right)
    return left

def factor():
    if match(NUMBER): return Literal(previous().value)
    if match(LEFT_PAREN):
        e = expr()
        expect(RIGHT_PAREN, "expected ')'")
        return e
    error("expected expression")

The while loop plus left = Binary(left, ...) is what makes 1 - 2 - 3 group as (1 - 2) - 3.

§2The four helpers

Almost every parser is built from the same small helpers over the token list.

def peek():     return tokens[pos]
def advance():  pos += 1; return tokens[pos - 1]
def check(t):   return peek().type == t
def match(t):   # consume only if it is the one we want
    if check(t): advance(); return true
    return false
def expect(t, msg):
    if check(t): return advance()
    error(peek(), msg)

peek is the lookahead. Deciding what to do from one token is called LL(1) parsing, and Twig's grammar is designed so that one token is enough almost everywhere.

§3Statements and the top level

Statements work the same way, with the first token choosing the rule.

def statement():
    if match(PRINT):  return print_stmt()
    if match(IF):     return if_stmt()
    if match(WHILE):  return while_stmt()
    if match(LEFT_BRACE): return Block(block_body())
    return expression_stmt()

def if_stmt():
    expect(LEFT_PAREN, "expected '(' after 'if'")
    cond = expr()
    expect(RIGHT_PAREN, "expected ')' after condition")
    then = statement()
    other = statement() if match(ELSE) else nil
    return If(cond, then, other)

def program():
    stmts = []
    while not check(EOF): stmts.append(declaration())
    return stmts

Because every rule is a function, the call stack is the parse. Nested parentheses mean nested calls.

The key insight If you can write the grammar, you can write the parser. Keep the two in sync and the parser stays easy to read, test, and extend.

§4Common Mistakes

MistakeWhat HappensFix
Using left = term() once instead of a loopOnly one operator is parsed; 1 + 2 + 3 leaves a stray tokenLoop while the next token is an operator at this level
Making a rule call itself first, like expr = expr + termInfinite recursion, since no token is consumed before the recursive callRewrite left recursion as a loop
Forgetting to consume the closing tokenThe next rule sees ) or ; and reports a confusing errorUse expect for every delimiter
Practice
  1. Add while statements to the sketch, including the parenthesised condition and a statement body.
  2. Trace 1 - 2 - 3 through expr, term, and factor, writing out the Binary tree built at each step.
Key takeaways
  • Each grammar rule becomes one function, and nested rules become nested calls.
  • Repetition in a rule becomes a loop that builds the tree to the left.
  • peek, advance, match, and expect are enough to build the whole parser.
