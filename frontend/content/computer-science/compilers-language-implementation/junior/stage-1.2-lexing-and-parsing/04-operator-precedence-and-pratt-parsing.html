Operator Precedence & Pratt Parsing

A Pratt parser handles all operator precedence with one function and a table of binding powers, instead of one grammar rule per level.

§1The problem with layers

With layered rules, Twig's ten precedence levels need ten nearly identical functions, and adding an operator means adding a level. Pratt parsing replaces them with one loop and a number per operator.

Each operator gets a binding power: how strongly it pulls on its neighbours. The higher the number, the tighter it binds.

or         10
and        20
== !=      30
< <= > >=  40
+ -        50
* / %      60
unary - not 70

§2One function for all of expressions

parse_expr(min_bp) parses an expression, stopping when it sees an operator that binds more loosely than min_bp.

def parse_expr(min_bp):
    left = prefix()                        # a literal, name, '(', or unary operator
    while true:
        op = peek()
        bp = INFIX_BP.get(op.type)
        if bp is nil or bp < min_bp: break
        advance()
        right = parse_expr(bp + 1)         # +1 makes the operator left-associative
        left = Binary(left, op, right)
    return left

def prefix():
    t = advance()
    match t.type:
        NUMBER: return Literal(t.value)
        IDENT:  return Variable(t.lexeme)
        MINUS, NOT: return Unary(t, parse_expr(UNARY_BP))
        LEFT_PAREN:
            e = parse_expr(0); expect(RIGHT_PAREN); return e

Start with parse_expr(0) and everything binds. The recursion into parse_expr(bp + 1) is the key step: it parses the right-hand side only as far as operators that bind tighter than this one.

§3Tracing 1 + 2 * 3

parse_expr(0)
  left = 1
  see '+' (50 >= 0) → right = parse_expr(51)
        left = 2
        see '*' (60 >= 51) → right = parse_expr(61) = 3
        left = Binary(2 * 3)
        see ';' → stop
  left = Binary(1 + (2 * 3))

For a right-associative operator (like exponentiation in some languages) recurse with parse_expr(bp) instead of bp + 1, so an equal operator on the right is absorbed by the inner call. Twig has none, but your own extensions may.

The key insight Precedence becomes data. Adding an operator is one line in a table, not a new function, and associativity is the difference between bp and bp + 1.

§4Common Mistakes

MistakeWhat HappensFix
Recursing with parse_expr(bp) for ordinary operators1 - 2 - 3 becomes 1 - (2 - 3)Use bp + 1 for left associativity
Starting the top-level call with a high min_bpLoose operators like or are never parsedCall parse_expr(0) from the top
Giving unary minus and binary minus the same entry-2 * 3 parses wrongly, or the table gets confusedKeep a separate prefix table and give unary operators high binding power
Practice
  1. Trace -a * b + c through parse_expr(0), writing out each call and the final tree.
  2. Add a right-associative ** operator to the table and show that 2 ** 3 ** 2 groups as 2 ** (3 ** 2).
Key takeaways
  • A binding power per operator replaces a grammar rule per precedence level.
  • parse_expr(min_bp) stops at any operator that binds more loosely than min_bp.
  • Left or right associativity is just bp + 1 versus bp in the recursive call.
