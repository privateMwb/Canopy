Relational Databases & SQL Basics

Tables, queries, and why databases exist.

§1Why Not Just Use a File?

Your server's memory vanishes when the process restarts, and a JSON file breaks the moment two requests write at once. A database is software built to store data durably, let many clients read and write it concurrently, and answer questions about it quickly. A relational database such as PostgreSQL, MySQL, or SQLite organizes data into tables of rows and columns, with relationships between tables, and you talk to it in SQL.

CREATE TABLE users (
  id         SERIAL PRIMARY KEY,
  email      TEXT NOT NULL UNIQUE,
  name       TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE notes (
  id      SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  title   TEXT NOT NULL,
  body    TEXT NOT NULL DEFAULT ''
);

Each table has a primary key that uniquely identifies a row. The REFERENCES clause is a foreign key: the database itself refuses a note whose user_id does not exist. Rules enforced by the database cannot be forgotten by application code.

§2The Four Core Operations

-- Create
INSERT INTO users (email, name) VALUES ('ada@example.com', 'Ada');

-- Read
SELECT id, title FROM notes
WHERE user_id = 1 AND title ILIKE '%sql%'
ORDER BY id DESC
LIMIT 10;

-- Update
UPDATE notes SET title = 'SQL basics' WHERE id = 3;

-- Delete
DELETE FROM notes WHERE id = 3;
The most dangerous missing line An UPDATE or DELETE without a WHERE clause affects every row in the table. Write the WHERE first, and consider running a SELECT with the same condition to preview what will change.

§3Joining Tables

Because related data lives in separate tables, you combine it at query time with a JOIN. An INNER JOIN keeps only rows with a match on both sides; a LEFT JOIN keeps every row from the left table and fills in NULL where there is no match.

SELECT u.name, n.title
FROM users u
JOIN notes n ON n.user_id = u.id
WHERE u.email = 'ada@example.com';

-- Count notes per user, including users with none
SELECT u.name, COUNT(n.id) AS note_count
FROM users u
LEFT JOIN notes n ON n.user_id = u.id
GROUP BY u.id, u.name;

A final habit: NULL means "unknown," and it is not equal to anything, including itself. Test for it with IS NULL, never = NULL.

§4Common Mistakes

MistakeWhat HappensFix
UPDATE or DELETE with no WHEREEvery row is changed or removedPreview with SELECT, and run risky statements inside a transaction
Using SELECT * in application codeFetches unneeded columns and breaks when the schema changesList the columns you actually need
Comparing with = NULLThe condition is never true, so rows silently go missingUse IS NULL / IS NOT NULL
Practice
  1. Install PostgreSQL (or use SQLite), create the two tables above, insert two users and four notes, and write a query listing each user with their note titles.
  2. Write a LEFT JOIN query that finds users who have no notes at all.
  3. Try inserting a note with a user_id that does not exist, and read the error message.
Key takeaways
  • Databases give you durability, concurrent access, and fast queries that files and memory cannot.
  • Tables, primary keys, and foreign keys let the database itself enforce your data's rules.
  • SELECT, INSERT, UPDATE, DELETE, and JOIN cover most day-to-day work; always scope changes with a WHERE.
