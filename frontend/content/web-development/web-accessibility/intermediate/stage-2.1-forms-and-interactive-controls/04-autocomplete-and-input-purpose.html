Autocomplete & Input Purpose

Typing is hard for many people, and harder still when you must remember a password or retype something you already gave. The right attributes let browsers, password managers, and assistive tools do the work.

§1The autocomplete Attribute

The autocomplete attribute tells the browser what kind of data a field expects, so it can offer to fill it. It also lets assistive technology identify the purpose of a field, for example to show an icon for it. This is WCAG 1.3.5, Identify Input Purpose (Level AA), and it applies to fields that collect information about the user.

<label for="given">First name</label>
<input id="given" name="given" autocomplete="given-name">

<label for="mail">Email</label>
<input id="mail" name="mail" type="email" autocomplete="email" inputmode="email">

Choose the right type too. type="email", type="tel", and inputmode bring up the correct keyboard on mobile devices, which saves effort for everyone.

§2Accessible Authentication

Logins are a common failure point. WCAG 2.2 Success Criterion 3.3.8 (Accessible Authentication, Minimum, Level AA) says that a step in authentication must not require a cognitive function test, such as remembering a password, solving a puzzle, or transcribing characters, unless there is an alternative or a mechanism that helps.

  • Allow password managers to fill fields: use correct autocomplete values and do not interfere with them.
  • Allow paste into password fields. Blocking paste is a common anti-pattern that breaks password managers.
  • Offer alternatives such as passkeys, email links, or an authenticator app.
  • If you use CAPTCHA, provide an alternative that does not rely on solving a puzzle.
<label for="user">Username</label>
<input id="user" name="user" autocomplete="username">

<label for="pass">Password</label>
<input id="pass" name="pass" type="password" autocomplete="current-password">

<!-- Bad: blocks password managers and paste -->
<input type="password" onpaste="return false" autocomplete="off">

§3Redundant Entry

WCAG 2.2 Success Criterion 3.3.7 (Redundant Entry, Level A) says that information a user has already entered in the same process should not have to be typed again. Either fill it in automatically or let the user pick it. Exceptions cover security (such as confirming a new password), essential re-entry, and information that is no longer valid.

<!-- Shipping and billing: offer to reuse what was already entered -->
<label>
  <input type="checkbox" id="same" checked>
  Billing address is the same as shipping
</label>

Multi-step checkouts and long applications are the usual offenders. Carry values forward between steps, and avoid asking for the same detail twice.

The key insight Each of these features removes work: less typing, less memorizing, less repeating. They help people with motor and cognitive disabilities, and they help everyone on a phone.

Practice
  1. Look at a checkout form. Add the right autocomplete values for each field and test that your browser autofills them.
  2. Review a login flow against 3.3.8. Does it allow a password manager, paste, and a non-puzzle alternative?
Key takeaways
  • Use autocomplete tokens and the right input types so browsers and assistive tools know each field's purpose.
  • Authentication must not depend on memorizing or transcribing, unless an alternative or helper exists. Allow paste and password managers.
  • Do not make users re-enter information they already provided in the same process.
