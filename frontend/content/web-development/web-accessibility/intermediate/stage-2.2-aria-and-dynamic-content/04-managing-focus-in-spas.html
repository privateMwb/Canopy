Managing Focus in SPAs

In a single-page app, navigation swaps content without a page load. Browsers normally announce a new page and reset focus. In an SPA, nothing does that for you unless you write it.

§1What Goes Wrong on a Route Change

When a link in a single-page app changes the view, the old content disappears and new content appears. A sighted user sees the change. A screen reader user hears nothing, and their keyboard focus may still sit on a link that no longer exists, which drops it back to the top of the document.

A good route change does three things: updates the document title, moves focus somewhere meaningful, and gives assistive technology a clue that the page changed.

function onRouteChange(pageTitle) {
  document.title = pageTitle + ' – Trailhead';      // 1. announce via the title

  const h1 = document.querySelector('main h1');
  h1.setAttribute('tabindex', '-1');                // 2. make the heading focusable
  h1.focus();                                        // ...and move focus to it
}

Focusing the main heading is a widely used pattern. It announces the new page title, and the next Tab press continues from the start of the new content. Some frameworks include a built-in route announcer, so check what yours does and test it rather than assuming.

§2Dialogs, Menus, and Removals

The same logic applies inside a page. Whenever you open, close, or remove something, decide where focus should go.

EventWhere focus should go
Open a dialogInto the dialog, usually its heading or first control
Close a dialogBack to the element that opened it
Delete an item from a listThe next item, or the list heading if it was the last
Open a menuThe first item (or the menu itself)
Show an error summaryThe summary, so it is announced
let lastFocused;

function openPanel(panel) {
  lastFocused = document.activeElement;   // remember where we were
  panel.hidden = false;
  panel.querySelector('h2').focus();      // h2 has tabindex="-1"
}

function closePanel(panel) {
  panel.hidden = true;
  lastFocused.focus();                    // restore
}

§3Loading States and Back Navigation

Asynchronous loading needs communicating too. Use a live region to say that content is loading and when it has arrived, and aria-busy on a region that is mid-update.

<div id="results" aria-busy="false"></div>
<p role="status" id="load-status"></p>

<script>
  async function search(q) {
    results.setAttribute('aria-busy', 'true');
    loadStatus.textContent = 'Loading results…';
    const html = await fetchResults(q);
    results.innerHTML = html;
    results.setAttribute('aria-busy', 'false');
    loadStatus.textContent = results.children.length + ' results loaded';
  }
</script>

Finally, honor the browser's back and forward buttons: restore scroll position, and place focus sensibly on the previous view, since users expect these to behave like ordinary page navigation.

The key insight A page load gives free behavior: a new title, focus reset to the top, and an announcement. In an SPA, you must recreate each of those on purpose.

§4Common Mistakes

MistakeWhat HappensFix
Changing the view with no title update and no focus moveScreen reader users do not know the page changedUpdate document.title and focus the new main heading
Letting focus fall to body after deleting somethingUsers lose their place and restart from the topMove focus to the next logical element
Not restoring focus when a dialog closesUsers must tab from the top againReturn focus to the element that opened it
Practice
  1. In a single-page app you have built or used, navigate between two routes with a screen reader. What is announced? Add a title update and a focus move.
  2. Add a delete button to a list, and decide where focus should go after each deletion, including when the last item is removed.
Key takeaways
  • In SPAs, update the document title and move focus to a meaningful element on each route change.
  • Always decide where focus goes when opening, closing, or removing UI, and restore it when you close.
  • Announce loading and results with live regions and aria-busy.
