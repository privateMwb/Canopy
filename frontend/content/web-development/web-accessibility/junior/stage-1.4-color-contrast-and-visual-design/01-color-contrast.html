Color Contrast

Text that looks fine to you on a bright monitor can be unreadable to someone with low vision, an aging eye, or a phone in sunlight. Contrast is measured, not guessed, and it is one of the easiest barriers to fix.

§1The Contrast Ratio

Contrast ratio compares the relative luminance of two colors, on a scale from 1:1 (identical) to 21:1 (black on white). WCAG sets minimums for different kinds of content.

ContentMinimum ratioWCAG criterion
Normal text4.5:11.4.3 Contrast (Minimum), AA
Large text (at least 24px, or 18.66px bold)3:11.4.3 Contrast (Minimum), AA
UI components and graphics (borders, icons, focus rings, chart elements)3:11.4.11 Non-text Contrast, AA
Normal text, enhanced7:11.4.6 Contrast (Enhanced), AAA

Large text is allowed a lower ratio because bigger letterforms are easier to read. Logos, purely decorative elements, and disabled controls are exempt, but placeholder text and text over images are not.

§2Measuring and Fixing

You never need to compute ratios by hand. Browser DevTools show the ratio when you inspect a color, and tools like the WebAIM Contrast Checker and the Colour Contrast Analyser accept any two colors.

/* On a white background */
.text-ok      { color: #767676; }   /* 4.54:1 passes AA for normal text */
.text-fail    { color: #777777; }   /* 4.48:1 just misses AA */
.text-better  { color: #595959; }   /* 7.0:1 passes AAA */

/* UI boundaries need 3:1 too */
input { border: 1px solid #767676; }  /* the field edge must be perceivable */

To fix a failure, adjust the lightness of one color, usually darkening text or lightening a dark background, until it passes. Work this into your design tokens so every use inherits the fix.

§3Tricky Cases

A handful of situations cause most contrast failures in practice:

  • Text on images or gradients. Measure against the worst spot behind the text, or add a solid or semi-opaque overlay.
  • Placeholder text. It is text, so it must also meet 4.5:1. Never use placeholder as the only label.
  • Hover and focus states. Each state is its own color pair. Check them all.
  • Brand colors. A brand color may not be usable for text on white. Use it for large areas or darker variants for text.
  • Icon-only buttons and chart lines. Meaningful graphics need 3:1 against their surroundings.
/* Semi-opaque overlay to guarantee legible text on a photo */
.hero { position: relative; }
.hero::before {
  content: "";
  position: absolute; inset: 0;
  background: rgb(0 0 0 / 0.55);
}
.hero h1 { position: relative; color: #fff; }
The key insight Pick accessible colors at the design-token level, once, rather than checking each screen. A palette where every text and background pairing is pre-approved prevents most contrast bugs before they exist.

§4Common Mistakes

MistakeWhat HappensFix
Light gray text on white "for elegance"Low-vision users and anyone in glare cannot read itCheck every pair and meet 4.5:1 for normal text
Checking only the default stateHover, focus, and disabled-looking states fail unnoticedTest every state of every interactive element
Forgetting borders and iconsInputs and icon buttons become invisibleMeet 3:1 for UI components and meaningful graphics
Practice
  1. Open DevTools on a real site and use its color picker to find the contrast ratio of body text, a link, and a placeholder. Which fail?
  2. Choose a brand color that fails on white as text. Find the nearest darker shade that passes 4.5:1, and note both hex values.
Key takeaways
  • Normal text needs 4.5:1, large text 3:1, and UI components and meaningful graphics 3:1.
  • Measure with DevTools or a contrast checker, and fix by adjusting lightness.
  • Check every state, backgrounds behind images, and placeholder text, and bake accessible pairs into design tokens.
