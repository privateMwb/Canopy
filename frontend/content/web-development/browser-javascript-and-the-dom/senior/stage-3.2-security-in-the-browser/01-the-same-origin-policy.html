The Same-Origin Policy

The same-origin policy is the browser's most important security rule. Almost every browser security mechanism, from CORS to CSP to cookie flags, is either built on it or a controlled exception to it.

§1What Is Isolated

An origin is the triple of scheme, host, and port. The same-origin policy (SOP) says that content from one origin cannot read data from another. It exists so that a malicious page you visit cannot read your webmail in another tab, even though your browser holds your logged-in cookies for it.

ResourceCross-origin: embedding / sendingCross-origin: reading
fetch / XMLHttpRequestAllowed to send (subject to preflight)Blocked unless CORS allows
<img>, <script>, <link>, <video>Allowed to loadContent not readable by script (except scripts execute)
<iframe>Allowed to embed (unless blocked by headers)Blocked: no access to its DOM
CookiesSent with matching requests (SameSite rules)Scoped by host and path, not by port
localStorage, IndexedDBn/aIsolated per origin

Notice the pattern: the browser lets a page send many kinds of cross-origin requests, but denies the reading of responses. That is why attacks like CSRF (forging a request) remain possible even with SOP, and why they need separate defenses.

§2The Controlled Exceptions

Legitimate sites sometimes need to share across origins. The platform provides explicit, opt-in mechanisms, each of which relaxes SOP in a narrow way:

MechanismWhat it allowsWho opts in
CORS (Access-Control-Allow-Origin)Reading specific cross-origin responsesThe server
postMessageMessaging between windows/frames/workersThe receiver (by listening and validating)
document.domain (deprecated)Relaxing to a parent domainBoth sides (being removed)
<script src> / JSONPRunning third-party code with full page privilegesThe embedding page (dangerous)
// safe postMessage: always check the sender's origin and validate the data
window.addEventListener("message", (e) => {
  if (e.origin !== "https://widgets.example.com") return;   // never trust "*"
  if (typeof e.data?.height !== "number") return;           // validate the shape
  frame.style.height = e.data.height + "px";
});

// sending: name the exact target origin
frame.contentWindow.postMessage({ type: "ready" }, "https://widgets.example.com");

Including a third-party <script> is the largest hole in SOP by design: that script runs as your origin, with access to your DOM, cookies (non-HttpOnly), and storage. This is why third-party scripts are a security decision, not just a performance one.

§3Related Boundaries

SOP is complemented by newer, finer-grained isolation features, which matter for a growing set of powerful APIs:

  • Site vs. origin: a.example.com and b.example.com are different origins but the same site. SameSite cookies and some features key off *site*, not origin.
  • Cross-Origin-Opener-Policy (COOP) and Cross-Origin-Embedder-Policy (COEP) isolate your page from other windows; together they enable *cross-origin isolation*, needed for SharedArrayBuffer.
  • Cross-Origin-Resource-Policy (CORP) lets a server forbid other origins from loading its resources at all.
  • Site Isolation puts different sites in different OS processes, protecting against speculative-execution attacks like Spectre.
  • X-Frame-Options / frame-ancestors stop other sites from framing yours, preventing clickjacking.
// response headers for a hardened app
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Resource-Policy: same-site
Content-Security-Policy: frame-ancestors 'none'
Read vs. send The most useful mental model: SOP blocks reading across origins, not sending. Any defense you design must account for the requests an attacker's page can still make with the victim's cookies.

§4Common Mistakes

Practice
  1. For five URL pairs, decide whether they are same-origin, same-site, or cross-site and explain each decision.
  2. Build two pages on different ports that exchange data with postMessage, validating origin and shape on receipt.
  3. Try to read an <iframe>'s DOM across origins in the console and record the exact error.
Key takeaways
  • SOP lets pages send many cross-origin requests but blocks reading responses and DOM across origins.
  • CORS, postMessage, and script inclusion are the opt-in exceptions; each demands careful handling.
  • Origin, site, and isolation headers (COOP/COEP/CORP) are different boundaries; know which one a feature uses.
