The DOM Tree

The browser turns your HTML into a tree of objects. Understanding that tree, and the difference between nodes and elements, is the foundation for everything else in this subject.

§1From HTML to Objects

The Document Object Model (DOM) is the browser's in-memory representation of the page. When it parses HTML it creates one object per piece of the document and connects them in a tree. Your script reads and changes those objects, and the browser re-renders when they change.

<body>
  <h1 id="title">Hello</h1>
  <ul>
    <li>One</li>
    <li>Two</li>
  </ul>
</body>

// resulting tree
// body
// ├─ h1#title ── "Hello"
// └─ ul
//    ├─ li ── "One"
//    └─ li ── "Two"

The tree is not the same thing as your source file. The parser fixes broken markup (adding a missing <tbody> inside a <table>, for example), and scripts change it after load. Inspect the Elements panel, not View Source, to see the real DOM.

§2Nodes vs. Elements

Everything in the tree is a node. There are several kinds, and the two you meet constantly are element nodes (tags) and text nodes (the characters inside them). Whitespace between tags is also a text node, which surprises many beginners.

Node typeExamplenodeType
Element<li>1
Text"One"3
Comment<!-- note -->8
Documentdocument9

Because of those stray text nodes, the node-based properties and the element-based properties give different answers:

const ul = document.querySelector("ul");

ul.childNodes.length   // includes whitespace text nodes
ul.children.length     // only the <li> elements: 2

ul.firstChild          // may be a text node
ul.firstElementChild   // the first <li>

In nearly all UI code you want the Element versions: children, firstElementChild, nextElementSibling, parentElement.

§3Walking the Tree

Every node knows its neighbours, so you can move around without searching:

const li = document.querySelector("li");

li.parentElement           // the <ul>
li.nextElementSibling      // the second <li>
li.previousElementSibling  // null: it is first
li.closest("ul")           // nearest ancestor matching a selector
li.textContent             // "One"

Everything inherits from Node: an HTMLLIElement is an HTMLElement, which is an Element, which is a Node. That is why textContent works on every node and classList only on elements.

Live structure, not a copy The DOM is a live object graph, not a snapshot of your HTML. Changing it in script changes what the user sees immediately, and the original HTML file is never touched.

§4Common Mistakes

MistakeWhat HappensFix
Using firstChild and getting a blank text nodeThe code reads "\n " instead of the elementUse firstElementChild or children[0]
Reading View Source to debug a dynamic pageYou see the original HTML, not the current DOMUse the Elements panel in DevTools
Treating children like an arraychildren.map is not a functionConvert with Array.from(el.children)
Assuming the parser keeps your HTML exactlyMissing tags are added, misnested tags are rearrangedValidate your HTML and trust the Elements panel
Practice
  1. Write a small page with a nested list. In the console, print childNodes.length and children.length of the outer <ul> and explain the difference.
  2. Starting from one <li>, reach the heading above the list using only parentElement and sibling properties.
  3. Add an HTML comment inside the list and find it by checking nodeType.
Key takeaways
  • The DOM is a live tree of objects the browser builds from your HTML.
  • Elements are one kind of node; text and comments are nodes too, so prefer the *Element* properties.
  • Use the Elements panel to see the real tree, not View Source.
