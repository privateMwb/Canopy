Debugging in DevTools

DevTools is the browser's built-in workshop. Knowing the Elements, Console, Sources, and Network panels turns a mystery into a short, repeatable investigation.

§1The Elements Panel

The Elements panel shows the live DOM, not your original HTML. Click any node to see the CSS rules applying to it (and which ones are overridden), its box model, and its event listeners. You can double-click text or attributes to edit them and see the effect immediately.

  • Right-click a node and choose Break on → subtree modifications to pause whenever script changes it.
  • Use $0 in the Console to refer to the element currently selected in the panel.
  • Toggle the :hover or :focus state from the Styles pane to debug states that vanish when you move the mouse.

§2Breakpoints and the Sources Panel

console.log is quick, but a breakpoint lets you stop the program and inspect every variable at that moment. Open the Sources panel, click a line number, and reload or trigger the code. Execution pauses on that line.

ControlDoes
Resume (F8)Run until the next breakpoint
Step over (F10)Run this line, skipping into function calls
Step into (F11)Go inside the function being called
Step out (Shift+F11)Finish the current function and return to the caller

While paused, hover over a variable to see its value, read the Scope pane, and look at the Call Stack to see how you got here. You can also add watch expressions and conditional breakpoints (right-click the line number), which only pause when an expression is true.

function total(items) {
  let sum = 0;
  for (const item of items) {
    debugger;               // pauses here when DevTools is open
    sum += item.price * item.qty;
  }
  return sum;
}

§3Logging Effectively

When you do log, make the output easy to read. Label values, use the right level, and use the structured helpers.

console.log({ user, count });       // shows names with values
console.table(rows);                // arrays of objects as a table
console.group("render");
console.log("start");
console.groupEnd();
console.time("sort");
sort(data);
console.timeEnd("sort");            // sort: 12.4 ms
console.assert(items.length > 0, "items is empty");

The Network panel is the other essential tool: it lists every request with status, timing, headers, and response body, so you can tell at a glance whether a failure is in your code or on the server.

A repeatable method Reproduce the bug, find the first place where the actual value differs from the expected one, then work backward from there. A breakpoint a few lines before the symptom is almost always better than guessing.

§4Common Mistakes

MistakeWhat HappensFix
Logging console.log(user) for an object that changes laterThe console shows the latest state, which can misleadLog a copy: console.log(structuredClone(user))
Leaving debugger statements in committed codePauses for anyone who opens DevToolsRemove them before you commit; lint for them
Debugging minified code without source mapsCryptic names and one giant lineEnable source maps or debug the unminified build
Ignoring red errors at the top of the consoleLater errors are just fallout from the first oneFix the first error before anything else
Practice
  1. Write a function with an off-by-one bug, then find it using only breakpoints and the Scope pane.
  2. Set a conditional breakpoint that fires only when a loop variable equals 7.
  3. Use the Network panel to find which request on a page is slowest, and read its response headers.
Key takeaways
  • The Elements panel shows the live DOM; the Sources panel lets you pause and inspect.
  • Breakpoints, step controls, and watch expressions beat scattering console.log calls.
  • When logging, label values and use table, group, and time for readable output.
