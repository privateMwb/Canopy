Tooling: npm, Vite & Formatting

Modern front-end projects share a standard setup: npm for packages, a dev server and bundler like Vite, and automatic formatting. Getting comfortable with it removes a lot of friction.

§1npm and package.json

npm installs libraries and runs project scripts. Every project has a package.json describing it, and npm install <name> adds a dependency to it and downloads the code into node_modules/ (which you never commit).

npm init -y                 # create package.json
npm install dayjs           # runtime dependency
npm install -D vite         # dev-only tool
npm run dev                 # run a script defined in package.json

{
  "scripts": { "dev": "vite", "build": "vite build", "preview": "vite preview" },
  "dependencies": { "dayjs": "^1.11.0" },
  "devDependencies": { "vite": "^5.0.0" }
}

package-lock.json records the exact versions installed. Commit it, so every machine and the CI server get identical dependencies. The ^ in a version means "compatible updates are allowed".

§2Vite: Dev Server and Build

Vite is a development server and build tool. In development it serves your modules directly with near-instant reloads and hot module replacement. For production it bundles, minifies, and fingerprints your files.

npm create vite@latest my-app -- --template vanilla
cd my-app
npm install
npm run dev        # http://localhost:5173
npm run build      # outputs optimized files to dist/

// main.js: bare imports now work because Vite resolves them
import dayjs from "dayjs";
import "./style.css";                       // CSS can be imported too
console.log(dayjs().format("YYYY-MM-DD"));

Vite also handles environment variables (import.meta.env.VITE_API_URL), a dev-server proxy for avoiding CORS during development, and deployment-ready output in dist/, which you upload to any static host.

§3Formatting and Linting

Agree on style by machine, not by argument. Prettier reformats code consistently on save or commit, and ESLint catches likely bugs such as unused variables and missing await. They solve different problems, so use both.

npm install -D prettier eslint

npx prettier --write .        # format everything
npx eslint src                # report problems

// package.json
{ "scripts": { "format": "prettier --write .", "lint": "eslint src" } }

Add .gitignore entries for node_modules/ and dist/, configure your editor to format on save, and consider a pre-commit hook so unformatted code never lands. Keep dependencies few: every package is code you did not write, will have to update, and that may carry vulnerabilities (npm audit reports known ones).

Reproducible beats clever A new teammate should be able to run npm install and npm run dev and have a working app. Commit package.json and the lockfile, document the scripts, and avoid steps that only work on your machine.

§4Common Mistakes

MistakeWhat HappensFix
Committing node_modules/Huge repository, platform-specific filesAdd it to .gitignore; commit the lockfile instead
Putting build tools in dependenciesBloated production installsUse npm install -D for dev-only tools
Deleting package-lock.json to "fix" problemsVersions drift between machinesKeep it; use npm ci for clean, exact installs
Adding a package for a one-line jobMore code to audit and updateUse the platform, or write the few lines yourself
Practice
  1. Create a Vite vanilla project, install dayjs, and display a formatted date.
  2. Add Prettier and a format script; deliberately break the formatting and fix it with one command.
  3. Run npm run build, open dist/ and note the file names and sizes; then run npm audit.
Key takeaways
  • package.json lists dependencies and scripts; commit the lockfile, not node_modules/.
  • Vite provides a fast dev server and an optimized production build.
  • Prettier formats and ESLint catches bugs: automate both so style is never a debate.
