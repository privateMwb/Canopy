Bubbling, Capturing & Delegation

Events do not stay on the element where they happen: they travel through the tree. Once you understand that path, one well-placed listener can handle hundreds of elements, including ones that do not exist yet.

§1The Three Phases

When you click an element, the browser dispatches the event along the path from the top of the document down to the target and back up again, in three phases:

  1. Capturing: from window down through each ancestor to the target.
  2. Target: the event arrives at the element itself.
  3. Bubbling: back up through the ancestors to window.

By default, listeners run during the bubbling phase. That is why a click on a button inside a <div> also triggers a click listener on the <div>, then on <body>, then on document.

outer.addEventListener("click", () => console.log("outer (bubble)"));
inner.addEventListener("click", () => console.log("inner (bubble)"));
outer.addEventListener("click", () => console.log("outer (capture)"), true);

// click inner -> outer (capture), inner (bubble), outer (bubble)

Passing true or { capture: true } registers the listener for the capturing phase instead. You rarely need this, but it is useful for intercepting an event before the target sees it. Note that a few events, such as focus and blur, do not bubble.

§2Event Delegation

Because events bubble, you can attach one listener to a parent and decide inside it which child was the target. This is event delegation, and it has two big advantages: far fewer listeners, and it automatically works for children added later.

const list = document.querySelector("#todos");

// without delegation: a listener per item, and new items need their own
list.querySelectorAll("button.delete").forEach((b) =>
  b.addEventListener("click", remove));

// with delegation: one listener, works for items added later
list.addEventListener("click", (e) => {
  const btn = e.target.closest("button.delete");
  if (!btn || !list.contains(btn)) return;      // click was elsewhere
  btn.closest("li").remove();
});

closest() is the key tool. It walks up from e.target and returns the nearest element matching the selector, so it still works when the user clicks an icon or <span> inside the button.

§3When Not to Delegate

Delegation is a default, not a rule. It is a poor fit for events that do not bubble (focus, blur, mouseenter, scroll on elements), though focusin and focusout are bubbling alternatives. It also adds a small cost to every event in that subtree, so do not put a heavy listener on document for something that fires constantly such as mousemove.

form.addEventListener("focusin", (e) => {
  e.target.closest(".field")?.classList.add("active");
});
form.addEventListener("focusout", (e) => {
  e.target.closest(".field")?.classList.remove("active");
});
One listener, many elements Delegation moves the decision from "which elements have a listener?" to "what was clicked?" It scales with no extra code and survives re-rendering, which is why frameworks use it internally.

§4Common Mistakes

MistakeWhat HappensFix
Checking e.target === button when the button contains an iconClicks on the icon are missedUse e.target.closest("button")
Delegating focus or blurThe listener never fires: they do not bubbleUse focusin and focusout
Not verifying the match is inside the containerA closest hit outside your list triggers the handlerCheck container.contains(match)
Putting stopPropagation() in a child handlerDelegated listeners above it never see the clickRemove it and filter in the parent
Practice
  1. Add three nested elements with listeners at each level and predict, then verify, the log order. Repeat with capture: true on the outermost.
  2. Rebuild a to-do list so that one listener on the <ul> handles delete buttons for every item, including those added later.
  3. Add a data-action attribute to buttons and dispatch to different functions from a single delegated handler.
Key takeaways
  • Events capture down, hit the target, then bubble up; listeners run on the way up by default.
  • Delegation uses one parent listener plus target.closest() to serve many, including future, children.
  • Some events do not bubble: use their bubbling counterparts or attach directly.
