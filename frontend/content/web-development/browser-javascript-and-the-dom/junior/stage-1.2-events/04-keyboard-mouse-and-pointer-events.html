Keyboard, Mouse & Pointer Events

Input events tell you what the user is doing with a keyboard, mouse, finger, or pen. Choosing the right event and reading it correctly keeps your interface usable for everyone.

§1Keyboard Events

keydown fires when a key is pressed (and repeats while held); keyup fires on release. Use event.key for the character or key name and event.code for the physical key position. Avoid the deprecated keyCode, and avoid keypress.

document.addEventListener("keydown", (e) => {
  if (e.key === "Escape") closeDialog();

  if ((e.ctrlKey || e.metaKey) && e.key === "s") {
    e.preventDefault();        // stop the browser's Save dialog
    save();
  }
  if (e.repeat) return;        // ignore auto-repeat while held
});

Keyboard events go to the focused element, so a listener on a <div> does nothing unless the div can take focus (tabindex="0"). Do not take over keys that people expect to behave normally, and do not ignore keyboard users: every action available by mouse must also be available from the keyboard.

§2Mouse Events

The common mouse events are click, dblclick, mousedown, mouseup, mousemove, mouseenter/mouseleave (do not bubble), and mouseover/mouseout (bubble). The event reports where the pointer is in several coordinate systems.

PropertyMeasured from
clientX, clientYThe visible viewport
pageX, pageYThe whole document (includes scroll)
offsetX, offsetYThe target element's edge
buttonWhich button: 0 left, 1 middle, 2 right
canvas.addEventListener("mousemove", (e) => {
  const rect = canvas.getBoundingClientRect();
  const x = e.clientX - rect.left;     // position inside the canvas
  const y = e.clientY - rect.top;
  drawDot(x, y);
});

§3Pointer Events: One API for Everything

Touch screens, pens, and mice all produce pointer events: pointerdown, pointermove, pointerup, pointercancel, plus pointerenter and pointerleave. Writing one set of handlers works across devices, which is better than handling mouse* and touch* separately.

const area = document.querySelector("#drag");
let dragging = false;

area.addEventListener("pointerdown", (e) => {
  dragging = true;
  area.setPointerCapture(e.pointerId);   // keep receiving events even outside
});
area.addEventListener("pointermove", (e) => {
  if (dragging) moveTo(e.clientX, e.clientY);
});
area.addEventListener("pointerup", () => { dragging = false; });
area.addEventListener("pointercancel", () => { dragging = false; });

pointerType tells you whether the input was "mouse", "touch", or "pen". For touch interactions you usually also need the CSS property touch-action: none on the element, or the browser will treat the drag as a scroll and cancel your events.

Do not forget the keyboard If you build a clickable <div>, you have to add focus, key handling, and a role yourself. A real <button> gives you click, Enter, Space, and focus for free, so start there.

§4Common Mistakes

MistakeWhat HappensFix
Using keyCode or keypressDeprecated, inconsistent across browsersUse keydown with event.key
Listening for keys on a non-focusable <div>The handler never firesAdd tabindex="0" or listen on document
Handling only mouse* eventsThe interface is dead on touch devicesUse pointer events
Forgetting pointercancelThe element stays stuck in a dragging stateReset state on pointerup and pointercancel
Practice
  1. Add keyboard shortcuts to a page (/ to focus search, Escape to close a panel) and ignore them while the user types in an input.
  2. Write a draggable box using pointer events and setPointerCapture; test it with a mouse and a touch screen or emulator.
  3. Log clientX/pageX/offsetX as you move over a scrolled page and explain how each differs.
Key takeaways
  • Use keydown with event.key; keyboard events go to the focused element.
  • Mouse coordinates come in client, page, and offset flavors: choose the one that matches your task.
  • Pointer events cover mouse, touch, and pen in a single API.
