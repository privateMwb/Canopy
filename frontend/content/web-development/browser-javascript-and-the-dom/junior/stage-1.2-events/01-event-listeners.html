Event Listeners

Pages become interactive when you react to things the user does. addEventListener is the one mechanism for that, and how you write and remove listeners affects both correctness and memory.

§1addEventListener

An event is a signal that something happened: a click, a key press, a finished download, a form submission. A listener is a function the browser calls when that event occurs on an element.

const btn = document.querySelector("#save");

function onSave(event) {
  console.log("saved", event.type);
}

btn.addEventListener("click", onSave);   // pass the function, do not call it

You can add many listeners for the same event on the same element and they run in the order added. Passing onSave() instead of onSave calls the function immediately and registers its return value, which is one of the classic beginner mistakes.

You may also see btn.onclick = fn or an inline onclick="..." attribute. These work, but onclick allows only one handler and inline attributes mix behavior into markup, so prefer addEventListener.

§2Handlers, this, and Arrow Functions

A handler is just a function. Inside a regular function handler, this is the element the listener is attached to. Inside an arrow function, this is whatever it was where the arrow was written. Using event.currentTarget is clearer in both cases.

btn.addEventListener("click", function (e) {
  this.classList.toggle("on");               // this === e.currentTarget
});

btn.addEventListener("click", (e) => {
  e.currentTarget.classList.toggle("on");    // explicit and works everywhere
});

Arrow functions are convenient but anonymous, which matters for the next section: you cannot remove a listener unless you still have a reference to the exact same function.

§3Removing Listeners and Options

removeEventListener needs the same event type and the same function reference that you added. An inline arrow function creates a new function each time, so it cannot be removed later.

btn.addEventListener("click", onSave);
btn.removeEventListener("click", onSave);   // works

btn.addEventListener("click", () => doIt());
btn.removeEventListener("click", () => doIt());   // does nothing: different function

The third argument takes options. Two are especially useful: once removes the listener after it runs the first time, and signal lets you remove many listeners at once with an AbortController.

btn.addEventListener("click", showWelcome, { once: true });

const ctrl = new AbortController();
window.addEventListener("resize", onResize, { signal: ctrl.signal });
window.addEventListener("scroll", onScroll, { signal: ctrl.signal });

ctrl.abort();   // removes both listeners

Remember to remove listeners you add to long-lived objects such as window or document when the part of the page that needed them goes away. Otherwise they keep running and keep their closed-over variables alive.

Pass the function, do not call it addEventListener("click", handler) registers the function. addEventListener("click", handler()) runs it right now and registers undefined. Look for the parentheses when a handler fires at page load.

§4Common Mistakes

MistakeWhat HappensFix
Writing addEventListener("click", doIt())doIt runs immediately; nothing happens on clickPass doIt without parentheses
Removing with a new inline arrow functionThe listener is never removedKeep the function in a variable, or use an AbortController signal
Assigning el.onclick = ... twiceThe second handler silently replaces the firstUse addEventListener, which stacks handlers
Adding listeners on window and never removing themHandlers pile up and leak memoryRemove them, or abort via signal
Practice
  1. Write a button that increments a counter shown on the page, using addEventListener.
  2. Make a button that works only once using the once option, then reimplement it with removeEventListener.
  3. Register three listeners with one AbortController and remove them all with a single call.
Key takeaways
  • addEventListener(type, fn) is the standard way to respond to events; pass the function itself.
  • To remove a listener you need the same function reference, or use once or an AbortSignal.
  • Clean up listeners on long-lived targets so they do not accumulate.
