Cancellation & Timeouts

Users type, click, and navigate faster than the network answers. AbortController lets you cancel work you no longer need, and a few habits prevent stale responses from overwriting fresh ones.

§1AbortController

An AbortController creates a signal you pass to an operation. Calling controller.abort() tells that operation to stop. fetch supports this directly: the promise rejects with an AbortError.

const controller = new AbortController();

fetch("/api/search?q=dom", { signal: controller.signal })
  .then((res) => res.json())
  .then(render)
  .catch((err) => {
    if (err.name === "AbortError") return;     // expected: not a real failure
    showError(err);
  });

controller.abort();         // cancel the request

Always treat AbortError separately from genuine errors; cancelling is something you chose, so you normally do not want an error message for it. A controller is single-use: after abort(), create a new one for the next operation.

§2Avoiding Stale Responses

Imagine a search box: the user types "d", then "do", then "dom". Three requests go out, but the network may answer them out of order. If the response for "d" arrives last, it overwrites the right results. The fix is to cancel the previous request each time a new one starts.

let current;                                  // the in-flight controller

async function search(q) {
  current?.abort();                           // cancel the previous request
  current = new AbortController();
  try {
    const res = await fetch(`/api/search?q=${encodeURIComponent(q)}`, {
      signal: current.signal,
    });
    render(await res.json());
  } catch (err) {
    if (err.name !== "AbortError") showError(err);
  }
}

input.addEventListener("input", (e) => search(e.target.value));

If an API does not support cancellation, use a request token instead: store an incrementing id, and ignore any response whose id is not the latest.

let latest = 0;
async function search(q) {
  const id = ++latest;
  const data = await getResults(q);
  if (id !== latest) return;      // a newer search started: drop this result
  render(data);
}

§3Timeouts and Combined Signals

fetch has no built-in timeout. The platform provides helpers that produce signals for you: AbortSignal.timeout(ms) aborts after a delay, and AbortSignal.any([...]) combines several signals so that either the user or the clock can cancel.

try {
  const res = await fetch("/api/report", { signal: AbortSignal.timeout(5000) });
  show(await res.json());
} catch (err) {
  if (err.name === "TimeoutError") showError("The server took too long.");
  else if (err.name === "AbortError") return;
  else throw err;
}

const userCancel = new AbortController();
const signal = AbortSignal.any([userCancel.signal, AbortSignal.timeout(5000)]);
fetch("/api/export", { signal });

The same signal works for more than fetch: you can pass it to addEventListener to remove listeners, check signal.aborted in your own loops, or listen for its abort event to clean up.

Cancel, then ignore the cancel error Every new request in a type-ahead should cancel the last one. Catch AbortError quietly, so that cancelling stays invisible to the user.

§4Common Mistakes

MistakeWhat HappensFix
Showing an error when a request is abortedFlashing error messages during normal typingIgnore err.name === "AbortError"
Reusing an aborted controllerEvery later request is immediately abortedCreate a new AbortController per operation
No timeout on requestsThe UI waits indefinitely on a stalled networkUse AbortSignal.timeout(ms)
Relying on arrival order of responsesStale results overwrite fresh onesAbort previous requests or compare request ids
Practice
  1. Add AbortController cancellation to a search box and confirm in the Network panel that earlier requests are cancelled.
  2. Add a 3-second timeout and show a distinct message for timeouts versus network failures.
  3. Implement the request-token version for a function that cannot be aborted, and test it with randomized delays.
Key takeaways
  • AbortController and its signal cancel fetch, listeners, and your own async code.
  • Cancel the previous request when a new one starts, and treat AbortError as expected.
  • Use AbortSignal.timeout for deadlines and AbortSignal.any to combine reasons to stop.
