IntersectionObserver & ResizeObserver

Observers let the browser tell you when something changes, instead of you polling or listening to scroll constantly. They power lazy loading, infinite scroll, and components that adapt to their own size.

§1IntersectionObserver

IntersectionObserver reports when an element enters or leaves the viewport (or another container). The browser computes this efficiently off your scroll handlers, so it is far cheaper than listening to scroll and calling getBoundingClientRect.

const observer = new IntersectionObserver(
  (entries) => {
    for (const entry of entries) {
      if (entry.isIntersecting) {
        console.log("visible:", entry.target.id, entry.intersectionRatio);
      }
    }
  },
  { root: null, rootMargin: "200px", threshold: [0, 0.5, 1] }
);

document.querySelectorAll(".card").forEach((el) => observer.observe(el));
// observer.unobserve(el);  observer.disconnect();
  • root: the scrolling container to measure against (null means the viewport).
  • rootMargin: grows or shrinks the root box; "200px" fires before the element is actually visible.
  • threshold: which visible fractions trigger the callback (0 = any pixel, 1 = fully visible).

§2Lazy Loading and Infinite Scroll

For images, the platform now offers loading="lazy" natively, which should be your first choice. IntersectionObserver is for everything else: loading content, starting animations, or tracking what has been seen.

// lazy-load images once they are close to the viewport
const io = new IntersectionObserver((entries, obs) => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    e.target.src = e.target.dataset.src;
    obs.unobserve(e.target);               // done with this one
  }
}, { rootMargin: "300px" });
document.querySelectorAll("img[data-src]").forEach((img) => io.observe(img));

// infinite scroll: observe a sentinel at the bottom of the list
const sentinel = document.querySelector("#sentinel");
new IntersectionObserver(async ([entry]) => {
  if (entry.isIntersecting) await loadNextPage();
}).observe(sentinel);

Remember to unobserve elements you are finished with, and to give images explicit width and height (or an aspect-ratio) so the page does not jump when they load.

§3ResizeObserver

ResizeObserver fires when an element's own size changes, regardless of the cause: the window resizing, a sidebar collapsing, content loading, or a parent changing. It makes component-level responsiveness possible, which media queries (based on the viewport) cannot do.

const ro = new ResizeObserver((entries) => {
  for (const { target, contentRect } of entries) {
    target.classList.toggle("compact", contentRect.width < 400);
  }
});
ro.observe(document.querySelector(".panel"));

// canvas that matches its container
new ResizeObserver(([entry]) => {
  const { width, height } = entry.contentRect;
  canvas.width = width * devicePixelRatio;
  canvas.height = height * devicePixelRatio;
  redraw();
}).observe(canvas.parentElement);

Avoid changing the observed element's size from inside its own callback in a way that triggers another resize, or you will get a "ResizeObserver loop" warning. Where CSS can do the job, prefer container queries (@container) over script.

Do not poll, subscribe If you find yourself reading getBoundingClientRect inside a scroll or resize listener, replace it with an observer. The browser batches the work and keeps the main thread free.

§4Common Mistakes

MistakeWhat HappensFix
Measuring position in a scroll handlerForced layout on every event; janky scrollingUse IntersectionObserver
Never calling unobserve/disconnectCallbacks keep firing and hold elements in memoryUnobserve when finished
Lazy-loading images without reserved spaceLayout jumps as images arriveSet width/height or aspect-ratio
Resizing the observed element in its own callbackLoop warnings and flickerAdjust children, or use CSS container queries
Practice
  1. Fade in each card as it scrolls into view using a class toggled by IntersectionObserver.
  2. Build infinite scroll with a sentinel element that loads the next page of data.
  3. Make a panel switch between a compact and a wide layout based on its own width using ResizeObserver.
Key takeaways
  • IntersectionObserver reports visibility changes efficiently, replacing scroll-position polling.
  • ResizeObserver reacts to an element's own size, enabling component-level responsiveness.
  • Always unobserve when done, and reserve space so lazy content does not shift the layout.
