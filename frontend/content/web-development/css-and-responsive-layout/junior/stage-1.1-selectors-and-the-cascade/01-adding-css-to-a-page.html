Adding CSS to a Page

CSS reaches a page three ways, an external stylesheet, a <style> block, or an inline style attribute, and an external file is almost always the right choice.

§1Three Ways to Add CSS

The browser treats all three as the same language; they differ in where the rules live and how reusable they are.

<!-- 1. external stylesheet: best for almost everything -->
<link rel="stylesheet" href="/css/site.css">

<!-- 2. internal style block: fine for a one-off demo or critical CSS -->
<style>
  body { font-family: system-ui, sans-serif; }
</style>

<!-- 3. inline style: highest priority, hardest to maintain -->
<p style="color: #b91c1c;">Warning</p>

An external file is cached by the browser and shared by every page, so a change in one place restyles the whole site.

§2Anatomy of a Rule

A rule has a selector that says what to style and a declaration block of property: value; pairs.

selector {
  property: value;
  another-property: value;
}

h1 {
  color: #15803d;
  font-size: 2rem;
}

Each declaration ends with a semicolon. A missing one makes the browser drop the declaration after it, which is a classic source of "why isn't this working" moments.

§3How the Browser Applies It

The browser downloads the HTML, discovers the <link>, fetches the CSS, and builds a style map before it paints. A stylesheet in the <head> is render-blocking, which is intentional: it prevents a flash of unstyled content.

  • Put <link> elements in the <head>, before scripts that need styles.
  • Keep one main stylesheet while learning; split later when it grows.
  • Use @import rarely; it chains requests and slows loading. Prefer multiple <link>s or a build step.

Comments use /* ... */. CSS has no single-line comment form, and // is not a comment.

Where to put what Use an external stylesheet by default. Reserve inline styles for values computed at runtime (such as a progress bar's width), because they can't be overridden easily and can't be reused.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting the semicolon between declarationsThe next declaration is silently ignoredEnd every declaration with ;
Writing // commentsThe browser parses them as broken rulesUse /* comment */
Styling everything with style="" attributesDuplicated, high-priority rules that are hard to changeMove rules into a stylesheet and use classes
Wrong href path to the stylesheetThe page loads unstyled with a 404 in the Network panelCheck the path relative to the page, or use a root-relative path
Practice
  1. Create index.html and site.css, link them, and change the page's background and text color from the stylesheet.
  2. Break the link path on purpose and find the 404 in DevTools' Network panel.
Key takeaways
  • Link an external stylesheet from the <head> by default.
  • A rule is a selector plus declarations ending in semicolons.
  • CSS comments are /* */ only.
