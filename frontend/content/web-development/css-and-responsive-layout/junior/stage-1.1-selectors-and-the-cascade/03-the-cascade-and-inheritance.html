The Cascade & Inheritance

The cascade is the algorithm that resolves conflicting declarations, and inheritance passes some values from parent to child, so many properties never need to be set twice.

§1How the Cascade Decides

For each property on each element, the browser collects every declaration that applies and sorts them. In rough order of priority:

  1. Origin and importance: user-agent defaults, then author styles; !important flips the order.
  2. Layers: later cascade layers beat earlier ones (covered in a later level).
  3. Specificity: the more specific selector wins.
  4. Source order: the last declaration wins a tie.

This is why it's called *cascading*. You don't write one rule per element; you write general rules and layer more specific ones on top.

§2Inheritance

Some properties are inherited: if you don't set them on an element, it uses its parent's computed value. Typography is the main case: color, font-family, font-size, line-height, and text-align. Layout-related properties such as margin, padding, border, and background are not inherited.

body {
  font-family: system-ui, sans-serif;   /* inherited by everything inside */
  color: #1c1f26;
  line-height: 1.6;
}

.card {
  border: 1px solid #ccc;   /* not inherited by .card's children */
}

Set typography once on body and let it flow down, rather than repeating it on every element.

§3Controlling Inheritance

Four keywords work on any property and give you explicit control.

KeywordMeaning
inheritUse the parent's computed value, even for non-inherited properties
initialReset to the property's spec default
unsetinherit if the property inherits, otherwise initial
revertRoll back to the browser's default styling
a { color: inherit; text-decoration: none; }   /* links take surrounding text color */
button { font: inherit; }                    /* form controls ignore font by default */
Why your button ignores your font Form controls don't inherit font settings by default because the browser gives them their own. A one-line button, input, select, textarea { font: inherit; } fixes it.

§4Common Mistakes

MistakeWhat HappensFix
Setting font and color on every elementRepetition, and changes need edits everywhereSet them on body and let inheritance work
Expecting border or margin to inheritChildren don't get the parent's borderSet them where they are needed, or use inherit deliberately
Reordering rules and being surprisedEqual specificity means the last rule winsKeep related rules together in a predictable order
Practice
  1. Move repeated font-family and color declarations onto body and delete the duplicates.
  2. Make links inherit the color of the surrounding text with color: inherit, and check the result.
Key takeaways
  • The cascade resolves conflicts by origin, specificity, and then order.
  • Typography properties inherit; box properties do not.
  • inherit, initial, unset, and revert give explicit control.
