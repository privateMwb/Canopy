Selectors & Specificity

Selectors choose which elements a rule applies to, and specificity decides which rule wins when several match.

§1The Core Selectors

p { }                  /* type: every <p> */
.card { }               /* class: class="card" */
#main { }               /* id: id="main" */
a[href^="https"] { }    /* attribute: href starts with https */
.card, .panel { }       /* group: either one */
nav a { }               /* descendant: any a inside nav */
ul > li { }             /* child: li directly inside ul */
h2 + p { }              /* adjacent sibling: p right after h2 */
a:hover { }             /* pseudo-class: a state */
p::first-line { }       /* pseudo-element: a part of an element */
li:nth-child(2n) { }    /* structural pseudo-class */

Classes are the workhorse. They are reusable, descriptive, and carry modest specificity. IDs are unique and very strong, which makes them awkward for styling.

§2Calculating Specificity

When two rules set the same property on the same element, the more specific selector wins. Think of specificity as three counters: IDs, then classes (plus attributes and pseudo-classes), then types (plus pseudo-elements). Compare left to right.

SelectorIDsClassesTypesWritten
p0010,0,1
.card p0110,1,1
a:hover0110,1,1
#main .card1101,1,0
nav ul li a0040,0,4

The counts don't overflow: no number of type selectors ever beats one class. 0,0,4 loses to 0,1,0.

§3When Specificity Is Equal

If two selectors tie, the one that appears later in the source wins. Inline styles beat all selectors, and !important beats inline styles, which is why both are a last resort.

.btn { background: gray; }
.btn { background: green; }   /* wins: same specificity, later */

#hero .btn { background: blue; }   /* wins: has an ID */

The universal selector * and the :where() pseudo-class add zero specificity, which makes them handy for gentle defaults.

Keep specificity low and flat Style with single classes wherever you can. A codebase of .card, .card-title, and .btn rarely has specificity fights. A codebase of #page .main ul li a always does.

§4Common Mistakes

MistakeWhat HappensFix
Using IDs for stylingSpecificity so high that only another ID or !important can override itUse classes for styling and keep IDs for fragments and labels
Reaching for !important to win a fightFuture overrides need !important too, and it spreadsFind and fix the specificity cause
Writing long descendant chains (.a .b .c .d)Brittle rules tied to the HTML structureGive the target its own class
Assuming source order always decidesA more specific earlier rule still winsCompare specificity first, then order
Practice
  1. Calculate the specificity of five selectors from a stylesheet you have written, and predict which wins for a shared property.
  2. Rewrite a rule that uses an ID selector so that it uses a class and still behaves the same.
Key takeaways
  • Pick elements with type, class, attribute, and pseudo selectors.
  • Specificity is compared as IDs, then classes, then types, and ties go to the later rule.
  • Prefer flat, class-based selectors and avoid !important.
