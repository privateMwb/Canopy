Linting & Visual Regression Testing

Stylelint catches CSS mistakes and enforces conventions as you type, and screenshot tests catch visual regressions that no linter can see.

§1Stylelint

Stylelint parses CSS and applies rules: invalid properties, duplicate selectors, overly specific selectors, and your own conventions.

npm install --save-dev stylelint stylelint-config-standard
npx stylelint "src/**/*.css"
# .stylelintrc.json
# {
#   "extends": "stylelint-config-standard",
#   "rules": {
#     "selector-max-id": 0,
#     "declaration-no-important": true,
#     "selector-class-pattern": "^[a-z][a-z0-9]*(__[a-z0-9-]+)?(--[a-z0-9-]+)?$"
#   }
# }

Rules like selector-max-id, declaration-no-important, and a class-name pattern turn your team's conventions into automatic checks. Many rules can auto-fix with --fix.

§2Visual Regression Testing

A change can pass every lint rule and still break the look. Screenshot tests render pages or components, then compare them to approved baselines.

// Playwright example
import { test, expect } from "@playwright/test";

test("card matches baseline", async ({ page }) => {
  await page.goto("/components/card");
  await expect(page).toHaveScreenshot("card.png", { maxDiffPixelRatio: 0.01 });
});

Tools include Playwright, Percy, Chromatic, and BackstopJS. Fix the fonts, animations, and dynamic data so that screenshots are deterministic, and run them in a consistent environment such as a container.

§3Putting It in CI

  • Run Stylelint on every pull request, and fail the build on errors.
  • Run screenshot tests for key components and pages at several viewport widths and in both themes.
  • Review diffs as part of code review: update the baseline only when the change is intended.
  • Keep tests few and meaningful. Hundreds of flaky screenshots teach people to ignore failures.

Together these tools make large refactors safer: lint verifies the code, and screenshots prove that the look hasn't changed.

Lint the code, snapshot the look They cover different failure types. A linter can't tell that a margin shifted by 20px, and a screenshot test can't tell that you used !important.

§4Common Mistakes

MistakeWhat HappensFix
Snapshotting pages with live data and animationsFlaky diffs that nobody trustsMock data, freeze animations, and wait for fonts
Updating baselines without reviewingReal regressions get approvedReview every visual diff
Enabling every lint rule on day oneThousands of errors, and the tool is abandonedStart with a small set and add gradually
Practice
  1. Add Stylelint with a no-IDs and no-!important rule to a project and fix the results.
  2. Write a Playwright screenshot test for one component at two viewport widths.
Key takeaways
  • Stylelint enforces CSS conventions and catches errors automatically.
  • Screenshot tests catch visual regressions that linting can't.
  • Run both in CI, with stable test data and reviewed baselines.
