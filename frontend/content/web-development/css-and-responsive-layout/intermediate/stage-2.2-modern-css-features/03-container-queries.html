Container Queries

Container queries let a component adapt to the space it is given, not to the viewport, which makes it reusable in a sidebar, a grid cell, or a full-width hero.

§1The Problem with Viewport Queries

A media query answers "how wide is the window?" But a card in a narrow sidebar and the same card in a wide main column are in the same window. The card should respond to its own container.

§2Declaring a Container and Querying It

Mark an ancestor as a container, then write @container rules that apply to its descendants.

.card-wrap {
  container-type: inline-size;     /* track this element's inline size */
  container-name: card;            /* optional name */
}

.card { display: grid; gap: 1rem; }

@container card (min-width: 32rem) {
  .card { grid-template-columns: 10rem 1fr; }   /* image left, text right */
}

The queried element must be an ancestor of the elements it styles; a container can't restyle itself. Use container: card / inline-size as a shorthand.

§3Container Units and Style Queries

Inside a container, cqw, cqi, and related units are percentages of the container's size, which is great for fluid type within a component.

.card-title { font-size: clamp(1.1rem, 4cqi, 1.75rem); }

@container (min-width: 40rem) and (max-width: 60rem) { .card { padding: 2rem; } }

/* style queries, where supported: respond to a custom property */
@container style(--layout: wide) { .card { grid-template-columns: 1fr 1fr; } }

Size container queries are supported in current browsers. Style queries on custom properties are newer, so check support before depending on them.

Components own their responsiveness With container queries, a component carries its own breakpoints, so a layout can place it anywhere and it still looks right. Page-level media queries then handle only the page frame.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting container-typeThe @container rule never matchesDeclare it on an ancestor
Querying the element's own size from itselfA container can't style itselfQuery a wrapper, and style the children
Using container-type: size casuallyIt requires explicit height and can collapse the elementUse inline-size unless you need both
Practice
  1. Build a card that switches from stacked to side-by-side at a container width of 32rem, and place it in a sidebar and in a main column.
  2. Use cqi units to size a heading relative to its card.
Key takeaways
  • Add container-type: inline-size to an ancestor and use @container to restyle its descendants.
  • Components adapt to available space rather than the viewport.
  • Use container units for fluid type inside components.
