Containment & Rendering Performance

contain and content-visibility tell the browser what can't affect the rest of the page, so it can skip work for what is off-screen or unchanged.

§1CSS Containment

contain promises that an element's internals don't affect the outside, so changes inside it can be handled locally instead of re-laying out the whole page.

ValuePromise
layoutNothing inside affects layout outside; the element is an independent formatting context
paintNothing paints outside its box; descendants are clipped to it
styleCounters and quotes don't escape (rarely useful)
sizeIt doesn't depend on its content for size; you must size it yourself
contentShorthand for layout paint style
strictShorthand for layout paint style size
.widget { contain: content; }
.sidebar { contain: layout paint; }

contain: layout and paint also create stacking contexts and containing blocks for fixed and absolute descendants, so check side effects.

§2content-visibility: auto

For long pages, content-visibility: auto lets the browser skip layout and paint of off-screen sections, rendering them as they approach the viewport.

.article-section {
  content-visibility: auto;
  contain-intrinsic-size: auto 600px;   /* a placeholder size so the scrollbar stays stable */
}

Without contain-intrinsic-size, skipped sections have zero height and the scrollbar jumps as they render. The auto keyword remembers the last real size. Skipped content stays available to find-in-page and the accessibility tree in current browsers.

§3Selector and Style Costs in Context

Real-world selector cost is usually small compared with layout and paint. Still, a few habits help.

  • Keep selectors short, and avoid long descendant chains and heavy :has() use over large trees.
  • Avoid scoping broad style changes high in the tree.
  • Limit large blurred shadows, filters, and backdrop effects on big areas; they're paint-heavy.
  • Use DevTools' Selector Stats (in the Performance panel) to see which selectors cost time.

Containment is a tool for specific, measured problems: long feeds, dashboards of independent widgets, and big off-screen content. Don't apply it globally.

Measure the win Apply content-visibility: auto to a long page and compare Rendering time in a Performance trace. If the gain is small, remove it, because it adds complexity for no benefit.

§4Common Mistakes

MistakeWhat HappensFix
Using contain: size without sizing the elementThe element collapses to zeroProvide explicit dimensions, or avoid it
Using content-visibility: auto with no contain-intrinsic-sizeScrollbar jumps and layout shiftProvide a placeholder size
Applying containment everywhere blindlyUnexpected clipping and stacking contextsTarget specific hot spots
Practice
  1. Add content-visibility: auto to a long article's sections and compare the initial render time before and after.
  2. Apply contain: content to a widget that updates frequently and check how much layout work a change inside it causes.
Key takeaways
  • contain isolates an element's internals so changes stay local.
  • content-visibility: auto skips off-screen rendering; give it contain-intrinsic-size.
  • Apply these to measured hot spots, not everywhere.
