Stacking Contexts & Painting Order

z-index only compares elements within the same stacking context, so most "z-index doesn't work" bugs are really stacking context bugs.

§1What a Stacking Context Is

A stacking context is a self-contained layer. Everything inside it is painted together, as a group, and z-index values inside are compared only against siblings in the same context. A child can never escape its parent's context to go above something outside it.

.header { position: relative; z-index: 1; }
.modal  { position: fixed; z-index: 9999; }   /* inside .app with z-index: 0 ... */
.app    { position: relative; z-index: 0; }   /* ...so .modal is capped by .app's level */

If .header (z-index 1) is a sibling of .app (z-index 0), the header paints above the entire .app subtree, including the modal, no matter how large the modal's number is.

§2What Creates One

  • The root <html> element.
  • position: relative | absolute with a z-index other than auto; fixed and sticky always.
  • A flex or grid child with a z-index other than auto.
  • opacity less than 1.
  • transform, filter, perspective, clip-path, mask, or will-change for those properties.
  • isolation: isolate, mix-blend-mode other than normal, and contain: paint or layout.

The commonly surprising ones are opacity, transform, and filter: adding them to an ancestor can silently trap its descendants' z-index inside.

§3Painting Order and Taming It

Within one stacking context, painting goes from back to front: the context's background, negative z-index children, in-flow block backgrounds, floats, inline content, z-index: auto and 0 positioned elements, then positive z-index children.

/* a deliberate, local context: contain z-index values inside a component */
.card { isolation: isolate; }
.card .badge { z-index: 1; }   /* only compared with other things inside .card */

/* a small named scale instead of 9999 */
:root { --z-sticky: 10; --z-dropdown: 20; --z-modal: 30; --z-toast: 40; }

isolation: isolate is the clean way to create a stacking context on purpose. For overlays like modals, render them with <dialog> and the top layer, which sits above all stacking contexts.

Debug by walking up When z-index fails, walk up the ancestors of both elements, looking for the first property that creates a stacking context. Compare the z-index of those two contexts, not of the elements.

§4Common Mistakes

MistakeWhat HappensFix
Raising z-index to 99999 to winDoesn't help when the problem is a parent's stacking contextFind the ancestor that creates the context
Adding transform or opacity to a wrapper without knowing the effectChildren's z-index becomes trappedCheck for new stacking contexts after such changes
Scattering arbitrary z-index numbers across the codebaseEscalating, unreadable valuesDefine a z-index scale with tokens
Practice
  1. Build a page where a modal with a huge z-index still appears under a header, then fix it by identifying the stacking context.
  2. Replace a hand-rolled modal's z-index with a <dialog> opened with showModal().
Key takeaways
  • z-index only competes within the same stacking context.
  • opacity, transform, filter, and positioned z-index create contexts.
  • Use isolation: isolate, a token scale, and the top layer to keep things predictable.
