The Layout Algorithms

Block, inline, flex, and grid each run a different layout algorithm, and knowing their inputs explains most layout surprises.

§1Block and Inline Formatting

In block layout, boxes stack vertically, each filling the available inline size; height comes from content. In inline layout, text and inline boxes flow into line boxes that wrap at the container's width. Block formatting contexts (BFC) are isolated layout regions: margins don't collapse across their edge, and they contain floats.

.contain-floats { display: flow-root; }   /* creates a BFC without side effects */
/* other triggers: overflow other than visible, display: flex/grid items, position: absolute */

§2Flex Layout, Step by Step

The flex algorithm works in a fixed sequence, which is why min-width: auto and basis matter.

  1. Determine each item's flex base size (from flex-basis, width, or content) and its hypothetical size clamped by min and max.
  2. Collect items into lines (one, or several with wrap).
  3. Resolve flexible lengths: compute free space, then grow or shrink items, freezing any that hit a min or max, and repeat.
  4. Determine cross sizes and align items on the cross axis.
  5. Distribute the lines with align-content.

Shrink is weighted by flex-shrink times base size, so larger items give up more space. A frozen item (clamped by min-width: auto) makes the others absorb the difference.

§3Grid Layout, Track Sizing

Grid sizes its tracks in an explicit algorithm: it resolves fixed sizes first, then sizes auto and intrinsic tracks from their items' contributions, then distributes the rest to fr tracks, and then places items.

Track sizing keywordResolved from
px, % (definite)Immediately
min-content / max-contentThe items' narrowest / widest content
automin-content up to max-content, stretching into free space
frShare of remaining space after everything else
minmax(a, b)A range the algorithm resolves within

This is why 1fr behaves like minmax(auto, 1fr): its minimum is the content's minimum size, and why minmax(0, 1fr) is a better default in content-heavy layouts.

Intrinsic vs. extrinsic sizing Some layouts size items from the container (extrinsic) and others size the container from its contents (intrinsic). Most layout bugs are a mismatch between the two, such as a percentage height with no definite parent height.

§4Common Mistakes

MistakeWhat HappensFix
Expecting percentage height to work with an auto-height parentResolves to auto and does nothingGive the parent a definite height, or use flex or grid sizing
Fighting a flex item that won't shrinkIts automatic minimum size froze itSet min-width: 0 or overflow on the item
Using 1fr for tracks with wide contentTracks expand past their shareUse minmax(0, 1fr)
Practice
  1. Draw by hand how a flex container with three items of different basis and shrink values distributes a deficit of 100px.
  2. Use DevTools' Grid overlay to inspect how auto, fr, and minmax() tracks resolve in a real layout.
Key takeaways
  • Block, inline, flex, and grid are distinct algorithms with defined steps.
  • Flex and grid sizing depend on base sizes, min and max clamps, and content contributions.
  • Intrinsic and extrinsic sizing mismatches cause most surprises.
