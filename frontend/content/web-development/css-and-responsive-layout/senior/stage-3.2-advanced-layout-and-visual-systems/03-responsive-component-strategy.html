Responsive Component Strategy

A modern responsive system uses container queries for components, viewport queries for the page frame, and preference queries for the user, each at its own level.

§1Three Kinds of Queries, Three Jobs

QueryAsksUse it for
Container queryHow much space does my parent give me?Component layout: card, media, toolbar
Media query (width)How big is the viewport?Page frame: nav pattern, columns, sidebar presence
Preference queryWhat does the user prefer or support?prefers-color-scheme, prefers-reduced-motion, prefers-contrast, hover, pointer
Feature queryDoes the browser support this?@supports enhancements

The mistake to avoid is using viewport queries to restyle components: those components break the moment they are placed in a different-width slot.

§2A Layered Component

/* the component adapts to its own container */
.media-card-wrap { container: media-card / inline-size; }

.media-card { display: grid; gap: var(--space-s); }
@container media-card (min-width: 30rem) {
  .media-card { grid-template-columns: 12rem 1fr; }
}

/* the page frame uses the viewport */
@media (min-width: 64em) {
  .page { grid-template-columns: 16rem 1fr; }
}

/* the user's preferences adjust motion and contrast */
@media (prefers-reduced-motion: no-preference) { .media-card { transition: transform .2s; } }
@media (prefers-contrast: more) { .media-card { border-width: 2px; } }
@media (hover: hover) and (pointer: fine) { .media-card:hover { transform: translateY(-2px); } }

Writing motion inside prefers-reduced-motion: no-preference makes calm the default, and motion the opt-in, which is the safer polarity.

§3Rules of Thumb for a System

  • Components declare their own containers and breakpoints, and don't assume where they will be placed.
  • Layouts decide placement and spacing; components don't set their outer margins.
  • Use a small set of shared container breakpoints (for example, 20, 32, 48rem) as tokens.
  • Test each component alone, in a narrow slot, and in a wide slot.
  • Provide fallbacks for container query support only if your browser policy requires it; a single-column default is usually enough.

A component library documents each component's container behavior and shows it in a resizable container, not only at viewport sizes.

Match the query to the question If the answer depends on the parent's space, it's a container question. If it depends on the whole screen or the user's device or settings, it's a media question.

§4Common Mistakes

MistakeWhat HappensFix
Restyling components with viewport media queriesThey break when relocated to a narrow columnUse container queries
Making motion the default and reduced motion the exceptionReduced-motion users may see motion if a rule is missedAdd motion only under no-preference
Hard-coding breakpoints differently in each componentInconsistent responsive behaviorShare breakpoint tokens
Practice
  1. Build a card that works at 18rem, 30rem, and 50rem container widths, and place it in three different layout slots.
  2. Audit a component library for viewport media queries inside components and convert them.
Key takeaways
  • Container queries for components, media queries for the page frame, preference queries for the user.
  • Default to calm; add motion under prefers-reduced-motion: no-preference.
  • Test components in several container widths, not only viewport sizes.
