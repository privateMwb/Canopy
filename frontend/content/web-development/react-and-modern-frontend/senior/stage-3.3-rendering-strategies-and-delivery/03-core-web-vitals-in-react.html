Core Web Vitals in React

Core Web Vitals measure what users actually feel: how fast the main content appears, how quickly the page responds, and whether it jumps around. Each has typical React causes and specific fixes.

§1The Three Metrics

MetricMeasuresGood (75th percentile)Typical React culprit
LCP Largest Contentful PaintWhen the biggest visible element renders≤ 2.5 sClient rendering, slow data, unoptimized hero image, render-blocking JS
INP Interaction to Next PaintDelay from interaction to the next frame, across the visit≤ 200 msHeavy handlers, large re-renders, hydration, long tasks
CLS Cumulative Layout ShiftUnexpected movement of content≤ 0.1Images without dimensions, late-loading content, injected banners, font swaps

Measure in two ways. Lab tools (Lighthouse, DevTools Performance) reproduce problems and diagnose causes. Field data from real users (the web-vitals library, CrUX, your monitoring) tells you whether it matters, on real devices and networks. Always look at the 75th percentile, not the average.

import { onLCP, onINP, onCLS } from "web-vitals/attribution";

function report({ name, value, rating, attribution }) {
  navigator.sendBeacon("/rum", JSON.stringify({
    name, value, rating,
    page: location.pathname,
    // attribution says WHAT was slow: the LCP element, the INP event target, the shifting node
    detail: attribution,
  }));
}
onLCP(report); onINP(report); onCLS(report);

§2Fixing LCP and CLS

LCP is usually a hero image or a heading. The fastest page is one where that element is in the initial HTML and starts loading immediately.

  • Do not client-render the LCP element. If the hero depends on useEffect + fetch, LCP waits for JS, then the API. Server-render or statically generate it.
  • Prioritize the LCP image: <img fetchpriority="high"> and a <link rel="preload" as="image">, never loading="lazy" for above-the-fold images.
  • Optimize images: modern formats (AVIF/WebP), responsive srcset/sizes, correct dimensions, and a CDN. Framework image components automate much of this.
  • Cut render-blocking work: reduce JavaScript before first render, inline critical CSS, preconnect to critical origins.
  • Reduce TTFB with caching and edge rendering, since LCP cannot be earlier than the first byte.
<img src="/hero.avif" alt="..." width="1200" height="630" fetchpriority="high"
     srcset="/hero-600.avif 600w, /hero-1200.avif 1200w" sizes="100vw" />

/* reserve space so late content does not shift the layout (CLS) */
.thumb { aspect-ratio: 16 / 9; width: 100%; }
.ad-slot { min-height: 250px; }
@font-face { font-family: Inter; src: url(/inter.woff2) format("woff2"); font-display: swap; size-adjust: 100%; }

CLS is mostly about reserving space: give images and embeds explicit dimensions or aspect-ratio, use skeletons that match final size, avoid inserting content above existing content, and animate with transform rather than layout properties. In React, watch components that render null first and content later, since they push everything below down when they appear.

§3Fixing INP in React

INP covers the whole interaction: input delay (main thread busy), handler time, and the render and paint that follow. Most React INP problems are too much synchronous work after a click or keystroke.

// keep input urgent; defer the expensive result
const [text, setText] = useState("");
const deferred = useDeferredValue(text);
<input value={text} onChange={(e) => setText(e.target.value)} />
<Results query={deferred} />                          {/* memoized, can lag behind */}

// transitions for navigation and big updates
startTransition(() => setTab("reports"));

// break up long handler work, give feedback first
async function onClick() {
  setBusy(true);                                       // cheap, paints next frame
  await new Promise((r) => setTimeout(r));             // yield to the browser
  heavyWork();
}
  • Profile the interaction in the Performance panel and read the INP breakdown; find the long task and the component that dominates.
  • Shrink re-render scope: move state down, split contexts, use selectors, and let the React Compiler or memo skip unchanged subtrees.
  • Virtualize long lists, and avoid rendering hidden UI.
  • Reduce hydration and third-party JS, which often cause the input delay part of INP.
  • Offload CPU work to a Web Worker, and debounce high-frequency handlers.
  • Set performance budgets in CI (Lighthouse CI) and alert on field regressions after each release.
Fix the biggest metric for real users first Use field data to find which vital fails on which pages and devices, use lab tools to find the cause, and change one thing at a time. A single hero image or one heavy handler is often most of the problem.

§4Common Mistakes

MistakeWhat HappensFix
Lazy loading the hero imageLCP is delayed by deferred loadingUse fetchpriority="high" and no loading="lazy" above the fold
Images and embeds with no dimensionsContent jumps as they load; high CLSSet width/height or aspect-ratio
Fetching the main content in useEffectLCP waits for JS plus the API round tripRender it on the server or at build time
Judging by a fast laptop's Lighthouse scoreReal users on phones fail the vitalsUse field data and CPU throttling
Practice
  1. Add web-vitals with attribution to an app and find the LCP element and the worst INP interaction on a throttled device.
  2. Fix a CLS problem by reserving space for images and a late-loading banner, and confirm with the Layout Shift regions overlay.
  3. Use useDeferredValue or startTransition to bring a slow typing interaction under 200 ms INP.
Key takeaways
  • LCP, INP, and CLS measure loading, responsiveness, and stability, at the 75th percentile of real users.
  • Server-render and prioritize the LCP element; reserve space for everything that loads late.
  • Improve INP by shrinking render work, deferring non-urgent updates, and cutting hydration and long tasks.
