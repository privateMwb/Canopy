Code Splitting & Lazy Loading

Every user downloads your whole bundle unless you split it. React.lazy and dynamic imports load code only when it is needed, which speeds up the first visit.

§1lazy and Suspense

lazy() takes a function returning a dynamic import() and returns a component whose code is fetched the first time it renders. While it loads, the nearest <Suspense> boundary shows its fallback. Your bundler turns each dynamic import into a separate file (a chunk).

import { lazy, Suspense } from "react";

const Chart = lazy(() => import("./Chart"));          // Chart must be a default export

function Dashboard() {
  const [showChart, setShowChart] = useState(false);
  return (
    <>
      <button onClick={() => setShowChart(true)}>Show chart</button>
      {showChart && (
        <Suspense fallback={<p>Loading chart...</p>}>
          <Chart />
        </Suspense>
      )}
    </>
  );
}

For a named export, adapt it: lazy(() => import("./charts").then((m) => ({ default: m.BarChart }))). Define lazy() calls at the top level of a module, not inside components, or they are recreated each render and reload.

§2Where to Split

Split where the user will not need the code right away. The best candidates are large and conditional.

  • Routes (the biggest win): each page is its own chunk, loaded when the user navigates there.
  • Heavy, rarely used features: rich text editors, charts, PDF viewers, maps, code highlighters.
  • Modals and drawers that open on a click.
  • Admin or role-specific areas that most users never open.
  • Large libraries used in one place: import them dynamically instead of at the top of the file.
// route-level splitting with React Router
const router = createBrowserRouter([
  { path: "/", element: <Home /> },
  { path: "/reports", lazy: () => import("./routes/reports") },     // router-native lazy route
  { path: "/settings", Component: lazy(() => import("./routes/Settings")) },
]);

// a heavy library loaded only when needed
async function exportPdf(data) {
  const { generatePdf } = await import("./pdf");                    // separate chunk
  return generatePdf(data);
}

Do not split everything. Tiny components are not worth a network request, and too many chunks create waterfalls and loading flashes. Keep the above-the-fold content in the main bundle.

§3Preloading and Measuring

The cost of lazy loading is a delay the first time. You can hide it by preloading when the user signals intent: on hover, on focus, or after the main content is idle.

const loadSettings = () => import("./routes/Settings");
const Settings = lazy(loadSettings);

<Link to="/settings" onMouseEnter={loadSettings} onFocus={loadSettings}>Settings</Link>

// preload after the page is idle
requestIdleCallback(() => loadSettings());

// avoid a flash of fallback when switching between already-loaded views
const [isPending, startTransition] = useTransition();
startTransition(() => navigate("/settings"));      // keeps current UI until the chunk is ready
  • Measure with a bundle analyzer (rollup-plugin-visualizer or vite-bundle-visualizer) before and after, so you know what actually moved.
  • Check the Network panel to confirm chunks load on demand, not at startup.
  • Pair lazy components with an error boundary: a chunk can fail to load (offline, new deploy), and the user needs a retry.
  • After a new deploy, an old tab may request chunk files that no longer exist; handle the failure by prompting a reload.
  • Use skeleton fallbacks that match the final layout to avoid layout shift.
Ship less on the first visit The fastest code is code the user never downloads. Split by route first, then split heavy features, and measure the result rather than trusting intuition.

§4Common Mistakes

MistakeWhat HappensFix
Calling lazy() inside a componentComponent remounts and reloads every renderDefine lazy at module top level
Lazy loading a tiny componentA network request that costs more than it savesSplit only large or rarely used code
No error boundary around lazy componentsA failed chunk load blanks the pageWrap in an error boundary with a retry
Lazy loading the main above-the-fold contentSlower first paint with a spinnerKeep critical UI in the main bundle
Practice
  1. Convert each route of an app to a lazily loaded component, and confirm separate chunks in the build output.
  2. Open the bundle analyzer, find the largest dependency, and move it behind a dynamic import.
  3. Add preloading on link hover and measure how much faster the navigation feels with throttled network.
Key takeaways
  • lazy plus Suspense loads components on demand; each dynamic import becomes a chunk.
  • Split routes first, then heavy, rarely used features; avoid over-splitting.
  • Preload on intent, handle chunk-load failures, and measure with a bundle analyzer.
