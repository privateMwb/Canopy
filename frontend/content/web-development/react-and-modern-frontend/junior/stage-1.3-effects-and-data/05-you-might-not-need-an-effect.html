You Might Not Need an Effect

Effects are easy to overuse. Most of what beginners put in an effect is better calculated during render or done in an event handler, and removing the effect makes the code shorter and the UI more correct.

§1Derive Values During Render

If a value can be calculated from props or state, calculate it while rendering. Do not copy it into state and synchronize it with an effect. That approach renders twice (once with the stale value, once with the updated one) and creates a state that can fall out of sync.

// unnecessary effect and extra state
const [fullName, setFullName] = useState("");
useEffect(() => {
  setFullName(`${first} ${last}`);
}, [first, last]);

// just calculate it
const fullName = `${first} ${last}`;

// filtering a list: derive, do not store
const visible = todos.filter((t) => !t.done);

// expensive? React Compiler or useMemo can cache it (see the intermediate level)
const total = items.reduce((sum, i) => sum + i.price, 0);

The same applies to filtered lists, counts, formatted strings, and selected items. The rule: if you can compute it from what you already have, do not store it.

§2Use Event Handlers for User Actions

If something happens *because the user did something*, do it in the event handler. An effect cannot tell why a value changed, so using one for a user action splits cause and effect across two places and can fire at the wrong times (for example, on first load).

// effect watching for a "submitted" flag
useEffect(() => {
  if (submitted) post("/api/order", cart);
}, [submitted]);

// do it where the cause is
function handleBuy() {
  post("/api/order", cart);
  showToast("Order placed");
}

Effects are for synchronizing with external systems because the component is on screen (connecting to a chat room, a subscription, a timer). Event handlers are for responding to what the user did.

§3Other Patterns to Avoid

SmellBetter
Effect that sets state from other stateDerive it during render
Effect to reset state when a prop changesGive the component a key so it remounts: <Profile key={userId} />
Effect that calls a parent callback after state changesCall the callback in the same event handler
Chain of effects that each set state for the nextCompute everything in one handler or during render
Effect that fetches data on every change with manual cachingA data library (TanStack Query) or framework loader
Effect to subscribe to an external storeuseSyncExternalStore
// reset state when the user changes: use a key, not an effect
function ProfilePage({ userId }) {
  return <Profile key={userId} userId={userId} />;      // new key = fresh state
}

// adjust state during render only in rare cases; usually derive instead
const [selectedId, setSelectedId] = useState(null);
const selected = items.find((i) => i.id === selectedId) ?? null;   // derived, never stale
  • Before writing useEffect, ask: *is there an external system I need to sync with?* If not, you likely do not need one.
  • Fewer effects means fewer dependency arrays, fewer double-render surprises, and fewer bugs.
  • The official React docs page "You Might Not Need an Effect" is worth reading in full; it is the clearest guide to this topic.
A test for every effect Ask: "Does this sync with something outside React?" If the honest answer is no, replace it with a value calculated in render, a line in an event handler, or a key.

§4Common Mistakes

MistakeWhat HappensFix
Copying props into state with an effect to keep them in syncDouble renders and values that lag behindDerive from the prop directly
Storing filtered or sorted lists in stateTwo sources of truthCompute during render from the original list
Handling a click through useEffect on a flagFires on mount and at confusing timesDo the work in the click handler
Resetting a form with an effect on a changing propFlicker of stale content, then resetUse a key to remount the component
Practice
  1. Refactor a component that stores filteredItems in state with an effect so it derives the list during render.
  2. Replace an effect that resets a form when userId changes with a key on the form component.
  3. Count the effects in a project of yours, and for each write down the external system it synchronizes with. Remove any with no answer.
Key takeaways
  • Calculate values from props and state during render rather than syncing them in effects.
  • Handle user actions in event handlers; reserve effects for syncing with external systems.
  • Use key to reset state, and a data library for server data instead of hand-rolled effects.
