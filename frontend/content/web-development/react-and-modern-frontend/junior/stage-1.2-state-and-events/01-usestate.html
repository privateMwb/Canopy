useState

Props come from a parent, but some data belongs to the component itself and changes over time. useState gives a component a memory, and re-renders it whenever that memory changes.

§1Declaring State

useState(initial) returns a pair: the current value and a setter function. Calling the setter tells React to store a new value and re-render the component with it.

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);        // [value, setter]

  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

An ordinary variable does not work here: changing let count does not tell React anything happened, and the variable resets on every render anyway. State is preserved between renders and triggers them. Each instance of a component has its own state, so two <Counter /> elements count independently.

§2State Is a Snapshot

Within one render, state has a fixed value. Calling a setter does not change the variable you are looking at; it schedules a new render in which useState returns the new value.

function Demo() {
  const [n, setN] = useState(0);

  function handleClick() {
    setN(n + 1);
    setN(n + 1);
    setN(n + 1);
    console.log(n);       // still 0 here
  }                       // result after render: 1, not 3

  return <button onClick={handleClick}>{n}</button>;
}

All three calls used the same n (0), so each asked for 1. When the new value depends on the previous one, pass an updater function. React queues them and applies each to the latest value.

setN((prev) => prev + 1);
setN((prev) => prev + 1);
setN((prev) => prev + 1);        // result: 3

§3Updating Objects and Arrays

React detects a change by comparing the old and new value with Object.is. If you mutate an object or array and pass the same reference, React sees no change and may skip the update. Always create a new object or array.

const [user, setUser] = useState({ name: "Ada", city: "London" });
const [todos, setTodos] = useState([]);

// objects: copy, then override
setUser({ ...user, city: "Paris" });

// arrays: add, remove, replace without mutating
setTodos([...todos, { id: 1, text: "Write" }]);               // add
setTodos(todos.filter((t) => t.id !== 1));                    // remove
setTodos(todos.map((t) => (t.id === 1 ? { ...t, done: true } : t)));   // update

// wrong: same reference, so React may not re-render
todos.push({ id: 2, text: "Oops" });
setTodos(todos);
  • Pass a function to useState (useState(() => expensive())) to run costly initial setup once, not on every render.
  • Split unrelated values into separate useState calls; keep values that change together in one object.
  • Do not store values you can calculate from other state (like a total from an items array): derive them during render.
  • Call hooks only at the top level of a component, never inside conditions or loops.
Replace, never mutate Treat state as read-only. To change it, give the setter a new value: a new object, a new array, or a new number. That is how React knows something changed.

§4Common Mistakes

MistakeWhat HappensFix
Mutating state (items.push(x)) then calling the setterSame reference, so no re-render or stale UICreate a new array: setItems([...items, x])
Calling the setter three times with n + 1Only one increment happensUse setN((prev) => prev + 1)
Expecting state to update immediately after the setterconsole.log shows the old valueUse the new value you computed, or wait for the next render
Storing derived data in stateTwo sources of truth that fall out of syncCalculate it from existing state during render
Practice
  1. Build a counter with increment, decrement, and reset, and a second one that adds 3 using three updater calls.
  2. Make a to-do list where you can add, toggle, and remove items without ever mutating the array.
  3. Store a user object in state and update one field with the spread operator.
Key takeaways
  • useState returns [value, setter]; calling the setter stores the value and re-renders.
  • State is a snapshot per render; use updater functions when the next value depends on the previous.
  • Never mutate state: copy objects and arrays when you update them.
