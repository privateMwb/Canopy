Controlled Inputs & Forms

A controlled input has its value stored in React state, so the UI and the data can never disagree. It is the standard way to build forms, and it makes validation and live feedback easy.

§1The Controlled Input Pattern

In a controlled input, React state is the source of truth. You set the value from state and update the state in onChange. Every keystroke goes through your code.

function NameField() {
  const [name, setName] = useState("");

  return (
    <label>
      Name
      <input value={name} onChange={(e) => setName(e.target.value)} />
      <small>{name.length} characters</small>
    </label>
  );
}

If you set value without onChange, the input becomes read-only, and React warns you. If you want an uncontrolled input that the DOM manages itself, use defaultValue instead of value, and read the data on submit.

§2A Whole Form

For forms with several fields, keep them in one state object and use the input's name to update the right key. A single handler then serves every field.

function Signup() {
  const [form, setForm] = useState({ email: "", plan: "free", agree: false });

  function handleChange(e) {
    const { name, type, value, checked } = e.target;
    setForm((f) => ({ ...f, [name]: type === "checkbox" ? checked : value }));
  }

  function handleSubmit(e) {
    e.preventDefault();
    console.log("submit", form);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" type="email" value={form.email} onChange={handleChange} required />
      <select name="plan" value={form.plan} onChange={handleChange}>
        <option value="free">Free</option>
        <option value="pro">Pro</option>
      </select>
      <label>
        <input name="agree" type="checkbox" checked={form.agree} onChange={handleChange} />
        I agree
      </label>
      <button disabled={!form.agree}>Sign up</button>
    </form>
  );
}

The square brackets in [name]: value are a computed property name: they use the variable's value as the key. Note that select uses value in React, unlike the HTML selected attribute.

§3Validation and Feedback

Because the value is in state, you can compute errors directly from it during render instead of storing them separately. Show errors after the user has interacted with the field, not on the first keystroke.

const emailError = !form.email.includes("@") ? "Enter a valid email" : "";
const canSubmit = form.agree && emailError === "";

<input
  id="email"
  name="email"
  value={form.email}
  onChange={handleChange}
  aria-invalid={Boolean(emailError)}
  aria-describedby="email-error"
/>
<p id="email-error" role="alert">{emailError}</p>
  • Always connect a <label> to its input, with htmlFor/id or by wrapping.
  • Use the browser's built-in validation attributes (required, type, minLength) as a first layer.
  • Validate again on the server: client checks are for experience, not security.
  • For large forms, libraries such as React Hook Form reduce re-renders and boilerplate (covered in the intermediate level).
One source of truth In a controlled form, what you see in the input is exactly what is in state. That makes resetting a form as simple as setting state back to its initial value.

§4Common Mistakes

MistakeWhat HappensFix
Setting value without onChangeThe field cannot be typed into; a warning appearsAdd onChange, or use defaultValue
Switching between undefined and a string for valueWarning: uncontrolled to controlledInitialize state with "", never undefined
Using value on a checkboxState and UI do not matchUse checked for checkboxes and radios
Treating a number input's value as a number"5" + 1 is "51"Convert with Number() or valueAsNumber
Practice
  1. Build a login form with email and password, controlled inputs, and a disabled submit button until both are filled.
  2. Add a live character counter and a required-field error that appears only after the field has been touched.
  3. Add a Reset button that returns every field to its initial value in one setForm call.
Key takeaways
  • Controlled inputs take value (or checked) from state and update it in onChange.
  • One state object and a name-based handler can serve a whole form.
  • Compute validation from state during render, and validate again on the server.
