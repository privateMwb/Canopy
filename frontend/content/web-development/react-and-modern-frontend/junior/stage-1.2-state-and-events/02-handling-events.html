Handling Events

Event handlers connect the user's actions to state changes. React's event system looks like the DOM's, with a few differences worth knowing before they trip you up.

§1Attaching Handlers

Pass a function to an event prop such as onClick, onChange, or onSubmit. React calls it with an event object when the event happens. Handler props are written in camelCase.

function Like() {
  const [likes, setLikes] = useState(0);

  function handleClick(event) {
    console.log(event.type);          // "click"
    setLikes((n) => n + 1);
  }

  return <button onClick={handleClick}>Like ({likes})</button>;
}

Define handlers inside the component so that they can see its props and state. Name them handleSomething, and name handler props onSomething (<Menu onSelect={handleSelect} />), a convention that makes the data flow easy to read.

§2Pass the Function, Do Not Call It

The most common beginner bug is calling the function while rendering instead of passing it. onClick={handleClick()} runs handleClick immediately during render, and gives React its return value. If it sets state, you also get an infinite loop.

<button onClick={handleClick}>OK</button>         // passes the function
<button onClick={handleClick()}>Bug</button>      // calls it during render

// to pass an argument, wrap it in an arrow function
<button onClick={() => handleDelete(item.id)}>Delete</button>

// an inline arrow is fine for short handlers
<button onClick={() => setOpen(!open)}>Toggle</button>

Creating an arrow function on each render is cheap and almost never a performance problem, so do not avoid inline handlers out of habit.

§3The Event Object and Default Behavior

React wraps the browser's event in a synthetic event with the same interface (target, currentTarget, preventDefault, stopPropagation, and so on) that behaves consistently across browsers. The most useful calls are preventDefault (stop the browser's built-in action) and reading values from event.target.

function SearchForm({ onSearch }) {
  function handleSubmit(event) {
    event.preventDefault();                       // do not reload the page
    const data = new FormData(event.currentTarget);
    onSearch(data.get("q"));
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="q" />
      <button>Search</button>
    </form>
  );
}
  • Events bubble up the tree, as in the DOM. Use event.stopPropagation() only when you must.
  • To run a handler in the capture phase, add Capture to the name: onClickCapture.
  • Use onKeyDown with event.key for keyboard shortcuts, and make sure keyboard users can do everything mouse users can.
  • Prefer real <button> elements for clicks. They give you keyboard and screen reader support for free; a clickable <div> does not.
A handler is a value, not a call Parentheses run the function. Without them, you hand the function to React so it can run it later, when the user acts.

§4Common Mistakes

MistakeWhat HappensFix
Writing onClick={doIt()}Runs during render; can loop foreverWrite onClick={doIt} or onClick={() => doIt(arg)}
Forgetting event.preventDefault() in a submit handlerThe page reloads and state is lostCall it first in onSubmit
Using onclick (lowercase)Nothing happens; React ignores itUse camelCase: onClick
Making a <div onClick> the buttonNot focusable or keyboard-operableUse <button>
Practice
  1. Add a button that toggles a panel open and closed using an inline arrow handler.
  2. Create a delete button per list row that calls handleDelete(item.id) using an arrow wrapper.
  3. Intercept a form's submit, read its fields with FormData, and log them without reloading the page.
Key takeaways
  • Pass handler functions to camelCase props like onClick; React calls them with an event.
  • Do not call the function in the JSX; wrap it in an arrow to pass arguments.
  • Use preventDefault for submits, and real buttons for accessibility.
