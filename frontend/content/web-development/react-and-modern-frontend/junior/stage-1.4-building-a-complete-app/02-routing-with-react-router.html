Routing with React Router

Real apps have several pages. React Router maps URLs to components, so the address bar, the Back button, and shared links all work in a single-page app.

§1Setting Up Routes

Install the router with npm install react-router. A router watches the URL and renders the component that matches. With the data router, you describe routes as objects and render them with RouterProvider.

import { createBrowserRouter, RouterProvider } from "react-router";

const router = createBrowserRouter([
  { path: "/", element: <Home /> },
  { path: "/movies", element: <MovieList /> },
  { path: "/movies/:id", element: <MovieDetail /> },
  { path: "*", element: <NotFound /> },                    // anything else
]);

export default function App() {
  return <RouterProvider router={router} />;
}

Use <Link> and <NavLink> for navigation instead of <a href>. They change the URL without a full page reload, so state and speed are preserved. NavLink also knows when it is the active page, which is handy for menus.

import { Link, NavLink } from "react-router";

<Link to="/movies">All movies</Link>
<NavLink to="/movies" className={({ isActive }) => (isActive ? "active" : "")}>
  Movies
</NavLink>

§2Params, Search Params, and Navigation

A path segment that starts with a colon (:id) is a parameter. Read it with useParams. Use search params (?q=dune&page=2) for optional state such as filters, which keeps it shareable and bookmarkable.

import { useParams, useSearchParams, useNavigate } from "react-router";

function MovieDetail() {
  const { id } = useParams();                    // "/movies/42" -> id = "42" (a string)
  const navigate = useNavigate();

  return (
    <>
      <h1>Movie {id}</h1>
      <button onClick={() => navigate(-1)}>Back</button>
    </>
  );
}

function MovieList() {
  const [params, setParams] = useSearchParams();
  const q = params.get("q") ?? "";

  return (
    <input
      value={q}
      onChange={(e) => setParams({ q: e.target.value })}   // updates the URL
    />
  );
}
  • Params are always strings: convert with Number(id) when you need a number.
  • Use navigate("/path") after an action (such as saving), and prefer <Link> for ordinary navigation.
  • Putting filter state in the URL means refresh, Back, and sharing a link all keep the same view.

§3Nested Routes and Layouts

Routes can be nested. A parent route renders shared UI (a navbar, a sidebar) and an <Outlet /> where the matching child route appears. This avoids repeating layout in every page.

import { Outlet } from "react-router";

function Layout() {
  return (
    <>
      <nav>
        <NavLink to="/">Home</NavLink>
        <NavLink to="/movies">Movies</NavLink>
      </nav>
      <main><Outlet /></main>                       {/* the child route renders here */}
    </>
  );
}

const router = createBrowserRouter([
  {
    path: "/",
    element: <Layout />,
    children: [
      { index: true, element: <Home /> },            // "/"
      { path: "movies", element: <MovieList /> },     // "/movies"
      { path: "movies/:id", element: <MovieDetail /> },
      { path: "*", element: <NotFound /> },
    ],
  },
]);

React Router also supports loaders (fetch data before rendering a route), actions (handle form submissions), and error elements per route. Those features, and framework mode with server rendering, are beyond this lesson, but the route object you just wrote is where they attach. When you deploy a single-page app, configure the host to serve index.html for unknown paths, or deep links will return 404.

The URL is state Where the user is, and often what they are looking at (filters, tab, page), belongs in the URL. Routing gives you Back, refresh, and shareable links with almost no extra code.

§4Common Mistakes

MistakeWhat HappensFix
Using <a href> for internal linksFull page reload; state is lostUse <Link> or <NavLink>
Treating useParams() values as numbers"5" === 5 is false and "5" + 1 is "51"Convert with Number()
Forgetting a catch-all * routeUnknown URLs show a blank pageAdd a NotFound route
Deploying without a fallback to index.htmlRefreshing /movies/42 gives a 404Configure the host to rewrite all paths to index.html
Practice
  1. Build a three-page app (Home, List, Detail) with a shared layout using <Outlet />.
  2. Make a search box that stores its text in the URL with useSearchParams and restores it on refresh.
  3. Add a NotFound page and highlight the active link in the navigation with NavLink.
Key takeaways
  • Routes map URLs to components; use <Link>/NavLink to navigate without reloading.
  • Read path params with useParams and keep shareable state in search params.
  • Nest routes with a layout and <Outlet />, and add a catch-all route.
