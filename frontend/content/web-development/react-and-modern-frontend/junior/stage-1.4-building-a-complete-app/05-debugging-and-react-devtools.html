Debugging & React DevTools

Most React bugs are one of a small set of mistakes. The component tree in React DevTools, the console warnings, and a short checklist let you find them quickly instead of guessing.

§1React DevTools

Install the React Developer Tools browser extension. It adds two panels to your browser's DevTools: Components and Profiler.

  • Components shows the live component tree. Select a component to see its props, state, and hooks, and to edit them live to test how the UI reacts. Right-click and choose *Go to source* to jump to its code.
  • Use the search box to find a component by name, and the inspect icon to click an element on the page and select the component that rendered it.
  • Settings have Highlight updates when components render, which flashes components as they re-render. It shows immediately when something re-renders far more often than you expect.
  • Profiler records interactions and shows, per render, which components rendered, how long each took, and (with "Record why each component rendered") why. You will use it heavily in the performance lessons.

§2The Common Errors

Message or symptomLikely causeFix
Each child in a list should have a unique "key" propMissing or duplicate key in mapAdd a stable id as the key
Too many re-rendersA setter called directly during render (onClick={setN(1)})Pass a function: onClick={() => setN(1)}
Cannot read properties of undefinedData not loaded yet, or wrong shapeHandle loading; use optional chaining; check the data
Rendered more hooks than during the previous renderHook inside a condition or after an early returnMove all hooks to the top
Objects are not valid as a React childRendering an object ({user}) instead of a fieldRender user.name, or JSON.stringify to debug
Infinite effect loopEffect sets state that is in its dependencies, or an object/array dependency created each renderFix the dependencies; derive values instead
State does not update on screenMutated state instead of replacing itCreate a new object or array
Stale value inside a handler or effectClosure captured an old render's valueAdd the dependency; use an updater function

§3A Debugging Method

  1. Read the error message in full, including the component stack. It often names the file and line.
  2. Reproduce it reliably, and shrink the case: remove code until the bug disappears, then put back the last piece.
  3. Inspect the data in DevTools: are the props and state what you expect at the moment it goes wrong?
  4. Log or breakpoint at the first place the value is wrong, and work backward from there. A debugger statement, or a breakpoint in the Sources panel, shows the call stack and values.
  5. Check the Network panel for any data problem. Confirm the request URL, status, and the real response body.
  6. Change one thing at a time, and verify the result before moving on.
function Cart({ items }) {
  console.log("Cart render", items);               // quick look at what the component receives
  debugger;                                         // pauses here when DevTools is open

  // labeled objects are easier to read than bare values
  console.log({ itemsLength: items.length, first: items[0] });
  return /* ... */;
}
  • Remember StrictMode double-logs in development; that is not a bug.
  • Keep the react-hooks ESLint rules on: they catch many hook mistakes before you run the code.
  • Use error boundaries (covered later) so one broken component does not blank the whole page.
  • When asking for help, share a minimal reproduction (a CodeSandbox or StackBlitz), the exact error text, and what you expected.
Look at the data first Most "React bugs" are data bugs: the props, state, or API response is not what you assumed. Check the real values in DevTools before changing any code.

§4Common Mistakes

MistakeWhat HappensFix
Guessing and changing several things at onceYou cannot tell which change matteredChange one thing and verify
Ignoring console warningsThey usually point at the bug you will hit laterTreat warnings as errors to fix
Debugging with only the page, never DevToolsCannot see props, state, or re-rendersUse the Components and Profiler panels
Blaming StrictMode for double logs and removing itYou hide real impurity bugsFix the effect or render so it is safe to run twice
Practice
  1. Install React DevTools, select a component, and change a piece of its state live to see the UI update.
  2. Turn on "Highlight updates" and find a component that re-renders on every keystroke elsewhere in the page.
  3. Introduce three of the errors from the table on purpose, read each message, and fix it.
Key takeaways
  • React DevTools lets you inspect and edit props and state, and see what re-renders.
  • A handful of errors account for most bugs: keys, hook rules, mutation, stale values, and missing data.
  • Debug systematically: read the message, reproduce, inspect the data, find the first wrong value, change one thing.
