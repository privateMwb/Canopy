Rendering Lists & Conditionals

Real screens show lists of data and change based on conditions. map and a handful of conditional patterns cover almost every case, and the key prop is the one detail you cannot skip.

§1Rendering Lists with map

To turn an array into UI, call map and return a JSX element for each item. The result is an array of elements, which React renders in order.

const products = [
  { id: 1, name: "Tea", price: 4 },
  { id: 2, name: "Coffee", price: 6 },
];

function ProductList() {
  return (
    <ul>
      {products.map((p) => (
        <li key={p.id}>
          {p.name} ${p.price}
        </li>
      ))}
    </ul>
  );
}

To show a subset, transform the array first: products.filter((p) => p.price < 5).map(...). Do the filtering and sorting before the JSX so that the markup stays easy to read, and sort a copy ([...items].sort(...)) because sort mutates.

§2Why Keys Matter

Every element in a list needs a key prop: a string or number that is unique among siblings and stable for that item. React uses keys to match elements from one render to the next, so it can tell which item was added, removed, or moved, rather than rebuilding everything.

// good: a stable id from your data
{todos.map((t) => <TodoItem key={t.id} todo={t} />)}

// risky: the index changes when items are reordered, inserted, or removed
{todos.map((t, i) => <TodoItem key={i} todo={t} />)}

// bad: a new value every render, so React remounts every item
{todos.map((t) => <TodoItem key={Math.random()} todo={t} />)}

With index keys, deleting the first item makes React think the *last* one was removed, so inputs, focus, and component state can end up attached to the wrong rows. Use the index only for a static list that never reorders. The key goes on the element returned from map (the outermost one), and it is not passed down as a prop.

§3Showing the Right UI

Because JSX is JavaScript, you choose what to render with ordinary JavaScript. Pick the pattern that reads most clearly.

function Inbox({ messages, loading, error }) {
  if (loading) return <Spinner />;                      // early return
  if (error) return <p role="alert">{error}</p>;

  return (
    <section>
      <h2>Inbox {messages.length > 0 && <span>({messages.length})</span>}</h2>

      {messages.length === 0 ? <p>No messages.</p> : <MessageList items={messages} />}
    </section>
  );
}
PatternUse when
Early returnWhole component differs (loading, error, empty)
cond ? <A /> : <B />Choose between two pieces of UI
cond && <A />Show something or nothing
nullRender nothing from a component

Beware && with numbers: {items.length && <List />} renders a literal 0 when the array is empty, because 0 is a valid thing to render. Write {items.length > 0 && <List />} instead. Always plan for the empty case, because an empty list with no message looks broken.

Keys identify items, not positions A good key is an id that belongs to the data. If two renders show the same item, it must get the same key, even if the item moved. That is the only job keys have.

§4Common Mistakes

MistakeWhat HappensFix
Leaving out keyConsole warning, and slow or buggy updatesAdd a stable, unique key to each element from map
Using the array index as a key in a changing listState and inputs jump to the wrong rowsUse an id from the data
{count && <Badge />} where count can be 0A stray 0 appears on screenUse count > 0 && ... or a ternary
Sorting state in place with .sort()Mutates the original arraySort a copy: [...items].sort()
Practice
  1. Render a list of products and add a filter that hides those above a given price, computed before the JSX.
  2. Show a loading message, an error message, an empty state, and the list using early returns.
  3. Reproduce the index-key bug: render a list of text inputs, delete the first item, and watch the values mismatch. Then fix it with ids.
Key takeaways
  • Use map to render arrays; filter and sort first, and sort a copy.
  • Give each list element a stable, unique key from your data, not the index or a random number.
  • Pick the clearest conditional pattern, and watch out for && with numbers.
