details, summary & Disclosure

details and summary give you a keyboard-accessible, screen-reader-friendly accordion with no JavaScript at all.

§1A Native Disclosure Widget

<details> wraps hidden content; its first child <summary> is the always-visible toggle. Clicking, or pressing Enter or Space, expands it. The browser handles focus, state, and announcements.

<details>
  <summary>What is your refund policy?</summary>
  <p>You can return any item within 30 days for a full refund.</p>
</details>

<details open>
  <summary>Shipping</summary>
  <p>Orders ship within two business days.</p>
</details>

Add the boolean open attribute to start expanded. The browser toggles that attribute as the user interacts, and fires a toggle event you can listen for if you need one.

§2Exclusive Accordions and Styling

Give several <details> the same name and the browser treats them as an exclusive group: opening one closes the others. This is supported in current versions of the major browsers; older ones simply allow several to stay open, which is a safe fallback.

<details name="faq"><summary>Shipping</summary><p>...</p></details>
<details name="faq"><summary>Returns</summary><p>...</p></details>

summary { cursor: pointer; font-weight: 600; }
details[open] summary { color: #15803d; }

You can replace the default marker with CSS via summary::marker or list-style, but keep a clear visual cue that it expands.

§3When to Use It

  • Good for FAQs, optional detail, and "show more" content.
  • Not for site navigation menus; those are usually better as a plain visible list of links.
  • Collapsed content is easy to overlook, so don't hide crucial information there.

The name of the control is the summary text, so make it a clear, specific label.

Don't rebuild this by hand A custom accordion built from divs needs aria-expanded, aria-controls, keyboard handling, and focus management. details gives you all of that by default.

§4Common Mistakes

MistakeWhat HappensFix
Putting block content such as headings in summary carelesslyHeadings inside summary lose their heading role in some assistive techUse plain text, or wrap the details in a heading's section
Forgetting summaryThe browser adds a generic "Details" labelAlways supply a specific summary
Hiding essential legal or pricing text inside detailsUsers may miss itKeep critical information visible
Practice
  1. Build an FAQ with five items using details and summary and navigate it with the keyboard only.
  2. Add name to make it an exclusive accordion and style the open state.
Key takeaways
  • details and summary provide accessible disclosure without JavaScript.
  • Use open for the default state and a shared name for exclusive groups.
  • Don't hide critical content behind a disclosure.
