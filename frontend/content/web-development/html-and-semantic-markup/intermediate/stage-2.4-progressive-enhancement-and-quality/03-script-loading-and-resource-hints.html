Script Loading & Resource Hints

defer, async, and type="module" decide when scripts run, and preload, preconnect, and prefetch tell the browser what to fetch early.

§1Classic Scripts Block the Parser

A plain <script src> stops HTML parsing while it downloads and runs. That delays rendering of everything after it, which is why old advice said to put scripts at the end of the body. Attributes remove the need for that.

<script src="app.js"></script>           <!-- blocks parsing -->
<script src="app.js" defer></script>     <!-- download in parallel, run after parsing, in order -->
<script src="stats.js" async></script>   <!-- download in parallel, run as soon as ready, any order -->
<script type="module" src="main.js"></script>  <!-- deferred by default -->
AttributeDownloadsRunsUse for
(none)Blocks parserImmediatelyRare cases
deferIn parallelAfter parsing, in orderMost page scripts
asyncIn parallelASAP, unorderedIndependent scripts such as analytics
type="module"In parallelAfter parsing, like deferModern modular code

§2Resource Hints

Hints let the browser start work before it would normally discover a resource.

<!-- open a connection early to another origin -->
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

<!-- fetch a critical resource now -->
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

<!-- fetch something likely needed on the NEXT page, at low priority -->
<link rel="prefetch" href="/next-page.html">

preconnect saves a handshake, preload raises the priority of something you know the current page needs, and prefetch guesses at future navigation.

§3Using Hints Wisely

  • Preload only a few truly critical resources; it competes with everything else.
  • Always give preload an as value, and add crossorigin for fonts.
  • Preconnect only to origins you will definitely use soon.
  • Measure with DevTools or WebPageTest; guesses are often wrong.

Inline scripts are always parser-blocking unless they are modules. Keep them tiny and rare.

Default to defer For scripts that touch the DOM, defer in the <head> is almost always right: the download starts early and execution waits for the document.

§4Common Mistakes

MistakeWhat HappensFix
Putting async on scripts that depend on each otherThey run in unpredictable orderUse defer to preserve order
Preloading everythingCritical requests are starved of bandwidthPreload only a handful of key assets
Forgetting crossorigin on font preloadsThe font is fetched twiceAdd crossorigin to font preloads
Practice
  1. Convert a page with blocking scripts to defer and compare the First Contentful Paint.
  2. Add a preconnect and a font preload and verify in the Network panel that the font starts earlier.
Key takeaways
  • defer runs in order after parsing; async runs when ready; modules defer by default.
  • preload for the current page's critical assets, prefetch for likely next pages.
  • Measure before and after adding hints.
