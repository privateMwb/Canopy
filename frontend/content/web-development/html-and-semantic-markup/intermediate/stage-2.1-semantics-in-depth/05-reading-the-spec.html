Reading the Spec

When someone asks "can I put a div in a p?", the answer is in the HTML Living Standard; knowing how to read it, and MDN, saves guessing.

§1Where the Answers Live

The HTML Living Standard (html.spec.whatwg.org) is the authoritative specification, continuously updated by WHATWG. It is precise and dense. MDN Web Docs is the friendlier reference, with examples and browser-support tables. Use MDN to learn, the spec to settle disputes.

SourceBest for
HTML Living StandardExact rules, content models, parsing behavior
MDN Web DocsExplanations, examples, compatibility data
caniuse.comBrowser support at a glance
WAI-ARIA Authoring PracticesAccessible patterns for custom widgets

§2Anatomy of an Element Entry

Every element in the spec follows the same layout. Learn to read it, and any new tag becomes answerable.

  • Categories — flow, phrasing, interactive, and so on; used to decide where it can appear.
  • Contexts in which this element can be used — valid parents.
  • Content model — what it may contain.
  • Content attributes — the attributes it accepts.
  • Accessibility considerations — roles and notes.

§3Worked Example: Can a div Go in a p?

Look up <p>: its content model is phrasing content. <div> is flow content, not phrasing, so it isn't allowed inside <p>. Worse, the parser closes the paragraph automatically when it meets a <div>.

<p>Intro text
  <div>block</div>
</p>

<!-- the parser produces:
<p>Intro text</p>
<div>block</div>
<p></p>        <- the stray </p> creates an empty paragraph -->

This is a practical use of the spec: instead of memorizing rules, you can derive them from content models.

Spec first for "allowed?" questions MDN is great for "how do I?". For "is this valid?" or "what exactly happens?", read the element's content model and the parsing section of the spec.

§4Common Mistakes

MistakeWhat HappensFix
Treating a Stack Overflow answer from 2012 as currentOutdated or removed featuresCheck the spec and MDN for current status
Assuming that if it renders, it's validBrowsers forgive invalid markupValidate and read content models
Skipping browser compatibility tablesA feature works in your browser onlyCheck MDN's table and caniuse before relying on it
Practice
  1. Look up <label>, <dialog>, and <ul> in the spec and write down each one's content model and permitted parents.
  2. Find out why <a> can contain a <div> in modern HTML but <button> can't contain a link.
Key takeaways
  • The HTML Living Standard is authoritative; MDN is the friendly guide.
  • Learn to read element entries: categories, contexts, content model, attributes.
  • Validity questions are answered by content models, not by what renders.
