Publishing a Static Site

Static HTML needs only a host that serves files; GitHub Pages and Netlify are free, quick ways to get a real URL and then verify it works live.

§1Options for Hosting

A static site is a folder of files, so any web server will do. Two popular beginner-friendly options:

HostHow it worksGood for
GitHub PagesPush to a repo; enable Pages in settingsPersonal and project sites, tied to Git
NetlifyDrag the folder in, or connect a repoQuick previews, forms, redirects

Both provide HTTPS automatically, and both let you attach your own domain later.

§2Publishing with GitHub Pages

git init
git add .
git commit -m "First version of my site"
git branch -M main
git remote add origin https://github.com/you/my-site.git
git push -u origin main
# then: Settings → Pages → deploy from the main branch

After a minute or two the site appears at https://you.github.io/my-site/. Because that is a subfolder URL, check that your links work there (see the previous lesson).

§3Verify the Live Site

Publishing isn't done until you've tested the real URL, not your local copy.

  • Open it on a phone and a different browser.
  • Click every link, including the ones in the footer.
  • Check the Network tab for 404s on CSS, images, or scripts.
  • Confirm HTTPS shows a lock and the tab title is correct.
  • Run the live URL through the validator.

Add a 404.html at the root. Most static hosts serve it for missing pages, which gives visitors a way back.

Deploys can be cached If you push a fix and still see the old page, hard-refresh (Ctrl+Shift+R) or open the URL in a private window before assuming the deploy failed.

§4Common Mistakes

MistakeWhat HappensFix
Testing only on your own machineCase sensitivity and path problems appear only after publishingTest the live URL on another device
Forgetting HTTPS-relative resourcesMixed content (an http:// image on an https:// page) is blockedUse https:// or relative URLs for everything
Committing secrets or private filesThey become publicReview what is in the folder before the first push
Practice
  1. Publish a one-page site to GitHub Pages or Netlify and record its URL.
  2. Add a custom 404.html and test it by visiting a made-up path.
Key takeaways
  • Static sites need only file hosting; GitHub Pages and Netlify are free options.
  • Always test the live URL, not just your local copy.
  • Check links, asset paths, HTTPS, and a 404 page after deploying.
