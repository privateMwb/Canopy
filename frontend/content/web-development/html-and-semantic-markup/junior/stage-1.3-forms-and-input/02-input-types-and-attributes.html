Input Types & Attributes

The type attribute gives you built-in keyboards, pickers, and validation for free; learn the common types and the attributes that tune them.

§1Common Input Types

<input> changes behavior with type. Picking the correct one gives mobile users the right keyboard and gives the browser something to validate.

<input type="text" name="name">
<input type="email" name="email">
<input type="password" name="pw" autocomplete="current-password">
<input type="tel" name="phone">
<input type="url" name="site">
<input type="number" name="qty" min="1" max="10" step="1">
<input type="date" name="when">
<input type="search" name="q">
<input type="checkbox" name="agree" value="yes">
<input type="radio" name="size" value="m">

type="number" suits quantities. For things that merely look numeric, such as ZIP codes or card numbers, use type="text" with inputmode="numeric" so leading zeros survive.

§2Attributes That Shape Input

AttributeWhat it does
requiredBlocks submit until a value is entered

§3Radios and Checkboxes

Radio buttons with the same name form a group where only one can be chosen. Checkboxes are independent and submit their value only if checked.

<input type="radio" id="s" name="size" value="s">
<label for="s">Small</label>
<input type="radio" id="m" name="size" value="m" checked>
<label for="m">Medium</label>
Let the type do the work type="email" brings an @ keyboard on phones and basic validation. Using type="text" for everything throws that away.

§4Common Mistakes

MistakeWhat HappensFix
Using type="text" for everythingNo tailored keyboard or built-in checksPick email, tel, url, number, and date where they apply
Giving radio buttons different namesThey stop acting as a groupUse one shared name per group
Using type="number" for IDs and phone numbersStrips leading zeros and adds spinnersUse text with inputmode="numeric" or tel
Relying on disabled to keep a valueDisabled fields are not submittedUse readonly or a hidden input
Practice
  1. Build a form with email, tel, number (with limits), date, and a radio group, then test it on a phone or emulator.
  2. Compare what is submitted with disabled and readonly fields.
Key takeaways
  • Choose the type that matches the data.
  • Attributes such as required, min, and max give native constraints.
  • Radios share a name; checkboxes submit only when checked.
