Form Basics

A form collects values and sends them to a URL; understanding action, method, and name explains exactly what leaves the browser on submit.

§1A Minimal Working Form

A <form> groups controls. When submitted, the browser gathers every successful control's name and value, encodes them, and sends them to the URL in action using the HTTP method.

<form action="/subscribe" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required>
  <button type="submit">Subscribe</button>
</form>

The name attribute is what makes a control's value part of the submission. An input without a name is not sent.

§2GET vs. POST

The method decides *where* the data goes and what the request means.

MethodData locationUse for
getIn the URL query string: /search?q=oakSearches and filters; safe, repeatable, bookmarkable
postIn the request bodyCreating or changing data, passwords, large or sensitive payloads

Never use get for passwords or private data; query strings end up in browser history, logs, and referrer headers.

§3What Happens on Submit

Pressing a submit button, or Enter in most text fields, triggers validation and then navigation. The browser sends the request and loads the response as a new page.

POST /subscribe HTTP/1.1
Content-Type: application/x-www-form-urlencoded

email=sam%40example.com

Add enctype="multipart/form-data" when the form includes a file input. If JavaScript later intercepts the submit event, the form should still work on its own first; that is progressive enhancement, covered in the Intermediate level.

Forms work without JavaScript A plain HTML form submits, validates, and handles Enter and keyboard use by itself. Start there, then enhance.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting name on inputsThe value silently doesn't reach the serverGive every submitted control a name
Using method="get" for login formsThe password appears in the URL and historyUse post and HTTPS
Leaving out actionIt submits to the current URL, which may not be where you expectedSet action explicitly
Wrapping each field in its own <form>Only one field is sent at a timePut related controls in a single form
Practice
  1. Build a search form using get and look at the URL after submitting.
  2. Build a contact form with post and check the request body in the Network panel.
Key takeaways
  • Only named controls are submitted.
  • get puts data in the URL; post puts it in the body.
  • A form is fully functional without any JavaScript.
