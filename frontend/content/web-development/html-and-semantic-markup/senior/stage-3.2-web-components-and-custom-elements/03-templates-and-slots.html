Templates & Slots

<template> holds inert, reusable markup, and slots let one template serve many different contents.

§1The template Element

A <template> element's contents are parsed but inert: no scripts run, no images load, and nothing renders. Clone them when you need an instance.

<template id="row">
  <tr>
    <td class="name"></td>
    <td class="qty"></td>
  </tr>
</template>

<script>
  const tpl = document.querySelector("#row");
  function addRow(name, qty) {
    const frag = tpl.content.cloneNode(true);
    frag.querySelector(".name").textContent = name;
    frag.querySelector(".qty").textContent = qty;
    document.querySelector("tbody").append(frag);
  }
</script>

Using textContent instead of innerHTML keeps user-provided values from being interpreted as HTML.

§2Templates Inside Components

Components commonly create their template once, then clone it for each instance. That is faster and more predictable than building strings every time.

const tpl = document.createElement("template");
tpl.innerHTML = `
  <style>:host { display: inline-block }</style>
  <button part="button"><slot>Click me</slot></button>`;

class MyButton extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" }).append(tpl.content.cloneNode(true));
  }
}
customElements.define("my-button", MyButton);

The text inside <slot> is fallback content, which is shown only when nothing is slotted.

§3Named Slots and slotchange

Use named slots to give consumers several insertion points. Listen to the slotchange event to react when the slotted content changes.

<!-- inside the template -->
<header><slot name="header"></slot></header>
<slot></slot>
<footer><slot name="footer">© Canopy</slot></footer>

// in JavaScript
shadowRoot.querySelector("slot:not([name])").addEventListener("slotchange", (e) => {
  console.log(e.target.assignedNodes({ flatten: true }));
});

Declarative Shadow DOM (<template shadowrootmode="open">) lets the server render a shadow tree directly in HTML, so components can show up before any JavaScript executes.

Templates are a performance and safety tool Cloning parsed nodes avoids re-parsing HTML strings, and assigning textContent avoids injecting markup from data.

§4Common Mistakes

MistakeWhat HappensFix
Querying inside a <template> with document.querySelectorTemplate contents live in a separate fragmentUse template.content.querySelector
Using innerHTML with user data when filling a cloneXSS riskUse textContent or setAttribute
Forgetting to clone (cloneNode(true))Moves the content out; only one instance is possibleClone the content for each instance
Practice
  1. Render a list of rows from an array using a <template> and cloneNode.
  2. Add slotchange handling to a component that counts its slotted items.
Key takeaways
  • <template> content is inert until cloned.
  • Slots give components flexible, named insertion points with fallback content.
  • Clone templates and use textContent for data; consider Declarative Shadow DOM for server rendering.
