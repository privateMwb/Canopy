Templating & Server-Rendered HTML

Layouts, partials, and components keep server-rendered HTML DRY, but valid, escaped, accessible output is something you have to design in.

§1Layouts and Partials

A layout owns the document skeleton (doctype, head, landmarks) and a partial is a reusable fragment. Put the skeleton in one place so every page gets the same lang, viewport, and landmarks.

<!-- layouts/base.html (any templating language) -->
<!DOCTYPE html>
<html lang="{{ page.lang | default: 'en' }}">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{{ page.title }} | Canopy</title>
  {% block head %}{% endblock %}
</head>
<body>
  <a class="skip" href="#main">Skip to main content</a>
  {% include "partials/header.html" %}
  <main id="main">{% block content %}{% endblock %}</main>
  {% include "partials/footer.html" %}
</body>
</html>

The syntax differs between engines (Nunjucks, Liquid, Jinja, ERB, Blade), but the structure is the same.

§2Escaping by Default

Choose a templating engine that escapes output by default, and make the unescaped path hard to reach. Escaping depends on *where* the value lands: HTML text, an attribute, a URL, or a script all need different treatment.

<p>{{ comment.body }}</p>                       <!-- HTML-escaped: safe -->
<a href="{{ url }}">...</a>                      <!-- attribute context; validate URL scheme too -->
<div>{{ comment.html | safe }}</div>           <!-- DANGEROUS unless already sanitized -->

A value in an href also needs its scheme validated: javascript: URLs run code even when quotes are escaped properly.

§3Keeping Output Valid and Accessible

  • Unique IDs — generate IDs per instance (field-{{ id }}) so labels, for, and aria-* references don't collide when a partial is included many times.
  • Heading levels — pass the level into reusable partials instead of hard-coding <h2>.
  • Valid nesting — don't generate a <div> inside a <p> or a <li> outside a list when a conditional skips a wrapper.
  • Validate the output — run the validator or linter on rendered pages in CI, not on templates.

Streaming and partial rendering, discussed earlier, are friendly to server templates too: render the head and shell first, then the slower fragments.

Lint the output, not the template Templates contain logic and placeholders that validators can't parse. Render representative pages and check the final HTML.

§4Common Mistakes

MistakeWhat HappensFix
Turning off auto-escaping to "fix" display issuesOpens XSS holesFix the data, or sanitize rich content explicitly
Hard-coded IDs inside repeated partialsDuplicate IDs break labels and ARIAInclude a unique suffix per instance
Hard-coded heading levels in partialsBroken outline when reused in new contextsPass the heading level as a parameter
Practice
  1. Build a base layout with a skip link and landmarks, and two pages that extend it.
  2. Create a form-field partial that generates a unique id and wires its label and error message together.
Key takeaways
  • One layout owns the skeleton, lang, and landmarks.
  • Escape by default, and validate URLs by scheme as well.
  • Parameterize IDs and heading levels, and validate rendered output in CI.
