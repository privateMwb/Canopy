Measuring with Web Vitals & Lighthouse

Field data vs. lab data.

§1Lab Data vs. Field Data

Lab data comes from a controlled test, such as Lighthouse running on one simulated device and network. It is reproducible and great for debugging. Field data (real user monitoring) comes from actual visitors' devices, so it reflects the true variety of networks and hardware, and is what Google uses in its ranking signals.

LabField
SourceSimulated test runReal users
StrengthRepeatable, diagnostic, usable before launchShows what users truly experience
WeaknessMay not match real conditionsNeeds traffic and time; less diagnostic
ToolsLighthouse, WebPageTestCrUX, web-vitals library, RUM services, Vercel Speed Insights

§2The Core Web Vitals

MetricMeasures'Good' threshold
LCP, Largest Contentful PaintHow fast the main content appears2.5 s or less
INP, Interaction to Next PaintHow quickly the page responds to input200 ms or less
CLS, Cumulative Layout ShiftHow much the layout jumps around0.1 or less

These are assessed at the 75th percentile of real visits. INP replaced the older First Input Delay metric in 2024. Supporting metrics such as TTFB (time to first byte) and FCP help locate the cause when a vital is poor.

§3Measuring and Reporting

// app/web-vitals.tsx
"use client";
import { useReportWebVitals } from "next/web-vitals";

export function WebVitals() {
  useReportWebVitals((metric) => {
    navigator.sendBeacon("/api/vitals", JSON.stringify(metric));   // name, value, rating
  });
  return null;
}

A good workflow: find slow pages in field data, reproduce them with Lighthouse or the browser's performance panel, fix the specific bottleneck, deploy, and confirm in field data that the fix held.

Optimise what you measured Guessing wastes effort. A poor LCP might be a slow server, a huge image, or render-blocking script; each has a different fix. Use the supporting metrics to find out which before changing anything.

§4Common Mistakes

MistakeWhat HappensFix
Trusting a single Lighthouse scoreOne run varies and isn't what users experienceRun several times and check field data as well
Testing only on a fast laptop and networkReal users on mid-range phones suffer unseenThrottle CPU and network, and check field metrics
Averaging metrics instead of using percentilesOutliers and the slowest users are hiddenLook at the 75th percentile, and beyond
Practice
  1. Run Lighthouse on your deployed app three times, record LCP, INP or TBT, and CLS, and note the variation.
  2. Add Web Vitals reporting to your app and log the values from a few real page loads.
Key takeaways
  • Lab data diagnoses problems; field data tells you what real users experience.
  • Core Web Vitals are LCP, INP, and CLS, judged at the 75th percentile.
  • Measure, change one thing, and re-measure in the field to confirm improvement.
