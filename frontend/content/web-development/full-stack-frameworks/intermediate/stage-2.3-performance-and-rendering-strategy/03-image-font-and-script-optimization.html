Image, Font & Script Optimization

Built-in optimization and what it replaces.

§1Images, Fonts, and Scripts Are the Heavy Parts

Most page weight and many layout-shift and load-time problems come from three things: images, web fonts, and third-party scripts. Frameworks ship components that handle the common optimizations for you.

§2Images

The <Image> component resizes images, serves modern formats such as WebP or AVIF, lazy-loads off-screen images, and reserves space to prevent layout shift.

import Image from "next/image";

<Image
  src="/hero.jpg"
  alt="Team collaborating at a whiteboard"
  width={1200}
  height={630}
  priority                       // above-the-fold LCP image: preload, don't lazy-load
  sizes="(max-width: 768px) 100vw, 1200px"   // helps the browser pick a size
/>

Always provide width and height (or fill with a sized parent) so the browser reserves space. Add priority only to the one or two images visible on first load. Remote images need their hostname allowed in the config.

§3Fonts

next/font downloads fonts at build time and self-hosts them with the rest of your assets, so there's no request to a third-party font server and the fallback font is size-adjusted to minimise layout shift.

import { Inter } from "next/font/google";
const inter = Inter({ subsets: ["latin"], display: "swap" });
// <body className={inter.className}>

§4Scripts

Third-party scripts (analytics, chat widgets, ad tags) often cost more than your own code. The <Script> component controls when they load.

StrategyLoadsUse for
beforeInteractiveBefore the page becomes interactiveRare: bot detection, consent managers
afterInteractive (default)Soon after hydrationAnalytics, tag managers
lazyOnloadDuring browser idle timeChat widgets, low-priority embeds
Measure before and after Built-in components remove common mistakes but aren't magic. A 4000px photo with a wrong sizes value is still wasteful. Confirm with real measurements (lesson 2.3.5).

§5Common Mistakes

MistakeWhat HappensFix
Using plain <img> for large imagesOversized downloads and layout shiftUse <Image> with dimensions and sizes
Marking every image priorityEverything competes for bandwidth, so LCP doesn't improveUse priority on the single hero image only
Loading analytics synchronously in <head>Render-blocking scripts delay first paintUse <Script> with afterInteractive or lazyOnload
Practice
  1. Replace an <img> with <Image> and compare the bytes downloaded in the network tab.
  2. Audit your app's third-party scripts: for each, decide whether it's needed and which loading strategy fits.
Key takeaways
  • <Image>, next/font, and <Script> automate resizing, self-hosting, and load timing.
  • Reserve space for images and prioritise only the above-the-fold hero.
  • Third-party scripts are a major performance cost, so load them late or remove them.
