Server Actions & Form Handling

Submitting forms without writing separate API routes.

§1Forms Without API Routes

A Server Action is an async function marked "use server" that runs on the server but can be called from a form or a client component. You pass it to a form's action prop, and the framework handles the POST request, serialization, and response for you.

// app/contacts/actions.ts
"use server";
import { revalidatePath } from "next/cache";

export async function addContact(formData: FormData) {
  const name = String(formData.get("name") ?? "");
  await db.contact.create({ data: { name } });
  revalidatePath("/contacts");      // refresh the list
}

// app/contacts/page.tsx
<form action={addContact}>
  <input name="name" required />
  <button type="submit">Add</button>
</form>

Because it's a real HTML form, it works before JavaScript loads and is progressively enhanced once it does.

§2Pending State and Returning Results

Use useFormStatus inside a client child of the form to disable the button while submitting, and useActionState to receive a return value, such as validation errors, from the action.

"use client";
import { useActionState } from "react";
import { addContact } from "./actions";

export function ContactForm() {
  const [state, formAction, pending] = useActionState(addContact, { error: "" });
  return (
    <form action={formAction}>
      <input name="name" />
      <button disabled={pending}>{pending ? "Saving…" : "Add"}</button>
      {state.error && <p role="alert">{state.error}</p>}
    </form>
  );
}

§3Treat Actions as Public Endpoints

Every Server Action is reachable by an HTTP request, so a hidden button isn't protection. Always validate input and check authorization inside the action itself. Lessons 1.3.4 and 2.1.3 cover both.

An action is an API endpoint in disguise The convenience hides the fact that anyone can send a crafted request to it. Never trust the form data, and never skip the permission check because 'only logged-in users see this form.'

§4Common Mistakes

MistakeWhat HappensFix
Skipping server-side validationMalformed or malicious data reaches the databaseValidate inside the action, for example with Zod
Not revalidating after a mutationThe page keeps showing stale dataCall revalidatePath or revalidateTag after the write
Assuming UI visibility equals permissionAnyone who knows the action can call itCheck the session and permissions in the action
Practice
  1. Build a form that adds an item through a Server Action and refreshes the list without a manual reload.
  2. Add a pending state to the submit button and an error message returned from the action.
Key takeaways
  • Server Actions let a form call server code without writing a separate API route.
  • Use useActionState and useFormStatus for results and pending UI.
  • Treat every action as a public endpoint: validate and authorize inside it.
