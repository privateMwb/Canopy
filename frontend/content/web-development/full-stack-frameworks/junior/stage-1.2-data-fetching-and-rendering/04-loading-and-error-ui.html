Loading & Error UI

Streaming skeletons and error boundaries per route.

§1Showing Something While Data Loads

A slow query shouldn't leave the user staring at a blank screen. The App Router uses conventions to show instant feedback and to contain failures, both scoped to a route segment.

§2loading.tsx and Suspense

A loading.tsx file next to a page.tsx is shown immediately while the page's data resolves. Behind the scenes it wraps the page in a React <Suspense> boundary. For finer control, wrap just the slow part yourself so the rest of the page appears right away.

// app/dashboard/loading.tsx
export default function Loading() {
  return <div className="animate-pulse h-40 rounded bg-gray-200" />;
}

// Finer-grained: only the slow widget waits
import { Suspense } from "react";
<Suspense fallback={<ChartSkeleton />}>
  <RevenueChart />   {/* async Server Component */}
</Suspense>

Skeletons that match the final layout feel faster than spinners and prevent content from jumping when it arrives.

§3error.tsx and not-found.tsx

An error.tsx file defines the UI shown when something in that segment throws. It must be a Client Component, and it receives the error plus a reset function to retry. For missing content, call notFound() to render the nearest not-found.tsx.

// app/dashboard/error.tsx
"use client";
export default function Error({ error, reset }: { error: Error; reset: () => void }) {
  return (
    <div>
      <p>Something went wrong loading the dashboard.</p>
      <button onClick={() => reset()}>Try again</button>
    </div>
  );
}

// In a page
import { notFound } from "next/navigation";
if (!post) notFound();
Errors stay local An error boundary catches failures in its own segment and below, so the rest of the layout, such as navigation, stays usable. Put boundaries around risky data, not just at the root.

§4Common Mistakes

MistakeWhat HappensFix
One giant loading.tsx for a complex pageNothing appears until the slowest query finishesWrap slow parts in separate <Suspense> boundaries
Forgetting "use client" in error.tsxA build error, because error boundaries must be client componentsAdd the directive
Showing raw error messages to usersLeaked internals and confusing textShow a friendly message and log details on the server
Practice
  1. Add an artificial two-second delay to a data fetch and build a skeleton loading.tsx that matches the page layout.
  2. Make a route throw an error on purpose and confirm that only that segment is replaced by the error UI.
Key takeaways
  • loading.tsx and <Suspense> show useful UI while data streams in.
  • error.tsx contains failures to one segment and offers a retry.
  • notFound() handles missing content with a dedicated page.
