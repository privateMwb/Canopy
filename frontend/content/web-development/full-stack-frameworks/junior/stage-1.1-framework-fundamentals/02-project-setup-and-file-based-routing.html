Project Setup & File-Based Routing

Folders as routes, layouts, and dynamic segments.

§1Starting a Project

create-next-app asks about TypeScript, linting, Tailwind, and the src/ folder, then writes a working app. The important directory is app/, which holds every route. Files outside app/ that matter early are public/ for static assets and next.config.ts for framework settings.

§2Folders Are Routes

Each folder inside app/ is a URL segment. A folder becomes a visitable page only when it contains a page.tsx file, which means you can keep helper components next to routes without accidentally publishing them.

app/
  layout.tsx            # root layout, wraps every page
  page.tsx              # /
  about/
    page.tsx            # /about
  blog/
    page.tsx            # /blog
    [slug]/
      page.tsx          # /blog/anything (dynamic segment)

§3Layouts and Dynamic Segments

A layout.tsx wraps every page beneath it and persists across navigation, so it doesn't re-render or lose state when the user moves between its children. The root layout must render the <html> and <body> tags.

// app/blog/[slug]/page.tsx
export default async function Post({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;   // params is a Promise in recent versions
  return <h1>Post: {slug}</h1>;
}

Square brackets mark a dynamic segment, [...slug] catches every remaining segment, and [[...slug]] also matches the bare parent path. Parentheses, as in (marketing), group routes and layouts without adding to the URL.

Gotcha: params are async In recent Next.js versions params and searchParams are Promises you must await. Older tutorials destructure them directly. If you see a warning about accessing params synchronously, that's why.

§4Common Mistakes

MistakeWhat HappensFix
Creating a folder with no page.tsxThe URL returns 404 even though the folder existsAdd page.tsx; folders alone are not routes
Putting <html> in a nested layoutDuplicate document tags and hydration errorsOnly the root layout renders <html> and <body>
Forgetting that layouts persistState in a layout surprises you by surviving navigationUse a template or per-page component if state must reset
Practice
  1. Create /, /about, and /blog/[slug] routes, and make the blog page display its slug.
  2. Add a layout with a shared navigation bar and confirm it does not remount when you navigate between pages.
Key takeaways
  • Folders under app/ are URL segments, and a page.tsx file makes one visitable.
  • Layouts wrap their children and persist across navigation.
  • Dynamic segments use [brackets], and route groups (name) organise code without changing the URL.
