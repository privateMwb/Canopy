Server vs. Client Components

What runs where, and how to choose.

§1Two Kinds of Component

In the App Router every component is a Server Component by default. It runs only on the server, its code never ships to the browser, and it can be async. A Client Component opts in with "use client" at the top of the file, runs in the browser (and is also pre-rendered on the server for first paint), and can use state, effects, and event handlers.

CapabilityServer ComponentClient Component
Read a database or secret directlyYesNo
Use useState, useEffectNoYes
Attach onClick and other handlersNoYes
Use browser APIs (window, localStorage)NoYes
Adds to the JavaScript bundleNoYes

§2Drawing the Boundary

"use client" marks a boundary: that file and everything it imports become client code. So push the directive as far down the tree as possible, to the small interactive leaf, and keep the page itself on the server.

// app/products/page.tsx  (Server Component)
import { LikeButton } from "./like-button";

export default async function Products() {
  const products = await db.product.findMany();   // runs on the server only
  return products.map((p) => (
    <li key={p.id}>{p.name} <LikeButton id={p.id} /></li>
  ));
}

// app/products/like-button.tsx
"use client";
import { useState } from "react";
export function LikeButton({ id }: { id: string }) {
  const [liked, setLiked] = useState(false);
  return <button onClick={() => setLiked(!liked)}>{liked ? "♥" : "♡"}</button>;
}

§3Passing Data Across the Boundary

A Server Component can render a Client Component and pass it props, but those props must be serializable: strings, numbers, plain objects, arrays, and similar. You can't pass functions, class instances, or database connections. A Client Component can also receive Server Components as children, which lets interactive wrappers contain server-rendered content.

A quick decision rule Start on the server. Add "use client" only when you need state, effects, event handlers, or browser APIs, and then only in the smallest component that needs them.

§4Common Mistakes

MistakeWhat HappensFix
Adding "use client" to the top of every fileYou lose server rendering benefits and ship far more JavaScriptKeep pages on the server; mark only interactive leaves
Importing server-only code into a client fileBuild errors, or secrets leaking into the bundleUse the server-only package to fail the build on misuse
Passing a function as a prop to a Client ComponentA serialization error at render timePass data, and define handlers inside the client component
Practice
  1. Build a page that reads data on the server and contains one interactive counter. Which file needs "use client"?
  2. Open the browser's network tab and compare the JavaScript downloaded when the whole page is a client component versus when only the counter is.
Key takeaways
  • Components are Server Components by default; "use client" opts a file, and its imports, into the browser bundle.
  • Keep the client boundary small and low in the tree.
  • Props crossing the boundary must be serializable.
