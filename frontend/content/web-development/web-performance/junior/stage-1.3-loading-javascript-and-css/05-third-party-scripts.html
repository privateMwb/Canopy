Third-Party Scripts

Analytics, chat widgets, tag managers, and ads are code you don't control, running on your page. They are often the largest cause of slowness nobody owns.

§1Why Third Parties Hurt

Each third-party script adds a new origin to connect to, bytes to download, and JavaScript to run on the same main thread as your own code. They load more scripts of their own, which load more, and you can't easily inspect or optimize any of it.

  • Network: extra DNS, connection, and TLS costs per origin.
  • Main thread: long tasks that delay interaction and hurt INP.
  • Layout shifts: ads and embeds that inject content late.
  • Reliability: if the vendor is slow or down, your page can suffer too.
  • Privacy and security: they see your users and run with your page's privileges.

§2Measuring Their Cost

Don't guess. Lighthouse has a Reduce the impact of third-party code audit that totals the transfer size and main-thread blocking time by vendor. The Network tab can filter by third-party domain, and the Performance panel attributes long tasks to the script URL.

# Network tab -> right-click request -> Block request domain, then reload

The experiment of blocking a domain and re-measuring is the most direct way to put a number on what a script costs. Then ask whether the value it provides is worth that cost.

§3Containing the Damage

TacticWhat it does
Audit and removeDelete tags nobody uses. This is the biggest win.
async or deferStop the script blocking the parser
Load after interaction or idleDelay chat widgets until the user shows intent
FacadesShow a lightweight placeholder, such as a video thumbnail, and load the real embed on click
preconnectWarm the connection for a third party you really need early
Self-host static assetsRemove a third-party connection, if licensing allows
loading="lazy" on iframesDefer offscreen embeds
<div class="video-facade" data-id="abc123">
  <img src="thumb.jpg" width="640" height="360" loading="lazy" alt="Play video">
  <button>Play</button>
</div>
<!-- JS swaps in the real iframe only when the button is clicked -->
Ownership Third-party tags tend to accumulate because anyone can add one and nobody removes one. Keep a list of what's on the page, who asked for it, and what it costs.

§4Common Mistakes

MistakeWhat HappensFix
Letting every team add tags freelyPage weight and blocking grow unnoticedKeep an inventory and review it regularly
Loading a chat widget at page startHeavy JavaScript runs before the user needs itLoad it on idle or on first interaction
Embedding a video player directlyLarge scripts and requests on every viewUse a facade that loads on click
Practice
  1. Run Lighthouse and write down the three third parties with the greatest main-thread time.
  2. Block one vendor's domain in DevTools and compare LCP and Total Blocking Time with and without it.
Key takeaways
  • Third-party scripts add network cost, main-thread work, and risk you don't control.
  • Measure each vendor's cost, for instance by blocking its domain and re-measuring.
  • Remove what's unneeded, delay the rest, and use facades for heavy embeds.
