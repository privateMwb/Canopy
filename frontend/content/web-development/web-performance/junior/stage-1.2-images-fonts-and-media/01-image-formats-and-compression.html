Image Formats & Compression

Images are usually the heaviest thing on a page. Choosing the right format and compressing it well is often the biggest single win.

§1Choosing a Format

There is no best format, only the best format for the content. Raster formats store pixels. Vector formats store shapes, and stay sharp at any size.

FormatBest forNotes
JPEGPhotosUniversal, lossy, no transparency
PNGSharp graphics needing lossless pixels or transparencyLarge for photos
WebPPhotos and graphicsTypically smaller than JPEG and PNG; broad support
AVIFPhotos where size matters mostOften the smallest, slower to encode; wide support
SVGLogos, icons, simple illustrationsVector, tiny, scales perfectly, can be styled

A sensible default today is AVIF or WebP with a JPEG fallback for photos, and SVG for anything that is genuinely a shape. Don't use PNG for photographs: it can be many times larger than the same image as a lossy format.

§2Compression and Quality

Lossy compression discards detail the eye is unlikely to notice. Lossless compression keeps every pixel but saves less. For photos, lossy is the normal choice, and the quality setting is the lever.

  • Quality around 70 to 85 is usually visually indistinguishable from 100 at a fraction of the size.
  • Compare images side by side at the size they are displayed. Artifacts you only see zoomed in don't matter to users.
  • Strip unneeded metadata (camera data, color profiles you don't use) to shave bytes.
# Convert and compress with common command-line tools
cwebp -q 80 hero.jpg -o hero.webp
avifenc --min 20 --max 35 hero.jpg hero.avif
svgo logo.svg -o logo.min.svg

Build pipelines and image CDNs can do this automatically, resizing and converting on the fly. Whichever route you use, make it the default, not a manual step someone forgets.

§3Serving Modern Formats Safely

The <picture> element lets the browser pick the first format it supports, so old browsers still get an image.

<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" width="1200" height="600" alt="A mountain at sunrise">
</picture>

Always set width and height (or aspect-ratio in CSS) so the browser reserves space before the image arrives. This prevents layout shift, covered later in the course.

The key insight Format and quality settings change bytes far more than any code optimization. Check image weight first when a page is heavy.

§4Common Mistakes

MistakeWhat HappensFix
Using PNG for photographsFiles several times larger than neededUse AVIF, WebP, or JPEG for photos
Saving everything at maximum qualityWasted bytes with no visible gainTest 70 to 85 and compare at display size
Serving AVIF or WebP with no fallbackOlder browsers show a broken imageUse <picture> with a JPEG <img> fallback
Practice
  1. Take one photo and export it as JPEG, WebP, and AVIF at similar visual quality. Record each file size.
  2. Replace a logo PNG with an SVG and compare the size and sharpness on a high-density screen.
Key takeaways
  • Use SVG for shapes, and AVIF or WebP with a JPEG fallback for photos.
  • Lossy quality around 70 to 85 usually looks the same at a much smaller size.
  • <picture> serves modern formats safely, and width and height prevent layout shift.
