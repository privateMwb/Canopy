Lazy Loading

Don't download what the user hasn't scrolled to. Lazy loading defers offscreen images and iframes, but the wrong image deferred hurts more than it helps.

§1Native Lazy Loading

Browsers can defer offscreen images and iframes with a single attribute. The resource is fetched only when it is about to come into view.

<img src="gallery-12.jpg" width="600" height="400" loading="lazy" alt="...">
<iframe src="https://example.com/map" loading="lazy" title="Map"></iframe>

This saves bandwidth for content many users never reach, and leaves more capacity for what they do see. Keep width and height set, so the space is reserved and the page doesn't jump when the image appears.

§2The Most Common Mistake

Lazy loading is for things below the fold. Never lazy load the image that is likely to be your LCP element, such as a hero image. Deferring it delays the largest paint, which makes LCP worse.

ImageWhat to do
Hero or banner above the foldloading="eager" (the default), consider fetchpriority="high"
Product images below the foldloading="lazy"
Images in a carousel after the first slideloading="lazy"
Anything the user sees immediatelyLoad normally
<img src="hero.jpg" fetchpriority="high" width="1600" height="700" alt="...">   <!-- above the fold: prioritize -->
<img src="card-9.jpg" loading="lazy" width="400" height="300" alt="...">         <!-- below the fold: defer -->

§3When You Need More Control

Native lazy loading covers most cases. For custom behavior, such as lazy loading a background image or a heavy widget, use an IntersectionObserver, which tells you when an element nears the viewport.

const io = new IntersectionObserver((entries, obs) => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    e.target.src = e.target.dataset.src;   // start the real load
    obs.unobserve(e.target);
  }
}, { rootMargin: '200px' });              // start a little early

document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));

Beware: images that only load once JavaScript runs are invisible to the browser's early scanner and fail without scripts. Prefer the native attribute when it does the job.

Rule of thumb Above the fold: load eagerly and prioritize. Below the fold: load lazily. Check what your LCP element is before applying loading="lazy" broadly.

§4Common Mistakes

MistakeWhat HappensFix
Adding loading="lazy" to every imageThe hero image is delayed and LCP gets worseLeave above-the-fold images eager
Lazy loading without width and heightContent jumps as images appearAlways reserve space
Replacing native lazy loading with a script for no reasonLate discovery and a dependency on JavaScriptUse the native attribute where possible
Practice
  1. On an image-heavy page, add loading="lazy" to images below the fold. Compare the bytes transferred on initial load.
  2. Find your page's LCP element in DevTools and confirm it is not lazy loaded.
Key takeaways
  • loading="lazy" defers offscreen images and iframes with no JavaScript.
  • Never lazy load the LCP image, and give above-the-fold images priority.
  • Reserve space with width and height, and reach for IntersectionObserver only when native isn't enough.
