Responsive Images

A phone doesn't need a 3000-pixel-wide photo. Responsive images let the browser download only the size it will actually use.

§1Why Size Matters

If you serve one large image to everyone, a small screen downloads many times more pixels than it can show. The goal is to offer several sizes of the same image and let the browser choose, based on the layout width and the screen's pixel density.

ConceptMeaning
CSS pixelsThe layout unit; a phone might be 390 wide
Device pixel ratio (DPR)Physical pixels per CSS pixel; 2× or 3× on many phones
Intrinsic widthThe real pixel width of an image file

An image shown 400 CSS pixels wide on a 2× screen needs about 800 pixels of real width to look sharp. More than that is wasted, and less will look blurry.

§2srcset and sizes

srcset lists candidate files with their widths, using the w descriptor. sizes tells the browser how wide the image will be in the layout, before the CSS is available, so it can pick early.

<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w,
          photo-800.jpg 800w,
          photo-1600.jpg 1600w"
  sizes="(min-width: 900px) 600px, 100vw"
  width="800" height="533"
  alt="Harbour at dusk">

Read sizes like this: on screens at least 900px wide the image is 600px wide, otherwise it fills the viewport. The browser multiplies by the pixel density and picks the closest candidate.

Gotcha If sizes is wrong or missing, the browser assumes the image is 100vw and may download a far larger file than needed. Setting sizes accurately is where most of the saving comes from.

§3Art Direction and Density Switching

Sometimes you want a different crop at different sizes, such as a wide banner on desktop and a tight portrait on mobile. That is art direction, and it uses <picture> with media queries.

<picture>
  <source media="(max-width: 600px)" srcset="hero-portrait.jpg">
  <img src="hero-wide.jpg" width="1600" height="600" alt="Team at work">
</picture>

For fixed-size images such as an avatar, a simpler density descriptor works: srcset="a.jpg 1x, a@2x.jpg 2x". Use w plus sizes for fluid images, and x for fixed ones.

§4Common Mistakes

MistakeWhat HappensFix
Omitting sizes with a w srcsetThe browser assumes full-width and over-downloadsDescribe the real layout width in sizes
Using srcset with only one huge fileNo saving on small screensGenerate at least three widths
Using <picture> when only resolution differsExtra markup for nothingUse srcset and sizes; reserve <picture> for art direction and formats
Practice
  1. Generate three widths of one image and add srcset and sizes. In DevTools, resize the window and watch which file loads.
  2. Test on a 2× screen or emulated device. Compare the downloaded file to what a 1× window picks.
Key takeaways
  • Serve several widths so each device downloads only what it can display.
  • srcset lists the candidates and sizes tells the browser the layout width, and both matter.
  • Use <picture> for different crops or formats, and srcset alone for plain resolution switching.
