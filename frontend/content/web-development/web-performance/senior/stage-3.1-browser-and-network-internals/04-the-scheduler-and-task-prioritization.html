The Scheduler & Task Prioritization

The main thread runs one task at a time. Scheduling APIs let you decide what runs first, what can wait, and when to give control back so the page stays responsive.

§1The Event Loop and Priorities

The browser's main thread runs a loop: take a task, run it to completion, update rendering if it's time, repeat. A task can't be interrupted, so a long task blocks input and painting until it finishes. All work competes in a single queue, and the browser makes its own decisions about order, which treats user input as most urgent and background work as least.

PriorityExamples
User-blockingResponding to a click or keypress, updating visible state
User-visibleRendering content the user is looking at, but not directly responding to
BackgroundAnalytics, prefetching, cache warming, logging

The problem is that your code has its own idea of importance, and a plain setTimeout doesn't express it. Scheduling APIs let you state your intent.

§2scheduler.postTask and scheduler.yield

// Run background work at low priority so it never competes with input
scheduler.postTask(() => sendAnalytics(), { priority: 'background' });

// Important work, run soon
scheduler.postTask(() => updateVisibleList(), { priority: 'user-visible' });

// Cancel work that is no longer needed
const controller = new TaskController({ priority: 'background' });
scheduler.postTask(buildIndex, { signal: controller.signal });
controller.abort();

scheduler.yield() pauses your function and lets the browser handle pending input and rendering, then resumes your work with priority, ahead of other queued tasks. This makes chunking long work much more predictable than a bare setTimeout, which sends the continuation to the back of the queue.

async function processInChunks(items) {
  for (let i = 0; i < items.length; i++) {
    handle(items[i]);
    if (i % 50 === 0) await scheduler.yield();   // let input and paint run
  }
}

// Feature-detect and fall back: 
const yieldNow = globalThis.scheduler?.yield
  ? () => scheduler.yield()
  : () => new Promise(r => setTimeout(r, 0));

§3Putting It to Work

  • Use isInputPending() (where available) inside long loops to yield only when the user has actually tried to interact.
  • requestIdleCallback runs work when the browser is idle. It is good for low-value work, but it can starve on busy pages, so give it a timeout for anything that must eventually run.
  • Break work by priority: do the visible update first, then yield, then defer everything else.
  • Coordinate third-party code. Their long tasks compete with yours, and wrapping or delaying their loading is part of scheduling.
  • Measure with the Long Animation Frames API (long-animation-frame entries), which attributes slow frames to specific scripts.
new PerformanceObserver(list => {
  for (const e of list.getEntries()) {
    console.log('slow frame', Math.round(e.duration), 'ms', e.scripts.map(s => s.sourceURL));
  }
}).observe({ type: 'long-animation-frame', buffered: true });

Support for these APIs varies between browsers, so feature-detect and always provide a fallback. Treat them as progressive enhancements to the same principle: keep tasks short and run the important ones first.

Gotcha setTimeout(fn, 0) doesn't mean 'right away'. It queues behind everything already waiting. scheduler.yield() is designed to resume your work sooner.

§4Common Mistakes

MistakeWhat HappensFix
Using setTimeout(0) to yield in a long loopYour continuation waits behind unrelated tasksUse scheduler.yield() with a fallback
Running analytics at the same priority as UI updatesBackground work delays inputPost it at background priority
Assuming scheduling APIs exist everywhereCode breaks in browsers without themFeature-detect and fall back
Practice
  1. Chunk a long loop using scheduler.yield() with a setTimeout fallback, and show the long task split in a trace.
  2. Capture long animation frames in a page and identify the script responsible for the worst one.
Key takeaways
  • The main thread runs tasks to completion, so priority and chunking decide responsiveness.
  • scheduler.postTask expresses priority and scheduler.yield resumes work sooner than setTimeout.
  • Feature-detect, fall back, and use long-animation-frame data to find what blocks.
