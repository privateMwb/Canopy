Fixing CLS

Layout shifts happen when something loads late and pushes content around. The cure is nearly always the same: reserve space before the content arrives.

§1How CLS Is Scored

A layout shift occurs when a visible element moves between frames without a user action. Each shift is scored by how much of the viewport moved (impact fraction) and how far (distance fraction), multiplied together. CLS reports the worst burst of shifts, grouped in short windows, over the page's life. Good is 0.1 or less.

Shifts that follow a user input, such as expanding a menu within about half a second of a click, are excluded. The target is surprise movement.

§2The Usual Causes and Fixes

CauseFix
Images and video without dimensionsSet width and height, or CSS aspect-ratio
Ads, embeds, and iframes injected lateReserve a container with a fixed or minimum size
Web fonts swapping and reflowing textfont-display plus size-adjust on a matching fallback
Banners or notices inserted above contentReserve their space, or overlay them instead of pushing
Content injected by JavaScript above existing contentInsert below the fold or in reserved space
Animations that change layout propertiesAnimate transform instead
<!-- The browser can compute the box before the image loads -->
<img src="photo.jpg" width="800" height="600" alt="...">

/* Responsive: keep intrinsic ratio, scale with the container */
img { max-width: 100%; height: auto; }

/* Reserve space for a late-loading ad slot */
.ad-slot { min-height: 250px; aspect-ratio: 300 / 250; }

§3Finding Shifts

Shifts are easy to cause and hard to see. Use tools that name the element.

  • The Performance panel's Layout Shifts track lists each shift and highlights the elements that moved.
  • Chrome's Rendering tab can flash shifted regions as you use the page.
  • web-vitals attribution reports the largest shift source in the field, so you can see which element hurts real users.
new PerformanceObserver(list => {
  for (const e of list.getEntries()) {
    if (!e.hadRecentInput) console.log('shift', e.value, e.sources?.map(s => s.node));
  }
}).observe({ type: 'layout-shift', buffered: true });

Test with a throttled network and a cleared cache. Shifts often disappear on a fast connection where everything arrives before first paint. Also scroll and interact, since many shifts happen after load.

Rule of thumb If something will appear later, give it a box now. The content can arrive when it likes, and the page won't move.

§4Common Mistakes

MistakeWhat HappensFix
Omitting width and height on imagesThe page reflows as each image loadsAlways set dimensions or aspect-ratio
Inserting a cookie banner at the topEverything below jumps downReserve space or overlay it at the bottom
Testing only on a fast connection with a warm cacheShifts stay hidden until real users hit themThrottle and clear the cache
Practice
  1. Find the largest layout shift on a page using the Performance panel, and name the element that moved.
  2. Fix it by reserving space, then re-record and confirm the shift is gone.
Key takeaways
  • CLS scores unexpected movement by how much of the screen moved and how far.
  • Reserve space for images, embeds, ads, banners, and fonts before they load.
  • Find the shifting element with traces and attribution, and test under throttling.
