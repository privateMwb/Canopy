Code Splitting & Dynamic Imports

Most users never need most of your code on first load. Code splitting ships a small initial bundle and loads the rest when it's needed.

§1Splitting With Dynamic import()

A static import is bundled into the initial file. A dynamic import() returns a promise and tells the bundler to put that module in a separate chunk, fetched on demand.

// Static: always in the main bundle
import { renderChart } from './chart.js';

// Dynamic: fetched only when the user opens the report
reportButton.addEventListener('click', async () => {
  const { renderChart } = await import('./chart.js');
  renderChart(data);
});

Bundlers such as Vite, Rollup, webpack, and esbuild create the chunk and its hashed filename for you.

§2Where to Split

Split pointExampleNotes
RouteEach page loads its own codeThe best default. Users only pay for the page they visit.
Feature or interactionRich text editor, charts, PDF exportLoad on click, hover, or when visible
Heavy libraryMaps, 3D, syntax highlightingLoad only where used
Below the foldComments, recommendationsLoad when scrolled near
// React: route-level splitting
import { lazy, Suspense } from 'react';
const Settings = lazy(() => import('./pages/Settings'));

<Suspense fallback={<Spinner />}>
  <Settings />
</Suspense>

Also split out vendor code that changes rarely from your app code that changes often. Stable chunks keep their hashes across deploys and stay cached.

§3Avoiding the Downsides

Splitting trades one big download for several smaller ones, and a poor split can make things slower, because the code now arrives late.

  • Request waterfalls: a chunk that imports another chunk adds a round trip. Check the Network panel for chains.
  • Visible delays: a user clicks and waits for a chunk. Show immediate feedback, and prefetch the likely next chunk when idle or on hover.
  • Too many tiny chunks: per-request overhead and lost compression benefits add up.
  • Never split the critical path: the code needed for the first screen should be in the initial bundle.
// Warm the chunk when the user shows intent
link.addEventListener('pointerenter', () => import('./pages/Settings'), { once: true });

// or hint it in HTML
// <link rel="modulepreload" href="/assets/settings.8ac1.js">
The key insight Split by what the user does next, and prefetch what they are likely to do. The goal is a small first load without a visible wait later.

§4Common Mistakes

MistakeWhat HappensFix
Splitting code needed for the first screenIt arrives late and delays renderingKeep first-screen code in the main bundle
Lazy loading with no loading stateUsers click and nothing visibly happensShow feedback and prefetch on intent
Creating hundreds of tiny chunksOverhead outweighs the benefitSplit at meaningful boundaries
Practice
  1. Convert one route or heavy feature in a project to a dynamic import and confirm a separate chunk appears in the build.
  2. Add a prefetch on hover for that chunk and verify it in the Network panel.
Key takeaways
  • Dynamic import() puts code in separate chunks loaded on demand.
  • Split by route, feature, and heavy library, and keep first-screen code in the main bundle.
  • Beware of chains and waits: show feedback and prefetch on intent.
