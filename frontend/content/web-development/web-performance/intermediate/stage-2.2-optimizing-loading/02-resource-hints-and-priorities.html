Resource Hints & Priorities

The browser decides what to fetch and in what order using its best guess. Resource hints let you correct that guess when you know better.

§1How Priority Works

Browsers assign each request a priority: render-blocking CSS and the main document are highest, scripts and fonts are typically medium or high, and images are usually low until the browser knows they are in the viewport. The scheduler uses priority to decide which requests get bandwidth first.

Often the problem is not priority but discovery. The browser can't prioritize a resource it hasn't found yet, such as a hero image set from CSS or JavaScript. Hints help in both cases. Use the Priority column in the Network panel to see what the browser chose.

§3Using Hints Without Hurting

Hints are not free. Every preload competes for bandwidth with something else, and preloading too much just moves the contention around.

  • Preload only a few critical resources. If everything is high priority, nothing is.
  • Match the details. A font preload needs crossorigin, and as and type should be correct. A mismatch makes the browser fetch it twice.
  • Don't preconnect to many origins. Each open connection costs resources, and unused ones are wasted.
  • Use fetchpriority="high" on at most the one or two images that are LCP candidates.
  • Verify in the waterfall that the hinted resource starts earlier and that nothing important now starts later.

The best fix for late discovery is often to put the resource in the HTML where the preload scanner can find it, instead of adding a hint to compensate for hiding it.

Gotcha A preload for something never used within a few seconds triggers a console warning, because you spent bandwidth on nothing. Treat that warning as a real bug.

§4Common Mistakes

MistakeWhat HappensFix
Preloading a font without crossoriginThe font is downloaded twiceAlways include crossorigin for fonts
Preloading dozens of resourcesContention makes the critical ones slowerPreload only the few that gate rendering
Setting fetchpriority="high" on many imagesPriority becomes meaninglessReserve it for the LCP candidate
Practice
  1. Find your page's LCP image in the Network panel. Note its priority and start time, then add a hint and compare.
  2. Add preconnect for a critical third-party origin and confirm in the waterfall that its connection time moved earlier.
Key takeaways
  • The browser prioritizes by type and position, and hints let you override its guess.
  • preconnect, preload, prefetch, and fetchpriority each solve a different problem.
  • Use few hints, match their attributes exactly, and verify the result in a waterfall.
