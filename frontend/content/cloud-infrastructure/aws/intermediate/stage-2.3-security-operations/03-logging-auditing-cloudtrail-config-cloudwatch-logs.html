Logging & Auditing: CloudTrail, Config & CloudWatch Logs

Three services answer the audit questions: CloudTrail records API calls, Config records resource state, and CloudWatch Logs holds application and service logs.

§1CloudTrail: Who Did What

CloudTrail records management API calls: who called what, from where, and when. The 90-day Event history is on by default; to keep records longer, create a trail that delivers to S3, ideally an organization trail covering every account and region.

aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=DeleteBucket

aws cloudtrail create-trail --name org-trail --s3-bucket-name audit-logs-bucket \
  --is-multi-region-trail --enable-log-file-validation

Data events (such as S3 object reads) are optional and billed separately, so enable them for sensitive buckets.

§2Config: What Changed

AWS Config records configuration history of resources and evaluates them against rules, for example "S3 buckets must not be public" or "EBS volumes must be encrypted". It answers "what did this security group look like last Tuesday" and "which resources are non-compliant now".

§3CloudWatch Logs: What Happened

Application logs, VPC Flow Logs, Lambda output, and many service logs land in CloudWatch Logs. Use metric filters to turn log patterns into alarms, and ship important logs to a separate account or S3 for tamper resistance.

QuestionService
Who deleted this bucket?CloudTrail
When did this setting change, and is it compliant?Config
What did the app do at 14:02?CloudWatch Logs
Protect the audit trail Logs are evidence. Send them to a separate, locked-down account, turn on log file validation, and restrict who can delete them, because an attacker's first move is often to erase their tracks.

§4Common Mistakes

MistakeWhat HappensFix
Relying on 90-day Event history onlyNo evidence of older eventsCreate an organization trail to S3
Logs stored in the same account attackers can accessLogs can be deleted or alteredCentralize in a dedicated log archive account
Config enabled in one region onlyBlind spots elsewhereEnable in all regions you use
Practice
  1. Create a trail and find your own recent sign-in event.
  2. Enable a Config rule for encrypted EBS volumes and find a non-compliant resource.
Key takeaways
  • CloudTrail records API activity, Config tracks resource state, CloudWatch Logs holds logs.
  • Keep audit data long-term and in a protected account.
  • Use all three together to answer who, what changed, and what happened.
