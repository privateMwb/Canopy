CloudFormation Fundamentals

CloudFormation turns templates into stacks, previews updates with change sets, and can detect drift from manual changes.

§1Template Anatomy

AWSTemplateFormatVersion: '2010-09-09'
Parameters:
  Env:
    Type: String
    AllowedValues: [dev, prod]
Conditions:
  IsProd: !Equals [!Ref Env, prod]
Resources:
  Bucket:
    Type: AWS::S3::Bucket
    DeletionPolicy: Retain
    Properties:
      VersioningConfiguration:
        Status: !If [IsProd, Enabled, Suspended]
Outputs:
  BucketName:
    Value: !Ref Bucket
    Export:
      Name: !Sub '${Env}-bucket-name'

Key sections: Parameters (inputs), Conditions, Resources (required), and Outputs (values to show or export). Intrinsic functions such as !Ref, !Sub, and !GetAtt wire resources together.

§2Stacks, Change Sets, and Rollback

aws cloudformation create-change-set --stack-name app \
  --change-set-name review-1 --template-body file://app.yaml
aws cloudformation describe-change-set --stack-name app --change-set-name review-1
aws cloudformation execute-change-set --stack-name app --change-set-name review-1

A change set previews what an update will add, modify, or replace. Pay special attention to Replacement: True, which means the resource will be recreated. If an update fails, CloudFormation rolls back to the previous state.

§3Protection and Drift

  • DeletionPolicy: Retain or Snapshot keeps data resources after a stack is deleted.
  • Stack policies and termination protection guard critical stacks.
  • Drift detection compares real resources with the template to reveal manual changes.
  • Split large systems into nested stacks or several stacks, linked with exports or parameters.
Read the change set for 'Replacement' A property change that forces replacement can delete and recreate a database. The change set tells you before it happens; read it every time for stateful resources.

§4Common Mistakes

MistakeWhat HappensFix
Updating without reviewing a change setUnexpected replacement of data resourcesPreview changes and use DeletionPolicy on stateful resources
Editing resources by hand in the consoleDrift and failed or reverting updatesChange only through the template; check drift
One huge template for everythingSlow, risky updates and hard ownershipSplit by lifecycle and ownership
Practice
  1. Deploy a stack, change a property, and read the change set before executing it.
  2. Edit a resource by hand and detect the drift.
Key takeaways
  • Templates describe resources; stacks deploy them as a unit with rollback.
  • Change sets reveal replacements before they happen.
  • Protect stateful resources and watch for drift.
