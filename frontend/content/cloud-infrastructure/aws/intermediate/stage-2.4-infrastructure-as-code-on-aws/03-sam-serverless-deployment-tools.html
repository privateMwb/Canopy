SAM & Serverless Deployment Tools

SAM is a CloudFormation extension that makes serverless applications short to define and easy to test and deploy.

§1The SAM Template

AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Globals:
  Function:
    Runtime: python3.12
    Timeout: 10
Resources:
  HelloFn:
    Type: AWS::Serverless::Function
    Properties:
      Handler: app.handler
      CodeUri: src/
      Events:
        Api:
          Type: HttpApi
          Properties:
            Path: /hello
            Method: get

The Transform line expands short AWS::Serverless::* resources into full CloudFormation, including the function, its role, and the API.

§2The SAM CLI Workflow

sam init
sam build
sam local invoke HelloFn --event events/get.json
sam local start-api
sam deploy --guided

sam local runs functions in containers on your machine for fast feedback, and sam sync can push code changes rapidly to a development stack.

§3Safe Deployments and Alternatives

  • Gradual deployments with AutoPublishAlias and DeploymentPreference shift traffic to a new version in steps (canary or linear) and roll back on alarms.
  • The CDK can also define serverless apps and works well with SAM tooling for local testing.
  • Other frameworks (Serverless Framework, Terraform) exist; choose by team skills and the rest of your toolchain.
Shift traffic, don't flip it With aliases and deployment preferences, a bad function version gets 10% of traffic and a failing alarm rolls it back, long before every user sees it.

§4Common Mistakes

MistakeWhat HappensFix
Deploying new Lambda code straight to all trafficBad release hits everyoneUse alias traffic shifting with alarms
Testing only in the cloudSlow feedback loopUse sam local and unit tests
Over-broad function roles from policy shortcutsExcess permissionsUse SAM policy templates or explicit scoped policies
Practice
  1. Build and deploy a SAM app with an HTTP API and test it locally first.
  2. Add a canary deployment preference and trigger a rollback with a failing alarm.
Key takeaways
  • SAM extends CloudFormation with short serverless resource types.
  • The SAM CLI builds, tests locally, and deploys.
  • Use gradual deployments to limit the blast radius of bad releases.
