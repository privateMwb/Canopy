Load Balancers & Auto Scaling Groups

A load balancer spreads requests across servers, and an Auto Scaling group keeps the right number of healthy servers running.

§1Elastic Load Balancing

TypeLayerUse for
Application (ALB)7 (HTTP/HTTPS)Web apps; path and host routing, WebSockets
Network (NLB)4 (TCP/UDP/TLS)Very high throughput, static IPs, non-HTTP protocols
Gateway (GWLB)3Inserting security and inspection appliances

An ALB routes by listener rules to target groups, and uses health checks to send traffic only to healthy targets.

# Example listener rules
Host: api.example.com          -> target group api
Path: /static/*                -> target group assets
Default                        -> target group web

§2Auto Scaling Groups

An Auto Scaling group (ASG) launches instances from a launch template across the subnets you give it, keeps the count between a minimum and maximum, and replaces instances that fail health checks.

aws autoscaling create-auto-scaling-group \
  --auto-scaling-group-name web-asg \
  --launch-template LaunchTemplateName=web,Version='$Latest' \
  --min-size 2 --max-size 6 --desired-capacity 2 \
  --vpc-zone-identifier "subnet-aaa,subnet-bbb" \
  --target-group-arns $TG_ARN \
  --health-check-type ELB --health-check-grace-period 120

Use ELB health checks so an instance that is running but not serving gets replaced, not just one that has crashed at the OS level.

§3Scaling on Demand

A target tracking policy keeps a metric near a target, for example average CPU at 50% or requests per target at a set number, adding and removing instances for you. Request count per target is often a better signal than CPU for web apps.

aws autoscaling put-scaling-policy --auto-scaling-group-name web-asg \
  --policy-name rps-target --policy-type TargetTrackingScaling \
  --target-tracking-configuration file://rps.json
Servers must be disposable Auto scaling only works if any instance can be killed and replaced. Keep state in databases, S3, or caches, and let a launch template build a ready server on its own.

§4Common Mistakes

MistakeWhat HappensFix
Health check type EC2 onlyHung apps stay in serviceUse ELB health checks with a sensible grace period
Storing session data on the instanceUsers logged out on scale-inUse a shared session store such as ElastiCache
Minimum of 1 instanceReplacement means downtimeUse a minimum of 2 across AZs for production
Practice
  1. Create an ASG behind an ALB across two AZs and confirm traffic reaches both.
  2. Add a target tracking policy and generate load to watch it scale out.
Key takeaways
  • ALBs route HTTP traffic to health-checked target groups.
  • ASGs maintain capacity across AZs and replace failed instances.
  • Scale on workload-relevant metrics and keep instances stateless.
