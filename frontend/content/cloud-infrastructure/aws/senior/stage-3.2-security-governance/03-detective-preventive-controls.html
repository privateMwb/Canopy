Detective & Preventive Controls

Good security combines preventive controls that stop bad actions with detective controls that find what slips through.

§1Preventive Controls

ControlPrevents
SCPsDisallowed actions and regions across accounts
IAM boundaries and least privilegeExcess permissions
S3 Block Public Access (account level)Public buckets
Security groups, WAF, private subnetsUnwanted network reachability
Declarative checks in pipelines (policy as code)Bad infrastructure before deployment

§2Detective Controls

ServiceDetects
GuardDutyThreats: unusual API calls, compromised instances, crypto-mining, suspicious DNS
Security HubAggregates findings and checks against standards
AWS ConfigNon-compliant resource configurations
InspectorVulnerabilities in EC2, containers, and Lambda
MacieSensitive data exposure in S3
IAM Access AnalyzerResources shared outside your organization, unused access

Run these through a delegated administrator security account for the whole organization, with findings routed to EventBridge for alerting and automated response.

§3Closing the Loop

GuardDuty finding: UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration
  → EventBridge rule
  → Lambda/Step Functions: tag instance, snapshot, isolate via security group
  → page on-call + open ticket

Detection without response is a dashboard nobody reads. Decide which findings are auto-remediated, which page a human, and which are reviewed in batches, and reduce noise so the important ones are not ignored.

Prevent the predictable, detect the rest Anything you can forbid cheaply (public buckets, disabling logging) should be blocked. Detection is for the long tail you cannot enumerate in advance.

§4Common Mistakes

MistakeWhat HappensFix
Enabling services in one account onlyGaps across the organizationEnable organization-wide with a delegated admin
No owner for findingsAlerts pile upRoute to owners with severity and SLAs
Auto-remediating without safeguardsRemediation breaks productionStart with notify-only, then automate safe fixes
Practice
  1. Enable GuardDuty and Security Hub in a test account and review the first findings.
  2. Write an EventBridge rule that sends high-severity findings to a notification topic.
Key takeaways
  • Preventive controls block known-bad actions; detective controls find the rest.
  • GuardDuty, Security Hub, Config, Inspector, Macie, and Access Analyzer each cover different risks.
  • Findings need owners, severity, and defined responses.
