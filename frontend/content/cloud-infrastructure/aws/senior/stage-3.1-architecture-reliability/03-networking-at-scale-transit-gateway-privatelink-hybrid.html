Networking at Scale: Transit Gateway, PrivateLink & Hybrid

As VPC count grows, point-to-point links stop scaling, so you need hub-and-spoke routing, private service exposure, and hybrid connectivity.

§1The Connectivity Options

OptionUse forWatch out for
VPC peeringSimple connection between two VPCsNot transitive; mesh explodes as VPCs grow
Transit GatewayHub connecting many VPCs and on-premisesRouting design and per-GB cost
PrivateLink (interface endpoints)Expose or consume one service privately, without routing whole networksPer-endpoint hourly and data charges
Gateway endpoints (S3, DynamoDB)Private access to those services at no endpoint chargeOnly for those two services
Site-to-Site VPNEncrypted tunnels over the internetBandwidth and latency vary
Direct ConnectDedicated private link to AWSLead time and cost; usually pair with VPN backup

§2Transit Gateway Design

A Transit Gateway has route tables and attachments for VPCs, VPNs, and Direct Connect gateways. Multiple route tables let you segment: shared services reachable by everyone, production isolated from development.

Spoke VPCs  ──attach──►  Transit Gateway  ◄──attach──  VPN / Direct Connect
   (prod)     route table A                                  (on-premises)
   (dev)      route table B   shared-services reachable from both

Plan non-overlapping CIDR ranges from the start; overlapping addresses make connecting networks painful or impossible.

§3PrivateLink and DNS

PrivateLink lets a provider expose a service behind a Network Load Balancer, and consumers reach it through an endpoint in their own VPC, with traffic staying on AWS's network and no route between the VPCs. It scales well because it connects services, not networks. Enable private DNS and use Route 53 Resolver for hybrid name resolution.

Connect services, not networks When a team needs one API from another, PrivateLink exposes exactly that. Routing two whole networks together exposes everything on both sides.

§4Common Mistakes

MistakeWhat HappensFix
Overlapping CIDR rangesNetworks cannot be connectedAllocate address space centrally (IPAM)
Peering mesh for dozens of VPCsUnmanageable route tablesUse Transit Gateway
Single VPN or single Direct ConnectOne failure cuts hybrid accessAdd redundancy: second link or VPN backup
Practice
  1. Design a hub-and-spoke network for prod, dev, and shared-services VPCs with isolation rules.
  2. Replace a peering connection with a PrivateLink service endpoint.
Key takeaways
  • Peering is simple but not transitive; Transit Gateway scales hub-and-spoke.
  • PrivateLink exposes individual services without joining networks.
  • Plan IP ranges early and build redundant hybrid links.
