CloudFront & Static Sites

CloudFront caches your content at edge locations, so a static site in a private S3 bucket can be fast and secure worldwide.

§1How CloudFront Works

A distribution sits in front of an origin (S3, a load balancer, or any HTTP server). Viewers connect to a nearby edge location; on a cache miss the edge fetches from the origin, stores it, and serves later requests from cache.

§2A Static Site Setup

  1. Keep the S3 bucket private with Block Public Access on.
  2. Create a distribution with the bucket as origin and Origin Access Control (OAC) so only CloudFront can read it.
  3. Set the default root object to index.html.
  4. Attach an ACM certificate (from us-east-1) and an alias record in Route 53.
  5. Redirect HTTP to HTTPS in the viewer protocol policy.
# Bucket policy allowing only this distribution (via OAC)
{
  "Effect": "Allow",
  "Principal": {"Service": "cloudfront.amazonaws.com"},
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::my-site-bucket/*",
  "Condition": {"StringEquals": {
    "AWS:SourceArn": "arn:aws:cloudfront::123456789012:distribution/E123ABC"}}
}

§3Caching and Invalidation

Objects are cached according to their cache headers and the distribution's cache policy. After you deploy new files, either create an invalidation or, better, use versioned file names (such as app.3f2a1c.js) so new content has a new URL and nothing needs invalidating.

aws cloudfront create-invalidation \
  --distribution-id E123ABC --paths "/index.html"
Version your assets Cache invalidation is the slow, awkward fix. Hashed asset names let you cache aggressively and ship updates instantly; only the small HTML entry point needs a short cache.

§4Common Mistakes

MistakeWhat HappensFix
Making the bucket public instead of using OACContent reachable around the CDNKeep it private and grant CloudFront access with OAC
Forgetting the default root objectVisiting the domain returns an errorSet index.html as the default root object
Serving updates that stay staleUsers see old files until cache expiresUse hashed filenames or invalidate changed paths
Practice
  1. Host a small static site in S3 and put CloudFront in front using OAC.
  2. Deploy a change and confirm users see it using both an invalidation and a hashed filename.
Key takeaways
  • CloudFront caches origin content at edge locations for speed.
  • Use a private bucket with Origin Access Control rather than a public bucket.
  • Version asset names so caching and fast updates both work.
