From Console to Code: CloudFormation & CDK Intro

Infrastructure as code describes your resources in files so they can be reviewed, repeated, and rolled back, instead of clicked together once.

§1Why Not Just Click?

Console work is slow to repeat, impossible to review, and leaves no record of what was configured. Code-defined infrastructure can be version-controlled, peer-reviewed, tested in a throwaway account, and recreated after a disaster.

§2CloudFormation

CloudFormation is AWS's native engine: you write a template (YAML or JSON) describing resources, create a stack, and CloudFormation creates, updates, and deletes them as one unit.

Resources:
  Logs:
    Type: AWS::S3::Bucket
    Properties:
      VersioningConfiguration:
        Status: Enabled
      PublicAccessBlockConfiguration:
        BlockPublicAcls: true
        BlockPublicPolicy: true
        IgnorePublicAcls: true
        RestrictPublicBuckets: true
aws cloudformation deploy --template-file bucket.yaml --stack-name demo-bucket

§3The CDK

The AWS CDK lets you define the same resources in a programming language such as TypeScript or Python, and it synthesizes CloudFormation templates.

import * as s3 from 'aws-cdk-lib/aws-s3';

new s3.Bucket(this, 'Logs', {
  versioned: true,
  blockPublicAccess: s3.BlockPublicAccess.BLOCK_ALL,
});

You get loops, functions, and defaults. Both tools end in CloudFormation, which is covered in depth in the intermediate level.

The template is the source of truth Once infrastructure is managed by code, changes go through the code. Hand edits in the console create drift that the next deployment may silently undo.

§4Common Mistakes

MistakeWhat HappensFix
Mixing console edits with stack-managed resourcesDrift and surprising rollbacksChange through the template only
Hardcoding account IDs and namesTemplate can't be reusedUse parameters and references
Skipping version control for templatesNo history or reviewKeep infrastructure code in git like application code
Practice
  1. Write a CloudFormation template for a private versioned S3 bucket and deploy it.
  2. Delete the stack and confirm the bucket is removed.
Key takeaways
  • Code-defined infrastructure is repeatable, reviewable, and recoverable.
  • CloudFormation deploys templates as stacks; the CDK generates those templates from code.
  • Treat the template as the only way to change what it manages.
