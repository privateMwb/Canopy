VPC Basics

A VPC is your private network inside AWS; subnets, route tables, and gateways decide what can talk to what and to the internet.

§1The Building Blocks

A VPC is an isolated virtual network with an IP range (CIDR block) such as 10.0.0.0/16. You divide it into subnets, each in a single AZ. Every account starts with a default VPC in each region, which is fine for experiments but not for real systems.

§2What Makes a Subnet Public

A subnet is public if its route table sends internet traffic (0.0.0.0/0) to an internet gateway, and its instances have public IPs. It is private if it has no such route.

Route table for public subnet:
10.0.0.0/16   local
0.0.0.0/0     igw-0abc123

Route table for private subnet:
10.0.0.0/16   local
0.0.0.0/0     nat-0def456   # outbound only, via NAT gateway

A NAT gateway (in a public subnet) lets private instances reach the internet outbound without being reachable from it. It costs per hour plus per GB, so it is a common cost surprise.

§3A Typical Layout

SubnetHoldsInternet route
Public (per AZ)Load balancers, NAT gatewayInternet gateway
Private app (per AZ)Application serversNAT gateway for outbound
Private data (per AZ)DatabasesNone

Use at least two AZs and size CIDR blocks generously, because changing them later is painful.

Public is a routing fact "Public subnet" is not a setting: it is the existence of a route to an internet gateway. Checking the route table tells you the truth faster than the subnet's name.

§4Common Mistakes

MistakeWhat HappensFix
Putting databases in public subnetsDirect internet exposurePlace data stores in private subnets
Overlapping CIDR ranges across VPCsPeering and VPN connections fail laterPlan address space across the organization
Forgetting NAT gateway costsSteady hourly and per-GB chargesShare gateways deliberately; consider VPC endpoints
Practice
  1. Create a VPC with two public and two private subnets across two AZs.
  2. Launch an instance in the private subnet and confirm it reaches the internet only through NAT.
Key takeaways
  • A VPC is carved into per-AZ subnets with route tables controlling traffic.
  • A subnet is public only if it routes to an internet gateway.
  • Keep servers and databases private; NAT gives outbound-only access.
