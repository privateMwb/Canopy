Security Groups, NACLs & Basic Network Security

Security groups and network ACLs are two layers of traffic filtering with different behaviors you need to tell apart.

§1Security Groups

A security group is a virtual firewall attached to an instance's network interface. Rules only allow; anything not allowed is denied. It is stateful: if a request is allowed in, the response is allowed out automatically.

aws ec2 authorize-security-group-ingress \
  --group-id sg-0web \
  --protocol tcp --port 443 --cidr 0.0.0.0/0

aws ec2 authorize-security-group-ingress \
  --group-id sg-0db \
  --protocol tcp --port 5432 \
  --source-group sg-0web   # only the web tier may connect

Referencing another security group as the source is more robust than IP ranges, because it follows instances as they come and go.

§2Network ACLs

A network ACL works at the subnet boundary, has numbered rules evaluated in order, supports both allow and deny, and is stateless, so you must allow return traffic yourself (including ephemeral ports).

Security groupNetwork ACL
Applies toInstance interfaceSubnet
RulesAllow onlyAllow and deny
StateStatefulStateless
EvaluationAll rules togetherIn number order

§3Putting It Together

  • Use security groups as the main control: one per tier, referencing each other.
  • Use NACLs sparingly, for coarse blocks such as denying a hostile IP range.
  • Never expose SSH, RDP, or database ports to 0.0.0.0/0.
  • Turn on VPC Flow Logs to see accepted and rejected traffic when debugging.
Reference groups, not addresses Letting the database group accept traffic only from the web group expresses the real intent ("only the app talks to the database") and stays correct when IPs change.

§4Common Mistakes

MistakeWhat HappensFix
Opening 0.0.0.0/0 on admin or database portsInternet scanners reach sensitive servicesAllow only specific sources or use Session Manager
Editing NACLs and forgetting return trafficConnections hang one-wayAllow ephemeral ports both ways, or rely on security groups
Reusing one security group for everythingRules get too broadCreate one per role or tier
Practice
  1. Build web and database security groups so only the web group can reach port 5432.
  2. Enable VPC Flow Logs and find a rejected connection.
Key takeaways
  • Security groups are stateful allow-lists on instances.
  • NACLs are stateless, ordered allow/deny rules on subnets.
  • Use security-group references and keep sensitive ports closed to the internet.
