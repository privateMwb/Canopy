Volumes & PersistentVolumeClaims

Container filesystems vanish with the pod, so durable data needs a PersistentVolumeClaim that outlives any single pod.

§1Volumes Inside a Pod

A pod can declare volumes and mount them into containers. Some are temporary:

  • emptyDir: an empty directory created when the pod starts and deleted when the pod is removed. Useful as scratch space or to share files between containers in the same pod.
  • configMap and secret: expose those objects as files.

None of these survive pod deletion if they are emptyDir. For data that must persist, you need persistent storage.

§2PersistentVolumes and Claims

Kubernetes separates who provides storage from who needs it:

  • A PersistentVolume (PV) is a piece of storage in the cluster, such as a cloud disk or network share.
  • A PersistentVolumeClaim (PVC) is a pod's request for storage: how much, and what access mode.
  • Kubernetes binds a claim to a suitable volume.

In most clusters you only write the claim, and a StorageClass creates the volume on demand.

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: data
spec:
  accessModes: ["ReadWriteOnce"]
  resources:
    requests:
      storage: 5Gi

Then the pod references the claim:

spec:
  containers:
    - name: db
      image: postgres:16
      volumeMounts:
        - name: pgdata
          mountPath: /var/lib/postgresql/data
  volumes:
    - name: pgdata
      persistentVolumeClaim:
        claimName: data

§3Access Modes and Reclaim

Access modeMeaning
ReadWriteOnceMounted read-write by a single node (the common block-disk case)
ReadOnlyManyMounted read-only by many nodes
ReadWriteManyRead-write by many nodes; needs a shared filesystem such as NFS
ReadWriteOncePodRead-write by exactly one pod

When a claim is deleted, the volume's reclaim policy decides what happens: Delete removes the underlying disk, Retain keeps it for manual cleanup. Cloud defaults are often Delete, so deleting a claim can destroy data.

kubectl get pvc
kubectl get pv
kubectl describe pvc data       # check Events if it stays Pending
Pending claims A PVC stuck in Pending usually means no StorageClass could satisfy it, or the class waits until a pod uses the claim. Read the Events from describe.

§4Common Mistakes

MistakeWhat HappensFix
Writing data to the container filesystemIt is lost when the pod is replacedMount a PVC at the path that holds data
Running a multi-replica Deployment on a ReadWriteOnce diskPods on other nodes cannot mount itUse a StatefulSet with per-pod volumes, or a ReadWriteMany store
Deleting a PVC casuallyThe reclaim policy may delete the diskCheck reclaimPolicy and take a backup first
Practice
  1. Create a PVC, mount it in a pod, write a file, delete the pod, recreate it, and confirm the file remains.
  2. Run kubectl get pv and map each volume back to its claim.
Key takeaways
  • emptyDir is temporary; PVCs outlive pods.
  • A PVC requests storage and a PV provides it, usually created dynamically.
  • Access modes and reclaim policy decide who can mount it and what happens when it is released.
