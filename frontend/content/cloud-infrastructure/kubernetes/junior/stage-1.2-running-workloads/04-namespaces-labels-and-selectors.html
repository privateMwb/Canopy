Namespaces, Labels & Selectors

Namespaces divide a cluster into named areas, and labels and selectors are how every Kubernetes object finds and groups the others.

§1Namespaces

A namespace is a scope for names. Two teams can each have a Deployment called web if they live in different namespaces. Namespaces are also the unit for access rules and resource quotas, which later stages cover.

kubectl get namespaces
kubectl create namespace staging
kubectl get pods -n staging
kubectl config set-context --current --namespace=staging   # change your default

A fresh cluster has default, kube-system (cluster components), kube-public, and kube-node-lease. Put your own apps in dedicated namespaces rather than default.

You can also set metadata.namespace in a manifest, or pass -n on the command line. Some objects, such as Nodes and Namespaces themselves, are cluster-scoped and belong to no namespace.

What namespaces are not A namespace is an organizing boundary, not a security boundary by default. Pods in different namespaces can still talk to each other unless you add network policies, and nothing limits resource use until you add quotas.

§2Labels

Labels are key-value pairs attached to objects in metadata.labels. They carry no meaning to Kubernetes itself; you invent them to describe your things.

metadata:
  labels:
    app: web
    tier: frontend
    env: prod
    version: v2

A widely used convention is the app.kubernetes.io/ family (app.kubernetes.io/name, app.kubernetes.io/version), which tools understand.

§3Selectors

A selector queries labels. Services, Deployments, and kubectl all use them.

kubectl get pods -l app=web
kubectl get pods -l 'env in (prod,staging)'
kubectl get pods -l app=web,tier=frontend       # comma means AND
kubectl label pod web-abc version=v3 --overwrite

Equality selectors (app=web) and set-based ones (env in (...), !debug) both work. In manifests, matchLabels is the equality form and matchExpressions the set form.

Labels are for selecting; annotations (metadata.annotations) are for non-identifying notes such as build info, contact details, or tool configuration, and cannot be used in selectors.

§4Common Mistakes

MistakeWhat HappensFix
Everything in the default namespaceNames collide and cleanup is hardUse one namespace per app or team
Inconsistent label names (App, app, application)Selectors silently match nothingAgree on a label scheme and follow it
Treating namespaces as securityCross-namespace traffic and access are still openAdd RBAC, network policies, and quotas
Practice
  1. Create two namespaces, deploy the same app in both, and compare kubectl get pods -A.
  2. Use -l to select only pods with tier=frontend, then relabel one pod and rerun the query.
Key takeaways
  • Namespaces scope names, access, and quotas; they do not isolate by themselves.
  • Labels are free-form key-value tags; selectors query them.
  • Consistent labels are what let Services and Deployments find the right pods.
