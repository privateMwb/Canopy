Images & Registries for Kubernetes

A cluster can only run images it can pull, so registry access, tag discipline, and pull secrets decide whether your pods start.

§1How Images Are Pulled

When a pod is scheduled, the node's container runtime pulls each image from its registry. The reference has the form registry/repository:tag or registry/repository@sha256:.... With no registry prefix, Docker Hub is assumed, and anonymous pulls there are rate limited, so busy clusters usually use a registry they control.

§2Tags and Digests

ReferenceBehavior
myapp:latestMoves over time; different nodes may run different builds
myapp:1.4.2A readable version, but the registry can retag it
myapp:1.4.2-3f9c1abVersion plus commit hash, unique per build
myapp@sha256:9b2f...A digest: content-addressed and immutable

A good habit is one unique tag per build, pinned in the manifest, with a digest for the strictest environments. imagePullPolicy controls when nodes pull: IfNotPresent is the default for versioned tags, and Always is the default for latest.

§3Private Registries and Pull Secrets

For a private registry, create a docker-registry Secret and let the pod use it:

kubectl create secret docker-registry regcred \
  --docker-server=registry.example.com \
  --docker-username=ci-bot \
  --docker-password="$REGISTRY_TOKEN"
spec:
  imagePullSecrets:
    - name: regcred
  containers:
    - name: app
      image: registry.example.com/team/app:1.4.2

Attaching the secret to the namespace's default ServiceAccount applies it to every pod there without editing each manifest.

On the big clouds you often skip pull secrets entirely: ECR, Artifact Registry, and ACR can authorize the cluster's nodes through the cloud identity, so the nodes pull without a stored password.

§4Diagnosing Pull Failures

kubectl describe pod web | grep -A3 -i 'pull\|failed'

Typical messages: manifest unknown (the tag does not exist), unauthorized (missing or wrong pull secret), no such host (a typo in the registry name or no network route). If it works on your laptop but not the cluster, check that the nodes, not you, can reach and authenticate to the registry.

Pinning matters for rollbacks If a tag can change, rollout undo may bring back the same new image under the old name. Immutable tags or digests make a rollback truly return to what ran before.

§5Common Mistakes

MistakeWhat HappensFix
Using latest in productionPods run mismatched builds and rollbacks are unreliableUse unique, immutable tags or digests
Pull secret in the wrong namespaceSecrets are namespaced, so pods cannot find itCreate the secret in the pod's namespace
Relying on Docker Hub anonymous pullsRate limits break scale-upsMirror to your own registry or use authenticated pulls
Practice
  1. Create a pull secret for a private registry and reference it from a pod.
  2. Rewrite a manifest to pin an image by digest instead of tag.
Key takeaways
  • Image references combine registry, repository, and tag or digest.
  • Private registries need pull secrets, or cloud identity on the major providers.
  • Unique, immutable tags keep deployments predictable and rollbacks honest.
