Namespaces & cgroups

A container is a normal Linux process wrapped in namespaces that limit what it can see and cgroups that limit what it can use.

§1Namespaces: What a Process Can See

A namespace gives a process its own view of one kind of resource.

  • pid: its own process tree, where the container's first process is PID 1.
  • net: its own network interfaces, routes, and ports.
  • mnt: its own mount table and root filesystem.
  • uts: its own hostname.
  • ipc: its own shared memory and semaphores.
  • user: its own user and group id mappings, so root inside can be an ordinary user outside.
  • cgroup and time namespaces for the cgroup view and clocks.
sudo unshare --pid --fork --mount-proc --uts --net bash
hostname container-demo        # affects only this namespace
ps aux                         # only a handful of processes
ip link                        # only loopback
ls -l /proc/$$/ns              # the namespaces a process belongs to
sudo lsns                      # all namespaces on the host

§2cgroups: What a Process Can Use

Control groups limit and account for CPU, memory, I/O, and process counts. In cgroup v2, they are a file hierarchy.

sudo mkdir /sys/fs/cgroup/demo
echo 100M | sudo tee /sys/fs/cgroup/demo/memory.max
echo "50000 100000" | sudo tee /sys/fs/cgroup/demo/cpu.max    # 50% of one CPU
echo $$ | sudo tee /sys/fs/cgroup/demo/cgroup.procs           # put this shell in the group
cat /sys/fs/cgroup/demo/memory.current

docker run --memory 512m writes memory.max for that container's group, and exceeding it invokes the kernel OOM killer.

§3Putting It Together

Docker creates a set of namespaces, a cgroup, a root filesystem, a security profile, and starts your process inside them. That is the whole trick.

docker run -d --name demo nginx
PID=$(docker inspect -f '{{.State.Pid}}' demo)
sudo ls -l /proc/$PID/ns
cat /proc/$PID/cgroup
The key insight There is no "container" object in the kernel, only a process with namespaces and cgroups. That explains both the lightness and the limits of isolation.

§4Common Mistakes

MistakeWhat HappensFix
Thinking a container has its own kernelKernel flaws affect every container on the hostTreat the kernel as shared and keep it patched
Setting memory limits without understanding page cacheSurprise OOM kills or throttlingMonitor memory.current and memory.events
Assuming root in a container is harmlessWithout a user namespace it is real rootUse rootless mode or user namespace remapping
Practice
  1. Use unshare to start a shell with its own PID, UTS, and network namespaces and show what differs from the host.
  2. Create a cgroup with a 50 MB memory limit and watch a memory-hungry process get killed.
Key takeaways
  • Namespaces restrict what a process sees, and cgroups restrict what it consumes.
  • Docker sets up both, plus a root filesystem and security profile, and starts your process.
  • The kernel is shared, so isolation is only as strong as the kernel and configuration.
