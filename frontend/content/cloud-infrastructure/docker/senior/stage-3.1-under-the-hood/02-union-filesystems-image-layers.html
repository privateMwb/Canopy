Union Filesystems & Image Layers

Images are stacks of read-only layers described by a standard format, and containers add one writable layer on top.

§1Layers

Each Dockerfile instruction that changes the filesystem creates a layer: a tarball of added, changed, and deleted files, identified by a content hash. Layers are shared between images and cached by registries and hosts.

docker image inspect nginx:1.27 --format '{{json .RootFS.Layers}}' | head -c 300
docker history --no-trunc nginx:1.27 | head

§2Union Filesystems

At run time the layers are combined into one view with a union filesystem, usually overlayfs.

upperdir   writable container layer          (new and changed files)
lowerdir   image layers, read-only, stacked  (shared by all containers from the image)
merged     what the container sees
mount | grep overlay
docker inspect demo --format '{{json .GraphDriver.Data}}'

Reading a file finds it in the topmost layer that has it. Writing a file from a lower layer copies it up to the writable layer first (copy-on-write). Deleting creates a whiteout marker, so the file is hidden but still exists in the lower layer.

§3Consequences

  • A deleted file still costs space in the layer that added it.
  • Heavy writes to the container layer are slow, so databases and logs belong in volumes.
  • Ten containers from one image share its layers and cost only their writable layers.

§4The OCI Image Format

An image is a manifest (listing layer digests and a config blob) plus the layers, defined by the Open Container Initiative specification, so tools from different vendors interoperate.

docker save nginx:1.27 -o nginx.tar && tar -tf nginx.tar | head
skopeo inspect docker://docker.io/library/nginx:1.27
crane manifest nginx:1.27 | jq

The config holds the entrypoint, environment, and history, and the manifest list maps platforms to manifests.

The key insight Layers are immutable, content-addressed tarballs. Everything that makes images cacheable, shareable, and sometimes bloated follows from that.

§5Common Mistakes

MistakeWhat HappensFix
Deleting a large file in a later layerThe image does not shrinkAvoid creating it, or build in a stage you discard
Writing heavy data in the container layerPoor performance and lost data on removalUse volumes
Treating a tag as the image itselfTags move, but layers and digests are exactReference by digest when it matters
Practice
  1. Save an image to a tar file and identify its manifest, config, and layers by hand.
  2. Show copy-on-write by modifying a file from the image layer and finding the new copy in the container's upperdir.
Key takeaways
  • Images are stacks of read-only, content-addressed layers plus a manifest and config.
  • Overlayfs presents layers as one filesystem with copy-on-write and whiteouts.
  • The OCI specification lets different tools build, store, and run the same images.
