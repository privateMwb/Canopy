Writing a Dockerfile

A Dockerfile is a short script of instructions that docker build turns into an image, one layer per step.

§1The Four Core Instructions

Here is a complete Dockerfile for a small Node.js app:

FROM node:22-slim
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
  • FROM picks the base image that everything else builds on.
  • WORKDIR sets (and creates) the directory for the instructions that follow, and for the running container.
  • COPY brings files from your build context into the image.
  • RUN executes a command at build time and saves the result as a layer.
  • CMD sets the default command at run time.

EXPOSE only documents the port the app listens on; it does not publish anything. You still need -p at run time.

§2Building and Running

docker build -t myapp:1.0 .      # the dot is the build context
docker run -d -p 3000:3000 myapp:1.0
docker history myapp:1.0         # see each layer and its size

-t names and tags the result. Without it you get an anonymous image identified only by a hash.

§3Build Time vs. Run Time

The most common beginner confusion is when things happen. RUN npm ci executes once, during docker build, and its output is baked into the image. CMD does not run during the build at all; it runs every time a container starts. If you want something to happen at every start, it belongs in CMD or ENTRYPOINT, not RUN.

Every instruction is a snapshot Each RUN, COPY, and ADD adds a layer that is stored permanently. Deleting a file in a later RUN hides it but does not shrink the image, because the earlier layer still contains it. The next lessons build on this idea.

§4Common Mistakes

MistakeWhat HappensFix
Using RUN to start the appThe build hangs or the app is not running in the containerStart the app with CMD
Expecting EXPOSE to publish a portThe app is unreachable from the hostAdd -p HOST:CONTAINER to docker run
Forgetting the build context dot"docker build requires exactly 1 argument"End with . or a path to the context
Practice
  1. Write a Dockerfile for a tiny script in any language you know, build it, and run it.
  2. Run docker history on your image and match each layer to the instruction that created it.
Key takeaways
  • A Dockerfile is a list of instructions; each filesystem-changing one creates a layer.
  • RUN happens at build time, CMD at container start.
  • EXPOSE documents a port; -p is what publishes it.
