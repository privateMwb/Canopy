Language Recipes: Node, Python, Java & Go

Each language has a standard shape for its Dockerfile, driven by how it installs dependencies and whether it produces a compiled artifact.

§1Node.js and Python: Install, Then Copy

Interpreted languages need the runtime plus dependencies. Use a lockfile install and the cache-friendly ordering from the previous lesson.

# Node
FROM node:22-slim
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
ENV NODE_ENV=production
CMD ["node", "server.js"]
# Python
FROM python:3.12-slim
WORKDIR /app
ENV PYTHONUNBUFFERED=1
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]

PYTHONUNBUFFERED=1 makes Python print logs immediately instead of buffering them, so docker logs shows output in real time. Apps must listen on 0.0.0.0, not 127.0.0.1, or published ports will not reach them.

§2Java and Go: Build, Then Ship the Artifact

Compiled languages need a toolchain to build but not to run. A multi-stage build (covered fully in the Intermediate level) keeps the compiler out of the final image:

# Java (Maven)
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /src
COPY pom.xml .
RUN mvn -q dependency:go-offline
COPY src ./src
RUN mvn -q package -DskipTests

FROM eclipse-temurin:21-jre
COPY --from=build /src/target/app.jar /app.jar
CMD ["java", "-jar", "/app.jar"]
# Go
FROM golang:1.23 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /out/server .

FROM gcr.io/distroless/static-debian12
COPY --from=build /out/server /server
CMD ["/server"]

A statically linked Go binary can run on an almost empty base image, which is why Go images are often only a few megabytes.

§3Common Ground

All four recipes share the same habits: pin the base image version, install from a lockfile, copy the manifest before the source, exclude local artifacts with .dockerignore, and use the exec form for CMD. Check each language's official image page for the current supported tags before copying a version number.

Match the recipe to the stack, not the habit Do not copy a Node Dockerfile pattern into a Go project. Ask two questions each time: how does this language install dependencies, and does it produce an artifact that can run without the build tools?

Practice
  1. Containerize a small app in the language you know best using the recipe above, and note the final image size.
  2. Change the base from a full image to a -slim variant and compare sizes and build success.
Key takeaways
  • Interpreted stacks: copy the manifest, install from the lockfile, copy the source.
  • Compiled stacks: build in one stage and ship only the artifact in a runtime-only image.
  • Bind to 0.0.0.0, pin versions, and use the exec form everywhere.
