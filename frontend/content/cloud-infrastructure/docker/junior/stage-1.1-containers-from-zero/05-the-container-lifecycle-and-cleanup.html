The Container Lifecycle & Cleanup

A container moves through a small set of states, stopped containers still occupy disk, and routine cleanup keeps your machine from filling up.

§1The States

docker create --name c1 nginx     # created, not started
docker start c1                   # running
docker stop c1                    # exited (stopped)
docker rm c1                      # gone

docker run is create plus start. A stopped container is not deleted: its filesystem and logs remain until you docker rm it, and docker ps -a shows them. docker stop sends SIGTERM, waits a grace period (10 seconds by default), then sends SIGKILL. docker kill skips the politeness and sends SIGKILL immediately.

§2Restart Policies

By default a container that exits stays exited. A restart policy changes that:

PolicyBehavior
no (default)Never restart automatically
on-failure[:N]Restart only after a non-zero exit, optionally at most N times
unless-stoppedRestart always, except after you stop it manually
alwaysRestart always, including when the daemon starts
docker run -d --restart unless-stopped --name web nginx

§3Cleaning Up

Stopped containers, unused images, and old networks and volumes accumulate. Remove deliberately:

docker ps -a                    # see everything, including exited
docker container prune          # remove all stopped containers
docker image prune              # remove dangling (untagged) images
docker system df                # how much space Docker is using
docker system prune             # stopped containers, unused networks, dangling images

For one-off containers, docker run --rm prevents the buildup in the first place.

Prune knows nothing about "important" docker volume prune deletes volumes not attached to any container, which can include a database you stopped yesterday. Read the confirmation prompt, and never add -f to a prune you have not run interactively first.

§4Common Mistakes

MistakeWhat HappensFix
Using docker ps and thinking nothing existsStopped containers are hidden without -aUse docker ps -a
Never pruningDisk fills with stopped containers and old imagesUse --rm for throwaways and prune on a schedule
Running docker system prune --volumes casuallyDeletes unattached volumes with real dataCheck docker volume ls first
Practice
  1. Create a container without starting it, inspect its state in docker ps -a, start it, stop it, and remove it.
  2. Run docker system df, then prune what is safe to prune and compare the numbers.
Key takeaways
  • run is create plus start, and a stopped container persists until removed.
  • stop sends SIGTERM then SIGKILL; restart policies decide whether exits are automatic.
  • --rm and regular pruning keep disk use under control; check volumes before deleting them.
