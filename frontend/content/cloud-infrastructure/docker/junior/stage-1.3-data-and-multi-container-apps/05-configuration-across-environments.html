Configuration Across Environments

Compose can read variables from the shell and from .env files so the same file serves several environments without committing credentials.

§1Variable Substitution and .env

Compose substitutes ${VARIABLE} in the file from your shell environment or from a .env file in the project directory:

# .env  (not committed)
POSTGRES_PASSWORD=devpass
APP_PORT=8080
services:
  web:
    ports:
      - "${APP_PORT:-3000}:3000"
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD}

${VAR:-default} supplies a fallback, and ${VAR:?message} stops with an error if the variable is missing, which is better than silently starting with an empty password. Check what Compose resolved with docker compose config.

§2env_file and Overrides

env_file passes a whole file of variables into a container, which is separate from substitution in the Compose file itself:

services:
  web:
    env_file:
      - ./config/app.env

For environment differences, Compose automatically merges compose.yaml with compose.override.yaml when present, which is perfect for local development tweaks. You can also name files explicitly:

docker compose -f compose.yaml -f compose.prod.yaml up -d

Later files override earlier ones, so keep the base file valid on its own.

§3Keeping Secrets Out of Git

  • Commit a .env.example listing every variable with fake values; ignore the real .env in .gitignore.
  • Never bake credentials into images (ENV, ARG, or COPY .env); they end up in layers.
  • For anything beyond local development, use a secret manager or Compose secrets, which later stages cover.
Two meanings of "environment file" .env feeds Compose's own ${...} substitution. env_file: and environment: feed variables into the container. A variable in .env is not automatically available inside the container unless you pass it through.

§4Common Mistakes

MistakeWhat HappensFix
Committing .envCredentials leak into history and clonesAdd it to .gitignore and commit .env.example
Expecting .env values inside the containerThe variable is empty in the appReference it in environment: or use env_file:
Never checking resolved configTypos create silent defaultsRun docker compose config to see the final file
Practice
  1. Parameterize the published port and database password with .env, then use docker compose config to confirm the values.
  2. Add a compose.override.yaml that publishes the database port for local tools, and confirm it merges automatically.
Key takeaways
  • ${VAR}, ${VAR:-default}, and ${VAR:?error} make one Compose file flexible and safe.
  • .env configures Compose; env_file and environment configure containers.
  • Commit .env.example, never .env, and keep secrets out of images.
