Docker Compose

Compose lets you declare an application's services, networks, and volumes in a single YAML file and manage them all with one command.

§1The Compose File

Compose reads compose.yaml (or docker-compose.yml) from the current directory. A minimal web app and database:

services:
  web:
    build: .
    ports:
      - "8080:3000"
    environment:
      DATABASE_URL: postgres://postgres:devpass@db:5432/app
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

Each key under services is a service. build builds from a Dockerfile, image pulls a prebuilt one, and Compose automatically creates a network so web reaches the database at the hostname db. A top-level version: key is obsolete in current Compose and can be omitted.

§2The Everyday Commands

docker compose up -d          # create and start everything in the background
docker compose ps             # status of the project's containers
docker compose logs -f web    # follow one service's logs
docker compose exec db psql -U postgres app
docker compose down           # stop and remove containers and the network
docker compose down -v        # ...and also delete the named volumes (data!)

Run docker compose up --build after changing a Dockerfile or the files it copies. Compose names resources after the project (by default the folder name), so two checkouts of the same project do not collide.

§3What Compose Replaces

The file is a readable, version-controlled equivalent of a long docker run command for every container plus the network and volume commands. Anyone on the team can run docker compose up and get the same environment.

depends_on is about order, not readiness depends_on: [db] starts the database container first, but the app may still start before Postgres accepts connections. The next lesson fixes this with health checks.

§4Common Mistakes

MistakeWhat HappensFix
Editing a Dockerfile and running only upCompose reuses the old imageRun docker compose up --build
Using down -v casuallyDeletes named volumes and the data in themUse plain down unless you want a fresh database
Using localhost between services"connection refused"Use the service name as the hostname
Practice
  1. Write a Compose file for any web app plus Postgres, bring it up, and connect with docker compose exec.
  2. Run docker compose down, bring it up again, and check that data in the named volume survives.
Key takeaways
  • One compose.yaml describes services, networks, and volumes for the whole app.
  • up -d, ps, logs, exec, and down are the daily commands.
  • Services reach each other by service name, and depends_on alone does not wait for readiness.
