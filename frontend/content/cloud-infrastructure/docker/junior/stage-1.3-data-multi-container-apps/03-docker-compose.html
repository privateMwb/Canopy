Docker Compose

Docker Compose describes a whole multi-container application in one file and starts or stops it with a single command.

§1A Compose File

services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://postgres:devpass@db:5432/app
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:

Compose creates a network for the project automatically, so services reach each other by service name (db).

§2Everyday Commands

docker compose up -d              # build if needed, create, and start everything
docker compose ps
docker compose logs -f web
docker compose exec db psql -U postgres app
docker compose up -d --build      # rebuild after changing the Dockerfile
docker compose down               # stop and remove containers and networks
docker compose down -v            # also remove named volumes (deletes data!)

§3Configuration

Use a .env file for values and reference them as ${VARIABLE}. Use profiles for optional services and docker-compose.override.yaml for development overrides.

    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD:?set DB_PASSWORD}

The :? form fails with a clear message if the variable is unset.

§4One File, Many Machines

The same file describes the stack for every teammate, so "how do I run this project?" becomes docker compose up.

The key insight A Compose file is executable documentation of how your application runs. Keep it in version control with the code.

§5Common Mistakes

MistakeWhat HappensFix
Running docker compose down -v casuallyThe database volume is deletedUse plain down, and -v only when you want a clean slate
Committing real passwords in the Compose fileSecrets in version controlUse a .env file excluded from Git
Using the old docker-compose binary with the new syntaxVersion mismatch errorsUse docker compose (the plugin)
Practice
  1. Convert a set of docker run commands for your app into a Compose file.
  2. Add a .env file and use it in the Compose file with a required variable.
Key takeaways
  • Compose declares services, networks, and volumes in one file.
  • up -d, down, logs, and exec are the core commands.
  • Keep secrets in an ignored .env file, not in the YAML.
