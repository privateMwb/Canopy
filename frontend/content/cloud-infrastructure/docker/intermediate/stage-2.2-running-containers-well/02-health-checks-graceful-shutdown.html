Health Checks & Graceful Shutdown

Containers receive stop signals, and an app that ignores them gets killed mid-request, so shutdown deserves as much care as startup.

§1What docker stop Does

It sends SIGTERM to the main process (PID 1), waits for a timeout (10 seconds by default), then sends SIGKILL. A well-behaved app uses the warning to finish in-flight requests and close connections.

process.on("SIGTERM", () => {
  console.log("shutting down");
  server.close(() => process.exit(0));      // stop accepting, finish active requests
  setTimeout(() => process.exit(1), 8000);  // safety net
});
docker stop --time 30 api                   # allow more time
docker kill --signal=SIGHUP api             # send another signal

§2The PID 1 Problem

PID 1 has special rules in Linux: it does not get default signal handlers, and it must reap zombie child processes. Shell-form CMD, shell wrapper scripts, or apps that spawn children can break signal delivery.

  • Use exec form CMD ["node", "server.js"].
  • In wrapper scripts, end with exec "$@" so the app replaces the shell.
  • Use a tiny init such as tini (docker run --init) to forward signals and reap zombies.
RUN apt-get update && apt-get install -y --no-install-recommends tini
ENTRYPOINT ["/usr/bin/tini", "--"]
CMD ["node", "server.js"]

§3Health Checks

A health check tells Docker whether the process is truly working, not just running.

HEALTHCHECK --interval=15s --timeout=3s --start-period=20s --retries=3 \
  CMD curl -fsS http://localhost:3000/healthz || exit 1
docker ps                                   # STATUS shows (healthy) or (unhealthy)
docker inspect --format '{{json .State.Health}}' api

Make /healthz cheap and meaningful, and do not make it fail because of a dependency's temporary hiccup, or you will trigger needless restarts.

The key insight Handle SIGTERM and exit cleanly. If a container always takes ten seconds to stop, it is being killed, not stopped.

§4Common Mistakes

MistakeWhat HappensFix
Shell-form CMD or a wrapper script without execSIGTERM never reaches the appUse exec form and exec in scripts
Slow shutdown that drops requestsUsers see errors during every deployHandle SIGTERM and drain connections
A health check that tests every dependencyRestarts cascade during an outageKeep it cheap and focused on this process
Practice
  1. Measure how long docker stop takes for an app with and without a SIGTERM handler.
  2. Add a health check, break the app, and watch the status change.
Key takeaways
  • docker stop sends SIGTERM, then SIGKILL after a timeout.
  • Use exec form, exec in scripts, or an init like tini to handle signals correctly.
  • Health checks should be cheap and report whether this process works.
