BuildKit, Cache Mounts & Build Secrets

BuildKit, the default builder, adds cache mounts that persist package downloads between builds and secret mounts that never end up in an image layer.

§1BuildKit Basics

BuildKit is the default builder in current Docker. It builds independent stages in parallel, skips unused ones, and supports extended RUN options. To use the newest Dockerfile features, you can declare the syntax at the very top of the file:

# syntax=docker/dockerfile:1
FROM python:3.12-slim

Use docker build --progress=plain . when you need the full, unabridged command output instead of the compact view.

§2Cache Mounts

A cache mount gives a RUN step a directory that persists across builds but is not part of the image. Package managers can then reuse downloads even when the dependency layer must rebuild:

# syntax=docker/dockerfile:1
FROM python:3.12-slim
COPY requirements.txt .
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -r requirements.txt

FROM node:22-slim
COPY package*.json ./
RUN --mount=type=cache,target=/root/.npm \
    npm ci

Since the cache lives outside the layers, you no longer need --no-cache-dir for pip, and adding one dependency no longer re-downloads everything. Typical cache targets are /root/.cache/pip, /root/.npm, /go/pkg/mod, /root/.m2, and /var/cache/apt.

§3Build Secrets

Passing a token with ARG or ENV records it in the image history. A secret mount exposes it as a file only for the duration of one RUN, and it is never written to a layer:

# syntax=docker/dockerfile:1
FROM node:22-slim
WORKDIR /app
COPY package*.json ./
RUN --mount=type=secret,id=npm_token \
    NPM_TOKEN="$(cat /run/secrets/npm_token)" npm ci
docker build --secret id=npm_token,src=$HOME/.npm_token -t app .
docker history --no-trunc app      # the token appears nowhere

For private Git over SSH, use RUN --mount=type=ssh with docker build --ssh default.

Secrets in the build are for the build A secret mount protects the image. Anything your build script does with the secret, such as writing it to a config file under /app, can still leak it. Keep secret use to a single command that does not persist the value.

§4Common Mistakes

MistakeWhat HappensFix
Passing tokens with --build-argSecret is visible in docker historyUse --mount=type=secret
Sharing one cache mount between parallel builds of aptLock errors or corrupted package stateAdd sharing=locked to the cache mount
Expecting cache mounts to exist in CISlow builds on fresh runnersUse registry or CI cache export, covered in the CI stage
Practice
  1. Add a pip or npm cache mount to a Dockerfile, change one dependency, and compare rebuild time to before.
  2. Build with a dummy secret and prove with docker history and docker run --rm app ls /run/secrets that it is not in the image.
Key takeaways
  • BuildKit is the default and adds parallel stages, cache mounts, and secret mounts.
  • Cache mounts persist downloads between builds without enlarging the image.
  • Secret mounts keep credentials out of layers, unlike ARG and ENV.
