Reproducible & Multi-Platform Builds

A build is reproducible when the same inputs always give the same image, and multi-platform builds make that true for different CPUs.

§1Reproducibility

Sources of drift: unpinned base tags, unpinned packages, "latest" downloads, and timestamps.

  • Pin the base image by version and ideally digest.
  • Pin dependencies with lockfiles, and use npm ci, pip install --require-hashes, or go mod download.
  • Pin system packages where feasible, or accept and document the drift.
  • Use SOURCE_DATE_EPOCH to control timestamps for bit-for-bit reproducible builds.
FROM node:22.9.0-slim@sha256:...
COPY package-lock.json ./
RUN npm ci

Perfect bit-for-bit reproducibility is hard. Reproducible behavior is usually the goal.

§2Multi-Platform Images

Laptops with Apple Silicon use arm64, many servers use amd64. An image built on one will not run natively on the other.

docker buildx create --use
docker buildx build --platform linux/amd64,linux/arm64 -t ghcr.io/example/app:1.0 --push .
docker buildx imagetools inspect ghcr.io/example/app:1.0

The registry stores a manifest list pointing to each platform's image, and clients pull the matching one automatically.

§3Cross-Compiling

Building for another architecture under emulation (QEMU) is slow. Prefer cross-compiling in the build stage.

FROM --platform=$BUILDPLATFORM golang:1.23 AS build
ARG TARGETOS TARGETARCH
RUN GOOS=$TARGETOS GOARCH=$TARGETARCH go build -o /out/app ./cmd/app

§4Tagging for Releases

Tag with a version and a commit SHA, and keep the digest in your deployment records, so you can always say exactly what was running.

The key insight Pin inputs to get predictable output, and publish a multi-platform manifest so the same tag works on every machine.

§5Common Mistakes

MistakeWhat HappensFix
Building only on an arm64 laptop and deploying to amd64"exec format error" at runtimeBuild multi-platform with buildx
Floating dependencies in the buildDifferent builds on different daysUse lockfiles and pinned versions
Running the whole build under emulationBuilds take very longCross-compile in the build stage
Practice
  1. Build an image for two architectures and inspect the manifest list.
  2. Rebuild the same commit twice and compare image digests, then list what prevents them from matching.
Key takeaways
  • Reproducibility comes from pinning base images, dependencies, and tools.
  • Buildx produces multi-platform images behind one tag.
  • Cross-compilation beats emulation for speed.
