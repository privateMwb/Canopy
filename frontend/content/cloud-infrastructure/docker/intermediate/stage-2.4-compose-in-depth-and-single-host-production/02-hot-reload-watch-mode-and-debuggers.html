Hot Reload, Watch Mode & Debuggers

Compose Watch syncs or rebuilds on file changes, and exposing a debug port lets your editor step through code that runs in a container.

§1Compose Watch

Rebuilding on every edit is slow, and bind mounts have performance and ownership pitfalls on some platforms. Compose Watch watches files on the host and applies the right action to the container:

services:
  web:
    build: .
    ports: ["3000:3000"]
    develop:
      watch:
        - action: sync
          path: ./src
          target: /app/src
        - action: sync+restart
          path: ./config
          target: /app/config
        - action: rebuild
          path: package.json
docker compose watch          # or: docker compose up --watch
ActionDoesUse for
syncCopies changed files into the containerSource for apps with their own hot reload
sync+restartCopies, then restarts the serviceConfig and compiled languages
rebuildRebuilds the image and recreates the containerDependency manifests, Dockerfile changes

Watch avoids the host-to-container bind mount for source, so installed dependencies stay inside the image and file-sharing performance is no longer a bottleneck.

§2Reload Servers and Bind Mounts

Many frameworks (Vite, Next.js, Flask, nodemon, air for Go) reload when files change. With a bind mount, filesystem notifications sometimes fail across the VM boundary, so enable polling (for example, CHOKIDAR_USEPOLLING=true or --poll flags) if edits are not detected. Keep the dev server bound to 0.0.0.0 so published ports work.

§3Attaching a Debugger

Debuggers connect over a network port, so publish it and tell the runtime to listen on all interfaces:

services:
  web:
    command: node --inspect=0.0.0.0:9229 server.js
    ports:
      - "3000:3000"
      - "127.0.0.1:9229:9229"      # debugger, local only
# Python (debugpy)
command: python -m debugpy --listen 0.0.0.0:5678 -m flask run --host=0.0.0.0
# Java
JAVA_TOOL_OPTIONS=-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005

In VS Code, create an attach launch configuration with the matching port and set path mappings from the container path (/app) to your local folder so breakpoints land on the right files.

Never ship an open debug port A debugger port grants arbitrary code execution. Publish it only to 127.0.0.1, enable it only in a development override or profile, and make sure the production image and Compose file never include it.

§4Common Mistakes

MistakeWhat HappensFix
Hot reload not firing on a bind mountEdits ignoredEnable polling, or use Compose Watch sync
Debugger bound to 127.0.0.1 in the containerEditor cannot attach through the published portListen on 0.0.0.0 inside, publish to 127.0.0.1 outside
No path mappingBreakpoints never hitMap the container source path to the local folder
Practice
  1. Configure Compose Watch for an app with sync for source and rebuild for the dependency file, and observe each action.
  2. Attach your editor's debugger to a containerized app and stop on a breakpoint in a request handler.
Key takeaways
  • Compose Watch syncs, restarts, or rebuilds based on which files changed.
  • Polling and 0.0.0.0 binding fix most reload problems.
  • Expose debug ports locally and only in development.
