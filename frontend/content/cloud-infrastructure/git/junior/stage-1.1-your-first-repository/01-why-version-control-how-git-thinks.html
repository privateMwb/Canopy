Why Version Control & How Git Thinks

Git records snapshots of your project, and understanding its three areas explains almost every command you will run.

§1Snapshots, Not Copies

Version control remembers every saved state of your project so you can compare, return, and collaborate. Git stores each commit as a snapshot of all tracked files, plus a message, an author, a timestamp, and a pointer to the previous commit. Unchanged files are stored once and reused, so history stays small.

§2The Three Areas

Every change travels through three places:

  • Working tree: the files you edit on disk.
  • Staging area (index): the changes you have chosen to include in the next commit.
  • Repository: the permanent history, stored in the hidden .git folder.
edit file  →  git add  →  git commit
working tree    staging      repository

Staging lets you build a commit deliberately: edit ten files, stage three, and commit only those.

§3Why It Is Distributed

Your computer holds the entire history, not just the latest files. You can commit, browse history, and branch offline. Sharing with others is a separate step, covered in Stage 1.3.

git --version
ls -a            # in a repository, you will see .git
The key insight A commit is a snapshot with a parent pointer. Almost everything else in Git, including branches and merges, is built from that one idea.

§4Common Mistakes

MistakeWhat HappensFix
Treating Git as a backup of files onlyYou miss that commits are meaningful units of historyCommit small, coherent changes with clear messages
Thinking staging is optional ceremonyYou commit unrelated edits togetherStage only what belongs in one commit
Deleting the .git folder to "reset"All history is destroyedUse Git commands to undo changes, never delete .git
Practice
  1. Draw the three areas and trace where a one-line edit to a file lives after each step: edit, add, commit.
  2. Explain in two sentences why Git can work offline.
Key takeaways
  • Git stores snapshots, and each commit points to its parent.
  • Changes move from the working tree to staging to the repository.
  • Your machine holds the full history, so most work needs no network.
