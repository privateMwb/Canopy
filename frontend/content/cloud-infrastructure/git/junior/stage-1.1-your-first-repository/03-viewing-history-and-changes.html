Viewing History & Changes

status, log, diff, and show answer four everyday questions: what state am I in, what happened, what did I change, and what did that commit do.

§1Status: Where Am I?

git status is the command you will run most. It lists files that are staged, modified but not staged, and untracked, and tells you what branch you are on.

git status
git status -s                  # short form: two letters per file
#  M app.py   modified, not staged
# M  app.py   modified and staged
# ?? notes.txt   untracked

§2Log: What Happened?

git log lists commits from newest to oldest. The default output is long, so you will usually want a compact view.

git log --oneline                    # one line per commit
git log --oneline --graph --all      # draw branches as a graph
git log -5                           # only the last five
git log --author="Ada"               # filter by author
git log -- app.py                    # only commits touching app.py

§3Diff: What Changed?

git diff compares areas. With no arguments it shows changes in the working tree that are not yet staged. Add --staged to see what will go into the next commit.

git diff                  # working tree vs. staging area
git diff --staged         # staging area vs. last commit
git diff HEAD             # working tree vs. last commit
git diff a1b2c3d d4e5f6a  # between any two commits

In diff output, lines starting with - were removed and lines starting with + were added. The @@ lines mark where in the file each change sits.

§4Show: What Did This Commit Do?

git show              # the latest commit: message and its diff
git show a1b2c3d      # a specific commit
git show HEAD~2       # the commit two before the latest
Review before you commit Running git diff --staged right before git commit is the cheapest code review you will ever do. It catches debug prints, stray edits, and files that should not be there.

§5Common Mistakes

MistakeWhat HappensFix
Running git diff after staging and seeing nothingPlain git diff only shows unstaged changes, so it looks like nothing changedUse git diff --staged to see staged changes
Scrolling through a long raw git logHard to find what you needUse --oneline, -n, --author, or a path filter
Quitting the pager with Ctrl+CConfusing exits and a half-drawn terminalPress q to leave the pager
Practice
  1. In a practice repository, change a file and compare the output of git diff, git diff --staged, and git diff HEAD at each step as you stage and commit it.
  2. Use git log to find the last commit that touched one specific file, then use git show to read what it changed.
Key takeaways
  • git status shows state, git log shows history, git diff shows changes, git show shows one commit.
  • git diff shows unstaged changes; git diff --staged shows what the next commit contains.
  • --oneline and --graph make history readable at a glance.
