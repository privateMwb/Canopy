Line Endings, Whitespace & .gitattributes

Windows, macOS, and Linux end lines differently, and unmanaged line endings make whole files look changed; a few settings and a .gitattributes file fix it for the whole team.

§1The Problem

Windows ends lines with two characters, CRLF (\r\n). macOS and Linux use one, LF (\n). If one developer saves a file with CRLF and another with LF, Git sees every line as changed, producing enormous noisy diffs and false conflicts.

git diff                   # a file shows every line changed, but nothing looks different
git diff --ignore-space-at-eol   # diff while ignoring line-ending differences
file app.js                # reports: ... with CRLF line terminators

§2Per-Developer Setting: core.autocrlf

git config --global core.autocrlf true     # Windows: CRLF in working tree, LF in repo
git config --global core.autocrlf input    # macOS/Linux: convert CRLF to LF on commit

This protects you, but it is stored on each person's machine, so it cannot guarantee a team agrees.

§3Per-Repository Rules: .gitattributes

A committed .gitattributes file applies to everyone who clones the repository, which is why it is the better solution.

# .gitattributes
* text=auto                 # let Git normalize text files to LF in the repo
*.sh text eol=lf           # shell scripts must always be LF
*.bat text eol=crlf        # Windows batch files must be CRLF
*.png binary               # never touch or diff-as-text these
*.pdf binary

After adding or changing rules in an existing repository, renormalize so files are rewritten to match:

git add --renormalize .
git commit -m "Normalize line endings"

§4Whitespace

git diff --check                 # flags trailing whitespace and conflict markers
git diff -w                      # ignore all whitespace changes when reading a diff
git config --global core.whitespace trailing-space,space-before-tab

Pair this with an .editorconfig file, which many editors read, so everyone's editor produces the same line endings, indentation, and final newline.

Commit the rules, not just the habits Settings on one machine cannot protect a team. Put * text=auto and explicit eol rules in .gitattributes so correct behavior travels with the repository.

§5Common Mistakes

MistakeWhat HappensFix
Changing line endings in the same commit as real workA huge diff hides the real changeDo the normalization as its own commit
Marking binaries as textCorrupted images or archivesList binary types with binary in .gitattributes
Relying only on core.autocrlfA teammate with a different setting reintroduces the problemAdd .gitattributes to the repository
Practice
  1. Create a file with CRLF endings, commit it, then add * text=auto to .gitattributes and renormalize; examine what changed.
  2. Use git diff --check on a file with trailing whitespace and fix what it reports.
Key takeaways
  • CRLF versus LF differences create noisy diffs and false conflicts.
  • .gitattributes makes line-ending rules travel with the repository.
  • Normalize in a separate commit and mark binary files explicitly.
