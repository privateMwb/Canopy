Push, Fetch & Pull

Push sends your commits, fetch downloads others' commits without touching your work, and pull is fetch plus a merge or rebase, so knowing the difference prevents surprises.

§1Push: Share Your Commits

git push uploads your branch's new commits to a remote. The first time, -u links your local branch to a remote branch so later pushes and pulls need no arguments. That link is called upstream tracking.

git push -u origin feature/login   # first push, sets upstream
git push                          # later pushes
git status                        # shows: ahead of 'origin/feature/login' by 2 commits

A push is rejected if the remote has commits you do not have. Git protects others' work, so you must integrate theirs first.

§2Fetch: Look Before You Merge

git fetch downloads new commits and updates your origin/... branches, but does not change your local branches or files. It is always safe.

git fetch origin
git log --oneline main..origin/main      # what is new on the remote?
git diff main origin/main              # what would change?

§3Pull: Fetch Plus Integrate

git pull runs a fetch and then integrates the result into your current branch. By default that is a merge; --rebase replays your commits on top instead.

git pull                       # fetch + merge
git pull --rebase              # fetch + rebase
git pull --ff-only             # fail rather than create a merge commit
git config --global pull.rebase false   # make your preference explicit
CommandChanges your files?Risk
git fetchNoNone; inspect first
git pullYes, merges or rebasesCan start a merge or conflicts

Fetch first when unsure If you want to see what teammates did before it touches your work, run git fetch and read the log. Pull is convenient, but fetch gives you a chance to look.

§4Common Mistakes

MistakeWhat HappensFix
Force-pushing to fix a rejected pushOverwrites teammates' commits on the remotePull or rebase to integrate first; never force-push a shared branch
Forgetting -u on the first pushLater git push or git pull complains no upstream is setUse git push -u origin <branch> once
Treating fetch and pull as the sameSurprise merges and conflictsUse fetch to look, pull to integrate
Practice
  1. Make a commit locally and push it; then check git status before and after to see the ahead/behind message change.
  2. Run git fetch, compare with git log main..origin/main, and only then integrate with git pull.
Key takeaways
  • git push uploads commits; -u sets upstream tracking once.
  • git fetch is safe and updates only remote-tracking branches.
  • git pull equals fetch plus merge (or rebase with --rebase).
