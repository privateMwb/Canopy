Clone, Remotes & Origin

A remote is another copy of your repository, usually on a hosting site, and git clone creates a local copy that already knows where it came from.

§1Cloning

git clone downloads the full repository, with every commit and branch, and checks out the default branch. It also records where it came from under the name origin.

git clone https://github.com/example/recipes.git
git clone git@github.com:example/recipes.git      # SSH form
git clone https://github.com/example/recipes.git my-folder   # choose the folder name
cd recipes && git log --oneline

§2What a Remote Is

A remote is a named bookmark for another repository's URL. origin is only the default name given to the one you cloned from; it has no special power. You can have several remotes, for example your own copy and the original project.

git remote -v                          # list remotes and their URLs
git remote add upstream https://github.com/original/recipes.git
git remote rename origin github
git remote set-url origin git@github.com:me/recipes.git

Starting from a local-only project instead? Create an empty repository on the host, then connect it:

git remote add origin git@github.com:me/recipes.git
git push -u origin main               # first push, and set up tracking

§3Remote-Tracking Branches

Your clone stores a read-only snapshot of where each remote branch was the last time you talked to it, named like origin/main. These remote-tracking branches move only when you fetch or pull, never when you edit locally.

git branch -r                # list remote-tracking branches
git log main..origin/main     # commits on the remote you do not have yet
Local and remote are separate repositories Your main and origin/main are two different pointers in two different repositories. They match only until someone commits on either side. Keeping them in sync is what push, fetch, and pull are for.

§4Common Mistakes

MistakeWhat HappensFix
Thinking origin is a special server nameConfusion when a clone has a different remote nameIt is just a default label; check with git remote -v
Cloning inside an existing repositoryA nested repo that confuses status and historyClone into a clean folder outside other repos
Assuming origin/main updates by itselfYou compare against stale informationRun git fetch to refresh remote-tracking branches
Practice
  1. Clone any public repository, list its remotes, and use git log --oneline -5 to read its latest history.
  2. Add a second remote named backup to a practice repository, list remotes, then remove it with git remote remove backup.
Key takeaways
  • git clone copies the whole repository and sets up origin.
  • A remote is a named URL; origin is only a convention.
  • origin/main is a local record of the remote's state, updated by fetch.
