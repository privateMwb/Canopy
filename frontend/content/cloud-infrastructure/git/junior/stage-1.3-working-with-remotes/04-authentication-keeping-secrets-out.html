Authentication & Keeping Secrets Out

Choose a safe way to authenticate, never commit secrets, and know the real recovery steps if you do.

§1Authenticating

  • SSH keys: generate a key pair, keep the private key private, and upload the public key to the host.
  • HTTPS with a token: use a personal access token or a credential manager, never your account password.
ssh-keygen -t ed25519 -C "ada@example.com"
cat ~/.ssh/id_ed25519.pub            # paste this public key into the host settings
ssh -T git@github.com                # test the connection
git config --global credential.helper store   # or use the OS keychain helper

Protect the private key with a passphrase, and give tokens the narrowest scope and an expiry.

§2Keeping Secrets Out

Never commit passwords, API keys, tokens, private keys, or .env files. Use environment variables or a secrets manager, add secret files to .gitignore, and consider a pre-commit scanner.

# .gitignore
.env
*.pem
secrets/

§3If You Commit a Secret

Deleting the file in a new commit does not remove it from history, and clones and forks may already hold it.

1. Revoke or rotate the secret immediately. This is the only step that truly fixes it.

2. Remove it from history with a tool such as git filter-repo if the repository warrants it.

3. Force-push cleaned history and tell collaborators to re-clone.

4. Check logs and provider dashboards for misuse.

The key insight Assume any pushed secret is compromised. Rotating it matters far more than rewriting history.

§4Common Mistakes

MistakeWhat HappensFix
Committing .env and deleting it next commitThe secret remains in historyRotate it, then clean history if needed
Using your account password over HTTPSIt is no longer accepted, and it is riskyUse a token or SSH key
Sharing one SSH key across machines and peopleOne leak compromises everythingOne key per device, never shared
Practice
  1. Generate an SSH key, add it to a hosting account, and clone a private repository over SSH.
  2. Write the four-step response plan for a leaked API key and keep it in your team notes.
Key takeaways
  • Authenticate with SSH keys or scoped tokens, never passwords.
  • Keep secrets out of the repository with ignore rules and environment variables.
  • If a secret leaks, rotate first and clean history second.
