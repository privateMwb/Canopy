Merging: Fast-Forward & Three-Way

Merging brings one branch's work into another; Git either slides a pointer forward or creates a merge commit, depending on whether the branches have diverged.

§1Fast-Forward Merge

If the branch you are merging into has not moved since you branched off, there is nothing to combine. Git simply moves the pointer forward. This is a fast-forward, and it creates no new commit.

git switch main
git merge feature/login          # main just slides forward to E

Before:  A---B---C   <- main
                  \
                   D---E   <- feature/login
After:   A---B---C---D---E   <- main, feature/login

§2Three-Way Merge

If both branches gained new commits, their histories have diverged. Git finds the merge base, the most recent commit both share, and combines the changes from each side against that base. The result is a new merge commit with two parents.

A---B---C---F   <- main
     \       \
      D---E---M   <- main after merge (M has two parents)

git switch main
git merge feature/login     # creates merge commit M

If the two sides changed different parts of the project, Git merges automatically. If they changed the same lines, you get a conflict, covered in the next lesson.

§3Controlling the Merge Shape

git merge --no-ff feature/login   # force a merge commit even if fast-forward is possible
git merge --ff-only feature/login # refuse unless a fast-forward is possible
git log --oneline --graph         # see the shape afterward

Teams that want every feature visible as a group use --no-ff. Teams that want a straight line use fast-forward or rebase. Neither is wrong, but a team should pick one.

Merge into the branch you are on git merge X always merges X into the current branch. Check which branch you are on first. To bring a feature into main, switch to main, then merge the feature.

§4Common Mistakes

MistakeWhat HappensFix
Merging in the wrong directionmain is unchanged while your feature branch gains unrelated commitsSwitch to the destination branch before running git merge
Expecting a merge commit every timeConfusion when the log shows a straight lineA fast-forward is normal when branches have not diverged
Merging with uncommitted changesGit refuses or the result is hard to untangleCommit or stash first, so the merge starts from a clean state
Practice
  1. Make a branch, add a commit, and merge it into main with no other changes on main; confirm it was a fast-forward.
  2. Add a different commit to main, then merge another branch, and find the merge commit and its two parents in the graph.
Key takeaways
  • A fast-forward only moves a pointer; no merge commit is created.
  • A three-way merge uses the merge base and records a commit with two parents.
  • git merge X merges X into whichever branch you are currently on.
