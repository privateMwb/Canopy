Detached HEAD & Moving Around History

You can check out any commit or tag to look at the past, and understanding detached HEAD lets you explore without fear and return safely.

§1Checking Out the Past

Normally HEAD points at a branch. If you check out a commit or tag directly, HEAD points at that commit instead. This is a detached HEAD: you are viewing an old snapshot, not standing on any branch.

git switch --detach a1b2c3d   # look at an old commit
git switch --detach v1.0.0     # or a tag
git checkout a1b2c3d           # older command, same effect
# You are in 'detached HEAD' state...

This is safe for looking around, running an old build, or comparing behavior. The danger comes from committing here: a new commit has no branch pointing at it, so once you switch away it becomes hard to find.

§2Keeping Work Done in a Detached State

If you did commit while detached and want to keep it, give it a branch before leaving:

git switch -c rescue-experiment   # new branch at the current commit
git switch main                   # now safe to leave

To get back without keeping anything, just switch to a branch: git switch main, or git switch - to return to the previous location.

§3Relative References

You do not have to type commit IDs. Names can be written relative to another reference.

ReferenceMeaning
HEADThe commit you are on now
HEAD~1 or HEAD~The first parent of HEAD, one commit back
HEAD~3Three commits back along first parents
main^2The second parent of a merge commit on main
v1.0.0The commit a tag points to
git show HEAD~2
git diff HEAD~3 HEAD          # everything changed in the last three commits
git restore --source=HEAD~2 app.py   # get one old file back, without moving HEAD
Detached HEAD is not an error Git's long warning message makes it sound alarming, but it only means HEAD is not on a branch. Look around freely. If you make commits you want to keep, put a branch on them before you leave.

§4Common Mistakes

MistakeWhat HappensFix
Committing while detached, then switching awayThe new commits are no longer reachable by any branch nameCreate a branch with git switch -c before leaving
Confusing ~ and ^You land on the wrong parent of a merge commit~n goes back n generations; ^n picks the nth parent
Fearing the warning and avoiding historyYou never inspect old versionsUse git switch --detach to explore, git switch main to return
Practice
  1. Detach to a commit three steps back using HEAD~3, look at a file, and return to main with git switch -.
  2. Detach, make a commit, then rescue it by creating a branch, and verify it with git log --oneline --all.
Key takeaways
  • Detached HEAD means HEAD points at a commit, not a branch.
  • Commits made while detached need a branch to stay easy to find.
  • HEAD~n walks back along first parents; tags and IDs name specific commits.
