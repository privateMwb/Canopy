Teaching Git & Building a Team Culture

Most Git trouble on a team comes from fear and inconsistent habits rather than missing knowledge, so good onboarding builds a mental model and shared routines.

§1Teach the Model, Not Just the Commands

People who memorize commands panic when something unexpected happens. People who understand the model (snapshots, the three areas, branches as pointers, HEAD) can reason their way out. Start with a picture, then show each command moving things on it.

  • Draw commits and branch pointers on a whiteboard as you teach
  • Use git log --oneline --graph --all constantly, so the learner always sees the result of each step
  • Introduce undo before anything risky: restore, reset, and reflog early make experimentation safe

§3Reducing Fear

Fear shows up as avoiding rebase, never trying reset, or copying folders as backups. Counter it with demonstrations of recovery:

git branch backup                  # a free safety net
git reset --hard HEAD~3            # "destroy" three commits...
git reflog                         # ...then find them
git reset --hard backup            # ...and bring them back

Running a recovery drill, where an experienced person deliberately breaks a repository and the group fixes it, builds more confidence than a lecture.

§4Shared Habits and a Healthy Culture

  • Review culture: kind, specific, fast, and focused on code rather than people
  • Blameless history: use blame to find context, never to assign fault
  • Small and frequent: praise small PRs and quick reviews publicly
  • Document decisions: CONTRIBUTING.md, PR templates, and aliases make the right way the easy way
  • Let questions be normal: a channel for Git help, where "I broke it" gets help, not judgment
  • Revisit habits: hold a short retro on the workflow each quarter and change what hurts
Confidence comes from recovery, not from avoidance Once someone has seen the reflog bring back a "lost" commit, they stop fearing Git and start using it well. Make recovery part of the first lesson.

§5Common Mistakes

MistakeWhat HappensFix
Teaching a long list of commands on day oneOverload and memorized but not understood stepsTeach the model, then the five daily commands
Answering Git questions with a link to the manualLearners feel dismissed and stop askingPair, show the graph, and explain what happened
Naming and shaming after a mistakePeople hide errors and delay asking for helpTreat mistakes as learning, and practice recovery together
Practice
  1. Design a ninety-minute onboarding session for new hires: the model, the five commands, one recovery drill, and one pair-reviewed PR.
  2. Write a one-page "how we use Git here" guide covering branches, commits, reviews, and what to do when something goes wrong.
Key takeaways
  • Teach the mental model first, then the commands that act on it.
  • Practice recovery early; it removes fear and builds skill.
  • Culture lives in review habits, shared conventions, and a safe place to ask for help.
