Objects: Blobs, Trees, Commits & Tags

Git is a content-addressable object store, and every commit you have ever made is built from just four kinds of object.

§1The Four Objects

Everything lives in .git/objects, named by the SHA hash of its content.

  • Blob: the contents of one file, with no name.
  • Tree: a directory listing mapping names to blobs and other trees.
  • Commit: points to one tree, to its parent commit(s), and holds author and message.
  • Tag: an annotated label pointing to another object.
git cat-file -t HEAD                 # commit
git cat-file -p HEAD                 # tree, parent, author, message
git cat-file -p HEAD^{tree}          # the root directory listing
git cat-file -p a1b2c3d              # contents of a blob

§2Content Addressing

The name of an object is a hash of its content, so identical content is stored once, and any change produces a different name. A commit's hash covers its tree and its parents, so changing history anywhere changes every later hash. This is why history is tamper-evident.

echo "hello" | git hash-object --stdin       # compute the hash without storing
echo "hello" | git hash-object -w --stdin    # store it as a blob

Git is moving from SHA-1 to SHA-256 for new repositories, but the model is the same.

§3Building a Commit by Hand

git update-index --add --cacheinfo 100644,<blob-sha>,hello.txt
git write-tree                                # makes a tree from the index
git commit-tree <tree-sha> -m "By hand"       # makes a commit object
git update-ref refs/heads/manual <commit-sha> # point a branch at it

§4Why It Matters

Knowing that a commit is a tree plus parents explains why branches are cheap, why history rewriting changes hashes, and why identical files do not bloat a repository.

The key insight Git is a key-value store of immutable objects with a version-control interface on top. The porcelain commands are conveniences over this core.

§5Common Mistakes

MistakeWhat HappensFix
Thinking Git stores diffs between versionsYou misread how storage and history workRemember commits are snapshots, and deltas are a storage optimization in packfiles
Assuming rewriting a commit edits itIt creates a new object with a new hashExpect new hashes after rebase and amend
Treating hashes as arbitrary labelsThey carry integrity guaranteesUse hashes to verify content and identity
Practice
  1. Make a commit with only plumbing commands, then inspect it with git cat-file -p.
  2. Show that two identical files in different folders produce one blob.
Key takeaways
  • Git has four object types: blob, tree, commit, and tag.
  • Objects are named by content hash, so identical data is stored once and history is tamper-evident.
  • Higher-level commands are conveniences over this object store.
