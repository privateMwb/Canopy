Refs, the Index & Packfiles

Branches and tags are small files that name objects, the staging area is a real data structure, and packfiles compress the object store so repositories stay small.

§1Refs: Names for Commits

A ref is a file containing a hash. A branch is just a file in .git/refs/heads/, and a tag one in .git/refs/tags/. HEAD usually holds the name of the current branch instead of a hash.

cat .git/HEAD                      # ref: refs/heads/main
cat .git/refs/heads/main           # a1b2c3d4...  (a 40-character hash)
git rev-parse main                 # resolve a name to a hash
git update-ref refs/heads/rescue a1b2c3d   # create a branch by hand
git show-ref                       # list refs; refs may be consolidated in .git/packed-refs

Committing is: write a new commit object, then update the current branch's ref file to its hash. Everything about "moving a branch" is rewriting one small file.

§2The Index: The Staging Area as Data

.git/index is a binary file listing, for each tracked path, its mode, the hash of the staged blob, and file stat data used to detect changes quickly. git add writes a blob and updates the index. git commit turns the index into a tree.

git ls-files --stage                  # path, mode, blob hash, and stage number
# 100644 ce013625... 0   notes.txt
git write-tree                         # turn the index into a tree object
git diff --cached                      # compare the index to HEAD

During a conflicted merge the index holds up to three versions of a file in stages 1, 2, and 3 (base, ours, theirs), which is how Git tracks what is unresolved.

§3Packfiles: Compact Storage

Initially each object is a separate zlib-compressed loose file. To save space and speed up transfer, Git packs many objects into a packfile, storing similar objects as deltas against each other, with an index file for fast lookup. This is where Git uses differences, an implementation detail beneath the snapshot model.

git count-objects -vH                 # loose vs. packed size
git gc                               # pack loose objects, prune, repack refs
git verify-pack -v .git/objects/pack/pack-*.idx | head
git repack -a -d --depth=50 --window=250   # tune delta search

Git runs gc --auto for you after enough activity, and pushes and fetches send packs, so the same format serves storage and the network.

Everything is a file you can read A branch is a 41-byte text file, the index is a sorted list, and a pack is an indexed archive. Peeking inside .git removes the mystery from nearly every Git behavior.

§4Common Mistakes

MistakeWhat HappensFix
Editing files inside .git by handCorrupted refs or indexUse update-ref, symbolic-ref, and normal commands
Assuming every object is a loose fileLooking for hashes in .git/objects that live in packsUse git cat-file, which finds objects wherever they are
Running aggressive gc --prune=now casuallyUnreachable objects, including recoverable work, are deletedLet normal gc run; prune only deliberately
Practice
  1. Create a branch by writing to .git/refs/heads/ with git update-ref, then verify it with git branch.
  2. Compare git count-objects -vH before and after git gc in a repository with many commits.
Key takeaways
  • Refs are small files naming commits; HEAD usually names a branch.
  • The index lists staged blobs and becomes the next commit's tree.
  • Packfiles delta-compress objects for storage and transfer.
