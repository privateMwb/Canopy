Hooks, Linting & Branch Protection

Hooks run checks on your machine, and branch protection enforces the rules on the server where they cannot be skipped.

§1Local Hooks

Hooks are scripts in .git/hooks/ that run at points such as pre-commit and commit-msg. They are not shared by clone, so teams use a manager.

#!/bin/sh
# .git/hooks/pre-commit
npm run lint --silent || { echo "Lint failed"; exit 1; }
git config core.hooksPath .githooks      # keep hooks in the repo and share them

Tools such as pre-commit, Husky, and lefthook install and version hooks. Keep hooks fast: slow ones get bypassed with --no-verify.

§2What to Check Locally

  • Formatting and linting.
  • Secret scanning.
  • Commit message format.
  • Fast unit tests only; leave the long suite to CI.

§3Branch Protection on the Server

Local hooks can be skipped, so enforce the important rules on the host:

  • Require pull requests and a number of approving reviews.
  • Require status checks (build, tests, lint) to pass.
  • Require branches to be up to date before merging.
  • Block force pushes and deletion of main.
  • Use CODEOWNERS to require review from the right people.
# CODEOWNERS
/infra/    @platform-team
*.sql      @data-team

§4Layers

Local hooks give fast feedback, CI gives authoritative checks, and branch protection makes those checks mandatory.

The key insight Hooks help, protection enforces. Never rely on a rule that a developer can bypass with one flag.

§5Common Mistakes

MistakeWhat HappensFix
Slow pre-commit hooksDevelopers bypass them with --no-verifyKeep them under a few seconds
Relying only on local hooksSkipped hooks let bad code throughEnforce the same checks in CI and branch protection
Protecting main but allowing admins to bypass casuallyThe rules erodeApply protection to everyone and keep exceptions rare
Practice
  1. Add a pre-commit hook that blocks a commit containing a fake API key pattern.
  2. Configure branch protection on a test repository and try to push straight to main.
Key takeaways
  • Hooks run locally and are not shared automatically, so use a manager.
  • Branch protection enforces reviews and checks on the server.
  • Layer fast local checks, CI, and protection.
