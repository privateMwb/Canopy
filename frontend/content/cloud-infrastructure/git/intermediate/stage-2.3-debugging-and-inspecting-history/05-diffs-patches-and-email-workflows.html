Diffs, Patches & Email Workflows

Git can package changes as plain text patches and apply them elsewhere, which is how the Linux kernel and many projects collaborate without any hosting site.

§1Diff and Apply: Plain Patches

A patch is a diff saved as a text file. Anyone with the same base code can apply it.

git diff > my-change.patch               # unstaged changes as a patch
git diff --staged > staged.patch
git apply --check my-change.patch          # dry run: would it apply cleanly?
git apply my-change.patch                  # apply to the working tree, no commit
git apply --stat my-change.patch           # summarize what it touches

git apply changes files but records no commit, and it fails entirely rather than partially, which makes it safe to try.

§2format-patch and am: Patches With Commit Info

git format-patch writes one email-style file per commit, preserving author, date, and message. git am applies them and recreates the commits.

git format-patch origin/main               # one .patch file for each local commit
git format-patch -3 HEAD -o outgoing/      # the last three commits into a folder
git am outgoing/*.patch                    # apply them as real commits
git am --continue                          # after fixing a failed patch
git am --abort

§3Sending By Email

git send-email --to=maintainers@example.org outgoing/*.patch
git format-patch --cover-letter -v2 -3    # a cover letter and a version 2 of the series

Reviewers reply inline to the email, and authors send a revised version (v2, v3) of the series. Projects that work this way value small, well-described, individually-reviewable commits, which is a useful discipline anywhere.

ToolResultKeeps commit metadata?
git diff / git applyWorking tree changesNo
git format-patch / git amReal commitsYes
git bundleA file containing a repository or branch historyYes (and whole history)
Offline and email-based sharing still works A patch file or a git bundle can travel on a USB stick, through a ticket, or by email. That is possible because Git is distributed: no server is needed for sharing.

§4Common Mistakes

MistakeWhat HappensFix
Using git apply when you need the commit historyChanges land uncommitted, with no authorUse format-patch and am to preserve commits
Applying a patch to the wrong baseFailures or misplaced changesCheck the base commit and run git apply --check first
Sending one huge patchHard to review by emailSend a series of small, logical patches
Practice
  1. Create two commits, export them with git format-patch, reset to the base, and recreate the commits with git am.
  2. Make a patch with git diff, test it with git apply --check, and apply it in a second clone of the repository.
Key takeaways
  • git diff and git apply move uncommitted changes as plain patch files.
  • format-patch and am carry whole commits, including author and message.
  • Patch workflows reward small, well-described commits.
