Blame & Log Archaeology

Git history can answer who changed a line, when a string appeared, and why, if you ask with the right command.

§1Blame

git blame app.py                       # who last changed each line
git blame -L 40,60 app.py              # only lines 40 to 60
git blame -w -C -C app.py              # ignore whitespace and follow moved code
git blame --ignore-rev a1b2c3d app.py  # skip a formatting-only commit

blame shows the last change, which may be a reformat. Use --ignore-revs-file to skip bulk formatting commits permanently.

§2Searching History

git log -S"calculate_tax" --oneline         # commits that added or removed this string
git log -G"timeout\s*=\s*\d+" --oneline     # commits whose diff matches a regex
git log -L :parse_config:config.py          # history of one function
git log --follow -- src/old_name.py         # follow a file across renames
git log --author="ada" --since="2 weeks ago" --oneline
git log --grep="rounding" -i --oneline      # search commit messages

-S finds when a piece of text entered or left the code. It is the fastest way to find when something was deleted.

§3Reading the Result

git show a1b2c3d                    # see the full change and message
git log -p -- path/to/file          # every change to a file, with diffs
git log --first-parent --oneline    # follow only main's merges

§4Connecting to Context

The commit message, PR discussion, and linked ticket often explain the reason. Good messages make this possible, and poor ones leave you guessing.

The key insight git log -S answers "when did this appear?" and git blame answers "who last touched this?" Use both before changing code you do not understand.

§5Common Mistakes

MistakeWhat HappensFix
Treating blame as a way to find someone to blameCulture suffersUse it to find context and ask questions
Stopping at the formatting commitYou miss the real author of the logicUse --ignore-rev or -w -C
Searching only the current filesDeleted code stays invisibleUse git log -S across history
Practice
  1. Pick a function in a real project and trace its history with git log -L.
  2. Find the commit that removed a specific string using git log -S.
Key takeaways
  • blame shows the last change to each line, and options skip noise.
  • -S, -G, -L, and --follow search and trace history.
  • The goal is context and understanding, not blame.
