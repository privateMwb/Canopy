Amending, Splitting & Reordering Commits

Beyond fixing the last commit, Git lets you repair any earlier commit and divide one oversized commit into several focused ones.

§1Amending the Last Commit, Fully

git commit --amend                    # edit message and staged changes of the last commit
git commit --amend --no-edit          # keep the message, add newly staged changes
git commit --amend --author="Ada <ada@example.com>"
git commit --amend --reset-author     # fix a wrong identity on the last commit

§2Fixing an Older Commit

To change a commit that is not the latest, mark it edit in an interactive rebase. Git stops right after applying it, and you can change files and amend.

git rebase -i HEAD~5            # change 'pick' to 'edit' on the target commit
# Git stops at that commit
# ...fix the file...
git add app.py
git commit --amend --no-edit
git rebase --continue

For a one-line message fix on an older commit, reword is simpler than edit.

§3Splitting One Commit Into Several

Mark the oversized commit edit. When Git stops, undo the commit but keep the changes, then re-commit them in pieces.

git rebase -i HEAD~3                # mark the big commit as 'edit'
git reset HEAD~                    # un-commit, files stay modified
git add -p                         # stage the first logical part
git commit -m "Extract validation into its own module"
git add -p
git commit -m "Add validation for phone numbers"
git rebase --continue

§4Reordering

In the interactive todo list, move lines to change order. Conflicts appear if later commits depend on earlier ones, so reorder only independent changes, and run the tests after.

git rebase -i HEAD~4              # drag lines into the new order
git range-diff main@{1} main HEAD      # compare the branch before and after
Verify the result still tells the truth After rewriting, run the tests on each rewritten commit if you can, and git range-diff or git diff old-branch..HEAD to confirm the final content matches what you started with.

§5Common Mistakes

MistakeWhat HappensFix
Amending after pushingYour branch and the remote diverge, requiring a force pushAmend only unpublished commits
Splitting a commit without testing each pieceAn intermediate commit that does not build, which breaks bisect laterRun the tests after each split commit
Forgetting git rebase --continueYou stay stuck in the middle of a rebaseCheck git status; it says what to do next
Practice
  1. Make a commit that mixes two unrelated changes, then split it into two commits using rebase -i, reset HEAD~, and add -p.
  2. Fix a typo in a commit three steps back using edit and --amend --no-edit.
Key takeaways
  • --amend fixes the last commit; rebase -i with edit fixes older ones.
  • Split a commit with reset HEAD~ and add -p, then recommit in pieces.
  • Rewrite only unpublished commits and verify each result builds.
