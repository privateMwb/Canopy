Reflog: The Safety Net

The reflog is Git's private diary of where HEAD and your branches have been, so commits you thought were gone after a reset or bad rebase are almost always recoverable.

§1What the Reflog Records

Every time HEAD or a branch moves, via commit, checkout, merge, rebase, or reset, Git logs it locally in the reflog. It is a personal history of your own movements, separate from the project history, and it is not shared when you push.

git reflog
# a1b2c3d HEAD@{0}: reset: moving to HEAD~3
# f6e5d4c HEAD@{1}: commit: Add checkout page
# 9c8b7a6 HEAD@{2}: commit: Add cart summary

HEAD@{1} means "where HEAD was one move ago". The commits you reset away are still listed here.

§2Recovering From a Mistake

git reset --hard HEAD~3          # oops, that lost three commits
git reflog                       # find the commit from before the reset
git reset --hard f6e5d4c         # put the branch back exactly as it was

git switch -c rescued f6e5d4c    # or: keep the old state as a new branch
git branch -f main HEAD@{1}      # or: point main back to where it was

This also rescues commits from a bad rebase, a deleted branch, or an overzealous commit --amend. Each branch has its own log too: git reflog show feature/login.

§3Limits

  • It only covers committed work. Uncommitted edits discarded by reset --hard or restore were never recorded.
  • It is local to your clone. A different clone has its own reflog.
  • Entries expire, by default after about 90 days for reachable commits and 30 days for unreachable ones, and garbage collection then removes the objects.
Committed work is hard to lose If you ever committed it, the reflog can almost certainly get it back for a while. That is a strong reason to commit often: work that exists only in the working tree has no safety net.

§4Common Mistakes

MistakeWhat HappensFix
Expecting the reflog to save uncommitted editsDiscarded changes are goneCommit or stash before risky commands
Waiting months before lookingEntries and objects have expiredRecover soon; reflog entries are temporary
Looking for the reflog on the serverIt does not exist thereIt is a local record only; check the clone where it happened
Practice
  1. Make four commits, run git reset --hard HEAD~3, and restore all of them using git reflog.
  2. Delete a branch with git branch -D, then recover it from the reflog with git switch -c <name> <sha>.
Key takeaways
  • The reflog logs every movement of HEAD and branches locally.
  • Use git reflog plus git reset --hard <sha> or a new branch to recover lost commits.
  • It covers only committed work and entries eventually expire.
