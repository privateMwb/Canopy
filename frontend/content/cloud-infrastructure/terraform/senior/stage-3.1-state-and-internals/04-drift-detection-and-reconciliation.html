Drift Detection & Reconciliation

Real infrastructure changes outside Terraform. Drift detection finds the differences, and you decide whether code or reality should win.

§1How Drift Happens

People fix incidents in the console, autoscalers resize things, other tools modify shared resources, and cloud providers change defaults. Each leaves state and reality disagreeing.

§2Detecting It

terraform plan -refresh-only             # show differences between state and reality
terraform plan -detailed-exitcode        # exit 2 means changes are pending

A scheduled pipeline can run plan -detailed-exitcode against each stack nightly and alert when it returns 2. HCP Terraform offers built-in health assessments that do this, and there are third-party tools that continuously compare cloud configuration with code.

# check blocks report problems without failing the run
check "site_up" {
  data "http" "home" { url = "https://example.com/health" }
  assert {
    condition     = data.http.home.status_code == 200
    error_message = "Health endpoint is not returning 200."
  }
}

§3Reconciling

For each difference, choose deliberately:

  1. Reality is wrong. Run apply to revert it to the code. This is the point of IaC.
  2. Reality is right. Update the code to match, so the plan shows no change.
  3. It changes legitimately and constantly. Tell Terraform to tolerate it with ignore_changes, such as an autoscaler's desired count.
  4. Record the new state only. terraform apply -refresh-only updates state to match reality without changing infrastructure, which is useful after you update code to match.
Drift is a process problem first A flood of drift usually means people cannot make changes through the pipeline fast enough. Detection tells you where; fixing it means a fast, trusted path to change, plus tight console permissions so manual edits are the exception.

§4Common Mistakes

MistakeWhat HappensFix
Running a blanket apply on found driftReverts an emergency fix that was still neededReview each difference before choosing a direction
Ignoring attributes widely with ignore_changesTerraform stops governing important settingsIgnore specific attributes only, with a comment explaining why
Checking drift manually and rarelyLarge, risky diffs accumulateSchedule detection and alert on it
Practice
  1. Change a tag on a resource in the console, run plan -refresh-only, and then reconcile it both ways.
  2. Schedule a plan with -detailed-exitcode that alerts when the exit code is 2.
Key takeaways
  • plan -refresh-only and -detailed-exitcode surface drift.
  • For each difference, decide whether code or reality wins, or whether to ignore it.
  • Fix the cause of drift (slow change paths, broad console access), not only the symptoms.
