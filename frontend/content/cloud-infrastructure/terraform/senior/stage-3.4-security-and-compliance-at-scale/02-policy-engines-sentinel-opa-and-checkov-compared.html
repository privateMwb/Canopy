Policy Engines: Sentinel, OPA & Checkov Compared

Sentinel, OPA, and Checkov all enforce rules on Terraform, but they differ in language, where they run, and how much they ask of you.

§1Three Common Choices

AspectSentinelOPA (Rego)Checkov
Made byHashiCorpOpen Policy Agent communityPrisma Cloud (open source core)
LanguageSentinelRegoPython-based checks, YAML custom policies
StrengthNative in HCP Terraform and Enterprise, with enforcement levelsGeneral-purpose, one language for many systemsHundreds of built-in checks, ready on day one
CostNeeds HCP Terraform or Enterprise tiers that include policyFree and open sourceFree core, with a paid platform
Best forTeams already on HashiCorp's platformOrganizations standardizing policy across toolsQuickly gaining coverage with little authoring

HCP Terraform can also run OPA policies, and Trivy and similar scanners cover much of the same ground as Checkov. Overlap is normal.

§2Where They Fit

# Static scan: no plan needed, fast, catches obvious misconfiguration
checkov -d .

# Plan-based: sees real values and module expansion
terraform show -json tfplan > plan.json
conftest test plan.json --policy policy/

Static analysis is quick and gives early feedback in the editor and pull request. Plan-based evaluation is more accurate because values and module expansion are resolved.

§3Operating a Policy Layer

  • Start with built-in packs, then add custom rules for your own standards.
  • Version policy like code: review, test, and release it with changelogs.
  • Test policies with sample plans that should pass and fail.
  • Provide exceptions with an owner, a reason, and an expiry date.
  • Measure the fail rate and time to fix, so rules that mostly produce noise get tuned or removed.
Policy that people route around is worse than none Rules that block legitimate work create shadow processes. Aim for few, high-signal rules, fast feedback in the pull request, and an exception path that is quicker than a workaround.

§4Common Mistakes

MistakeWhat HappensFix
Enabling every built-in rule at onceHundreds of findings and alert fatigueStart with a prioritized subset and expand
Policies without testsA bad rule blocks every pipelineTest with passing and failing sample plans
Permanent exceptionsThe rule means nothing over timeGive exceptions an expiry and review them
Practice
  1. Run Checkov or Trivy on a repository and triage the ten findings by severity.
  2. Write one rule in Rego or Sentinel, and test it against a plan that should pass and one that should fail.
Key takeaways
  • Sentinel is native to HashiCorp's platforms, OPA is general-purpose, and Checkov gives broad built-in coverage.
  • Use static scans for fast feedback and plan-based checks for accuracy.
  • Version, test, and tune policies, and give exceptions an owner and an expiry.
