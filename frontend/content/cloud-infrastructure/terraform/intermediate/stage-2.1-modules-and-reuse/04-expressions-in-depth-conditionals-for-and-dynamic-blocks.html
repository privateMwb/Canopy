Expressions in Depth: Conditionals, for & Dynamic Blocks

Conditionals, for expressions, and dynamic blocks make modules flexible. Use them to remove repetition, not to build puzzles.

§1Conditionals and Optional Resources

The ternary condition ? a : b chooses a value. Combined with count, it toggles a resource on or off.

variable "enable_logging" { type = bool }

resource "aws_s3_bucket" "access_logs" {
  count  = var.enable_logging ? 1 : 0
  bucket = "${var.name}-access-logs"
}

output "access_log_bucket" {
  value = one(aws_s3_bucket.access_logs[*].id)    # null when disabled
}

one() returns the single element of a list, or null if it is empty, which avoids index errors when the resource is absent.

§2for Expressions

A for expression transforms a list or map into another.

locals {
  names     = ["web", "api", "worker"]
  upper     = [for n in local.names : upper(n)]
  by_name   = { for n in local.names : n => "svc-${n}" }
  big_ones  = [for k, v in var.sizes : k if v > 100]     # filter
}

The splat form aws_instance.web[*].id is shorthand for collecting one attribute from every instance.

§3Dynamic Blocks

When a resource takes a repeated nested block and you do not know how many up front, a dynamic block generates them from a collection.

variable "ingress_ports" { type = list(number) }

resource "aws_security_group" "web" {
  name_prefix = "web-"

  dynamic "ingress" {
    for_each = var.ingress_ports
    content {
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["10.0.0.0/8"]
    }
  }
}
Reach for these last A resource written out three times is often clearer than a dynamic block that generates it. Use flexibility when it removes real repetition, and keep the simple, explicit version when there are only a few cases.

§4Common Mistakes

MistakeWhat HappensFix
Indexing resource[0] on a count = 0 resource"Invalid index" error when the toggle is offUse one(resource[*].attr) or try()
Overusing dynamic for fixed blocksHard-to-read code with no benefitWrite plain nested blocks when the number is fixed
Nesting several for expressionsImpossible to debugBreak them into named locals and test in terraform console
Practice
  1. Add an optional resource controlled by a boolean and verify both settings in the plan.
  2. Write a for expression that turns a list of names into a map, and print it in terraform console.
Key takeaways
  • count = condition ? 1 : 0 toggles resources; use one() to read them safely.
  • for expressions reshape data; dynamic blocks generate repeated nested blocks.
  • Prefer explicit, readable code unless flexibility removes real repetition.
