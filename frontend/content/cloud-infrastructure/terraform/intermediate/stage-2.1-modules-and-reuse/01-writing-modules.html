Writing Modules

A module is a directory of Terraform files you call like a function. Every configuration you have written is already one, the root module.

§1A Module Is Just a Directory

Any folder of .tf files is a module. The directory you run Terraform in is the root module. A child module is one the root calls with a module block, passing inputs and reading outputs.

.
├── main.tf              # root module
└── modules/
    └── bucket/
        ├── main.tf
        ├── variables.tf
        └── outputs.tf
# modules/bucket/variables.tf
variable "name" { type = string }

# modules/bucket/main.tf
resource "aws_s3_bucket" "this" {
  bucket = var.name
}

# modules/bucket/outputs.tf
output "arn" { value = aws_s3_bucket.this.arn }

§2Calling It

module "logs" {
  source = "./modules/bucket"
  name   = "acme-logs"
}

module "assets" {
  source = "./modules/bucket"
  name   = "acme-assets"
}

output "logs_arn" { value = module.logs.arn }

Run terraform init after adding or changing a module source, so Terraform can load it. Each call creates its own copy of the resources, addressed as module.logs.aws_s3_bucket.this.

§3Why Bother

Modules remove copy-paste, give a team a consistent way to build common things, and let you change the definition once. They also hide detail: a caller sees name and arn, not the ten resources behind them.

Start with duplication, then extract Write the resources flat first. When you copy them a second time, you know exactly which values vary, and those become the module's variables. Modules designed up front tend to guess wrong.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting terraform init after adding a module"Module not installed" errorRun init whenever sources change
Reading a child module's resources from the rootYou cannot reference module.x.aws_s3_bucket.this directlyExpose what callers need through outputs
Making modules before understanding the repetitionAwkward interfaces with too many or wrong variablesExtract after the second or third real use
Practice
  1. Move a bucket resource into modules/bucket and call it twice with different names.
  2. Output the ARN of each and read the resource addresses in the plan.
Key takeaways
  • A module is a directory; the one you run in is the root module.
  • Callers pass inputs and read outputs, and cannot reach inside.
  • Extract a module when real repetition shows you its interface.
