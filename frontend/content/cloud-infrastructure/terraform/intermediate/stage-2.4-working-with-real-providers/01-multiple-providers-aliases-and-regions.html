Multiple Providers, Aliases & Regions

One configuration can talk to several accounts and regions at once. Provider aliases are how you tell each resource which one to use.

§1Aliases

A provider block without an alias is the default. Add more with alias, and select one on a resource with the provider argument.

provider "aws" {
  region = "us-east-1"
}

provider "aws" {
  alias  = "west"
  region = "us-west-2"
}

resource "aws_s3_bucket" "primary" {
  bucket = "acme-data-east"
}

resource "aws_s3_bucket" "replica" {
  provider = aws.west
  bucket   = "acme-data-west"
}

Resources without provider use the default configuration. Some recent versions of the AWS provider add a per-resource region argument for many resources, which can remove the need for aliases when you only vary region within one account. Check your provider version's documentation.

§2Multiple Accounts

Combine aliases with assume_role to manage several accounts from one configuration.

provider "aws" {
  alias = "prod"
  assume_role {
    role_arn = "arn:aws:iam::222222222222:role/terraform"
  }
}

§3Passing Providers to Modules

A module inherits the default provider. To give it another, pass it explicitly with providers.

module "replica_bucket" {
  source = "./modules/bucket"
  providers = {
    aws = aws.west
  }
}

Inside a reusable module that expects more than one provider, declare each with configuration_aliases in its required_providers.

Providers are not dynamic In Terraform, you cannot loop over providers with for_each, so every region or account needs its own explicit block. OpenTofu added support for provider iteration in release 1.9, one of the places the two tools have diverged. Large multi-region setups are often better split into one stack per region.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting provider = on a resourceIt lands in the default region or accountSet the provider explicitly for anything non-default
Putting a provider block inside a moduleThe module cannot be used with count, for_each, or removed cleanlyConfigure providers in the root and pass them in
Mixing up bucket names across regionsGlobal-name collisions and confusionInclude region or environment in the names
Practice
  1. Create a bucket in two regions in one configuration using an alias, and view both in the plan.
  2. Pass an aliased provider into a module with providers = {} and confirm which region its resources use.
Key takeaways
  • Aliases let one configuration target several regions or accounts.
  • Select a provider on a resource with provider, and on a module with providers.
  • Providers cannot be created in a loop; split large fan-out into separate stacks.
