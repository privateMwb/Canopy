Atlantis, Spacelift & Pull-Request Automation

Pull-request automation tools run Terraform in response to comments and merges, giving teams a ready-made workflow instead of hand-built pipelines.

§1What They Do

These tools watch your repository, run plan when a pull request changes Terraform, post the result as a comment, and run apply when you ask or when the PR merges. They add what raw CI lacks: per-directory locking so two pull requests do not plan the same stack at once, a clear audit trail, and a team-friendly interface.

# Atlantis: commands as pull-request comments
atlantis plan -d envs/prod
atlantis apply -d envs/prod

§2The Main Options

ToolStyleNotes
AtlantisSelf-hosted, open sourceYou run the server and give it credentials; configured with atlantis.yaml
HCP TerraformHosted by HashiCorpVCS-driven runs, with policy and access control
Spacelift, env0, ScalrHosted or self-hosted platformsPolicies, drift detection, and support for several IaC tools
Plain CIYour own pipelinesMaximum flexibility, and you build every feature yourself
# atlantis.yaml
version: 3
projects:
  - name: prod-network
    dir: envs/prod/network
    workspace: default
    autoplan:
      when_modified: ["*.tf", "../../modules/**/*.tf"]

§3Choosing

Pick based on the work you do not want to own. Atlantis is cheap and flexible but you operate it and secure its credentials, since it can apply anything it can read. Hosted platforms trade cost for governance, policy, and less maintenance. For a small team, a well-built CI workflow is often enough.

The tool holds the keys Whatever runs your applies has write access to your infrastructure. Restrict who can trigger an apply (for example, require approval before apply), isolate the runner, and review its configuration as carefully as production code.

§4Common Mistakes

MistakeWhat HappensFix
Letting anyone comment applyUnreviewed changes reach productionRequire approvals and restrict who can apply
Running the automation server with admin credentialsA compromise grants full controlScope credentials and isolate per environment
Skipping locking in a custom setupTwo pull requests change the same stateUse a tool with per-project locks, or add your own
Practice
  1. Write an atlantis.yaml that defines two projects with separate directories and autoplan triggers.
  2. Compare Atlantis and HCP Terraform for your team on cost, control, and operations.
Key takeaways
  • PR-automation tools plan on pull requests, apply on approval, and lock per project.
  • Choose between self-hosted control and hosted convenience based on the work you want to own.
  • The automation's credentials are as sensitive as production access.
