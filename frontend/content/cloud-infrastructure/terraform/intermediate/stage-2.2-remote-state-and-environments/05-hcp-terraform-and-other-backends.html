HCP Terraform & Other Backends

HCP Terraform is HashiCorp's hosted service for state, runs, and collaboration. You should know what it offers and how it compares with running your own.

§1What It Provides

HCP Terraform (formerly Terraform Cloud) stores state with locking and versioning, runs plans and applies on managed workers, stores variables and secrets per workspace, and adds access control, a private module registry, and policy enforcement. Terraform Enterprise is the self-hosted version.

terraform {
  cloud {
    organization = "acme"
    workspaces { name = "prod-network" }
  }
}

After terraform login and terraform init, runs execute remotely and stream output to your terminal. A VCS-connected workspace can also plan on every pull request and apply on merge.

Other managed options exist, including Spacelift, env0, and Scalr, which fill a similar role and sometimes support both Terraform and OpenTofu.

§3Choosing

Self-managed backends with a CI pipeline cost little and give full control, but you build and maintain the workflow. A hosted platform removes that work and adds governance features, in exchange for cost and dependence on a vendor. Pricing and licensing change, so verify current terms before deciding.

Backends are swappable, workflows are not Moving state between backends is routine. What is hard to move is everything built around the platform: policies, variable sets, run triggers, and team permissions. Decide on the workflow first.

Practice
  1. Write a one-page comparison of your team's needs against HCP Terraform and a self-managed S3 plus CI setup.
  2. Read the documentation for a remote backend you do not use and list how it handles locking.
Key takeaways
  • HCP Terraform bundles state, remote runs, access control, and policy.
  • Self-managed backends are cheaper and flexible, but you build the workflow.
  • Choose by the workflow your team needs, and verify current pricing.
