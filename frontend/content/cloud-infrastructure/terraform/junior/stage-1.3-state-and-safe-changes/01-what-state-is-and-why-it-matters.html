What State Is & Why It Matters

State is how Terraform remembers which real resources belong to which blocks of code. Lose it and Terraform forgets what it built.

§1What State Contains

After an apply, Terraform writes a terraform.tfstate file (JSON) mapping each resource address in your code, like aws_s3_bucket.logs, to the real object, with its ID and every attribute the provider returned. On the next plan, Terraform refreshes those objects from the API, compares them with your configuration, and computes the difference.

terraform state list                    # every resource Terraform tracks
terraform state show aws_s3_bucket.logs # the recorded attributes of one
terraform show                          # human-readable view of the whole state

Without state, Terraform could not tell "this bucket is mine, change it" from "this bucket exists, leave it alone". It would also not know what to delete when you remove a block.

§2Rules for Living With State

  • Never edit it by hand. Use terraform state subcommands (stage 3.1 covers them).
  • It contains secrets. Attributes such as database passwords are stored in plain text, so protect the file like a credential.
  • Never commit it to git. Add terraform.tfstate* and .terraform/ to .gitignore.
  • One state, one writer at a time. Two people applying against the same file corrupt each other's view. Remote backends and locking (stage 2.2) solve this.

§3State Is Not the Cloud

State is Terraform's *record* of the world, and the world can change without it. If someone deletes a resource in the console, the next plan's refresh notices it is gone and proposes to recreate it. If the state file is lost, Terraform believes nothing exists and plans to create everything again, which fails or duplicates.

Local state is a lab-only setup A state file on your laptop works for learning. For anything shared or important, store state in a remote backend with locking and versioning. Treat that move as a prerequisite for teamwork, not an optimization.

§4Common Mistakes

MistakeWhat HappensFix
Committing terraform.tfstateSecrets and resource details leak through gitGitignore it and use a remote backend
Deleting state to "start fresh"Terraform forgets existing resources and tries to recreate themDestroy first, or remove specific entries with terraform state rm
Editing the JSON manuallyCorrupt state and unpredictable plansUse terraform state mv, rm, or import
Practice
  1. Apply a small configuration, then read terraform state list and terraform state show for one resource.
  2. Copy the state file aside, delete the original, and run plan. What does Terraform now believe, and why?
Key takeaways
  • State maps your code to real resources and is required for correct updates and deletes.
  • It can hold secrets, so never commit it and always protect it.
  • State is a record, not reality, and refresh reconciles the two on each plan.
