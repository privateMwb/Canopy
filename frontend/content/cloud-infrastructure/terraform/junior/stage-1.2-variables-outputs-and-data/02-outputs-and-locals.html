Outputs & Locals

Outputs publish values from a configuration, and locals give names to expressions you would otherwise repeat.

§1Outputs

An output block exposes a value after apply. You see it in the terminal, read it with terraform output, and, as you will see in stage 2.1, pass it between modules.

output "bucket_name" {
  value       = aws_s3_bucket.logs.bucket
  description = "Name of the log bucket."
}

output "db_endpoint" {
  value     = aws_db_instance.main.endpoint
  sensitive = true
}
terraform output                  # all outputs
terraform output bucket_name      # one, printed plainly
terraform output -json            # machine-readable, for scripts

An output marked sensitive is hidden in normal display but still present in state and in -json output.

§2Locals

A locals block assigns names to expressions. Use it to compute a value once and reuse it, not as a general replacement for variables. Variables are inputs from outside; locals are internal.

locals {
  name_prefix = "${var.project}-${var.environment}"
  common_tags = {
    Project     = var.project
    Environment = var.environment
    ManagedBy   = "terraform"
  }
}

resource "aws_s3_bucket" "logs" {
  bucket = "${local.name_prefix}-logs"
  tags   = local.common_tags
}

Now changing the naming scheme means editing one line, and every resource follows.

Do not overuse locals A local that is used once and hides a simple reference makes code harder to read. Introduce one when an expression repeats, or when a good name makes intent clearer than the expression does.

§3Common Mistakes

MistakeWhat HappensFix
Creating an output for everythingA noisy interface that is hard to maintainOutput only values a person, script, or another module needs
Using locals as inputsCallers cannot override the valueUse a variable for anything callers should set
Printing secrets as normal outputsValues appear in logs and CI outputMark them sensitive, or do not output them at all
Practice
  1. Add a common_tags local and apply it to two resources, then change one tag value and read the plan.
  2. Use terraform output -json and pipe it to jq to extract one value.
Key takeaways
  • Outputs publish results; locals name internal expressions.
  • Variables are inputs, locals are not overridable, and outputs leave the configuration.
  • Sensitive outputs are hidden on screen, not removed from state.
