Cleaning Up & Cost Awareness

A stack you forget about keeps billing you. Destroying safely and knowing what costs money are part of using Terraform responsibly.

§1Destroying Safely

terraform destroy removes everything the configuration manages. It is a plan like any other, so read it.

terraform plan -destroy                 # preview what would be removed
terraform destroy                       # confirm and delete
terraform destroy -target=aws_instance.web   # one resource; use rarely

Protection settings can make destroy fail on purpose. If a database has deletion_protection, you must change it and apply *before* destroying. Non-empty S3 buckets also block deletion unless force_destroy = true, which is convenient in labs and dangerous in production.

§2What Costs Money

Some resources are free to define and cost nothing until used (VPCs, subnets, security groups). Others bill continuously while they exist, even when idle:

  • NAT gateways (hourly plus data)
  • Load balancers and Elastic IPs that are not attached
  • Running instances and databases, including stopped instances' volumes
  • Snapshots, backups, and log storage that accumulate
# Make ownership and expiry visible on everything
provider "aws" {
  region = "us-east-1"
  default_tags {
    tags = { ManagedBy = "terraform", Project = var.name, Owner = "your-team" }
  }
}

default_tags applies tags to every resource the provider supports, which lets you find forgotten stacks in a billing report.

§3Know What Is Left

After a destroy, check that nothing remains: terraform state list should be empty, and the cloud's billing or resource view should agree. Anything created outside Terraform, such as snapshots, log groups, or manual tweaks, is not removed by it.

Set a budget alert before you experiment A billing alert at a small threshold turns "I forgot a NAT gateway for a month" into an email on day two. It takes minutes and costs nothing.

§4Common Mistakes

MistakeWhat HappensFix
Leaving a lab stack runningOngoing charges for idle resourcesDestroy when done, and set a budget alert
Using force_destroy on production bucketsTerraform deletes all the dataReserve it for disposable environments
Relying on -target for cleanupDependencies are skipped and state divergesDestroy the whole configuration, or fix the cause
Practice
  1. Run terraform plan -destroy on a small stack and compare the list with what you created.
  2. Add default_tags to your provider and find the tags on a resource after apply.
Key takeaways
  • plan -destroy previews a teardown just like a normal plan.
  • Tag everything and set budget alerts so forgotten resources are found quickly.
  • Verify nothing is left running after destroying a stack.
