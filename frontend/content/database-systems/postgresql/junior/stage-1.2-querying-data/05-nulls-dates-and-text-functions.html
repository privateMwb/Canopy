NULLs, Dates & Text Functions

NULL means "unknown", not "empty", and dates and text come with a rich set of built-in functions worth knowing by heart.

§1Three-Valued Logic

Comparisons involving NULL produce NULL (unknown), and WHERE keeps only rows where the condition is true. That makes NULL behave unlike any other value.

SELECT NULL = NULL;                  -- NULL, not true
SELECT NULL IS NULL;                 -- true
SELECT NULL IS DISTINCT FROM 1;      -- true (NULL-safe comparison)
SELECT true AND NULL, false AND NULL, true OR NULL;   -- NULL, false, true

SELECT coalesce(nickname, name, 'unknown') FROM people;   -- first non-NULL
SELECT nullif(total, 0);                                   -- NULL when total is 0

Aggregates ignore NULLs (except count(*)). Use coalesce to supply a default and nullif to avoid divide-by-zero: amount / nullif(count, 0).

§2Dates, Times, and Intervals

Subtracting two dates gives an integer number of days; subtracting two timestamps gives an interval. You can add intervals to dates and timestamps.

SELECT current_date, now(), now() - interval '7 days';
SELECT date '2026-12-25' - current_date AS days_until;
SELECT date_trunc('month', now());                       -- first instant of this month
SELECT extract(year FROM published), extract(dow FROM published) FROM books;
SELECT to_char(now(), 'YYYY-MM-DD HH24:MI'), to_date('03/04/2026', 'DD/MM/YYYY');
SELECT generate_series(date '2026-01-01', date '2026-01-07', interval '1 day');

date_trunc is the workhorse for grouping by day, week, or month. For half-open ranges, prefer ts >= '2026-01-01' AND ts < '2026-02-01' over BETWEEN, which includes both endpoints and can double-count boundary rows.

§3Text Functions

Strings use || for concatenation (a NULL on either side makes the result NULL; concat() treats NULL as empty). Common helpers:

SELECT lower(name), upper(name), length(name), btrim('  hi  ');
SELECT substring('postgres' FROM 1 FOR 4);              -- post
SELECT position('gres' IN 'postgres');                   -- 5
SELECT replace(title, 'The ', ''), split_part('a,b,c', ',', 2);   -- b
SELECT title FROM books WHERE title ILIKE '%dune%';
SELECT title FROM books WHERE title ~* '^the\s';         -- regex, case-insensitive
SELECT format('%s costs %s', title, price) FROM books;

LIKE and ILIKE use % (any run) and _ (one character). Regular expressions use ~ (match) and ~* (case-insensitive match). Leading-wildcard patterns like '%dune%' cannot use an ordinary index; Stage 2.2 shows full-text search and trigram options.

The key insight NULL is a third truth value, not a blank. Any comparison with = against NULL is unknown, so use IS NULL, IS DISTINCT FROM, and coalesce deliberately.

§4Common Mistakes

MistakeWhat HappensFix
Using || with a nullable columnThe entire concatenated string becomes NULLUse concat() or coalesce(col, '')
Using BETWEEN for timestamp rangesRows exactly at the upper bound are included in two adjacent rangesUse >= start AND < end
Dividing by a column that can be zeroError: division by zeroDivide by nullif(col, 0) and handle the NULL result
Practice
  1. Evaluate NULL = NULL, NULL IS NULL, and NULL IS DISTINCT FROM NULL and explain each result.
  2. Count books per month using date_trunc('month', published).
  3. Produce "Surname, Initial" strings from a full_name column using split_part, substring, and concat.
Key takeaways
  • NULL propagates through comparisons and concatenation; use IS NULL, coalesce, and nullif.
  • date_trunc, extract, and intervals handle most date work; use half-open ranges for timestamps.
  • Learn the core text functions, and remember leading-wildcard LIKE cannot use a normal index.
