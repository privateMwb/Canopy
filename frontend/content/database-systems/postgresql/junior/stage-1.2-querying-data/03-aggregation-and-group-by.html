Aggregation & GROUP BY

Aggregates collapse many rows into one value, and GROUP BY does that once per group.

§1Aggregate Functions

count, sum, avg, min, and max summarize a set of rows. Without GROUP BY, the whole result is one group.

SELECT count(*)            AS books,
       count(price)        AS priced_books,     -- skips NULLs
       avg(price)          AS avg_price,
       min(published), max(published)
FROM books;

SELECT count(DISTINCT author_id) FROM books;

count(*) counts rows; count(col) counts rows where col is not NULL. Aggregates other than count return NULL on an empty input, so wrap with coalesce(sum(x), 0) when you want zero.

§2GROUP BY and HAVING

GROUP BY splits rows into groups by the listed expressions and runs the aggregates once per group. The rule: every column in the select list must either appear in GROUP BY or be inside an aggregate.

SELECT author_id, count(*) AS n, round(avg(price), 2) AS avg_price
FROM books
WHERE in_stock                    -- filters rows BEFORE grouping
GROUP BY author_id
HAVING count(*) >= 3              -- filters groups AFTER grouping
ORDER BY n DESC;

WHERE cannot use aggregates because it runs before grouping; HAVING exists for conditions on aggregate results. You may group by an expression or a column position (GROUP BY 1), though names are clearer.

§3Useful Extras

FILTER applies a condition to a single aggregate, which is cleaner than CASE expressions. GROUPING SETS, ROLLUP, and CUBE compute several levels of subtotals in one pass.

SELECT author_id,
       count(*) FILTER (WHERE in_stock)     AS in_stock,
       count(*) FILTER (WHERE NOT in_stock) AS sold_out,
       string_agg(title, ', ' ORDER BY title) AS titles
FROM books
GROUP BY author_id;

SELECT author_id, extract(year FROM published) AS yr, count(*)
FROM books
GROUP BY ROLLUP (author_id, yr);          -- per author/year, per author, grand total

string_agg and array_agg gather values into one string or array per group, which is handy for reports and for returning a parent row with its children in one query.

The key insight Order of evaluation explains most grouping errors: FROM/JOIN, then WHERE, then GROUP BY, then HAVING, then the select list, then ORDER BY and LIMIT.

§4Common Mistakes

MistakeWhat HappensFix
Selecting a column that is neither grouped nor aggregatedError: column must appear in the GROUP BY clause or be used in an aggregate functionAdd it to GROUP BY or wrap it in an aggregate
Using an aggregate in WHEREError: aggregate functions are not allowed in WHEREUse HAVING
Summing after a join that duplicated rowsTotals are inflated by the duplication factorAggregate each side separately, then join the results
Practice
  1. Report the number of books and the average price per author, only for authors with at least two books.
  2. Use FILTER to show in-stock and sold-out counts in one query.
  3. Use ROLLUP to produce counts per author and year with subtotals.
Key takeaways
  • count(*) counts rows; count(col) ignores NULLs.
  • Every selected column is grouped or aggregated; WHERE filters rows, HAVING filters groups.
  • FILTER and string_agg make single-query reports easy.
