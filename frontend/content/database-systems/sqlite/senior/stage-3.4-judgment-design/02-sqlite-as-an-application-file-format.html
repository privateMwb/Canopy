SQLite as an Application File Format

A SQLite file can be the document format of an application, replacing a pile of custom files with one transactional, queryable container.

§1The Idea

Instead of inventing a binary format or zipping many files, save the user's document as a single .myapp file that is a SQLite database. The SQLite project documents this as an appropriate and recommended use, and lists a long-term support commitment for the file format.

§2Advantages

  • Atomic saves: a crash during save leaves the previous version intact, since transactions are atomic.
  • Incremental updates: change one part without rewriting the whole file.
  • Queryability: search and index document content with SQL and FTS.
  • Tooling: any SQLite tool can inspect the document, which helps debugging and user trust.
  • Portability and longevity: one cross-platform, well-documented format.
  • Mixed content: structured data, blobs, and metadata in one place.

§3Design Practices

PRAGMA application_id = 0x4D594150;      -- identifies your file type (32-bit integer)
PRAGMA user_version = 4;                 -- the format version
CREATE TABLE meta (key TEXT PRIMARY KEY, value) STRICT;
CREATE TABLE object (id INTEGER PRIMARY KEY, kind TEXT NOT NULL, data BLOB NOT NULL) STRICT;

Set application_id and user_version, document the schema, and keep migrations. Use journal_mode = DELETE or checkpoint and close so that the user sees one file when sharing it by email.

§4Pitfalls

  • Users copy the file while it is open, so close WAL connections on save or use the default journal mode.
  • Opening untrusted documents requires the defensive steps from the security lesson.
  • Deleted content may linger in free pages, so run VACUUM before sharing a document that had sensitive data removed.
  • Large blobs bloat the database, so benchmark storing media inside versus beside it.

§5Compare

Sometimes a zip of files or plain JSON is simpler. SQLite is a strong choice when you need partial updates, queries, or crash safety.

The key insight A SQLite file gives your document format transactions, indexes, and tooling for free. Plan the versioning and sharing details up front.

§6Common Mistakes

MistakeWhat HappensFix
Leaving the file in WAL mode when users share itThe recipient gets a file missing recent changesCheckpoint and use a single-file mode at save
Not setting application_id and user_versionFiles cannot be identified or migratedSet both from day one
Deleting sensitive content without VACUUMOld data remains in free pagesVacuum before sharing
Practice
  1. Sketch a schema for a note-taking or drawing app's document format, including application_id, versioning, and a meta table.
  2. Save a document, delete a section, and use a hex viewer to see whether the old text is still in the file before and after VACUUM.
Key takeaways
  • SQLite works well as an application file format with atomic, incremental saves.
  • Set application_id and user_version, and keep the schema documented.
  • Mind WAL sidecar files, untrusted documents, and leftover data in free pages.
