Large Databases & Limits

SQLite has hard limits on size and shape, and most are far above what typical applications reach, but a few are worth knowing.

§1Documented Limits

Defaults of the standard build (many can be lowered at compile time or runtime):

  • Database size: up to about 281 terabytes.
  • Maximum string or BLOB size: 1,000,000,000 bytes by default (about 1 GB).
  • Columns per table: 2,000 by default.
  • SQL statement length: 1,000,000 bytes by default.
  • Bound parameters: 32,766 by default in recent versions.
  • Attached databases: 10 by default, raisable to 125.
  • Compound SELECT terms and join tables: limited, with joins up to 64 tables.
SELECT sqlite_compileoption_used('MAX_VARIABLE_NUMBER');
PRAGMA max_page_count;

§2The Practical Limits

The first limit you hit is rarely a number in that list.

  • Write throughput of one writer.
  • Operational limits: backing up or vacuuming a very large file takes time and disk space, since VACUUM needs room for a full copy.
  • Memory of per-connection caches.
  • Query performance that depends on indexes and the working set fitting in cache.

§3How Big Is Too Big?

Hundreds of gigabytes work well with proper indexes and enough RAM and disk, and terabyte databases exist. The real question is operational: how long does a backup, restore, or migration take, and can you tolerate it? If a full restore takes hours and your recovery objective is minutes, the size is too big for your design.

PRAGMA page_count;  PRAGMA page_size;   -- size = page_count × page_size

§4Working Around Limits

Split by tenant or time, archive old data into separate files, store large blobs outside the database, and keep statements within parameter limits by using temp tables or json_each for large lists.

The key insight The size at which SQLite becomes awkward is set by operations and workload, not by the engine's maximum. Measure backup and restore time at your target size.

§5Common Mistakes

MistakeWhat HappensFix
Building a 100,000-item IN (...) listYou exceed parameter or statement limitsUse a temporary table or json_each
Running VACUUM without enough free diskIt fails or fills the diskEnsure free space of about the database size
Looking only at the 281 TB limitOperations become impractical long beforeTest restore and migration times at real size
Practice
  1. Create a table with 100 columns and a very long statement and note which limits you hit and how errors look.
  2. Estimate backup and restore times for a database ten times your current size.
Key takeaways
  • Documented limits are generous: terabytes of data, gigabyte values, and thousands of columns.
  • The practical limits are write rate, operations, memory, and working set.
  • Measure backup, restore, and migration times to decide how big is too big.
