Anatomy of a Database File

A SQLite database is one ordinary file, but while it is in use, other files can appear beside it that matter just as much.

§1The Main File

The file is divided into fixed-size pages, 4096 bytes by default, and begins with a 100-byte header that starts with the text SQLite format 3.

head -c 16 app.db | xxd             # shows "SQLite format 3\0"
sqlite3 app.db "PRAGMA page_size; PRAGMA page_count; PRAGMA freelist_count;"
ls -l app.db

page_size × page_count equals the file size.

§2Sidecar Files

  • app.db-journal: the rollback journal, present during a write in the default mode.
  • app.db-wal: the write-ahead log in WAL mode, holding recent committed changes not yet merged into the main file.
  • app.db-shm: shared memory index for the WAL.

Deleting a -wal file for a database that was not shut down cleanly loses committed transactions. A leftover -journal file is a hot journal that SQLite uses to roll back an interrupted write on the next open.

§3Portability

The file format is stable, cross-platform, and works across different CPU architectures and byte orders. A database made on a phone opens on a laptop. The Library of Congress recommends it as a storage format and its maintainers promise to support it long term.

§4Size and Free Space

Deleted rows leave free pages that SQLite reuses, but it does not shrink the file on its own. VACUUM rebuilds the file to reclaim the space.

The key insight Think of the database as a set of files, not one. Copy or move them together, and only when the database is idle or backed up properly.

§5Common Mistakes

MistakeWhat HappensFix
Copying only app.db while the app runs in WAL modeThe copy lacks recent commits and may be inconsistentUse .backup or VACUUM INTO
Deleting -wal or -journal files to "clean up"Committed data is lost or the database is corruptedLet SQLite remove them on a clean close
Expecting the file to shrink after DELETEThe pages are free, not returnedRun VACUUM if you need the space back
Practice
  1. Look at the header bytes of a database and calculate its size from page_size and page_count.
  2. Enable WAL mode, write some data, and list the files that appear before and after closing all connections.
Key takeaways
  • A database is divided into pages and starts with a header.
  • Journal, WAL, and shared-memory files are part of the database state while in use.
  • VACUUM reclaims free space, and deleting rows alone does not shrink the file.
