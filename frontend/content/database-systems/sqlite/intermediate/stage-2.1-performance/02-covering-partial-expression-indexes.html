Covering, Partial & Expression Indexes

Beyond single-column indexes, composite, covering, partial, and expression indexes each fit a specific query shape.

§1Composite and Covering Indexes

Column order matters: an index on (a, b) helps filters on a and on a, b, but not on b alone. Put equality columns first, then a range or sort column.

CREATE INDEX idx_items_cat_price ON item (category, price_cents);
SELECT category, price_cents FROM item WHERE category = 'pen' ORDER BY price_cents;
-- SEARCH item USING COVERING INDEX idx_items_cat_price (category=?)

A covering index includes every column the query needs, so SQLite never reads the table. SQLite has no INCLUDE clause, so extra columns go at the end of the index.

§2Partial Indexes

Index only the rows you will search for.

CREATE INDEX idx_task_open ON task (due_at) WHERE done = 0;
SELECT * FROM task WHERE done = 0 AND due_at < datetime('now');

The index stays small and cheap to maintain, and is used only when the query's WHERE implies the index's condition.

§3Expression Indexes

CREATE INDEX idx_account_email_lower ON account (lower(email));
SELECT * FROM account WHERE lower(email) = lower(:email);

The query must use the same expression, written the same way.

§4The Write Cost

Every index must be updated on each insert, update, and delete of the columns it covers, and it uses disk space. Check sizes with sqlite3_analyzer, and drop indexes that no query uses.

DROP INDEX idx_unused;
The key insight Design an index for a query, not for a column. Equality first, then range or sort, and use partial indexes for hot subsets.

§5Common Mistakes

MistakeWhat HappensFix
Index (b, a) when queries filter on aThe index is not used for aPut the filtered column first
Creating many overlapping indexesWrites slow down and the file growsRemove ones that a longer index already covers
Partial index condition that does not match the queryThe index is ignoredMake the query include the same condition
Practice
  1. Create a covering index for one of your report queries and confirm the plan says COVERING INDEX.
  2. Add a partial index for "unfinished tasks" and compare its size to a full index.
Key takeaways
  • Index column order should be equality columns, then range or sort.
  • Covering, partial, and expression indexes target specific queries.
  • Every index slows writes, so remove the ones you do not use.
