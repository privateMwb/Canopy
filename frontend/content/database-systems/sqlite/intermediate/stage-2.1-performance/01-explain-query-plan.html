EXPLAIN QUERY PLAN

EXPLAIN QUERY PLAN tells you whether SQLite will scan a table or search an index, which is the first thing to check for a slow query.

§1Reading the Plan

EXPLAIN QUERY PLAN
SELECT * FROM orders WHERE customer_id = 7 ORDER BY created_at DESC LIMIT 20;
SEARCH orders USING INDEX idx_orders_customer (customer_id=?)
USE TEMP B-TREE FOR ORDER BY
  • SCAN reads every row of a table. Fine for tiny tables, costly for large ones.
  • SEARCH uses an index or the primary key to jump to matching rows.
  • COVERING INDEX means the query was answered from the index alone, without touching the table.
  • USE TEMP B-TREE FOR ORDER BY means an extra sort that an index might remove.

§2Fixing the Example

A composite index on (customer_id, created_at) serves both the filter and the order.

CREATE INDEX idx_orders_cust_created ON orders (customer_id, created_at);
-- SEARCH orders USING INDEX idx_orders_cust_created (customer_id=?)

The temp sort disappears because the index is already in the needed order.

§3Why a Plan Might Surprise You

The planner may skip an index when it expects to read most of the table anyway, when a function is applied to the column, when types differ ('7' against an integer column), or when statistics suggest a full scan is cheaper.

SELECT * FROM orders WHERE customer_id + 0 = 7;     -- cannot use the index

§4In the Shell

.eqp on prints the plan before every query result, and EXPLAIN (without QUERY PLAN) shows the low-level bytecode, covered in the senior level.

The key insight Read the plan for words that show full table scans on big tables, and temp B-trees on large sorts. Those are the usual targets.

§5Common Mistakes

MistakeWhat HappensFix
Tuning without reading the planYou add indexes the query ignoresCheck EXPLAIN QUERY PLAN before and after
Wrapping an indexed column in an expressionThe index cannot be usedMove the expression to the other side or index the expression
Comparing text with an integer columnAffinity can prevent index usePass the right type
Practice
  1. Take a slow query, record its plan, add an index, and record the new plan and timing.
  2. Find a query in your project that shows SCAN on a table with more than 10,000 rows.
Key takeaways
  • SCAN reads everything, and SEARCH uses an index.
  • A composite index can serve both filtering and ordering.
  • Expressions or type mismatches can stop an index from being used.
