The Locking Model

SQLite allows many readers or one writer on a database file, and understanding its lock levels explains every SQLITE_BUSY error.

§1The Lock Levels

  • UNLOCKED: not touching the database.
  • SHARED: reading. Many connections can hold it at once.
  • RESERVED: intending to write. Only one at a time, and readers can continue.
  • PENDING: waiting for readers to finish, and no new readers are allowed.
  • EXCLUSIVE: writing to the file. No other connection can read or write.
BEGIN;                      -- no lock yet: deferred
SELECT count(*) FROM log;   -- takes SHARED
INSERT INTO log VALUES (1); -- tries to take RESERVED
COMMIT;                     -- needs EXCLUSIVE briefly to write

§2What Blocks What

In the default rollback-journal mode, a writer must wait for readers to finish before the final commit, and while it commits, readers must wait. So readers and the writer block each other at commit time.

§3SQLITE_BUSY

When a connection cannot get the lock it needs, SQLite returns SQLITE_BUSY ("database is locked"). The usual fixes:

  • Set a busy timeout so SQLite retries for a while.
  • Keep write transactions short.
  • Use WAL mode to let readers and a writer coexist.
PRAGMA busy_timeout = 5000;

§4One Writer at a Time

No matter the mode, there is only one writer at a moment. Many writers can queue, so total write throughput is limited by how short each write transaction is.

The key insight "Database is locked" is a waiting problem, not a corruption problem. Reduce how long you hold locks and add a timeout.

§5Common Mistakes

MistakeWhat HappensFix
No busy timeoutConcurrent connections fail immediately with SQLITE_BUSYSet busy_timeout
Long transactions that include slow workOther writers starveDo slow work outside the transaction
Assuming many writers can run in parallelThey are serializedDesign for one writer and keep each write short
Practice
  1. Open two connections to one file, hold a write transaction in one, and observe the error from the other with and without a busy timeout.
  2. List which lock a plain SELECT takes and which an INSERT takes.
Key takeaways
  • There are five lock levels, and only one writer holds RESERVED or EXCLUSIVE.
  • SQLITE_BUSY means a lock could not be acquired in time.
  • Short write transactions and a busy timeout prevent most failures.
