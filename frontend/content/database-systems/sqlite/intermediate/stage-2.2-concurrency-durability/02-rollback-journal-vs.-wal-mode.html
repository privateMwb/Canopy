Rollback Journal vs. WAL Mode

WAL mode writes changes to a separate log instead of overwriting the database, and that lets readers and a writer work at the same time.

§1Rollback Journal (the Default)

Before changing a page, SQLite copies the original to a journal file. If a crash happens, the journal restores the old pages. Writers modify the database file directly, and readers must be excluded at commit.

§2Write-Ahead Log

In WAL mode, new page versions are appended to a -wal file, and a commit is just a record in that log. Readers see the database as of when they started, using the log plus the main file, so they are never blocked by a writer, and the writer is never blocked by readers.

PRAGMA journal_mode = WAL;        -- stored in the file, remains until changed
PRAGMA wal_checkpoint(TRUNCATE);  -- merge the log back and shrink it

§3Checkpoints

Periodically, a checkpoint copies committed pages from the WAL into the main file so the log does not grow forever. By default this happens automatically at about 1,000 pages. A long-running reader can prevent a checkpoint from finishing past its snapshot, so the WAL can grow large.

§4Trade-Offs

  • Better: concurrent reads during writes, usually faster writes, fewer syncs.
  • Worse: all connections must be on the same machine, because WAL uses shared memory; it does not work reliably over network file systems. Very large transactions are less efficient, and there are extra files to manage.
  • Still true: there is only one writer at a time.
PRAGMA journal_mode;              -- wal
The key insight WAL makes the common web-app pattern (many readers, occasional writer) work well. It is the right default for most applications.

§5Common Mistakes

MistakeWhat HappensFix
Using WAL on a network file systemCorruption or errors from broken shared memoryKeep the database on a local disk
A reader holding a transaction open for hoursThe WAL cannot be checkpointed and growsKeep read transactions short
Copying only the main file in WAL modeRecent data is in the -wal fileUse .backup or VACUUM INTO
Practice
  1. Run a writer loop and a reader loop in rollback mode and then in WAL mode, and compare errors and throughput.
  2. Open a long read transaction, write heavily, and watch the -wal file grow until you end the read.
Key takeaways
  • Rollback journals protect pages before change, and WAL appends changes to a log.
  • WAL lets readers and one writer run concurrently.
  • WAL needs a local file system and attention to checkpoints.
