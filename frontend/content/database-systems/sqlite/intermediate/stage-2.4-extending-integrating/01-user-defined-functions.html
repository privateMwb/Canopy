User-Defined Functions

Your application can register its own functions, which SQL then calls like any built-in function.

§1Registering a Function

import sqlite3, re

def slugify(s):
    return re.sub(r"[^a-z0-9]+", "-", s.lower()).strip("-")

con = sqlite3.connect(":memory:")
con.create_function("slugify", 1, slugify, deterministic=True)
print(con.execute("SELECT slugify('Hello, World!')").fetchone()[0])      # hello-world
db.function("slugify", { deterministic: true }, (s) => s.toLowerCase().replace(/[^a-z0-9]+/g, "-"));

deterministic promises the same input always returns the same output, which lets SQLite use the function in indexes and optimize repeated calls.

§2Aggregates and Collations

class Median:
    def __init__(self): self.values = []
    def step(self, v): self.values.append(v)
    def finalize(self):
        v = sorted(self.values); n = len(v)
        return None if n == 0 else (v[n // 2] if n % 2 else (v[n // 2 - 1] + v[n // 2]) / 2)

con.create_aggregate("median", 1, Median)
con.create_collation("nocase_unicode", lambda a, b: (a.casefold() > b.casefold()) - (a.casefold() < b.casefold()))

§3Use in Indexes

CREATE INDEX idx_post_slug ON post (slugify(title));

An expression index may only call deterministic functions.

§4Trade-Offs

A function exists only on connections that registered it. Opening the database in the shell, or with another program, fails to evaluate it. Avoid depending on custom functions in indexes, triggers, or views if other tools must open the file.

Gotcha If an index or a view uses a custom function, opening the file elsewhere can fail with "no such function". Think about every tool that will touch the database.

§5Common Mistakes

MistakeWhat HappensFix
Using a custom function in an indexOther tools cannot use or rebuild the databasePrefer built-in functions in the schema
Marking a non-deterministic function deterministicWrong results from caching or index useOnly mark true pure functions
Doing heavy work in a function called on every rowSlow queriesFilter rows with SQL first
Practice
  1. Register a slugify function and use it in a query and in an UPDATE.
  2. Write a median aggregate and compare it with a manual SQL approach.
Key takeaways
  • Functions, aggregates, and collations can be registered from application code.
  • Mark pure functions deterministic so they can be optimized and indexed.
  • Custom functions exist only on the connections that register them.
