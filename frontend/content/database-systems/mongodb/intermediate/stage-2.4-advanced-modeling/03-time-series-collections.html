Time Series Collections

Time series collections store measurements in a compact, bucketed format that MongoDB manages for you, with fast time-range queries and lower storage cost.

§1Creating One

A time series collection is created with a timeField and optional metadata.

db.createCollection("readings", {
  timeseries: { timeField: "ts", metaField: "sensor", granularity: "minutes" },
  expireAfterSeconds: 60 * 60 * 24 * 90      // optional: delete data older than 90 days
})
db.readings.insertOne({ ts: new Date(), sensor: { id: "s1", site: "plant-A" }, temp: 21.4, humidity: 40 })
  • timeField is the date field in each measurement.
  • metaField holds labels that rarely change, such as the sensor's identity. Measurements with the same metadata are grouped together.
  • granularity hints at how often data arrives, so the internal buckets are sized well.

§2What Happens Underneath

This is the bucket pattern, done for you. MongoDB groups measurements with the same metadata and nearby timestamps into internal bucket documents stored in a columnar compressed form. Insertion is simple, but you query it like an ordinary collection.

db.readings.aggregate([
  { $match: { "sensor.id": "s1", ts: { $gte: ISODate("2026-03-01"), $lt: ISODate("2026-03-02") } } },
  { $group: { _id: { $dateTrunc: { date: "$ts", unit: "hour" } }, avgTemp: { $avg: "$temp" } } },
  { $sort: { _id: 1 } }
])

You get much smaller storage, a smaller index, and faster range scans than one document per reading.

§3Fit and Limits

Time series collections suit append-heavy measurements (metrics, IoT, prices). They are less suited to data you update often, since measurements are mostly insert-only, and updates and deletes of individual measurements are restricted. Choose metaField carefully, as it determines grouping, and keep it for stable values, never for the measurements themselves.

The key insight Use a time series collection when your data is a stream of timestamped measurements. It gives you the bucket pattern's benefits without writing the bucketing code.

§4Common Mistakes

MistakeWhat HappensFix
Putting changing values in metaFieldPoor grouping and many tiny bucketsKeep it for stable labels such as sensor id
Planning frequent updates to old readingsUpdates are restrictedTreat measurements as append-only
Wrong granularityLess efficient storage and queriesMatch it to how often each source reports
Practice
  1. Create a time series collection, insert a few thousand readings, and compute hourly averages.
  2. Add an expiry to the collection and explain what data you would lose and keep.
Key takeaways
  • A time series collection stores timestamped measurements in compact managed buckets.
  • timeField, metaField, and granularity shape how data is grouped.
  • It fits append-only streams, and not data you edit frequently.
