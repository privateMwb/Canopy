Covered Queries & the Profiler

A covered query is answered entirely from an index with no document reads, and the database profiler helps you find the slow queries worth optimizing.

§1Covered Queries

If every field a query filters on and returns is in one index, MongoDB can answer from the index alone, without fetching any document.

db.users.createIndex({ email: 1, name: 1 })
db.users.find({ email: "ada@example.com" }, { _id: 0, email: 1, name: 1 })
// explain: IXSCAN with no FETCH, and totalDocsExamined: 0

Two requirements: the projection must only include indexed fields, and _id must be excluded unless it is in the index. Covered queries are the cheapest possible read, but each extra indexed field makes the index larger, so use them for your hottest queries.

§2The Database Profiler

The profiler records operations that exceed a time threshold into system.profile.

db.setProfilingLevel(1, { slowms: 100 })      // log operations slower than 100 ms (0 off, 2 everything)
db.system.profile.find().sort({ ts: -1 }).limit(5)
db.system.profile.find({ millis: { $gt: 100 } }, { ns: 1, command: 1, millis: 1, planSummary: 1, docsExamined: 1, nreturned: 1 })

Entries show the namespace, the command, the duration, the plan summary (such as COLLSCAN), and counts of examined and returned documents.

§3A Tuning Workflow

  1. Turn on the profiler with a sensible threshold, or use Atlas Performance Advisor.
  2. Group slow entries by query shape and find the worst by total time.
  3. Run explain("executionStats") on each one.
  4. Add or change an index, and measure again.
  5. Remove indexes that $indexStats shows are unused.
The key insight Optimize the queries that cost the most in total, which is often a fast query run a million times, and not only the single slowest one.

§4Common Mistakes

MistakeWhat HappensFix
Leaving profiling level 2 on in productionOverhead and a growing profile collectionUse level 1 with a threshold, and turn it off when done
Trying to cover a query but returning _idIt still fetches documentsAdd _id: 0 to the projection
Tuning by guessworkIndexes added that nothing usesFind the real slow queries first
Practice
  1. Make one covered query on a test collection and prove with explain that totalDocsExamined is 0.
  2. Enable the profiler, run a mix of queries, and identify the two with the highest total time.
Key takeaways
  • A covered query returns data from the index alone, with no document fetches.
  • The profiler logs slow operations into system.profile for analysis.
  • Tune by total cost, measuring before and after each change.
