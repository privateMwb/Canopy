Compound Indexes & the ESR Rule

A compound index covers several fields in a defined order, and ordering those fields by Equality, then Sort, then Range makes one index serve most queries well.

§1Compound Indexes and Prefixes

A compound index sorts by the first field, then by the second within ties, and so on.

db.orders.createIndex({ customerId: 1, status: 1, placedAt: -1 })

It supports queries on any prefix of its fields: customerId; customerId and status; or all three. It does not efficiently support a query on status alone, because entries are not ordered by status globally.

§2The ESR Rule

Order the fields of a compound index in this sequence:

  1. Equality fields first (exact matches).
  2. Sort fields next.
  3. Range fields last ($gt, $lt, $in with many values).
// query: this customer's paid orders from 2026, newest first
db.orders.find({ customerId: 42, status: "paid", placedAt: { $gte: start } }).sort({ placedAt: -1 })
db.orders.createIndex({ customerId: 1, status: 1, placedAt: -1 })     // E, E, then S and R on one field

Equality fields narrow the search to one section of the index. Sort fields after them return that section already ordered, so no in-memory sort is needed. Range fields last let the scan stop as soon as the range ends.

A query that sorts on one field and ranges on another:

db.events.find({ userId: 7, score: { $gt: 50 } }).sort({ createdAt: -1 })
db.events.createIndex({ userId: 1, createdAt: -1, score: 1 })        // E, S, R

§3Sort Direction

A compound index can serve a sort in the same direction as defined or exactly reversed. { a: 1, b: -1 } serves sort({ a: 1, b: -1 }) and sort({ a: -1, b: 1 }), but not sort({ a: 1, b: 1 }).

The key insight One well-ordered compound index often replaces several single-field indexes. Single-field indexes are not combined effectively for a multi-field query plus sort.

§4Common Mistakes

MistakeWhat HappensFix
Putting the range field before the sort fieldMongoDB cannot return results in order and sorts in memoryFollow Equality, Sort, Range
Several single-field indexes for a multi-field queryOne is picked, and the rest of the work is filteringBuild one compound index
Sorting in a direction the index cannot provideAn in-memory sortMatch the index directions or their exact reverse
Practice
  1. Design the index for "a user's unread notifications, newest first, with priority at least 3".
  2. Create two versions of a compound index, one in ESR order and one not, and compare explain for a sort query.
Key takeaways
  • A compound index supports queries on its leading prefixes.
  • Order fields Equality, Sort, Range.
  • One compound index in the right order beats several single-field indexes.
