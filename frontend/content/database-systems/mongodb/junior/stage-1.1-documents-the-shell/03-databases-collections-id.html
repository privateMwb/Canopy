Databases, Collections & _id

Data is organized into databases and collections, and every document carries a unique _id that MongoDB indexes automatically.

§1Databases and Collections

A MongoDB server hosts many databases, and each database holds collections of documents. There is no CREATE DATABASE step: both are created the first time you write to them.

use shop                                   // select the database (nothing exists on disk yet)
db.products.insertOne({ sku: "NB-1" })     // now "shop" and "products" both exist
show collections                           // products
db.products.drop()                         // delete the collection and its indexes
db.createCollection("orders")              // explicit creation, for options like validation

Three databases are reserved: admin, local, and config. Do not store your application data in them.

§2The _id Field

Every document must have an _id, and it must be unique within the collection. If you do not supply one, the driver or server generates an ObjectId. MongoDB builds a unique index on _id for every collection, so lookups by _id are always fast.

db.products.insertOne({ sku: "PN-3" })
// { acknowledged: true, insertedId: ObjectId("66a1f0c2e4b0a1b2c3d4e5f6") }

db.products.insertOne({ _id: "PN-3", name: "Pen" })    // your own _id: any type except an array
db.products.insertOne({ _id: "PN-3", name: "Again" })  // error: E11000 duplicate key

§3Inside an ObjectId

An ObjectId is 12 bytes: a 4-byte timestamp, a 5-byte random value fixed per process, and a 3-byte counter. That makes ids unique across machines without coordination, and roughly increasing over time.

const id = ObjectId()
id.getTimestamp()     // ISODate of creation, to the second

You can use a natural key as _id (an email, a SKU, a UUID) when it is truly unique and never changes. Otherwise the default ObjectId is a good choice.

The key insight _id is immutable. To "change" it you must insert a new document and delete the old one, so never use a value that might need editing.

§4Common Mistakes

MistakeWhat HappensFix
Using a mutable value (an email) as _idYou cannot update it, and changes force a copy and deleteUse an ObjectId and put the email in its own unique-indexed field
Comparing an ObjectId to a stringThe query matches nothingWrap it: ObjectId("...")
Misspelling a collection nameA new empty collection appears silentlyCheck show collections and use constants in code
Practice
  1. Insert three documents without an _id and one with a custom _id. Compare what you see.
  2. Use getTimestamp() on two ids created a second apart and explain what you observe.
Key takeaways
  • Databases and collections are created implicitly on first write.
  • _id is required, unique, indexed, and immutable.
  • An ObjectId is unique without coordination and embeds its creation time.
