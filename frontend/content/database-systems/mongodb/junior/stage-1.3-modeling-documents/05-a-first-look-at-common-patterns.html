A First Look at Common Patterns

A few named patterns, subset, bucket, and computed values, solve recurring modeling problems, and you can already apply them with the tools you know.

§1The Subset Pattern

Keep the hot part of a large related set inside the parent, and the rest in another collection. The product page shows ten reviews, so the product embeds ten and the reviews collection holds all of them.

{ _id: "NB-1", name: "Notebook", topReviews: [ /* 10 most helpful */ ] }

The working set shrinks, since most requests never need the full history.

§2The Bucket Pattern

For a stream of small items, such as sensor readings, group many of them into one document instead of one document per reading.

{ sensorId: "s1", day: ISODate("2026-03-01"), count: 3,
  readings: [ { t: ISODate("2026-03-01T00:00:00Z"), v: 20.1 },
              { t: ISODate("2026-03-01T00:01:00Z"), v: 20.3 } ] }

db.readings.updateOne(
  { sensorId: "s1", day: ISODate("2026-03-01"), count: { $lt: 200 } },
  { $push: { readings: { t: new Date(), v: 20.4 } }, $inc: { count: 1 } },
  { upsert: true })

Each bucket is bounded (200 readings), there are far fewer documents and index entries, and a day of data is one read.

§3The Computed Pattern

If a value is expensive to calculate and read far more often than it changes, calculate it when the data changes and store the result.

db.products.updateOne({ _id: "NB-1" }, { $inc: { reviewCount: 1, starTotal: 5 } })
// average = starTotal / reviewCount, read directly instead of aggregating all reviews
The key insight Each pattern trades a little write-time work or duplication for cheaper, more predictable reads. You already have the operators to apply them.

§4Common Mistakes

MistakeWhat HappensFix
Bucketing with no size or time boundThe bucket turns into an unbounded arrayCap by count or time period
Computing a value on every readRepeated expensive aggregationStore the computed value and update it with the data
Using a pattern with no query that needs itExtra complexity for nothingApply a pattern only to a measured problem
Practice
  1. Design a bucketed model for temperature readings and write the upsert that adds a reading to the right bucket.
  2. Add reviewCount and starTotal to a product, and write the update that runs when a review is posted.
Key takeaways
  • The subset pattern embeds the hot slice of a large set and keeps the rest in a collection.
  • The bucket pattern groups many small items into bounded documents.
  • The computed pattern stores derived values, updated when the underlying data changes.
