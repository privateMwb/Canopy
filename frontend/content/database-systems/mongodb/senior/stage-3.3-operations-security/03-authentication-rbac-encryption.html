Authentication, RBAC & Encryption

A secured MongoDB deployment authenticates every client, grants only the roles each needs, encrypts traffic and data, and records what happens.

§1Authentication

A self-managed server starts with no access control unless you enable it, which has caused many public data leaks. Turn it on, and require credentials.

# mongod.conf
security:
  authorization: enabled
net:
  bindIp: 10.0.0.5          # not 0.0.0.0 unless a firewall protects it
  tls:
    mode: requireTLS
    certificateKeyFile: /etc/ssl/mongo.pem

Authentication mechanisms include SCRAM (username and password, the default), x.509 certificates, and LDAP or OIDC/Kerberos in enterprise setups. Replica set members authenticate to each other with a keyfile or x.509 certificates.

§2Role-Based Access Control

RBAC grants privileges (actions on resources) through roles, and users receive roles.

use admin
db.createUser({ user: "reporting", pwd: passwordPrompt(), roles: [ { role: "read", db: "shop" } ] })

db.createRole({
  role: "orderWriter",
  privileges: [ { resource: { db: "shop", collection: "orders" }, actions: ["find", "insert", "update"] } ],
  roles: []
})

Built-in roles such as read, readWrite, dbAdmin, clusterMonitor, and backup cover common jobs. Create custom roles for narrower access, give each service its own user, and avoid using root outside administration.

§3Encryption

LayerProtects againstHow
In transitEavesdropping on the networkTLS between clients and servers, and between members
At restStolen disks or backupsEncrypted storage (enterprise or Atlas), or disk-level encryption
In useExposure to the database operatorClient-Side Field Level Encryption and Queryable Encryption

Field-level encryption encrypts selected fields in the application with keys the server never sees, so even an administrator or a leaked backup reveals only ciphertext. Queryable Encryption allows certain queries on encrypted fields.

Add auditing to record authentication events and sensitive operations, and keep secrets in a secrets manager with rotation.

The key insight Security is layers. Network limits, authentication, narrow roles, encryption, and audit logs each cover a failure of the others.

§4Common Mistakes

MistakeWhat HappensFix
Running without authorization enabledAnyone who can reach the port has full accessEnable authentication and bind to private interfaces
Shared admin credentials in every serviceOne leak exposes everythingOne least-privilege user per service
TLS off inside a "trusted" networkCredentials and data travel in clear textRequire TLS everywhere
Practice
  1. Create a read-only user and a custom role that can only insert into one collection, and test both.
  2. Decide which fields in a user profile deserve field-level encryption, and which threat each protects against.
Key takeaways
  • Enable authentication, bind to private interfaces, and require TLS.
  • RBAC gives each user only the privileges it needs, through built-in or custom roles.
  • Encrypt in transit, at rest, and for sensitive fields, and keep an audit trail.
