Callable Functions & App Check

A callable function is a function the client calls like a normal method, with the user's identity attached automatically.

§1Defining and Calling

// functions/index.js
import { onCall, HttpsError } from "firebase-functions/v2/https";
import { getAuth } from "firebase-admin/auth";

export const makeAdmin = onCall(async (request) => {
  if (!request.auth) throw new HttpsError("unauthenticated", "Sign in first.");
  if (request.auth.token.role !== "admin") throw new HttpsError("permission-denied", "Admins only.");

  const { uid } = request.data;
  if (typeof uid !== "string") throw new HttpsError("invalid-argument", "uid is required.");

  await getAuth().setCustomUserClaims(uid, { role: "admin" });
  return { ok: true };
});
// client
import { getFunctions, httpsCallable } from "firebase/functions";
const makeAdmin = httpsCallable(getFunctions(), "makeAdmin");
const res = await makeAdmin({ uid: "abc" });

The SDK sends the user's ID token and decodes it for you, so request.auth is trustworthy. Always validate request.data, because it comes from the client.

§2Errors

Throw HttpsError with a standard code (invalid-argument, not-found, permission-denied, failed-precondition, and others). The client receives error.code and error.message. Any other thrown error becomes a generic internal, which hides details from users and shows them in the logs.

§3App Check

App Check proves that a request comes from your real app, not a script. On the web it uses reCAPTCHA; on mobile it uses device attestation.

// client
import { initializeAppCheck, ReCaptchaV3Provider } from "firebase/app-check";
initializeAppCheck(app, { provider: new ReCaptchaV3Provider("SITE_KEY"), isTokenAutoRefreshEnabled: true });

// server
export const makeAdmin = onCall({ enforceAppCheck: true }, handler);

App Check is a layer against abuse, not a replacement for authentication or rules: it says the app is genuine, not that the user is allowed.

Authenticate, authorize, validate A callable function gives you identity for free, but you still must check permission and validate every input yourself, as in any API.

§4Common Mistakes

MistakeWhat HappensFix
Trusting request.data as validBad or malicious input reaches your logicValidate type and range, and throw invalid-argument
Checking sign-in but not permissionAny user can call an admin functionCheck roles or ownership explicitly
Treating App Check as authorizationGenuine apps can still be abused by signed-in usersCombine App Check with auth and validation
Practice
  1. Write a callable function that changes a user's role and rejects non-admins, then call it from the client.
  2. Enable App Check enforcement in a staging project and confirm a call without a valid App Check token is rejected.
Key takeaways
  • Callable functions receive the caller's identity as request.auth.
  • Validate inputs and permissions yourself; throw HttpsError for expected failures.
  • App Check verifies the app, not the user.
