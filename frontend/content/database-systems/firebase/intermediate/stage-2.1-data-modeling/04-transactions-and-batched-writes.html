Transactions & Batched Writes

Transactions and batches make several writes succeed or fail together, and they differ in whether they read first.

§1Batched Writes

A batch is a set of writes applied atomically. Nothing is partly applied, and it works offline.

import { writeBatch, doc } from "firebase/firestore";

const batch = writeBatch(db);
batch.set(doc(db, "orders", "o1"), { total: 40 });
batch.update(doc(db, "users", "alice"), { orders: increment(1) });
batch.delete(doc(db, "carts", "alice"));
await batch.commit();

Batches have a cap on operations and total size (long documented as 500 writes), so chunk large jobs into several batches. Use a batch when you already know every value to write and do not need to read first.

§2Transactions

A transaction reads documents and then writes based on what it read, with Firestore guaranteeing nothing changed in between.

import { runTransaction, doc } from "firebase/firestore";

await runTransaction(db, async (tx) => {
  const ref = doc(db, "products", "p1");
  const snap = await tx.get(ref);
  const stock = snap.data().stock;
  if (stock < 1) throw new Error("Out of stock");
  tx.update(ref, { stock: stock - 1 });
});

If another write touches a document you read, Firestore retries the function, so it must have no side effects other than the transaction's own reads and writes. All reads must come before writes.

§3Limits to Respect

  • Client transactions require a network connection; they fail offline
  • Do not put things like sending email or Math.random()-dependent logic inside the function, because it may run several times
  • Hot documents with many competing transactions slow down and eventually fail
  • For server code, the Admin SDK has similar transactions with different locking behavior
Read-then-write means transaction If your write depends on what you just read, such as decrementing stock, use a transaction. If you already know the values, a batch is simpler and works offline.

§4Common Mistakes

MistakeWhat HappensFix
Reading with getDoc then writing outside a transactionTwo users both pass the stock check and oversellDo the read inside runTransaction
Sending email inside a transaction functionDuplicate emails when it retriesDo side effects after the transaction commits
Putting thousands of writes in one batchExceeds limits and failsChunk into several batches
Practice
  1. Write a transaction that decrements stock only when it is above zero, and test with two tabs at once.
  2. Write a helper that deletes a large list of documents by chunking batches.
Key takeaways
  • Batches apply known writes atomically and work offline.
  • Transactions read then write safely, retry on conflict, and need a connection.
  • Keep transaction functions free of side effects.
