Counters & Aggregations

Counting and summing in Firestore can be done by the server, by a stored counter, or by a sharded counter, depending on how often it changes.

§1Server-Side Aggregate Queries

Aggregate queries compute results on the server without downloading the documents.

import { getCountFromServer, getAggregateFromServer, sum, average, collection, query, where } from "firebase/firestore";

const q = query(collection(db, "orders"), where("status", "==", "paid"));

const c = await getCountFromServer(q);
console.log(c.data().count);

const a = await getAggregateFromServer(q, { total: sum("amount"), avg: average("amount") });
console.log(a.data().total, a.data().avg);

They are billed far more cheaply than reading every document (roughly one read per batch of index entries scanned) but still scale with the number of matches, so a count over millions of documents is not free.

§2Stored Counters

For something shown constantly, such as likes on a post, keep the number on the document and update it atomically.

import { writeBatch, doc, increment } from "firebase/firestore";

const batch = writeBatch(db);
batch.set(doc(db, "posts/p1/likes", uid), { at: serverTimestamp() });
batch.update(doc(db, "posts/p1"), { likeCount: increment(1) });
await batch.commit();

Writing the like document and the counter in one batch keeps them consistent. Rules can verify the pairing.

§3Distributed Counters

A single document can only handle roughly one sustained write per second. For a number that many users change at once, split it into shards: several counter documents, each incremented at random, summed on read.

const shard = Math.floor(Math.random() * 10);
await updateDoc(doc(db, "stats/pageviews/shards", String(shard)), { n: increment(1) });
// total = sum of n across the 10 shard documents
Pick by write rate Few writes per second: a stored counter. Many concurrent writes: a sharded counter. Rarely needed or ad hoc: an aggregate query.

§4Common Mistakes

MistakeWhat HappensFix
Reading every document to countA huge read bill and slow screensUse getCountFromServer or a stored counter
Updating one counter document from thousands of clientsWrites contend and fail past about one per secondShard the counter
Updating the counter and the data in separate callsA crash between them leaves the count wrongUse a batch or transaction
Practice
  1. Add a likeCount to posts, updated with increment in the same batch that records the like.
  2. Run getCountFromServer on a collection and compare the cost to reading it with getDocs.
Key takeaways
  • Aggregate queries count and sum on the server cheaply.
  • Stored counters are fast to read; keep them consistent with batches.
  • Shard counters when many clients write at once.
