Remote Config & Analytics

Remote Config lets you change app values and run experiments without shipping an update, and Analytics tells you whether it worked.

§1Remote Config

Define parameters in the console with default values, optional conditions, and percentage rollouts. The app fetches and applies them.

import { getRemoteConfig, fetchAndActivate, getValue } from "firebase/remote-config";

const rc = getRemoteConfig(app);
rc.settings.minimumFetchIntervalMillis = 3600000;         // fetch at most hourly
rc.defaultConfig = { new_checkout: false, banner_text: "Welcome" };

await fetchAndActivate(rc);
if (getValue(rc, "new_checkout").asBoolean()) showNewCheckout();

Always set defaults in code so the app works before the first fetch or when it fails. Values can differ by country, app version, language, or a random percentage of users, which makes feature flags and gradual rollouts possible.

§2Analytics

Google Analytics for Firebase records events and user properties.

import { getAnalytics, logEvent, setUserProperties } from "firebase/analytics";

const analytics = getAnalytics(app);
logEvent(analytics, "purchase", { value: 29.99, currency: "EUR" });
setUserProperties(analytics, { plan: "pro" });

A set of events are collected automatically, and you can add custom ones. Analytics powers audiences, funnels, and the BigQuery export covered in the senior level.

§3A/B Testing

The A/B Testing feature combines the two: serve different Remote Config values to different groups, and measure an Analytics goal such as purchases. Decide the metric before you start, run long enough for a meaningful result, and remember that Remote Config values reach clients, so never put secrets in them.

Config is public Remote Config values are downloaded by clients and visible to users. Use them for behavior flags and copy, never for keys or private logic.

§4Common Mistakes

MistakeWhat HappensFix
No in-app default valuesThe app breaks offline or on first launchSet defaultConfig for every parameter
Fetching on every screenThrottling and wasted requestsRespect the minimum fetch interval
Running a test with no clear goal metricNo conclusion can be drawnPick the success event before starting
Practice
  1. Add a feature flag with Remote Config and turn it on for 10% of users from the console.
  2. Log a custom event for a key action and find it in the Analytics dashboard.
Key takeaways
  • Remote Config changes behavior without a release, with defaults, conditions, and rollouts.
  • Analytics events show what users actually do.
  • Together they support experiments; keep config values non-secret.
