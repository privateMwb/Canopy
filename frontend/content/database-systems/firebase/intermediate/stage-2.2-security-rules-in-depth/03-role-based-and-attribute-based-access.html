Role-Based & Attribute-Based Access

Real apps need admins, team members, and shared documents, which are expressed with roles stored in custom claims or in membership data.

§1Custom Claims

A custom claim is a small piece of data attached to a user's ID token, set only from trusted server code.

// server only, with the Admin SDK
import { getAuth } from "firebase-admin/auth";
await getAuth().setCustomUserClaims(uid, { role: "admin" });
function isAdmin() { return request.auth.token.role == 'admin'; }

match /reports/{id} {
  allow read: if isAdmin();
}

Claims are fast, because no database read is needed. They are limited to about 1000 bytes and take effect only after the user's token refreshes, which the client forces with getIdToken(true).

§2Membership Documents

When roles are per team or per project, store membership in the database and check it with get() or exists().

function isMember(teamId) {
  return exists(/databases/$(database)/documents/teams/$(teamId)/members/$(request.auth.uid));
}
function roleIn(teamId) {
  return get(/databases/$(database)/documents/teams/$(teamId)/members/$(request.auth.uid)).data.role;
}

match /teams/{teamId}/projects/{pid} {
  allow read: if isMember(teamId);
  allow write: if roleIn(teamId) in ['owner', 'editor'];
}

Changes apply immediately, with no token refresh, at the cost of an extra document read per check.

§3Sharing Documents

For "share with these people", store a list of user IDs on the document.

allow read: if request.auth.uid == resource.data.ownerId
            || request.auth.uid in resource.data.sharedWith;

Clients then query with where("sharedWith", "array-contains", uid), matching the rule so the query is allowed.

Claims for global, documents for contextual Use custom claims for a few broad, rarely changing roles like admin. Use membership documents for per-team or per-resource permissions that change often.

§4Common Mistakes

MistakeWhat HappensFix
Putting roles in a user-editable documentUsers grant themselves adminSet roles via claims from a server or protect the field in rules
Expecting a claim to apply immediatelyThe old role persists until the token refreshesForce a token refresh after changing claims
Storing lots of data in claimsThe token exceeds its size limitKeep claims tiny; store the rest in documents
Practice
  1. Set an admin claim with a small script on the emulator and write a rule that only admins can read a collection.
  2. Implement team membership with exists() and test that a non-member is denied.
Key takeaways
  • Custom claims are set from the server and read as request.auth.token.
  • Membership documents allow per-resource roles checked with get() and exists().
  • Sharing uses a list on the document and a matching array-contains query.
