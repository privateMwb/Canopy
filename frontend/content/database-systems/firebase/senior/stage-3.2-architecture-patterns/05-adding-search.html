Adding Search

Firestore cannot search inside text or rank results, so search is a separate system that you keep in sync.

§1Why It Is Missing

Firestore only serves queries from exact-match and range indexes. Substring matching, typo tolerance, relevance ranking, facets, and stemming need different data structures. Prefix tricks and array-contains on keyword arrays cover only the simplest cases and scale poorly.

§2Bolt-On Options

  • Typesense or Algolia or Elasticsearch via a Firebase extension or your own functions that index documents as they change
  • Vector search in Firestore with findNearest, for semantic similarity, using embeddings you compute
// keep an external index in sync
export const indexNote = onDocumentWritten("notes/{id}", async (event) => {
  const id = event.params.id;
  if (!event.data.after.exists) return searchClient.delete(id);
  await searchClient.upsert({ id, ...event.data.after.data() });
});

The client then queries the search service for IDs or full results, using a search-only key restricted to the user's data.

§3Design Concerns

Decide the source of truth (Firestore), and treat the search index as a rebuildable copy. Provide a way to reindex everything. Mind security: never expose an admin search key to clients, and filter results by tenant or permission, since the search service does not read your rules. Plan for eventual consistency, because a new document may take seconds to be searchable.

Search is a derived index Keep Firestore as the truth and the search service as a disposable copy you can rebuild. Then a sync bug is an annoyance, not data loss.

§4Common Mistakes

MistakeWhat HappensFix
Exposing an admin search key in the clientAnyone can read or delete the whole indexUse scoped, search-only keys or search through a function
Not filtering search results by permissionUsers see documents they cannot readApply tenant and ACL filters in the search query
No way to rebuild the indexA sync bug leaves search wrong foreverWrite a full reindex job
Practice
  1. Write a function that mirrors a collection into a search service on every write and deletion.
  2. Write a reindex script that rebuilds the whole search index from Firestore.
Key takeaways
  • Firestore has no full-text search; use a dedicated search service.
  • Sync the index with functions and keep Firestore as the source of truth.
  • Secure search keys and filter by permission.
