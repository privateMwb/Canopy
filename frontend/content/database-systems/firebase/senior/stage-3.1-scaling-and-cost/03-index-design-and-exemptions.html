Index Design & Exemptions

Every indexed field makes writes heavier and uses storage, so at scale you choose which indexes you actually need.

§1What Is Indexed by Default

Every field of every document gets single-field indexes automatically: ascending and descending, plus an array-contains index for arrays. A map field gets indexes for each nested field. Each write updates every one of them, and the index entries count toward your stored data.

A document with a large array or many nested fields can create thousands of index entries, with a limit of about 40,000 per document. Writes get slower and more expensive as that number grows.

§2Single-Field Exemptions

You can turn indexes off for fields you never query or sort on.

{
  "indexes": [],
  "fieldOverrides": [
    { "collectionGroup": "logs", "fieldPath": "message", "indexes": [] },
    { "collectionGroup": "events", "fieldPath": "createdAt",
      "indexes": [ { "order": "DESCENDING", "queryScope": "COLLECTION" } ] }
  ]
}

The first override removes all indexing from a big free-text message field. The second keeps only a descending index on createdAt. Good candidates for exemption are long strings, large maps and arrays, and sequential timestamp fields on very write-heavy collections.

§3Keeping Composite Indexes Lean

  • Review firestore.indexes.json regularly and delete composites no query uses
  • The console and usage tools show index storage and which queries use which index
  • Prefer fewer, broader composite indexes that serve several queries
  • Remember that removing an index that a query needs makes that query fail, so confirm in staging first
Indexes are a write-time tax Indexes make reads fast by making writes do more work. At low volume that is invisible; at scale it is a major cost and latency driver.

§4Common Mistakes

MistakeWhat HappensFix
Leaving default indexing on huge text fieldsWasted storage and slower writesAdd a single-field exemption
Putting thousands of values in an indexed arrayYou approach the index entry limitRestructure or exempt the field
Deleting an index without checking usageA production query breaksVerify in staging and monitor errors after
Practice
  1. Identify the three fattest fields in your largest collection and decide which can be exempted.
  2. Add a field override to firestore.indexes.json and deploy it to a staging project.
Key takeaways
  • Every field is indexed by default, and every write updates those indexes.
  • Exempt fields you never query to save storage and write cost.
  • Prune unused composite indexes.
