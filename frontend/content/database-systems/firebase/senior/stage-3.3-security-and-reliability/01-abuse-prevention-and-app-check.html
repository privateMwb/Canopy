Abuse Prevention & App Check

A public Firebase backend invites scripts, scrapers, and cost attacks, so you need layers beyond authentication.

§1The Threats

  • Scripted clients using your public config to hammer Firestore, Storage, or Functions
  • Scraping of data that rules allow any signed-in user to read
  • Sign-up abuse: bots creating thousands of accounts to bypass per-user limits
  • Cost attacks: expensive queries, large uploads, or function calls designed to run up your bill

§2App Check in Practice

App Check attaches an attestation token to requests from your genuine app, and Firebase services can reject requests without one.

Roll it out safely:

1. Register providers (reCAPTCHA Enterprise on web, Play Integrity on Android, App Attest or DeviceCheck on iOS) 2. Add the client SDK and monitor metrics to see how many requests carry valid tokens 3. When nearly all legitimate traffic is verified, switch each product (Firestore, Storage, Functions) to enforced 4. Use debug tokens for local development and CI, kept secret and revocable

An attacker can still run a real browser or a farm of real devices, so App Check raises the cost of abuse; it does not eliminate it.

§3Other Layers

  • Rate limits inside functions, using a counter document or a service such as Cloud Armor in front of HTTP functions
  • Quotas per user enforced in function code or via rules that compare counters
  • Sign-up protection: email enumeration protection, reCAPTCHA on sign-up, blocking functions to reject suspicious accounts
  • Tight rules and limits: bounded list queries, upload size caps, and maxInstances on every function
  • Alerts on unusual read, write, and function-invocation spikes
Make abuse expensive and visible You cannot make a public endpoint unattackable, but you can make attacks cost more than they are worth and ensure you see them within minutes.

§4Common Mistakes

MistakeWhat HappensFix
Enforcing App Check immediatelyLegitimate users on old app versions are blockedRun in monitoring mode first, then enforce gradually
Relying only on App CheckReal devices and scripts that pass attestation still abuse youCombine with rules, rate limits, and alerts
Leaving debug tokens in shared codeAnyone can bypass App CheckKeep debug tokens secret and revoke them regularly
Practice
  1. Enable App Check in monitoring mode and read the verified request metrics for a day.
  2. Add a per-user rate limit to one callable function using a counter document.
Key takeaways
  • Public backends face scripted abuse, scraping, and cost attacks.
  • Roll out App Check through monitoring, then enforcement, with debug tokens for development.
  • Layer rate limits, rules, caps, and alerts.
