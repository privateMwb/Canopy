Cost Forecasting & Growth Planning

A cost forecast turns per-user behavior into a monthly number, and shows which designs stop making sense as you grow.

§1Building a Cost Model

Start from user behavior and work up:

daily active users            : 20,000
sessions per user per day     : 3
reads per session             : 60      -> 3,600,000 reads/day
writes per user per day       : 8       -> 160,000 writes/day
function invocations per day  : 200,000
stored data                   : 40 GB

Multiply by current prices from the official calculator for your region, add storage, egress, functions, Storage, and extras like BigQuery. Measure the real numbers from the usage dashboard rather than guessing. Compare the model to the actual bill each month and adjust.

§2What Changes at 10x

  • Linear costs (reads, writes) grow with usage; a feature that costs a cent per user matters at scale
  • Superlinear costs appear from feeds that fan out, listeners on shared data, and background jobs scanning everything
  • Limits such as hotspots and the one-write-per-second ceiling begin to bite
  • Operational cost (humans, incident time) grows with complexity

For each major screen, estimate reads per view and see which ones dominate. A 10x review should list the top five costs and the design change that cuts each one: caching, bundles, summary documents, batching, or moving a workload to a different system.

§3Guardrails

Set budget alerts at several thresholds, with an owner who acts on them. Put limit on queries and maxInstances on functions. Add dashboards for reads per active user, because a rise in that ratio is the earliest sign of an inefficient release.

Track cost per active user Total spend rises as you grow, which is fine. Spend per active user rising is the warning sign that a release or design got less efficient.

§4Common Mistakes

MistakeWhat HappensFix
Forecasting from storage sizeReads and writes dominate, so the forecast is far too lowModel operations per user per day
Using remembered pricesStale numbers lead to wrong decisionsUse the current calculator for your region
Reviewing cost only when the bill hurtsInefficiencies compound for monthsReview cost per active user monthly
Practice
  1. Build a spreadsheet model for your app's monthly cost and compare it to a real invoice.
  2. List the top five cost drivers and the design change that would cut each by half.
Key takeaways
  • Model cost from user behavior: operations per user, times prices, plus storage and egress.
  • Look for superlinear costs and limits at 10x scale.
  • Track spend per active user and set budget alerts.
