Firebase Hosting & Deployment

Firebase Hosting serves your static site or single-page app from a global CDN with HTTPS, and a deploy is one command.

§1Deploying

firebase init hosting             # choose a public folder (e.g. dist) and SPA behavior
npm run build
firebase deploy --only hosting

The deploy uploads your files, creates a new immutable release, and serves it at your-project.web.app and your-project.firebaseapp.com. Custom domains are added in the console and get free certificates.

§2firebase.json

{
  "hosting": {
    "public": "dist",
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
    "rewrites": [{ "source": "**", "destination": "/index.html" }],
    "headers": [
      {
        "source": "**/*.@(js|css)",
        "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }]
      }
    ]
  }
}

The catch-all rewrite serves index.html for any path, which single-page apps need so deep links work on refresh. Long cache headers on hashed asset files make repeat visits fast.

§3Previews and Rollbacks

firebase hosting:channel:deploy pr-42         # a temporary preview URL for testing

A preview channel gives you a separate URL that expires, so you can share changes before they go live. Every live deploy is kept in the release history, and you can roll back to a previous release from the Hosting page in the console in one click.

Deploys are immutable Because each release is a complete, versioned snapshot, rolling back is instant and safe. That makes frequent deploys low-risk.

§4Common Mistakes

MistakeWhat HappensFix
No rewrite for a single-page appRefreshing on /settings shows a 404Add the catch-all rewrite to index.html
Deploying the source folder instead of the build outputUsers get unbuilt filesSet public to the build directory and build first
Caching index.html for a yearUsers never see new releasesKeep index.html uncached and cache hashed assets long
Practice
  1. Deploy a small site, then change a word, deploy again, and roll back in the console.
  2. Create a preview channel for a change and open its URL on your phone.
Key takeaways
  • firebase deploy --only hosting publishes an immutable release.
  • Rewrites make single-page app routes work, and headers control caching.
  • Preview channels share changes before launch, and rollbacks undo a bad release.
