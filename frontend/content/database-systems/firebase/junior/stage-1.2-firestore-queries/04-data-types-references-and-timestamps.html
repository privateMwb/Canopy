Data Types, References & Timestamps

Firestore's special types, especially timestamps and references, behave differently from plain JSON, so they deserve their own care.

§1Timestamps

Use serverTimestamp() for creation and update times so every record uses the server's clock, not a user's possibly wrong device clock.

import { serverTimestamp, Timestamp } from "firebase/firestore";

await addDoc(col, { text: "hi", createdAt: serverTimestamp() });

const t = Timestamp.fromDate(new Date("2026-01-15"));
const jsDate = snap.data().createdAt.toDate();       // Timestamp -> Date

In a listener, a pending serverTimestamp() reads as null until the server fills it in, so guard for that.

§2References

A reference field stores a pointer to another document. It does not fetch it; you read the target in a second call.

import { doc, getDoc } from "firebase/firestore";

await setDoc(doc(db, "posts", "p1"), { author: doc(db, "users", "alice") });

const post = (await getDoc(doc(db, "posts", "p1"))).data();
const author = await getDoc(post.author);             // a second read

Many designs store the author's ID string and a copy of the display name instead, which avoids the second read. That pattern is covered in the intermediate level.

§3Arrays and Maps

import { arrayUnion, arrayRemove, deleteField } from "firebase/firestore";

await updateDoc(ref, { tags: arrayUnion("sale") });     // add if absent
await updateDoc(ref, { tags: arrayRemove("old") });     // remove all matches
await updateDoc(ref, { "address.city": "Porto" });      // change one nested field
await updateDoc(ref, { nickname: deleteField() });      // remove a field

Arrays cannot directly contain other arrays, and you cannot update one element by index. If you need to edit elements individually, use a map keyed by ID or a subcollection.

Dot notation reaches into maps updateDoc(ref, { address: { city: "Porto" } }) replaces the whole address map, while { "address.city": "Porto" } changes only the city.

§4Common Mistakes

MistakeWhat HappensFix
Using new Date() for created timesWrong or manipulated device clocks corrupt orderingUse serverTimestamp()
Not handling a null pending timestampA crash or "Invalid Date" in the UICheck for null before calling toDate()
Updating a nested map by passing the objectSibling fields inside the map are erasedUse dot-notation field paths
Practice
  1. Add a createdAt with serverTimestamp() and display it as a readable date, handling the pending case.
  2. Store tags as an array and add and remove a tag with arrayUnion and arrayRemove.
Key takeaways
  • Prefer serverTimestamp() over client dates.
  • References point to documents but do not load them automatically.
  • Dot-notation paths update nested map fields without overwriting siblings.
