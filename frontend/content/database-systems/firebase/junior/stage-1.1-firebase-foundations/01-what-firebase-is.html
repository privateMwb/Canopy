What Firebase Is

Firebase is Google's backend-as-a-service: a set of hosted products that replace the servers you would otherwise write and run yourself.

§1A Backend You Don't Run

Most apps need the same few things: somewhere to store data, a way to sign users in, somewhere to put files, and somewhere to host the site. Firebase provides each as a managed service you call directly from the client with an SDK, so a small team can ship without provisioning a single server.

  • Firestore and Realtime Database: hosted databases with live updates
  • Authentication: email, social, phone, and anonymous sign-in
  • Cloud Storage: user-uploaded files
  • Hosting: static sites and single-page apps on a global CDN
  • Cloud Functions: server code that runs on events or HTTP requests
  • Others: Cloud Messaging, Remote Config, Analytics, App Check

§2What Runs Where

The browser or phone runs your app plus the Firebase SDK. The SDK talks to Google-run services over the network. There is no server of yours in the middle, which is why security rules matter: they are the only thing between a user and your data.

Browser / phone          Google-run services
┌──────────────┐        ┌────────────────────┐
│ your app     │──SDK──▶│ Firestore          │
│ + Firebase   │──SDK──▶│ Authentication     │
│   SDK        │──SDK──▶│ Cloud Storage      │
└──────────────┘        │ Cloud Functions    │ ◀─ your server code
                        └────────────────────┘

Firebase projects sit on top of a Google Cloud project, so everything here is also visible in the Google Cloud console.

§3Pricing in One Paragraph

Every project starts on the free Spark plan, which has daily and monthly quotas and no billing. The pay-as-you-go Blaze plan removes the hard caps and bills for usage above the free tier. Some products, notably Cloud Functions, require Blaze. Pricing is covered properly in the senior level; for now, know that Firestore bills per document read, write, and delete.

The key insight Firebase trades server code for configuration. That is a good trade until your needs outgrow what the managed products offer, which is what the later levels are about.

§4Common Mistakes

MistakeWhat HappensFix
Treating Firebase as one databaseYou miss that Auth, Storage, and Hosting are separate products with separate rulesLearn each product's role and its own access rules
Assuming the client is trustedAnyone can open dev tools and call the SDK with their own codeEnforce access with security rules, never with client-side checks
Ignoring the billing planA feature fails because it needs Blaze, or a loop causes a surprise billKnow which products need Blaze and set budget alerts
Practice
  1. List the Firebase products an app with sign-in, profile photos, and a feed would need, and say which one stores each kind of data.
  2. Open the Firebase pricing page and find the free daily quota for Firestore reads, writes, and deletes.
Key takeaways
  • Firebase is a set of managed backend products called directly from the client with an SDK.
  • Because there is no server of yours in the path, security rules are your access control.
  • Spark is free with quotas; Blaze is pay-as-you-go and required for some products.
