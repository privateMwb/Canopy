Projects, the Console & the CLI

A Firebase project is the container for everything, the console is its dashboard, and the CLI is how you deploy and configure it from your terminal.

§1The Project and the Console

A project holds your apps, databases, users, files, and settings. Create one at console.firebase.google.com. Inside it you register apps (web, iOS, Android), each with its own configuration, and enable the products you want. A single project can serve a web app and two mobile apps that share one database and one set of users.

The console lets you browse Firestore data, see users, read function logs, and edit rules. It is excellent for inspecting; use files and the CLI for anything you want versioned.

§2Installing and Logging In to the CLI

npm install -g firebase-tools
firebase login                  # opens a browser to authenticate
firebase projects:list          # confirm you can see your projects

The CLI needs Node.js. firebase login stores credentials locally so later commands run as you.

§3Initializing a Local Project

Run firebase init in your app's folder and pick the products you use. It writes configuration files you commit to git.

cd my-app
firebase init firestore hosting
  • firebase.json: what to deploy and how (hosting folder, rules file, index file)
  • .firebaserc: which Firebase project this folder is linked to
  • firestore.rules: your Firestore security rules
  • firestore.indexes.json: your composite indexes
firebase deploy                          # deploy everything configured
firebase deploy --only firestore:rules   # deploy just the rules
Rules and indexes live in files Treat firestore.rules and firestore.indexes.json like source code: review them in pull requests and deploy them from the CLI, instead of editing them by hand in the console where changes leave no history.

§4Common Mistakes

MistakeWhat HappensFix
Editing rules only in the consoleNo history, and the next deploy can overwrite your changeKeep the rules file in git and deploy with the CLI
Running firebase deploy blindlyDeploys every configured product to whichever project is activeCheck firebase use first and use --only to narrow the deploy
Not committing .firebaserc and firebase.jsonTeammates cannot reproduce the setupCommit both; they contain no secrets
Practice
  1. Create a project in the console, install the CLI, log in, and run firebase projects:list to see it.
  2. Run firebase init firestore in an empty folder and read each generated file.
Key takeaways
  • A project contains your apps and products; the console inspects it and the CLI configures and deploys it.
  • firebase init generates firebase.json, .firebaserc, and rules and index files to commit.
  • Use --only to deploy one product at a time and avoid surprises.
