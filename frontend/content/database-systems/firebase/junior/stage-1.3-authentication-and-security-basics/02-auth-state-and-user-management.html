Auth State & User Management

The signed-in user changes over time, so your app should react to it with a listener instead of checking once.

§1Observing Auth State

auth.currentUser is null for a moment at startup while the SDK restores the previous session, so checking it immediately gives a false "signed out". Use the listener instead.

import { onAuthStateChanged, signOut } from "firebase/auth";

const unsubscribe = onAuthStateChanged(auth, (user) => {
  if (user) {
    showApp(user.uid, user.displayName);
  } else {
    showLogin();
  }
});

await signOut(auth);

The callback runs once at startup with the restored user (or null) and again on every sign-in or sign-out. Show a loading state until it first fires.

§2Managing the User

import { updateProfile, sendEmailVerification, sendPasswordResetEmail,
         updatePassword, deleteUser } from "firebase/auth";

await updateProfile(auth.currentUser, { displayName: "Ana" });
await sendEmailVerification(auth.currentUser);
await sendPasswordResetEmail(auth, "ana@example.com");

Sensitive actions such as changing a password or deleting the account require a recent sign-in. If the session is old you get auth/requires-recent-login, and you must reauthenticate the user before retrying.

§3Linking Accounts

A common flow starts users as anonymous and upgrades them later, keeping their data under the same uid.

import { linkWithPopup, GoogleAuthProvider, EmailAuthProvider, linkWithCredential } from "firebase/auth";

await linkWithPopup(auth.currentUser, new GoogleAuthProvider());

const cred = EmailAuthProvider.credential("ana@example.com", "s3cret-pass");
await linkWithCredential(auth.currentUser, cred);

If the credential already belongs to another account, linking fails and you must decide how to merge or sign in to the existing account instead.

Auth is asynchronous Treat "who is signed in" as a stream of values over time. Build your UI to render from the latest value, not from a one-time check.

§4Common Mistakes

MistakeWhat HappensFix
Checking currentUser at loadYou treat signed-in users as signed outWait for onAuthStateChanged to fire
Calling sensitive actions without reauthenticatingError: auth/requires-recent-loginReauthenticate, then retry the action
Creating a new account when an anonymous user signs upThe anonymous data is orphanedLink the credential to the existing user
Practice
  1. Add a header that shows the user's name and a sign-out button, driven only by onAuthStateChanged.
  2. Start anonymous, create a document, then link Google sign-in and confirm the uid and document are unchanged.
Key takeaways
  • Use onAuthStateChanged instead of reading currentUser once.
  • Sensitive account changes need a recent sign-in.
  • Linking credentials upgrades an anonymous user without changing the uid.
