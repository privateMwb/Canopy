Your First Security Rules

Security rules are the server-side checks that decide whether each read or write is allowed, and they are the most important thing you write in a Firebase app.

§1Locked Mode and Test Mode

A new Firestore database starts in one of two modes. Locked mode denies every client read and write. Test mode allows everyone to read and write until a date about 30 days away, then locks. Test mode is convenient and dangerous: anyone who finds your project ID can read, change, or delete all your data, and bots do scan for this.

// test mode (never ship this)
allow read, write: if request.time < timestamp.date(2026, 2, 1);

§2match and allow

Rules live in firestore.rules. A match block selects documents by path, and allow statements grant operations when their condition is true.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // anyone signed in can read the public posts
    match /posts/{postId} {
      allow read: if request.auth != null;
    }

    // everything else is denied by default
  }
}

Operations are read (which covers get and list) and write (which covers create, update, and delete). Anything that no rule allows is denied.

§3Rules Are Not Filters

Rules do not filter query results. If a query could return documents the user is not allowed to read, the whole query fails, even if some matching documents would have been allowed. Your query must itself be constrained so that every possible result passes the rule. This surprises almost everyone the first time and is why rules and queries are designed together.

firebase deploy --only firestore:rules
Deny by default Start from nothing and grant only what each feature needs. A rule you did not write cannot be a hole.

§4Common Mistakes

MistakeWhat HappensFix
Leaving test mode onAnyone on the internet can read and wipe the databaseWrite real rules before launching, and set a calendar reminder if you use test mode
Writing allow read, write: if truePublic read and write access to a collectionRequire authentication and ownership instead
Expecting rules to filter a query's resultsThe whole query is rejectedAdd where clauses that match what the rule allows
Practice
  1. Replace test mode with rules that let only signed-in users read the posts collection and nobody write it.
  2. Run a query the rule denies and read the "Missing or insufficient permissions" error.
Key takeaways
  • Rules run on Google's servers and decide every read and write.
  • match selects documents and allow grants operations; everything else is denied.
  • Rules are not filters: queries must be constrained to what the rules allow.
