Monitoring with INFO & SLOWLOG

Redis reports its own health through INFO and records slow commands in SLOWLOG, which together answer most "what is going on?" questions.

§1Reading INFO

INFO                      # everything
INFO memory               # used_memory, fragmentation ratio
INFO stats                # hits, misses, evicted_keys, ops/sec
INFO clients              # connected_clients, blocked_clients
INFO persistence          # last save status

Useful numbers to watch: used_memory against maxmemory, keyspace_hits versus keyspace_misses (your cache hit rate), evicted_keys, connected_clients, and instantaneous_ops_per_sec.

§2Finding Slow Commands

CONFIG SET slowlog-log-slower-than 10000    # microseconds, so 10 ms
SLOWLOG GET 10
SLOWLOG LEN

The slowlog records the command, its arguments, and how long it executed. It does not include time spent waiting in the queue or on the network.

§3Live Views

redis-cli --stat prints rolling statistics. MONITOR streams every command but is expensive, so use it only briefly on a quiet system.

The key insight A falling hit rate, rising evictions, or growing memory usually shows up in INFO hours before users notice. Graph these numbers instead of reading them during an outage.

§4Common Mistakes

MistakeWhat HappensFix
Leaving MONITOR running on productionIt slows the server significantlyUse it briefly, or sample with the slowlog
Ignoring evicted_keysThe cache is silently too smallAlert when it grows and size memory accordingly
Reading the slowlog as total request timeNetwork and queue time are not includedAlso measure latency from the client side
Practice
  1. Lower the slowlog threshold, run a command on a large key, and find it in SLOWLOG GET.
  2. Compute your cache hit rate from keyspace_hits and keyspace_misses.
Key takeaways
  • INFO sections report memory, clients, stats, and persistence state.
  • SLOWLOG captures commands that took long to execute.
  • Chart the key metrics so trends are visible before incidents.
