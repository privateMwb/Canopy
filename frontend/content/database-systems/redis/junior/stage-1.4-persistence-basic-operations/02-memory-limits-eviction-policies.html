Memory Limits & Eviction Policies

Redis stores everything in RAM, so you set a limit and tell it what to do when that limit is reached.

§1Setting a Limit

maxmemory 2gb
maxmemory-policy allkeys-lru

Without maxmemory, Redis grows until the operating system kills it. Leave headroom: persistence forks and replication buffers use extra memory beyond the data itself.

§2Eviction Policies

  • noeviction: refuse writes that need memory (reads still work). This is the default.
  • allkeys-lru: evict the least recently used key, any key. Good for pure caches.
  • allkeys-lfu: evict the least frequently used key. Good when some keys are hot long-term.
  • volatile-lru, volatile-lfu, volatile-ttl: only evict keys that have a TTL.
  • allkeys-random, volatile-random: random choices.
CONFIG SET maxmemory-policy allkeys-lfu
INFO memory
INFO stats                # look at evicted_keys

§3Approximate by Design

Redis does not track exact LRU order. It samples a handful of keys and evicts the best candidate, which is much cheaper and close enough.

Gotcha A volatile-* policy with no keys that have a TTL behaves like noeviction, and writes start failing with an out-of-memory error.

§4Common Mistakes

MistakeWhat HappensFix
No maxmemory setThe process grows until the OS kills itSet a limit with headroom
Using noeviction for a cacheWrites fail when memory fillsChoose an allkeys-* policy
Using volatile-lru when nothing has a TTLNothing can be evictedAdd TTLs, or use an allkeys-* policy
Practice
  1. Set maxmemory to 10 MB, load keys until eviction starts, and watch evicted_keys in INFO stats.
  2. Switch between allkeys-lru and noeviction and note how the same write behaves.
Key takeaways
  • Set maxmemory and a policy, and leave headroom beyond the data.
  • Use allkeys-lru or allkeys-lfu for caches, and noeviction where data must not vanish.
  • Eviction is sampled, so it is approximate.
