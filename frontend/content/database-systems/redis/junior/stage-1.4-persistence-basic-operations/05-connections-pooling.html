Connections & Pooling

Each client holds a connection, so pooling, timeouts, and limits decide whether a traffic spike is smooth or catastrophic.

§1Client Limits

Redis has a cap on simultaneous clients, 10,000 by default (maxclients). Every web worker, job worker, and script holds at least one.

INFO clients               # connected_clients
CLIENT LIST                # who is connected, from where, and idle time
CONFIG GET maxclients

§2Pooling and Reuse

A pool keeps a bounded number of open connections that requests borrow and return. Pool size should match concurrency, not request volume, because commands are fast and can share a connection.

const redis = createClient({ url, socket: { connectTimeout: 2000 } });
redis.on("error", (e) => log(e));

§3Connection Storms

If Redis restarts, thousands of clients reconnect at once. Use exponential backoff with jitter in clients so reconnection attempts spread out. Also set timeout (idle client timeout) and TCP keepalives so dead connections are cleaned up.

timeout 300
tcp-keepalive 300

§4Count Before You Scale

Number of app instances multiplied by pool size per instance must stay well below maxclients. Doubling your servers can silently double your connections.

Gotcha Blocking commands such as BLPOP hold a connection for the whole wait, so a worker pool that blocks needs one connection per waiting worker.

§5Common Mistakes

MistakeWhat HappensFix
A new connection per requestSlow requests and connection exhaustionReuse a pooled or shared client
Retrying instantly in a tight loop after a failureA reconnect storm keeps Redis downBack off exponentially and add jitter
Never setting timeoutsDead clients hold connections foreverConfigure timeout and client-side timeouts
Practice
  1. Run 200 connections against a test server and watch connected_clients and CLIENT LIST.
  2. Calculate the total connections for 40 app instances with a pool of 10 and 20 job workers each holding 2.
Key takeaways
  • Reuse connections through a shared client or a bounded pool.
  • Add backoff with jitter so reconnections do not stampede.
  • Total connections across all instances must stay below maxclients.
