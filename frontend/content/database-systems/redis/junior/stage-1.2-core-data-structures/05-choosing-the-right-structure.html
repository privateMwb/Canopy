Choosing the Right Structure

Choosing a structure means starting from the question you will ask, because a wrong choice shows up later as slow commands or wasted memory.

§1Start From the Access Pattern

  • Do I need a FIFO queue or a stack? A list.
  • Do I need an object with several fields I update separately? A hash.
  • Do I need "is X in this group?" or "what do these groups share?" A set.
  • Do I need ranking, top-N, or "everything between two values"? A sorted set.
  • Do I need a single value, a counter, or a cached blob? A string.

The same data can be modeled several ways. Ten thousand "recent items" could be a list per user, a sorted set scored by time, or a string holding JSON. Each answers different questions well.

§2The Cost of a Wrong Choice

# Wrong: membership check in a list scans every element
LPOS blocked:ips "203.0.113.5"
# Right: constant time in a set
SISMEMBER blocked:ips "203.0.113.5"

Using a list for membership, a string for an object you update field by field, or a set where order matters does not fail at once. It works in testing and then slows down, wastes memory, or loses updates at scale.

The key insight Write the queries first, then pick the structure. If you cannot say what question a key answers, it is not ready to be modeled.

§3Sometimes Combine Them

A common design uses a hash for the object and a sorted set as an index over it: HSET product:7 ... holds details, ZADD products:by_price 9.99 7 lets you range by price, and you fetch the hashes for the ids returned.

§4Common Mistakes

MistakeWhat HappensFix
Putting an entire object as JSON in a string and updating one fieldRead-modify-write races and wasted bandwidthUse a hash
One big list used as a lookup tableEvery lookup is linearUse a hash or set keyed by the lookup value
Sorting in the client after fetching everythingLarge transfers and slow responsesUse a sorted set so Redis keeps the order
Practice
  1. For a "top 10 most viewed articles this week" feature, choose a structure and write the commands for recording a view and reading the top 10.
  2. Model a friends list with a set and a "recently active friends" view with a sorted set, and explain why one structure alone is not enough.
Key takeaways
  • Pick the structure from the question you will ask, not from the shape of the data.
  • A wrong structure works at small scale and fails quietly at large scale.
  • Combine structures: a hash for details and a sorted set or set as an index.
