What Redis Is & When to Use It

Redis keeps its data in memory and exposes real data structures, which makes it very fast and shapes what it is good at.

§1An In-Memory Data Structure Server

Redis is a server that holds data in RAM and answers commands over a network connection. Unlike a plain key-value cache, the values are data structures: strings, lists, hashes, sets, sorted sets, streams, and more, each with its own commands.

SET greeting "hello"
GET greeting              # "hello"
LPUSH queue job1 job2     # a list
ZADD scores 120 alice     # a sorted set

Because the data lives in memory, a typical command takes well under a millisecond. Because commands run one at a time on a single thread, each one is atomic.

§2What It Is Good At

  • Caching results that are expensive to compute or fetch.
  • Sessions and tokens that expire on their own.
  • Counters and rate limits that many clients update at once.
  • Queues, leaderboards, and live feeds that map onto lists, sorted sets, and streams.

§3What It Is Not

Memory costs more than disk, so Redis is rarely the right home for a large dataset you need to query in flexible ways. It has no joins and no ad-hoc queries; you decide the access pattern up front and pick the structure that serves it. It can persist data to disk, but its default role is a fast companion to a primary database, not a replacement.

The key insight Redis is not "a faster database." It is a set of data structures with network access, and the speed comes from keeping them in memory and keeping the commands simple.

§4Common Mistakes

MistakeWhat HappensFix
Treating Redis as the only copy of important dataA restart or failover can lose recent writesKeep the source of truth in a durable database unless you have configured and tested persistence
Storing a huge dataset because "it's fast"Memory cost grows and eviction starts removing dataCache the hot subset and set a memory limit
Expecting SQL-style queriesYou can only look up by key or by structureDesign the key and structure around the question you will ask
Practice
  1. List three features of an application you know and decide which would benefit from Redis and which should stay in a regular database.
  2. Explain in two sentences why a single-threaded server can still handle many clients quickly.
Key takeaways
  • Redis is an in-memory server whose values are real data structures.
  • It excels at caches, counters, sessions, queues, and rankings.
  • It is usually a companion to a durable database, not a replacement for one.
