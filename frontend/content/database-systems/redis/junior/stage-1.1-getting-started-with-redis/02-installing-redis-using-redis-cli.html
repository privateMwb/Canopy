Installing Redis & Using redis-cli

You can run Redis with a single command and explore it from redis-cli, which is the fastest way to learn what every command does.

§1Starting a Server

On Linux and macOS you can install Redis from a package manager, or run it in a container, which keeps your machine clean.

docker run --name redis -p 6379:6379 -d redis:7
redis-cli ping            # PONG

Redis listens on port 6379 by default. PONG means the server is up and you can reach it.

§2Using redis-cli

redis-cli with no arguments opens an interactive session. You can also pass a single command.

SET user:1:name "Ada"
GET user:1:name
EXISTS user:1:name        # 1 means yes, 0 means no
DEL user:1:name           # returns how many keys were removed
TYPE greeting             # string, list, hash, set, zset, stream

Try HELP SET for built-in documentation of any command, including its syntax and the version it was added in.

§3Exploring Keys Safely

KEYS * lists every key, but it walks the whole keyspace in one blocking call. On a big production instance that stalls everything else. Use SCAN instead, which returns a few keys at a time with a cursor.

SCAN 0 MATCH user:* COUNT 100
# returns a new cursor and a batch of keys; repeat until the cursor is 0
DBSIZE                    # number of keys in the current database

Redis also has numbered databases (0 to 15 by default), chosen with SELECT n. Most teams ignore them and use key prefixes instead.

Gotcha FLUSHALL and FLUSHDB delete everything without asking. Never run them on a shared or production instance by habit.

§4Common Mistakes

MistakeWhat HappensFix
Running KEYS * on a production serverThe server blocks while it scans every keyUse SCAN with a MATCH pattern
Forgetting -p when the port is mapped differentlyredis-cli cannot connectPass -h and -p, or use a connection URL
Using FLUSHALL to "clean up"Every key in every database is goneDelete by prefix with SCAN and DEL, or use a throwaway instance for experiments
Practice
  1. Start a Redis container, set five keys, and list them with SCAN. Then check each one with TYPE.
  2. Run HELP SET and HELP GET, and note one option of SET you had not seen.
Key takeaways
  • Redis listens on port 6379, and redis-cli ping confirms it is reachable.
  • TYPE, EXISTS, DEL, and HELP cover most exploration needs.
  • Use SCAN rather than KEYS on anything that is not a toy.
