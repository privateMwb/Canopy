RDB, Forking & Latency

Redis snapshots by forking, which is cheap in theory and can stall the server in practice when memory is large.

§1How a Snapshot Works

BGSAVE forks a child process. Parent and child share memory pages using copy-on-write: when the parent modifies a page after the fork, the operating system copies that page for the child. The child writes the frozen view to disk while the parent keeps serving clients.

BGSAVE
INFO persistence         # rdb_bgsave_in_progress, rdb_last_bgsave_time_sec
LASTSAVE                 # unix time of last successful save
INFO stats               # latest_fork_usec: how long the fork blocked

§2Where Latency Comes From

  • The fork itself copies the page tables, which takes longer the more memory the process uses. Large instances can pause for tens or hundreds of milliseconds.
  • Copy-on-write needs extra memory proportional to how many pages the parent changes during the snapshot. A write-heavy workload may use close to double the memory.
  • Transparent Huge Pages on Linux make copy-on-write copy 2 MB at a time and cause long stalls. Disable them as Redis recommends.
echo never > /sys/kernel/mm/transparent_hugepage/enabled

Also keep vm.overcommit_memory = 1 so the fork does not fail on a loaded host.

§3Planning

Size memory with headroom for the fork. Schedule heavy snapshots away from peak traffic, or take them from a replica.

The key insight A snapshot is not free. The cost is paid as fork latency and as extra memory while it runs.

§4Common Mistakes

MistakeWhat HappensFix
Using 90% of RAM for dataThe fork and copy-on-write run out of memoryLeave generous headroom
THP left enabledRandom multi-second latency spikesDisable transparent huge pages
Snapshotting on the primary at peak timeUsers see slow responsesSnapshot on a replica or off-peak
Practice
  1. Load a few GB of data, run BGSAVE under write load, and record latest_fork_usec and peak memory.
  2. Check the THP and overcommit_memory settings on a Linux host.
Key takeaways
  • BGSAVE forks and relies on copy-on-write.
  • Fork time grows with memory size, and writes during the snapshot add memory.
  • Disable THP, set overcommit, and leave headroom.
