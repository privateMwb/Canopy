TTL Design & Jitter

A TTL is a staleness budget, and spreading expirations with jitter keeps thousands of keys from vanishing in the same second.

§1Picking a Lifetime

Base it on three things: how stale the data may be, how expensive a miss is, and how often it changes. Expensive and rarely changing data deserves a long TTL; cheap or fast-changing data a short one. Long TTLs also raise memory use.

  • Static reference data: hours or days.
  • Product details: minutes to an hour.
  • Feeds and counters: seconds.
  • "Not found" markers: short, such as 30 to 60 seconds.

§2Synchronized Expiry

If you warm a million keys at once with EX 3600, they all expire together and the database receives a million misses in the same moment.

const jitter = Math.floor(Math.random() * 300);          // 0 to 5 minutes extra
await redis.set(key, value, { EX: 3600 + jitter });

Adding 10% to 20% random variation spreads the expiry over a window, so refills trickle in.

§3Watching Expirations

INFO stats                # expired_keys, expired_stale_perc
OBJECT FREQ cache:product:77     # access frequency with an LFU policy

Redis removes expired keys lazily when touched and with a background sample, so memory can briefly hold keys that are already expired.

The key insight Choose TTLs per kind of data, add jitter at write time, and revisit them when you see hit rate and database load.

§4Common Mistakes

MistakeWhat HappensFix
One TTL for everythingSome data is stale, other data is refetched constantlySet TTLs by data type
Bulk-loading with identical TTLsA wave of simultaneous missesAdd random jitter
Assuming expired keys vanish instantlyThey may linger until sampled or accessedDo not depend on exact expiry timing
Practice
  1. Define a TTL table for five kinds of data in an app you know and justify each.
  2. Warm 10,000 keys with and without jitter and graph expirations per second.
Key takeaways
  • Set TTLs from staleness tolerance, cost of a miss, and change rate.
  • Add jitter so bulk-loaded keys do not expire together.
  • Expiration is not instantaneous and should not be timed precisely.
