Memory Management & Fragmentation

Redis memory is more than your data: every key has overhead, and the allocator can hold memory that Redis is no longer using.

§1Per-Key Overhead

Every key carries a dictionary entry, an object header, and an expiry entry if it has a TTL. Small keys can use 50 to 100 bytes beyond their data, so ten million tiny keys are far costlier than their payload suggests.

MEMORY USAGE user:1001          # bytes for this key and value
MEMORY STATS
MEMORY DOCTOR                   # plain-language hints
INFO memory

§2Fragmentation

mem_fragmentation_ratio is resident set size divided by logical used memory. A ratio far above 1.5 means the allocator (usually jemalloc) holds freed pages that are scattered; below 1 means the system is swapping, which is serious.

CONFIG SET activedefrag yes     # online defragmentation, uses some CPU
MEMORY PURGE                    # ask the allocator to release memory

§3Finding Where It Goes

redis-cli --bigkeys and --memkeys sample the keyspace to find the largest keys by element count or bytes. MEMORY USAGE with SAMPLES 0 gives an exact figure for a nested key.

redis-cli --memkeys
redis-cli --bigkeys -i 0.1       # throttle so it does not hurt production

§4Common Culprits

Unbounded lists and streams, keys with no TTL, large JSON strings, long key names, and caches storing data nobody reads.

The key insight Memory problems are almost always a few keys or patterns. Find them with sampling before changing configuration.

§5Common Mistakes

MistakeWhat HappensFix
Looking only at used_memoryRSS and fragmentation are hiddenCompare used memory, RSS, and the ratio
Running --bigkeys at full speed in productionIt adds loadThrottle with -i
Ignoring unbounded structuresMemory creeps up until eviction or OOMCap lists and streams, and set TTLs
Practice
  1. Run --memkeys on a test dataset, find the largest pattern, and propose a fix.
  2. Create fragmentation by deleting every other key and observe the ratio with and without active defrag.
Key takeaways
  • Each key has fixed overhead beyond its data.
  • Fragmentation is RSS versus used memory, and below 1 means swapping.
  • Sample the keyspace to find the few keys that dominate memory.
