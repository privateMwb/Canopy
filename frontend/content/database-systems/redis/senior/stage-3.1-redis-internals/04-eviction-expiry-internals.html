Eviction & Expiry Internals

Redis expires keys lazily and by sampling, and evicts by sampling too, so both are approximations with real costs for big keys.

§1How Expiry Works

Two mechanisms run together. Lazy expiry checks a key's TTL when it is accessed and removes it if due. Active expiry runs about ten times a second: it samples keys that have a TTL, deletes the expired ones, and repeats if more than about a quarter of the sample was expired.

INFO stats           # expired_keys, expire_cycle_cpu_milliseconds

If millions of keys expire at the same instant, the active cycle can consume noticeable CPU and add latency.

§2How Eviction Works

When memory exceeds maxmemory, Redis samples a few keys (maxmemory-samples, default 5) and evicts the best candidate under the policy, repeating until it is under the limit. More samples approximate true LRU or LFU more closely at slightly higher CPU cost.

maxmemory-samples 10
lfu-log-factor 10
lfu-decay-time 1

§3Big Keys Hurt

Evicting or expiring a huge key frees a lot of memory at once and can block the loop. Lazy-free settings move this work to a background thread.

lazyfree-lazy-eviction yes
lazyfree-lazy-expire yes
lazyfree-lazy-server-del yes

Prefer many moderate keys to a few giant ones, so each removal is cheap.

The key insight Expiry and eviction are sampling algorithms. Their cost depends on the distribution of your TTLs and the size of your keys.

§4Common Mistakes

MistakeWhat HappensFix
Mass expiry at one secondCPU spike and latencyAdd jitter to TTLs
Giant collections as single keysDeleting or evicting one blocks the loopSplit into buckets and enable lazy freeing
Expecting exact LRUEviction is approximateRaise maxmemory-samples if accuracy matters
Practice
  1. Create 2 million keys with the same TTL and measure latency when they expire, then repeat with jitter.
  2. Enable lazy freeing and compare latency when a very large key is evicted.
Key takeaways
  • Expiry is lazy plus a sampled active cycle.
  • Eviction samples candidates, controlled by maxmemory-samples.
  • Big keys and synchronized TTLs create latency spikes.
