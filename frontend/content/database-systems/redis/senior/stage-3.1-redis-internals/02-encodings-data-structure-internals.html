Encodings & Data Structure Internals

Redis stores small collections in compact encodings and switches to heavier structures as they grow, which explains much of its memory use.

§1Seeing the Encoding

OBJECT ENCODING mykey
# int | embstr | raw (strings)
# listpack | quicklist (lists)  | listpack | hashtable (hashes)
# listpack | skiplist (zsets)   | intset | listpack | hashtable (sets)

§2Compact Forms

Small hashes, sorted sets, and (in recent versions) lists and some sets use a listpack: a single contiguous array of entries with very little overhead. Lookups scan it, which is fast when it is small. A set containing only integers uses an intset, a sorted array of integers.

hash-max-listpack-entries 128
hash-max-listpack-value 64
zset-max-listpack-entries 128

§3Heavy Forms

Beyond those limits, a hash becomes a hash table and a sorted set a skiplist plus hash table, which give constant or logarithmic operations but use several times more memory per element. Lists become a quicklist, a linked list of listpacks.

§4Why It Matters

Thousands of small hashes cost far less than the same data as millions of separate keys, and raising a limit can save memory at the price of slower per-key operations. Check with MEMORY USAGE key before and after.

HSET h f1 v1
OBJECT ENCODING h        # listpack
MEMORY USAGE h
The key insight Encoding is chosen by size thresholds, and crossing one can double a key's memory overnight. Know your thresholds before you model data.

§5Common Mistakes

MistakeWhat HappensFix
Assuming memory use is linear in element countA threshold crossing causes a jumpTest sizes around the limits
Raising listpack limits to huge valuesEvery operation scans a long arrayKeep limits modest and benchmark
One key per tiny objectPer-key overhead dominatesGroup small objects into hashes
Practice
  1. Grow a hash from 10 to 1,000 fields and record the encoding and MEMORY USAGE at each step.
  2. Store 100,000 small values as strings and as fields in bucketed hashes, and compare memory.
Key takeaways
  • OBJECT ENCODING shows how a key is stored internally.
  • Small collections use compact listpack or intset encodings.
  • Crossing thresholds switches to larger structures and raises memory use.
