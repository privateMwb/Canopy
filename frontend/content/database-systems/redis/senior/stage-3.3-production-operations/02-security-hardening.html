Security Hardening

Hardening Redis means closing the network, using least-privilege ACLs and TLS, and disabling commands that nobody should run.

§1Network Isolation

Private subnet, security groups allowing only application hosts, no public IP. Use protected mode and bind to specific interfaces.

bind 10.0.1.12
protected-mode yes

§2ACL Design

Create a user per service with only the commands and key patterns it needs. Disable the default user or give it a strong password.

ACL SETUSER cache-svc on >strongpass ~cache:* &none +@read +@write -@dangerous
ACL SETUSER admin on >adminpass ~* &* +@all
ACL SETUSER default off
ACL SAVE                         # persist to the ACL file

-@dangerous removes commands such as FLUSHALL, KEYS, CONFIG, and DEBUG. Store users in an ACL file (aclfile) so they survive restarts.

§3TLS

tls-port 6380
port 0                            # disable plaintext
tls-cert-file /etc/redis/redis.crt
tls-key-file  /etc/redis/redis.key
tls-ca-cert-file /etc/redis/ca.crt
tls-auth-clients yes

Encrypt client connections and replication links (tls-replication yes, tls-cluster yes).

§4Other Controls

Run as a non-root user, restrict file permissions on the config and data directory, rename or ACL-block CONFIG, keep logs free of secrets, and patch promptly. Audit with ACL LOG to see denied commands.

ACL LOG 10
The key insight Assume the network will be breached and make each credential nearly useless on its own.

§5Common Mistakes

MistakeWhat HappensFix
Leaving the default user with no passwordFull access for anyone who connectsDisable it or set a strong password
TLS on the client port but plaintext replicationData crosses the network in the clearEnable TLS for replication and cluster links
One +@all user for every serviceA single leak is a total compromiseUse per-service ACL users
Practice
  1. Create ACL users for a cache service and a read-only dashboard, then try forbidden commands with each.
  2. Enable TLS on a test instance and connect with a client that requires it.
Key takeaways
  • Isolate Redis on a private network with strict access rules.
  • Use per-service ACL users and block dangerous commands.
  • Encrypt client, replication, and cluster traffic with TLS.
