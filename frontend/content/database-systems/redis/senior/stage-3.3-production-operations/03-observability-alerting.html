Observability & Alerting

The best Redis alerts fire on trends that predict a problem, such as memory growth, eviction, and replication lag, before users feel it.

§1Core Metrics

  • Memory: used_memory versus maxmemory, fragmentation ratio, evicted_keys.
  • Throughput and latency: instantaneous_ops_per_sec, slowlog entries, latency events, client-side p99.
  • Clients: connected_clients, blocked_clients, rejected_connections.
  • Persistence: rdb_last_bgsave_status, aof_last_write_status, aof_delayed_fsync, latest_fork_usec.
  • Replication: master_link_status, master_repl_offset gap, replica lag.
  • Effectiveness: keyspace_hits and keyspace_misses for hit rate.

§2Collecting

redis_exporter --redis.addr redis://localhost:6379      # Prometheus exporter

Send INFO metrics to your monitoring system and graph them. Add client-side metrics as well, since server numbers do not show network or pool problems.

§3Alerts That Help

  • Memory above 80% of maxmemory.
  • Evictions growing on a datastore (where they should be zero).
  • Replica disconnected or lag above a threshold.
  • Last save failed, or the AOF reports write errors.
  • Rejected connections above zero.
  • Hit rate drops sharply (a deploy may have changed keys).

§4Reducing Noise

Alert on symptoms with clear actions, and write a runbook link into every alert.

The key insight A graph with no alert is a dashboard, and an alert with no action is noise. Pair each metric with what a responder should do.

§5Common Mistakes

MistakeWhat HappensFix
Alerting on raw CPU onlyThe main thread can be saturated while total CPU looks lowWatch latency and ops per second as well
No alert on persistence failureYou discover broken backups during an incidentAlert on save status
Alerting on every eviction on a cacheConstant noiseAlert on an abnormal eviction rate
Practice
  1. Set up an exporter and dashboard with the metrics above, then trigger each alert on a test instance.
  2. Write a one-paragraph runbook entry for "memory above 80%".
Key takeaways
  • Track memory, latency, clients, persistence, replication, and hit rate.
  • Alert on predictive symptoms and attach a runbook.
  • Combine server metrics with client-side measurements.
