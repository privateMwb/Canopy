Upgrades & Rolling Changes

Upgrading Redis safely means reading the release notes, testing with real traffic, and rolling through replicas before touching the primary.

§1Before You Start

Read the release notes and the list of breaking changes, check client library compatibility, and confirm that your modules, scripts, and configuration work. Test on a staging copy with a realistic dataset, including redis-check-rdb on a production backup.

§2Rolling Upgrade With Replication

1. Upgrade a replica, restart it, and confirm it resyncs.

2. Repeat for the other replicas, one at a time.

3. Trigger a controlled failover so an upgraded replica becomes primary.

4. Upgrade the old primary, which rejoins as a replica.

SENTINEL failover mymaster           # with Sentinel
CLUSTER FAILOVER                     # in Cluster, run on the replica

Replicas can usually run a newer minor version than their primary, but not the reverse in general. Confirm in the notes for your versions.

§3Cluster

Upgrade replicas first, then fail each primary over to its upgraded replica, one shard at a time, waiting for cluster_state:ok between steps.

§4Rollback

Keep the previous binary and a recent backup. Rolling back after writes with new data formats may not be possible, so decide the point of no return in advance.

The key insight A rolling change keeps the service available but gives you a window where two versions coexist. Test that mixed state.

§5Common Mistakes

MistakeWhat HappensFix
Upgrading the primary firstReplicas on an older version may not followUpgrade replicas, then fail over
Skipping several major versionsCompatibility surprisesRead the notes for each step, and test the path
No rollback planAn incident has no safe exitKeep binaries, backups, and a documented decision point
Practice
  1. Perform a rolling upgrade on a test replica set while a load generator runs and record the errors.
  2. Write a rollback checklist for a major version upgrade.
Key takeaways
  • Test upgrades on realistic data before production.
  • Upgrade replicas first, fail over, then upgrade the old primary.
  • Define rollback and the point of no return in advance.
