Cluster-Aware Clients

A cluster client keeps its own slot map, follows redirects, and refreshes its view of the cluster when it changes.

§1What a Cluster-Aware Client Does

It connects to a few seed nodes, calls CLUSTER SLOTS (or CLUSTER SHARDS) to build a map of slot ranges to nodes, hashes each key locally, and sends the command straight to the owning node.

import { createCluster } from "redis";
const cluster = createCluster({
  rootNodes: [{ url: "redis://10.0.0.1:6379" }, { url: "redis://10.0.0.2:6379" }],
  defaults: { password: process.env.REDIS_PASSWORD },
});
await cluster.connect();
await cluster.set("{user:1}:name", "Ada");

§2Redirections and Refresh

On MOVED, the client updates its map and retries. On ASK, it retries once at the target without updating the map. Good clients refresh the map in the background and after connection errors.

§3Pipelines and Scripts

A pipeline across many keys is split by node and sent in parallel, which costs more than one round trip. Multi-key commands must still satisfy the same-slot rule. Reading from replicas is possible with READONLY or a client option, with the usual staleness trade-off.

§4Failures From the Client Side

During a failover, clients see connection errors and CLUSTERDOWN replies. Use retries with backoff and idempotent operations, and set sensible timeouts so the application degrades predictably.

Gotcha Some libraries only handle MOVED for single commands, not inside pipelines or scripts. Test those paths against a live resharding.

§5Common Mistakes

MistakeWhat HappensFix
Giving the client only one seed addressIf it is down at startup, the client cannot connectList several nodes
No retry on MOVED or CLUSTERDOWNErrors surface during every failoverUse a client with redirect and retry handling
Large cross-node pipelines assumed to be one round tripLatency is higher than expectedGroup keys by slot or node
Practice
  1. Run a load test against a cluster while resharding and count client errors.
  2. Write a client wrapper that retries once on connection loss and logs redirects.
Key takeaways
  • Cluster clients hold a slot map and route each command themselves.
  • MOVED updates the map, and ASK is a one-time redirect.
  • Plan retries and backoff for failover windows.
