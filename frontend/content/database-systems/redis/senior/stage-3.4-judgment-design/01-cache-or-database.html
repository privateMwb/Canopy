Cache or Database?

Whether Redis is a cache or a database depends on what you lose when it loses data, so decide that before you decide where to put anything.

§1The Question to Ask

"If this key vanished right now, what would happen?" For a cached product page, nothing important: it is rebuilt. For a session, a user logs in again. For an order, a payment, or a balance, the answer is a serious problem.

§2Durable Enough?

Even with AOF everysec and replication, Redis can lose recent writes on failover or crash, and noeviction is needed to avoid eviction. Persistence settings reduce loss, but a general-purpose Redis deployment is typically not as strong as a database with synchronous replication and transaction logging.

WAIT 2 50                # waits for replicas, but is not a guarantee of durability by itself
WAITAOF 1 1 100          # wait for local and replica AOF fsync (Redis 7.2+)

§3Reasonable Uses as Primary Store

Data that is derived (can be rebuilt), short-lived (sessions, tokens), approximate (analytics counters), or self-correcting (presence). Rate-limiter state, feature-flag caches, and leaderboards that can be recomputed all fit.

§4Unsafe Uses

Financial records, inventory of record, anything legally required to be kept, and the only copy of user-generated content.

§5A Safe Pattern

Keep the source of truth in a database, write the cache, and make the system correct when Redis is empty. If Redis is the only home for something, treat it with database-grade backups, replication, and monitoring, and write down the data you accept losing.

The key insight Persistence settings are not a promise. Decide by consequence of loss, not by how fast Redis is.

§6Common Mistakes

MistakeWhat HappensFix
Storing orders only in RedisA failover loses paid ordersKeep orders in a durable database
Trusting WAIT as a durability guaranteeReplicas can still fail with the primaryCombine with persistence and accept the remaining risk explicitly
No "rebuild from source" pathA flush is an outageBuild and test a cache warm-up
Practice
  1. Classify twelve data items from an app as cache, tolerable-loss store, or must-be-durable, and justify each.
  2. Describe how you would rebuild your Redis contents after losing everything.
Key takeaways
  • Decide by the consequence of losing the data.
  • Redis can be primary for derived, short-lived, or approximate data.
  • Keep irreplaceable records in a database built for durability.
