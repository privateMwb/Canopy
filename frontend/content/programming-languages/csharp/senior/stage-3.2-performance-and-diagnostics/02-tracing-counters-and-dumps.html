Tracing, Counters & Dumps

When a service misbehaves in production, you can't attach a debugger. The .NET diagnostic tools observe a live process with little overhead.

§1Counters: Is Something Wrong Right Now?

dotnet tool install --global dotnet-counters
dotnet-counters ps                                    // list .NET processes and their PIDs
dotnet-counters monitor --process-id 1234 \
  --counters System.Runtime,Microsoft.AspNetCore.Hosting

Counters are cheap, live metrics. The ones to read first:

CounterWhat it tells you
CPU UsageIs the process compute-bound?
GC Heap Size, Gen 2 Size, LOH SizeIs memory growing, and where?
Gen 0/1/2 GC Count, Allocation RateIs allocation pressure driving collections?
ThreadPool Thread Count, Queue Length, Completed ItemsAre requests waiting for threads (starvation)?
Exception CountAre failures being thrown and swallowed at a high rate?
Requests per second, Current RequestsThroughput and concurrency from ASP.NET Core

Counters are the triage step: they tell you which kind of problem you have (memory, CPU, threads) so you know which tool to use next.

§2Traces: Where Is the Time Going?

dotnet tool install --global dotnet-trace
dotnet-trace collect --process-id 1234 --duration 00:00:30    // sample CPU for 30 s
dotnet-trace collect -p 1234 --profile gc-verbose              // GC and allocation events

dotnet-trace records a .nettrace file of runtime events and CPU samples. Open it in PerfView, Visual Studio, or convert it with --format speedscope for a flame graph. A flame graph shows which call stacks consume the most time, and the widest frames are where to look. Collect during the problem, not before or after, and capture long enough (30 to 60 seconds) to include the slow behavior.

§3Dumps: What Is the Process Holding Right Now?

dotnet tool install --global dotnet-dump
dotnet-dump collect --process-id 1234                // snapshot of the process (a large file)
dotnet-dump analyze core_20261023_101500

> dumpheap -stat                  // object counts and sizes by type: who owns the memory?
> gcroot 000001a2b3c4d5e8         // why is this object still alive? shows the reference path
> clrthreads                      // list managed threads
> setthread 12
> clrstack                        // that thread's managed stack: what is it doing or waiting on?
> syncblk                         // which locks are held, and by which threads

A dump is a frozen snapshot: you can inspect every object and every thread's stack. Use dumpheap -stat to find the types with suspicious counts (50,000 instances of OrderCache.Entry), then gcroot to see what's keeping a sample object alive. For hangs, clrstack on each thread shows where they're blocked, so a pile of threads all waiting in the same method points at a lock or at .Result. Dumps contain whatever was in memory, including secrets, so handle them as sensitive data. In containers, you can install the tools in a separate debug container or enable collection through the diagnostic port.

The key insight Counters tell you what kind of problem, traces tell you where time goes, and dumps tell you what the process is holding or stuck on. Use them in that order.

§4Common Mistakes

MistakeWhat HappensFix
Collecting a trace when the problem isn't happeningA clean trace that shows nothingCapture during the incident, or script collection from an alert
Jumping straight to a dumpA huge file and no directionRead counters first to learn whether it's memory, CPU, or threads
Sharing dumps casuallyThey contain secrets and customer dataTreat them as sensitive: restrict access and delete them when done
Practice
  1. Run a simple service, watch it with dotnet-counters monitor, and generate load. Which counters move?
  2. Take a dump of a process that has a growing static list, then use dumpheap -stat and gcroot to find what's holding the memory.
Key takeaways
  • dotnet-counters shows live health metrics for triage.
  • dotnet-trace samples CPU and runtime events, and flame graphs show where time goes.
  • dotnet-dump inspects heap contents and thread stacks to explain leaks and hangs.
