Cancellation, IAsyncEnumerable & Channels

Long-running async work should be cancellable, results can be streamed instead of buffered, and channels connect producers to consumers safely.

§1Cancellation

static async Task<string> FetchAsync(HttpClient http, string url, CancellationToken ct)
{
    var response = await http.GetAsync(url, ct);        // pass the token down
    return await response.Content.ReadAsStringAsync(ct);
}

using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));   // auto-cancel after 5 s
try
{
    var text = await FetchAsync(http, url, cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("Cancelled or timed out.");
}

Cancellation is cooperative. The caller owns a CancellationTokenSource and passes its Token down; each operation checks it and throws OperationCanceledException when cancelled. Your own loops should call ct.ThrowIfCancellationRequested(). Every async method that does meaningful work should accept a token as its last parameter.

§2Streaming with IAsyncEnumerable

static async IAsyncEnumerable<string> ReadLinesAsync(
    string path, [EnumeratorCancellation] CancellationToken ct = default)
{
    using var reader = new StreamReader(path);
    string? line;
    while ((line = await reader.ReadLineAsync(ct)) is not null)
        yield return line;
}

await foreach (var line in ReadLinesAsync("big.log", ct))
    Console.WriteLine(line);

IAsyncEnumerable<T> is the async version of yield: the producer can await between items, and the consumer uses await foreach. It lets you start processing the first row of a database query, or the first page of an API, before the last one has arrived, without holding everything in memory.

§3Channels: Producer-Consumer Pipelines

var channel = Channel.CreateBounded<int>(capacity: 100);   // backpressure when full

var producer = Task.Run(async () =>
{
    for (int i = 0; i < 1000; i++)
        await channel.Writer.WriteAsync(i, ct);       // waits if the channel is full
    channel.Writer.Complete();                         // signal: no more items
});

var consumer = Task.Run(async () =>
{
    await foreach (var item in channel.Reader.ReadAllAsync(ct))
        Process(item);
});

await Task.WhenAll(producer, consumer);

A Channel<T> is a thread-safe, async-friendly queue. A bounded channel makes fast producers wait for slow consumers (backpressure) instead of filling memory. Calling Complete() ends the consumers' loops cleanly. Start several consumers on the same reader to process items in parallel.

The key insight Cancellation, streaming, and bounded queues share one idea: work must be able to stop, flow, and push back. Without them, a slow dependency becomes a runaway process.

§4Common Mistakes

MistakeWhat HappensFix
Accepting a CancellationToken but never passing it downCancellation is ignored and the operation keeps runningPass the token to every async call and check it in loops
An unbounded channel with a fast producerMemory grows until the process failsUse a bounded channel to apply backpressure
Forgetting Writer.Complete()Consumers wait forever and the program hangsComplete the writer in a finally block, or on error with Complete(ex)
Practice
  1. Write a downloader method that takes a CancellationToken, cancels after 2 seconds, and returns cleanly. Verify with a slow endpoint or Task.Delay.
  2. Build a producer that writes numbers to a bounded channel with capacity 5 and two consumers that sleep 100 ms each. Log when the producer has to wait.
Key takeaways
  • Cancellation is cooperative: pass the token down and handle OperationCanceledException.
  • IAsyncEnumerable streams results with await foreach and no buffering.
  • Bounded channels connect producers and consumers with backpressure; always complete the writer.
