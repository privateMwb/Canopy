Minimal APIs & Controllers

ASP.NET Core maps HTTP requests to C# code. Minimal APIs do it with a few lines, and controllers do it with classes, and both rely on the same routing and binding.

§1A Minimal API

dotnet new web -o Shop.Api
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Hello");
app.MapGet("/products/{id:int}", (int id) => Results.Ok(new { id, name = "Pen" }));
app.MapPost("/products", (CreateProduct body) =>
    Results.Created($"/products/{Guid.NewGuid()}", body));

app.Run();

record CreateProduct(string Name, decimal Price);

MapGet, MapPost, MapPut, and MapDelete bind a route pattern to a handler. Model binding fills handler parameters automatically: route values (id), query-string values, headers, and the JSON body (a complex-type parameter on POST/PUT), and services from DI. The :int route constraint rejects non-numeric ids with a 404.

§2Returning the Right Result

app.MapGet("/orders/{id:int}", async (int id, OrderDb db) =>
    await db.Orders.FindAsync(id) is { } order
        ? Results.Ok(order)              // 200
        : Results.NotFound());           // 404

app.MapPost("/orders", (NewOrder o) =>
    o.Qty <= 0
        ? Results.BadRequest(new { error = "Qty must be positive" })   // 400
        : Results.Created($"/orders/{1}", o));                           // 201

Status codes are part of your API's contract: clients branch on them. Return 404 for a missing resource, not 200 with an error message.

§3Controllers and Organizing Endpoints

[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    private readonly IProductService _svc;
    public ProductsController(IProductService svc) => _svc = svc;

    [HttpGet("{id:int}")]
    public async Task<ActionResult<Product>> Get(int id) =>
        await _svc.FindAsync(id) is { } p ? p : NotFound();

    [HttpPost]
    public async Task<IActionResult> Create(CreateProduct dto) { /* ... */ return CreatedAtAction(nameof(Get), new { id = 1 }, dto); }
}

// Program.cs
builder.Services.AddControllers();
app.MapControllers();

// Minimal API grouping
var products = app.MapGroup("/products").WithTags("Products");
products.MapGet("/", () => Results.Ok());

[ApiController] adds automatic 400 responses when the model fails validation. Minimal APIs and controllers can coexist in one app. Use minimal APIs with MapGroup for small services, and controllers when you want conventions, filters, and larger teams' familiarity.

The key insight An endpoint is a function from request to HTTP response. Keep handlers thin: bind and validate input, call a service, and translate the outcome into the right status code.

§4Common Mistakes

MistakeWhat HappensFix
Returning 200 with an error bodyClients and monitoring think the call succeededReturn the appropriate 4xx or 5xx status
Business logic inside handlersHard to test and reuseCall an injected service and keep the handler to HTTP concerns
Trusting bound values without validationNegative quantities, empty names, and oversized input reach your logicValidate (attributes, ValidationProblem, or a library) and return 400
Practice
  1. Build a minimal API with GET (list and by id), POST, and DELETE for an in-memory list of products, returning correct status codes. Test with curl or a .http file.
  2. Port one endpoint to a controller and compare the two styles.
Key takeaways
  • Routes bind to handlers, and model binding fills parameters from route, query, body, and services.
  • Status codes are part of the contract: 200, 201, 204, 400, 404, and 409 each mean something specific.
  • Keep endpoints thin and put logic in services.
