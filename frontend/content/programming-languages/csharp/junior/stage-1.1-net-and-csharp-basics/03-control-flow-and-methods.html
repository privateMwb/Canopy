Control Flow & Methods

Branch, loop, and organize code into small methods whose names and signatures say what they do.

§1Conditionals and Switch Expressions

if (score >= 90) grade = 'A';
else if (score >= 80) grade = 'B';
else grade = 'C';

// switch expression: produces a value, must cover all inputs
string label = day switch
{
    DayOfWeek.Saturday or DayOfWeek.Sunday => "weekend",
    _ => "weekday"
};

A switch expression evaluates to a value and uses _ as the catch-all. The compiler warns when a switch over an enum doesn't cover every case, and it throws at run time if no arm matches. Prefer it to a chain of if statements when you're choosing a value from one input.

§2Loops

for (int i = 0; i < 5; i++) Console.Write(i);

foreach (var name in names) Console.WriteLine(name);

int n = 10;
while (n > 0) { n -= 3; }

do { input = Console.ReadLine(); } while (string.IsNullOrWhiteSpace(input));

Use foreach whenever you don't need the index. It works on anything enumerable and can't go out of bounds. break leaves the loop and continue skips to the next iteration. You can't modify a collection while iterating over it with foreach: the enumerator throws InvalidOperationException.

§3Writing Methods

static decimal ApplyDiscount(decimal price, decimal percent = 10m)
{
    if (price < 0) throw new ArgumentOutOfRangeException(nameof(price));
    return price - price * percent / 100m;
}

// expression-bodied form for one-liners
static bool IsEven(int n) => n % 2 == 0;

var a = ApplyDiscount(80m);                  // default percent
var b = ApplyDiscount(percent: 25m, price: 80m); // named arguments

A clear method does one thing, has a verb-led name, validates its inputs early, and returns a value instead of printing it when the caller might want that value. Use optional and named arguments to keep call sites readable, and return a tuple when you need to give back two small related values: (int min, int max) Range(int[] xs).

The key insight Return early. Handling the invalid cases at the top of a method with if (...) return or throw keeps the main path flat, readable, and un-nested.

§4Common Mistakes

MistakeWhat HappensFix
Forgetting the _ arm in a switch expressionUnmatched values throw SwitchExpressionExceptionAdd a default arm, or cover every enum member and keep warnings enabled
Modifying a list inside foreach over that listInvalidOperationException at run timeIterate over a copy, or build a new list and replace the old one
Methods that both compute and printHard to test or reuseReturn the result and let the caller decide what to do with it
Practice
  1. Write static string Classify(int temperature) using a switch expression with relational patterns (< 0, < 20, and so on).
  2. Write a FizzBuzz method that returns a List<string> for 1 to n instead of printing, and call it from top-level statements.
Key takeaways
  • Switch expressions choose a value, and the compiler helps check coverage.
  • Use foreach by default and never change a collection while enumerating it.
  • Small, verb-named methods that validate early and return values are easy to read and test.
