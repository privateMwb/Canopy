LINQ Basics

LINQ lets you filter, transform, sort, and group any sequence with short, readable method chains.

§1The Core Operators

LINQ methods live in System.Linq (included by implicit usings) and work on any IEnumerable<T>. Each takes a lambda describing what to do with one element.

record Order(string Customer, string Item, decimal Total);

var expensive = orders
    .Where(o => o.Total > 100)          // filter
    .OrderByDescending(o => o.Total)    // sort
    .Select(o => new { o.Customer, o.Total }) // project to a new shape
    .ToList();                          // run it and materialize

bool any = orders.Any(o => o.Total > 500);
int count = orders.Count(o => o.Customer == "Ada");
decimal sum = orders.Sum(o => o.Total);
Order? first = orders.FirstOrDefault(o => o.Item == "Pen");

§2Grouping and Joining

var byCustomer = orders
    .GroupBy(o => o.Customer)
    .Select(g => new
    {
        Customer = g.Key,
        Orders = g.Count(),
        Revenue = g.Sum(o => o.Total)
    })
    .OrderByDescending(x => x.Revenue);

foreach (var row in byCustomer)
    Console.WriteLine($"{row.Customer}: {row.Orders} orders, {row.Revenue:C}");

var lookup = orders.ToLookup(o => o.Customer);   // key -> many
var names = orders.Select(o => o.Customer).Distinct();

GroupBy returns groups, each with a Key and the matching items. Follow it with Select to summarize each group. For one-to-one lookups by key, ToDictionary is usually clearer.

§3Reading a Query Chain

Read a chain top to bottom as a pipeline: start with this data, keep these, reshape to this, order by this. Most operators return a new sequence, so a long chain is a series of small, named steps. Choose the terminal operation by what you need:

  • ToList() / ToArray(): a snapshot you can index and reuse.
  • First vs. FirstOrDefault: First throws if nothing matches, FirstOrDefault returns null or the default value.
  • Single: exactly one match is required, and it throws on zero or several.

LINQ queries are lazy: they don't run until you enumerate them. Lesson 2.1 covers what that means in depth. For now, call ToList() when you need the result.

The key insight LINQ describes what you want, not how to loop to get it. If a chain gets hard to read, split it into well-named intermediate variables instead of nesting more lambdas.

§4Common Mistakes

MistakeWhat HappensFix
Using First when there might be no matchInvalidOperationException: Sequence contains no elementsUse FirstOrDefault and handle null, or Any first
Count() > 0 to test for itemsWalks the whole sequence needlesslyUse Any()
Cramming selection, filtering, and side effects into one lambdaUnreadable, and side effects run unpredictablyKeep lambdas small and pure; use a foreach for side effects
Practice
  1. With a list of Order records, print each customer's total spend, highest first, using GroupBy.
  2. Rewrite a foreach loop with an if and a running total into a LINQ chain. Which version is clearer?
Key takeaways
  • Where filters, Select transforms, OrderBy sorts, and GroupBy groups.
  • Choose terminal operators on purpose: ToList, Any, FirstOrDefault, Single.
  • Read chains as pipelines and split them when they stop being readable.
