Exceptions & IDisposable

Exceptions report failures that code can't continue past, and IDisposable with using ensures files, connections, and handles are released even when they happen.

§1try, catch, and finally

try
{
    var text = File.ReadAllText(path);
    var value = int.Parse(text);
}
catch (FileNotFoundException)
{
    Console.WriteLine("No such file.");
}
catch (FormatException ex) when (ex.Message.Length > 0)
{
    Console.WriteLine("Not a number.");
}
finally
{
    Console.WriteLine("Always runs.");
}

Catch the most specific exception type you can actually handle, most specific first. A when filter adds a condition. finally runs whether or not an exception occurred. Don't catch Exception unless you're at the outermost boundary (a request handler or the top of the program) where you log and turn the failure into a response.

§2Throwing and Rethrowing

static void Withdraw(decimal amount)
{
    if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
    // ...
}

try { Process(); }
catch (Exception ex)
{
    Log(ex);
    throw;            // rethrow, preserving the stack trace
    // throw ex;      // WRONG: resets the stack trace
}

throw new InvalidOperationException("Could not load config", innerException);

Use exceptions for exceptional conditions, not normal control flow. When an operation commonly fails, use the Try pattern (int.TryParse) so callers can handle failure without a try block. Wrap with an inner exception when you add context, so the original cause isn't lost.

§3IDisposable and using

Some objects hold resources that the garbage collector doesn't release promptly: file handles, database connections, sockets. They implement IDisposable, and using guarantees Dispose() is called even when an exception occurs.

using var reader = new StreamReader(path);       // disposed at end of scope
string? line = reader.ReadLine();

using (var conn = new SqlConnection(cs))             // classic block form
{
    conn.Open();
}                                                    // Dispose called here

public sealed class TempFile : IDisposable
{
    private readonly string _path = Path.GetTempFileName();
    public void Dispose() => File.Delete(_path);
}

If a type implements IDisposable, you own it once you create it, so wrap it in using. Async resources use await using with IAsyncDisposable.

The key insight using is try/finally with the cleanup written for you. Any time a method both acquires a resource and can fail, make the release automatic instead of remembering to do it.

§4Common Mistakes

MistakeWhat HappensFix
catch (Exception) { } with an empty bodyFailures vanish and bugs become mysteriesHandle it, log it, or let it propagate
throw ex; instead of throw;The original stack trace is lostUse bare throw; to rethrow
Forgetting using on streams and connectionsLocked files and exhausted connection poolsWrap every IDisposable you create in using
Practice
  1. Write a method that reads a file and parses an integer from it. Handle a missing file and a bad number separately, and wrap the reader in using.
  2. Create a Timer class implementing IDisposable that prints the elapsed time when disposed, and use it in a using block around some work.
Key takeaways
  • Catch specific exceptions you can handle, and rethrow with throw; to keep the stack trace.
  • Use Try methods for expected failures and exceptions for unexpected ones.
  • using guarantees Dispose runs, so use it for every disposable you create.
