Delegates, Events & Lambdas

Delegates let you treat a method as a value, lambdas are the shorthand for writing one inline, and events build a publish-subscribe pattern on top.

§1Delegates and Lambdas

A delegate is a type that refers to a method with a given signature. You almost never declare your own, because the framework provides Func<...> (returns a value), Action<...> (returns nothing), and Predicate<T>.

Func<int, int> square = x => x * x;
Action<string> log = msg => Console.WriteLine(msg);
Func<int, int, int> add = (a, b) => a + b;

Console.WriteLine(square(5));     // 25
log("hello");

static int Apply(Func<int,int> f, int v) => f(v);   // behavior as a parameter
Apply(x => x + 1, 10);            // 11
Apply(Math.Abs, -4);              // a method group works too

A lambda (x => x * x) is an inline anonymous method. This is exactly what LINQ's Where and Select take.

§2Closures

A lambda can use variables from the method around it. It captures the variable itself, not a copy of its current value.

int counter = 0;
Action inc = () => counter++;
inc(); inc();
Console.WriteLine(counter);   // 2: the lambda changed the outer variable

var actions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    int copy = i;                    // capture a per-iteration copy
    actions.Add(() => Console.Write(copy));
}

Captured variables live as long as the lambda does, which is convenient but can keep large objects alive longer than you expect. foreach variables are fresh per iteration, but a for loop's counter is one shared variable, so copy it if the lambda runs later.

§3Events

public class Downloader
{
    public event EventHandler<int>? ProgressChanged;     // publisher side

    public void Run()
    {
        for (int pct = 0; pct <= 100; pct += 25)
            ProgressChanged?.Invoke(this, pct);          // raise safely
    }
}

var d = new Downloader();
d.ProgressChanged += (sender, pct) => Console.WriteLine($"{pct}%");  // subscribe
d.Run();

An event is a delegate that outsiders can only subscribe to (+=) and unsubscribe from (-=); only the owning class can raise it. Always raise with ?.Invoke because an event with no subscribers is null. A subscriber stays referenced by the publisher until it unsubscribes, a classic source of memory leaks.

The key insight Passing a delegate means you decide what happens and the other code decides when. That inversion is what makes LINQ, event handlers, callbacks, and retry helpers possible.

§4Common Mistakes

MistakeWhat HappensFix
Capturing a for loop variable in a deferred lambdaEvery lambda sees the final valueCopy it to a local inside the loop body
Never unsubscribing from a long-lived publisher's eventThe subscriber can't be garbage collected (a leak)Unsubscribe with -= (for example in Dispose)
Invoking an event directly as Changed(this, e)NullReferenceException when nobody subscribedUse Changed?.Invoke(this, e)
Practice
  1. Write static List<int> Filter(List<int> xs, Func<int,bool> keep) and call it with three different lambdas.
  2. Add an event Action<string> Completed to a class, subscribe two handlers, and confirm both run when it's raised.
Key takeaways
  • Func and Action let you pass behavior as an argument; lambdas are the short syntax.
  • Lambdas capture variables, not values, so copy loop variables when needed.
  • Events are restricted delegates for publish-subscribe, and unsubscribing prevents leaks.
