Generics Basics

Generics let you write one type or method that works safely with many types, with the compiler checking correctness and no casting at run time.

§1Why Generics Exist

Before generics, collections held object, so you cast on the way out and any mistake crashed at run time. Generics move that check to compile time and avoid boxing value types.

var names = new List<string>();
names.Add("Ada");
// names.Add(42);        // compile error: int is not string
string n = names[0];      // no cast needed

§2Writing a Generic Type and Method

public class Stack<T>
{
    private readonly List<T> _items = new();
    public void Push(T item) => _items.Add(item);
    public T Pop()
    {
        if (_items.Count == 0) throw new InvalidOperationException("Empty");
        var item = _items[^1];          // index-from-end
        _items.RemoveAt(_items.Count - 1);
        return item;
    }
    public int Count => _items.Count;
}

var s = new Stack<int>();
s.Push(1);

public static T Max<T>(T a, T b) where T : IComparable<T> =>
    a.CompareTo(b) >= 0 ? a : b;

var m = Max(3, 7);        // type argument inferred: Max<int>

T is a placeholder filled in by the caller. The compiler usually infers type arguments for methods, as in Max(3, 7). A Stack<int> and a Stack<string> are separate types at run time, and for value types the runtime generates specialized code, so there's no boxing.

§3Constraints

Inside a generic method the compiler only lets you do what every possible T supports, which is almost nothing. A constraint promises more:

where T : class          // reference type
where T : struct         // non-nullable value type
where T : new()          // has a public parameterless constructor
where T : IComparable<T> // implements an interface
where T : Shape          // derives from a base class

In the Max example, without IComparable<T> the call to CompareTo wouldn't compile. Add constraints when the compiler asks for them, and no more.

The key insight Generics are a compile-time contract: "this works for any T that satisfies these constraints." If you find yourself casting inside a generic method, a constraint or a different design is usually missing.

§4Common Mistakes

MistakeWhat HappensFix
Using object or ArrayList instead of genericsCasts, boxing, and run-time type errorsUse List<T> and your own generic types
Calling members on T without a constraintCompile error: T doesn't contain that memberAdd the right where clause
Over-generic code with many type parametersHard to read and useStart with concrete types and generalize only when a second use appears
Practice
  1. Write a generic Pair<TFirst, TSecond> class with a Swap() method returning Pair<TSecond, TFirst>.
  2. Write static T? FirstOrNull<T>(IEnumerable<T> items, Func<T,bool> pred) where T : class and test it with strings.
Key takeaways
  • Generics give type safety with no casts and no boxing for value types.
  • The compiler infers method type arguments and checks them at compile time.
  • Constraints (where) say what a type parameter must support.
