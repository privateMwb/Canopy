Records, Structs & Enums

Records give you immutable data with value-based equality in one line, structs give you value semantics, and enums give names to a fixed set of choices.

§1Records

public record Person(string Name, int Age);

var a = new Person("Ada", 36);
var b = new Person("Ada", 36);
Console.WriteLine(a == b);        // True: compares values
Console.WriteLine(a);              // Person { Name = Ada, Age = 36 }

var older = a with { Age = 37 };   // copy with one change; a is untouched

A record is a class (reference type) whose compiler-generated members compare by value, print nicely, and support non-destructive with copies. The positional form above also creates init-only properties and a deconstructor: var (name, age) = a;. Use records for data that carries information, such as DTOs, messages, and configuration values.

§2Structs

public readonly struct Money
{
    public decimal Amount { get; }
    public string Currency { get; }
    public Money(decimal amount, string currency) => (Amount, Currency) = (amount, currency);
}

public readonly record struct Point(int X, int Y);  // value-type record

A struct is a value type: it's copied on assignment and has no identity. Choose one for small (roughly 16 bytes or less), logically single values that you'll treat as immutable, and mark it readonly to make that explicit. Everything else should be a class or record.

§3Enums

public enum OrderStatus { Pending, Shipped, Delivered, Cancelled }

var s = OrderStatus.Shipped;
string text = s switch
{
    OrderStatus.Pending => "Waiting",
    OrderStatus.Shipped => "On the way",
    OrderStatus.Delivered => "Done",
    OrderStatus.Cancelled => "Cancelled",
    _ => throw new ArgumentOutOfRangeException(nameof(s))
};

[Flags] public enum Permissions { None = 0, Read = 1, Write = 2, Execute = 4 }
var rw = Permissions.Read | Permissions.Write;

An enum is a named integer constant set. Any integer can be cast to an enum type, so validate values that come from outside with Enum.IsDefined and keep the _ arm in switches. [Flags] enums use powers of two so values can be combined with |.

The key insight Records are about what the data is (equal if the values are equal), while classes are about who the object is (identity). Pick the one that matches how you reason about equality.

§4Common Mistakes

MistakeWhat HappensFix
Using a record for an entity with identity (such as a database row that changes)Two different objects with the same field values compare equalUse a class for entities and records for values
A large mutable structExpensive copies and lost updatesKeep structs small and readonly, or use a class
Trusting a cast to an enumUndefined values slip throughValidate with Enum.IsDefined and handle the default switch arm
Practice
  1. Model an Address as a record, create two equal instances, and show they compare equal. Then make a copy with a different city using with.
  2. Create a [Flags] enum for file permissions and write a method that prints which flags are set using HasFlag.
Key takeaways
  • Records are reference types with value equality, readable ToString, and with copies.
  • Use small readonly structs for tiny single values; use classes and records otherwise.
  • Enums name a closed set of choices; validate values from outside and always handle the unexpected case.
