Classes, Properties & Encapsulation

A class bundles data with the behavior that protects it, and properties let you control exactly how that data is read and changed.

§1A Class with Fields and a Constructor

public class BankAccount
{
    private decimal _balance;          // field: private state
    public string Owner { get; }       // property: read-only after construction

    public BankAccount(string owner, decimal opening = 0m)
    {
        Owner = owner;
        _balance = opening;
    }

    public decimal Balance => _balance; // read-only computed property
}

Fields hold state and should almost always be private. The convention is a leading underscore for private fields. A constructor runs when you call new and must leave the object in a valid state.

§2Properties

A property looks like a field to callers but is really a pair of methods, so you can add validation or computation later without breaking any calling code.

public class Product
{
    private decimal _price;
    public decimal Price
    {
        get => _price;
        set
        {
            if (value < 0) throw new ArgumentOutOfRangeException(nameof(value));
            _price = value;
        }
    }
    public string Name { get; init; } = "";   // set only during initialization
    public int Stock { get; private set; }     // only this class can change it
}

var p = new Product { Name = "Pen", Price = 1.5m };
// p.Name = "Ink";   // error: init-only

Auto-properties ({ get; set; }) generate the backing field for you. init allows assignment only in an object initializer or constructor, which makes it the right default for data that shouldn't change afterwards.

§3Encapsulation in Practice

Encapsulation means other code can't put your object into an invalid state. Expose behavior through methods that enforce rules, and keep the representation private.

public void Withdraw(decimal amount)
{
    if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
    if (amount > _balance) throw new InvalidOperationException("Insufficient funds");
    _balance -= amount;
}
ModifierVisible to
publicAny code
internalThe same assembly (project)
protectedThis class and its subclasses
privateThis class only (the default for members)
The key insight Make members as private as they can be and data as immutable as it can be. A public setter is a promise that any value, set at any time, is valid, so offer it only when that's true.

§4Common Mistakes

MistakeWhat HappensFix
Public fields instead of propertiesYou can't add validation later without breaking callersUse properties, and private fields behind them
{ get; set; } on everythingObjects can be changed into invalid states from anywherePrefer init or private set and expose methods for changes
A constructor that leaves required state unsetHalf-initialized objects and null bugsTake required values as parameters, or use required members
Practice
  1. Write a Temperature class with a Celsius property that rejects values below -273.15, plus a read-only Fahrenheit property.
  2. Add a Deposit method to BankAccount and write down every invalid call you reject.
Key takeaways
  • Fields are private state; properties are the controlled public surface.
  • Use init and private set to limit who can change data and when.
  • Encapsulation keeps invalid states unrepresentable, and methods are where rules are enforced.
