Projects, Solutions & NuGet

Real applications split into several projects tied together by a solution, with reusable code arriving as NuGet packages.

§1Projects and Solutions

A project (.csproj) builds into one assembly: a console app, a class library, or a test project. A solution (.sln or .slnx) groups projects so you can build and test them together.

dotnet new sln -n Bookshop
dotnet new classlib -o src/Bookshop.Core
dotnet new console  -o src/Bookshop.Cli
dotnet sln add src/Bookshop.Core src/Bookshop.Cli
dotnet add src/Bookshop.Cli reference src/Bookshop.Core   // project reference
dotnet build                                             // builds everything

A project reference lets one project use the public types of another. Keep domain logic in a class library with no console or UI code, so it can be tested and reused.

§2Reading a csproj

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Humanizer.Core" Version="2.14.1" />
    <ProjectReference Include="..\Bookshop.Core\Bookshop.Core.csproj" />
  </ItemGroup>
</Project>

The SDK includes every .cs file in the folder automatically, so you don't list source files. PropertyGroup holds settings and ItemGroup holds references. To apply the same settings to many projects, put them in a Directory.Build.props file at the solution root.

§3NuGet Packages

dotnet add package Newtonsoft.Json              // latest stable
dotnet add package Serilog --version 4.0.0
dotnet remove package Newtonsoft.Json
dotnet list package --outdated
dotnet restore

NuGet is the package manager: dotnet add package edits the PackageReference in your csproj and restore downloads it to a shared cache. Packages bring their own dependencies. Before you add one, check how widely it's used, whether it's maintained, and its license, because you'll be responsible for it. Pin versions deliberately and update on purpose, not by accident.

The key insight The csproj is the single source of truth for how a project builds: framework, language settings, and dependencies. It's plain XML you can read and edit, so look at it whenever a build behaves unexpectedly.

§4Common Mistakes

MistakeWhat HappensFix
Putting everything in one console projectLogic is hard to test and reuseSplit into a class library plus thin app and test projects
Referencing a project's compiled DLL directlyRebuilds and versions drift out of syncUse a ProjectReference
Adding a package for something the framework already doesExtra dependencies, updates, and security surfaceCheck the base class library first
Practice
  1. Create a solution with a class library and a console app, reference one from the other, and call a library method from Program.cs.
  2. Add a NuGet package, open the csproj, and find the line it added. Then run dotnet list package.
Key takeaways
  • A solution groups projects, and project references connect them.
  • The csproj controls the target framework, settings, and dependencies.
  • NuGet packages are dependencies you own, so choose and update them deliberately.
