Patterns in the JDK & Frameworks

Design patterns are named solutions to recurring problems, and the quickest way to understand them is to recognize them in the JDK and frameworks you already use.

§1Builder

When an object has many optional parameters, a long constructor becomes unreadable (new Request(url, null, null, 30, true, false)). A builder sets them by name and creates the object at the end, and the result can be immutable.

HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create("https://example.com/api"))
    .header("Accept", "application/json")
    .timeout(Duration.ofSeconds(5))
    .GET()
    .build();                                          // validated and immutable

StringBuilder sb = new StringBuilder().append("a").append(1);     // also builder-shaped

For your own classes, a static nested Builder or, for simple cases, a record with a few well-named factory methods does the job. Libraries like Lombok can generate builders, but a hand-written one is only a few lines.

§2Factory

A factory hides which concrete class is created. A static factory method can have a descriptive name, return a cached instance, or return a subtype, which constructors cannot do.

List<String> a = List.of("x");                        // returns an unspecified immutable implementation
Optional<String> o = Optional.empty();                 // shared instance
Integer i = Integer.valueOf(127);                      // cached for small values
Calendar c = Calendar.getInstance();
LocalDate d = LocalDate.of(2026, 1, 15);
Path p = Path.of("a", "b");

public sealed interface Shape permits Circle, Square {
    static Shape circle(double r) { return new Circle(r); }      // callers never name the class
}

§3Strategy

A strategy is an interchangeable algorithm behind an interface. In modern Java, a lambda is usually the whole strategy: Comparator is the canonical example, since sorting stays the same and the ordering rule is swapped in.

people.sort(Comparator.comparing(Person::age));
people.sort(Comparator.comparing(Person::name));

interface PricingRule { long price(Cart c); }
PricingRule standard = c -> c.subtotal();
PricingRule member = c -> c.subtotal() * 90 / 100;
long total = (isMember ? member : standard).price(cart);

§4Observer

An observer lets objects subscribe to events from another object without it knowing who they are. Listener interfaces across Swing and JavaFX, and event publishers in Spring, work this way. Java's own Flow API and reactive streams build on the same idea.

class EventBus<E> {
    private final List<Consumer<E>> listeners = new CopyOnWriteArrayList<>();
    void subscribe(Consumer<E> l) { listeners.add(l); }
    void publish(E event) { listeners.forEach(l -> l.accept(event)); }
}
bus.subscribe(e -> audit.log(e));
bus.subscribe(e -> mailer.notify(e));

Beware of listeners that are never unsubscribed, which causes memory leaks, and of listeners that throw, which can stop the others from running.

§5More You Already Use

  • Decorator: new BufferedReader(new InputStreamReader(in)) wraps one object to add behavior; Collections.unmodifiableList is another.
  • Iterator: the for-each loop over any Iterable.
  • Template method: an abstract base class defines the skeleton and subclasses fill in steps, as with InputStream.read or Spring's JdbcTemplate.
  • Singleton: one shared instance. Prefer letting a framework or your main create one object and pass it around, as hand-written singletons make testing hard; if you need one, a single-element enum is the safest form.
  • Proxy: an object standing in for another to add behavior; Spring uses dynamic proxies for transactions and caching.
Patterns are vocabulary Their main value is communication: saying "this is a strategy" or "make it a builder" conveys a whole design in one phrase. Learn the problem each solves, because the code shape often differs in modern Java (a lambda replaces a strategy class).

§6Common Mistakes

MistakeWhat HappensFix
Using a long constructor with many same-typed argumentsEasy to swap arguments silentlyUse a builder or named factory methods
Hand-rolled global singletonsHidden dependencies and untestable codePass dependencies in, or use a DI framework
Applying a pattern because it's on a listExtra classes and no benefitStart from the problem, not the pattern
Listeners that are never removedMemory leaksProvide unsubscribe, or use weak references carefully
A listener that throws inside publishLater listeners are skippedCatch and log per listener
Writing a Strategy class hierarchy for a one-line behaviorBoilerplateUse a lambda or method reference
Practice
  1. Write an immutable EmailMessage with required to/subject and optional cc/bcc, using a builder that validates in build().
  2. Find three static factory methods in the JDK and say what each one gains over a constructor.
  3. Implement a tiny event bus, then show how a slow or throwing subscriber affects the others and fix it.
Key takeaways
  • Builder, factory, strategy, and observer are all visible in the standard library, and the JDK is a good source of examples.
  • In modern Java a lambda often replaces a strategy class, and static factories replace many constructors.
  • Choose a pattern in response to a real problem, and use pattern names as shared vocabulary.
