Recent Language Features

Java now ships a release every six months, with a long-term support release every two years, and the features added since Java 8 have changed what idiomatic code looks like.

§1The Release Model

A new Java version arrives every March and September. Most are supported for only six months; LTS (long-term support) versions, which are 8, 11, 17, 21, and 25, are the ones production systems tend to run, with years of vendor-provided security updates. Features usually appear first as preview features, off by default (enable with --enable-preview), and can change before being finalized. Always check which version a given feature is final in before relying on it.

§2Features You Will See Constantly

var (Java 10) infers local variable types. Use it when the type is obvious from the right-hand side; avoid it when it hurts readability. It works only for locals, not fields or method signatures.

var names = new ArrayList<String>();        // clear from the right side
var entry = map.entrySet().iterator().next();
// var x = compute();                       // what type is this? spell it out instead
for (var e : map.entrySet()) { }

Switch expressions (Java 14) and text blocks (Java 15) were covered earlier and are now standard. Records (16), sealed classes (17), and pattern matching for instanceof (16) are final, and pattern matching for switch and record patterns are final as of Java 21.

Enhanced collection and string APIs save a lot of boilerplate:

List<String> copy = List.copyOf(source);                  // 10
String s = "  hi ".strip();                               // 11 (Unicode-aware trim)
"ab".repeat(3);                                           // 11
"a\nb".lines().toList();                                  // 11
var list = stream.toList();                               // 16: unmodifiable
list.getFirst();  list.getLast();  list.reversed();       // 21: SequencedCollection

Helpful NullPointerException messages (14) now tell you which expression was null, such as Cannot invoke "String.length()" because "user.name" is null.

§3Newer Additions

Java 21 added virtual threads, record patterns, and sequenced collections. Later releases, including 25, continued to simplify getting started and trim boilerplate: simplified main (instance main methods and compact source files) lets a beginner's program be a few lines, flexible constructor bodies allow statements before super(...) for validation, and module import declarations shorten imports. Scoped values and the Stream Gatherers API for custom intermediate stream operations also reached final status in recent releases. Some features, such as structured concurrency, may still be in preview, so check the release notes for the version you actually run.

// Java 25: a complete program, no class or static needed
void main() {
    System.out.println("Hello");
}

§4Choosing a Version

For a new project, pick the newest LTS that your frameworks and deployment platform support. The jump between LTS versions is usually smaller than people fear, because Java is very backward compatible, but it is worth doing regularly rather than every eight years. Set the version explicitly in your build (--release 21 or a Gradle toolchain) so the compiler stops you from using APIs newer than your target.

Idiomatic Java keeps moving Code written in the Java 8 style still compiles, but modern features make it shorter and safer. When you read old code, expect loops and anonymous classes; when you write new code, reach for records, switch expressions, and pattern matching.

§5Common Mistakes

MistakeWhat HappensFix
Using var when the type isn't obviousReaders can't tell what a variable holdsUse var only when the right side makes the type clear
Relying on a preview feature in productionIt may change or be removed in the next releaseUse only finalized features, and pin the JDK version
Building with a newer JDK than you deploy onUnsupportedClassVersionError at runtimeSet --release or a toolchain to the deployment version
Assuming the newest release is the one to runShort support window and fewer ecosystem guaranteesPrefer the latest LTS unless there's a reason
Ignoring the new helpful null messagesWasted debugging timeRead the exception message carefully; it names the null expression
Practice
  1. Take a Java 8-style class (getters, equals, a switch statement) and modernize it with a record and a switch expression.
  2. Find out which LTS your machine runs with java --version, then write one feature available in that version but not in Java 8.
  3. Compile a class with a newer --release and run it on an older JVM to see the error message.
Key takeaways
  • Releases arrive twice a year, with LTS versions (8, 11, 17, 21, 25) being the production targets.
  • var, switch expressions, records, sealed types, and pattern matching are all final and now idiomatic.
  • Preview features can change, so verify finalization status and set the target version explicitly.
