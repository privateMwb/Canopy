Lambdas & Functional Interfaces

A lambda is a compact way to pass behavior as a value, and it works anywhere Java expects a functional interface, meaning an interface with exactly one abstract method.

§1From Anonymous Classes to Lambdas

Before Java 8, passing behavior meant writing an anonymous class. A lambda expresses the same thing without the ceremony. The compiler infers which interface you mean from the context.

Comparator<String> byLength = new Comparator<String>() {       // before
    @Override public int compare(String a, String b) {
        return Integer.compare(a.length(), b.length());
    }
};

Comparator<String> byLength2 = (a, b) -> Integer.compare(a.length(), b.length());   // after
Runnable r = () -> System.out.println("running");
Function<String, Integer> len = s -> s.length();
Function<Integer, Integer> sq = n -> { int r2 = n * n; return r2; };   // block body needs return

A functional interface has one abstract method (it may also have default and static methods). Mark your own with @FunctionalInterface so the compiler enforces it.

§2The Standard Functional Interfaces

java.util.function supplies the common shapes so you rarely need to define your own.

InterfaceMethodUse
Function<T,R>R apply(T)Transform a value
Predicate<T>boolean test(T)Yes/no question
Consumer<T>void accept(T)Do something with a value
Supplier<T>T get()Produce a value, often lazily
UnaryOperator<T>T apply(T)Transform to the same type
BinaryOperator<T>T apply(T, T)Combine two values
BiFunction<T,U,R>R apply(T, U)Two inputs, one output

Primitive variants such as IntPredicate, ToIntFunction, and IntBinaryOperator avoid boxing. These interfaces also compose:

Predicate<String> notBlank = s -> !s.isBlank();
Predicate<String> shortWord = s -> s.length() < 6;
Predicate<String> both = notBlank.and(shortWord);
Predicate<String> neither = notBlank.negate();

Function<Integer, Integer> plus1 = n -> n + 1;
Function<Integer, Integer> times2 = n -> n * 2;
plus1.andThen(times2).apply(3);          // (3+1)*2 = 8
plus1.compose(times2).apply(3);          // (3*2)+1 = 7

§3Method References

When a lambda only calls an existing method, a method reference is shorter. There are four forms.

Function<String, Integer> a = Integer::parseInt;            // static method
Function<String, String> b = String::toUpperCase;           // instance method of an arbitrary object
Consumer<Object> c = System.out::println;                   // instance method of a specific object
Supplier<List<String>> d = ArrayList::new;                  // constructor
List.of("b", "a").forEach(System.out::println);

§4Capturing Variables

A lambda can use variables from the enclosing method, but only if they are effectively final, meaning never reassigned after initialization. This is because the lambda may run later or on another thread, and it takes a copy of the value.

int base = 10;
Function<Integer, Integer> addBase = n -> n + base;          // fine
// base++;                                                   // would make the lambda above fail to compile

int[] counter = {0};                                         // a workaround: mutate the contents
Runnable inc = () -> counter[0]++;                           // legal, but a code smell

Inside a lambda, this means the enclosing object, unlike an anonymous class, where it means the anonymous instance.

Lambdas are values A lambda has no type of its own: the target type decides it. That is why the same x -> x + 1 can be a Function, a UnaryOperator, or an IntUnaryOperator depending on where it appears.

§5Common Mistakes

MistakeWhat HappensFix
Modifying a captured local variablelocal variables referenced from a lambda must be final or effectively finalUse an AtomicInteger/array, or restructure so no mutation is needed
Writing long multi-line lambdasHard to read and testExtract a named method and use a method reference
Defining your own interface for a standard shapeExtra types that duplicate Function and PredicateUse java.util.function unless a domain name adds clarity
Throwing a checked exception from a lambdaCompile error: the functional method doesn't declare itCatch it inside, or wrap in an unchecked exception
Confusing this in a lambda with this in an anonymous classWrong object referencedIn a lambda, this is the enclosing instance
Practice
  1. Replace an anonymous Comparator with a lambda, then with Comparator.comparing and a method reference.
  2. Write static <T> List<T> filter(List<T> list, Predicate<T> p) and use it with three different predicates, combining two with and.
  3. Build a Function<String,String> pipeline that trims, lowercases, and replaces spaces with dashes, using andThen.
Key takeaways
  • A lambda implements a functional interface, whose type is decided by the context.
  • Function, Predicate, Consumer, Supplier, and their relatives cover most needs and can be composed.
  • Lambdas capture effectively-final variables; prefer method references when a lambda just calls one method.
