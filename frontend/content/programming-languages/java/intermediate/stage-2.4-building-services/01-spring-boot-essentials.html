Spring Boot Essentials

Spring Boot gives you a working, configurable application from a few dependencies and one annotation, with the framework creating your objects and wiring them together.

§1Inversion of Control and Beans

In plain Java you create your own objects and pass them to each other. In Spring, an application context creates objects called beans, finds their dependencies, and injects them. You declare what you need, and the container supplies it. This is dependency inversion, automated.

@SpringBootApplication
public class App {
    public static void main(String[] args) {
        SpringApplication.run(App.class, args);        // starts the context, and the web server if present
    }
}

@Service
public class GreetingService {
    private final Clock clock;                          // a dependency
    public GreetingService(Clock clock) { this.clock = clock; }    // constructor injection
    public String greet(String name) { return "Hello " + name + " at " + clock.instant(); }
}

@Configuration
class AppConfig {
    @Bean Clock clock() { return Clock.systemUTC(); }  // a bean defined by a factory method
}

@SpringBootApplication combines three things: @Configuration, @EnableAutoConfiguration, and @ComponentScan. Component scanning finds classes annotated with @Component or its specializations (@Service, @Repository, @Controller, @RestController) in the application's package and below, so keep your main class in the root package.

§2Dependency Injection Done Right

Prefer constructor injection: dependencies are final, the class can't exist half-built, and you can instantiate it in a unit test with plain new and a fake. With a single constructor, @Autowired isn't even needed. Avoid field injection (@Autowired private Foo foo;), which hides dependencies and requires the container to test your class. By default beans are singletons: one shared instance per context, so they must be safe for concurrent use and should not hold per-request mutable state.

@Service
class OrderService {
    private final OrderRepository repo;
    private final PaymentGateway payments;
    OrderService(OrderRepository repo, PaymentGateway payments) {    // both injected
        this.repo = repo;
        this.payments = payments;
    }
}

If there are two beans of the same type, Spring can't choose; mark one @Primary or select with @Qualifier("name").

§3Auto-Configuration and Starters

Boot's magic is auto-configuration: it looks at what is on the classpath and what you have defined, and configures sensible defaults. Add spring-boot-starter-web and you get an embedded web server and JSON support; add a database driver and a DataSource appears, unless you define your own. Starters are dependency bundles named for a purpose (-web, -data-jpa, -validation, -actuator, -test) so you don't assemble versions by hand. You can ask Boot what it decided with --debug, which prints a conditions report.

§4Configuration and Lifecycle

Settings live in application.properties or application.yml, and Boot binds them to typed objects.

server:
  port: 8081
app:
  greeting:
    prefix: "Hi"
@ConfigurationProperties(prefix = "app.greeting")
record GreetingProps(String prefix) { }               // enable with @ConfigurationPropertiesScan

@Value("${server.port}") int port;                    // fine for one-off values

The lifecycle: the context is created, beans are instantiated in dependency order, @PostConstruct methods and ApplicationRunner beans run, the application serves, and on shutdown the context closes, calling @PreDestroy methods. Spring's @Transactional, @Cacheable, and @Async work by wrapping your bean in a proxy, which has a consequence: calling an annotated method from another method in the same class bypasses the proxy, so the annotation does nothing.

You still write plain Java Spring Boot's value is wiring, defaults, and operational features. Keep your business logic in ordinary classes with constructor parameters, so you can test them without starting a container.

§5Common Mistakes

MistakeWhat HappensFix
Field injection with @AutowiredHidden dependencies; can't build the object without SpringUse constructor injection
Main class in a sub-packageComponent scan misses other packagesPut @SpringBootApplication in the root package
Storing per-request state in a singleton beanData leaks and races between requestsKeep beans stateless, or pass state as parameters
Calling a @Transactional method from the same classThe proxy is bypassed, so no transactionCall it from another bean, or restructure
Two beans of one type, with no qualifierNoUniqueBeanDefinitionExceptionUse @Primary or @Qualifier
Hardcoding secrets in application.ymlCredentials in version controlRead from environment variables or a secrets store
Practice
  1. Create a Boot project with spring-boot-starter-web, run it, and add a @Service injected into a @RestController.
  2. Run with --debug and find which auto-configurations were applied and which were skipped, and why.
  3. Bind a @ConfigurationProperties record to values in application.yml, then override one with an environment variable.
Key takeaways
  • Spring creates and wires beans from your declarations; prefer constructor injection and stateless singletons.
  • Auto-configuration and starters supply defaults based on the classpath, and you override what you need.
  • Annotations like @Transactional work through proxies, so same-class calls bypass them.
