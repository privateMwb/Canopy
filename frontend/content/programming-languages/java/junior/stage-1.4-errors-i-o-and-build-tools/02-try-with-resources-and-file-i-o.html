try-with-resources & File I/O

Files, sockets, and database connections must be closed, and try-with-resources guarantees it, while java.nio.file makes the common read-and-write tasks short and safe.

§1try-with-resources

Any object that implements AutoCloseable can be declared in the parentheses after try. Java closes it automatically when the block ends, normally or by exception, in reverse order of declaration.

try (BufferedReader in = Files.newBufferedReader(Path.of("data.txt"));
     BufferedWriter out = Files.newBufferedWriter(Path.of("copy.txt"))) {
    String line;
    while ((line = in.readLine()) != null) {
        out.write(line);
        out.newLine();
    }
}                                        // both closed here, even if an exception was thrown

The old way was a try/finally with a null check and a nested try around close(), which is easy to get wrong and can hide the original exception. If the body and the close both throw, try-with-resources keeps the body's exception as the main one and attaches the close failure as a suppressed exception.

To make your own resource, implement AutoCloseable:

class Connection implements AutoCloseable {
    @Override public void close() { System.out.println("closed"); }
}

§2Paths and Files

java.nio.file is the modern file API. A Path represents a location, and Files has static methods for reading and writing. Prefer these over the older java.io.File.

import java.nio.file.*;
import java.nio.charset.StandardCharsets;
import java.util.List;

Path p = Path.of("notes", "today.txt");           // notes/today.txt on any OS
Files.createDirectories(p.getParent());

Files.writeString(p, "hello\nworld\n");                         // UTF-8 by default
String all = Files.readString(p);                               // whole file as a String
List<String> lines = Files.readAllLines(p);                     // fine for small files

Files.write(p, List.of("a", "b"), StandardCharsets.UTF_8,
            StandardOpenOption.APPEND);                         // append lines

boolean exists = Files.exists(p);
Files.copy(p, Path.of("backup.txt"), StandardCopyOption.REPLACE_EXISTING);
Files.delete(p);

readAllLines and readString load the entire file, so for big files stream the lines instead. The returned stream holds an open file, so it must also be closed:

try (java.util.stream.Stream<String> s = Files.lines(Path.of("big.log"))) {
    long errors = s.filter(l -> l.contains("ERROR")).count();
}

§3Practical Points

Most I/O methods throw the checked IOException; handle or declare it. Always be explicit about character encoding (the modern Files methods default to UTF-8, but older APIs like FileReader used the platform default). Use Path.of(...) with separate segments rather than hardcoding / or \. To write a file so that readers never see a half-written one, write to a temporary file and then use Files.move with StandardCopyOption.ATOMIC_MOVE.

If it opens, it closes Anything that holds an OS resource (file, socket, stream, connection) belongs in a try-with-resources. A leaked file handle might work for a long time and then fail in production when the OS limit is hit.

§4Common Mistakes

MistakeWhat HappensFix
Opening a stream without closing itFile handle leak; Windows can't delete the fileUse try-with-resources
Using FileReader or new String(bytes) without a charsetGarbled text on a machine with a different defaultPass StandardCharsets.UTF_8, or use Files.readString
Reading a huge file with readAllLinesOutOfMemoryErrorStream with Files.lines or a BufferedReader
Not closing the stream returned by Files.linesThe file stays openPut it in try-with-resources
Hardcoding path separatorsBreaks on another operating systemUse Path.of("a", "b")
Overwriting a file in placeA crash leaves a corrupt fileWrite a temp file, then move it into place
Practice
  1. Write a program that copies one text file to another, uppercasing each line, using try-with-resources with a reader and a writer.
  2. Count the lines containing a given word in a large file using Files.lines, without loading the whole file.
  3. Create a Resource class whose close() prints a message. Open two in one try, throw inside, and note the order of the close messages.
Key takeaways
  • Declare closeable resources in a try (...) and they are closed in reverse order, even on exceptions.
  • Use Path and Files rather than java.io.File, and specify the charset.
  • Stream large files line by line, and close streams that hold files.
