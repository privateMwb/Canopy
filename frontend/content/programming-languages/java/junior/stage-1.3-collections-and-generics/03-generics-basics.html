Generics Basics

Generics let a class or method work with many types while the compiler checks that you use them consistently, removing casts and catching mistakes at compile time.

§1Why Generics Exist

Before generics, collections held Object, and you had to cast on the way out, with errors found only at runtime. Generics move that check to compile time.

List raw = new ArrayList();             // raw type: avoid
raw.add("hello");
raw.add(42);
String s = (String) raw.get(1);         // compiles; ClassCastException at runtime

List<String> typed = new ArrayList<>();
typed.add("hello");
// typed.add(42);                        // compile error: caught early
String t = typed.get(0);                // no cast needed

The <> ("diamond") on the right side lets the compiler infer the type argument from the declaration.

§2Writing a Generic Class

A type parameter like T is a placeholder filled in by the caller. Conventional names are T (type), E (element), K/V (key/value).

public class Box<T> {
    private T value;
    public Box(T value) { this.value = value; }
    public T get() { return value; }
    public void set(T value) { this.value = value; }
}

Box<String> b = new Box<>("hi");
String s = b.get();                     // typed
Box<Integer> n = new Box<>(7);

public record Pair<A, B>(A first, B second) { }
Pair<String, Integer> p = new Pair<>("age", 30);

§3Generic Methods and Bounds

A method can declare its own type parameter before the return type. A bound restricts which types are allowed, which in turn lets you call that type's methods.

public static <T> T firstOrDefault(List<T> list, T fallback) {
    return list.isEmpty() ? fallback : list.get(0);
}

public static <T extends Comparable<T>> T max(List<T> list) {
    T best = list.get(0);
    for (T item : list) {
        if (item.compareTo(best) > 0) best = item;     // allowed because T is Comparable
    }
    return best;
}

String m = max(List.of("pear", "apple", "zebra"));      // type inferred: "zebra"

§4What Generics Can't Do

Type arguments must be reference types, so List<int> is illegal and you write List<Integer>; Java boxes and unboxes automatically. Also, List<String> is not a List<Object>, even though String is an Object; if it were, you could add an Integer to a list of strings. Wildcards, covered in the intermediate track, handle the cases where you need flexibility. And generics are erased at runtime, so you cannot write new T() or x instanceof List<String>.

List<Integer> ints = List.of(1, 2, 3);
// List<Number> nums = ints;             // compile error: generics are invariant
int total = 0;
for (int i : ints) total += i;           // unboxing happens automatically
Boxing has a cost List<Integer> holds Integer objects, not raw ints. That costs memory and allocation, and unboxing a null throws NullPointerException. For large numeric data, arrays of primitives are far more compact.

§5Common Mistakes

MistakeWhat HappensFix
Using raw types (List without <...>)No type checking and ClassCastException laterAlways supply a type argument
Assuming List<String> can be assigned to List<Object>Compile errorUse a wildcard such as List<? extends Object> (intermediate lesson)
Trying List<int>Compile errorUse List<Integer>, or an int[] for heavy numeric work
Calling compareTo on an unbounded TCompile error: method not foundAdd the bound T extends Comparable<T>
Trying new T()Compile error, because the type is erasedPass a Supplier<T> into the method
Practice
  1. Write a generic Stack<T> backed by an ArrayList<T> with push, pop, and peek.
  2. Write static <T extends Comparable<T>> boolean isSorted(List<T> list).
  3. Write a generic Pair<A, B> with a method swap() returning Pair<B, A>.
Key takeaways
  • Generics let the compiler check type use and remove casts; avoid raw types.
  • Type parameters can be declared on classes and methods, and bounds unlock methods of the bound type.
  • Generics work only with reference types, are invariant, and are erased at runtime.
