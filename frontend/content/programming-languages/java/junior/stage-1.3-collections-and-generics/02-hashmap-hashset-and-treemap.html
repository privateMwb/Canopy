HashMap, HashSet & TreeMap

Hash-based collections give near-constant-time lookups by turning a key's hashCode into a bucket, and the choice between HashMap, LinkedHashMap, and TreeMap is a choice about ordering.

§1Maps and Sets

A Map<K,V> stores key-value pairs with unique keys. A Set<E> stores unique elements; HashSet is really a HashMap where only the keys matter.

Map<String, Integer> stock = new HashMap<>();
stock.put("apple", 5);
stock.put("pear", 2);
stock.put("apple", 7);                    // replaces: returns old value 5
stock.get("pear");                        // 2
stock.get("plum");                        // null for a missing key
stock.getOrDefault("plum", 0);            // 0
stock.containsKey("apple");               // true
stock.putIfAbsent("fig", 1);

stock.merge("apple", 1, Integer::sum);    // increment, or insert 1 if absent
stock.computeIfAbsent("kiwi", k -> 0);

for (Map.Entry<String, Integer> e : stock.entrySet()) {
    System.out.println(e.getKey() + "=" + e.getValue());
}

Set<String> seen = new HashSet<>();
boolean isNew = seen.add("x");            // true the first time, false for a duplicate

Counting words with merge is the classic idiom: counts.merge(word, 1, Integer::sum).

§2How Hashing Works

HashMap computes key.hashCode(), uses it to pick one of several buckets, and then compares keys in that bucket using equals. With a good hash function, buckets stay small and get and put are O(1) on average. If many keys collide into one bucket, performance degrades toward O(n) (the JDK converts large buckets to trees to limit the damage).

This is why the equals/hashCode contract matters. If equal keys have different hash codes, or the key's fields change after insertion, the map looks in the wrong bucket and reports that the key does not exist.

record Sku(String code) { }                    // records have correct equals and hashCode
Map<Sku, Integer> prices = new HashMap<>();
prices.put(new Sku("A1"), 100);
prices.get(new Sku("A1"));                     // 100: equal key, same hash

§3Choosing the Ordering

  • HashMap / HashSet: no ordering guarantee. Fastest in general.
  • LinkedHashMap / LinkedHashSet: iterate in insertion order, at small extra cost.
  • TreeMap / TreeSet: keep keys sorted, with O(log n) operations, and offer range queries.
TreeMap<Integer, String> grades = new TreeMap<>();
grades.put(90, "A"); grades.put(80, "B"); grades.put(70, "C");
grades.floorEntry(85);                    // 80=B (greatest key <= 85)
grades.ceilingKey(85);                    // 90
grades.firstKey();                        // 70
grades.headMap(80);                       // keys below 80

Never rely on HashMap iteration order; it can change between runs and Java versions. TreeMap keys must be mutually comparable or you must supply a Comparator.

A missing key is not the same as a null value get returns null both when the key is absent and when it maps to null. Use containsKey, or getOrDefault, when the difference matters. Also, HashMap allows one null key; TreeMap does not.

§4Common Mistakes

MistakeWhat HappensFix
Using a mutable object as a key and then changing itThe entry becomes unfindableUse immutable keys (strings, records)
Overriding equals without hashCode on a key classget fails to find equal keysOverride both, or use a record
Depending on HashMap iteration orderOutput order changes unexpectedlyUse LinkedHashMap or TreeMap when order matters
Unboxing map.get(k) into an int without a checkNullPointerException for a missing keyUse getOrDefault
Using TreeMap when order isn't neededO(log n) cost for nothingUse HashMap
Practice
  1. Count the frequency of each word in a paragraph using merge, then print the words sorted by count.
  2. Write a class with a deliberately bad hashCode that always returns 1, put 50,000 instances in a HashSet, and compare the timing with a good hash.
  3. Use a TreeMap to look up which grade band a score of 83 falls in with floorEntry.
Key takeaways
  • Maps hold unique keys; HashMap is the fast default, LinkedHashMap preserves insertion order, TreeMap sorts.
  • Lookups are fast because hashCode selects a bucket and equals confirms the match.
  • Keys must be immutable with a consistent equals/hashCode, or lookups silently break.
