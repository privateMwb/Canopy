Collections Utilities & Immutable Collections

The Collections class and the List.of family cover common operations, and immutable collections plus defensive copying keep one part of a program from silently corrupting another's data.

§1Collections and Arrays Utilities

java.util.Collections provides static helpers that operate on collections.

List<Integer> nums = new ArrayList<>(List.of(5, 3, 8, 1));
Collections.sort(nums);                  // [1, 3, 5, 8]
Collections.reverse(nums);               // [8, 5, 3, 1]
Collections.shuffle(nums);
Collections.max(nums);                   // 8
Collections.min(nums);                   // 1
Collections.frequency(nums, 3);          // 1
Collections.swap(nums, 0, 1);
Collections.nCopies(3, "ab");            // [ab, ab, ab]
Collections.emptyList();                 // an immutable empty list

List<Integer> sorted = new ArrayList<>(nums);
Collections.sort(sorted);
int idx = Collections.binarySearch(sorted, 5);    // list must be sorted first

§2Immutable Collections

Since Java 9, List.of, Set.of, and Map.of create immutable collections. Any attempt to modify one throws UnsupportedOperationException. They also reject null elements, and Set.of and Map.of throw on duplicate elements or keys. The iteration order of Set.of and Map.of is unspecified.

List<String> fixed = List.of("a", "b", "c");
// fixed.add("d");                        // UnsupportedOperationException
Set<Integer> primes = Set.of(2, 3, 5);
Map<String, Integer> ages = Map.of("Ada", 36, "Grace", 45);
Map<String, Integer> big = Map.ofEntries(Map.entry("a", 1), Map.entry("b", 2));

These are ideal for constants and for return values you don't want callers to change.

§3Views vs. Copies

Several APIs hand back something that looks unmodifiable but is not independent. Collections.unmodifiableList(list) is a read-only view: callers can't change it, but if the original list changes, the view changes too. List.copyOf(list) makes a truly independent immutable copy.

List<String> original = new ArrayList<>(List.of("a", "b"));
List<String> view = Collections.unmodifiableList(original);
List<String> copy = List.copyOf(original);

original.add("c");
System.out.println(view);               // [a, b, c]  — the view sees the change
System.out.println(copy);               // [a, b]     — the copy does not

§4Defensive Copying

If a class stores a collection passed in by a caller, copy it on the way in; if it hands one out, copy it (or return an unmodifiable collection) on the way out. Otherwise the caller keeps a reference to your internals.

public final class Course {
    private final List<String> students;
    public Course(List<String> students) {
        this.students = List.copyOf(students);           // copy in
    }
    public List<String> students() { return students; }  // already immutable: safe to return
}

Immutable collections are shallow: the collection can't change, but the objects inside still can, if they are mutable.

Immutable by default A collection that can't change can't surprise you. Prefer List.of and List.copyOf for data that doesn't need mutation, and your code becomes easier to reason about and safe to share between threads.

§5Common Mistakes

MistakeWhat HappensFix
Calling add on the result of List.ofUnsupportedOperationExceptionCreate an ArrayList from it if you need to modify it
Treating Collections.unmodifiableList as a snapshotIt changes when the underlying list changesUse List.copyOf for an independent copy
Putting null in List.of or Map.ofNullPointerExceptionUse ArrayList/HashMap, or avoid nulls
Storing a caller's list directly in a fieldThe caller can modify your internal state laterCopy it in the constructor
Binary searching an unsorted listMeaningless resultsSort first, or use a hash-based structure
Practice
  1. Write a class with a List<String> field that is safe against changes by callers on both the way in and the way out. Prove it with a test.
  2. Show the difference between Collections.unmodifiableList and List.copyOf by modifying the source after wrapping it.
  3. Use Collections.frequency and Collections.max to find the most common element of a list.
Key takeaways
  • Collections offers sorting, searching, shuffling, and frequency helpers; List.of, Set.of, and Map.of build immutable collections.
  • unmodifiableList is a read-only view, while List.copyOf is an independent copy.
  • Copy collections on the way in and out so a class owns its own state.
