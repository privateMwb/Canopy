ArrayList & LinkedList

ArrayList and LinkedList both implement List, but they are built differently, and for almost every real workload ArrayList is the better choice.

§1The List Interface

A List is an ordered collection that allows duplicates and access by index. Declare variables as List and pick the implementation when you construct it.

import java.util.*;

List<String> names = new ArrayList<>();
names.add("Ada");
names.add("Grace");
names.add(0, "Alan");                  // insert at index: shifts the rest right
names.get(1);                          // "Ada"
names.set(1, "Ida");                   // replace
names.remove("Grace");                 // by value
names.remove(0);                       // by index
names.size();                          // 1
names.contains("Ida");                 // true (linear search, uses equals)
names.indexOf("Ida");                  // 0

Watch the remove overloads on List<Integer>: list.remove(1) removes the element at index 1, while list.remove(Integer.valueOf(1)) removes the value 1.

§2How They Differ

ArrayList stores elements in a resizable array. LinkedList stores each element in a separate node with links to the previous and next nodes.

OperationArrayListLinkedList
get(i)O(1)O(n), walks the chain
add at endO(1) amortizedO(1)
Insert or remove in the middleO(n), shifts elementsO(1) once you hold the node, but finding it is O(n)
Memory per elementCompactExtra object plus two pointers
Cache behaviorExcellent, contiguousPoor, scattered objects

The theoretical advantage of LinkedList for insertions in the middle almost never shows up in practice. You usually have to search for the position first, which costs O(n), and the cache-unfriendly nodes make it slower than shifting a contiguous array. If you need a queue or stack, use ArrayDeque instead of LinkedList.

Deque<Integer> stack = new ArrayDeque<>();
stack.push(1); stack.push(2);
stack.pop();                           // 2

Queue<String> queue = new ArrayDeque<>();
queue.offer("a"); queue.offer("b");
queue.poll();                          // "a"

§3Capacity and Modification

ArrayList grows automatically by allocating a larger array and copying, so if you know roughly how many elements to expect, pass an initial capacity: new ArrayList<>(10_000). Never add or remove elements while iterating with a for-each loop, or you get ConcurrentModificationException; use an Iterator with remove() or removeIf.

List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 4, 5, 6));
nums.removeIf(n -> n % 2 == 0);        // [1, 3, 5]
The default answer Start with ArrayList. Choose ArrayDeque for queue and stack behavior. LinkedList is rarely the right answer and needs a measured reason.

§4Common Mistakes

MistakeWhat HappensFix
Choosing LinkedList because "insertion is O(1)"Slower in practice from node allocation and searchingUse ArrayList and measure if you suspect otherwise
Calling remove(int) when you meant to remove a valueRemoves by index, or throws IndexOutOfBoundsExceptionUse remove(Integer.valueOf(x)) for values
Removing inside a for-each loopConcurrentModificationExceptionUse removeIf or an Iterator
Calling get(i) in a loop over a LinkedListAccidentally O(n²)Iterate with for-each
Declaring ArrayList<String> everywhereLocks callers to one implementationDeclare List<String>
Practice
  1. Fill an ArrayList and a LinkedList with 100,000 integers, then time repeated get(i) across the list. Explain the difference.
  2. Remove all negative numbers from a list with removeIf, then do it again with an explicit Iterator.
  3. Implement a browser-style back/forward history using two ArrayDeque stacks.
Key takeaways
  • ArrayList is an array-backed list with O(1) indexed access and is the default choice.
  • LinkedList is node-based; its theoretical benefits rarely survive real hardware.
  • Use ArrayDeque for stacks and queues, and never modify a list while iterating over it with for-each.
