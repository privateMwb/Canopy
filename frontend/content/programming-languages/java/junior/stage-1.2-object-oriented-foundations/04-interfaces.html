Interfaces

An interface defines a contract that any class can fulfill, so code can depend on what something does rather than what it is.

§1Contracts

An interface lists method signatures with no state. A class declares that it implements the interface and must provide every method. A class can implement many interfaces, which is how Java gets multiple inheritance of type without the problems of multiple inheritance of state.

public interface Notifier {
    void send(String to, String message);
}

public class EmailNotifier implements Notifier {
    @Override public void send(String to, String message) {
        System.out.println("email to " + to + ": " + message);
    }
}
public class SmsNotifier implements Notifier {
    @Override public void send(String to, String message) {
        System.out.println("sms to " + to + ": " + message);
    }
}

§2Program to an Interface

Declare variables, parameters, and return types using the interface, and only name a concrete class where you construct the object. Callers then don't care which implementation they get, and you can swap or fake it.

public class OrderService {
    private final Notifier notifier;                      // depends on the contract
    public OrderService(Notifier notifier) { this.notifier = notifier; }
    public void placed(String customer) { notifier.send(customer, "Order received"); }
}

new OrderService(new EmailNotifier()).placed("ada@example.com");
new OrderService(new SmsNotifier()).placed("+15550100");

java.util.List<String> names = new java.util.ArrayList<>();   // declared as List, not ArrayList

In a test you can pass a tiny fake Notifier that records messages, without sending anything. This idea, called dependency injection, underlies frameworks you will meet later.

§3Default and Static Methods

Interfaces can contain default methods with a body, which lets a library add behavior to an interface without breaking existing implementers, and static methods for helpers.

public interface Greeter {
    String name();
    default String greet() { return "Hello, " + name(); }      // inherited by implementers
    static Greeter of(String n) { return () -> n; }            // factory
}

If two interfaces provide the same default method, the class must override it to resolve the conflict. Interface fields are implicitly public static final constants.

§4Interface or Abstract Class?

Use an interface for a capability that unrelated classes may share, like Comparable or Runnable. Use an abstract class when related classes share fields or partial implementation. In modern Java the default choice is an interface, adding an abstract class only if you need shared state.

Many-to-one is fine, one-to-many is not A class can implement as many interfaces as it likes but extend only one class. That asymmetry is why capabilities are expressed as interfaces.

Practice
  1. Define interface PaymentMethod { boolean pay(long cents); }, implement Card and Cash, and write a Checkout class that only knows PaymentMethod.
  2. Write a test double FakeNotifier that records messages in a list, and use it with OrderService to assert that one message was sent.
  3. Add a default String receipt(long cents) to PaymentMethod and reuse it from both implementations.
Key takeaways
  • An interface is a contract; classes implement it and can implement several.
  • Program to the interface and name the concrete class only when constructing it.
  • Default and static methods let interfaces evolve, but interfaces still have no instance state.
