Classes, Objects & Constructors

A class is a blueprint that bundles data (fields) with behavior (methods), and an object is one instance of it, created with new and reached through a reference.

§1Fields, Methods, and this

A class declares the fields each object carries and the methods that operate on them. Inside an instance method, this refers to the object the method was called on. Each object has its own copy of every instance field.

public class Account {
    private String owner;
    private long balanceCents;

    public Account(String owner, long openingCents) {   // constructor
        this.owner = owner;               // 'this' disambiguates field from parameter
        this.balanceCents = openingCents;
    }

    public void deposit(long cents) { this.balanceCents += cents; }
    public long balance() { return balanceCents; }
}

Account a = new Account("Ada", 5_000);
Account b = new Account("Grace", 100);
a.deposit(250);                          // only a changes

§2Constructors

A constructor has the class's name and no return type. It runs once, as part of new, and its job is to leave the object in a valid state. If you write no constructor, Java supplies an empty default one; as soon as you write any constructor, the default disappears. Constructors can be overloaded and can call each other with this(...).

public Account(String owner) {
    this(owner, 0);                      // delegate to the main constructor
}

Fields you don't initialize get defaults (0, false, null), but local variables do not, and the compiler rejects reading one before it is assigned.

§3References, Identity, and static

A variable like a holds a reference, not the object. Copying the variable copies the reference, so two variables can point to one object. An object with no references left becomes eligible for garbage collection; you never free memory yourself.

Account x = new Account("Ada");
Account y = x;                          // same object
y.deposit(100);                         // x.balance() is 100 as well
Account z = null;
z.deposit(1);                           // NullPointerException

A static member belongs to the class itself, not to any object. Use static for constants and utility methods, but be careful with mutable static fields because they act as global state.

public class Counter {
    private static int created = 0;          // one shared value
    public static final int MAX = 100;       // constant
    public Counter() { created++; }
    public static int created() { return created; }
}
Objects live on the heap, references live in variables new allocates the object; the variable holds only a pointer to it. That one fact explains aliasing, == vs. equals, null, and why passing an object to a method lets the method change it.

§4Common Mistakes

MistakeWhat HappensFix
Assigning a field to itself: owner = owner; in a constructorThe parameter shadows the field, so the field stays nullWrite this.owner = owner;
Calling a method on a null referenceNullPointerExceptionMake sure the reference is set; validate arguments in the constructor
Writing a constructor and still calling new Foo()constructor Foo in class Foo cannot be appliedAdd a no-argument constructor or pass the required arguments
Using a mutable static field for per-object dataEvery object shares and overwrites itMake per-object data an instance field
Expecting b = a to copy an objectBoth names refer to one objectCreate a new object or write a copy method
Practice
  1. Write a Rectangle class with width and height, a constructor, and methods area() and perimeter(). Create three and print their areas.
  2. Add a second constructor Rectangle(double side) that builds a square by calling this(side, side).
  3. Write a snippet that creates two references to one Account, changes it via one, and prints it via the other. Explain the output.
Key takeaways
  • A class defines fields and methods; each new creates an object with its own field values.
  • Constructors establish a valid initial state, and this refers to the current object.
  • Variables hold references, so assignment aliases objects; static members belong to the class.
