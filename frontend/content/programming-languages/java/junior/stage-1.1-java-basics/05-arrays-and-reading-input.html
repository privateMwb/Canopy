Arrays & Reading Input

Arrays are fixed-size, zero-indexed containers, and main(String[] args) and Scanner are how a console program gets data from the outside world.

§1Arrays

An array has a fixed length set when it is created, holds elements of one type, and is a reference type, so assigning one array variable to another shares the same array. Elements start at the default value: 0, false, or null.

int[] scores = new int[5];              // [0, 0, 0, 0, 0]
int[] primes = {2, 3, 5, 7};
scores[0] = 90;
System.out.println(primes.length);      // 4 (a field, not a method)

int[][] grid = new int[3][4];           // 3 rows, 4 columns
grid[1][2] = 7;

int[] alias = primes;                   // same array, not a copy
int[] copy = java.util.Arrays.copyOf(primes, primes.length);
alias[0] = 99;                          // primes[0] is now 99, copy[0] is still 2

Reading outside the bounds throws ArrayIndexOutOfBoundsException at runtime; Java never reads past the end silently. The java.util.Arrays class provides the helpers you will use constantly.

import java.util.Arrays;

int[] a = {5, 2, 9, 1};
Arrays.sort(a);                              // in place: [1, 2, 5, 9]
System.out.println(Arrays.toString(a));      // [1, 2, 5, 9] (printing 'a' directly shows a hash)
int pos = Arrays.binarySearch(a, 5);         // 2 (array must be sorted)
System.out.println(Arrays.equals(a, new int[]{1, 2, 5, 9}));   // true; a.equals(...) would be false

§2Command-Line Arguments

The String[] args parameter of main holds whatever follows the class name on the command line. Everything arrives as a String, so numbers must be parsed.

public class Add {
    public static void main(String[] args) {
        if (args.length != 2) {
            System.err.println("usage: java Add <a> <b>");
            System.exit(1);
        }
        int a = Integer.parseInt(args[0]);     // throws NumberFormatException if not a number
        int b = Integer.parseInt(args[1]);
        System.out.println(a + b);
    }
}

§3Reading Input with Scanner

Scanner reads tokens from a stream, typically System.in.

import java.util.Scanner;

try (Scanner in = new Scanner(System.in)) {
    System.out.print("Name: ");
    String name = in.nextLine();
    System.out.print("Age: ");
    int age = in.nextInt();
    System.out.println(name + " is " + age);
}

Use hasNextInt() or hasNextLine() to check before reading, so bad or missing input does not crash the program.

The nextInt() / nextLine() trap nextInt() reads the number but leaves the newline in the buffer, so a following nextLine() returns an empty string. Either call nextLine() once to discard the rest of the line, or read every line with nextLine() and parse it yourself.

Practice
  1. Write a program that reads integers until the user types done, then prints the min, max, and average, using hasNextInt() to detect the end.
  2. Write int[] reverse(int[] a) that returns a new reversed array without modifying the input.
  3. Change the Add program so that bad input prints a friendly message rather than a stack trace.
Key takeaways
  • Arrays are fixed-size reference types; use Arrays for printing, sorting, copying, and comparing.
  • Command-line arguments arrive as strings in args and must be validated and parsed.
  • Scanner reads console input, but mixing nextInt() and nextLine() needs care.
