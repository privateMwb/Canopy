Strings & Text

A String is an immutable sequence of characters, which makes it safe to share but means that building text in a loop needs StringBuilder.

§1Immutability

Once created, a String never changes. Methods like toUpperCase or replace return a new string and leave the original alone. Forgetting to use the returned value is a classic bug.

String s = "hello";
s.toUpperCase();                   // result discarded: s is still "hello"
s = s.toUpperCase();               // now s refers to "HELLO"

String t = "  Ada Lovelace ";
t.trim().toLowerCase().split(" ");     // chaining works because each call returns a String
"a,b,,c".split(",");                   // ["a", "b", "", "c"]
"Ada".charAt(0);                       // 'A'
"Ada".substring(1);                    // "da"
"banana".indexOf("na");                // 2
"Ada".isBlank();                       // false

§2Comparing Strings

== compares whether two variables point at the same object, not whether the text matches. Use equals. String literals are interned (shared), which is why == sometimes appears to work and then fails on a string built at runtime.

String a = "java";
String b = "ja" + "va";                 // compile-time constant: same interned object
String c = new String("java");          // a new object

System.out.println(a == b);             // true (by accident of interning)
System.out.println(a == c);             // false
System.out.println(a.equals(c));        // true
System.out.println("Java".equalsIgnoreCase(a));   // true
System.out.println("yes".equals(input));          // safe even if input is null

§3Building Text

Each + in a loop creates a new string and copies everything, so repeated concatenation is quadratic. A StringBuilder is mutable and appends in place.

StringBuilder sb = new StringBuilder();
for (int i = 0; i < 5; i++) {
    sb.append(i).append(',');
}
sb.setLength(sb.length() - 1);          // drop trailing comma
String csv = sb.toString();             // "0,1,2,3,4"

String msg = String.format("%s scored %.1f (%d%%)", "Ada", 91.456, 91);
String joined = String.join("|", "a", "b", "c");
String repeated = "ab".repeat(3);        // "ababab"

For multi-line text such as JSON or SQL, text blocks (""") keep the layout readable and strip common indentation:

String json = """
    {
      "name": "Ada",
      "role": "engineer"
    }
    """;
Strings and Unicode A char is a 16-bit UTF-16 unit, so characters outside the basic range (many emoji) take two chars. length() counts UTF-16 units, not visible characters. Use codePoints() if you need real characters.

§4Common Mistakes

MistakeWhat HappensFix
Comparing strings with ==Works for literals, fails for runtime-built stringsAlways use equals (or equalsIgnoreCase)
Ignoring the return value of toUpperCase, trim, etc.The original string is unchangedAssign the result: s = s.trim()
Concatenating in a large loop with +Slow, with lots of garbageUse a StringBuilder
Calling input.equals("yes") on a possibly null valueNullPointerExceptionPut the literal first: "yes".equals(input)
Assuming length() equals visible charactersWrong counts for emoji and some scriptsCount with codePoints() when it matters
Practice
  1. Write isPalindrome(String s) that ignores case and spaces, using StringBuilder.reverse() or a two-pointer loop.
  2. Write a method that counts the words in a sentence, handling multiple spaces. Try split with a regex, then explain why split(" ") gets it wrong.
  3. Print a three-line receipt using a text block and String.format.
Key takeaways
  • Strings are immutable; string methods return new strings.
  • Compare text with equals, never ==.
  • Use StringBuilder for building text in loops and text blocks for multi-line literals.
