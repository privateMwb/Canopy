The JDK, the JVM & the Compile-Run Cycle

Java source is compiled to bytecode, and the JVM runs that bytecode, which is why the same .class file runs on any operating system with a JVM.

§1Three Names, Three Jobs

The JDK (Java Development Kit) is what you install to write Java. It contains javac (the compiler), java (the launcher), jar, javadoc, and other tools. The JRE is the runtime part; the JVM is the virtual machine inside it that actually executes code. Modern distributions ship only the JDK, so in practice you install one thing.

Java source files end in .java. The compiler turns each class into a .class file of bytecode, a compact instruction set for an imaginary machine. The JVM loads that bytecode and either interprets it or compiles hot paths to native machine code at runtime (the JIT, covered in the senior track).

§2Compile and Run by Hand

// Hello.java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, " + (args.length > 0 ? args[0] : "world"));
    }
}
javac Hello.java          # produces Hello.class
java Hello Ada            # runs it: Hello, Ada
java Hello.java Ada       # single-file mode: compile in memory and run

javac takes a file name; java takes a class name (no .class). Mixing these up is the most common first-day error. The launcher finds the entry point by looking for public static void main(String[] args); recent JDKs also accept a simpler instance main in "unnamed class" source files, but the classic form is what you will see everywhere.

§3The Classpath

When java needs a class, it searches the classpath: a list of directories and .jar files. The default is the current directory. If your code depends on a library, you point to it with -cp.

javac -cp lib/gson.jar -d out src/App.java
java  -cp out:lib/gson.jar App      # use ; instead of : on Windows

-d out tells javac where to put the .class files. Build tools (a later lesson) manage all of this for you, but you should understand what they are doing underneath.

Why "write once, run anywhere" works Java compiles to bytecode, not to a specific CPU. Each platform has its own JVM that translates bytecode for the local machine. Your .class file is portable; the JVM is not.

Practice
  1. Write Hello.java, compile it with javac, and look at the .class file that appears. Run it with and without an argument.
  2. Run javap -c Hello and find the line that calls println. You are looking at the bytecode the JVM executes.
  3. Move Hello.class into a folder named out and run it again using -cp out.
Key takeaways
  • javac compiles .java source to .class bytecode; java starts a JVM that runs it.
  • The classpath tells the JVM where to find classes; build tools exist largely to manage it.
  • Bytecode is portable across platforms because each platform provides its own JVM.
