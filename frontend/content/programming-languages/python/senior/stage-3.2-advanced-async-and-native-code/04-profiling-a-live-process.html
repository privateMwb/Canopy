Profiling a Live Process

Sampling profilers such as py-spy attach to a running Python process and show where time goes, without restarting or modifying it.

§1Why Sampling

Deterministic profilers like cProfile instrument every call, which slows the program and requires starting it with the profiler. A sampling profiler instead looks at the program's call stack many times per second and counts which functions appear most often. The overhead is small, so it's safe to point at a misbehaving production process.

§2py-spy

py-spy runs as a separate process and reads the target's memory, so it needs no code changes.

python -m pip install py-spy

py-spy top --pid 12345                      # live "top"-style view of hot functions
py-spy dump --pid 12345                     # one-shot stack of every thread (great for hangs)
py-spy record -o profile.svg --pid 12345    # record for a while, write a flame graph
py-spy record -d 30 -r 100 -o prof.svg -- python app.py    # profile a new run

Attaching typically requires the same user or elevated privileges (on Linux, ptrace restrictions may apply; in containers you may need to grant the relevant capability). py-spy dump answers "what is it doing right now?", the first question during a hang.

§3Reading a Flame Graph

In a flame graph, each box is a function; width shows the share of samples where it was on the stack; vertical position shows call depth (callers below, callees above). Look for wide boxes at the top: functions where time is actually spent. Wide boxes lower down only mean "everything runs under this."

main
 └─ handle_request ─────────────────────── (100%)
     ├─ parse_body ────── (8%)
     ├─ load_user ──────────────────── (30%)
     │    └─ socket.recv ───────────── (28%)   <- waiting on the network
     └─ render ──────────────────── (55%)
          └─ re.compile ─────────── (50%)      <- recompiling a regex per request

Compare idle and active samples: py-spy by default hides idle threads, and --idle includes them, which is what you want when diagnosing a service that is slow because it's waiting. --native shows C frames, which helps when time disappears into an extension.

§4Memory

For memory growth, use tools that track allocations.

import tracemalloc
tracemalloc.start(10)               # keep 10 frames of traceback per allocation
# ... later, from a debug endpoint or signal handler ...
snap = tracemalloc.take_snapshot()
for s in snap.statistics("traceback")[:3]:
    print(s)

memray and scalene provide richer memory profiling, including native allocations and flame graphs, at higher overhead. tracemalloc adds noticeable overhead, so enable it deliberately and briefly. Sometimes the cause is outside Python's view, such as a C extension, so compare with operating-system numbers (ps, /proc/<pid>/status).

§5A Safe Production Routine

  • Start with py-spy dump to see current stacks; then record for 30 to 60 seconds under real load.
  • Capture a profile of a healthy instance for comparison.
  • Save the flame graph with the incident notes, and change one thing at a time.
The key insight Production behavior depends on production load. A sampling profiler lets you observe the real thing, rather than a reproduction that may not have the problem.

§6Common Mistakes

MistakeWhat HappensFix
Reading a flame graph's width as time per callMisreads where the cost isWidth is share of samples; focus on wide boxes at the top
Profiling only active samples for a latency problemMisses time spent waiting on I/O or locksInclude idle samples (--idle) and check what threads wait on
Leaving tracemalloc enabled permanentlySlower service and higher memory useEnable it temporarily for investigation
Practice
  1. Run a small CPU-heavy script, attach py-spy top from another terminal, and identify the top function.
  2. Record a flame graph of a program that makes a blocking call in an async handler, and point to the wide frame that shows the stall.
Key takeaways
  • Sampling profilers like py-spy attach to live processes with low overhead and no code changes.
  • py-spy dump shows stacks now; record produces flame graphs; read wide boxes at the top.
  • Use tracemalloc or memray for memory, and enable them deliberately.
