Context Managers & contextlib

The with statement guarantees setup and teardown around a block, and you can build your own with a class or a generator.

§1What with Does

with expr as name: calls expr.__enter__() at the start, binds its result to name, and calls __exit__() when the block ends, even if an exception occurred.

with open("data.txt", encoding="utf-8") as f:
    data = f.read()
# the file is closed here, no matter what happened above

That guarantee makes with the right tool for files, locks, database transactions, temporary state, and timing.

§2Writing One as a Class

import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        return False             # False: don't suppress exceptions

with Timer() as t:
    sum(range(5_000_000))
print(f"{t.elapsed:.3f}s")

__exit__ receives the exception details (all None if the block succeeded). Returning a truthy value suppresses the exception; do that only on purpose.

§3The Easy Way: @contextmanager

contextlib.contextmanager turns a generator with a single yield into a context manager. Code before yield is setup, and code after is teardown, so put the teardown in finally.

from contextlib import contextmanager
import os

@contextmanager
def working_directory(path):
    previous = os.getcwd()
    os.chdir(path)
    try:
        yield
    finally:
        os.chdir(previous)       # always restored

with working_directory("/tmp"):
    print(os.getcwd())

Anything yielded becomes the as target: yield f gives with opened(...) as f.

§4More from contextlib

from contextlib import suppress, closing, ExitStack, redirect_stdout
import io

with suppress(FileNotFoundError):        # ignore a specific error
    os.remove("maybe-missing.tmp")

buf = io.StringIO()
with redirect_stdout(buf):               # capture print output
    print("captured")

with ExitStack() as stack:               # a dynamic number of resources
    files = [stack.enter_context(open(p, encoding="utf-8")) for p in paths]

Several managers can share one statement: with open(a) as fa, open(b) as fb:.

The key insight Use with whenever "undo this later" is part of an operation: closing, unlocking, committing, restoring. If you notice yourself writing try: ... finally: cleanup(), a context manager is likely the cleaner form.

§5Common Mistakes

MistakeWhat HappensFix
Skipping try/finally around yield in @contextmanagerTeardown is skipped when the block raisesWrap the yield in try ... finally
Returning True from __exit__ by accidentExceptions are silently swallowedReturn False or None unless suppression is intended
Using a file after its with blockValueError: I/O operation on closed fileFinish all reads inside the block
Practice
  1. Write a context manager temporary_env(name, value) that sets an environment variable and restores the old state on exit.
  2. Write a Transaction class-based manager that prints "commit" on success and "rollback" if the block raises.
Key takeaways
  • with calls __enter__ on entry and __exit__ on exit, even when errors occur.
  • @contextmanager builds a manager from a generator: setup, yield, teardown in finally.
  • contextlib provides suppress, closing, ExitStack, and more for common patterns.
