asyncio Fundamentals

asyncio runs thousands of waiting tasks on a single thread by switching between coroutines whenever one hits an await.

§1Coroutines and await

async def defines a coroutine function; calling it returns a coroutine object that does nothing until it is awaited or scheduled. await pauses the current coroutine until the awaited operation finishes, letting the event loop run others in the meantime.

import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)         # non-blocking wait
    return f"{name} done"

async def main():
    result = await fetch("a", 1)
    print(result)

asyncio.run(main())                    # start the event loop

§2Running Things Concurrently

Awaiting one after another is sequential. To overlap waits, create tasks or use gather / TaskGroup.

async def main():
    start = asyncio.get_running_loop().time()

    results = await asyncio.gather(
        fetch("a", 1), fetch("b", 1), fetch("c", 1)
    )
    print(results, f"{asyncio.get_running_loop().time() - start:.1f}s")   # about 1s

# Python 3.11+: structured concurrency
async def main2():
    async with asyncio.TaskGroup() as tg:
        t1 = tg.create_task(fetch("a", 1))
        t2 = tg.create_task(fetch("b", 2))
    print(t1.result(), t2.result())    # after BOTH finish

A TaskGroup waits for all its tasks and, if one fails, cancels the rest, so errors don't leak.

§3Async Libraries and Timeouts

Network calls need an async-aware library: aiohttp, httpx.AsyncClient, or asyncio's own streams. The standard requests library blocks the whole loop.

import httpx

async def get_status(url):
    async with httpx.AsyncClient(timeout=5) as client:
        r = await client.get(url)
        return r.status_code

async def main():
    try:
        async with asyncio.timeout(3):             # 3.11+
            print(await get_status("https://example.com"))
    except TimeoutError:
        print("too slow")

§4When asyncio Beats Threads

asyncio shines with many concurrent, mostly idle connections (thousands of sockets) because a task costs far less than a thread, and switch points are explicit, so there are fewer race conditions. But it only works if everything in the path cooperates: one blocking call (a plain time.sleep, a CPU-heavy loop) freezes every task.

async def bad():
    time.sleep(2)          # blocks the entire event loop!

async def good():
    await asyncio.sleep(2)

# For unavoidable blocking calls:
result = await asyncio.to_thread(blocking_function, arg)    # 3.9+
The key insight async doesn't make code faster by itself. It makes waiting cheap by letting one thread do useful work while many operations are pending. If nothing is waiting, there's nothing to gain.

§5Common Mistakes

MistakeWhat HappensFix
Calling a coroutine without awaitRuntimeWarning: coroutine was never awaited, and nothing runsawait it, or schedule it with a task
Using time.sleep or requests inside async defEvery task stallsUse asyncio.sleep, an async client, or asyncio.to_thread
Awaiting in a loop (for u in urls: await get(u))Requests run one at a timeUse gather or a TaskGroup
Practice
  1. Fetch five URLs concurrently with TaskGroup and print how long the total takes compared to doing them one by one.
  2. Add a 2-second timeout to a slow coroutine using asyncio.timeout, and handle the TimeoutError.
Key takeaways
  • await pauses a coroutine and lets the event loop run other work.
  • Use gather or TaskGroup to overlap waits; awaiting in a loop is sequential.
  • Never block the event loop; offload blocking calls with asyncio.to_thread.
