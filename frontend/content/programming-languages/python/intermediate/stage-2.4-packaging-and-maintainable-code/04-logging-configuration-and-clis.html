Logging, Configuration & CLIs

Use the logging module instead of print, read settings from the environment, and expose your program through a proper command-line interface.

§1Logging

logging gives levels, timestamps, destinations, and per-module control. Libraries create a logger and let the application configure it.

import logging

log = logging.getLogger(__name__)      # one logger per module

def process(order_id):
    log.info("processing order %s", order_id)
    try:
        ...
    except Exception:
        log.exception("order %s failed", order_id)   # includes the traceback
        raise

Levels from least to most severe: DEBUG, INFO, WARNING, ERROR, CRITICAL. In the application's entry point, configure once:

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s",
)

Pass values as arguments (log.info("x=%s", x)), not as a pre-formatted string, so formatting only happens if the message is actually emitted.

§2Configuration

Separate configuration from code, and read it from the environment, following the "twelve-factor" idea. Secrets must never be committed.

import os
from dataclasses import dataclass

@dataclass(frozen=True)
class Settings:
    database_url: str
    debug: bool = False
    timeout: float = 5.0

def load_settings() -> Settings:
    try:
        return Settings(
            database_url=os.environ["DATABASE_URL"],      # required
            debug=os.environ.get("DEBUG", "0") == "1",    # optional
            timeout=float(os.environ.get("TIMEOUT", "5")),
        )
    except KeyError as missing:
        raise SystemExit(f"missing required setting: {missing}")

For files, tomllib (built in, 3.11+) reads TOML. Pydantic Settings can load and validate configuration from environment variables and .env files.

§3Command-Line Interfaces

argparse is in the standard library; click and typer are popular third-party options with less boilerplate.

import argparse

def main(argv=None):
    parser = argparse.ArgumentParser(description="Summarize a log file.")
    parser.add_argument("path", help="log file to read")
    parser.add_argument("-n", "--top", type=int, default=5, help="rows to show")
    parser.add_argument("-v", "--verbose", action="store_true")
    args = parser.parse_args(argv)

    logging.basicConfig(level=logging.DEBUG if args.verbose else logging.INFO)
    ...
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
import typer

app = typer.Typer()

@app.command()
def summarize(path: str, top: int = 5, verbose: bool = False):
    """Summarize a log file."""
    ...

if __name__ == "__main__":
    app()

Accepting argv as a parameter makes main testable: assert main(["file.log", "-n", "3"]) == 0. Return meaningful exit codes (0 for success, nonzero for failure), print results to stdout and diagnostics to stderr.

The key insight Libraries should log but never configure logging, and should never call print or sys.exit. Only the application's entry point decides where logs go, how they look, and when the process exits.

§4Common Mistakes

MistakeWhat HappensFix
Using print for diagnosticsNo levels, no timestamps, impossible to silence selectivelyUse logging with getLogger(__name__)
Hard-coding secrets or URLs in sourceLeaks and per-environment editsRead from environment variables or a secret store
Calling logging.basicConfig inside a libraryOverrides the application's choicesConfigure only in main
Practice
  1. Add logging to a script with INFO for progress and DEBUG for details, controlled by a --verbose flag.
  2. Build a small CLI with argparse or typer that takes a file path and an option, then test main() by passing argv directly.
Key takeaways
  • Use logging.getLogger(__name__) in modules and configure logging once in the entry point.
  • Read configuration from the environment and fail fast when required values are missing.
  • Make main(argv) testable and use exit codes, stdout, and stderr properly.
