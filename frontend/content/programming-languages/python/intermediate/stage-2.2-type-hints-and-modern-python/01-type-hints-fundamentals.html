Type Hints Fundamentals

Type hints annotate what your code expects and returns; Python ignores them at runtime, but tools and teammates rely on them.

§1Annotating Functions and Variables

Parameters get : type and the return value gets -> type. Variables can be annotated at assignment.

def greet(name: str, times: int = 1) -> str:
    return ("Hello, " + name + "! ") * times

count: int = 0
names: list[str] = []
scores: dict[str, float] = {"ana": 91.5}
point: tuple[int, int] = (3, 4)
coords: tuple[float, ...] = (1.0, 2.0, 3.0)     # variable length

Built-in generics such as list[str] and dict[str, int] work from Python 3.9; before that, you imported List and Dict from typing.

§2Optional, Unions, and Any

A value that might be None or one of several types uses | (Python 3.10+; earlier, Optional[X] and Union[X, Y]).

from typing import Any, Callable

def find_user(user_id: int) -> str | None:       # may return None
    ...

def parse(value: int | str) -> int:
    return int(value)

def apply(func: Callable[[int], int], x: int) -> int:
    return func(x)

def log(payload: Any) -> None:                    # opt out of checking
    print(payload)

Prefer a precise type or a Protocol (next lesson) over Any, which switches checking off for everything it touches.

§3Hints Don't Do Anything at Runtime

The interpreter stores annotations but does not enforce them. This runs without complaint:

def double(n: int) -> int:
    return n * 2

print(double("ab"))        # abab : no error from Python

The value of hints comes from static checkers (mypy, pyright), editors that autocomplete from them, and documentation. They catch mismatches before the code runs.

§4Useful Building Blocks

from typing import Literal, TypedDict, Final, NamedTuple

Mode = Literal["r", "w", "a"]                     # only these exact values

class Movie(TypedDict):                           # dict with known keys
    title: str
    year: int

MAX_RETRIES: Final = 3                            # checker flags reassignment

def open_file(path: str, mode: Mode = "r") -> None: ...

m: Movie = {"title": "Alien", "year": 1979}

A class name is also a type, so def f(acct: Account) -> Account works. If you refer to a class not yet defined, quote it ("Account") or add from __future__ import annotations.

The key insight Think of type hints as checked documentation. They cost little, never change behavior, and make a function's contract visible to people and tools at the point of use.

§5Common Mistakes

MistakeWhat HappensFix
Expecting Python to raise on a wrong typeBad values flow through unnoticedRun a type checker, and validate real input at boundaries
Using Any everywhereThe checker finds nothingUse specific types, object, or a Protocol
Writing list instead of list[int]The element type is uncheckedParametrize collections
Practice
  1. Annotate a function average(values) that takes a list of numbers and returns a float, or None for an empty list.
  2. Write a TypedDict for a user record with id, name, and optional email, and use it as a function parameter type.
Key takeaways
  • Use param: T and -> T; T | None marks values that may be absent.
  • Hints aren't enforced at runtime; static checkers and editors use them.
  • Literal, TypedDict, and Final express more precise contracts than plain types.
