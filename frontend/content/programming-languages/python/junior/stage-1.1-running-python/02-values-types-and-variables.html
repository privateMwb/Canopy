Values, Types & Variables

A Python variable is a name bound to an object, and the type belongs to the object, not the name.

§1Names Point at Objects

Assignment doesn't copy a value into a box. It binds a name to an object. You can rebind the same name to an object of a different type at any time, which is what "dynamically typed" means. Objects, however, always have exactly one type.

x = 42
print(type(x))     # <class 'int'>
x = "forty-two"    # rebinding: same name, different object
print(type(x))     # <class 'str'>

Floats are binary approximations, so compare them with math.isclose(a, b) rather than ==. For exact decimal arithmetic such as money, use decimal.Decimal.

import math
print(0.1 + 0.2 == 0.3)               # False
print(math.isclose(0.1 + 0.2, 0.3))   # True
print(7 // 2, 7 % 2, 7 / 2)           # 3 1 3.5

§3Dynamic, but Strongly Typed

Python won't guess when you mix incompatible types: "3" + 4 raises TypeError. Convert explicitly with int(), float(), str(). Use type(x) to inspect and isinstance(x, int) to check, which also accepts subclasses.

age = int("30")          # str -> int
label = "Age: " + str(age)
print(isinstance(True, int))   # True

Naming convention: snake_case for variables and functions, UPPER_CASE for constants.

The key insight When you write b = a, no copy is made. Both names point at the same object. This is invisible for numbers and strings (which can't change) and matters a great deal for lists, covered in Stage 1.2.

Practice
  1. Predict the output of type(3 / 1), type(3 // 1), and type(True + 1), then check in the REPL.
  2. Convert the string "12.5" into an int. What error do you get, and what two-step conversion works?
Key takeaways
  • Names bind to objects; the type lives on the object, so one name can point at different types over time.
  • Python is dynamically typed but strongly typed: mixed types raise errors instead of converting silently.
  • Use == for value comparison and is only for identity checks like x is None.
