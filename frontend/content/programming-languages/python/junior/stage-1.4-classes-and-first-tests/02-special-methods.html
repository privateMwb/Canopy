Special Methods

Methods with double-underscore names let your objects work with print, ==, len, for, and the other built-in syntax.

§1Making Objects Printable

Python calls __repr__ to get an unambiguous developer view (shown in the REPL and in containers) and __str__ for friendly output used by print and str(). If you define only one, define __repr__.

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Point({self.x!r}, {self.y!r})"

p = Point(1, 2)
print(p)            # Point(1, 2)  (falls back to __repr__)
print([p])          # [Point(1, 2)]

Without __repr__, you'd see something like <__main__.Point object at 0x...>, which tells you nothing.

§2Equality and Hashing

By default, == compares identity. Define __eq__ to compare by value. If you define __eq__ on a mutable class, Python makes instances unhashable unless you also define __hash__.

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):
        return hash((self.x, self.y))     # only safe if x, y don't change

print(Point(1, 2) == Point(1, 2))         # True
print(len({Point(1, 2), Point(1, 2)}))    # 1

Returning NotImplemented (not False) lets Python try the other operand's method, which is the correct protocol.

§3Behaving Like a Container

class Playlist:
    def __init__(self, songs):
        self._songs = list(songs)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        return self._songs[index]

    def __iter__(self):
        return iter(self._songs)

    def __contains__(self, song):
        return song in self._songs

pl = Playlist(["a", "b", "c"])
print(len(pl), pl[0], "b" in pl)     # 3 a True
for s in pl:
    print(s)

Operators have special methods too: __add__ for +, __lt__ for <, __bool__ for truthiness, and __call__ to make an instance callable.

The key insight Special methods are Python's protocols. You don't inherit from a "Sequence" class to get len(); you define __len__ and the built-in just works. These are called "dunder" (double underscore) methods.

§4Common Mistakes

MistakeWhat HappensFix
No __repr__Debug output like <Point object at 0x7f...>Add a __repr__ that shows the constructor call
Defining __eq__ without thinking about __hash__Instances become unhashable, so they fail in sets and as dict keysDefine __hash__ consistently, or keep the class immutable
Returning False for a wrong-type comparison in __eq__Blocks reflected comparisonReturn NotImplemented
Practice
  1. Add __repr__, __eq__, and __add__ to a Vector2 class so Vector2(1, 2) + Vector2(3, 4) works.
  2. Write a Deck class that supports len(), indexing, and iteration.
Key takeaways
  • __repr__ is for developers and __str__ for end users; always define __repr__.
  • Define __eq__ for value equality, and keep __hash__ consistent with it.
  • __len__, __iter__, and __getitem__ make your class work with built-in syntax.
