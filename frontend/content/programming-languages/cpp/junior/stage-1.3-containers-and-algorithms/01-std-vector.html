std::vector

std::vector is the default container: a growable array whose elements sit side by side in memory, with a few rules about growth you must know.

§1Size, Capacity, and Growth

A vector owns a heap buffer. Size is how many elements it holds; capacity is how many fit before it must reallocate. When it runs out of room it allocates a larger buffer (typically 1.5x to 2x), moves the elements over, and frees the old one.

#include <vector>
std::vector<int> v;
v.reserve(100);                    // capacity >= 100, size still 0
for (int i = 0; i < 100; ++i) v.push_back(i);   // no reallocation
std::cout << v.size() << ' ' << v.capacity() << '\n';

std::vector<int> a(5, 7);          // five 7s: parentheses mean (count, value)
std::vector<int> b{5, 7};          // braces mean the elements 5 and 7

push_back is amortized O(1). reserve when you know the final size avoids repeated reallocation.

§2Access and Modification

v[2];            // unchecked
v.at(2);         // throws std::out_of_range
v.front(); v.back();
v.pop_back();
v.insert(v.begin() + 1, 42);     // O(n): shifts later elements
v.erase(v.begin());              // O(n)
v.clear();                       // size 0, capacity unchanged

Use emplace_back(args...) to construct an element in place rather than building a temporary and copying it.

std::vector<std::pair<int, std::string>> items;
items.emplace_back(1, "one");

§3Invalidated Iterators

Iterators, pointers, and references into a vector are tied to its buffer. A reallocation invalidates all of them, and an insert or erase invalidates everything at or after the change point.

std::vector<int> v{1, 2, 3};
int& first = v[0];
v.push_back(4);          // may reallocate
first = 10;              // DANGLING: first may point at freed memory

for (auto it = v.begin(); it != v.end(); ++it)
    if (*it == 2) v.erase(it);     // BUG: it is invalid after erase

The safe removal idiom is erase-remove (or std::erase_if in C++20):

std::erase_if(v, [](int x) { return x % 2 == 0; });

§4When Not to Use a Vector

Inserting or erasing in the middle is linear, and std::vector<bool> is a special packed type that doesn't behave like other vectors. Otherwise, start with std::vector; contiguous memory is fast on modern CPUs, often beating "theoretically better" structures.

The key insight Never hold an iterator, pointer, or reference into a vector across an operation that can grow or shrink it. Re-fetch after the change, or use indices.

§5Common Mistakes

MistakeWhat HappensFix
Keeping a reference to an element, then calling push_backReallocation leaves a dangling referenceUse an index, or reserve up front
Erasing inside a range-for loopInvalid iterator, undefined behaviorUse std::erase_if or the erase-remove idiom
Mixing up vector<int>(5, 7) and vector<int>{5, 7}Five elements vs. twoRemember: parentheses count, braces list
Practice
  1. Fill a vector with 1 to 20 and use std::erase_if to remove the multiples of 3.
  2. Print size() and capacity() after each push_back for 20 pushes. Where does capacity jump?
  3. Produce a dangling reference with push_back and catch it with -fsanitize=address.
Key takeaways
  • A vector stores elements contiguously; size is the count, capacity is the room.
  • Growing or erasing can invalidate every iterator, pointer, and reference into it.
  • Use reserve when the size is known and std::erase_if to remove by condition.
