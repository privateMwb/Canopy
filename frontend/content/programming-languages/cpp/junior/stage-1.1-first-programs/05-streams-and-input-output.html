Streams & Input/Output

C++ reads and writes through stream objects, and robust programs check that every read actually succeeded.

§1Output with std::cout

std::cout is the standard output stream, written with <<. '\n' ends a line; std::endl also flushes the buffer, which is much slower in a loop and rarely needed.

#include <iostream>
#include <iomanip>
int main() {
    int items{3};
    double price{4.5};
    std::cout << "Items: " << items << '\n';
    std::cout << std::fixed << std::setprecision(2)
              << "Total: " << items * price << '\n';        // Total: 13.50
    std::cerr << "warning: this goes to stderr\n";
}

Manipulators like std::fixed, std::setprecision, and std::setw change how later values print; precision and fixed stay set until you change them. Since C++20 std::format is often clearer, covered in a later lesson.

§2Input with std::cin

>> reads whitespace-separated values and converts them to the target type. If the conversion fails, the stream enters a fail state and every later read does nothing until you clear it.

int age;
std::cout << "Age? ";
if (!(std::cin >> age)) {
    std::cerr << "not a number\n";
    std::cin.clear();                                         // reset the error flags
    std::cin.ignore(10000, '\n');                             // discard the bad line
}

Checking the result of a read (if (std::cin >> x)) is the single most important input habit.

§3Reading Lines

>> stops at whitespace, so it cannot read "Ada Lovelace" into one string. Use std::getline for whole lines, and read line by line in a loop for files or piped input.

std::string line;
while (std::getline(std::cin, line)) {          // false at end of input
    std::cout << "got: " << line << '\n';
}

Mixing >> and getline is a classic trap: >> leaves the newline in the buffer, so the next getline returns an empty line. Skip it with std::cin >> std::ws or std::cin.ignore().

§4Files and String Streams

Files and in-memory strings use the same interface. std::ifstream and std::ofstream (from <fstream>) close themselves when they go out of scope, which is RAII at work.

#include <fstream>
#include <sstream>
std::ifstream in{"data.txt"};
if (!in) { std::cerr << "cannot open file\n"; return 1; }
std::string word;
while (in >> word) { /* process */ }

std::istringstream parts{"10 20 30"};
int a, b, c;
parts >> a >> b >> c;                           // parse numbers out of a string
The key insight The condition while (in >> x) both reads and tests. Writing while (!in.eof()) is a bug: the flag only turns on after a read fails, so you process one extra bogus value.

§5Common Mistakes

MistakeWhat HappensFix
Never checking whether cin >> x succeededBad input leaves x unset and all later reads failTest the read and recover with clear and ignore
Using std::endl on every lineFlushes each time, which slows heavy outputUse '\n'
Looping on !in.eof()An extra iteration with stale dataLoop on the read itself
Practice
  1. Read integers from standard input until end of input and print their sum and average to two decimals.
  2. Read a file line by line and print each line with its line number.
  3. Use std::istringstream to parse the line "x=3 y=4" into two integers.
Key takeaways
  • Always test the result of a read, and loop with while (in >> x) or while (getline(...)).
  • Use '\n' instead of std::endl unless you really need a flush.
  • File and string streams share the stream interface and close themselves automatically.
