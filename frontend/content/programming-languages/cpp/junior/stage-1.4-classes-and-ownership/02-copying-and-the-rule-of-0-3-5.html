Copying & the Rule of 0/3/5

The compiler writes copy operations for you, and they are correct unless your class owns a raw resource, in which case you must take over all of them or none.

§1What the Compiler Generates

For a class with no special functions, the compiler provides a copy constructor, copy assignment, and destructor that act member by member. A copy duplicates each member, so classes made of std::string, std::vector, and similar types are copied correctly for free.

struct Person { std::string name; std::vector<int> scores; };
Person a{"Ada", {1, 2}};
Person b = a;          // copy constructor: deep copy of name and scores
b = a;                 // copy assignment

§2When the Defaults Break

A raw pointer member copies as an address, so two objects end up sharing one allocation and both free it.

class Buffer {
    int* data_;
    std::size_t n_;
public:
    explicit Buffer(std::size_t n) : data_{new int[n]{}}, n_{n} {}
    ~Buffer() { delete[] data_; }
};
Buffer a{10};
Buffer b = a;          // shallow copy: both hold the same pointer
                       // at scope end both destructors delete[] it: DOUBLE FREE

§3The Rule of Three

If a class needs a custom destructor, copy constructor, or copy assignment, it almost certainly needs all three, because each exists to manage the same resource.

Buffer(const Buffer& o) : data_{new int[o.n_]}, n_{o.n_} {
    std::copy(o.data_, o.data_ + n_, data_);
}
Buffer& operator=(const Buffer& o) {
    if (this != &o) {
        Buffer tmp{o};                // copy first
        std::swap(data_, tmp.data_);  // then swap, so failure leaves *this intact
        std::swap(n_, tmp.n_);
    }
    return *this;
}

§4Rule of Five and Rule of Zero

With move semantics (covered in Level 2), the Rule of Three grows to five: add a move constructor and move assignment. But the best rule is the Rule of Zero: write none of the five by letting members manage resources.

class Buffer {
    std::vector<int> data_;          // owns its memory
public:
    explicit Buffer(std::size_t n) : data_(n) {}
};                                   // copy, move, destroy all correct by default

To block copying deliberately, write Buffer(const Buffer&) = delete;. To keep the compiler's version, write = default.

The key insight Use the Rule of Zero: hold resources in standard types (vector, string, unique_ptr), and you write no special member functions. Only the classes that wrap a raw resource need the Rule of Three or Five.

§5Common Mistakes

MistakeWhat HappensFix
Writing a destructor but no copy operationsCompiler-generated copies share the pointer; double freeFollow the Rule of Three, or switch to a vector or smart pointer
Copy assignment that deletes first, then copiesSelf-assignment destroys the dataCopy-and-swap, or check this != &o
Copying an object whose copying makes no sense (a mutex, a file handle)Compiles to something wrongDeclare the operations = delete
Practice
  1. Reproduce the double free with the raw-pointer Buffer, observe the ASan report, then fix it two ways: Rule of Three and Rule of Zero.
  2. Make a class non-copyable with = delete and read the compiler's error when you copy it.
Key takeaways
  • Compiler-generated copies are member-wise and correct unless the class holds a raw resource.
  • If you write one of destructor/copy-ctor/copy-assign, write all three, or better, none.
  • Prefer the Rule of Zero, and use = delete to forbid copying on purpose.
