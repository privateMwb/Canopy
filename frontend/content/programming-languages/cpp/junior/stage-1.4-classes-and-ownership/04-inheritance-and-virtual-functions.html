Inheritance & Virtual Functions

Virtual functions let code call the right behavior through a base-class interface, and a few rules keep this safe.

§1Base and Derived Classes

A derived class inherits the base's members and can be used wherever the base is expected. Mark functions virtual in the base, and override them in the derived class.

class Shape {
public:
    virtual ~Shape() = default;              // always virtual in a polymorphic base
    virtual double area() const = 0;         // pure virtual: Shape is abstract
};
class Circle : public Shape {
    double r_;
public:
    explicit Circle(double r) : r_{r} {}
    double area() const override { return 3.14159265 * r_ * r_; }
};
class Square : public Shape {
    double s_;
public:
    explicit Square(double s) : s_{s} {}
    double area() const override { return s_ * s_; }
};

= 0 makes a function pure virtual, so the class can't be instantiated and acts as an interface. override makes the compiler check that you really are overriding something.

§2Dynamic Dispatch

Calling a virtual function through a pointer or reference to the base runs the derived version, chosen at run time.

std::vector<std::unique_ptr<Shape>> shapes;
shapes.push_back(std::make_unique<Circle>(1.0));
shapes.push_back(std::make_unique<Square>(2.0));
for (const auto& s : shapes)
    std::cout << s->area() << '\n';          // Circle::area, then Square::area

Virtual calls go through a table of function pointers (the vtable), costing one indirect call and blocking inlining.

§3Virtual Destructors

Deleting a derived object through a base pointer is undefined behavior unless the base destructor is virtual, since only the base destructor would run.

Shape* p = new Circle{1.0};
delete p;          // UB without virtual ~Shape(); derived part never destroyed

§4Slicing

Copying a derived object into a base object (not pointer or reference) cuts off the derived part, and virtual behavior is lost.

Circle c{1.0};
Shape s = c;                 // does not compile for abstract Shape; for a concrete base it slices
void f(Shape by_value);      // calling f(c) slices
void g(const Shape& ref);    // calling g(c) is fine: no copy

Always hold polymorphic objects by pointer or reference, and pass them by reference.

The key insight A class with virtual functions must have a virtual destructor. A good rule: if it has any virtual function, add virtual ~T() = default; and override every derived function.

§5Common Mistakes

MistakeWhat HappensFix
Base class with virtual functions but a non-virtual destructorDerived destructors skipped on delete through baseAdd virtual ~Base() = default;
Omitting override and getting a signature slightly wrong (a missing const)Silently creates a new function instead of overridingAlways write override
Passing polymorphic objects by valueSlicingPass const Base& or smart pointers
Practice
  1. Add a Triangle to the shapes example and a perimeter() virtual function.
  2. Break override on purpose by dropping const from the derived signature and read the compiler's complaint.
Key takeaways
  • Virtual functions dispatch on the object's real type at run time.
  • Give polymorphic bases a virtual destructor and mark overrides with override.
  • Never pass polymorphic objects by value; slicing erases the derived behavior.
