Pointers & References

A pointer is an object that holds an address, and a reference is a permanent alias; both let code refer to data without copying it.

§1Addresses and Pointers

Every object lives at an address. &x gives the address of x, and a pointer variable stores such an address. *p follows the pointer to the object (dereferencing).

int x{10};
int* p{&x};          // p holds the address of x
*p = 20;             // writes through the pointer: x is now 20
std::cout << x << ' ' << *p << '\n';        // 20 20
std::cout << (p == &x) << '\n';             // 1: same address

The type matters: int* points at an int, so p + 1 moves by sizeof(int) bytes, not one byte.

§2nullptr and Validity

A pointer may hold no address at all. Use nullptr for that and check before dereferencing. Dereferencing a null, uninitialized, or dangling pointer is undefined behavior.

int* q{nullptr};
if (q) { *q = 1; }           // guarded: q is false when null

int* bad;                    // uninitialized: garbage address
// *bad = 5;                 // undefined behavior, may crash or corrupt memory

Never use 0 or NULL for null pointers in modern code; nullptr has its own type and avoids overload surprises.

§3References

A reference is another name for an existing object. It must be initialized, cannot be reseated to refer to something else, and cannot be null. Using it needs no *.

int a{1}, b{2};
int& r{a};
r = 5;               // a is now 5
r = b;               // assigns b's VALUE to a; r still refers to a

Under the hood a reference is usually implemented like a pointer, but the language gives it safer rules, so references are the default for parameters and pointers are used when "might be absent" or "can be repointed" is needed.

§4const with Pointers

Read declarations right to left:

const int* p1 = &a;      // pointer to const int: can't change *p1, can repoint p1
int* const p2 = &a;      // const pointer to int: can change *p2, can't repoint p2
const int* const p3 = &a;   // neither
The key insight Pointer vs. reference is a question about the contract. A T& parameter promises there is always an object; a T* parameter admits there might not be, and the callee must check.

§5Common Mistakes

MistakeWhat HappensFix
Dereferencing a pointer without a null checkCrash or undefined behaviorCheck if (p) or use a reference when null is not allowed
Returning the address of a local variableDangling pointer once the function returnsReturn by value, or point to something that outlives the call
Declaring int* a, b; expecting two pointersOnly a is a pointer; b is an intDeclare one variable per line
Practice
  1. Write void increment(int* p) and void increment(int& r), then call both. What extra check does the pointer version need?
  2. Print p, p + 1, and sizeof(int) for an int* and observe the 4-byte step.
Key takeaways
  • A pointer stores an address and can be null or repointed; a reference is a fixed alias.
  • Check pointers before dereferencing, and use nullptr, never 0 or NULL.
  • Prefer references for parameters that must exist; use pointers for optional or repointable access.
