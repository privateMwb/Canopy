Arrays & std::array

C-style arrays decay to pointers and carry no size, so std::array and std::vector are the right defaults.

§1C-Style Arrays

A C array is a fixed number of elements stored contiguously. Its size is part of its type, but only until you pass it somewhere.

int a[5]{1, 2, 3, 4, 5};
std::cout << sizeof(a) / sizeof(a[0]) << '\n';     // 5

void show(int arr[]) {                              // really: int* arr
    std::cout << sizeof(arr) << '\n';               // pointer size (8), not 20!
}

This is array decay: when passed to a function, the array becomes a pointer to its first element and the length is lost. Nothing stops you from indexing past the end.

int a[5]{};
a[5] = 1;        // out of bounds: undefined behavior, no error required

§2std::array

std::array<T, N> wraps a fixed-size array in a normal object. It has the same layout and speed, but it copies by value, knows its size, and works with standard algorithms.

#include <array>
std::array<int, 5> a{1, 2, 3, 4, 5};
std::cout << a.size() << ' ' << a.front() << ' ' << a.back() << '\n';
for (int x : a) std::cout << x << ' ';
a.at(5);                                // throws std::out_of_range instead of silent UB

void show(const std::array<int, 5>& arr);   // size travels with the type

std::array is the right choice when the size is a compile-time constant.

§3std::vector When Size Varies

If the size is only known at runtime or changes, use std::vector<T>, which owns heap memory and grows as needed. Both containers support the same indexing, iteration, and .at() checks.

std::vector<int> v(5, 0);        // five zeros
v.push_back(9);
std::cout << v.size() << '\n';   // 6

For a function that merely reads a sequence of any container, C++20's std::span<const int> accepts arrays, std::array, and std::vector alike without copying.

The key insight operator[] never checks bounds on any of these types. The safety of std::array comes from knowing its size and from .at(), so test boundaries with .at() or sanitizers.

§4Common Mistakes

MistakeWhat HappensFix
Computing sizeof(arr)/sizeof(arr[0]) inside a function that got int arr[]Computes pointer size over element size, a wrong countPass std::array, std::vector, or std::span
Writing a loop i <= sizeOff-by-one reads or writes one element past the endUse i < size or a range-for
Allocating new int[n] for a runtime-sized arrayManual delete[] requiredUse std::vector<int>(n)
Practice
  1. Write the same "sum the elements" function for a C array (with a length param) and std::array. Compare the call sites.
  2. Index one element past the end of a std::array with [] and then with .at(). What differs?
Key takeaways
  • C arrays decay to pointers and lose their size when passed to functions.
  • Use std::array for fixed sizes and std::vector for dynamic sizes.
  • [] is unchecked; use .at() or sanitizers when hunting bounds errors.
