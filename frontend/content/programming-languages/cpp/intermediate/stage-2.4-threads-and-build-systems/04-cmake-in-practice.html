CMake in Practice

CMake describes your project in terms of targets and their dependencies, and generates the build files for whichever compiler and platform you use.

§1A Minimal Project

myapp/
  CMakeLists.txt
  src/main.cpp
  src/greeter.cpp
  include/myapp/greeter.h
cmake_minimum_required(VERSION 3.20)
project(myapp VERSION 1.0 LANGUAGES CXX)

add_library(greeter src/greeter.cpp)
target_include_directories(greeter PUBLIC include)
target_compile_features(greeter PUBLIC cxx_std_20)

add_executable(myapp src/main.cpp)
target_link_libraries(myapp PRIVATE greeter)

Build it out of source, so generated files stay out of your repository:

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/myapp

§2Think in Targets

A target is an executable or library, and properties belong to targets, not to global variables. The visibility keywords say who needs a property:

  • PRIVATE: only this target uses it (its own .cpp files).
  • PUBLIC: this target and anything linking to it (its headers' include path).
  • INTERFACE: only the users, not this target itself (header-only libraries).

When myapp links to greeter, it inherits greeter's public include directory and C++ standard automatically. Avoid directory-wide commands like include_directories and add_definitions.

§3Build Types, Warnings, and Sanitizers

add_compile_options(-Wall -Wextra -Wpedantic)     # or per target: target_compile_options
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)                     # -std=c++20 instead of gnu++20
option(ENABLE_SANITIZERS "Build with ASan/UBSan" OFF)
if(ENABLE_SANITIZERS)
  add_compile_options(-fsanitize=address,undefined -fno-omit-frame-pointer)
  add_link_options(-fsanitize=address,undefined)
endif()

Debug has no optimization and full symbols, Release is optimized with no asserts (-O3 -DNDEBUG), and RelWithDebInfo is optimized with symbols, which is what you want for profiling. Set the standard on the target with target_compile_features so it's visible to anyone linking.

§4Dependencies

Find an installed package with find_package(Threads REQUIRED) and link its imported target, or fetch one at configure time.

find_package(Threads REQUIRED)
target_link_libraries(myapp PRIVATE Threads::Threads)

include(FetchContent)
FetchContent_Declare(fmt GIT_REPOSITORY https://github.com/fmtlib/fmt GIT_TAG 10.2.1)
FetchContent_MakeAvailable(fmt)
target_link_libraries(myapp PRIVATE fmt::fmt)

Pin a specific version (tag or hash) so builds are reproducible. For larger projects, a package manager such as vcpkg or Conan manages dependencies.

The key insight Modern CMake is declarative: say what each target needs, and let linking propagate requirements. If you find yourself setting global flags, you are using the old style.

§5Common Mistakes

MistakeWhat HappensFix
Using include_directories or global CMAKE_CXX_FLAGS everywhereEvery target inherits settings; hard to maintainUse target_* commands with visibility
Building inside the source treeGenerated files clutter the repoAlways cmake -S . -B build
Benchmarking a Debug buildNumbers are meaninglessMeasure Release or RelWithDebInfo
Practice
  1. Turn a two-file program into a library plus an executable in CMake, and build it out of source in both Debug and Release.
  2. Add an ENABLE_SANITIZERS option and confirm a deliberate bug is caught when it's on.
Key takeaways
  • Describe the build as targets with PRIVATE/PUBLIC/INTERFACE dependencies.
  • Build out of source, and pick the build type deliberately.
  • Put warnings, sanitizers, and dependencies into CMake so every machine builds the same way.
