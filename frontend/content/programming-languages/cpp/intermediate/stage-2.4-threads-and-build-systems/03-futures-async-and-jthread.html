Futures, async & jthread

Futures and jthread let you think in terms of results and cancellation instead of raw threads and manual joins.

§1std::async and std::future

std::async runs a function, possibly on another thread, and returns a std::future for the result. Calling .get() waits for completion and returns the value, or rethrows any exception the task threw.

#include <future>
int slowSquare(int x) { std::this_thread::sleep_for(std::chrono::seconds{1}); return x * x; }
auto f1 = std::async(std::launch::async, slowSquare, 6);
auto f2 = std::async(std::launch::async, slowSquare, 7);
std::cout << f1.get() + f2.get() << '\n';          // about 1 second total, not 2

Pass std::launch::async explicitly: the default policy may run the task lazily on the calling thread, and the destructor of a future from async blocks until the task finishes, so ignoring the returned future makes the call synchronous.

§2promise and packaged_task

A std::promise is the writing end of a future: one thread sets a value or an exception, another reads it.

std::promise<int> p;
std::future<int> f = p.get_future();
std::thread t{[&p] {
    try { p.set_value(compute()); }
    catch (...) { p.set_exception(std::current_exception()); }
}};
int result = f.get();
t.join();

A future carries one result once; use std::shared_future for several readers.

§3std::jthread and stop_token

std::jthread (C++20) joins automatically in its destructor and supports cooperative cancellation. A callable whose first parameter is a std::stop_token can check whether a stop was requested.

std::jthread worker{[](std::stop_token st) {
    while (!st.stop_requested()) {
        doChunkOfWork();
    }
    std::cout << "stopping cleanly\n";
}};
std::this_thread::sleep_for(std::chrono::seconds{2});
worker.request_stop();                // asks politely; the thread must check
                                      // destructor requests stop and joins

Cancellation is cooperative: the thread must check the token, and a long blocking call won't notice unless it takes a token (such as std::condition_variable_any::wait with a stop_token). This beats forcibly killing threads, which would skip destructors and leak resources.

§4Choosing a Tool

  • One-off background computation with a result: std::async or a thread pool, then .get().
  • A long-running worker you need to stop: std::jthread plus stop_token.
  • Many small tasks: a thread pool, since creating a thread per task is expensive (the senior stage covers it).
The key insight Prefer std::jthread to std::thread: it removes the "forgot to join" crash and gives a standard way to ask threads to stop.

§5Common Mistakes

MistakeWhat HappensFix
Ignoring the future returned from std::asyncIts destructor blocks, so the call isn't concurrentStore the future and call get() later
Calling .get() twice on a std::futureThrows; the result can be taken only onceUse shared_future
Expecting request_stop() to interrupt a blocking callThread keeps running until it checks the tokenPoll stop_requested() or use stoppable waits
Practice
  1. Launch four std::async tasks that sum parts of a large vector and combine the futures.
  2. Write a jthread that prints a heartbeat every 100 ms until told to stop, then verify it exits cleanly.
Key takeaways
  • std::async plus future gives results and exception propagation, with launch::async for real concurrency.
  • std::jthread auto-joins and supports cooperative cancellation through stop_token.
  • Cancellation works only when the thread checks for it.
