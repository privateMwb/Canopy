Type Traits & constexpr

<type_traits> lets code ask questions about types, and constexpr moves ordinary computation from run time to compile time.

§1constexpr Functions and Variables

A constexpr function can be evaluated during compilation when its inputs are compile-time constants, and it is also a normal function at run time.

constexpr int factorial(int n) { return n <= 1 ? 1 : n * factorial(n - 1); }
constexpr int f5 = factorial(5);           // computed by the compiler
std::array<int, factorial(4)> a;           // array of 24
static_assert(factorial(5) == 120, "factorial is wrong");

Modern constexpr allows loops, local variables, and even std::vector and std::string in some cases. consteval functions *must* be evaluated at compile time. If compile-time evaluation hits undefined behavior, it becomes a compile error, which makes constexpr a good UB detector.

§2if constexpr

if constexpr discards the untaken branch at compile time, so each branch can use operations valid only for certain types.

template <typename T>
std::string describe(const T& v) {
    if constexpr (std::is_integral_v<T>)       return "int:" + std::to_string(v);
    else if constexpr (std::is_same_v<T, std::string>) return "str:" + v;
    else                                       return "other";
}

A plain if would fail to compile because both branches must be valid for every T.

§3Type Traits

<type_traits> provides compile-time queries (::value, or the _v shortcut) and transformations (::type, or the _t shortcut).

#include <type_traits>
static_assert(std::is_integral_v<int>);
static_assert(!std::is_pointer_v<int>);
static_assert(std::is_same_v<std::remove_reference_t<int&>, int>);
static_assert(std::is_trivially_copyable_v<int>);
using U = std::make_unsigned_t<int>;              // unsigned int
using D = std::decay_t<const int&>;               // int

Traits drive library choices: std::vector can use memmove for trivially copyable elements, and std::copy picks the fastest copy strategy.

§4static_assert in Templates

Use static_assert to check an assumption with a readable message at compile time.

template <typename T>
void process(T value) {
    static_assert(std::is_copy_constructible_v<T>, "T must be copyable");
}
The key insight Compile-time computation moves work, and also bugs, earlier. Anything that can be checked by static_assert should be, since the program fails to build instead of failing in production.

§5Common Mistakes

MistakeWhat HappensFix
Using plain if where branches use type-specific operationsCompile error for the other typesUse if constexpr
Assuming constexpr means "always at compile time"May run at run time with non-constant inputsUse consteval, or assign to a constexpr variable to force it
Forgetting ::value or _v on a traitUsing the trait type, not the booleanUse std::is_integral_v<T>
Practice
  1. Write a constexpr function computing the nth Fibonacci number and static_assert the first five values.
  2. Write describe above for three more categories using if constexpr and traits.
Key takeaways
  • constexpr lets the compiler run code, and failing there is a build error.
  • if constexpr selects code per type at compile time.
  • Use traits and static_assert to state and check assumptions about types.
