Concepts

Concepts name the requirements a template places on its types, so misuse gives a clear error at the call site instead of a wall of text from inside the template.

§1The Problem Concepts Solve

An unconstrained template accepts anything and fails deep inside when an operation is missing.

template <typename T>
T sum(const std::vector<T>& v) { T t{}; for (auto& x : v) t += x; return t; }
sum(std::vector<std::vector<int>>{});    // error pages about operator+=

Before C++20, constraints were expressed with SFINAE tricks (std::enable_if), which were hard to write and harder to read.

§2Using Standard Concepts

C++20 provides ready-made concepts in <concepts>. Put one in place of typename, or after the template header with requires.

#include <concepts>
template <std::integral T>
T half(T x) { return x / 2; }

template <typename T> requires std::floating_point<T>
T half(T x) { return x / 2; }

half(10);       // integral overload
half(3.0);      // floating-point overload
// half("hi");  // error: no matching function; constraint not satisfied

Constraints also take part in overload resolution, so you can write different versions for different kinds of types and the compiler picks the one whose requirements are met.

§3Writing Your Own Concept

A concept is a named compile-time boolean. The requires expression checks that expressions are valid and optionally what they return.

template <typename T>
concept Addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;
};

template <Addable T>
T add3(T a, T b, T c) { return a + b + c; }

template <typename T>
concept Printable = requires(std::ostream& os, const T& v) { os << v; };

Abbreviated syntax goes further: void print(const Printable auto& v);.

§4Subsumption

When two overloads are both viable and one's constraint is built from the other's (for example std::signed_integral is defined in terms of std::integral), the more constrained one wins. This is how the standard library can offer a faster algorithm for random-access iterators and a general one for weaker iterators, with no tag-dispatch tricks.

template <std::integral T>        void show(T)  { std::cout << "integral\n"; }
template <std::signed_integral T> void show(T)  { std::cout << "signed\n"; }
show(5u);    // integral
show(5);     // signed: the more constrained overload is chosen
The key insight A concept documents intent as well as checking it. template <std::ranges::range R> tells the reader what R is, which typename R never could.

§5Common Mistakes

MistakeWhat HappensFix
Writing a concept that checks too littleConstraint passes, and the body still fails insideAdd the operations the body actually uses
Writing a concept that checks the wrong thing (e.g., just sizeof(T) > 0)Gives false confidenceTest with a type that should be rejected
Reaching for enable_if in C++20 codeHard to read and maintainUse requires or a concept
Practice
  1. Write a Number concept (integral or floating point) and a function constrained by it. Try calling it with std::string and read the error.
  2. Write a concept HasSize requiring .size() that returns something convertible to std::size_t, and use it in an abbreviated function template.
Key takeaways
  • Concepts state template requirements and give clear errors at the call site.
  • Use standard concepts first, and requires expressions for custom ones.
  • Constrained overloads let the most specific viable one win.
