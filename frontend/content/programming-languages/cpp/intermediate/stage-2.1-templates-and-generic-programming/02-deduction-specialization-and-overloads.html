Deduction, Specialization & Overloads

Calling a template means the compiler deduces its arguments from yours and then chooses among overloads and specializations, so knowing the rules explains most surprises.

§1Template Argument Deduction

The compiler infers T by matching the argument type against the parameter pattern.

template <typename T> void f(T x);          // by value: drops const and references
template <typename T> void g(const T& x);   // T is the plain type
template <typename T> void h(T& x);         // T may deduce to a const type

int a{1};
const int c{2};
f(c);       // T = int (const dropped: it's a copy)
g(c);       // T = int, parameter is const int&
h(c);       // T = const int

Deduction doesn't consider conversions beyond these adjustments, which is why maxOf(1, 2.5) fails: T can't be both int and double.

§2Overloads and Templates Together

A non-template function and a template can share a name. The compiler prefers the non-template when both match equally well.

template <typename T> void show(T x) { std::cout << "generic\n"; }
void show(int x)                     { std::cout << "int\n"; }
show(5);        // "int": the exact non-template wins
show(5.0);      // "generic"
show<>(5);      // forces the template

§3Full Specialization

You can give a template a special implementation for one exact type.

template <typename T> struct Describe { static const char* name() { return "unknown"; } };
template <> struct Describe<int>      { static const char* name() { return "int"; } };
template <> struct Describe<double>   { static const char* name() { return "double"; } };
std::cout << Describe<int>::name() << '\n';

Class templates can also be partially specialized for a family of types, such as all pointers.

template <typename T> struct Describe<T*> { static const char* name() { return "pointer"; } };

Function templates cannot be partially specialized. Prefer overloading a function over specializing it, because overloads take part in normal resolution while specializations don't, which gives surprising results.

§4Forwarding References Preview

template <typename T> void k(T&& x) has special deduction rules: it binds to lvalues and rvalues (covered in the move semantics stage). It is not simply an rvalue reference.

The key insight When a template call selects something unexpected, ask three questions: what did T deduce to, which overloads were viable, and is a non-template an equally good match? Printing the deduced type often clears it up.

§5Common Mistakes

MistakeWhat HappensFix
Specializing a function template and expecting overload-like behaviorThe specialization may be ignored in favor of another overloadOverload the function instead
Expecting f(c) to keep const for a by-value parameterconst is dropped; you got a copyUse const T& if you need constness preserved
Passing a string literal to template <typename T> void f(T a, T b) with different lengthsconst char[3] vs. const char[6] conflictAccept std::string_view, or deduce each separately
Practice
  1. Write a typeName<T>() that returns a string through specialization for int, double, and a pointer partial specialization.
  2. Overload a template with a non-template and predict, then verify, which is chosen for several calls.
Key takeaways
  • T is deduced from arguments by pattern, dropping top-level const and references when passed by value.
  • A non-template overload beats an equally good template.
  • Prefer overloads to function-template specialization; partial specialization is for class templates.
