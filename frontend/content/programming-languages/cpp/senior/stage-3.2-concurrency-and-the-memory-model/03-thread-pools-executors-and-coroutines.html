Thread Pools, Executors & Coroutines

A thread pool reuses a fixed set of workers for many tasks, and C++20 coroutines let a function suspend and resume, which is the building block for asynchronous code.

§1A Thread Pool

Creating a thread per task is expensive. A pool starts N workers that pull tasks from a shared queue.

class ThreadPool {
    std::vector<std::jthread> workers_;
    std::queue<std::function<void()>> tasks_;
    std::mutex m_;
    std::condition_variable_any cv_;
public:
    explicit ThreadPool(std::size_t n = std::thread::hardware_concurrency()) {
        for (std::size_t i = 0; i < n; ++i)
            workers_.emplace_back([this](std::stop_token st) {
                while (true) {
                    std::function<void()> task;
                    {
                        std::unique_lock lock{m_};
                        if (!cv_.wait(lock, st, [this] { return !tasks_.empty(); })) return;   // stop requested
                        task = std::move(tasks_.front());
                        tasks_.pop();
                    }
                    task();
                }
            });
    }
    void submit(std::function<void()> f) {
        { std::lock_guard lock{m_}; tasks_.push(std::move(f)); }
        cv_.notify_one();
    }
};

Size CPU-bound pools to the core count, and use bigger pools only when tasks block on I/O. Run the task outside the lock. Returning a std::future from submit (via std::packaged_task) gives callers results and exceptions.

§2Scheduling Improvements

A single shared queue becomes a contention point. Work stealing gives each worker its own deque; an idle worker takes tasks from another's far end. Other design questions: bounded queues for backpressure, task priorities, and avoiding a task that blocks waiting on another task in the same pool, which can deadlock when all workers are blocked.

§3Coroutines

A coroutine is a function that can suspend (co_await, co_yield) and be resumed later, with its local state stored in a heap-allocated frame. C++20 provides the language machinery; libraries supply the types.

// A generator that yields values lazily (std::generator in C++23)
std::generator<int> iota(int start) {
    for (int i = start; ; ++i)
        co_yield i;                         // suspend, hand a value to the caller
}
for (int x : iota(1) | std::views::take(3)) std::cout << x << ' ';   // 1 2 3

A coroutine's return type defines its behavior through a promise type: what happens at the start, at co_yield, at co_return, and on exceptions. co_await calls into an awaiter that decides whether to suspend and who resumes. Writing these from scratch is intricate, so most code uses a library (cppcoro, Boost.Asio, libunifex, or std::generator and std::execution as they arrive).

§4Why Coroutines for Concurrency

A coroutine awaiting I/O suspends and gives its thread to other work, so one thread can serve thousands of connections without a thread per connection. The state is stored in the frame, not on a stack.

asio::awaitable<void> session(tcp::socket s) {
    char buf[1024];
    for (;;) {
        std::size_t n = co_await s.async_read_some(asio::buffer(buf), asio::use_awaitable);
        co_await asio::async_write(s, asio::buffer(buf, n), asio::use_awaitable);
    }
}

Lifetime hazards are the big risk: reference parameters and locals captured by a coroutine may be destroyed before it resumes, so pass by value into coroutines.

The key insight A coroutine's locals live in a frame on the heap, not the stack, so the stack-lifetime rules you rely on don't hold. Pass owned values into coroutines, not references to things that might disappear while suspended.

§5Common Mistakes

MistakeWhat HappensFix
Running tasks while holding the queue mutexSerializes all workersPop the task, release the lock, then run it
A pool task waiting on another task in the same poolAll workers block; deadlockUse continuations, or a separate pool
Passing references to a coroutine that outlives themDangling access after the first suspensionTake parameters by value
Practice
  1. Add std::future support to submit using std::packaged_task, and use it to sum chunks of a vector in parallel.
  2. Write a lazy std::generator of Fibonacci numbers and take the first 20.
Key takeaways
  • A pool amortizes thread creation, and the queue design determines how well it scales.
  • Coroutines suspend and resume with their state in a heap frame, driven by promise and awaiter types.
  • Pass owned values into coroutines; borrowed references can dangle across suspensions.
