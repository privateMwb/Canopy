Large Codebases & Build Times

In a large C++ codebase, compile time becomes a daily cost, and the main levers are including less, compiling less, and caching what's been done.

§1Why C++ Builds Are Slow

Every #include pastes text, which the compiler must parse again in each translation unit. A header that includes <regex> or heavy templates might be reparsed 2,000 times in a build. Template instantiation also repeats per translation unit. And a change to one widely included header recompiles everything that includes it directly or transitively. First measure: clang -ftime-trace (view in chrome://tracing or Perfetto) shows time per header and per template instantiation. ClangBuildAnalyzer summarizes an entire build, and -H or -ftime-report give quick views in GCC.

§2Include Less

  • Forward declarations: if a header only uses a type by pointer or reference, declare it with class Foo; instead of including its header.
  • Pimpl: moves private members and their includes into the .cpp.
  • Include what you use: tools like include-what-you-use and clang-tidy's misc-include-cleaner find unnecessary or missing includes.
  • Keep heavy headers out of other headers: <iostream>, <regex>, <filesystem>, and big libraries should be included only in the .cpp files that use them.
// widget.h
class Engine;                       // forward declaration is enough
class Widget {
    Engine* engine_;                // pointer: no need for the full type
public:
    void run(const Engine& e);      // reference: same
};

§3Precompiled Headers, Unity Builds, and Modules

  • Precompiled headers parse a set of stable headers (standard library, third-party) once and reuse the result: target_precompile_headers(app PRIVATE <vector> <string> <map>) in CMake.
  • Unity (jumbo) builds concatenate several .cpp files into one translation unit, so common headers parse once. They help, but can cause name clashes and hurt incremental builds (set(CMAKE_UNITY_BUILD ON)).
  • C++20 modules (import std;, export module foo;) replace textual inclusion with compiled interfaces that are parsed once. Tool and build-system support (CMake, Ninja, Clang, GCC, MSVC) is improving but still uneven, so check your toolchain before depending on it.

§4Caching and Parallelism

  • Use Ninja and build in parallel: cmake --build build -j.
  • ccache or sccache caches compiler output keyed by the preprocessed source and flags, so unchanged files and CI reruns skip compilation: cmake -DCMAKE_CXX_COMPILER_LAUNCHER=ccache.
  • Distributed builds (distcc, icecream, Bazel remote execution) spread compilation across machines.
  • A faster linker (lld, mold) speeds up the link step, which dominates incremental builds: -fuse-ld=lld.
  • Keep targets small and the dependency graph shallow so a change rebuilds a small part.

§5Taming Template and Dependency Growth

Extern templates (extern template class std::vector<Foo>;) avoid instantiating the same specialization in every unit. Move non-trivial inline code from headers into .cpp files. Enforce layering rules (which libraries may depend on which) in the build so the dependency graph doesn't tangle.

The key insight The fastest compilation is the one you don't do. Measure with a time trace, then fix the biggest items, since one heavy header included everywhere usually costs more than all your own code.

§6Common Mistakes

MistakeWhat HappensFix
Adding #include <big-header> to a widely used headerEvery dependent file recompiles and reparses itInclude it in the .cpp, or forward-declare
Optimizing build times without measuringTime spent on the wrong thingsUse -ftime-trace or ClangBuildAnalyzer first
Turning on unity builds and ignoring odd errorsAnonymous-namespace names collide across filesKeep names distinct, or exclude problem files
Practice
  1. Run a clang build with -ftime-trace and identify the three most expensive headers.
  2. Reduce one widely included header's includes using forward declarations and pimpl, and measure the rebuild time before and after.
Key takeaways
  • Textual inclusion and template instantiation repeat per translation unit, so include less and reuse more.
  • Forward declarations, pimpl, precompiled headers, and (eventually) modules reduce parsing.
  • ccache, a fast linker, and parallel builds cut the cost of what remains, and measurement must guide all of it.
