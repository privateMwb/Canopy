Undefined Behavior in Depth

The optimizer assumes your program never invokes undefined behavior and builds on that assumption, so UB bugs can change code far from where they occur.

§1UB as a Contract

Undefined behavior is a promise from you to the compiler: "this will never happen." The compiler uses it to simplify code, and when the promise is broken, the generated code can do anything, including things that look unrelated to the bug, such as deleting a safety check or running a function that was never called.

int f(int* p) {
    int x = *p;                // dereference implies p != nullptr
    if (p == nullptr) return -1;   // compiler may delete this branch entirely
    return x;
}

The check is "dead" because if p were null, the earlier dereference would already be UB. This is an optimization, not a bug in the compiler.

§2Signed Integer Overflow

Signed overflow is UB, which lets the compiler assume i + 1 > i and simplify loops and comparisons.

bool alwaysTrue(int i) { return i + 1 > i; }       // folded to `return true`
for (int i = 0; i <= n; ++i) { ... }               // if n == INT_MAX: infinite loop, or assumed impossible

Unsigned overflow is defined (wraps modulo 2^N). For checked arithmetic, test before the operation (if (a > INT_MAX - b)), use __builtin_add_overflow, or C++26's std::add_sat and checked helpers. Build with -fsanitize=signed-integer-overflow to catch it in tests.

§3Strict Aliasing

The compiler may assume that pointers of unrelated types don't refer to the same object, so it can keep values in registers and reorder.

float f{1.0f};
int* ip = reinterpret_cast<int*>(&f);
int bits = *ip;                        // UB: accessing a float through an int lvalue

int bits2;
std::memcpy(&bits2, &f, sizeof bits2); // OK: compiles to a single move
int bits3 = std::bit_cast<int>(f);     // C++20: the clearest form

The legal exceptions are accessing any object through char, unsigned char, or std::byte, and through a type that is the signed/unsigned variant of its own type. For type punning, use memcpy or std::bit_cast, which the optimizer handles efficiently.

§4More Sources of UB

  • Out-of-bounds access, including one-past-the-end dereference.
  • Use of an object outside its lifetime, and use of uninitialized values (for most types).
  • Data races, and modifying a const object.
  • Shifting by negative or too-large amounts, and division by zero.
  • Missing return in a non-void function, which is UB for the caller, not just a warning.
  • Violating a function's contract on standard-library requirements (e.g., a comparator that is not a strict weak ordering in std::sort).

§5Living with UB

Sanitizers (-fsanitize=undefined,address) catch many cases at run time. -Wall -Wextra, static analysis, and compile-time evaluation (constexpr rejects UB) catch others. Hardened library modes add bounds checks. The goal is not to memorize the list, but to treat every conversion, cast, and index as something that has preconditions.

The key insight Don't ask "what will the machine do?" Ask "is this allowed by the language?" Once UB occurs, reasoning from the machine model stops being valid, and the optimizer is entitled to the consequences.

§6Common Mistakes

MistakeWhat HappensFix
Testing for overflow after it happens (if (a + b < a) on signed ints)The compiler may delete the checkCheck before, or use overflow builtins
Using reinterpret_cast between unrelated object types to read bytesStrict aliasing violationUse std::memcpy or std::bit_cast
Concluding "this UB is harmless on my compiler"Next compiler version or flag may break itRemove all UB; don't depend on observed behavior
Practice
  1. Compile alwaysTrue at -O0 and -O2 on Compiler Explorer and compare the output. Then rewrite it with defined behavior.
  2. Write a float-to-bits function three ways: reinterpret_cast, memcpy, and std::bit_cast, and check that UBSan or the assembly agrees.
Key takeaways
  • The optimizer assumes UB never happens, and checks that rely on UB may be removed.
  • Signed overflow and strict-aliasing violations are common, and have defined alternatives (memcpy, bit_cast, checked arithmetic).
  • Use sanitizers and compile-time evaluation to find UB, and never rely on "it works here."
