Type Erasure, CRTP & Policy-Based Design

C++ has several ways to abstract over types, such as virtual functions, templates, and type erasure, and each trades speed, code size, flexibility, and binary compatibility differently.

§1The Options

  • Virtual functions: run-time polymorphism. One compiled function, indirect call, objects must inherit from a base.
  • Templates / static polymorphism: compile-time polymorphism. A copy of the code per type, fully inlinable, no inheritance needed, but implementation must be visible and types differ.
  • Type erasure: a value-semantic wrapper that hides the concrete type behind a uniform interface, combining the strengths of both.

§2CRTP (Curiously Recurring Template Pattern)

A class derives from a template of itself, so the base can call derived functions with no virtual dispatch.

template <typename Derived>
struct Shape {
    double area() const { return static_cast<const Derived*>(this)->areaImpl(); }
    void describe() const { std::cout << "area " << area() << '\n'; }
};
struct Circle : Shape<Circle> {
    double r{1};
    double areaImpl() const { return 3.14159 * r * r; }
};

It yields inlined calls and is how mixins like std::enable_shared_from_this or "add comparison operators from <" are written. The costs: every derived type gets a different base, so there's no common type to store in a vector, and errors are harder to read. C++23 "deducing this" removes much of the need for CRTP.

§3Policy-Based Design

Configure behavior by passing small classes as template parameters.

struct ThrowOnError { static void fail(const char* m) { throw std::runtime_error{m}; } };
struct AbortOnError { static void fail(const char* m) { std::cerr << m << '\n'; std::abort(); } };

template <typename T, typename ErrorPolicy = ThrowOnError>
class Checked {
    std::vector<T> v_;
public:
    T& at(std::size_t i) {
        if (i >= v_.size()) ErrorPolicy::fail("index out of range");
        return v_[i];
    }
};
Checked<int, AbortOnError> a;

Policies compile away, but each combination is a separate type, and too many policies make a class hard to use.

§4Type Erasure

Type erasure gives value semantics and a stable type to anything that fits an interface, with no inheritance in the user's types. std::function and std::any are examples. The pattern is a non-template handle holding a hidden virtual interface.

class Drawable {
    struct Concept {
        virtual ~Concept() = default;
        virtual void draw(std::ostream&) const = 0;
        virtual std::unique_ptr<Concept> clone() const = 0;
    };
    template <typename T>
    struct Model final : Concept {
        T value;
        explicit Model(T v) : value{std::move(v)} {}
        void draw(std::ostream& os) const override { value.draw(os); }
        std::unique_ptr<Concept> clone() const override { return std::make_unique<Model>(*this); }
    };
    std::unique_ptr<Concept> p_;
public:
    template <typename T> Drawable(T v) : p_{std::make_unique<Model<T>>(std::move(v))} {}
    Drawable(const Drawable& o) : p_{o.p_->clone()} {}
    Drawable(Drawable&&) noexcept = default;
    void draw(std::ostream& os) const { p_->draw(os); }
};
std::vector<Drawable> scene{Circle{}, Square{}};     // unrelated types, one container

Costs: a heap allocation (unless small-buffer optimization is used), one indirect call, and more code. Benefits: types don't need a common base, and the interface can be added after the fact.

The key insight Choose by what varies and what must stay stable. If types are known at compile time and speed matters, use templates. If you need a heterogeneous collection or a stable binary interface, use virtual functions or type erasure.

§5Common Mistakes

MistakeWhat HappensFix
Using CRTP when a plain template function would doComplexity for no benefitReserve CRTP for adding functionality to a class
Type erasure with expensive copies by defaultUnexpected allocations when copiedProvide move, and document or avoid copy
Stacking five policy parametersHard to read, and each combination is a new typeUse fewer policies or runtime configuration
Practice
  1. Add comparison operators to a class via a CRTP Comparable<T> base that needs only operator<.
  2. Build a small Callable<R(Args...)> type-erased wrapper and compare its size and call overhead to std::function.
Key takeaways
  • Virtual functions, templates, and type erasure trade run-time cost, code size, and flexibility.
  • CRTP gives static polymorphism and mixins, and policies configure behavior at compile time.
  • Type erasure provides value-semantic polymorphism at the cost of an allocation and an indirect call.
