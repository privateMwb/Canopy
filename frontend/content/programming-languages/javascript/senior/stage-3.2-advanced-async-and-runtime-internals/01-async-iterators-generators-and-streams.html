Async Iterators, Generators & Streams

Async iteration lets you consume data one piece at a time as it arrives, and streams add backpressure so a fast producer can't overwhelm a slow consumer.

§1Generators and Async Generators

A generator (function*) is a function that can pause at yield and resume later, producing values lazily. An async generator (async function*) can also await between yields, and is consumed with for await...of. Nothing runs until the consumer asks for the next value — the consumer sets the pace.

function* naturals() { let n = 0; while (true) yield n++; }   // infinite, but lazy
const [a, b, c] = naturals();                                    // takes only three

async function* pages(url) {
  let next = url;
  while (next) {
    const res = await fetch(next);
    const { items, nextUrl } = await res.json();
    yield* items;                       // hand out items one at a time
    next = nextUrl;
  }
}

for await (const item of pages("/api/items")) {
  if (item.done) break;                 // break stops fetching more pages
  process(item);
}

§2Backpressure

Backpressure is the consumer telling the producer to slow down. With a naive event-based approach, a fast source piles data into memory faster than it's handled. Pull-based iteration and streams solve this: the producer only generates more when the consumer is ready.

// Bad: push-based, unbounded buffer
source.on("data", async (chunk) => { await slowWrite(chunk); });   // chunks queue up in memory

// Good: pull-based — the loop only reads the next chunk after the write finishes
for await (const chunk of source) {
  await slowWrite(chunk);
}

// Node's pipeline wires up backpressure and cleanup for you
import { pipeline } from "node:stream/promises";
await pipeline(source, transform, destination);   // pauses upstream when downstream is full

§3Web Streams and Node Streams

The browser and modern Node share Web Streams (ReadableStream, TransformStream, WritableStream). Node's older stream module is still pervasive; Readable.fromWeb, Readable.toWeb, and async iteration bridge the two. A TransformStream is the right shape for a pipeline stage.

const upper = new TransformStream({
  transform(chunk, controller) { controller.enqueue(chunk.toUpperCase()); },
});

const res = await fetch("/big.txt");
await res.body
  .pipeThrough(new TextDecoderStream())
  .pipeThrough(upper)
  .pipeTo(new WritableStream({ write(text) { output.append(text); } }, new CountQueuingStrategy({ highWaterMark: 4 })));

// Convert an async generator into a stream
const stream = ReadableStream.from(pages("/api/items"));   // (supported in modern runtimes)

Always handle errors and cancellation at the *end* of the chain: pipeTo rejects, and cancelling the downstream cancels the source — which is exactly what stops a download when a user navigates away.

Pull beats push for safety If a producer can ever outrun its consumer, put a pull boundary (async iteration or a stream) between them. Otherwise your memory use is bounded only by how fast the other side is.

§4Common Mistakes

MistakeWhat HappensFix
Reading a whole large response with res.text() or res.json()Entire payload in memory before processingStream and process incrementally
Using .on("data") with async work insideNo backpressure; memory grows unboundedUse for await...of or pipeline
Not cleaning up when the consumer stops earlySource keeps producing or holds resourcesUse try/finally; break calls the generator's return()
Practice
  1. Write an async generator that reads a paginated API and yields items, and stop after the first 25 — confirm no extra pages were requested.
  2. Build a TransformStream pipeline that decompresses, splits into lines, and counts matching lines in a large file without buffering it.
Key takeaways
  • Generators produce lazily; async generators add await and are consumed with for await.
  • Backpressure keeps memory bounded by letting the consumer set the pace.
  • Compose with pipeThrough/pipeTo or Node's pipeline for correct errors and cleanup.
