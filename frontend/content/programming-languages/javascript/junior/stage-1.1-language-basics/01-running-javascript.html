Running JavaScript

JavaScript runs in the browser console, in a page's script tag, and in Node.js — and ES modules are how you split code across files in all of them.

§1The Browser Console

Every browser ships a JavaScript REPL. Open DevTools (F12, or Cmd/Ctrl+Shift+J), pick the Console tab, and type. Each line is evaluated immediately and the result is echoed back. It is the fastest way to test a one-liner.

console.log("hello");        // prints hello
2 + 2                         // the console shows 4
document.title                // the current page's title
console.table([{a: 1}, {a: 2}]) // renders a table

§2Script Tags

To run code as part of a page, put it in a <script> tag. Without attributes, the browser stops parsing HTML, runs the script, then continues. That is why scripts that touch the page need to wait for it to exist.

<!-- blocks parsing until it runs -->
<script src="app.js"></script>

<!-- downloads in parallel, runs after the HTML is parsed -->
<script src="app.js" defer></script>

<!-- a module: always deferred, has its own scope -->
<script type="module" src="main.js"></script>

Prefer defer or type="module" for scripts that read the DOM. async runs the script as soon as it downloads, in no guaranteed order — fine for independent scripts such as analytics.

§3Node.js

Node runs JavaScript outside a browser. There is no document or window; instead you get file, network, and process APIs. Run a file with node file.js, or start a REPL with plain node.

// hello.js
console.log("Running on", process.version);
console.log("Args:", process.argv.slice(2));

// $ node hello.js one two
// Running on v22.x.x
// Args: [ 'one', 'two' ]

The language is the same in both places, but the host environment differs. fetch and setTimeout exist in both; document only in browsers; fs only in Node.

§4ES Modules

A module is a file with its own scope that uses import and export. Names inside a module are private unless exported, so modules don't pollute each other or the global scope.

// math.js
export const PI = 3.14159;
export function area(r) { return PI * r * r; }

// main.js
import { area } from "./math.js";
console.log(area(2));

In the browser, load the entry file with type="module". In Node, use the .mjs extension or set "type": "module" in package.json. Relative imports must include the file extension.

The key insight The language and the environment are separate things. If code works in the console but fails in Node (or the reverse), check whether it relies on a browser-only or Node-only API before suspecting the language.

§5Common Mistakes

MistakeWhat HappensFix
Script in <head> reads document.getElementByIdReturns null because the element isn't parsed yetAdd defer, use type="module", or place the script at the end of <body>
Opening an ES-module page via file://Browser blocks the module import (CORS)Serve the folder, e.g. npx serve or python3 -m http.server
Using import in a Node file with no module setupSyntaxError: Cannot use import statement outside a moduleUse .mjs or "type": "module" in package.json
Practice
  1. Open the console on any site and run document.querySelectorAll('a').length to count its links.
  2. Write greet.js that prints the first command-line argument, run it with Node, then turn it into a module imported by a second file.
Key takeaways
  • JavaScript runs in the browser console, script tags, and Node — same language, different host APIs.
  • Use defer or type="module" so scripts run after the HTML is parsed.
  • ES modules give each file its own scope; share things with export and import.
