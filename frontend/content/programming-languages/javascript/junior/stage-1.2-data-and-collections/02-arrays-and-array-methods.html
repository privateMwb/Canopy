Arrays & Array Methods

Arrays carry a toolbox of methods — map, filter, reduce, find, and sort — and knowing which ones mutate prevents a whole class of bugs.

§1Transforming Without Mutating

map, filter, reduce, find, some, every, and slice return new values and leave the array alone. Chain them to describe a pipeline.

const orders = [
  { id: 1, total: 20, paid: true },
  { id: 2, total: 55, paid: false },
  { id: 3, total: 35, paid: true },
];

orders.map((o) => o.total);                     // [20, 55, 35]
orders.filter((o) => o.paid);                   // two orders
orders.find((o) => o.id === 3);                 // the order, or undefined
orders.some((o) => !o.paid);                    // true
orders.every((o) => o.total > 10);              // true
orders.reduce((sum, o) => sum + o.total, 0);    // 110

const paidTotal = orders
  .filter((o) => o.paid)
  .map((o) => o.total)
  .reduce((a, b) => a + b, 0);                  // 55

§2Methods That Mutate

push, pop, shift, unshift, splice, sort, reverse, and fill change the array in place. Newer non-mutating twins exist: toSorted, toReversed, toSpliced, and with.

const a = [3, 1, 2];
a.sort();                  // mutates a -> [1, 2, 3]

const b = [3, 1, 2];
const sorted = b.toSorted();   // b is untouched
const copy = [...b].sort();    // the older way to get the same result

b.with(0, 99);             // [99, 1, 2] — returns a new array

§3Sorting Correctly

Without a comparator, sort converts items to strings and compares those — so 10 sorts before 9. Pass a comparator that returns a negative, zero, or positive number.

[10, 9, 1].sort();                     // [1, 10, 9]  — string order!
[10, 9, 1].sort((a, b) => a - b);      // [1, 9, 10]
users.sort((a, b) => a.name.localeCompare(b.name));  // strings, locale-aware

// Handy extras
[1, [2, [3]]].flat(Infinity);          // [1, 2, 3]
Array.from({ length: 3 }, (_, i) => i * 2);  // [0, 2, 4]
[...new Set([1, 1, 2])];               // [1, 2] — unique values

forEach runs a function per item but returns nothing and can't be stopped. Use for...of when you need break, continue, or await inside the loop.

The question to ask Before calling an array method, ask: does it return a new array or change this one? Mutating a shared array — especially one held in app state — causes bugs that appear far from the cause.

§4Common Mistakes

MistakeWhat HappensFix
[10, 2, 1].sort() with no comparatorSorted as strings: [1, 10, 2]Pass (a, b) => a - b
Calling reduce with no initial value on a possibly-empty arrayThrows TypeErrorAlways supply an initial value
Using map just for side effectsBuilds a useless array; unclear intentUse forEach or for...of
Practice
  1. From an array of { name, age } objects, produce the sorted list of names of everyone 18 or older, without changing the original array.
  2. Use reduce to count how many times each word appears in an array of words, returning an object.
Key takeaways
  • map, filter, reduce, and find return new values; sort, splice, and push mutate.
  • Always pass a comparator to sort for numbers; prefer toSorted when you shouldn't mutate.
  • Reach for for...of when you need early exit or await in a loop.
