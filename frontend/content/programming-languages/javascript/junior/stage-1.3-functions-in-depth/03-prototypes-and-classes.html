Prototypes & Classes

JavaScript objects inherit through a prototype chain, and class syntax is a cleaner way to set that chain up.

§1The Prototype Chain

Every object has an internal link to another object, its prototype. When you read a property that the object doesn't have, the engine looks along that chain until it finds it or reaches null.

const animal = { speak() { return `${this.name} makes a sound`; } };
const dog = Object.create(animal);   // dog's prototype is animal
dog.name = "Rex";
dog.speak();                         // found on animal, this = dog

Object.getPrototypeOf(dog) === animal;  // true
dog.hasOwnProperty("speak");            // false — inherited
[].__proto__ === Array.prototype;       // true: arrays inherit map, filter, ...

§2Class Syntax

class is syntax over prototypes. Methods are placed on the prototype (shared across instances), constructor initializes each instance, and extends links the chain. Always call super() first in a derived constructor.

class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
  static create(name) { return new this(name); }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);                   // required before using this
    this.breed = breed;
  }
  speak() { return `${super.speak()} — woof`; }
}

const d = new Dog("Rex", "lab");
d.speak();                         // "Rex makes a sound — woof"
d instanceof Animal;               // true

§3Getters, Setters, and Private Fields

Getters and setters expose computed or validated properties. Fields starting with # are truly private — inaccessible outside the class, enforced by the engine, not by convention.

class Temperature {
  #celsius = 0;                       // private field

  get fahrenheit() { return this.#celsius * 9 / 5 + 32; }
  set celsius(v) {
    if (typeof v !== "number") throw new TypeError("number required");
    this.#celsius = v;
  }
  get celsius() { return this.#celsius; }
}

const t = new Temperature();
t.celsius = 100;
t.fahrenheit;                         // 212
// t.#celsius;                        // SyntaxError — truly private

Prefer composition (an object that *has* another) over deep inheritance trees. A plain function or object is often simpler than a class.

Remember Methods defined in a class live on the prototype, shared by all instances. Methods assigned as arrow-function fields (handle = () => {}) are created per instance — useful for keeping this, but costlier.

Passing a class method as a callbackthis is lostBind it, wrap it, or define it as an arrow-function field

Key takeaways
  • Objects look up missing properties along their prototype chain.
  • class is syntax over prototypes: constructor, extends, super, static, getters, setters.
  • #private fields are enforced by the language; prefer composition over deep inheritance.
