this, call, apply & bind

this is decided by how a function is called, not where it is written — except in arrow functions, which take this from the surrounding scope.

§1How this Gets Its Value

For a regular function, this is determined at the call site. A method call uses the object before the dot; a plain call gets undefined in strict mode (modules and classes are always strict) or the global object in sloppy mode.

const user = {
  name: "Ana",
  hello() { return `Hi, I'm ${this.name}`; },
};

user.hello();                    // "Hi, I'm Ana"  — this = user

const loose = user.hello;        // detach the method
// loose();                      // this is undefined -> TypeError reading .name

new Person();                    // this = the new object
button.addEventListener("click", function () {
  console.log(this);             // the button element
});

§2call, apply, and bind

These let you choose this explicitly. call and apply invoke the function immediately (arguments listed vs. in an array). bind returns a new function with this fixed.

function intro(greeting, punct) {
  return `${greeting}, ${this.name}${punct}`;
}
const ana = { name: "Ana" };

intro.call(ana, "Hello", "!");       // "Hello, Ana!"
intro.apply(ana, ["Hello", "!"]);    // same
const bound = intro.bind(ana, "Hey");
bound("?");                          // "Hey, Ana?"

setTimeout(user.hello.bind(user), 100);  // keeps this = user

§3Arrow Functions and this

Arrow functions have no this of their own. They use the this of the scope where they were written (lexical this). That's ideal for callbacks inside methods, and wrong for methods themselves.

const timer = {
  seconds: 0,
  start() {
    setInterval(() => {            // arrow: this is still `timer`
      this.seconds++;
    }, 1000);
  },
};

const bad = {
  count: 0,
  inc: () => { this.count++; },    // wrong: this is the outer scope, not `bad`
};

Rule of thumb: use method shorthand for object methods, and arrow functions for callbacks nested inside them. call, apply, and bind cannot change an arrow function's this.

Debugging this When this is wrong, ask: how was the function called? obj.method(), a detached method(), new, an event handler, or call/bind? The answer determines this.

§4Common Mistakes

MistakeWhat HappensFix
Passing obj.method as a callbackthis is lost — often undefinedPass obj.method.bind(obj) or () => obj.method()
Using an arrow function as an object methodthis is the outer scope, not the objectUse method shorthand
Using a function callback inside a method and reading thisthis is not the objectUse an arrow function for the callback
Practice
  1. Create an object with a method, detach it into a variable, and observe the error. Fix it three ways: bind, arrow wrapper, and call.
  2. Write a Timer class whose start method uses setInterval with an arrow callback to increment a counter.
Key takeaways
  • this depends on how a regular function is called.
  • call/apply invoke with a chosen this; bind returns a function with this fixed.
  • Arrow functions inherit this lexically — great for callbacks, wrong for methods.
