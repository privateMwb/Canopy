Callbacks & Promises

Asynchronous code lets the program keep working while it waits, and promises are the standard way to represent a value that will arrive later.

§1Why Async Exists

JavaScript runs on a single thread. If a network request blocked it, the whole page would freeze. So slow operations (timers, network, disk) are started and return immediately; the result is delivered later through a callback or a promise.

console.log("1");
setTimeout(() => console.log("2"), 0);   // runs later, after the current code finishes
console.log("3");
// Output: 1, 3, 2

§2Callback Pitfalls

Callbacks work, but chaining several async steps nests deeper and deeper ("callback hell"), error handling must be repeated at each level, and there's no standard way to know whether the callback might be called twice or never.

getUser(id, (err, user) => {
  if (err) return handle(err);
  getPosts(user, (err, posts) => {
    if (err) return handle(err);
    getComments(posts[0], (err, comments) => {
      if (err) return handle(err);
      render(comments);
    });
  });
});

§3Promises

A Promise is in one of three states: pending, fulfilled with a value, or rejected with a reason. .then runs on fulfillment, .catch on rejection, and .finally always. Each returns a *new* promise, so you can chain flat instead of nesting.

const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

getUser(1)
  .then((user) => getPosts(user))        // return a promise: the chain waits
  .then((posts) => posts.length)         // return a value: passed along
  .catch((err) => { console.error(err); return 0; })   // handles any earlier failure
  .finally(() => console.log("done"));

Promise.resolve(5);                      // already fulfilled
Promise.reject(new Error("no"));         // already rejected

A rejection that nothing handles becomes an unhandled rejection, which logs an error in browsers and can crash Node. Always end a chain with .catch, or await inside try/catch.

Remember Always return the inner promise inside .then. If you forget, the next step runs immediately with undefined instead of waiting for the work to finish.

§4Common Mistakes

MistakeWhat HappensFix
Not returning the inner promise in .thenThe chain doesn't wait; the next step gets undefinedreturn the promise
Nesting .then inside .thenRecreates callback hellReturn and chain flat
No .catch at the end of a chainUnhandled rejectionAdd a final .catch or use try/catch with await
Practice
  1. Write wait(ms) returning a promise, then chain three waits that each log a message.
  2. Wrap setTimeout so a promise rejects if a flag is set, and observe the unhandled-rejection warning when you leave out .catch.
Key takeaways
  • Slow operations return immediately and deliver results later — the thread never blocks.
  • Promises have three states and chain flat with .then, .catch, and .finally.
  • Always return inner promises and always handle rejections.
