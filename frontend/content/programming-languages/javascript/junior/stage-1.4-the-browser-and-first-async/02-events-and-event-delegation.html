Events & Event Delegation

Events let your code react to the user, and understanding how they bubble up the tree lets one listener handle many elements.

§1Listening for Events

addEventListener registers a handler that receives an Event object. The most useful properties are target (what was actually hit) and currentTarget (the element holding the listener). Remove a listener with removeEventListener using the same function reference.

const btn = document.querySelector("#save");

function onClick(event) {
  console.log(event.type, event.target, event.currentTarget);
}
btn.addEventListener("click", onClick);
btn.removeEventListener("click", onClick);

btn.addEventListener("click", () => alert("once"), { once: true });

document.addEventListener("keydown", (e) => {
  if (e.key === "Escape") closeDialog();
});

§2Bubbling, Capturing, and preventDefault

An event travels down from the root to the target (capture), then back up through each ancestor (bubble). Handlers normally run in the bubble phase, so a click on a button also reaches its parents. preventDefault() cancels the browser's default action (following a link, submitting a form); stopPropagation() stops the event traveling further.

form.addEventListener("submit", (e) => {
  e.preventDefault();               // don't reload the page
  save(new FormData(form));
});

link.addEventListener("click", (e) => e.preventDefault());

inner.addEventListener("click", (e) => {
  e.stopPropagation();              // parents won't hear this click
});
// Use stopPropagation sparingly — it can break unrelated listeners.

§3Event Delegation

Instead of attaching a listener to every item, attach one to a common parent and use event.target to see which child was hit. This works for elements added later too, and uses far less memory.

const list = document.querySelector("#todos");

list.addEventListener("click", (e) => {
  const button = e.target.closest("button.delete");   // handles clicks on icons inside
  if (!button || !list.contains(button)) return;
  button.closest("li").remove();
});

// Items added later still work
const li = document.createElement("li");
li.innerHTML = '<button class="delete">x</button>';
list.append(li);

closest(selector) walks up from the clicked element — that's what makes delegation robust when a button contains an icon or a span.

Prefer delegation when You have many similar elements, or elements added and removed over time. One listener on the container beats hundreds on the children.

§4Common Mistakes

MistakeWhat HappensFix
removeEventListener with a new inline functionNothing is removed — it's a different functionKeep a named reference and pass that
Checking e.target directly in delegationMisses clicks on child elements like iconsUse e.target.closest(selector)
Forgetting e.preventDefault() on a submit handlerThe page reloads and state is lostCall it at the top of the handler
Practice
  1. Add a click listener to a <ul> that toggles a done class on whichever <li> was clicked — including ones added later.
  2. Log the order in which listeners run for a click on a nested element, using both bubble and capture listeners.
Key takeaways
  • Handlers receive an event with target and currentTarget; events bubble up the tree.
  • preventDefault stops default browser behavior; stopPropagation stops bubbling.
  • Delegation — one listener on a parent plus closest() — handles many and future elements.
