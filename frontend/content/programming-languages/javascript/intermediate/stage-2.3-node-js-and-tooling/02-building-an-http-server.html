Building an HTTP Server

Start with Node's built-in http module to see what's really happening, then use a framework like Express or Fastify for routing, middleware, and error handling.

§1The http Module

A server is a function that receives a request and writes a response. Everything a framework does is built on this: parse the URL, pick a handler, set status and headers, send a body.

import http from "node:http";

const server = http.createServer((req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);
  if (req.method === "GET" && url.pathname === "/health") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ ok: true }));
    return;
  }
  res.writeHead(404).end("Not found");
});
server.listen(3000, () => console.log("http://localhost:3000"));

§2Routing and Middleware

A framework gives you declarative routes and middleware: functions that run in order for each request and either respond or call next(). Order matters. Error-handling middleware takes four arguments and goes last.

import express from "express";
const app = express();

app.use(express.json());                              // parse JSON bodies
app.use((req, res, next) => {                         // logging middleware
  console.log(req.method, req.url);
  next();
});

const todos = [];
app.get("/todos", (req, res) => res.json(todos));
app.get("/todos/:id", (req, res) => {
  const todo = todos.find((t) => t.id === Number(req.params.id));
  if (!todo) return res.status(404).json({ error: "not found" });
  res.json(todo);
});
app.post("/todos", (req, res) => {
  const { title } = req.body ?? {};
  if (typeof title !== "string" || !title.trim()) {
    return res.status(400).json({ error: "title is required" });
  }
  const todo = { id: todos.length + 1, title: title.trim() };
  todos.push(todo);
  res.status(201).json(todo);
});

§3Error Handling

Errors thrown in a synchronous handler reach Express's error middleware, but a rejected promise in an async handler needs to be forwarded to next (Express 5 does this automatically; Express 4 and others need a wrapper). Use consistent status codes and never leak stack traces to clients.

// Express 4: wrap async handlers (Express 5 and Fastify handle this for you)
const wrap = (fn) => (req, res, next) => fn(req, res, next).catch(next);
app.get("/users/:id", wrap(async (req, res) => {
  res.json(await db.findUser(req.params.id));
}));

app.use((req, res) => res.status(404).json({ error: "not found" }));   // after all routes

app.use((err, req, res, next) => {                    // four arguments = error handler
  console.error(err);                                  // log details server-side
  res.status(err.status ?? 500).json({ error: "internal error" });   // generic to client
});

Validate every input at the edge — body, params, and query. Treat all of it as untrusted until a schema says otherwise.

Status codes are part of the API 200 ok, 201 created, 400 bad input, 401/403 auth, 404 missing, 409 conflict, 500 your bug. Clients depend on them; don't answer errors with 200.

§4Common Mistakes

MistakeWhat HappensFix
Registering the error handler before the routesIt never sees their errorsAdd it last, after all routes and middleware
Trusting req.body without validationCrashes or injection from malformed inputValidate shape and types; reject with 400
Returning err.stack to the clientLeaks internalsLog server-side; send a generic message
Practice
  1. Write a raw http server with /health and /echo (POST) routes, then rewrite it in Express and compare the code.
  2. Add a middleware that measures and logs request duration, and an error handler that returns JSON.
Key takeaways
  • A server is a function from request to response; frameworks add routing and middleware.
  • Middleware order matters; the error handler goes last and takes four arguments.
  • Validate all input, return correct status codes, and never expose stack traces.
