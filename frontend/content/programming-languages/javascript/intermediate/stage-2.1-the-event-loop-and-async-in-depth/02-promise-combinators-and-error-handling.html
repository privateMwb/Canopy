Promise Combinators & Error Handling

all, allSettled, race, and any combine several promises into one, and each answers a different question about success and failure.

§1The Four Combinators

All four take an iterable of promises. They differ in *when they settle* and *what they return*.

const jobs = [fetchA(), fetchB(), fetchC()];

await Promise.all(jobs);          // all succeed -> array of values; first reject -> rejects
await Promise.allSettled(jobs);   // never rejects -> [{status, value|reason}, ...]
await Promise.race(jobs);         // first to settle (success OR failure) wins
await Promise.any(jobs);          // first to *succeed*; rejects only if all fail (AggregateError)
const results = await Promise.allSettled([getUser(), getPosts(), getAds()]);
for (const r of results) {
  if (r.status === "fulfilled") use(r.value);
  else console.warn("failed:", r.reason);   // optional pieces don't break the page
}

// Mirror requests; take the fastest successful one
const data = await Promise.any([fetch(mirror1), fetch(mirror2)]);

§2Choosing the Right One

Use all when you need *every* result and one failure invalidates the rest. Use allSettled when partial success is acceptable. Use race for timeouts (a promise that rejects after N ms). Use any for redundancy.

const timeout = (ms) =>
  new Promise((_, reject) => setTimeout(() => reject(new Error("timeout")), ms));

const res = await Promise.race([fetch("/slow"), timeout(3000)]);
// Note: the fetch itself isn't cancelled — next lesson covers AbortController

§3Unhandled Rejections

A rejected promise with no handler by the time the microtask queue drains triggers unhandledrejection (browser) or unhandledRejection (Node, which since v15 terminates the process by default). The usual culprits: a missing .catch, a forgotten await, or a floating promise inside a loop.

async function save() { throw new Error("db down"); }

function bad() { save(); }                  // floating promise — nothing handles it
async function good() {
  try { await save(); } catch (e) { report(e); }
}

window.addEventListener("unhandledrejection", (e) => report(e.reason));
process.on("unhandledRejection", (reason) => { report(reason); });   // Node — last resort

Global handlers are a safety net for logging, not a place to handle errors. Handle each failure where you have the context to react to it.

A subtle trap Promise.all rejecting does not cancel the other promises — they keep running, and their later rejections are silently ignored. If you need to stop work, you need cancellation, not just a combinator.

§4Common Mistakes

MistakeWhat HappensFix
Using Promise.all when some results are optionalOne failure discards every other resultUse allSettled and handle each outcome
Calling an async function without await or .catchFloating promise; rejection goes unhandledawait it, return it, or attach .catch
Expecting Promise.race to cancel the losersThey keep running in the backgroundPair with AbortController
Practice
  1. Fetch three URLs with allSettled and print how many succeeded and failed, with the failure reasons.
  2. Implement withTimeout(promise, ms) using Promise.race and make sure the timer is cleared when the promise wins.
Key takeaways
  • all = every success, allSettled = every outcome, race = first to settle, any = first success.
  • A floating promise is an unhandled rejection waiting to happen — await it or .catch it.
  • Combinators don't cancel the losing work; they only change what you wait for.
